# Holo 跨端接口契约规范

> **适用场景：任何 iOS ↔ 后端（HoloBackend）之间的接口——新增接口、修改请求/响应字段、改字段类型、新功能带网络通信、后端改任何 `context.json(...)` 返回体。**
>
> 本规范由 2026-10-28「一个发现」开启必失败事故设立：后端 `grant` 返回嵌套对象、iOS 声明为字符串，服务端已成功入库、客户端却解码失败误报「无法开启」；136 个单测全绿（mock 绕过解码 + 无跨端对拍 + 新测试文件假绿三重防线缺失），最终靠用户真机手报才暴露。同类问题连续两天两起（10-27 `policyVersion`、10-28 `grant`），定性为流程缺陷而非个案。完整复盘见记忆档 `discovery-enable-contract-drift-1028`。

---

## 一、单一真源：响应形状的真源在后端代码

1. **每个接口响应的形状（有哪些字段、什么类型、嵌套结构），唯一真源 = 后端 controller 代码里 `context.json({...})` 的返回体**（如 `HoloBackend/src/discovery/discoveryController.js`）。iOS 的 Decodable 模型是这份真源的「翻译」，必须逐字段对齐。
2. iOS 模型**强类型对齐，不做无差别宽容**：字段类型与后端一致；后端可为空的字段才用 Optional；不消费的字段也要按真实类型建模（如 `EnableResponse.Grant`），禁止「反正用不到就随便声明个类型」。形状变化应该让解码显式失败并被契约测试抓住，而不是被宽容解码吞掉。
3. 已知的历史例外要显式处理并注释：如后端版本号「字符串 "v1" 与数字 1 并存」（`CapabilitiesResponse.policyVersion` 的自定义 `init(from:)`）。新接口不允许再制造这类双形状。

## 二、契约测试：接口变更的必要条件

4. **每个跨端接口模块必须有一份契约测试**（现有样板：`HoloTests/Services/AI/Discovery/DiscoveryContractTests.swift`）：用**后端真实响应形状的 JSON 字面量**逐端点解码，断言关键字段值。
5. **字面量只能来自两个地方**：后端 controller/controlStore 代码逐字段抄写（注释钉死真源文件与行号），或生产/测试环境实测响应原文。**禁止照着 iOS 模型反编字面量**——那是自我印证，等于没测。
6. **测试文件头必须写明变更义务**：「改任一端必须同步另一端与本文件；禁止为了让测试变绿而单方面修改字面量迁就 iOS 模型」。
7. **后端改响应形状的会话/人员，同步改 iOS 契约测试字面量是同一项工作的一部分**，不是「以后再说」。改了 `context.json` 返回体而契约测试没动，视为改动未完成。

## 三、mock 纪律：不许绕过解码环节

8. 测试里 mock 网络返回时，允许直接构造 Swift 结构体（便利起见），但**必须同时存在走 `JSONDecoder` 真实解码路径的契约测试**——mock 自造的对象永远发现不了类型声明错误。
9. mock 构造的响应字段形状必须照抄后端真实形状（含嵌套对象），禁止编造后端不存在的形状（如 `grant: "grant-1"` 字符串——2026-10-28 事故的直接现场）。

## 四、防假绿：HoloTests 新文件必须显式挂载并确认执行

10. **HoloTests target 不在同步组**：`fileSystemSynchronizedGroups` 只挂了主 App（Holo）与 HoloMac target，测试 target 是传统显式清单——**新建测试文件必须在 `project.pbxproj` 登记四处**：`PBXBuildFile`、`PBXFileReference`、group children、Sources build phase；ID 用对应模块的编号序列并先查重。
11. **挂载后必须单独跑一次该套件**（`-only-testing:HoloTests/新套件名`）确认用例真的执行；「测试全绿但总数没涨」= 文件没编译 = 假绿。参照样板 ID 序列：Discovery 测试用 `D1A1000000000000000000xx`。

## 五、开闸纪律：灰度锁会掩盖契约问题

12. **被 kill switch / feature flag / 灰度锁住的功能，深处接口从未被真实流量验证过**——锁会在早期检查点短路，把契约漂移全部沉底，开闸后集中爆发（剥洋葱）。因此：**开闸（env 开关、flag 翻转、rollout）前，契约测试全绿是开闸条件之一**；开闸后第一次真实使用要主动跟进（真机走完整用户路径，而不是等用户报障）。
13. 新接口「后端已测 + iOS 已测」≠ 交付完成——两端测试都绿只证明各自正确，**接缝处的对拍只有契约测试能证明**。

## ✅ 改接口时的自检清单（交付前逐条过）

- [ ] 后端响应形状变了吗？变了 → iOS 模型 + 契约测试字面量同步改了吗（真源=controller 代码）？
- [ ] 新接口 → 建了/扩展了对应 `*ContractTests`？字面量来自后端代码或实测原文？
- [ ] 新建了测试文件 → pbxproj 四处登记 + 单独跑该套件确认执行、总数真的涨了？
- [ ] mock 的响应形状照抄后端真实形状了吗？
- [ ] 功能要开闸 → 契约测试全绿了吗？开闸后首跑有人跟进吗？
