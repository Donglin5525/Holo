> **定位**：这是 Holo 视觉与交互设计的唯一真源，**任何页面改造（改 UI、新建页面、调整样式）开工前必读**。
> **代码真源**：`Holo/Holo APP/Holo/Holo/Utils/DesignSystem.swift`。本文是它的结构化说明；token 的最终值以代码为准，改了 token 必须同步改本文。
> **适用范围**：全 App 所有界面。图表类有专项规范 [`图表设计规范.md`](图表设计规范.md)，本文不重复，只引用。

## 2026-10-12：验收必须挑刺儿（用户视角硬闸门，东林设立）

> **事实背景**：习惯弹层改版首版，模拟器判读「全 PASS」交付，东林真机上一眼抓到两个基本问题——打卡标记肉眼不可见、稀疏柱状图孤柱顶格。判读标准停在「元素渲染了、无叠压、编译绿」，而这是**入场券不是验收线**。东林原话：「必须要挑刺儿，找到真正用户关心的问题修复好，不要每次都我来跟你说这种最基本的问题。」

**硬要求（UI 改动交付前逐条过，违反即视为未验收）：**

1. **验收线 = 真实用户第一眼**。「看不懂」「觉得丑」「觉得怪」「觉得空」都算不过关——与「元素存在、无叠压、无裁切」是两回事，后者只是及格线。观感是硬闸门，不是加分项。
2. **交付前自己先把刺挑了**：每张验收截图回答三问——**一个外行第一眼看得懂吗？最惨数据状态下体面吗？和 App 整体气质协调吗？**任何一问答不过，回去改完再交付，不带病出门。
3. **数据可视化 / 标记类 UI 必须实测「最惨稀疏态」**：造 1~3 天数据的习惯/账户/记录实拍判读（只造常规密度数据 = 没验过）。判读任务书必须用用户视角提问（「你能看懂这行标记吗」「这张图你会觉得丑吗」），**禁止只发版式核对清单**——清单式任务书只会得到清单式 PASS。
4. **基本问题不许出门**：可见性（标记/图标肉眼可辨）、可读性（外行能懂）、空态/稀疏态、极端文案长度——这四类属于「不该需要用户来发现」的级别。被用户报出，即算验收失职，必须当天回填教训到踩坑档案。
5. **挑刺前置给方案阶段**：界面方案稿（HTML/截图）必须画出最惨稀疏态长什么样，不能只画数据饱满的漂亮态。

执行侧：走查/判读子代理的对应铁律见 `ios-qa` 铁律五；主会话派发判读任务书时按第 3 条组织问题。

## 一、颜色系统

**统一程度：✅ 强统一。** 业务页面以 Tool 语义色为准；旧品牌、图表及用户自定义颜色仍有独立用途。历史统计不能作为当前全量覆盖证明。

### 1.1 品牌主色（固定橙，不随深浅模式变）

| Token | 色值 | 用途 |
|---|---|---|
| `Color.holoPrimary` | `#F46D38` | **主强调色**：主按钮、选中态、品牌标识 |
| `Color.holoPrimaryLight` | `#FED7AA` | 主色的浅色变体：徽章底、浅色背景 |
| `Color.holoPrimaryDark` | `#EA580C` | 主色的深色变体：渐变收尾、深色文字 |

> 说明：`holoPrimary` 是固定橙色，**不随深浅模式切换**。`Light/Dark` 后缀是同色系的明暗档位，不是浅色/深色模式。

### 1.2 背景 / 容器色（colorset，自动适配深浅）

这些颜色在 Asset Catalog 里定义了 Light / Dark 两套值，**系统切换深色模式时自动适配，代码里只写 token 名**。

| Token | Light | Dark | 用途 |
|---|---|---|---|
| `Color.holoBackground` | `#FDFCF8` | `#0E0E10` | 页面主背景（米白 / 近黑） |
| `Color.holoCardBackground` | `#FFFFFF` | `#2C2C2E` | 卡片背景 |
| `Color.holoGlassBackground` | 白 `@0.7` | 黑 `@0.5` | 毛玻璃浮层（底部导航、浮窗） |
| `Color.holoBorder` | `#F0F0F0` | `#3A3A3C` | 边框 |
| `Color.holoDivider` | `#F1F5F9` | `#38383A` | 分隔线（图表网格线也用它的低透明度） |
| `Color`（Shadow） | 黑 `@0.04` | 黑 `@0.20` | 阴影色（Dark 下更明显） |

### 1.3 旧文字色（兼容历史页面；业务页优先使用上方 Tool 色）

| Token | Light | Dark | 用途 |
|---|---|---|---|
| `Color.holoTextPrimary` | `#333333` | `#F5F5F5` | 主文字 |

| `Color.holoTextPlaceholder` | `#9CA3AF` | `#6B7280` | 输入框占位符 |

### 1.4 功能 / 状态色（固定，不随深浅变）

| `Color.holoPurple` | `#C084FC` | 紫色装饰 |
| `Color.holoAI` | `#7C5CFC` | **AI 功能专属色**，与品牌橙区分，用于智能整理等入口 |

### 1.5 图表配色

12 色调色板（`holoChart1`…`holoChart12`）+ 自动取色函数 `holoChartColors(count:)`。
**详见 [`图表设计规范.md`](图表设计规范.md)**，本文不重复。图表色禁止硬编码，必须走 `holoChart*` 或语义色 token。

### 1.6 热力图色阶

唯一来源：`HoloDesignSystem.holoHeatmapColor(level:palette:colorScheme:)`，支持 `warm`（活跃/品牌橙）和 `cool`（记录数/信息蓝）两套，各 0–5 级，Light/Dark 独立色阶。
**禁止在组件里硬编码热力图 hex**，全 App 热力图色阶只从这里取。

### 1.7 分类色（记账分类）

`holoCategoryDining` / `Transport` / `Shopping` / `Coffee` / `Grocery` / `Utilities` / `Entertain` / `Housing` / `Salary` / `Bonus`，与前端原型对齐，定义在 `DesignSystem.swift`。

### 1.8 Holo Plus 主题色

`enum HoloPlusTheme`：深底渐变（`darkGradient`）、深底文字（`accentText` / `subtleText`）、徽章（`badgeBg` / `badgeText`）、光晕（`glowColor`）、描边（`strokeColor`）、浅底高亮（`plusColumnTint` / `plusValueColor`）。
**Plus 相关页面配色只从这里取，禁止再内联金色/橙色 hex。**

### 🔴 颜色红线

- **禁止硬编码 hex**（`Color(red:green:blue:)` 或 `Color(hex:)` 字面量）。新颜色必须先加到 `DesignSystem.swift` 再用。
- **禁止 `if 深色模式` 判断颜色**，用 colorset 让系统自动适配。
- `Color(hex:)` 解析器在 `Utils/Color+Hex.swift`，仅用于定义 token，不用于业务代码内联。

## 二、字体系统

**统一程度：⚠️ 一半散乱**（设计 token 约 1063 处 vs 原生 `.system(size:)` 约 1109 处，各占一半）。

> 注意：原生 `.system(size:)` 主要是**图标尺寸**（见 §8.4）和少量特殊数字显示，正文/标题应优先用下列 token。

| Token | 对应系统字体 | 用途 |
|---|---|---|
| `.font(.holoAmount)` | `largeTitle` + bold | 金额大数字 |
| `.font(.holoTitle)` | `title` + bold | 大标题 |
| `.font(.holoHeading)` | `title3` + semibold | 页面标题 |
| `.font(.holoBody)` | `body` + medium | 正文（默认） |
| `.font(.holoCaption)` | `subheadline` | 辅助/说明文字 |
| `.font(.holoLabel)` | `caption` + medium | 按钮标签 |
| `.font(.holoTinyLabel)` | `caption2` + medium | 底部导航标签 |

所有 token 跟随系统动态字体缩放（无障碍）。

### 🔴 字体红线

- 正文/标题用 token，**不要裸写 `.font(.system(size: N))` 当正文字号**。
- 图标尺寸允许用 `.font(.system(size:))`（图标不是文字，见 §8.4）。
- 金额显示（空间受限）必须用 `NumberFormatter.compactCurrency()`，禁止 `fixedSize`（见 `CLAUDE.md` 编码约定）。

## 三、间距系统

**统一程度：✅ 强统一**（约 1508 处使用，几乎替代魔法数字）。

| Token | 值 | 典型用途 |
|---|---|---|
| `HoloSpacing.xs` | 4pt | 紧凑元素间隙 |
| `HoloSpacing.sm` | 8pt | 小间隙 |
| `HoloSpacing.md` | 16pt | **标准内边距**（卡片内、列表行、水平页边距） |
| `HoloSpacing.lg` | 24pt | 段落间距、导航外边距 |
| `HoloSpacing.xl` | 32pt | 大段落 |
| `HoloSpacing.xxl` | 48pt | 页面顶部留白 |

> 图表卡片内边距约定：水平 16 / 垂直 14（见图表规范）。

### 🔴 间距红线

- **禁止魔法数字**（`padding(17)`、`spacing: 13` 这类）。用 `HoloSpacing`；确需中间值时优先用现有档位组合，不要开新值。
- 若某个尺寸反复出现且不属于现有档位，**先加到 `HoloSpacing` 再用**，不要散落硬编码。

## 四、圆角系统

| Token | 值 | 典型用途 |

- 胶囊形优先用 `Capsule()` 而非 `RoundedRectangle(cornerRadius: 9999)`。

## 五、阴影与卡片

### 5.1 标准卡片（高频，必用）

```swift
VStack { /* 内容 */ }
    .holoCard()   // 卡片底 + 16 圆角 + 0.5pt 描边 + 轻投影
```

`holoCard()` 定义：`holoCardBackground` 底 + `HoloRadius.lg` 圆角 + `holoDivider.opacity(0.4)` 的 0.5pt 描边 + `black.opacity(0.035)` / radius 8 / y 3 的阴影。内容 padding 由调用方控制。

### 5.2 阴影 token

| Token | 用途 |
|---|---|
| `HoloShadow.card` / `.button` | 卡片 / 按钮常规投影（走 Shadow colorset，自动适配深浅） |
| `HoloShadow.primaryGlow()` / `.float` | 品牌橙发光（主按钮、浮动按钮） |

### 🔴 阴影/卡片红线

- 卡片外观用 `.holoCard()`，**不要每张卡手写 background + clipShape + stroke + shadow**。
- 标准卡片之外如需自定义阴影，颜色走 `HoloShadow.*` 或 `Shadow` colorset，不要硬编码阴影参数。

## 六、触觉反馈

**统一程度：✅ 最统一**（全 App 的正面榜样）。单一入口 `HoloHapticManager` / `HapticManager`。

| 方法 | 触觉类型 | 场景 |
|---|---|---|
| `HapticManager.success()` | 通知·成功 | 保存、创建成功 |
| `HapticManager.warning()` | 通知·警告 | 警告提示 |
| `HapticManager.error()` | 通知·错误 | 操作失败 |
| `HapticManager.light()` | 撞击·轻 | 计数、选择切换（最常用） |
| `HapticManager.medium()` | 撞击·中 | 打卡、任务完成、长按 |
| `HapticManager.heavy()` | 撞击·重 | 重操作 |
| `HapticManager.selection()` | 选择 | 拖拽排序、滑动选择 |
| `HapticManager.taskCompletion()` | 音效+中撞击 | 任务完成庆祝 |

### 🔴 触觉红线

- **禁止直接用 `UIImpactFeedbackGenerator` / `UINotificationFeedbackGenerator`**，一律走 `HapticManager`。

## 七、动画

**统一程度：✅ 已建立 token**（`HoloAnimation`，见 `Utils/DesignSystem.swift`）。新增动画的唯一来源；现有页面渐进迁移中，值与原习惯值一致，迁移不改变手感。

### 标准 token

| Token | 值 | 用途 |
|---|---|---|
| `HoloAnimation.quick` | `easeInOut(0.15)` | 微交互——开关、高亮、按压反馈 |
| `HoloAnimation.standard` | `easeInOut(0.2)` | 常规切换——展开/收起、淡入（默认首选） |
| `HoloAnimation.smooth` | `easeInOut(0.25)` | 较慢切换——导航高亮、板块过渡 |
| `HoloAnimation.snappy` | `spring(0.3, 0.7)` | 弹性交互——拖拽、卡片弹入、选中态（最常用） |
| `HoloAnimation.grounded` | `spring(0.45, 0.82)` | 沉稳弹性——滑动返回、大块视图位移 |
| `Animation.holoScreenTransition` | `easeInOut(0.28)` | 全屏模块转场专用（`Utils/HoloScreenDismiss.swift`） |

用法：

```swift
withAnimation(HoloAnimation.snappy) { isExpanded.toggle() }
.animation(HoloAnimation.standard, value: selection)
```

### 🔴 动画红线

- 新增动画**必须用 `HoloAnimation.*`**，禁止裸写 `.easeInOut(duration:)` / `.spring(response:)` 魔法数字。
- 含动画的交互**必须做 `reduceMotion` 兜底**（参考 `Components/BottomNavBar.swift`）。
- 现有裸数字可渐进迁移到 token（值一致，不改变手感）；不要在迁移中引入 0.18 / 0.62 这类孤立数值。

### 2026-10-04：温暖且有惊喜的操作反馈

- 普通按钮采用 `HoloPressStyle`；已带布局和颜色的业务按钮继续用 `HoloActionStyle`。按压比例取 `HoloAnimation.pressScale`，不添加手势、不改变命中区域。
- 新记录保存成功后由 `HoloMotionFeedbackCenter` 发布真实 ID 与操作 ID，列表使用 `holoRecordArrival` 播放 400ms 局部光痕。编辑旧记录、同步、刷新、失败不发布成功事件。展示账本保留 10 秒、最多 128 项，同一操作只消费一次。
- 好习惯当天首次有效记录使用 600ms 局部暖光；计数增加、撤销后重新勾选不重复庆祝，坏习惯不庆祝。仓库通知可能同步更新 UI，首次判断须在调用仓库前快照。
- 任务三秒窗口内写「已勾选，可撤回」；确认成功后才写「已完成」。计时、落库、撤回只由 `HoloTaskCompletionCoordinator` 持有，展示层不得另建保存计时器。
- 日回放日期保持稳定，明确打开的一天按时段短促展开；每段最多延迟 300ms，全部展开不超过 600ms。连续滚动、刷新、筛选与懒加载重建不补播，照片拖动继续跟随手指。
- `holoMotionSurfaceIsActive` 标记常驻页面和被弹层遮住的列表是否可见，子容器必须与父状态相与；不可见或后台不播放新增反馈，持续光效暂停。首页品牌绘制与正常动效参数保持原值。
- 持续装饰使用 `HoloContinuousMotion` / `holoRepeatingPhase`，光标使用 `holoAmbientOpacity`；减少动态效果、后台、不可见页面与关闭交互开关时停止运动，保持状态可读。**例外：首页品牌光球（背景光晕/弧线与中央球体）不受减少动态效果约束，持续运转**（东林 2026-10-06 拍板，后台与首页不可见时仍暂停）。纸屑只播放一轮，装饰不命中也不进入无障碍树。
- 新的一次性 KeyframeAnimator 必须显式 `repeating: false`。任务待确认期间只展示可撤回反馈，确认后再回应一次；新人首次记录庆祝只接明确本地保存来源，不监听通用数据刷新。
- 四个 `HoloMotionRollout` 开关默认开启：按压/转场、记录、完成、日回放。关闭只改变展示，保存与撤回不受影响；系统减少动态效果优先，保留状态和操作入口。

实现与验收边界见 [`全局动效改版实施记录`](../_common/plans/2026-10-04-Holo全局动效改版-实施与验收.md)。

## 八、组件规范

> 现状说明：Holo 的组件层**尚未抽象成标准组件库**。下面记录的是各组件**事实上的约定写法**——改造时照此执行，保证一致性。

### 8.1 主按钮（CTA）— 事实规范

业务页面优先复用 `HoloActionStyle(role:)`，按钮外观不承担保存、触觉或成功提示等副作用：

```swift
Button { /* 真实业务动作 */ } label: {
    Text("保存").frame(maxWidth: .infinity)
}
.buttonStyle(HoloActionStyle(role: .primary))
.disabled(!canSave)
```

| 维度 | 当前业务规则 |
|---|---|
| 启用背景 / 前景 | primary=`holoToolAction` / `holoToolOnAction`；secondary=`holoToolSurface` / `holoToolText`；destructive=深红 / 白 |
| 禁用态 | `holoToolInset` 中性实底 + `holoToolTextSecondary`，不把品牌橙压透明叠成泥棕 |
| 圆角 / 热区 | `HoloRadius.md` / 至少 44pt；大表单可增加高度，动态字体不得用固定高度裁字 |
| 字体 | `.holoText(.body)` 随系统缩放 |
| 加载与防重复 | 由真实动作状态控制；加载、恢复、购买等互斥操作使用同一事实状态禁用 |

未迁移旧按钮仍有 56pt 大按钮及品牌主色写法，属于历史兼容；新增/改造以本节和文首 V2 为准。固定色的用户分类、图表、仪式页面与首页品牌绘制另按其用途处理。

### 8.2 输入框 — 现状散乱（临时约定）

**没有统一输入框组件**。改造时若新建表单输入，按此约定保持风格：

- 背景：`holoCardBackground`，圆角 `HoloRadius.md`，padding 用 `HoloSpacing`。
- 占位符色：`holoTextPlaceholder`。
- **禁止**沿用裸 `TextField` + 硬编码 `cornerRadius` / `padding`（如 `ChatInputView` 的旧写法不应被复制）。
- 金额输入用现成组件 `Components/AmountInput.swift`。

### 8.3 弹窗 / Sheet — 统一壳（2026-09-27 起）

约 112 个 `.sheet`。**任何 sheet / fullScreenCover 内容根部必须套 `.holoSheetShell()`**（`DesignSystem.swift`），它提供品牌暖底（`holoBackground` 铺满安全区）+ 隐藏 List/Form 系统灰底。不套壳 = 弹层露系统默认白/灰底——2026-09 健康洞察证据页、分步推进提案层两次因此被打回，此为品牌色问题最高发源。

- 新建弹层：根部第一修饰符就写 `.holoSheetShell()`，与 `presentationDetents` 顺序无关。
- 遇到无壳存量弹层顺手补上；特殊底（图片画廊黑底、法律文档 WebView 白纸、分享卡渐变）不套。
- **内部状态字样禁止上 UI**：来源/降级/兜底等定性信息（如「使用本地兜底」「Local fallback copy」）只进日志与诊断页，caveat 类用户可见字段只能是用户语言（本次事故：兜底洞察把内部来源标记当 caveat 渲染，被用户直接看到）。
- 能确定高度的优先用 `.height(N)`，N 取整（200 / 320 / 400 / 480…），避免 `.medium` 在不同机型高度不可控。
- 统一显示拖拽指示器 `.presentationDragIndicator(.visible)`（现状多数缺失，新建/改造时补上）。
- 弹层内容的**排版骨架**（三区结构、说明文字左对齐、按钮贴底）见 §8.7 第 6 类及定式 8-10；「套了壳但内容居中堆一坨」同样按版式缺陷打回。
- 内容区圆角用 `HoloRadius`，不硬编码。
- 聚焦 `UITextView` 时弹 `confirmationDialog` 有失焦竞态（见记忆 [[confirmationdialog-uitextview-race]]），改用 `.sheet(item:)`。

### 8.4 SF Symbol 图标 — 颜色统一，尺寸待收敛

`Image(systemName:)` 约 600 处，密度极高。

- **颜色**：✅ 走 token（`holoPrimary` / `holoTextSecondary` 等），统一。优先用 `.foregroundStyle`，不要用已废弃的 `.foregroundColor`。
- **尺寸**：⚠️ 散落约 18 种 size。约定收敛到以下档位：

| 档位 | size | 典型用途 |
|---|---|---|
| 极小 | 10–11 | 轴标签、角标 |
| 小 | 13–14 | 行内图标、说明 |
| 标准 | 16 | 导航、列表行图标（最常用） |
| 中 | 18–20 | 入口卡片图标 |
| 大 | 24 | 中央功能按钮 |

- 新增图标优先选上表尺寸；**新增/修改 SF Symbol 名称必须先验证存在**（`NSImage(systemSymbolName:) != nil`），无效名称渲染空白（见 `CLAUDE.md`）。

### 8.5 底部导航

参考 `Components/BottomNavBar.swift`：3 项（个人 / 中央 AI / 记忆长廊），浮动毛玻璃 `ultraThinMaterial` + `HoloRadius.xl`；左右文字按钮图标 size 16 + `holoTinyLabel`，选中 `holoPrimary`；中央 AI 按钮凸起 `Circle` 56×56 `holoPrimary` + sparkles 图标 + `offset(y: -24)`。**首页结构禁止改动**（见记忆 [[goal-feature-elevate-to-mainline]]）。

**顶栏返回按钮位置（2026-10-15 东林设立）**：页面级/模块级「返回」按钮（chevron.left 语义）一律放**顶栏最左**，全 App 已统一（财务/习惯/任务/健康/长廊/纪念日/想法同口径）；右上角只放设置/新增/菜单等操作按钮。改版挪动顶栏元素时必须复查返回键是否仍在最左——想法模块曾因「收起箭头改返回箭头、位置没挪」把返回键留在右上角被打回。时间翻页控件（◀ 日期 ▶ 成对出现）不算返回，不受此条约束。


### 8.6 Toast

用 `Views/Components/HoloToast.swift`，不要自建浮层提示（避免全屏透明视图拦截触摸，见踩坑速查表）。

### 8.7 文字版式与容器适配（防溢出 / 防错位，2026-10-11 东林设立）

> 背景：UI 验收反复打回的五类版式硬伤。这类问题编译不报错、单元测试测不出，只能靠走查发现，故立为硬约束。ios-qa 走查已把五类缺陷列为每张截图的默认判读项（见 ios-qa 铁律四）。

**六类禁止出现的版式缺陷（2026-10-11 东林设立，第 6 类同日补）：**

| # | 缺陷 | 判定标准 | 已发生案例 |
|---|------|---------|-----------|
| 1 | **意外换行** | 本应单行的文字（金额、时间、标签、按钮文案、行内说明）在常规机型被挤成两行 | 拍立得卡 caption 时间戳与 6 行长文同行竞争被挤压（9ca918f2c 修） |
| 2 | **顶格错位** | 同层元素左缘/右缘不齐，或与页边距、容器内边距不一致（视觉上「贴边」「凸出去」「缩进来」） | 长廊带图想法卡走满宽特写行，与「时间列+卡」行结构不齐（9ca918f2c 修） |
| 3 | **文字冒出胶囊** | 胶囊/徽章/chip/标签内文字溢出圆角边界，或字形被边界裁切 | 时间门 76pt 大数字负字距把布局宽度算短，末字符被裁（9ca918f2c 修） |
| 4 | **上下不一致** | 同一行内元素垂直中线不对齐；卡片上下内边距不对称；同类卡上下留白不同 | ——（预防性条款） |
| 5 | **不协调** | 新元素与所在页面既有语言明显打架（字号/间距/圆角/颜色/形态不同档） | 任务「拆开」通栏品牌胶囊大按钮与嵌卡语言冲突，被打回重做行式入口（0cb1cf8d5） |
| 6 | **弹窗无排版** | 弹层内容默认全部居中堆放：无「头部/内容/操作」三区结构与分区手段（分隔线/底色/分组容器），整段说明文字居中，近全屏弹层按钮悬空不贴底 | 「拆成这 4 步」确认弹窗：头部三行全居中、三区边界靠猜、说明文字居中顶满边距、近全屏面板内容悬空中部按钮不贴底、步骤名截断省略号（2026-10-11 东林实报） |

**预防定式（写代码时执行）：**

1. **最长文案先行**：任何装文字的容器，先用现实最长值（最长用户输入 / AI 输出、Dynamic Type 放大一档）验证放得下，再调短文案的样式。动态文字（用户输入、AI 生成、多语言）禁止按短样例定宽。
2. **单行语义三件套**：单行语义的文字 = `lineLimit(1)` + 明确截断模式（`.truncationMode(.tail/.middle)`）+ 宽度弹性安排（`layoutPriority` / `ViewThatFits` 降级），三件齐备才放进紧凑行。禁止靠被动换行兜底。
3. **胶囊内边距下限**：胶囊 / chip 水平 padding ≥ `HoloSpacing.sm`(8)，文字 `lineLimit(1)`；文字宽度可变时容器随文字自适应，不定宽硬塞。
4. **负字距/特殊字距必实测**：tracking 为负或收紧字距时，布局算出的宽度可能短于实际字形宽度，末字符会被裁——必须实测渲染宽度（大数字、等宽金额高危）。
5. **行结构复用**：同一列表新增卡型时复用既有行骨架（时间列 / 缩进 / 左右缘常量用同一套），不自建对齐口径。
6. **行内对齐显式声明**：图标+文字+数字混排行统一 `alignment: .center`，字号档位相近才放同行；上下 padding 对称取值。
7. **新元素先找同构**：新组件先抄同页最近的同类组件（同字号档 / 间距档 / 圆角档 / 色 token），确无同构再回本规范选档——与既有语言打架的「更好看」按不协调打回。
8. **弹层三区骨架**：任何弹层（sheet / 自定义浮层 / 确认卡）内容按「头部区（标题+说明）→ 内容区（列表/表单，**左对齐**）→ 操作区（主按钮）」三区组织，区与区之间用固定间距或分隔线明确分开，禁止三区边界靠猜。头部只有一行短标题可居中；**说明文字一律左对齐**（与内容区同口径），禁止整段说明居中——文案变长换行后居中多行不可读。
9. **近全屏弹层按钮贴底**：近全屏 / 大高度弹层的主操作按钮固定贴底部安全区，内容不足时用弹性空隙下推；禁止按钮悬在屏中部、上下各留大片空白。内容密度低的弹层优先收紧 detent 高度（§8.3），而不是放大留白。
10. **弹层内功能图标分组**：同一行功能不同的图标（如「标注」与「删除」）必须拉开间距并做视觉权重区分（删除/危险类用次要色或更小尺寸），禁止同尺寸同色并排（易误读误触）。

> 与 V2 条目的关系：V2「大字体拥挤时可换行或分组」指**主动设计**的换行/分组，不受本节限制；本节禁的是**被动**的——设计预期单行却被挤爆的换行。

**验收定式**：涉及对齐 / 宽度的改动，验收点必须数值化（如「卡左缘 = 页边距 20 + 时间列 46 + 间距」），禁止只写「看起来对齐」——目测判读已被实证不可靠（装饰环撑大光球事故）。

### 8.8 弹层脚手架与返回/关闭语言（2026-10-17 口径收敛）

> 本节为全 App 弹层与导航语言的统一口径。新弹层一律用 `Components/HoloSheetScaffold.swift` 起壳（标题 + 左上关闭 + 右上主操作 + 拖拽条 + 贴底主按钮）；存量弹层按 §十三路线分批迁移。规则如下：

1. **返回与关闭语言**：推入页返回＝白圆底 chevron；弹层关闭＝左上 X 圆钮；全屏编辑页＝左上关闭＋右上主操作；所有弹层必须带拖拽指示条（`.presentationDragIndicator(.visible)`）。
2. **弹层操作唯一性**：一个弹层只允许一个主操作按钮＋一个关闭；主操作＝实心 `holoToolAction` 胶囊、贴底、44pt 热区、文字 `holoToolOnAction`。
3. **分段控件唯一样式**：分段控件选中＝灰轨道＋白色浮起块，全 App 唯一样式；禁止下划线式、纯变色式变体。
4. **字号档位口径**：模块主页大标题＝左对齐 28pt 档；区块标题 20pt、正文 17pt、辅助 15pt、注释 13pt（对应 `holoText` 档位 pageTitle / sectionTitle / body / supporting / metadata）。
5. **空态四件套**：图标＋标题＋说明＋动作，四件齐全才出门。
6. **口径表**：日期列表 9/28、详情 9月28日 周一；任务量词「项」；金额小数两位、仅负值染红、零值不染色。

### 🔴 组件红线

- 主 CTA 按 §8.1 写，**不要自创按钮配色/高度/圆角**。
- 新输入框/弹窗按 §8.2 / §8.3 约定，禁止复制旧散乱写法。
- 图标颜色走 token，禁止硬编码；尺寸收敛到 §8.4 档位。
- 胶囊/标签/单行文字按 §8.7 验证最长文案与对齐口径，禁止裸放动态文字进定宽容器。

## 九、深色模式

**机制**：颜色全部走 Asset Catalog 的 colorset，**系统切换深浅模式时自动适配**，代码里只写 token 名（如 `Color.holoBackground`）。
用户还可在设置里手动覆盖（跟随系统 / 浅色 / 深色），由 `Utils/DarkModeManager.swift` 通过 `preferredColorScheme` 应用。

### 🔴 深色模式红线

- **禁止 `if colorScheme == .dark` 判断颜色**。需要 light/dark 不同的色，在 colorset 里配两套值。
- 个别确需按模式区分的**非颜色**逻辑（如热力图色阶），用 `HoloDesignSystem` 提供的 `colorScheme` 参数函数，不要自己 switch hex。
- 新增语义色时，**同步在 colorset 配好 Light + Dark 两套**，否则深色模式会穿帮。

## 十、红线汇总（禁止清单）

> 改造前、改造后各过一遍。

1. ❌ 硬编码颜色 hex / RGB —— 必须走 `DesignSystem.swift` token
2. ❌ `if 深色模式` 判断颜色 —— 用 colorset 自动适配
3. ❌ 裸写 `.font(.system(size:))` 当正文字号 —— 用 `holo*` 字体 token
4. ❌ 魔法数字间距 —— 用 `HoloSpacing`
5. ❌ 硬编码圆角 —— 用 `HoloRadius`
6. ❌ 手写卡片外观 —— 用 `.holoCard()`
7. ❌ 直接用 `UI*FeedbackGenerator` —— 用 `HapticManager`
8. ❌ 自创主按钮样式 —— 按 §8.1
9. ❌ 图标尺寸随意开新值 —— 收敛到 §8.4 档位
10. ❌ 复制旧的散乱输入框/弹窗写法 —— 按 §8.2 / §8.3 约定
11. ❌ 未验证就写 SF Symbol 名称 —— 先 `NSImage(systemSymbolName:)` 验证
12. ❌ 裸写动画魔法数字（`.easeInOut(duration:)` / `.spring(...)`）—— 用 `HoloAnimation.*` token
13. ❌ sheet / fullScreenCover 内容根部不套 `.holoSheetShell()` —— 露系统白/灰底（品牌色问题最高发源，见 §8.3）
14. ❌ 内部状态字样（兜底/降级/来源标记）写进用户可见文案 —— 只进日志与诊断页，见 §8.3
15. ❌ 单行语义文字被动换行、动态文字塞定宽胶囊不验最长文案 —— 见 §8.7
16. ❌ 新元素自建对齐/行结构、与同页语言不协调 —— 复用同构组件，见 §8.7
17. ❌ 验收只查「元素存在/无叠压」就交付 —— 必须过「挑刺儿三问」（外行看得懂/最惨态体面/整体协调），数据类 UI 必须实测最惨稀疏态，见文首 2026-10-12 节

## 十二、精细化实施规则（2026-10-14）

- **真实反馈**：只有保存/删除/恢复成功才提示完成；失败保留输入和最后有效内容，并给可重试入口。异步动作禁止用 `try?` 掩盖失败后继续提示成功。
- **业务状态色**：说明、警告、成功、失败、信息和 AI 来源文字使用 Tool 语义色；状态色不用于替换用户分类色、习惯色或图表系列色。正文与辅助说明不得叠加低透明度降低可读性；装饰、禁用态、网格线单独处理。
- **可触区域**：`HoloIconButton` 提供 44×44pt 热区和可访问名称；图标大小与触摸区域分开。小型按钮也必须可操作，不能只给图标一个名称而遗漏热区。
- **长内容与大字体**：正文不可按短样例定宽；标题、说明、主要按钮允许主动换行。胶囊只放短状态，长动态内容使用可换行的行或段落。金额与单位一起核对，不能只看到裸数字。
- **单一保存**：确认页已经完成事务的结果由回执驱动；页面不得再次补写一份“保存成功”状态，失败时也不能诱导重复提交。
- **品牌保护检查**：`scripts/verify-visual-v2.py` 按品牌色、背景、绝对时间动画参数及绘制隔离分别检查，正文/按钮对比度独立运行，任何失败都不遮蔽其他检查。源码契约不等同于像素/真机验收。
- **对比度门槛边界**：正文和辅助文字按 ≥4.5:1 检查，包括已登记的 10% 状态淡底合成；品牌按钮沿用已批准的 ≥3:1 产品约定，不能据此宣称普通按钮文字满足 WCAG AA。
- **能力核对**：视觉改版前后同时核对语音、复制、手势、返回、撤销、输入保留和保存反馈，不以“新页面可渲染”代替能力完整性。
- **整行命中**：列表里的 `.buttonStyle(.plain)` 不能只给文字热区；带 Spacer 的 label 显式铺满可用宽度，并在 label 内声明 `contentShape(Rectangle())`。点选后必须验证弹层关闭或状态变化，不能只查背后元素 exists。
- **独立操作**：展开内容的按钮、输入框不得放进标题按钮的 label；撤回等独立按钮不与说明文字做 `.accessibilityElement(children: .combine)`，使用 `.contain` 保留独立访问。
- **回车语义**：先明确回车是提交还是换行。新增步骤名使用单行提交并保持聚焦；保存失败不清空输入，错误弹窗导致失焦时不得自动再次提交。
