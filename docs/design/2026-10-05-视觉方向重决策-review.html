3决策链：三个问题按顺序过

Q1
「米白 + 赤陶按钮」这个调性，你喜不喜欢？
只看上面中间那格。喜欢 → 选项 A；不喜欢但想要排版优化 → 选项 B（推荐窗口）；连排版改动也不想要 → 选项 C。
Q2
决定了方向，接受对应的成本与周期。
见下方三选项的成本对比——回退反而最贵，因为 87 个文件已与动效批次、其他在途改动纠缠，快照又放在临时目录（随时会清）。
Q3
无论选哪个，两条防线必须同时立。
① 真机包只从已提交的代码构建，半成品永远不再上你手机；② 在途批次收尾必须过全量回归（1618 测试 + 既有走查），不再用「自建 3 用例」当验收。

A · 全盘接受

「赤陶调我认可，做完它」
  • 保留现方向，补完 69 处混用 + 页面框架层 + 嵌套卡缺口
  • 补全量回归 + 真机走查后统一装包
  • App 最终 = 米白底 + 砖红按钮的安静风
成本：中高（新改动分布在几十个文件）｜周期：数天｜风险：中（改动面大，需整轮回归）
推荐窗口

B · 保结构、换回品牌色

「排版优化留下，颜色回到 Holo 橙」
  • 8 个颜色文件的值对齐品牌体系（按钮 #B44B28 → #F46D38 系）
  • 习惯磁贴恢复「习惯色淡底 / 完成实底反白」
  • 保留：字体层级、44pt 热区、去花哨动效、深色模式、无障碍达标
  • 改动集中在色值层，85 个文件的结构优化不用动
成本：低（色板集中，改值全局生效）｜周期：半天~一天＋回归｜风险：低

C · 整体回退

「全部恢复到改造前」
  • 按 87 文件清单逐文件恢复，保留其他会话的在途改动
  • 排版/热区/无障碍优化一并丢弃
  • 回退快照在 /tmp，正在过期的路上，要做就得快
成本：高（逐文件手术＋与其他批次解纠缠）｜周期：数天｜风险：高（手术面最大）
