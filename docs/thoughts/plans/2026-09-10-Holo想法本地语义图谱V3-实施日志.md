#### 新发现的事实（方案未提及，实施需纳入）

1. **PromptManager 完整实现仅 DEBUG 编译**：Release 为 stub（`loadPrompt` 抛错），生产 prompt 完全依赖后端注入。「iOS 后备模板与后端同步」的约定仍成立，但 Release 不消费本地模板。涉及 `PromptManager.swift:12, ~1600`。

3. **限流真实数字**：thought_organize 端点 20/分、**500/日**（`config.js:507-510`）；thought_embedding 与 personal_context_embedding 均 20/分、**120/日**（`config.js:245-248, 306-309`）。方案 13.3 的「120 请求/日」对 embedding 回填成立。

5. **no-store 非全局中间件**，逐端点手动添加；新端点必须记得加。
6. Core Data 实体为**纯代码程序化定义**（`NSEntityDescription`），无 .xcdatamodeld；新增 `ThoughtTopicLink` 实体照此模式在 `CoreDataStack+ThoughtEntities.swift` 添加。

### 核心设计决策

1. **镜像原则**：Phase 1 的 link 层 pair 集合完全镜像旧 relationship（读仍以旧为主），只叠加来源/状态/可见性语义——shadow 差异天然归零，旧 UI 零感知。
2. **存量映射（保守）**：topicAssignmentReason 非空 → legacy/ai；其余（含 confidence==1 无法与 AI 恰满区分）→ legacy/unknown。宁 legacy 不伪造用户决定（方案 §18.2）。visibility 一律 internal。
3. **已知妥协（在档）**：V2 applyClassification 通道重建用户拒绝过的 pair 时，link 层如实镜像翻回 active（V2 覆盖用户决定是 V3 根治对象；墓碑压制在 Phase 3 的 ai/v3 写入路径生效）。测试已锁定该行为并注明。
4. **重复行收敛**：upsert/统计按语义对（thought+topic）而非行 ID——多设备 CloudKit 竞态的异形 ID 重复行也能收敛（superseded）。
