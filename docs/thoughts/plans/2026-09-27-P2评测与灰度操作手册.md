# P2 · 评测与灰度操作手册（想法主题归类）

日期：2026-09-27。前置：P0 数据一致已交付（四处一致/墓碑/补跑/标签解耦全绿）、P1 感知层已交付（来源字样/轻点导航/构成行/交集桥/归入回执）。
本手册是 P2 的执行规程——**P2 的每一步都依赖真实数据或东林拍板，不可由 Agent 单方面宣布完成**。本文件本身交付的是「可直接照做的操作定义」，不是评测结果。

## 1. 冻结样本集（第一步，人工环节）

### 1.1 样本格式（frozen samples JSON Schema）
```json
{
  "sampleSetId": "thought-relation-eval-v1",
  "frozenAt": "ISO8601",
  "modelVersion": "text-embedding-v3-v1",
  "engineVersion": "thought_semantic_v3.0",
  "samples": [
    {
      "id": "S001",
      "scenario": "same_topic_high",       // 场景标签，见 1.2
      "topicTitle": "日本旅行",
      "memberExcerpts": ["想带妈妈去日本…", "查了东京住宿…"],  // 已有主题的 3-5 条真实成员（去标识化摘录）
      "newThoughtText": "假期可能只有五天…",  // 待判定的新想法
      "humanLabel": "high",                // 人工标注：该新想法应 high/medium/low/none 归入该主题
      "labelReason": "与成员同一出行计划"    // 标注理由（复核用）
    }
  ]
}
```
去标识化纪律：摘录经 `ThoughtIndexV2Policy.redactedText` 同款规则脱敏（email/电话/身份证→占位符），人名地名保留业务语义所需最小集。

### 1.2 场景覆盖矩阵（每场景 ≥10 条，总量 ≥120 + 留出集 30）
| 场景 tag | 说明 | 预期 majority |
|---|---|---|
| same_topic_high | 确属某既有主题、正文足以判断 | high（召回分母） |
| similar_not_same | 主题相近但不是同一方向（钓鱼 vs 游泳） | none/low |
| cross_topic | 一条想法涉及两个方向 | 至多一个 high |
| multi_tag_no_topic | 多标签但无对应主题 | none |
| same_name_tag_topic | 标签与主题同名 | 互不干扰 |
| irony_shift | 反讽/观点转变 | none/low |
| short_sentence | 短句（<15 字） | 允许 none（合法空） |
| image_heavy | 图片为主 | 允许 none |
| cross_day_repeat | 跨日重复粘贴 | 去重不重复归 |
| edited_deleted | 编辑/软删后旧关系失效 | 失效 |
| user_rejected | 已被用户拒绝过的 pair | 不复活（精确率分母） |

### 1.3 冻结与留出
- 标注完成 → 文件存 `docs/thoughts/eval/thought-relation-eval-v1.json`，记录 SHA256 于本手册附表；此后**不得修改**（发现标错→新增 v2 集）。
- 留出集 30 条单独成文件，**从未参与任何阈值调参**，只在最终门禁跑一次。

## 2. 校准配置（第二步）
1. 用冻结集（非留出）跑 shadow（relation=shadow）收集 score_features + verifier 结论；
2. 网格搜索 `recallMinCosine / marginMinDelta / neighborVoteMinCount`，目标：high 精确率 ≥95% 且召回最大化；
3. 生成 `Holo/Holo APP/Holo/Holo/Resources/ThoughtSemanticCalibration.json`（字段：modelVersion、calibrationVersion、recallMinCosine、marginMinDelta、neighborVoteMinCount、candidateExpiryDays、sampleSetId、results{precision, recall, perScenario}）；
4. 验证：Debug 构建启动日志确认 `isCalibrated=true`（否则 relation=.on 仍回退 shadow）。

## 3. 质量门（第三步，留出集一次性判定）
- **high 精确率 ≥95%**（user_rejected 场景 0 复活）；
- **严重误归 = 0**（similar_not_same / irony 场景产出 high 即严重）；
- 召回 ≥60%（same_topic_high 中正文足以判断的子集）；
- 任一不过 → 停在 shadow，改候选/证据链，禁止降阈值硬出。

## 4. 灰度与放量（第四步，每步东林拍板）
1. 内部真机 shadow 一周（relation=shadow，观察 relation_candidate 表分布）；
2. 小比例 relation=on（改 `ThoughtSemanticFeatureFlags` 默认或远端配置），观察卡片归入回执/纠错率；
3. 每步核对生产：后端路由 env、`/v1/prompts/meta` 的 source/version/digest、真实 provider、最小真实请求；
4. 成本实测：日常单条 relate 的 token/金额/P50/P95；目标单条几分钱以内；补跑另设按日上限。

## 5. 回退演练（上线前必须走过一遍并记录）
- [ ] 关 relation（shadow/off）→ 新自动关联停止；**已落的 AI link 保留展示**（版本化投影规则决定，不靠关 flag 留半套 UI）；
- [ ] 关 `ThoughtSemanticFeatureFlags.uiEnabled` → 隐藏 AI 新 UI，侧栏导航保持开放；用户标签/手动主题/拒绝墓碑不受影响；
- [ ] 侧栏导航需要回退时发布新版本恢复旧导航；本机旧灰度值已不生效，侧栏数据无残留影响；
- [ ] 「删除设备智能索引」→ 向量/候选/簇可重建（backfill bootstrap 重新入队）；
- [ ] 后端 semantic-relate 隐私闸门关闭 → 客户端 relate 任务全部失败重试终态，不影响记录/标签/手动主题/字面搜索。
