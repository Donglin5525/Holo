# 想法编辑器体验体检与改造计划

## 产品目标

把想法模块从“能输入、能保存”提升为“输入顺手、内容关系看得懂、编辑和阅读一致”的长期基础能力，体验基线对齐主流文本输入软件，而不是继续在单个页面上做局部修补。

## 当前巡检结论

### P0：用户已经明确感知的问题

1. 键盘工具栏使用半透明玻璃背景，和想法编辑器的卡片背景叠加后显脏；按钮组横向间距和视觉占用偏大。
2. 颜色面板的“重置颜色”不是用户需要的状态。当前清除颜色后，光标处的旧颜色又会被 contextual 格式推断恢复，造成点击无效的错觉。颜色应包含一个普通的黑色选项。
3. 选中文字转任务后，任务作用范围必须是持续可见状态，不能只依赖一次性反馈动画；动画还会触发 `UITextView` 拆分引用属性区间，导致一次引用被序列化成多个引用。
4. 详情页使用结构化富文本渲染，卡片外层却使用另一套纯文本清洗逻辑；`@引用`、任务标识和富文本样式因此可能出现内外层不一致。

### P1：从代码结构确认的体验风险

1. 编辑态和外层阅读态此前不是同一套正文基线：编辑器曾固定 16pt，卡片正文是动态 17pt；本轮已统一到系统 Body 17pt 动态字号和约 6pt 行间距，仍需在真实设备继续观察中文输入法组字和极端字号。
2. 引用候选面板、编辑器 Token、详情页 Token、卡片预览各自有截断和展示规则，后续容易出现“候选项看到的标题”和“插入后的 `@标题`”不一致。
3. 任务、引用、标签都属于不可拆分的 Token，但删除、重新编辑、复制粘贴、选区跨 Token、任务完成状态等边界还没有形成一套统一验收矩阵。
4. 编辑器最小高度、底部内边距和语音入口共同制造了较大的空白区域，需要和工具栏一起做真实输入场景验收，不能只看单个控件尺寸。

### 本轮深测新增结论

1. `@` 数据先以纯文本创建、再异步加载 `richContentJSON` 时，编辑器需要重新水合结构化节点，否则颜色看似存在但点击身份已经丢失；现已补齐并在 Simulator 验证内层点击可跳转。
2. 任务转换的作用文字使用持久下划线，任务标记与引用 Token 同时存在时，最终富文本节点应保持“一条任务 + 一条引用”；已移除会破坏 Token 属性边界的布局动画，并用 Core Data 读取结果验证该约束。
3. 当前真实回归记录中，编辑器工具栏无障碍描述为“文字样式”，视觉使用画笔 SF Symbol，不再使用“格式”中文按钮；Simulator 的大字号路径中完成按钮仍保持勾选图标，真实设备仍需检查图标辨识度。
4. Simulator 真实截图显示短内容仍被 360pt 最小高度撑成大块空白，录音入口漂在空白区；“完成”按钮也被系统默认样式放大成重胶囊。已收敛为 240pt 起步高度、较小底部安全空间和 plain 按钮。
5. 普通格式重算会经过 `resolvedAttributes`；任务作用范围的下划线不是用户手动下划线，必须在加粗/改色/改格式后仍保留。Token 也必须按身份合并属性区间，不能按 UIKit 的属性段数量生成业务节点。
6. @ 候选搜索虽然有 150ms 防抖，但仅取消旧 `Task` 不足以阻止已经开始的 Core Data 查询回写；快速连续输入时旧候选可能覆盖新候选。已加入请求序号校验，查询前后都确认仍是当前输入。
7. 候选浮层目前用固定宽度和估算高度定位，长标题、横屏/iPad、光标靠近底部时仍可能遮挡正文或越界；候选项也没有硬件键盘上下选择/回车确认，需要作为引用体验专项继续验收。
8. 粘贴和程序化格式操作曾没有独立的 Token 语义剪贴板与可验证的撤销/重做单元；本轮已补上应用内结构化剪贴板、外部纯文本归一化，以及包含文字/Token/光标的程序化撤销桥，仍需真实设备验证系统菜单和撤销粒度。
9. 候选浮层已从屏幕尺寸估算改为读取编辑器实际容器宽高，面板宽度、上下翻转和边界均按当前容器计算；仍需用横屏/iPad/底部光标真实路径确认 GeometryReader 不影响编辑器触摸。
10. 候选项标题此前没有复用 Token 的截断规则，长标题会出现“候选项”和插入后的 `@标题` 不一致；现已统一为同一展示文本，并清理正文首字符多余的 `@` 前缀。
11. 取消任务标记时此前只检查作用范围首字符是否有用户下划线，混合格式可能导致后续字符的手动下划线被误删；现已按子区间保存并恢复用户格式。
12. 编辑页外层滚动原本禁止交互式收键盘，长文输入只能依赖“完成”或额外点击；现已在外层和实际承载长文的 `UITextView` 同时启用交互式收键盘，Simulator 已用长文下滑确认键盘可收起，真实键盘和设备仍需复核。
13. 工具栏显式插入 `@/#` 时，如果光标紧贴英文、数字或路径字符，原触发位置规则会让候选面板不出现；现已自动补一个分隔空格。真实 Simulator 路径已确认 `Hello` 后点 `@` 会出现候选列表，候选点击后正文显示为行内 `@Token`。
14. 深色模式下已检查编辑卡片、任务色、`@Token`、录音入口和颜色面板：背景、边框、文字对比度和黑色色块仍可辨识；Simulator 也已覆盖大字号、长文输入和拖拽收键盘，动态字体极限档位、真机键盘和长文手势仍需单独验收。
15. 对照公开产品资料后，主流写作体验的共同点不是堆更多格式按钮，而是把写作区保持干净、把能力放进键盘上方工具栏或二级菜单，并保证正文可调字号、可读行长、CJK 排版和专注写作状态。Notion 移动端采用键盘上方工具栏，iA Writer 强调编辑与格式预览分离并提供字号、CJK 排版和 64/72/80 字符行长设置；Holo 后续以“低干扰主界面 + 可发现的二级能力 + 统一正文基线”作为产品方向。
16. 颜色面板已把色点视觉尺寸与触控尺寸分离：视觉色点 32pt、按钮热区 44pt；面板高度同步调整，并按安全区约束上边界，避免小色点难点或浮层越界。
17. 连续插入同一条笔记时，原实现仅用实体 ID 判定 Token 身份，两个独立 `@Token` 会在序列化、点击或删除时被合并；现已增加独立 Token 实例 ID，并补充相邻同目标引用的回归用例。真实 Simulator 已确认两个引用可同时显示并可点开操作菜单。
18. 真实 Simulator 截图发现浅色模式下品牌橙作为 Token 正文色偏浅，长标题可读性不足；现改为浅色深橙、深色浅橙，背景色仍沿用品牌橙低透明度。
19. 当前构建已通过硬件键盘路径验证候选面板：方向键移动、回车提交、Escape 关闭均生效；Escape 会保留用户已输入的 `@`，不会误删正文。
20. 当前构建已通过一次编辑撤销/重做路径验证：撤销移除工具栏插入的 `@`，重做恢复 `@` 并重新进入候选态；Token 属性与光标状态的更复杂组合仍需继续覆盖。
21. 任务标记原先只保存 `displayText`，重进时通过向前搜索重复文本恢复下划线；现新增 `sourceLength` 写入 rich JSON 和富文本属性，按任务标记前的结构长度恢复作用范围，并对旧 JSON 用快照 UTF-16 长度兼容。
22. 本轮尝试用 Simulator 的系统复制/粘贴路径验证应用内语义剪贴板，但系统选区复制没有可靠地产生可粘贴内容，新编辑器粘贴后仍为空白；语义剪贴板代码已编译，跨编辑器实际保留 Token 身份仍不能算通过，需在真机和系统菜单路径单独复核。
23. 首次新建想法后立即点击“转为任务”时，自动保存虽然已经创建了草稿，但 SwiftUI 状态更新存在时序差，任务面板可能拿不到刚创建的想法；现改为让落库方法同步返回持久化 ID，再按 ID读取来源想法。
24. 编辑器字号原本只在创建 UITextView 时按当前字号计算，用户在编辑过程中切换动态字体档位时，正文和任务标记不会一起刷新；现已监听字号环境变化并重新水合节点、保留选区和光标。
25. Token 的键盘光标边界此前在 Token 起点会被错误吸附，方向键向后移动可能卡在起点；现允许起点作为可遍历边界，向前/向后分别跳到 Token 两侧，点击仍按最近边界处理。
26. 应用内复制的纯文本不能直接使用 NSTextAttachment 或 Markdown 原文，否则外部粘贴会出现不可见占位符或 `**` 等编辑标记；现对外输出可见纯文本，对内另存结构化 JSON，系统菜单路径仍需真机复核。
27. 选中多行文字转任务时，确认面板原本可以创建多个任务，但编辑器回调只插入第一个任务标记，后续任务看不出对应原文；现已按“选中一段文字 = 创建一个任务”的产品语义收敛为单候选，并隐藏该场景下没有明确映射意义的 AI 拆分入口。整篇想法的逐行任务提取仍保留多任务模式，后续需单独设计原文范围映射。
28. 最新 Debug 构建在 iPhone Simulator 中完成了“选中词语 → 确认创建一个任务 → 返回编辑器 → 保存退出”的真实路径：确认面板文案与单候选一致，编辑器和外层卡片均能看到原文下划线，Core Data 的 rich JSON 保存了 `sourceLength`。
29. 通过真实候选面板插入的 `@` 引用已写入 Core Data 结构化 JSON；重进编辑器时继续显示橙色 `@标题`，点击 Token 可打开操作面板并进入详情页，详情页主内容与列表卡片均能显示引用文字。系统手敲 `@` 紧贴英文单词时仍遵循“词边界不触发候选”的规则，需要后续决定是否对 CJK/普通正文放宽。
30. 在 iPad Simulator 上完成竖屏和横屏检查：正文宽度、工具栏图标、键盘上方候选浮层均未截断或越界；横屏候选浮层仍贴近光标左侧，工具栏视觉高度没有随屏幕放大。
31. 系统快捷键直接复制完整引用 Token 的路径仍可能因 iOS 选区命中不稳定而得到空内容；现已在 Token 操作面板增加“复制引用/复制标签”，直接写入同一语义剪贴板。最新 iPhone Simulator 已验证：点击“复制引用”后，在新想法中粘贴仍保留橙色 `@Token` 身份，普通文字也能继续通过系统复制粘贴。
32. 整篇任务提取原本只创建任务，不把每条任务映射回正文；现已让候选行携带编辑器可见文本范围，按原文位置批量插入多个任务关系标识，并以一次撤销单元提交。最新 iPhone Simulator 已验证两条任务各自下划线、保存重进后仍保留；AI 拆分结果只有在标题在正文中唯一命中时才自动映射，重复或无法确认的结果不误标。
33. `@` 候选浮层此前只显示标题，用户从 `@` 入口进入后仍要靠上下文猜它是引用；现让候选标题也显示 `@` 前缀，并在 iPhone Simulator 里确认候选项、插入后的 Token 和外层列表都采用同一前缀语义。
34. 任务关系不仅要在保存重进时正确，编辑期也要跟随正文：现已支持作用范围内插入/替换时继承任务下划线、删除时收缩 `sourceLength`，并修复键盘直接删除任务标记后残留下划线的问题；iPhone Simulator 已验证替换、范围内插入、撤销/重做、保存重进和键盘删除任务标记。
35. 取消 `@`/`#` Token 关系原本会用基础属性重建普通文字，可能丢失用户在 Token 上施加的颜色、粗体、下划线或任务作用范围；现改为只清理 Token 身份，保留用户格式，补充了节点管线回归用例。
36. 长标题引用在正文内保留短 Token 是必要的排版取舍，但操作面板不能再次只显示同一段截断文字；现补充来源首行摘要，让用户能确认“这条 @ 到底指向哪条想法”，同时不让正文被长标题撑坏。
37. 本轮新增引用来源摘要后，Thought App 主 target 的 iOS Simulator Debug 构建再次通过；Swift 语法解析与 `git diff --check` 也通过。当前仍不把 HoloTests target 误报为已执行测试，系统选区直接复制完整 Token、中文真键盘组字和 VoiceOver 仍列入下一轮真机/专项验收。
38. 本轮继续统一任务作用范围入口：键盘、语音、普通粘贴、应用内结构化粘贴以及工具栏插入的文字/`@`/`#` 都会继承目标任务下划线；替换任务标记或删光作用文字时会清理旧关系，避免残留下划线或孤立“任务”附件。只读富文本同时补充任务与引用的辅助功能语义，避免 `NSTextAttachment` 被读成无意义占位符。Swift 语法解析和 `git diff --check` 通过；全 App 构建本轮被工作区另一处并发的 AI/聊天改动阻断，未将其误报为想法模块失败。
39. 中文输入法组字此前不经过任务范围编辑分支，可能让新输入文字脱离任务下划线；现把当前任务 ID 带入 `typingAttributes`，组字提交后只刷新任务 `sourceLength`/孤立标记，不重建全文，降低光标跳动风险。最新 `/tmp/HoloThoughtsDeepDerived19` 全量 Debug Simulator 构建成功并已安装到独立 Holo Simulator；真实中文键盘组字和 VoiceOver 仍需切换到对应 Simulator 窗口后验收。
40. 列表续行和当前行插入列表原先用 Swift `Character` 数量推算 UIKit 的 UTF-16 光标位置；前文包含 emoji、旗帜或组合字符时会把前缀插到错误位置。现统一通过 `NSString` 的 UTF-16 换行区间计算行首；`/tmp/HoloThoughtsDeepDerived21` 全量 Debug Simulator 构建通过。
41. UTF-16 行首算法已提为 `MarkdownTextView.lineStart(in:before:)`，并补充 emoji/旗帜回归用例；`/tmp/HoloThoughtsDeepDerived22` 全量 Debug Simulator 构建通过。HoloTests 目前有独立 target 但没有对应 scheme，本轮不把测试源文件存在误报为已执行 XCTest。

## 统一体验基线

- 正文：系统动态字体 Body，默认 17pt、Regular 字重，不使用固定不可缩放字号；只有用户主动加粗时才提升字重。
- 行高：正文行间距约 6pt；段落之间不额外堆叠大块空白。空行、列表续行、中文输入法组字时保持同一基线。
- 横向边距：编辑器和详情正文共用 16pt 左右文本边距；卡片沿用容器内边距，但正文排版基线不另起一套。
- 引用：`@标题` 始终作为正文中的行内对象显示；编辑、卡片、详情三处显示文字一致，点击行为按页面上下文决定。
- 任务：被转化的原文持续显示细下划线，末尾保留轻量任务关系标识；重进、保存、编辑、取消标记后都保持语义一致。
- 工具栏：实体不透明背景；以 SF Symbols 表达能力，不在主工具栏展示“格式”等中文标题；保留 44pt 左右触控目标，缩小视觉图标和组间空隙。
- 颜色：调色板提供包括黑色在内的普通颜色，不再提供“重置颜色”这一特殊概念。
- Token 确认：正文内允许短显示，候选项和操作面板必须提供足够的来源上下文；不能为了省空间牺牲“我引用的是谁”的确定性。

### 公开平台基线

- Apple HIG 将 iOS/iPadOS 正文默认字号列为 17pt，并要求使用 Dynamic Type、在大字号下保持布局可读；这支持 Holo 采用系统 Body 17pt 作为输入与阅读共同基线。[Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography/)、[Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility/)
- Apple HIG 对按钮的通用建议是至少 44×44pt 触控区域；因此工具栏可以压缩视觉图标和组间留白，但不应牺牲点击热区。[Apple Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons/)
- Apple 对 Text View 建议采用 Dynamic Type，并在较大文字设置下验证可读性；后续验收必须覆盖动态字体，而不只看默认字号。[Apple Text Views](https://developer.apple.com/design/human-interface-guidelines/text-views/)
- Notion 的公开帮助文档将 `@` 页面提及作为正文内联能力，并把颜色、粗体等放在选中文字后的二级菜单；Google Docs 的 iPhone 文档也把字号、文字颜色、段落间距放在 Format/二级入口中。由此本项目采用“正文短 Token + 操作时补来源信息”的方式，兼顾阅读宽度和身份确认。[Notion 文本样式与提及](https://www.notion.com/en-gb/help/customize-and-style-your-content)、[Google Docs iPhone 格式](https://support.google.com/docs/answer/1663349?co=GENIE.Platform%3DiOS&hl=en-en)

## 推进阶段

### Phase 1：本轮基础修复

- 工具栏改为不透明卡片背景，压缩视觉高度与组间距，格式入口保持图标表达。
- 颜色面板移除重置按钮，加入黑色；修正颜色状态写入和恢复逻辑。
- 选中文字转任务：捕获真实选区，持久化任务作用范围，并在编辑/阅读态统一显示下划线。
- 任务转换不再使用会触发富文本属性拆分的布局动画，避免引用节点重复写入。
- 任务作用范围的系统下划线不被普通格式重算清除；连续且身份相同的 Token 属性段合并为一个业务节点。
