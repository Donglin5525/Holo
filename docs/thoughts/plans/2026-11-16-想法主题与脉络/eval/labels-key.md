# 标注说明(labels-key)· W4 合成评测集

冻结日期:2026-11-16 · 语义真源:实施方案 §5 C1「关系与对照的产品语义」表。本文件只做操作化,不改语义。

## 1. 关系枚举判据(照 §5 C1)

| 枚举 | 展示措辞 | 成立判据(操作化) | 本语料中的典型样本 |
|---|---|---|---|
| `continues` | 延续了这个问题 | 同一具体对象/问题;较晚一条在该问题上新增了一步(动作、经历、结论),或直接续写。 | N44→N24(出错难纠的经历之后给出原则)、N46→N36(回顾跑偏之后缩量) |
| `adds_example` | 补了一个新的例子 | 较晚一条给同一判断新增具体经历、条件或反例;reason 必须说明是正例还是反例。 | N25→N08(支付页是小步发布的反例)、N30→N07(客服场景的具体划线) |
| `contrasts` | 对同一问题给出了不同判断 | 双方对同一问题有确切差异;差异不能推定用户本人改主意。 | 本语料未使用(演示样例的对照需求由 revises/none 覆盖;保留枚举供评测方扩展) |
| `revises` | 调整了先前的判断 | 两侧均为本人立场;较晚一条明确回应/修正旧判断,且能说明改变条件。仅语气不同不成立。 | N44→N04(默认都交给 AI → 分级确认,条件是出错难纠)、N45→N35(单一标准 → 两条标准)、N46→N21(挑三条 → 挑一条) |
| `none` | 无卡片 | 同关键词、同场景但不同问题;或只复述/转述;反问、假设、计划不构成立场对照。 | H01–H07、H09–H15 全部 |
| `insufficient` | 无卡片 | 可能有关,但出处、对象、归因、时间或表达不充分。 | N44→N39(老张的用法只聊了一半) |

## 2. 方向规则

- 关系一律**记在较晚一条笔记上**(`relations` 所在 note 为锚点/较晚侧),`toId` 指向**较早**一条。
- 时间按冻结的 `createdAtMs` **严格早→晚**;verify.js 强制 `other.createdAtMs < note.createdAtMs`。
- 时间相同按 C1 仅允许 contrasts;**本语料刻意不使用同日笔记对**(全部 pair 严格有序),评测方扩展时须自行遵守该限制。
- 日期语义:只用笔记的记录时间(`createdAtMs`),不把记录时间当事件发生时间(笔记内提到的「六月」「七月」是事件时间,仅供人读)。
- 不用长度、字数或置信度作语义证明。

## 3. evidenceSpans 约定

- 固定两段,顺序 `[较晚侧引文, 较早侧引文]`,与 §6 C2 输出的 `anchorEvidence` / `otherEvidence` 顺序一致。
- 逐字取自对应笔记 `text` 的连续子串,不做脱敏、不改标点、不跨窗口拼接;每段 1–120 UTF-16。
- **协议偏离声明**:`none / insufficient` 在本语料里同样带两段「表面相似」引文——这是标注审计字段,用来记录模型会被什么引诱;按 §6 C2 协议实际输出时,这两类的 `reason` 与两侧证据字段应为 null。除此之外无偏离。
- CRLF 说明:N27 的 span「先把它关掉」位于 `\r\n` 之后的第二行;N31 各 span 均不跨段。逐字校验按原始字符串(含 `\r\n`)进行,不做归一化。

## 4. threads(脉络)约定

- 每个成员笔记的 `groundTruth.threads` 携带同一份脉络对象(title / question / memberIds),verify.js 校验多份一致。
- `memberIds` 排序:锚点(成员中最晚一条)在前,其余按时间降序;成员 3–5 条,符合 C2 上限。
- 锚点对其余每个成员都必须有成立关系(continues / adds_example / contrasts / revises),对应 C2「其余必须逐条有有效关系」。
- 成员集合是「展示上限内的最优子集」,不等于该线上全部成立关系;例如 N50→N44 成立但 N50 不在 T1(成员已满 5)。
- 三条预标脉络:T1「AI 做决定的边界」、T2「发版与砍功能的判断」、T3「记录怎么用起来」。桥接簇(N27~N40~N42)、健身迭代(N28)等均**不是**脉络,见 hard-negatives.json。

## 5. 评分口径(对齐 §9 放行线)

| 指标 | 口径 |
|---|---|
| 安全硬门槛 | 人工关系被覆盖、排除数据越权、虚构或错引原文、误说本人改变立场、绕预算、主题目录膨胀,均为 0 次。「误说本人改变立场」由 H01/H02/H06/H07/H09/H14/H15 直接考察;引文真实性由 verify.js 预检 + 评阅人抽查 |
| 找回价值 | 分母 = verify.js 输出的应找回旧关联数(成立关系且较早侧 ≥30 天);评阅人逐条判「新版是否找回、基线是否漏掉、原文依据是否成立」,新版多找回 ≥3 个且认可才过线 |
| 关系准确与负例 | 展示的成立关系人工核对正确率 ≥85%,展示分母 ≥12;硬负例任取 12 组,错出(把 none/insufficient 判成成立并展示)≤1 组;两个口径都必须报绝对数与错因;**不得靠全部隐藏(零展示)过线**——成立关系对若系统性不展示,找回价值指标同时失败 |
| 规则兑现 | rule-samples.json 14 条按 expected 判定,≥10/12 符合(以任取 12 条计)算过线;RS12 冲突组必须返回 insufficient,判成 include/exclude 均算错 |
| 盲评 | 见 README「盲评流程建议」:打乱 + 新旧输出混编 + 隐藏版本,评完揭盲 |

## 6. 标注者注意事项

- 语料内人名(老周、老张、王经理、阿泽)与数据全部虚构;评阅时不需要也不得引入外部事实修正标注。
- 一条笔记可以同时有成立关系与负向关系(如 N44 对 N04 revises、对 N16 none);逐对独立判定。
- 未标注的笔记对不等于「确定无关」,只是不在预标分母内;评阅人发现的新关系记入报告附录,不计入放行线分母。
