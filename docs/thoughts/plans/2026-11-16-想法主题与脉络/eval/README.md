**本目录下所有数据均为合成数据,严禁任何真实用户数据进入。** 语料中的「老周」「老张」「王经理」等人物、产品数据(崩溃率、留存点数)全部虚构;出现的手机号形态字符串(`13800138000`、`13800138001`)是公开的保留测试号码形态,仅用于脱敏链路测试,不指向任何真实用户。硬负例、规则样本、校验脚本同属本评测集的一部分,同样全合成。

## 语料结构

- **主题**:单一试点主题「产品思考」,对应 §5 B1「本机配置仅一个稳定 pilotTopicID」。
- **三条内容线交织**:T1「AI 决策边界」(§1 演示三篇落于 N04 → N24 → N44,可产生脉络「AI 做决定的边界」)、T2「产品迭代判断」(发版节奏 / 砍功能 / 排期标准)、T3「记录工具的用法反思」(只存不读 / 每周回顾 / 双源问题)。

- **对抗性设计**:正文刻意混入 emoji(🤬 / ✋)、CRLF 换行(N27、N31)、手机号形态假数据(N14、N30);长文 N29 / N31(>400 UTF-16)结论置于尾部,供双窗口采样(R15「旧笔记证据在尾部」)。

## 盲评流程建议

1. 评阅人只拿「打乱后的笔记正文 + 待评关系对清单」:由执行方用一次性脚本把 `synthetic-corpus.json` 的 notes 数组按稳定随机序打乱、剥离 `groundTruth`,连同被评系统的输出(旧版 / 新版)混编为一份清单。
2. **隐藏版本**:新旧系统输出随机重排、去掉 policyVersion / 模型名 / 评测版本等任何可版本识别字段,评阅人逐对判「成立关系是否正确、硬负例是否错出、找回是否认可」。
3. 评阅人判完后执行方再揭盲,按上表分母计算指标;硬负例错出必须给绝对数与错因。
4. 打乱脚本不随本评测集交付(避免与评阅流程耦合),执行时现场写、用完即弃,不得改动本目录冻结文件。

## 冻结与偏离

- 本目录文件冻结后,对照评测期间只读不改;若语料有错,另开 `ERRATA.md` 记录而不是原地改。
- 与规格的已知偏离:`groundTruth.relations[].evidenceSpans` 对 `none / insufficient` 也带两侧「表面相似」引文(供硬负例审计);按 §6 C2 协议输出时这两类关系的证据字段应置 null。其余无偏离。
