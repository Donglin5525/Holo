2. 四个调用方（想法/任务×2/反馈）全部接入，失败从此可见。
3. 纯图片想法合法化：`hasContent` 计入图片；暂存改 `PendingImageItem`（原始 Data 持久化，与编辑模式同走 2048 压缩管线，此前新建模式被 1024 预览图封顶）；加图/删图触发自动保存。
4. 相机权限被拒反馈补齐（想法编辑器、任务详情页，对齐 TaskImagePicker 的 alert 做法）。

### CloudKit 同步核验（A6，只查证未改）
NSPersistentCloudKitContainer 会把变长 Binary 属性自动映射为 `_ckAsset` 伴随字段（CKAsset 承载），
**不受 CKRecord 单值 1MB 限制**，2048px/0.8 JPEG 附件无丢图风险。未开 `allowsExternalBinaryDataStorage`
只影响本地 SQLite 行大小（性能层面），不丢数据。参考：[onmyway133/blog#879](https://github.com/onmyway133/blog/issues/879)、[TN3164](https://developer.apple.com/documentation/technotes/tn3164-debugging-the-synchronization-of-nspersistentcloudkitcontainer)、[atomicbird](https://www.atomicbird.com/blog/cloudkit-moves-like-azure/)。

## 二、删除流与在途改动（Phase C-1，另一审查线）

### P0（已修）
**P0-D1 删除确认文案承诺「可在最近删除中恢复」，但单条删除根本不进回收站。**
单条删除 `markDeleted(batchId: nil)`——回收站（RecycleBinView）只展示批次（RecycleBinBatch），
单条软删 30 天后被静默物理清理，用户无法自助恢复。三处文案（ThoughtCardView/SwipeActionView/TaskDetailView）已改为如实口径「删除后将无法恢复，30 天后从设备彻底清除。」（走 String(localized) 三语）。
**产品建议待东林拍板**：若希望单条删除可自助恢复，需让单删也建批次进回收站（影响 RecycleBinService 展示口径，回收站列表会变长）——两个方向二选一，现状先保证文案诚实。
