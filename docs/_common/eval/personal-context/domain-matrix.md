# 个人情境「生活领域考题矩阵」

> 目的：把「所有生活场景都能被情境规划囊括」从承诺变成可执行的质量闸门。
> 原则：**清单是考题，不是代码**——任何领域漏了，处理纪律固定为「先补成考题，再修流水线」，永远不在提示词/代码里为具体场景开小灶。

## 基线（2026-09-08，生产 deepseek-v4-flash，48 组全量）

- **关系召回 95/96 = 99.0%**（唯 Miss：033「上月待办」式过去时态关系，出题设计瑕疵，已记录待校准）
- 落地率（进入规划的候选均经核验背书）**100%**；方案产出率 **100%**；红线违规 1 处，经证据复核为词面误报（方案陈述「你已确认由自己负责」是对用户自己的事实引用，非断言母亲已确认）
- 分领域召回：20 个领域全部 1.0，财务 0.929（即 033 一条）
- 结果存档 `heldout-2026-09-08.json`；评测器已支持 `--only` 定点跑、逐条召回明细与红线命中证据落盘

## 保证模型（三层）

| 层 | 保证什么 | 靠什么 | 失效长什么样 |
|---|---|---|---|
| 入库 | 记过的情况一定进情境库 | 全量分页萃取 + 每天首开补建 + 断点续跑幂等（多包 bug 已修，测试锁定） | 库条目不涨 / 想法被跳过 |
| 召回 | 提问时全库语义检索 | 向量余弦（阈值 0.45）+ 词法兜底 + 原文补查 | 库里有但「查看依据」为空 |
| 回归 | 改动不把某类场景改坏 | 本矩阵：按领域抽样的考题集，改动前后跑分对比 | 某领域召回/净收益掉线 |

## 已知边界（不承诺的范围）

- **数据源**：目前只有「想法」进情境库。记录在任务/财务/习惯里的规律暂不可见——数据源扩展是原方案既定的二期工作，属于覆盖面的真正增量。
- **未记录 = 不知道**：规划对「没记下来的情况」永远只能给常识方案；方案卡的「查看依据」空态与实验室「情境链路」状态区用于快速分辨「没记录」vs「没召回」。
