# 记忆萃取：命题与证据分离方案

> 2026-10-25 · 起因：东林实报「用户可能养有猫，近期购买了猫砂、雨刮器、猫粮和冻干」——雨刮器与养猫无关却被并进正文。
> 本方案不改数据模型、不迁移存量，只立契约与闸门。**需后端发版（提示词）+ iOS 发版（校验器）。**

## 一、问题回顾

10-19 晚东林建了两条任务：「买猫砂和雨刮器」「买猫粮和买冻干」，10-20 完成。10-21 萃取模型把它们聚合成一条记忆，正文写成「用户可能养有猫，近期购买了猫砂、雨刮器、猫粮和冻干」。

值得注意的细节：模型自己其实拿不准——它在记录里存了一条疑问「**雨刮器是用于用户的车还是他人的车？**」，但正文还是把雨刮器写了进去。**它一边怀疑、一边照写**，而系统没有任何一道闸拦住这种自相矛盾。

## 二、根因：三个结构性缺口

1. **正文职责混叠。** `statement` 同时承担两个职责：表达「命题」（用户可能养有猫）和复述「证据明细」（买了哪四样东西）。提示词只说「一句读完就懂」「克制命题」，没有定义「明细不准进正文」——模型自然把观察到的都装进一句。
2. **聚合粒度缺失。** 提示词说「多个来源指向同一生活命题时输出一个聚合候选并列出全部来源」——「来源指向命题」被当成非黑即白。而「买猫砂和雨刮器」这条来源对「养猫」命题是**部分支撑**（猫砂支撑，雨刮器无关）：来源里一次买多样、一段话聊多事，是生活记录的常态，现有契约没有「部分支撑」的表达方式，于是整条来源连同无关并列项被吸进命题。
3. **疑问与正文不联动。** `openQuestions`（存疑出口）和 `statement`（正文）是两个互不通气的字段：实体进了疑问，不影响它同时进正文。

## 三、方案：一条记忆 = 一个命题；明细永远不出现在命题里

### 闸 1（提示词契约）：命题-证据分离

`statement` 的操作化定义：**只表达一个关于用户生活的、可独立成立的判断**。

- ✅ 允许：「用户可能养有猫」「用户近期在采购养猫用品」「用户的车换过雨刮器」（各是独立命题）
- ❌ 禁止：枚举支撑明细（「购买了猫砂、猫砂、猫粮和冻干」）、逐字复述来源、括号考据

区分「命题级概括」与「明细罗列」的判据：**类目概括合法（养猫用品），具体物品枚举违规（猫砂、猫粮、冻干）**。提示词里给上述正反例。

明细的唯一去处是 `basis.quote`，并升级为**最小片段引用**：quote 只截取与该候选相关的逐字子片段（「买猫砂」而不是「任务「买猫砂和雨刮器」」）。来源被引用的部分=支撑本命题；未被引用的部分=与本命题无关。**部分支撑由此获得结构化表达。**

### 闸 2（提示词契约）：无关并列项的出口

一条来源含多个并列项时，每个并列项独立归属，三选一：

1. 支撑本命题 → 进本候选的 `basis.quote`（最小片段）；
2. 明确支撑另一个命题 → 输出为**独立候选**（各命题各自成记忆，互不沾染）；
3. 归属不明 → 实体写入 `openQuestions`（现成字段，零 schema 改动）。

这与既有规则「实体身份无法确认→泛称表达+身份疑问进 openQuestions」是同一家族——把「身份存疑不得断言」推广为「归属存疑不得并入」，规则家族化，不是雨刮器特例。

### 闸 3（端上机器闸门）：疑问实体隔离

**校验规则（纯机器可判，零 NLP）**：候选的 `openQuestions` 或 `counterEvidence` 中出现的实体（与该候选自报的 `objects[].label` 匹配），不得出现在 `statement` 中。违规 → **拒收该候选**（下一批次随修订重萃取），与跨域融合现有的 forgedEvidence / causalOrMedicalInference 拒绝同构——「模型输出不可信，本地再核验」的哲学补齐到个人情境链。

本案例在闸 3 下的行为：openQuestion 含「雨刮器」、statement 含「雨刮器」→ 拦截。模型想保留疑问就得让正文纯净；想写进正文就得先消除疑问——两头逼出诚实输出。

**刻意的克制**：机器闸只做这一条。不校验「statement 实体必须被 quote 覆盖」——那会误伤合法概括（「养猫用品」不在任何 quote 里），把校验器变成分词系统。校验器的定位是拦「模型自相矛盾」，不是证明模型正确。

## 四、为什么这是通用方案

- **与来源形态无关**：任务、账单、想法、对话、习惯、目标——只要存在「一条来源部分支撑命题」（合并购物、多主题对话、复合记账），同一套契约与闸门适用。
- **与具体实体无关**：不是「雨刮器规则」。下次「买牛奶和打印纸」「聊健身顺带说房贷」同样被拦。
- **schema 零迁移**：statement / basis.quote / openQuestions / objects / counterEvidence 全部是既有字段，只补契约与校验，CloudKit 模型不动，存量记录不需要任何迁移。
- **展示层闭环**：命题纯净后正文更短更稳；明细由来源行 + 出处弹层承载（同日已修复点击直达与原文回查）——命题与明细各就各位。

## 六、风险与对策

- **模型过度谨慎**（明细全进疑问、正文越来越空）：闸 1 明确「类目概括合法」，给正反例锚定；观察上线后 statement 平均长度与 openQuestions 频率，失衡再调权重。
- **quote 最小化削弱证据追溯**：出处弹层与来源行已有 liveText 全文回查兜底（2026-10-25 已修）——quote 是「支撑声明」，全文核对在 UI 层。
- **拒收率上升**：拒收即下批次重萃取（修订驱动重放，既有机制），不丢证据；若拒收率持续偏高说明契约表述过严，先调提示词不动闸门。

## 七、存量处置

不做批量清洗（避免扰动已确认记忆）。这条养猫记忆东林可在「这条记忆」页用「改一下」改写或「不准确」反馈——用户控制链已支持；其余存量随各自来源修订自然重学。
