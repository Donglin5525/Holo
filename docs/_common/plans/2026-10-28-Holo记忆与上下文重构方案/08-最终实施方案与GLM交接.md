## 1. 产品结论：最后要交付什么

让 Holo 从“收集很多关于你的句子”，变成“能说明依据、在相关任务中帮上忙、也听得进纠正的个人理解”。首版必须同时交付以下六个结果：

1. **看得懂**：每条已记住的内容有准确含义、条件、形成方式、具体用途和依据；历史缺什么就说缺什么。
2. **查得到**：能看原话、原业务记录或完整统计组成；返回后仍在原回答/方案位置，未提交草稿保留。
3. **有增量**：普通流水留在原模块，重要单次经历与明确保存不被误删；成熟规律少量确认，不把候选堆成待办。
4. **用得上**：相关回答与规划遵守已确认的约束；当前状态和精确数值查原模块，不拿旧摘要代替。
5. **改得动**：纠正改变真正含义；停用停止使用；遗忘清除记忆派生正文。所有消费者一致执行。
6. **能归因**：新回答能核对当时提供与标注的记忆版本；模型标注引用与任务实际受益分开评估。

不以条数减少、引用变多、确认率或测试总数增长作为成功。GLM 报告的 2512 条等数量是待复核线索；“使用字段缺失”表示实际使用未知。

## 2. 用户路径与页面交付

主路径仍是**正常记录 → 提问/规划 → 得到帮助**；管理记忆是按需分支。三个既有入口——个人页长期记忆、聊天顶部记忆、记忆展馆相关查看全部——进入同一个“Holo 记忆”。

| 用户动作 | 系统行为 | 用户可见结果 |
|---|---|---|
| “请记住，周末尽量不排工作” | 核对真实用户消息、持续范围与授权；持久化后才回执 | “已记住：周末尽量不排工作”，可查看、撤销；“尽量”不变绝对禁止 |
| 说“今晚回答短一点” | 进入本次会话条件 | 当次回答调整，不产生永久偏好 |
| 打开记忆中心 | 已记住按主题组织；成熟候选独立展示 | “已记住 / 值得确认”，候选首页最多 3 条，无红点催清 |
| 查看一条规律 | 展示支持/反例、时间窗、单位、覆盖与组成记录 | 知道为什么形成、缺什么、会用在哪；不只显示置信度 |
| 安排下周事项 | 查询当前任务/目标，检查相关明确约束，生成草案 | 能看到偏好怎样影响安排；草案不自动创建业务事项 |
| 点回答/方案的依据 | 打开当时版本，再预览或跳转来源 | 原来源有变化时分别展示“当时依据 / 当前状态”；可返回原位置 |
| 改成“周六上午可以工作，周日留给家人” | 修改结构化条件及语义版本，限制旧理解，保留独立纠正来源 | 后续建议按新条件；旧方案保留历史并提示依据变化 |
| 不准确 / 暂不处理 / 停用 / 遗忘 | 分别处理含义否定、30 天冷却、停止使用、清除派生正文 | 不能只换一个列表标签；恢复或同步不能偷偷复活 |

详情包含：准确结论、形成方式、适用范围、依据与状态、具体用途、使用与修改记录。来源已改、明确删除、无权限、待同步、本机缺失、核验错误分别显示。无需独立详情页的统计/消息用证据预览承接，不能显示无效按钮。

手动保存和纠正不依赖后台自动学习开关；也不会替用户开启自动学习。用户明确单次保存仍须遵守敏感处理及外发授权。若所需语义整理暂时失败，显示“原话已保存，待整理”，禁止说已形成可持续使用的新记忆；纠正时旧错误版本先停止使用。当前对话可直接按用户新原话响应。

## 3. 架构边界：复用现有系统，只补必要接缝

沿用 Core Data 普通/本机敏感分区、`CoreDataHoloMemoryRepository`、已有知识修订/操作、`HoloKnowledgeResolver`、查询服务、规划 frame/run/draft、后台调度及后端成本守卫。新增名称表示职责，优先扩展现有类型，不再造第二套记忆库、检索引擎、任务状态或调度系统。

```mermaid
flowchart LR
    S[八域原始来源] --> V[统一定位与版本核验]
    V --> P[候选生成与程序证据]
    P --> K[现有知识仓库与用户控制]
    K --> R[共同资格与按任务取用]
    S --> F[原模块实时事实]
    F --> R
    R --> O[聊天 / 规划 / 分析 / 发现]
    O --> U[当时版本使用清单]
    U --> C[查看依据与用户纠正]
    C --> K
```

共同资格出口返回语义修订、证据快照、来源状态、允许用途、分区及控制版本。各消费者只能缩小用途，不能自己把未成熟候选重新提升为事实。管理页可展示不可用历史，消费接口只能返回当前合规内容。检索去重池需要读取全部记录，不等于允许全部记录参与回答。

## 4. 冻结的数据与行为契约

### 4.1 来源与证据

| 职责 | 必需内容与规则 |
|---|---|
| `SourceLocator` | domain、entityType、entityID、容器/消息ID、规范化 sourceKey、源修订、分区；同一服务供生产、路由、核验与失效使用 |
| 原文支持 | 真实作者/角色、必要片段、规范化文本版本与 UTF-16 范围；范围只用于对应修订，原话不存在不得补造 |
| 时间 | 发生时间及精度、记录/捕获时间、时区与适用窗口分别存；捕获时间不冒充发生时间 |
| 独立事件 | 底层事件身份及派生链；同一事件跨想法、对话、报告出现只算一次 |
| 程序统计 | 指标/单位、口径版本、窗口/对照、完整成员、真实独立事件数、机会分母、有效观测、缺失、反例检索范围及结果、完整周期、必要 holdout |
| 来源状态 | 版本匹配、已变化、明确删除、来源排除、撤权、待同步、本机缺失、核验错误；找得到与支持结论分别判定 |

业务片段不再统一标 `explicitUserStatement`；助手输出不作独立证据。档案、预算、健康也要核真实来源/版本/权限，不能默认 verified。Habit 定义和 HabitRecord 打卡是不同实体；任务等来源沿用其真实删除/归档状态，不能统一假设 `deletedAt` 字段。

健康及含敏感联系的派生进入本机敏感分区。混合普通/敏感支持产生的整体敏感结论不能复制回普通分区；普通来源自身的独立非敏感事实可保持原身份。

来源依赖按真实证据与用户授权判断，不能因 formation 是 directExpression/userCorrection 就一律豁免。自动从想法/对话提炼的明确表达仍受其来源排除/撤权及删除政策约束；用户另外明确保存的独立陈述单独核对、保留自身来源。形成方式不等于永久的来源存活或权限证明。

统计继续调用原业务统计服务，沿用对账、转账、删除和单位规则，不在记忆端另算一套数字。首版保存有界且完整的证据清单：测量并冻结编码上限，超限改为原模块分页查询结果，明确它是本次查询，不能只存前 N 条冒充完整快照。模型生成的样本量、反例搜索完成声明或统计结果均不直接当程序事实。

### 4.2 语义、修订与证据身份——本轮新增硬门槛

1. 保留四种身份：来源、底层事件/证据、命题、语义修订。主题只负责组织。
2. **纠正必须修改实际含义**：主体、关系、肯否定、对象值、条件、时间、例外及允许用途按新原话重建并核对。不能只改 `displayText/aiUseText` 后沿用旧字段。
3. 复用现有结构化萃取路径处理手动保存/纠正；把用户新原话作为独立来源，绝不交给普通后台猜测替代用户决定。解析未完成时保存原话/草稿并限制旧版本，不自动沿用旧结构。
4. 同义润色不制造新事实；真实语义变化必须产生新指纹/修订。若条件变化导致命题 ID 改变，显式链接前后关系，旧命题限制与新命题用户授权在同分区事务中一起保存；操作不能挂旧命题却指向不属于它的新修订。
5. 证据 ID 绑定所有影响核验的内容：来源键与修订的**配对**、支持/反对、窗口/时区、统计定义/成员、覆盖/缺失、反例状态、完整周期、holdout 及策略版本。仅改变覆盖率或观察窗，证据 ID 也必须变化。捕获时间另保留，不能以时间戳替代证据内容身份。
6. 新键采用显式版本的规范化编码与 SHA-256；固定字段顺序、字符串规则、数值/日期/时区编码及 Locale，不依赖设备当前语言。旧 v1 ID 不全库重算，保留为 alias/provenance；新键发布先通过兼容门槛。
7. 修订身份要能区分实质语义/权威来源变化，不能让独立用户纠正因旧 ID 已存在而被 upsert 忽略。仅补证据走证据刷新操作，不能改写已发布的不可变修订。遗忘的正文清除是不可变审计的明确例外，见 §4.5。

### 4.3 每份证据只属于正确版本

证据刷新明确绑定 `propositionID + targetSemanticRevisionID/digest`，必要时带前序证据 ID。解析当前已确认版与待确认新版时，各取各的有效快照；不能取同命题最后一条刷新通用套用。

来源依赖索引、路由和复核统一从**当前有效证据快照**建立；支持与反对来源都登记依赖。初始快照仅在没有有效刷新时使用。新增支持 B、移除支持 A 后，B 的修改必须影响该命题，A 不再因旧依赖误伤它。索引可从权威修订/操作重建，不能成为新的事实库。

### 4.4 兼容与重复身份

读取结果包括可用、未知格式、损坏/冲突、覆盖状态及受影响命题/范围；保留原始字节。未知操作、未知 payload 不能静默变 `.none` 后继续授权。可从 MO 取得命题 ID 的，限制对应命题；范围也无法识别的，暂停该批无法证明完整性的记忆消费并报告覆盖不足，原始生活记录功能可继续。

追加不可变内容；局部修改旧统计不得用旧类型全量重编码未来载荷。已知安全的 JSON 字段合并保留未知键，未知字段可能改变权限/语义时只读隔离，不把“保留了字节”当作已经理解。

相同逻辑 ID、相同不可变内容可归并；相同 ID、不同不可变内容必须保留双份原字节、标冲突并限制受影响项。禁止按 fetch 第一条碰运气。比对包括规范化后的实际权威载荷，不能仅相信 ID 或忽略冲突字段。时间/展示等允许变化字段的例外须在契约中显式列出，不用笼统忽略全部 metadata。

首版优先用既有 14 类操作共同语义，不新增 `evidenceManifestChunk` / `sessionMemoryExclusion` 外层操作。诊断中旧枚举无法解码这两类是预期暴露的边界；修复目标是保留、识别受影响范围并限制，不是穷举所有未来类型。

### 4.5 用户控制、事务与遗忘

| 操作 | 持久行为 |
|---|---|
| 确认 | 绑定用户看到的准确语义与当前证据资格；不能授权扩大含义/用途 |
| 纠正 | 原话独立保存，新结构/修订生效，旧错误语义停用；不能仅镜像为旧记录 `.corrected` 却保留旧正文继续消费 |
| 不准确 | 区分证据错、理解错、当前不适用；限制对应范围，保留其他独立命题 |
| 暂不处理 | 同语义冷却 30 天，不等于否定；换措辞不能绕过 |
| 停用/恢复 | 停用留可恢复历史；恢复须见过全部相关限制且来源仍合格，不能解除遗忘或来源撤权 |
| 遗忘 | 立即停止消费，清除知识正文/支持片段、纠正操作中的正文、旧镜像、向量/摘要/缓存及记忆使用清单中的派生片段；保留最小无正文阻断与清除收据 |

同分区原话/修订、操作、必要旧别名限制、控制代际和本地提交收据放同一 Core Data 事务。失败不报成功；跨设备同步另显示 pending，不冒充已全端生效。旧别名同步不准 `try?` 后当全部完成。

主/敏感分区没有跨库原子事务：禁止把一份 revision 无条件插进两个 context。写前检查对象分区与上下文一致；跨分区控制用幂等分步骤收据恢复，未全部完成期间不放开消费。敏感数据从未进入普通库是验收项。

不可变操作用于追溯，并不允许永久保留用户要求忘掉的正文。清除过程可恢复、可核对，完成前只能显示“已停用，正在清除”；实际完成后才显示“已遗忘”。最小阻断不含原文、embedding 或能重建正文的摘要，不把隐藏画像当 tombstone。

遗忘记忆不等同删除原账单/原用户消息或改写所有历史聊天；这些由原模块管理。清除的是 Holo 记忆及其新增派生副本。旧回答可保留自身业务历史，但记忆依据入口变为已遗忘且不能再把相关旧记忆片段续传给下一轮模型。备份恢复/旧设备晚到数据先重放限制与清除账，再参与读取；不能恢复被遗忘派生内容的可用性。

### 4.6 来源失效与并发

通知只调度工作。已知来源变化按规范化键合并；远端空集合的保守事件必须进入增量对账，不能提前 return。使用现有持久历史/来源修订对账补足通知遗漏，避免每次同步给全库写 unknown。

失效/复核绑定来源修订、目标证据、语义修订与所见控制版本。**较晚写入不等于读取了较新来源**。旧快照晚到、设备时钟偏差、并发复核都不能解除较新删除、排除、撤权或用户限制。复核只能清除它确实观察并解决的来源状态，不能清除其他 ref 或独立用户控制。

“已变化/revised”本身不授权继续使用旧结论：原文/统计支持尚未按新修订重核时，暂停受影响用途；核对后仍支持原语义才能更新证据继续用，实质含义变化则产生新修订。纯格式变化可由适配器证明语义未变，不能把所有来源修改都当这种情况。

组装、提交、呈现/执行前均用权威版本比较受影响项。正在流式输出时发生纠正/撤权，停止受影响后续输出并说明依据更新；已显示部分保留历史标记。下一轮聊天/规划恢复时过滤已失效旧记忆上下文，不能只修 retrieval 却从最近消息/旧草案重新注入。

C1无法可靠定位失效片段时，不做伪精确的逐句剪裁：暂不向模型续传受影响的整条旧AI消息/旧计划背景，以明确占位说明依据已更新；现有frame中的安全任务条件经核验仍可复用。历史UI正文不被偷偷改写。关联原用户来源也按来源排除/学习阻断政策过滤，不能把原话自动续传当成绕过遗忘的第二条记忆通道；用户之后主动重新提到可作用于当次任务，不自动解除长期遗忘阻断。该规则与C2的精细压缩/逐句引用分别实现。

离线旧设备在收到控制前无法保证即时停止；产品如实显示同步边界。后端最低后台 build 只拦部分远端调用，不能冒充已控制所有旧客户端本机读取。旧客户端夹具必须证明：共同 disable/forget/旧别名限制能阻止继续使用；无法表达的新范围控制不开放。

## 5. 形成有价值理解：先做能验证的模板

模型提出准确命题、相关支持和用途；程序核来源、算术、独立事件、窗口、覆盖与授权；固定任务评审检验是否有帮助。不同职责不能让模型自报高分代替。

明确且持续的重要原话可在现有授权下保存，不要求重复发生。普通流水保留来源而不生成长期属性；购买用品不推定身份。希望、偏好、实际行为和本人解释分开。报告、发现和规划回到底层来源，不增加独立事件。

`useCases` 首版为表达偏好、时间安排、方案取舍、持续事项背景、重要经历回顾，均带触发条件及预期影响。“用于背景理解”一类空话不能通关；手动保存保留真实用户意图，不为凑用途编造理由。

### 5.1 模板与启用策略

保留现有模板参数，补齐供给并执行完整周期门禁，不通过降低门槛制造正例：

| 模板 | 当前初始门槛 | 本版实施安排 |
|---|---|---|
| periodicRule | 独立事件≥3、跨度≥21天、完整周期≥3、真实反例检索 | 保留实现；有登记的周期/统计定义与供给才开放，不由跨度直接推周期数 |
| comparableWindowChange | 事件≥10、跨度≥14天、完整可比周期≥2、覆盖≥0.7、反例检索 | 优先贯通财务既有统计口径，两个窗口可比；查询完整与生活记录完整分别说明 |
| weeklyRhythm | 事件≥6、跨度≥28天、完整自然周≥4、覆盖≥0.7、反例检索 | 优先贯通习惯日程/打卡；机会分母、有效观测、无记录/未完成/零严格分开 |
| openConditionalAssociation | 事件≥6、跨度≥28天、完整周期≥2、覆盖≥0.7、反例检索、冻结后 holdout≥1 | 默认不开放自动成熟；供给/独立验证完成并单独过闸才启用，不能反复拿训练证据复验 |

这些是待验证的产品初值，不是科学定律。完整周期按来源时区与模板定义计算，窗口端点/夏令时有测试；不能以天数除 7 自动宣称周期完整。未知覆盖不填 1，未搜索反例不填 searchedNoneFound，`sampleCount=总天数` 不能当真实独立事件数。

反例按命题强弱解释：绝对陈述出现一个真实反例应退出；概率性节奏保留例外并重算强度/适用范围，不能因 counterRefs 非空一律否决，也不能隐藏反例。范围/强度有实质变化时形成待确认新修订，不继承旧确认。

内部候选按来源修订/命题去重；过时且可重建的未接受候选退出工作集，复用既有容量/归档策略，不永久存全部模型草稿。明确保存、用户决定与遗忘阻断不因缓存回收丢失。首页至多 3 条成熟候选只是展示数量，不是全库或主题命题配额。

防碎片 Prompt 与程序准入同批交付：一条命题只保留相关片段；允许无候选；保留明确保存、重要单次经历及合格规律正例。修改 iOS `PromptManager.swift` 后备、后端 `defaultPrompts.json`、实际版本注册及夹具；不重复声称现有同包聚合/AI输出排除完全不存在。DeepSeek 不强塞 `response_format=json_object`。

## 6. 上下文与使用归因

### 6.1 组装与消费者

复用 `HoloContextRetrievalService`、`HoloPlanningRequestFrame`、`HoloContextPlanDraft` 与 `HoloMemoryQueryService`，增加薄的共同资格/组装适配。

组装顺序：当前用户明确条件 → 相关硬约束/冲突 → 当前业务事实 → 相关有效记忆 → 必要来源补查。全局表达偏好只放获授权且明确全局的少量项；不能把“核心记忆”当每轮广播个人资料的理由。来源内容按资料处理，不能成为系统指令。

初始预算继承 00：检索 40 候选、最多 8 条；记忆 2000 tokens、全局偏好 200 计入记忆；普通 ContextPack 2000、规划/分析 6000。它们不包含 system、当前问题、最近会话和输出预留，总输入仍按实际 provider 窗口核算。原文回退最多 4 段/8000 字符的既有边界继续使用，不以字符冒充 tokens。

相关明确硬约束有独立检查路径，不随 top-k 排名丢失，也不截断否定/条件。超预算先缩小查询范围、保留完整关键条件，仍放不下就给出明确不足或最小澄清，不能默默漏掉后继续承诺满足约束。当前明确指令与持久偏好冲突时按本次用户指令处理，并区分本次例外与永久修改。

| 消费入口 | 既有落点/需要接齐 |
|---|---|
| 普通聊天 | 实际 ChatViewModel 注入、流式完成、下一轮最近消息重用 |
| Agent/记忆工具 | `HoloLocalAgentRuntime`、`HoloMemoryTool/DataSource`、其 evidence 输出 |
| 情境规划 | `HoloContextChatPlanner/PromptRenderer`、draft/frame、恢复与采纳前检查 |
| 报告/分析/回放 | `HoloUnderstandingContextBuilder`、SummaryProvider、回放消费者实际调用 |
| 一个发现 | 现有 coordinator、KnowledgeLinkage、保存入口及失效详情 |
| 后台生产/跨域 | LiveObservation、PersonalContext、候选验证与报告回流 |
| 管理/导出/回收站/恢复 | 可显示历史但不得重新授予消费资格；清除链一致 |

这张表是最低清单。GLM 用调用点搜索补齐实际旁路，逐行记录已接/不适用及证据；不能只给页面换一个 repository 变量就宣布统一。

### 6.2 首版使用记录

区分 retrieved、provided、answerReferenced、userApplied。模型显式 ID 标注只证明它声称引用，不证明该记忆是答案原因或改善效果。

普通聊天沿用显式记忆 ID，校验本次提供的 ID 与**当时**版本，删除词重合兜底；缺标记时只展示“本次提供”，不擅称“回答引用”。陌生、过期、越权 ID 不显示；内部标记不得漏进气泡。必要时还要验证标注内容与实际命题不矛盾，但不假称已做逐句引用。

新非敏感回答在已有 `extractedDataJSON` 字符串字典合并 `memoryUsageManifestV1`，包含 request/output、consumer、阶段、命题/语义修订/证据ID、允许范围、来源与控制版本、必要作用和时间。保留旧 count/IDs 兼容，不覆盖其他业务键；最终回答和使用清单一起持久化，持久化失败不展示已完成的归因。

规划完整依据仍在 `contextPlanJSON` 的 `HoloContextPlanDraft.basisEntries/evidenceRefs/planEffects`；`contextPlanRunJSON` 只存轻量运行身份/状态，不扩大成证据仓库。

旧输出只有 ID 的，显示“历史引用未保存当时版本”，绝不取当前记忆冒充旧依据。新输出的快照绑定只读版本；用户遗忘/撤权后，依据入口保留状态解释，不能继续暴露被清除的派生正文。

### 6.3 敏感使用清单的确切存储职责

普通消息/规划属于现有业务库，可能随 CloudKit 同步；“记忆敏感分区在本机”不等于聊天全文从未外发/同步。外部模型授权、业务结果保存与新增记忆片段是三条分别核对的政策。

首版新增敏感使用映射使用**现有敏感目录下的版本化本地文件**，按 output/message ID 关联，通过单一 actor 串行管理、原子写入；不新增 CloudKit 实体或操作种类。保护等级、平台文件权限与现有敏感存储一致，排除云盘及设备云备份；原子写入的临时文件也受保护。目录不可用时不写普通库兜底。

普通同步消息最多含不携带健康主题、正文、证据ID等可识别敏感内容的“本机依据受隐私保护”占位；可省略整个敏感记录。敏感部分未保存时只显示受限/缺失状态，不借用当前证据伪造历史。完成清单写入与主消息落库之间的故障用幂等关联/收据处理，失败项不能当已完成。

该目录纳入消息删除、会话删除、记忆遗忘、来源排除/撤权、清空与账号数据清除；孤儿文件按关联核对回收。显式导出敏感内容须走既有授权的敏感导出流程，默认普通导出不能带走；恢复备份先执行限制，不自动恢复已清除内容。跨设备没有本机文件时如实显示“本机未保存该敏感依据”。

## 7. 存量分流与安全边界

1. 在合成库/授权隔离副本先复跑基线，记录 Store 身份、时间、Schema/App、同步状态、脚本、过滤条件、字段缺失与解析失败；存库状态、管理投影、消费资格分别统计。
2. 扫描所有状态及分区，不只 active。优先导入否定、停用、遗忘、来源排除和学习基线，随后补建其他理解；旧源较晚重新导入不变“新证据”。
3. 分类为：有历史依据可保留；用当前来源重核；明确/已确认但需限制原范围；未成熟；无价值流水回到来源；无法核验留历史；已限制项保留阻断。无数量配额，不按 331 个句式命中直接删除。
4. 每条旧项都有去向、alias/修订、策略及处理收据。批键为 Store/分区/旧ID/旧修订/策略版本；同分区原子提交成功后推进游标，重复运行不新增事实，失败可续跑。
5. 当前来源重核产生现在的新快照；不补造过去原文、原发生时间、过去用户确认或旧答案依据。不同阶段、不同条件不为压缩而合并。
6. 分层抽查至少 30 条并报告各层分母，覆盖 archived/candidate、域错标、敏感、缺源、重要单次经历、同主题不同命题、旧限制；不存在的类别记不存在。
7. 打开管理页不触发全历史重建；后台复用现有调度，只处理变化及有界续跑。

实际日用库迁移、CloudKit schema 发布、设备安装与生产后端部署均需另有明确授权；本文不授权。真实迁移前先由应用全量导出，并验证一致性副本及恢复方法。**CloudKit Development 是日用真实数据，绝不重置、清空或用来反复试跑。**

回滚指关闭新生产/消费能力与恢复兼容读取，保留限制与已提交收据；不是换回旧二进制随意打开已经演进的库，也不是把旧备份覆盖日用库。旧二进制不可安全回退时交付修复版本，原始记录继续可用。删除/遗忘的限制不能被“回滚”撤销。

## 8. 成本、性能与服务端契约

后台不新增独立全库反思任务。按 source+revision 去重合并，未提交/失败不推进游标。复用 `backgroundCostGuard.js` 的 purpose、成本预留、日/月/全局额度及实际结算；客户端领域观察默认 10 次不是全系统共享账本。个人情境、跨域、发现及回放逐条核真实入口与 provider 包装，含直调/重试、并发预留、超限及超时。

未知用量/超时沿用现有预留保守策略，不直接退款为零。预算主体当前存在购买身份与设备回退，先按实际身份核账，不能无依据承诺跨设备统一账户。记录排队、公平性和超限原因，不用加独立“整理任务”解决饥饿。

本地记录 fetch/解码/源查询/缓存命中数、冷暖缓存及 p50/p95；隔离规模至少覆盖现有报告约 2500 条与 10,000 条合成库。共同控制先过滤，命中项与相关硬约束有界核验；按实测引入可重建索引和版本缓存，不每次问答全库核所有原文。100ms 是待验证的本地查询 p95 目标，不是整个模型回答时延承诺。

凡触碰接口、字段、用途 purpose、开闸或 Prompt，遵守 [跨端接口契约规范](../../../standards/跨端接口契约规范.md)。真实响应形状以**后端 controller/实际输出**为准，实际 JSON 走 iOS 解码；禁止照 iOS 模型反编 mock 自证。新 XCTest 要在 pbxproj 四处挂载，单独跑证明实际执行；当前测试 target 已存在，不能照旧记忆说 XCTest 都跑不了。

本地完成后端改动须明确提示需要发版；部署只在明确授权后走统一 `holo-backend-deploy`。本工作区已有其他会话后端改动，不自动纳入提交/部署。
