# 最后审查的可复跑证据

`run_review_probes.py` 读取当前工作树，提取实际 Swift 声明/函数并编译合成局部探针；运行方式见[09 审查报告](../09-最终对抗性审查与问题闭环.md)。只需本机 Python3 与 Xcode Command Line Tools，不接网络，不打开任何 App/CloudKit/真实数据库。

`2026-10-28-源码探针基线.json` 是本次实际输出及源文件 SHA-256。它是有意保留的审查证据，不是业务测试通过报告，也不包含用户生活正文。编译文件与产物都在系统临时目录，脚本结束自动回收。

边界：

- 模型/身份与来源状态使用当前实际声明和函数，依赖类型只提供探针需要的最小字段；不代表完整仓库/同步集成。
- 纠正探针重现实际服务的四项赋值，不调用整个控制服务；赋值或源码结构改变后须人工复核并更新探针，不迁就旧输出。
- 归因探针直接编译实际 Reconciler 文件，使用两个合成反例。
- 部分静态检查只证明代码结构缺口，不能代替功能执行。
- 提取器按本次已核对的花括号块工作，不是通用 Swift parser。声明依赖或语法结构变动导致提取/编译失败时，先核源码；不能把诊断脚本失配解释成业务失败，更不能绕过实际代码手写一个“通过版本”。
- 退出0表示诊断完成。修复后的安全行为应由真实仓库、控制与消费者的回归测试证明，不能只追求这里每行都是true。

后续结果另存脱敏证据，保留基线。真实数据库、导出包、含原文日志以及生成二进制不入仓库。
