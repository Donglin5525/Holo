# 官方方案调研与 Holo 的取舍

查阅日期：2026-10-28。只使用开发者的官方文档，未购买、部署或实测这些服务。下面核实的是公开机制，不代表各家的实际效果排名、用户体验或适用于 Holo 的性能证明。Holo 的调整决定属于本方案的设计判断。

本文是调研依据；最后实施范围与契约以[08-v3.3最终交接](08-最终实施方案与GLM交接.md)为准，不能把厂商机制或后续能力直接当首版必做。

## 1. 公开方案与取舍

| 方案 | 官方资料确认的机制 | Holo 采用的设计思想 | Holo 的具体取舍 |
|---|---|---|---|
| Claude Code | 简短记忆索引与主题文件分开；索引在会话开始加载，主题细节按需读取；支持查看、编辑记忆。[官方记忆文档](https://code.claude.com/docs/en/memory) | 少量必要信息在前，详细依据按需展开；用户能查看和修改 | 个人生活数据继续使用结构化本地仓库；纯 Markdown 不能替代事件去重、权限和失效处理 |
| Anthropic agent 上下文工程 / Memory tool | 轻量引用支持即时取资料；会话压缩和持久笔记各有职责。Memory tool 由应用执行存储操作，应用控制数据位置。[上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)、[Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) | 资料索引与全文分离；生成前获取相关信息；应用拥有写入和授权规则 | 保留确定性的来源核验；模型可以提议记忆，不能自行决定它已成为可靠长期事实 |
| OpenAI 会话状态与压缩 | 会话状态支持多轮连续；压缩用于减少上下文、携带后续任务所需状态，其压缩项可以是不透明、不可供人解释的内容。[会话状态](https://developers.openai.com/api/docs/guides/conversation-state)、[Compaction](https://developers.openai.com/api/docs/guides/compaction) | 把正在解决的问题与长期记忆分开；长对话需要压缩 | Holo 需要可解释的会话摘要和来源引用；不将不透明压缩项当作用户可核对的长期记忆 |
| LangGraph / LangChain | 会话级短期状态与跨会话长期记忆分开；长期记忆可以是事实、经历、规则；区分即时写入与后台形成的延迟取舍。[Memory overview](https://docs.langchain.com/oss/python/concepts/memory) | 按作用域管理状态；用户明确要求的写入及时完成，自动整理放到后台 | 复用现有 Swift 调度和仓库；无需为了这些概念引入 Python 编排框架 |
| Letta | 当前 Agent SDK 使用版本化记忆仓库；`system/` 内容进入每轮提示，其余通过文件树按需读取；后台整理单独运行。[当前 Memory 文档](https://docs.letta.com/agent-sdk/memory) | 小规模核心上下文、按需读取其余资料、修订可追踪、后台整理 | 不把所有个人理解放进系统提示；不将 agent 编辑记忆的权限等同于修改用户事实的权威 |
| Mem0 / Zep（两种互补记忆服务） | Mem0 提供作用域、元数据、有效期与单条变更历史；Zep 把派生事实关联到原始 episode，并区分事实有效时间与系统获知时间。[Mem0 添加](https://docs.mem0.ai/core-concepts/memory-operations/add)、[变更历史](https://docs.mem0.ai/api-reference/memory/history-memory)、[Zep 来源关联](https://help.getzep.com/graph-overview)、[事实时间](https://help.getzep.com/facts) | 原始来源—理解—使用记录；时间与历史修订；按用途/用户隔离 | 本地实现这些必要能力；不新增个人数据上传、托管记忆服务或图数据库依赖 |

表中最后一行包含两家独立产品，共查阅七个产品/框架方向。合并展示是为了比较来源与生命周期能力，不表示两者架构相同。

## 2. 对 Holo 最重要的结论

### 2.1 记忆、上下文和事实查询各有职责

“我不希望周末排工作”可以是持续约束；“这次行程只有两天”属于本次任务；“本月花了多少”应读取原始账本。三者混成一个不断增长的摘要，既增加输入负担，也容易把过期状态当作事实。

### 2.2 来源关联解决追溯，不能独自证明结论

Zep 的官方说明明确区分来源追溯和事实正确性。Holo 也必须分别检验：来源能否找到、原文是否支持这句话、统计口径是否成立、这条理解是否有未来用途。[Zep Context Graph](https://help.getzep.com/graph-overview)

### 2.3 压缩解决会话长度，不能升级信息权威

OpenAI 的压缩文档描述的是继续会话所需的状态承载。由此对 Holo 作出的设计判断是：压缩摘要只能继续帮助本次任务，不能因为压缩过就成为长期生活证据。[OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction)

### 2.4 不能照搬“全自动记忆”的产品承诺

用户表达、模型推断、业务状态需要不同控制。Holo 包含财务、健康和生活安排，不能让模型生成的一段话直接取得和原始记录相同的权威。后台整理可以提高条理，但不构成新的独立行为证据。

## 3. 容易被旧经验误导的地方

- Letta 当前 SDK 文档已描述 MemFS；Memory blocks 页面被列在 V1 SDK legacy 下。本文以当前文档为主，不将旧版核心块机制当作全部现状。[当前 Memory](https://docs.letta.com/agent-sdk/memory)、[旧版 Memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks)
- 本次读到的 Mem0 Add 文档将新增描述为 additive，并提醒原样存储可能产生重复；不能直接套用“每次 add 都会自动准确更新和去重”的旧印象。Holo 的去重与控制需要自己的验收。[Mem0 Add](https://docs.mem0.ai/core-concepts/memory-operations/add)
- 有时间戳不等于正确理解时间；有历史 API 不等于每条结论均被原文支持；语义相似也不等于确实引用。[Zep Facts](https://help.getzep.com/facts)

## 4. 技术选择结论

| 备选方向 | 收益 | 代价 / 关键不足 | 本次结论 |
|---|---|---|---|
| 直接接入托管记忆服务 | 可获得检索、管理 API 等现成功能 | 增加上传、授权、成本及双重状态管理；无法自动解决 Holo 原始业务事实归属 | 当前不选 |
| 上图数据库统一全部生活信息 | 擅长显式关系与复杂路径查询 | 增加部署和同步复杂度；现阶段主要问题在依据、准入和消费一致性 | 当前不选；先使用已有命题与来源关系 |
| 把全部记忆改成文件 | 易读、容易查看版本 | 难处理多设备控制、统计成员、删除依赖、敏感分区与稳定身份 | 文件适合开发笔记，不作为个人事实真源 |
| 在现有本地仓库上统一证据、用途与上下文 | 保留数据归属和已有能力；能逐步替换旁路 | 需要真正改齐产生、展示、消费、失效、迁移几个接缝 | **推荐** |

对应产品与实施方案见 [00-产品与实施方案.md](00-产品与实施方案.md)。

## 5. GLM补充观点的交叉核验（2026-10-28）

- **Generative Agents**：原论文以新近性、重要性、相关性的加权和检索，按累计重要性触发反思，并让反思引用输入记录。可借鉴整理触发与引用关系，但它研究的是模拟角色行为，不能视为个人生活规律通过了真实性或反例验证。[原论文§4](https://arxiv.org/html/2304.03442)
- **Manus**：官方文章描述保留URL或文件路径以便取回上下文，设计压缩可恢复。Holo需要在此基础上核对修订与权限；保留指针不能保证被改或已删的原文仍能准确还原。[官方文章](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)
- **Gemini**：官方文档描述过去聊天记忆及相应开关、删除和纠正方式；不足以支持原稿“全部存前确认、条目极少”的概括。Holo每次最多三条成熟候选继续作为自身减负设计，不将它归因于竞品数量限制。[官方说明](https://support.google.com/gemini/answer/16598469?hl=en)
- **Mem0与生命周期**：四操作需要限定产品/版本再看实际实现，不能覆盖本文件已核实的当前Add平台文档。Zep已有来源与事实时间设计，因此“各家普遍缺生命周期”不作为差异化结论。Holo已有衰减参数属于自身代码事实，不构成竞品优劣证明。
- **未经来源支持的合规与产品概括**：原稿关于其他产品不可见、不可改或地区法律禁止的叙述，不纳入本方案依据；不从未经核实的市场表述推导Holo的产品或法律结论。
