## 1. 基线与样本先冻结

每次实施记录：Git revision 与脏文件范围、provider/模型/Prompt 版本、App/模型版本、来源类型、资料范围、时区、消费者、自动形成/辅助回答设置、数据分区及预算。只使用合成数据或经授权的隔离副本；不直接修改日用开发库。

固定 80 条语义评审样本：八域各 8 条，共 64 条，包含该域实际支持的正例和近似反例；再加 16 条转述、否定、时效、重复、派生回流与跨域样本。每条都有来源、预期理解、允许用途和拒绝/不足原因。不能要求档案等领域硬造行为规律来填满统一表格。

另外冻结 20 个实际任务：12 个应从个人背景受益，8 个不需要记忆。用同样基础数据、输入、模型版本和生成设置做有/无合规记忆对照；支持随机性的模型重复三次并保留全部结果。交换评审顺序，评审者先看答案再看条件标签。不能只展示最佳输出。

从迁移结果分层抽查至少 30 条，覆盖用户陈述、已确认、自动低价值、未成熟、失效/停用、无来源与敏感分区；同时给出各层总分母。不存在的类别记不存在，不伪造真库内容填表。

### 1.1 数据基线必须可复跑

GLM报告的2512条、331条句式命中、52条同主题等数量作为线索，不在未复核前当作批量处置清单。冻结基线应附：

1. 采样时刻和时区、脱敏Store身份、主/敏感分区、App/Schema版本、副本同步状态及一致性取样方式。
2. 实际只读查询/脚本、字段路径、过滤/去重条件、解析成功/失败/隔离数、状态与用户决策的完整分布及统计桶边界。存库状态、管理投影和消费资格分别计数。
3. 使用字段的缺失/null/0/正数分别计数；按消费者授权、资料包、消息引用、回执、写入和同步对账。无法证明的实际使用记unknown，不能记“从未用过”。
4. 证据覆盖分开统计：引用存在、实体/原文可定位、修订可核对、统计成员/口径齐全、语义受支持。按存储域与真实来源键对照，发现域错标单独报告。
5. 旧项到保留/分流/合并/证据的映射和语义对账样本；普通流水、重要单次经历、不同阶段、同主题不同关系均覆盖。真实用户内容留在授权环境，仓库只放脱敏汇总和合成夹具。

## 2. 七组必验场景

### A. 来源与可核对性

| ID | 场景 | 预期与必须留下的证据 |
|---|---|---|
| A01 | 想法中的本人明确偏好 | 展示准确原话，点入对应 Thought 与修订，原句可定位 |
| A02 | 对话用户原话与助手复述同现 | 只引用用户原话；可定位消息及上下文，助手复述不增加独立事件 |
| A03 | 财务窗口统计 | 展示单位、口径、窗口/对照、组成记录及必要数值；原模块复核一致 |
| A04 | 习惯定义、打卡、无记录混合 | 来源路由正确；分母来自应执行机会；未记、未完成、零不混用 |
| A05 | 任务、目标与档案状态变化 | 当前回答按原模块最新状态，保留原计划时间与截止时间的区别 |
| A06 | 健康撤权或样本减少 | 本机核验并限制受影响理解；新记忆证据/使用片段不复制进普通同步消息JSON；模型外发与聊天全文保存另按真实授权核对 |
| A07 | 原文含 emoji/附件/换行，后来被修改 | 片段范围与旧修订一致；新旧可区分，定位失败不假装原文已删 |
| A08 | 待同步、本机暂缺、明确删除、查询失败 | 四种状态分别呈现；缺少清单分片不能显示来源已核验 |

### B. 形成与具体用途

| ID | 场景 | 预期与必须留下的证据 |
|---|---|---|
| B01 | “请记住，我希望周末尽量不排工作” | 原意保存并轻回执，可撤销；不强制重复确认 |
| B02 | “今晚回答短一点” | 当前会话生效，不变成长期表达偏好 |
| B03 | 购买宠物用品 | 可作为消费事实，不能直接形成养宠物或照料责任的确定记忆 |
| B04 | “我希望早睡”与晚睡记录同现 | 目标/偏好与实际行为分别保存，不互相冒充 |
| B05 | 足够跨度、机会、真实重复与用途的规律 | 真正生成成熟候选，确认准确修订后进入相关消费；保留过程证据 |
| B06 | 覆盖未知、未查反例、缺独立验证周期 | 返回具体不足原因；不因 evidence 列表为空就声称已查过反例 |
| B07 | 同一事件被多次萃取、引用、写报告 | 独立计数不增加，不能伪造规律成熟；同义改写不无限增卡 |
| B08 | 一次重要搬家与一笔普通饮料流水 | 重要经历可保留；普通流水不占持续记忆；用途能分别解释 |

### C. 上下文与真实帮助

| ID | 场景 | 预期与必须留下的证据 |
|---|---|---|
| C01 | 查本月开销，同时有较旧财务记忆 | 精确金额查原账本，旧摘要不替代结果 |
| C02 | 安排下周工作，同时有明确周末约束 | 检查约束并影响安排；不能因 top-k 排名低而遗漏 |
| C03 | 问无关常识，记忆里有宠物与旅行 | 不硬塞个人背景，不产生无关引用 |
| C04 | 同一任务追问前轮已明确的时间条件 | 会话状态保留条件，不重复询问；不误保存成永久限制 |
| C05 | 长会话压缩前后继续规划 | 明确决定、否定选项、未决问题和来源引用保持；工具调用/结果完整 |
| C06 | 语义检索失效、网络不可用 | 按现有能力走本机词法/实体/时间检索并记录覆盖不足；无网络时不虚构已取得远端结果 |
| C07 | 资料包超预算，有重要约束和次要背景 | 去掉次要背景或缩小任务，重要约束不被截成半句 |
| C08 | Chat、Agent、分析、回放、规划读同一理解 | 资格、版本、允许用途一致；LifePattern 等旧注入旁路不越权 |

### D. 使用归因与历史

| ID | 场景 | 预期与必须留下的证据 |
|---|---|---|
| D01 | 记忆“周末会游泳”，回答“周末安排阅读” | 不能因“周末”重合认定引用；原反例固定回归 |
| D02 | 记忆“我不游泳”，回答“你可以去游泳” | 不将违背约束的结果算成功；固定原反例回归 |
| D03 | 记忆进入资料包，回答没有标注它 | 记录 provided；不冒称 answerReferenced |
| D04 | 回答返回陌生句柄/不存在的原句 | 引用校验失败，不显示伪来源；异常可定位 |
| D05 | 回答仅遵循“简洁回答” | 显示遵循偏好（如有必要），不把它当某个事实判断的证据 |
| D06 | 回答后记忆被修改 | 历史显示当时修订及更新提示，不能用当前记忆偷换原依据 |
| D07 | 从记忆查看相关使用，再返回回答 | 可定位正确输出/片段与用途，未使用过不等于没有价值 |
| D08 | 用户采纳规划 | 标为采纳事件；不自动推断已执行或实际效果变好 |

### E. 用户控制与发现联动

| ID | 场景 | 预期与必须留下的证据 |

| 语义支持 | 80 条固定评审样本，正确的支持/拒绝/不足判断 ≥95%；否定反转、主体错认、猜测当事实、医学越界等严重错误为 0 |
| 具体用途 | 30 条分层抽查中，对适合进入主记忆的内容，至少 80% 经评审有明确增量用途；同时报告全部分母和被分流内容 |
| 相关任务帮助 | 12 个应受益任务至少 10 个在对照评审中获得改善；所有重复输出保留，明确约束违反为 0；8 个无关任务不强行注入个人信息 |
| 归因 | 两个已复现的词重合反例均不冒领；陌生/过期/越权引用为 0；所有 displayed 引用绑定实际请求与当时版本 |
| 用户控制 | 56 项与原 99 场景涉及的纠正、停用、遗忘、恢复、撤权和晚到同步判据逐项通过，严重不一致为 0 |
| 成本与性能 | 资料包与静默调用不超已定预算；普通回答不因后台整理增加关键路径模型调用；本地查询 p95 目标和大库用户路径有可复跑记录 |
| 可发布 | 跨端契约、必要 standalone/集成、实际入口走查、真实设备与多设备、增量迁移/备份/恢复及受控发布记录完整 |

评审量不足时记未完成，不能把空分母算作 100%。没有成熟规律也必须核实是样本确实不足还是链路缺失；已构造的合格正例必须能产出。

## 4. 每项交付的证据格式

| 字段 | 内容 |
|---|---|
| Case / Commit / 状态 | 场景 ID、代码版本、通过/失败/未运行及原因 |
| 输入与基础条件 | 合成来源/授权副本、来源修订、时间/分区/授权、模型与 Prompt |
| 形成 | 结论、形成方式、支持与反例、用途、资格和不足原因 |
| 使用 | ContextPack 摘要、句柄到版本映射、输出片段、使用阶段 |
| 控制 | 操作前后、受影响入口、同步代际、恢复/撤销结果 |
| 复跑证据 | 测试名/命令、真实编码 JSON、人工判据、必要设备日志 |

报告结论必须区分程序检查、模型语义评审和用户体验验证。新建 XCTest 文件按现行项目清单登记，单跑证明实际执行；纯逻辑可继续 standalone 并挂现有测试桥。编译绿和测试总数不代替真实入口验证。

若同一模型生成又评审，记录为自评，不能声称独立盲评。保留全部脱敏对照输出供东林/独立评审复核；缺设备/模型/授权的步骤标未执行。回退演练保留用户限制，不把旧二进制/旧备份覆盖日用库当默认回滚。

## 5. 实施者执行检查

1. 对照当前工作区与原实施记录确认实际落点，保留并行改动；先冻结来源、用途和引用契约。
2. 把本文件场景分配到实现与测试位置，先完成 A/B 批次依赖和隔离迁移，再开放新写入。
3. 所有消费、管理、发现、导出与恢复入口必须登记接线情况；发现旁路立即加入范围，不留“旧服务继续按旧资格”的口子。
4. 先用八域合成正反例跑通，再按授权使用隔离样本。禁止新建真实生活记录来凑成熟规律。
5. 改模型/Prompt/接口时同步双方与真实契约夹具；记录 provider 能力差异和结构失败。
6. 最后按产品批次提供样本证据与未完成项。业务代码、真机、CloudKit 和后端的发布状态分别报告，不互相替代。
7. 迁移真实库、设备安装与生产部署按已有显式授权和项目规则执行；本方案本身不提供这些授权。

## 6. 本轮设计自审

由主会话顺序自审，没有使用子代理，也未冒充独立外部评审。

| 审查问题 | 在方案中的处理 |
|---|---|
| 会不会把每条事实都推给用户确认？ | 明确表达与来源状态可直接处理，只有成熟行为解释请求确认 |
| 会不会靠全部隐藏或全部拒绝过关？ | 固定可成熟正例、分层分母、有/无记忆任务对照同时验收 |
| 有来源就代表事实正确吗？ | 来源定位、语义支持、统计有效与具体用途分别判断 |
| 有引用就证明改善吗？ | retrieved/provided/answerReferenced/userApplied 分级；对照另测收益 |
| 相似句子会错误合并吗？ | 继续使用命题/修订身份，不确定保留区别；确认不能授权扩大语义 |
| 同一事件被多次引用会造出规律吗？ | 底层事件身份去重；报告和摘要不增加独立支持 |
| 一条缺失来源会杀掉全部主题吗？ | 只限制受影响命题/用途；保留独立纠正，重核剩余充分性 |
| 旧来源与新来源会混用吗？ | 固定语义修订、证据快照和引用；历史无法复原时明确标注 |
| 临时会话会被后台补学吗？ | 新会话排除属C2，未实现不展示该开关；既有来源排除仍须覆盖后台与同步，不能声称首版已具备全端临时会话隔离 |
| 全部资料会因“核心记忆”每轮泄漏吗？ | 核心只含明确全局表达偏好且受辅助回答授权；其他按任务/分区选择 |
| 新字段/分片会让旧端毁数据吗？ | W0 增量载荷与未知字段回写测试；无法保证则只读隔离 |
| 会不会新增昂贵编排和云事实库？ | 复用本地知识仓库、现有检索/预算/网关，仅加入必要版本化契约 |

这些是设计检查结论，不是实现或效果的通过记录。
