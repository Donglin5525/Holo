# Holo AI 输入区能力入口重规划

> 2026-09-19 · 产品方案与实施规格。本轮仅核对截图、工作区代码及既有目标共创计划并写文档；不是代码实现、模拟器/真机验收或生产生效声明。工作区有大量在途改动，实施时重新取基线。

## 1. 产品结论

这排入口应回答用户的三个不同问题：**我想弄明白一件事**、**我想把一件事想清楚并开始做**、**我想回看一段时间**。当前“深度分析 / 今日状态 / 周期回放 / 规划目标”以同权胶囊呈现；截图中“规划目标”已出屏，深度分析虽排第一，却没有在这一层说清楚能分析什么、用什么记录、得到什么。今日状态是有用的快问，但不足以长期占据稀缺的输入区位置。

推荐常驻顺序为：**深度分析 → 一起想清楚 → 周期回放**。前两个是主能力，第三个是时间回看。移走“今日状态”胶囊，不删除自然语言快问能力；不增加第四个常驻“更多”。运行中的分析/目标草案以临时的“继续处理”状态提示出现，不占据常驻席位。

| 入口 | 用户心里的问题 | 点开后 | 结果归属 | 与另外两个的边界 |
| --- | --- | --- | --- | --- |
| 深度分析 | “为什么会这样？不同记录之间有什么关系？” | 看到适用问题、可用数据与费用/隐私提示，选问题后可编辑并亲自发送 | 聊天结果与同一份“报告”档案 | 针对一个具体问题或关联，不自动创建/修改目标；只能提出有证据支持的关联与假设，不宣称因果 |
| 一起想清楚 | “我想做到一件事，但还不知道怎么选路” | 进入现有目标共创；澄清、比较路径、确认目标和第一步 | 用户确认后进入“我的目标”，已有目标可继续管理 | 是 Goal 的创建/调整入口，不是另建一个目标模块，也不等于分析报告 |
| 周期回放 | “这一周/这一个月发生了什么变化？” | 选择明确周期后生成已有回放 | 同一“报告”档案，聊天里有回放卡 | 先选时间，再回看事实；不替代针对问题的深度分析 |

“目标复盘”仍可留在深度分析的场景目录，回答已有目标为什么卡住；结果里如需调整，给“打开这个目标一起调整”的可确认跳转。它不能在后台改 Goal。“一起想清楚”则从新目标/已有目标的行动决策出发。

## 2. 截图与当前实现的事实边界

- 截图是键盘展开时的对话页，最后一个“规划目标”被横向裁切；四枚按钮视觉规格相同，用户难以识别何者是核心能力、何者需要多步操作。
- `HoloAICapabilityProvider` 固定四个常驻入口。`QuickActionBar` 横向滚动、无滚动指示；`AnalysisScenarioPanel` 在输入区内联展开，包含八张双列卡。现有目录的“长期模式”是普通问答、不占深度分析额度，放在该目录会混淆承诺。
- 场景选择只预填问句，发送权在用户；但当前显式分析路由要求发送文字**等于预填原句**。一旦用户为了贴合自己而改写，可能回到普通意图识别。这和“选场景后自由提出自己的问题”的预期冲突。
- 今日状态点击只预填“帮我看看今天的整体状态”，没有直接执行；今日页面本身已有“今日概况”等信息，但不等于完全替代该快问。
- 周期回放已有选择 Sheet 和独立生成/归档链路；报告 Tab 是结果阅读/搜索档案，不应并造另一套报告。
- `startGoalPlanning` 在 `goalWorkshopV1` 开启时进入现有 `GoalWorkshopFlowView`，关闭时回旧目标规划。目标页开闸后目前同时显示“一起想清楚”“让 HoloAI 规划”“手动创建”：新旧 AI 入口并列是过渡状态，不是最终信息架构。共创方案部分代码已在工作区，但冻结评测、真机和生产门槛尚不可视为通过；默认门禁为关。

## 3. 输入区与场景目录

### 3.1 收起态

```text
对话 / 报告
┌────────────────── 对话内容 ──────────────────┐
│ …                                          │
│ [深度分析 ⌄] [一起想清楚] [周期回放]        │
│ [告诉 Holo 发生了什么…             ][发送]   │
└────────────────────────────────────────────┘
```

保持“深度分析”全称，不能缩成无解释的“分析”。首两枚优先始终可见；普通 iPhone 尺寸目标是三枚同屏，窄屏和大字体下可让第三枚横向滚动，但必须露出下一枚边缘/提供 VoiceOver 可读的剩余入口，不把“找不到”当作滚动学习成本。无键盘时仍是同一顺序。点击区至少 44×44pt、可见按下态、焦点态；胶囊视觉高度可小于点击区。系统大字体时转为自适应排布，不截断主入口。[Apple 按钮指南](https://developer.apple.com/design/human-interface-guidelines/buttons)、[滚动视图指南](https://developer.apple.com/design/human-interface-guidelines/scroll-views)。

只在首次真正空会话和报告空态用解释型大卡做能力教育；成熟对话内不常驻一块营销大卡。输入框上方的“深度分析”始终存在，新用户可有一次非模态短提示：“不知怎么问？从一个问题开始”，用户关闭后不反复弹。报告空态已有能力橱窗，CTA 继续指向**同一个**分析目录。

### 3.2 点“深度分析”后的目录

当前双列八卡内联面板改为有清晰标题的可关闭场景选择层：中高度先露出 2–3 个**能直接看懂的问题**，上拉再看场景目录；打开时收起键盘，退出返回原输入，不抹掉用户已写文字。中/大高度、取消与上拉遵循 [Apple Sheet 指南](https://developer.apple.com/design/human-interface-guidelines/sheets)。不要让八卡把聊天内容突然顶走。

第一屏文案：

> 用你的记录，弄明白一个具体问题  
> 例如“最近支出结构变了吗？”“习惯中断常发生在什么时候？”“作息和任务节奏有没有一起变化？”  
> 选择后可改成你的问题；发送前会告诉你可用记录、云端处理和今天的剩余额度。

例子是**问题示范，不是已经观察到用户存在的事实**。可根据当前对话和真实可用数据调整排序：截图里的财务上下文可优先展示财务问题；若对话已经说明缺少分类明细/预算，就不能宣传“精准分类归因/预算分析”。显示“已有记录可分析什么 / 还缺什么”，提供“继续普通提问”或“去补记录”的选择，不把低覆盖数据包装成一份看似精确的报告。若尚不能可靠判定数据覆盖，使用固定示例而非伪个性化。

完整目录按用户任务分组，底层复用已有场景 ID 与已验证查询路径：

| 第一层 | 展开后的场景 | 处理建议 |
| --- | --- | --- |
| 看一个具体问题 | 财务、习惯、睡眠与健康、任务、想法、目标复盘 | 从“我想知道……”提问，选后保留场景意图；问题/时间范围可改 |
| 找跨领域关联 | 跨域洞察 | 明确会比较有记录的领域，并在结果标明关联证据与限制；没有足够两域数据时给诚实提示 |
| 长期理解我 | 长期模式 | 从“深度分析额度”目录移走，作为普通问答/记忆能力说明；若以后真的提供有证据的长期趋势报告，再以新的清晰契约进入分析 |

跨域是 Holo 的差异化能力，可以在第二屏置顶并标“跨记录看关联”，但不对数据少的用户统一许诺“发现隐藏规律”。将“王牌”营销标记换成解释适用条件的副标题。第一屏推荐问题不固定永远三条；无可验证数据时只展示能完成的入口和补全路径。

### 3.3 选择、编辑、发送的确定性契约

选择场景只是把一个可编辑的具体问题带回输入框，同时显示可移除的“深度分析 · 财务”等模式标识；用户改写问题但仍保留该标识时，**仍按显式分析路径**发送，不能依赖文字与模板逐字相等。用户删除模式标识或换为与该场景完全无关的请求时走普通聊天；二者切换应可见，避免一条普通问题误耗分析额度。发送前检查真实额度、数据覆盖提示、云端授权；取消/拒绝时不创建假完成报告，也不能扣不该扣的额度。与正在收集的旧目标规划会话冲突时，先明示“离开当前规划？”并保留可恢复的草案；不要暗中吞掉下一句话。

结果应先给用户可读的结论、分析范围、来源/证据、缺口与一个可选的下一步。发现关联时用“同时出现/可能有关”而非“导致”；不够数据时说不能判断。深度分析完成后仍写到现有聊天消息和报告档案，报告内追问走现有链路。周期回放同理复用当前档案，不新增并行保存系统。

## 4. 目标融合，而非目标替代

常驻“规划目标”**改名为“一起想清楚”**，这个名字说明它先协助澄清和选路径，不承诺点一下就自动生成一堆任务。入口应直达同一个目标共创会话；带入用户已输入的目标想法须可见可修改。进入时说明“聊清方向 → 选路径 → 核对计划 → 确认后保存到我的目标”，并提供“手动创建”的清晰退路。

“我的目标”仍是目标实体、进度、任务/习惯关系和历史版本的主场。入口统一后，目标页“新建”菜单最终仅保留“一起想清楚”“手动创建”；旧“让 HoloAI 规划”只在灰度/回退期保留，确认共创质量与持久化门槛后再从界面移除，旧数据和旧回退实现暂不删。目标详情的“一起想清楚怎么调整”指向已有目标的重规划；P0 若只能给建议，明确“尚未修改原目标”，P1 验收后才可逐项确认写回。确认前不创建 Goal/任务/习惯；确认后复用已设计的原子保存契约。

当共创门禁未开、服务不可用或评测未过时，常驻胶囊继续显示“规划目标”并走旧流程，或在该入口明确提供手动创建，不提前显示一个无法兑现的“一起想清楚”。产品上线时统一以服务端旗标和实际能力核实为准；设计文档和本地代码不代表商店版本已提供。

## 5. “今日状态”与第三席

去掉常驻“今日状态”，但保留用户说“帮我看看今天”的自然语言入口，并在 Today 页面使用已有今日概况/聚焦信息承接“现在有什么值得注意”。若某天确有**具体且可信的异常或待决策**，可在 Today/对话上下文出现一次性提示，例如“今天有一件事值得回看”，点击后说明来源，而不是恢复一个每天都一样的空泛胶囊。不能因为缺数据就编造“今天状态”。

第三席保留“周期回放”：它有已成型的时间选择、异步生成、报告归档链路，和分析的“问题驱动”形成互补。名称可在可用性测试里试“周期回放”与“回看一段时间”，本方案默认保留熟悉的既有名称。最近的未完成分析或共创会话，由消息流中的运行态卡/恢复横幅提示“继续”，不要永久挤掉回放；已完成的结果由“报告” Tab 找回。

## 6. 状态、约束与微文案

| 状态 | 用户看到/能做什么 | 不应发生 |
| --- | --- | --- |
| 有相关记录 | 问题建议 + 具体范围/来源 + “改成我的问题” | 只报场景名不说明用途 |
| 无记录/仅部分记录 | 显示已知缺口；允许普通提问、补记录，若坚持分析则提醒可能只能得到有限结论 | 用猜测分类、预算或关联冒充事实 |
| 额度未加载/用尽 | 未加载时不给虚构余额；用尽时说明重置规则并提供不耗分析额度的普通提问 | 误把普通长期模式问答灰掉或暗扣额度 |
| 未同意云端处理/离线 | 发起前说明所需数据和处理方式，用户可取消；失败保持问题与模式供重试 | 私自降级成另一种分析而仍展示“已完成” |
| 共创进行中/分析进行中 | 状态卡可恢复/取消，切换能力先说明现有会话去向 | 新入口吞掉正在回答的目标问题 |
| 切页/杀进程/返回 | 从已有分析任务或目标会话恢复同一工作，保留草案 | 再建一份 Goal、再扣一次分析额度 |

文案统一用“问题、记录、结论、下一步”，避免把内部的 Agent/路由/配额工程词当作用户主叙事。具体额度数字必须用实时有效快照，不在文案硬编码免费/Plus 次数。

## 8. 交付边界

本方案建议的是**入口重排 + 深度分析的可理解目录 + 目标共创的单一入口**。没有修改 iOS 业务代码、Prompt、后端或生产设置；没有模拟器、真机与用户研究结果。下一步实施前先核对在途改动和 `goalWorkshopV1` 实际灰度状态，不把旧文档或本地实现误认为上线事实。
