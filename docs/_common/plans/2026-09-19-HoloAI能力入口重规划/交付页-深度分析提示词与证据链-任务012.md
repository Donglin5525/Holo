## ① 用户可见变化与反例

| 变化 | 正例 | 反例（修复前） |
| --- | --- | --- |
| 七个场景预填问句全部换为「明确疑问 + 可核对比较 + 诚实边界」 | 财务：「最近的钱主要花在了哪里？是少数大额支出，还是多笔小额慢慢累积？…」 | 旧：「深度分析一下我最近的财务状况，重点看支出结构和预算执行」像功能说明 |
| 选中场景后**改写问句再发送，仍按该场景深度分析** | 选「财务」→改成「8月外卖比7月花得多吗？」→ 仍确定性进云端深度分析（带财务冻结任务） | 旧：改一个字就丢场景，落回普通意图识别，可能被抢走 |
| 长期模式移出「消耗额度」目录 | 场景宫格只剩 7 个分析场景；底部单独一行「不占额度：问问 Holo 眼中的你」 | 旧：与额度场景混排，易误解为也要扣次数 |
| 云端报告的时间口径可信 | 问九月只算九月；「与上一段比较」用同长度前移对照窗；未来分期不进历史 | 旧：8月+9月混算成 ¥30；按月分组实际全窗口合计；对比派生被静默丢弃 |
| 「完成」必须是真结论 | 空 claims 不能完成：先要求模型补「缺口说明 claim」，仍空则诚实失败「未能产出可核验的结论」 | 旧：claims=[] 照样落「深度分析完成」推送 |
| 数字可对账 | 与工具结果对不上的断言被剥离并记 warning；叙事摘要出现编数直接清空（回退 claims 拼接，不丢事实） | 旧：任何 JSON 合法即交付，数字无从核对 |
| 报告范围标注真实 | 显式场景报告标注「最近30天（起止日期）+ 快照截止」 | 旧：一律写「近180天」，与用户实际问的范围不符 |

## ④ 成本 / 隐私 / 旧客户端 / 回退

- **成本**：answerTask/能力目录增加 system prompt 常量开销约 1k 字符；v22 删掉了 v21 的无条件多轮泛查要求（第一轮近 90 天按月基线改为按需），轮次与 token 预期持平或下降，以真实 Eval 数据为准（§5 性能门槛）。交付核验修复轮最多消耗 1 轮。
- **隐私**：answerTask 只含场景 ID/问题类型/时间窗数字/清单文案，随快照同一密文通道上传、完成即焚，未新增任何个人原文上云。
- **旧客户端兼容**：无 answerTask → 保守默认任务（行为同旧版）；旧结果 JSON 缺新字段 → iOS 解码为 nil 安全回退；无 timeRange 的 dynamicPlan → 不过滤（旧协议兼容）；`/v1/ai/agent/cloud/start` 契约零改动（任务元数据走快照 PUT，不动表结构）。
- **回退**：iOS 直接回退场景文案与路由改动即可（旧客户端路径未删）；后端 Prompt 在 SQLite `prompt_versions` 按 v21 历史版本 rollbackPrompt；云端正确性修复（时间过滤/证据核验）不建议随表达 A/B 回退（方案 §5 口径）。
