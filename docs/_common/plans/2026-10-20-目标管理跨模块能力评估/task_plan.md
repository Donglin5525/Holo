# 目标管理跨模块能力评估

## 目标
核实当前目标管理如何关联五大模块，回答“任意目标如何被现有模块承接”，给出产品能力缺口和优先顺序。本轮仅做评估与方案，不改业务代码、不部署。

## 阶段
1. [已完成] 核对目标、模块、数据来源与日常入口的当前实现。
2. [已完成] 用存钱、减重及非数值目标检验完整闭环。
3. [已完成] 形成有证据的产品结论、优先级与验收建议。
4. [已完成] 将“北海道旅行储蓄”用户故事融入现有方案，补齐复盘证据、剩余期数重算、阶段性习惯、可行性与确认写回规则，同步旧方案相关段落。
5. [已完成] 按用户明确的通用目标闭环重新审查方案；提升 AI 拆解、差距分类和目标/计划修正为统一规则，存钱/减重/英语采用同一流程验收，修正财务案例主导的范围与实施顺序。
6. [已完成] 对抗性审查：以最初“各类目标由现有模块承接并持续修正”为基准，攻击轻量性、自动回顾入口、不确定时的可执行性、目标保真、真实写回与范围控制；直接修正方案并保留反例验收。
7. [已完成] 制作单文件可点击 HTML：存钱/减重/英语的完整旅程、跨模块执行、差距分支、确认修正及再次验证；以合成数据演示，用程序检查状态与交互，并打开本地预览交付评审。
8. [已完成] 按用户最终确认的现有布局边界核查目标、HoloAI报告与原模块入口，交付唯一权威的GLM实施方案、提示词和README；旧HTML已降为流程参考并移除虚构底栏。48个现有文件路径、链接/JSON及42条验收完整性核对通过；原型129项模拟DOM契约重测通过，无业务代码和生产变更。

## 边界
- 以当前代码为事实；旧方案与原型只作为参考。
- 结果、行动、约束分别判断；没有数据不等于失败。
- 现有工作区有其他会话的前后端改动，不触碰、不提交。
- HTML 为本地评审原型，不接真实模型/生活数据，不发布线上网站；沿用 Holo 视觉规则，保持三场景平行。

- 对抗审查后的文档检查因精确匹配“用户必填表”触发措辞误报；该语义已由“不要求用户依次填写”等正文覆盖，改为人工内容核对及链接/格式检查，未改业务代码来迎合检查。

- 首轮交互检查发现保存失败前切换评审开关会丢失输入；新增输入草稿保持后重测通过，并补重复采纳、阶段结束、收尾和首次真实测量的断言。
