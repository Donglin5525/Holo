# 目标管理方案对抗性审查

日期：2026-10-20。对象：《产品评估.md》及 2026-10-11 旧方案。本轮为主会话自审，没有调用子代理，也没有改业务代码或运行原生旅程。

最终补充审查已纳入[最终方案与GLM实施交接](最终方案与GLM实施交接.md)：保留现有导航，原模块记录，目标/HoloAI同报告；旧HTML仅作流程参考。实施与R01—R42以最终规格为准。

## 结论

主方向符合东林的预期，但审查前的方案不宜原样作为开发验收依据：存在前置建设过多、用户负担偏重、主动回顾未落到入口、不确定时无法推进、修正可能只停在建议等断点。主体已修正，下面保留反例与必要验收，避免仅以“文档有这些标题”判定覆盖完成。

最初预期是：**设置各类目标 → AI 拆解 → 由现有模块建立/关联任务、习惯、预算等 → 日常执行回流 → 分析差距 → 确认修正同一目标与计划 → 再执行。**

Holo 负责减少用户自己跨模块翻译和设置的工作；能定量的读数值，暂不可定量的用成果确认、用户反馈或探索步骤承接。用户只需表达目标、确认计划、日常执行、参与必要回顾。

## 最后一轮审查：现有布局和真实承载

- 原型的虚构底栏与五模块内嵌切换会诱导重做产品。已移除虚构底栏并明确流程示意；最终规格锁定个人→目标入口、原页面增量和跨模块跳转。
- 「目标与HoloAI都有报告」可能产生两份正文/不同采纳状态。最终统一到现有ChatMessage和ReportDetailRoute，两个入口同reportMessageID，只新增必要索引。
- 自报旅行资金的兜底会绕过财务模块，还会把净结余当专款。已撤销该新产品入口；来源改为已确认的财务口径/单账户读取，不可靠时未知，计划仍可执行。
- 上限习惯容易误改习惯全局完成语义。已明确原打卡规则不改，目标限制从原始数量独立计算。
- 「修正原计划」容易复用现有新建Goal.create及各仓库独立save。最终规定同goalID、授权差异、独立context单次保存和幂等，原模块对象真实变更。
- 结果/执行/原因线索必须沿同一快照、目标scope和授权范围读取；避免只扫前20个目标、只给标题上下文、关键词把报告错误分到财务。

这些是规格级修正，尚需GLM实施及按最终R01—R42运行验证，不能据此宣称App已解决。

## 当前代码支持的关键判断

主工程前缀为 `Holo/Holo APP/Holo/Holo/`。

- `Views/Goals/GoalWorkshopFlowView.swift:99`：既有目标入口明确说明只提供建议、不修改原目标。R5 是尚未实现的能力，不能包装成已具备。
- `Views/Goals/GoalWorkshopFlowModel.swift:51`：目前引用摘要主要是目标标题，版本固定写为 1。有效修正还需真实的当前计划、执行及结果依据。
- `Services/AI/GoalWorkshop/GoalWorkshopCommitService.swift:127`、`:165`：现有提交创建新 Goal，首版为 1；未来不能直接复用成更新原目标。此处是实施约束，不是宣称当前建议入口已造成重复目标。
- `Services/AI/GoalNotificationService.swift:38`：目前监听目标写操作，任务完成等高频动作不经此入口；风险提醒也不等于计划复盘调度。
- `Services/AI/GoalMetricEvaluator.swift:52`：手动量化记录已有累计/最新值基础，可优先复用；完整专项资金产品不是通用闭环必须先建的前提。输入、扣回等具体交互仍需实施时核实。

这些判断只证明当前源码边界，不证明产品体验有效。

## 首期验收应如何攻击

1. **冷启动**：没有任何记录、没有预算、目标没有截止日；仍能确认一份短期计划并开始，不能被设置表或测评拦住。
2. **仅在原模块执行**：分别做存钱、减重、英语；到期从常用入口发现同一张回顾卡，多次记录不重复催促或逐条请求模型。
3. **原因不确定**：数据不足时，清楚表达未知，同时给一个下一步或试行调整；不虚构因果，也不只回复无法判断。
4. **真实采纳**：确认前记下原目标 ID 与执行项；确认后读取同一目标、选中的变更与新版本，再次打开/同步仍一致。改目标定义需明确确认。
5. **连续两轮**：有改善可继续，无改善再调整；行动列表不只增不减，临时习惯到期停止，原历史和共享对象不变。
6. **跨模块线索**：没有给每笔交易/每条想法关联目标时，回顾仍可在允许范围内读到相关开支或用户困难摘要；结果计算与原因假设保持区分。
7. **过期与替换**：生成建议后补录/手动改计划，再确认；同时把一种练习换成另一种，核对新事实、旧记录含义与替代关系。

跨周真实试用后，重点看用户是否能开始、是否需要重复配置/记录、是否发现并理解差距、是否采纳调整及下一期是否有可观察变化。不能只用创建量、打卡量或复盘字数评定价值。
