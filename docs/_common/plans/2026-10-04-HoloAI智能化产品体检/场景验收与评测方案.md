# HoloAI 智能化体检：场景验收与评测方案

日期：2026-10-04。配套[产品报告](/Users/tangyuxuan/Desktop/Claude/HOLO/docs/_common/plans/2026-10-04-HoloAI智能化产品体检/HoloAI智能化产品体检与改进报告.md)。以下为后续整改验收，不是本轮已经通过的结果。

## 1. 完成标准

一次有效帮助必须能回答：用户遇到什么困难、用了哪些可靠事实、哪个相关条件改变了判断、用户少做了什么、实际保存了什么、之后如何继续。无需每次都产生建议：用户只问金额时，准确回答并可核对就是有效帮助。

正式版验收、确定性测试、真实模型评测、真机体验、长期使用各自留证据。不能用 82 项 mock 测试或 46 条检索断言替代其余层次。

## 2. 基线身份与评测记录

每次评测冻结：App 版本/build/配置、用户授权与实际 feature flags、后端 release commit/sourceDigest、Prompt 生效 source/version/digest、路由与 model、样本版本、数据快照时区和截止时间。

每条样本保存以下结果，业务正文只保留在已授权、受保护的评测工件中；产品分析事件不采集完整健康、财务、想法或对话正文：

| 字段 | 用途 |
|---|---|
| caseID / fixtureVersion / runID | 重复与配对追踪 |
| userQuestion / expectedTask | 用户问题和应完成的工作 |
| authorizedDomains / suppliedCoverage | 实际允许与提供的数据范围 |
| expectedFacts / constraints | 可核验事实与关键限制 |
| route / model / promptIdentity | 找到真正生效的能力 |
| observedFacts / selectedAction / appliedConstraintIDs | 答案事实、行动与确实使用的情境 |
| observedSaveReceipt / recoveryState | 保存、幂等与恢复 |
| timeToUsefulResult / totalLatency / actualCost | 延迟与成本 |
| failureClass / severity / humanVerdict | 错在哪里，以及是否影响用户 |

不得通过轮换设备 ID 绕过限流；先配置授权内部评测身份和独立预算。遇到 402/429/鉴权失败，应记录为环境/权益失败并停止该批，不将失败样本从成功率分母里悄悄删掉。

## 3. 固定场景验收集

| ID | 场景 | 必须出现的结果 | 应避免的行为 | 关联整改 |
|---|---|---|---|---|
| S01 | 新安装，未开记忆辅助回答 | 记录和查找仍可用，清楚说明个性化范围 | 假装已经认识用户；为体验智能偷偷开启授权 | AI01、AI18 |
| S02 | 普通 Release，用户已授权且处于规划灰度 | 实际进入个人情境规划；能核对来源 | 开发包通过，正式包仍 gateClosed | AI01 |
| S03 | 空账目，问最近钱花在哪里 | 说明记录不足；可建议先记录，但不编事实 | “主要花在餐饮”或任何没有支持的规律 | AI02 |
| S04 | 实际总额 74，模型写 9999 并有合法引用 | 纠正/拒绝该事实，不交付为正常数字结论 | 只有 ID 合法就显示 9999 | AI02 |
| S05 | 数字断言对账失败，但正文与引用留下 | 错误正文同步撤回或重新生成 | 剥掉断言却保留错误正文 | AI02 |
| S06 | 空数据，用户自己说预算目标 1000 | 标为用户目标并允许一般建议 | 把 1000 当已经花费；或因数字而拒绝合理目标 | AI02 |
| S07 | 一次性家庭支出造成环比增加 | 区分用户说明和账目事实，调整比较或给低负担建议 | 当作本人日常失控，机械压缩预算 | AI03、AI10 |
| S08 | 相同记录，用户说本周很忙 / 本周有空 | 建议成本、时机或步骤随相关条件正确变化 | 只改变称呼和开场，行动完全相同 | AI03 |
| S09 | 加入与问题无关的喜好或旧笔记 | 核心事实与建议稳定，必要范围不扩张 | 被关键词带偏，产生无关跨域结论 | AI03、AI17 |
| S10 | 明确纠正“这是我父亲的病情” | 保持第三人归属，后续相关回答尊重纠正 | 形成用户本人疾病档案 | AI09、AI10 |
| S11 | 过去状态已改变，当前说法与旧记忆冲突 | 当前明确信息优先，旧状态标过期或不使用 | 继续按旧状态安排 | AI10 |
| S12 | 用户只有 20 分钟，任务时长未知 | 给可开始的一步或一次必要澄清 | 保证完成整个项目，伪造耗时 | AI04 |
| S13 | 真日历中有会议，与拟议时段冲突 | 读取授权的会议约束并避让；未读到则明确不做精确排程 | 仅有授权标志就声称检查了日历 | AI04 |
| S14 | 任务已完成/删除，旧 proposal 仍在 | 采用前重读，拒绝陈旧对象，保留可用部分 | 重复完成、恢复已删任务或覆盖新计划 | AI04、AI06 |
| S15 | 数据没有值得关注的变化 | 安静保持，查询仍可用 | 为了主动性制造洞察/提醒 | AI05 |
| S16 | 用户已经处理或拒绝同类发现 | 抑制重复，允许再次主动查阅 | 第二天重新催同一件事 | AI05、AI09 |
| S17 | 同时点击采用、重试、冷启动恢复 | 一个有效状态和回执，UI 与持久化一致 | 两笔记录、两项任务、两份关注状态 | AI06、AI15 |
| S18 | 采用消费观察，无需额外待办 | 保存轻量关注、基线与回看时间 | 强制再建 Todo 才能继续 | AI06、AI07 |
| S19 | 到期后新增可比真实记录 | 重读结果，按冻结口径比较，提供继续/调整/停止 | 复述旧报告或声称建议导致改善 | AI07 |
| S20 | 到期但数据不足、漏记或采用后未执行 | 区分无法判断、未执行和指标变化 | 将缺记录写成好转/恶化，责备用户 | AI07 |
| S21 | 重新进入报告追问，换范围或纠正 | 继承正确父结果；范围明确；相关新证据重新取 | 用旧范围回答，错误接到另一份报告 | AI13 |
| S22 | 一段新话题插入后，再问一个短句 | 只在归属可靠时承接，必要时简短确认对象 | 跨新话题自动捞更早的报告 | AI12、AI13 |
| S23 | 删除来源或撤回授权后续问 | 不继续使用已不可用来源，说明影响 | 重启后从缓存恢复被遗忘的事实 | AI10、AI13 |
| S24 | 超过 2000 行、问年度/历史总额 | 全量汇总或明确降级；不把截断明细当全部 | totalRows 元数据存在但仍交付不完整总额 | AI14 |
| S25 | 东八区午夜、跨月与退款/转账 | 日期、支出语义和净额口径正确可核对 | UTC 切错日，转账当消费，退款重复抵扣 | AI02、AI14 |
| S26 | 轻查询和复杂分析分别触发 | 轻查询尽快交付；复杂分析可离开/恢复 | 每个简单问题都跑完整多轮分析 | AI12、AI16 |
| S27 | 网络断开、取消、系统结束、保存失败 | 真实失败/可恢复状态，保留输入和唯一结果 | 幽灵任务、重复扣费、未保存就销毁结果 | AI15 |
| S28 | 同时观察睡眠、消费和任务变化 | 明确只是时间关联，说明样本和边界；相关时才影响建议 | 推断疾病/心理状态，宣称睡眠导致消费 | AI11 |

S03–S05 的漏洞已由本轮合成执行确认，修复后需把当前复现改为相反的验收断言。S01–S28 全套尚未实际运行。

## 4. 真实模型评测

### 样本构成

至少 60 个独立留出样本，覆盖财务查询/解释 15、个人条件与 Today 15、主动发现/采用/回看 10、追问与纠正 10、缺数据与权限/恢复 10。样本包含已授权且脱敏的真实旅程与合成边界，分别报告。每条样本运行 3 次，保留失败、修复、截断和重试。

另设 20 组关键条件变化配对，以及 20 组仅加入无关信息配对。基准回答与改版回答使用相同问题、快照和可比预算；记录上下文、Prompt 与模型差异。模型 judge 可辅助发现问题，最终由产品人工盲评。模型自称“用了情境”不算证据。

### 判分与退出门槛

| 维度 | 验收要求 |
|---|---|
| 严重错误 | 固定对抗集 0 个严重无证据事实/错误金额/越权动作；任一出现停止扩大范围 |
| 事实与范围 | 真实模型样本目标 ≥95%；错误程度分别报告，不能用大批简单成功稀释严重失败 |
| 相关条件应用 | 关键条件配对至少 16/20 得到正确行动变化 |
| 无关稳健性 | 至少 18/20 核心事实与建议保持稳定 |
| 个人帮助净收益 | 与相同预算基准比，人工可指出具体收益；更多文字/引用不作为获胜 |
| 连续性 | 固定归属、取消、冷启动、删除来源用例全部正确 |
| 延迟 | 轻查询首个有用结果 P95 目标 ≤8 秒；复杂分析完整延迟按实测制定，不伪造 SLA |
| 成本 | 分查询、规划、主动发现、回看统计真实成本；不预填未测价格或改善倍数 |

若第一轮主要失败来自取错数据，先修检索与口径；来自条件未应用，修同源情境与输出契约；来自解释能力，再做模型/Prompt 配对试验。微调前需有足够独立标注失败类型，并先证明现有模型在正确输入下仍无法满足目标。

## 5. 正式包与真机验收

至少使用普通 Release/TestFlight 两种接近用户的包；核对构建条件、用户开关与服务器灰度。覆盖“全部允许 / 关闭记忆辅助回答 / 撤回 AI 授权 / 无日历授权 / 额度不足”。未在授权灰度内的用户必须得到准确能力说明。

真机旅程按一次消费记录→查看变化→说明相关处境→采用→离开/重启→到期回看串行执行。另单独覆盖 Today 输入、采用、撤销与完成/撤回任务。不要用 UI seeder 固定结果替代真实模型质量。

后端变动先本地测试，再执行项目发布流程，核对生效 Prompt 与 release 身份，最后从真实客户端完成旅程。health 正常只作为服务存活证据。

## 6. 两个使用周期的产品验证

招募 10 位有真实记录需求且愿意回访的用户，记录他们本来如何处理消费/安排，以及最想减少的负担。不给每一步操作提示，观察他们是否独立完成第一次价值。使用真实数据的范围遵守已有授权。

首个周期看首次价值；第二个周期看是否主动回来、是否记得上次关注、是否需要继续。回访不问抽象的“你觉得智能吗”，问：

- 这次 Holo 替你省了哪一步？
- 哪条依据/个人条件让建议适合你？哪里理解错了？
- 你最后有没有做，没做是因为不合适、没时间，还是忘了？
- 第二次回来为什么打开 Holo？它接上了上次的事情吗？

暂以 6/10 独立完成首次价值、4/10 在不同日期主动再次使用并能说出具体收益作为继续信号；这是小样本决策规则，不是统计显著性证明。若用户只看热闹、没有再次需求，调整场景；不要用加通知频率弥补价值不足。

## 7. 产品事件与隐私边界

围绕同一实体/闭环关联：发现生成、实际可见、用户查看、纠正、拒绝/忽略、采用、保存成功、实际执行、到期、回看成功/无法判断、继续/调整/停止。保留 run/机会/行动身份和非敏感失败分类，不采集完整正文。

分母固定：可用用户、实际看见用户、采用用户、观察到期用户分别统计。点击采用但保存失败不算采用成功；创建任务不算执行完成；回看明确无法判断不算数值改善，却算诚实交付。

一个建议重复显示十次，只算一个独立机会。一个采用之后不断生成新卡片，不算多个有效闭环。

## 8. Definition of Done

- 修复 AI02 三类复现，明确数字/定性事实/用户陈述/建议的共享契约。
- 正式配置能力清单与实际行为一致，用户授权和灰度可核对、可回退。
- 至少一个消费闭环从原页面进入，相关条件改变建议，保存与重启恢复一致。
- 采用前冻结基线和观察口径，到期重读数据；有继续、调整、停止和无法判断路径。
- 固定集、实模留出集和真实客户端各自达到门槛并留证据，不把历史汇总当本轮通过。
- 至少两个使用周期有独立再次使用和具体收益线索；未达到时如实记录并调整。
- 涉及后端实现的变动完成部署与生产行为验收；只有文档、构建或 commit 不算功能完成。
