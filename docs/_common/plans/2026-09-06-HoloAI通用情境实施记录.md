### 2. 关键实现决策

- **版本信封**：未知 schemaVersion 的载荷整份序列化进保留键 `holoOpaquePayload`（而非逐键动态写回——Codable 的 keyed 容器不接受任意键）。内容无损；情境记录仅进本机存储（单写入方），保留键不存在形状兼容问题。
- **身份规则**：锚点 = 既有 `.userTheme` 枚举 + `personal-context:<contextID>` 值；稳定 ID 沿用 `HoloMemoryIdentity`（算法不动）；合并判据 = 主体+对象+范围+命题归一化一致（`signatureComponentsEqual`），只有主题相同不得合并；claimKind 变化产生独立稳定 ID（替代链）。
- **旧端安全**：旧 JSON 无 `personalContext` 键解码为 nil（测试锁定）；旧端读写丢载荷的事实已测试记录，规避手段是 P2 的本机存储分流。
