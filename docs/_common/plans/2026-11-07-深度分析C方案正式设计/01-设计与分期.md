# 深度分析 C 方案正式设计（事实先行 · 自由写作 · 双道核对）

> 2026-11-07 东林拍板「按 C 方案推进」。本文是落地设计真源。
> 实验证据与三轮迭代记录：`~/Desktop/holo-deep-analysis-exp-1106/`（含东林真实数据，不进仓库）。
> 结论速览：C3 相比线上 A——事实错误 3.5→1.06/份、讲清真实原因 1-2→4.1/5、温度 2.8→3.9/5、硬凑 0.31→0.12；代价 4.1 次调用/份、约 6 万 token、约 3 分钟。

## 一、目标与非目标

**目标**：云端深度分析产出「像人写的、数字全对、按档案表达」的自由报告，旧版 App 直接可读，不需要发 iOS 版。

**非目标（本期不做）**：
- 不改 iOS 任何代码（复用现有结果契约渲染；新契约字段留待下个 App 版本再议）。
- 不动追问链路（追问仍走本地 Agent，靠 claims/证据映射保证它读得懂云端报告）。
- 不动目标回顾（goalScope 任务仍走旧引擎 agent_loop 多轮路径）。
- 不做模型提数·按需计算的完整版（M3 只做最小闭环，见 §4.2）。

## 二、总体架构

```
上传快照（不变，加密）
   ↓
【新引擎 deepReportEngine】（与旧 executor 并列，按开关选择）
   1. 事实清单计算器 factComputator（纯 JS，零模型）：从快照算出带编号的事实（F001…）
   2. 写作 writer（1 次模型调用）：清单 + 问题 + 档案 → 自由报告（新 prompt：deep_report_writer_v1）
   3. 双道核对：
      a. 数字核对器 checkNumbers（纯 JS）：逐句提取数字/约数（阿拉伯+中文数字）对清单核对
      b. 语义核对器 checker（1 次模型调用）：挑「约数说错/说过头/无依据/因果动机」的句子
   4. 修复 repair（仅在核对有发现时，1 次模型调用）：只改被点名的句子；修后程序再删仍不符的句子（保守）
   5. 结果映射 mapper（纯 JS）：自由报告 → 现有 CloudResult 契约（claims/sections/evidence）
   ↓
taskStore.complete / 推送（不变）
```

- 调用次数：2–4 次（无核对发现时 2 次）。额度池、推送、完成即焚、7 天过期全部复用现有执行器外壳（见 §4.7 接入点）。
- `engine` 字段标识：`"deep-report-v1"`（客户端目前不读，仅服务端留痕）。

## 三、事实清单计算器（factComputator）

**输入**：解密后的快照（datasets / answerTask / profileBrief / goalScope 等）+ 任务问句。
**输出**：一份文本事实清单（编号 F001…，中文，含口径说明），同时输出机器可读的数字白名单（供核对器）。

### 3.1 窗口口径（单一真相源）
- 主窗口 = `answerTask.primaryTimeRange`（冻结窗），无窗时用快照全窗（historyDays）。
- 「上期」= 紧邻前移的同长度窗口（口径对齐 iOS `EvidenceLedgerWindows`：上期上界=本期起点，不含当天零点陷阱）。
- 自然月口径用于「个人历史」（完整自然月才算入月均/中位数）。

### 3.2 覆盖域与条目（以实验 facts2/facts3 为蓝本，全部纯程序计算）
1. **财务总览**：本期/上期支出合计、笔数、环比（程序给「多了/少了 X 元（±Y%）」两个口径）。
2. **一次性项目拆分**：带 `project` 的支出单列；「剔除项目后的日常支出」对比；总变化中项目贡献占比（一句话结论直接算好）。
3. **收入构成**：按收入分类拆开对比；与支出同名的收入分类标注「可能是退款或报销」。
4. **分类对比**：按金额排序 + 变化贡献排序；「差额约合 N 笔该类平均消费」（N≥1 才写）。
5. **金额分档**：50/200/1000 档（判断大额 vs 小额累积）。
6. **单笔 Top、高频备注归并**。
7. **备注里反复出现的人或事**：跨备注同词归并（中文词 ≤6 字，排除系统标签如「自动生成」），给出笔数/合计/占比/逐笔明细（>8 笔只列最近 8 笔）。
8. **戒断类习惯与相关消费并列**（只并列，不推算，注明「每笔买了多少账单里没有记」）。
9. **习惯**：打卡/计数/测量三型分别给本期 vs 上期；**个人历史**（按自然月走势、按星期分布、中断次数/中位数/最长、恢复日分布、「本次中断排第几、比这次长的有几次」、「最近一次完成日期+距今天数」；当前没中断就明说）。
10. **任务/想法**：数量对比 + 按月走势；注明「内容不在数据里，原因不能判断」。
11. **一起变化检查**（生活体检场景）：口径与线上体检台账完全一致（按天对齐、对齐≥10 天、|r|≥0.35、Top3）；没有达标就输出「本期没有发现达到标准的『一起变化』」。
12. **固定大额**：完整自然月里 ≥3 个月出现单笔 ≥1000 的分类；每月同金额且 ≥3 笔的标注「像分期或固定订阅，不是一次性购买」。
13. **健康**：睡眠（时长/结构/作息圆形量 bedtimeMinutes-wakeMinutes 跨零点处理、效率）/步数/锻炼——**注意**：数据存在性由快照决定；服务端无法区分模拟器假数据，真机数据为准。
14. **口径与缺失**：00:00 时刻占比、快照截断（totalRows>rows）、预算/目标/正文类数据缺失声明、纪念日。

### 3.3 与 iOS 台账的关系
- 快照已带的 `financeEvidenceLedger` / `crossDomainCheckup` 文本**直接采用为事实段**（不重算，避免口径漂移）；factComputator 只补它们没覆盖的计算（收入构成、归人归事、个人历史、固定大额等）。
- 已知语义坑（照抄 iOS 注释）：退款行在台账里仍是收入形态；`habit.daily` 的 date 已按 dayCutoff 归日，禁止按时间戳重分桶；测量型 value=0 是缺测不是零。

## 四、写作与核对

### 4.1 写作（writer）
- 新 prompt 类型 `deep_report_writer_v1`（defaultPrompts 新条目，走 PROMPT_VERSIONS 版本管理）。内容 = C3 实验定稿的两层规则：
  - **底线**（档案也不可覆盖）：数字只能来自清单（可取整换单位）、不编造、无据不说、并发≠因果、不做诊断、不猜动机（用户档案里亲口说过的可呼应）。
  - **默认写法**（档案优先）：先答问题、标题是有内容的判断、先讲最大的那件事和真实原因、跟本人过去比、生活细节代替分类罗列、没有就说没有、直接而有温度、建议具体留余地、结尾交代局限。
  - **输出格式约束（新增，为契约映射）**：第一行 `# 标题`；正文段落用空行分隔；每段是完整的一段话；**不使用** markdown 加粗/列表符号/下划线/代码；不要在数字旁写「=」；不要出现 `finance.` 这类点分前缀。列表内容拆成多个短段。
- 人设前置与语言指令：`injectServerPrompt` 现成机制（purpose 注册 `deep_report_writer`，加入 PROFILE_CHANNEL_PURPOSES 与语言白名单）。
- 路由：新 route `deep_report_writer`（env `HOLO_DEEP_REPORT_WRITER_*`，默认= agent_loop 同款 qwen3.7-flash / 0.2 / medium）。
- **超时（实锤风险）**：openAICompatibleProvider 非流式硬超时 60s；实验观测 writer 单调用 20–60s 贴边。对策：给 provider 增加 per-route 超时覆盖（`timeoutMs`），writer 路由设 120s；不改默认值，零影响其他调用。

### 4.2 按需计算（M3 最小闭环）
- factComputator 产出「本次没算但数据里有」的能力清单（如：某关键词消费合计、某习惯与某分类的并列）。writer 在报告需要而清单没有的数字时，**不允许自己算**，只能文字带过。
- 一期不做模型回传请求；观测 writer 输出中「想要但没给的数」（日志标记），攒够样本再决定二期交互协议。

### 4.3 双道核对与修复
1. **checkNumbers（JS，实验版照搬）**：提取报告中的阿拉伯数字（含千分位、万/千/k、多/来、区间）、中文数字（两万/一万八/三成/十二顿）与清单白名单核对（±2%、×100 换算、约数区间）。日期/时刻/年份剔除（比生产版多剔中文日期）。
2. **checker（模型，qwen 同款）**：对照清单挑四类问题（约数说错/说过头如「多半」「全部」/无依据/因果与动机）。取整与档案呼应**明确不算问题**（实验翻车教训写死在 prompt 里）。
3. **repair（模型）**：只改被点名句子，禁止新增清单外内容。
4. **保守删句**：修后程序再核——仅删「两道核对都点名且修复未改动」的句子，单份最多 3 句、不超过正文 25%；否则保留并记录 warning（防止实验里「删穿报告」的重演）。
5. 所有核对过程打 `ai_call_logs`：purpose `cloud_deep_report_checker` / `cloud_deep_report_repair`；`describe` 式参数摘要（不落用户正文）。

## 五、结果映射（旧契约，App 零改动）

调研实证的渲染约束（HoloCloudAnalysisService / AgentDeepReportView / sanitizers）逐条对应：

| 报告元素 | 契约字段 | 规则 |
|---|---|---|
| 标题行 `# …` | `result.title` | 去掉 `# `；经 sanitizer（禁 `_`、` = `、点分前缀、`xx(`） |
| 开头导语段 | `narrativeSummary` | 报告第一段（或 writer 单独给的导语） |
| 其余段落 | `claims[]`（每段一条） | `id=para-N`；`displayText=段落原文`；段内**不得含换行/列表符**（mapper 拆行成多条 claim）；不含 metricAssertions（数字依据走 evidence） |
| 小节标题（若 writer 用了 `## `） | `reportStructure.sections[].title` + `paragraphClaimIDs` | 章节序号 no 由 mapper 生成（一二三）；kicker 可空 |
| 结尾建议/数据说明段 | `conclusionItems` / `disclosureNotes` | 按段落特征（writer prompt 约定「建议」段以「建议」起头、局限段固定句式）或全部走正文段落（保底） |
| 图表 | `chartHint` 只发 `kind:"trend"` 且 dataset ∈ {finance.transactions, health.sleep, health.steps…} | delta 不渲染，不发；无图不发 |
| 范围行 | `taskRange` + `snapshotCoverage` 照抄现有 | label/start/end 必填（解码硬要求） |
| 依据 | `evidence[]`：事实清单条目转 metric 型（value 取清单数值、formula 用聚合中文、dataset 用现有数据集名）；rows 型用快照行样本 | `claims[].evidenceIDs` 引用之，供「查看数据依据」与追问父上下文使用 |
| 撤回提示 | 新引擎**不发** METRIC_*/EVIDENCE_DROPPED 类 warnings | 核对已内联完成；只发不映射 UI 的信息性 warning（如 `DEEP_REPORT_CHECKER_KEPT:n`） |
| goalScope 回显 | 不适用 | goal 任务不走新引擎 |

- **iOS 契约测试（跨端规范要求）**：新增 `DeepReportResultContractTests.swift`，字面量=后端 mapper 代码逐字段抄写的最小新引擎结果 JSON，过现有 `CloudResult` 解码器断言渲染数据齐全。pbxproj 四处挂载+单独跑一次确认执行（规范§四）。
- 追问兼容：claims 映射保证 `HoloAgentContinuationContextCompiler` 拿得到父报告段落与证据（调研证实它只消费 claims/sections/evidence）。

## 六、开关、灰度与回滚

- env 总闸 `HOLO_DEEP_REPORT_ENGINE`（默认 `agent_loop`）；取值 `deep_report` 时新引擎生效。
- 设备灰度 `HOLO_DEEP_REPORT_DEVICE_IDS`（逗号分隔 deviceId；空=对该开关下的所有设备生效）。start 路由按 device 判定，executor 构造时注入引擎选择（模式照抄 discovery 的 env-first allowlist）。
- 回滚=env 改回 `agent_loop` 重启（免发版）。checker/writer 任何一路失败 → 任务失败走旧 `failureReason` 文案，不静默降级旧引擎（避免半新半旧报告）。
- iOS 侧不需要新 feature flag（入口无变化）。

## 七、测试与验收闸门

1. **后端单测**（node --test，模式照抄 cloud-analysis-executor.test 的 fake provider）：
   - factComputator：固定快照样本（把实验 4 题快照脱敏后做成 fixtures）逐条断言关键数字（611.44 / 7758 / 29.7% / 中断中位数 7.5）。
   - checkNumbers：数字/约数/中文数字/区间/误报样例（1550≈1550.20 不报；611 写「不到600」报）。
   - 保守删句上限（构造 10 个问题句只删 3）。
   - mapper：段落拆分、禁词清洗、taskRange 必填、evidence 形状。
   - 引擎选择与回滚：env/allowlist 矩阵。
2. **契约测试**：上述 iOS 契约测试 + 后端 `deepReportContract.test.js`（mapper 输出 schema 与 sanitize 规则）。

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| writer/checker 超 60s provider 超时 | per-route timeoutMs（writer 120s），默认值不动 |
| checker 误删/漏判 | 保守删句上限 + 评测闸门 + 撤回类 warnings 不发（UI 不再出现「已撤回」） |
| 段落含禁词被 iOS sanitizer 整段丢弃 | prompt 禁令 + mapper 兜底清洗（检出即替换/拆段）+ 契约测试覆盖 |
| 新引擎让旧追问读不懂父报告 | claims/sections/evidence 映射 + CloudFollowUpChainTests 补一条新引擎父报告用例 |
| 费用上升（4 次调用/份） | 深度分析低频（免费 2/天）；评测闸门盯 token/份；checker 无发现时省 1 次调用 |
| 周期型习惯（每周目标）无频次字段，折算只能按日近似 | 事实清单注明「按天折算」；快照补字段列为下个 App 版本候选项 |
| 模拟器假健康数据混入线上评测 | 评测快照固定用真机来源；服务端无法区分，靠流程保证 |
