- 定义：`backgroundSubject(deviceId, entitlement)` = sha256(`purchase:{environment}:{originalTransactionId}`)（有服务端已验证原始交易号时）否则 sha256(`device:{deviceId}`) — `src/usage/backgroundCostGuard.js:30-35`。
- 形成点（全部出现位置）：
  - 入口中间件：`const subject = backgroundSubject(deviceId, entitlementStore.get(deviceId))` — `src/app.js:391`。
  - 云端 worker：`reserveReplayDigestBudget` — `src/agent/cloudAnalysisExecutor.js:849-860`（导入 `:15`）。
  - 测试锚定语义（同交易跨设备同主体、验收模式不影响主体、无交易按设备隔离）：`tests/backgroundCostGuard.test.js:60-62`；`tests/replay-digest-budget.test.js:101`。
- 与「已验证 Holo session sub」账号主体的差异点：
  - holoSession 的 sub 是 **Apple identityToken 验证后的 SIWA sub**（`src/app.js:474-478`），仅用于内部诊断授权（`src/auth/internalDiagnosticsAuth.js:15-19`），**不参与任何额度/预算主体**。
  - 会员额度主体是 `entitlement.usageSubjectId` = `acceptance:{deviceId}:{tier}` 或 `purchase:{deviceId}` — `src/subscription/entitlementResolver.js:13、22`：**按 deviceId 键控**，同一笔购买换设备就是新主体；而 backgroundSubject 按 originalTransactionId 合并设备。两者互不相等。
  - SIWA 撤权链路（`/v1/auth/apple/revoke`、appleTokenStore，`src/app.js:526-568`）不会触及 backgroundSubject、usageSubjectId 或任何成本账本——成本主体里没有任何 Apple sub 字段。

## 与实施假设的冲突/缺口清单

1. **① 日界为上海日界——部分成立，存在 UTC 例外**。会员额度（quotaPolicy）、后台金额预算（backgroundCostGuard）、thought 金额台账都是上海日界；但**每 purpose 限流桶（rate_limits 表）的日键是 UTC**：`toISOStringDay`（`src/usage/sqliteUsageStore.js:85-91`），且 `dayExpires = now+24h` 的滚动过期并不严格对齐自然日。discovery 的「每日一批次」若落在 usageStore 限流桶上会与上海自然日错 8 小时；应改用 quotaPolicy/thoughtOrganizeBudgetStore 的上海日键模式。
2. **② 通用 chat 端点拒绝未注册 purpose——成立，且是双层拒绝**。无 route → 400；有 route 但无 prompt 映射 → 503。新增 discovery purpose 若走通用端点，两层都必须注册（但按实施包防旁路要求，通用端点应直接拒绝这两个 purpose）。
3. **③ "活跃 Prompt 可被 SQLite registry 覆盖 defaultPrompts.json"——运行期成立、重启后被反转为代码默认覆盖**。`syncDefaultPromptsToHistory` 只要发现 DB 最新内容 ≠ defaultPrompts.json 内容（**包括 admin managed 版本**），就会以更高版本号插入 `source='default_sync'` 的代码默认内容并成为活跃版（`src/prompts/promptRegistry.js:205-256`）。即 admin 在 SQLite 里的定制只在"本次进程生命周期 + 代码侧文件未变"内生效；进程重启即被代码默认顶掉。discovery prompt 若要求"SQLite 覆盖优先"需先修此语义。另一硬约束：prompt type 必须先进入 defaultPrompts.json 才存在（`promptRegistry.js:112`）。
4. **④ backgroundSubject 不等于稳定账号撤权主体——成立（与预期一致）**，且比预期更碎：成本主体三分（backgroundSubject=originalTransactionId/device 哈希；会员额度主体=usageSubjectId 按 deviceId 键控；SIWA sub 仅诊断授权）。三者无外键关联，SIWA 撤权不回收任何预算/额度。对 discovery 的含义：现有没有可直接复用的"稳定账号主体"——要么沿用 originalTransactionId 合并口径，要么引入新主体并明确与 SIWA sub 的映射策略。
5. **附加缺口**：
   - 服务端**没有**现成的"单设备租约"原语；最接近的是 `agent_step_idempotency` 的 processing 状态机+TTL+CAS 和 `thought_organize_operations` 的 in_progress 90s 守卫。
   - "每日一批次预算"无现成原语；最接近的是 backgroundCostGuard 的 subject 日预算+`briefAttempt` 24h 冷却指纹与 thoughtOrganizeBudgetStore 的 per-subject 日金额预算。
   - goal_workshop/matter_reconciliation 并非独立路由组；discovery 的「/v1/discovery/* 控制端点」应参照 `/v1/ai/agent/cloud/*` 组而非这两个 purpose。
   - 生产无 qwen 聊天路由：qwen 通道仅覆盖 embedding/ASR，主链路为 DeepSeek；discovery 模型路由按「当前可用路由配置选择」即 DeepSeek 系。
