# Holo 温暖陪伴体验升级：研究发现

## 已确认的核心结论

- 云端化主要解除运行时长、锁屏续跑和输出长度限制，没有自动补齐关系上下文、表达编排与后续回看。
- 当前云端深度分析的结构化结果存在“模型生成了叙事字段、执行器和客户端却未完整传递”的契约损耗，这是分析显得机械的直接原因之一。
- 本地普通聊天与本地 Agent 已有相关记忆、偏好、纠正和目标预取；云端首轮分析主要携带当前问题、工具目录和数据快照，缺少同等强度的关系上下文。
- 现有长期陪伴、个人情境、统一答案、主动性和结果回看方案可以复用；新方案应做整合与落地排序，不再建设第二套体系。
- 统一答案 ADR 已规定 Job 是时间真相源、建议必须类型化、兼容仅发生在 Renderer 边界；本方案不能让“温暖表达层”重新解释时间、证据或建议排序。
- 个人情境产品化方案已经给出来源核查、权限、行动确认、共同经历和约定回看边界；本方案应把这些能力接入云分析，而不是重新定义另一套隐私或执行规则。
- 既有方案明确要求：只有真实成功操作或用户明确反馈才能形成共同经历；回看应用内优先、通知单独同意，不承诺后台准时生成。
- 既有连续追问方案已经否决“整段聊天历史大 Context”，应复用 Result lineage 与 Context Snapshot，只带当前任务必要信息。
- 当前仓库存在大量与本方案无关的用户改动；本轮只新增方案文档，不修改、暂存或覆盖现有代码。
- 首轮普通深度分析已经被明确路由到云端独占轨道；周计划与续问仍走本地轨道，因此同一用户会在不同入口感受到不同程度的“被记得”。
- 本地 Agent 会在生成前确定性预取相关记忆、活跃目标、明确纠正和稳定偏好；云端执行器当前只把 `agent_loop`、工具目录和本轮问题组成消息，形成了上下文能力不对称。
- `agent_loop` 校验器已接受 `title`、`narrativeSummary`、`keyInsight` 和 claim 级 `interpretation`，但云端完成结果只持久化 title/claims/reasoning/evidence；iOS 契约也未声明后三类叙事字段。
- iOS 云结果最终把每条 claim 命名为“发现 N”，摘要是 claim 用分号拼接。即使模型已经生成自然摘要，当前链路也无法呈现。
- 云快照覆盖 11 类数据目录、默认 180 天、每类最多 2,000 行；“拥有更多数据”并不等于“知道当前应该采用哪几条个人背景”。
- 当前 Eval 以时间、工具、证据、安全、展示健壮性等确定性门禁为主；自然表达只由少量人工 rubric 处理，尚无关系姿态、情境反事实、叙事保真和回看连续性的正式类别。
- 主动性评分器已经进入 Memory Observer 的 Tier 2 触发链，但当前信号维度仍主要由目标信号数量和固定参数推导，且明确不拥有通知授权；它更像“是否值得后台深挖”的局部门槛，还不是完整的陪伴触达系统。
- Outcome Review 当前是 UserDefaults 中最多 50 条轻量记录，实际接线只确认 Memory Insight 创建任务成功后登记；还缺用户约定、基线快照、到期协调、真实数据重读和统一展示。
- 现有长期陪伴方案已经定义三种互动姿态、情感安全、主动机会与回看工单；本方案的价值是把“云分析温度”作为进入完整陪伴闭环的 Release A，而非覆盖既有路线图。
- Persona Preamble 已经足够明确，继续叠加人格形容词的收益很低，且会增加规则冲突；应让人格由结构化上下文、两阶段生成和产品行为真正落地。

## 待补充证据

- 当前结果回看、主动性评分、交互姿态相关代码的实际接入状态。
- 当前真实评测体系中，关系姿态、上下文反事实和叙事保真度的覆盖情况。

## 已收敛的架构约束

- `Verified Result` 负责事实、范围、证据与建议结构；`Relational Composer` 只负责表达顺序、语气与承接，不得新增事实或动作。
- 所有新旧结果兼容仍集中在现有 Renderer，不允许 Chat UI、云客户端和 Prompt 各自做一次自然语言解析。
- “记得你”必须能回指合法来源；没有相关来源时宁可给通用帮助，也不能表演式个性化。
- 原始历史默认不上送；优先上传经本机筛选、带来源与权限版本的结构化摘要。
- 主动触达和结果回看不进入第一阶段的发布阻塞条件，但从一开始预留 lineage、action 与 review 契约，避免后续重做。

## 推荐方向草案

采用“事实层与关系表达层分离”的统一链路：本地选择最小必要情境 → 云端完成证据化分析 → 保留完整语义结果 → 关系表达编排 → 用户行动 → 约定回看 → 更新记忆与偏好。

## 直接根因与对应修复层

| 根因 | 用户表现 | 修复层 |
|---|---|---|
| 叙事字段在云端结果链路丢失 | 标题之外仍像数据列表 | P0 契约保真 |
| 云端缺少本地已具备的关系上下文 | 分析准确但不像“懂我” | P1 上下文同源 |
| 同一模型同时查数、验证、写作 | 为守格式而僵硬 | P2 事实与表达分层 |
| 分析结束即终止 | 每次像第一次咨询 | P3 行动与回看 |
| 评测只强测正确、不强测关系质量 | 技术绿灯但体感不稳 | 全阶段双轨评测 |
