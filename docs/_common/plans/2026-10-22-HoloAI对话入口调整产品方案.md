# HoloAI 对话入口调整产品方案

> 后续方向已更新：参见 [2026-10-23「一个发现」洞察引擎与设置整合](2026-10-23-HoloAI一个发现与设置整合/产品与引擎方案.md)。本稿保留为前一轮讨论记录；其规则选题试点不作为当前推荐实施方向。

> 日期：2026-10-22  
> 版本：V0.1 · 产品评审稿  
> 状态：方向提案，尚未确认开发范围；本文不构成实施或部署授权。  
> 讨论起点：对话框上方的「深度分析、今日状态、周期回放」不再适合当前产品，需重新判断这块区域的用途。  
> 阅读提示：文中的界面文案、用户记录、分析结果都是设计示例；规则中的数量与时间窗口是待验证的初始建议。

## 1. 要做的产品决策

建议把对话入口从「展示 Holo 有哪些功能」逐步调整为「帮助用户开始和继续一个有价值的对话」。

完整方向包括三部分：

1. 新会话：有足够依据时，提供一个从用户记录中产生的具体话题。
2. 对话中：围绕当前问题，提供有明确作用的下一步，而不是一直陈列固定功能。
3. 主动发起：深度分析、周期回放、目标规划仍有固定、可发现的入口，用户随时可以使用。

**推荐先验证第 1 部分，不建议一次性重做整个对话页。** 先证明「基于真实记录的话题能带来有价值的对话」，再决定是否撤掉常驻胶囊、增加对话后的动态操作。

这不是已决定替换成另一排按钮，也不是把现有 AI 分析能力推倒重建。

## 2. 现状与问题

### 2.1 当前实现事实

以下按本次查阅的工作区代码描述，不等同于已发布版本，尤其工作区存在其他在途改动。

| 位置或入口 | 当前行为 | 本方案涉及的判断 |
|---|---|---|
| 常驻能力行 | 实际包含深度分析、今日状态、周期回放、规划目标四项 | 需要一并考虑规划目标，不能只处理用户提到的三项 |
| 深度分析 | 展开场景目录；选场景预填问题，用户确认发送 | 保留明确分析意图和发送前确认 |
| 今日状态 | 预填「帮我看看今天的整体状态」 | 提问范围宽，用户难预期答案的价值 |
| 周期回放 | 弹周期选择，进入独立回放生成流程 | 是报告生产任务，与一般聊天的使用节奏不同 |
| 规划目标 | 进入目标规划流程 | 不能把已有流程简单换成一句普通提问 |
| 新会话空态 | 根据引导状态展示使用指南、今日状态、深度分析、长期模式等 | 与常驻能力行存在重复引导 |
| 报告页 | 已有报告档案、阅读及部分报告追问能力；空态仍可引导回对话发起分析 | 报告能力已有承接位置，但发起入口需补齐，不能假设迁移已经完成 |

### 2.2 用户反馈与产品假设要分开

已知反馈：东林认为「今日状态、周期回放」比较鸡肋，原有胶囊不适用。

当前尚无本次方案可用的点击、发送、阅读或留存基线。以下是产品判断，需要验证：

- 「今日状态」缺少明确问题，容易把不同模块的数据各说一点，用户看完不清楚获得了什么。
- 「周期回放」适合特定时点集中阅读，不一定适合每次聊天常驻。
- 固定功能名称让用户先理解产品能力，再自己构造问题；不知道能问什么的人仍然不知道怎么开始。
- 所有对话都展示同一组入口，不能帮助用户延续当前讨论。

不能据此直接认定回放能力没有价值。入口使用少，也可能源于发现性、生成等待或报告质量问题。

## 3. 产品目标与边界

### 3.1 目标

| 用户情况 | 期望获得的帮助 |
|---|---|
| 有明确问题 | 可以立即输入，不经过推荐话题或功能选择 |
| 没有明确问题，但积累了记录 | 看见一件与自己有关、值得进一步聊的事情 |
| 已经在聊某个问题 | 知道如何核对、继续理解，或讨论下一步行动 |
| 想做固定任务 | 能稳定找到分析、回顾和规划入口 |
| 数据少或不希望被主动分析 | 界面依然可用，没有虚构的个人洞察 |

### 3.2 本方案不覆盖

- 不重写深度分析、回放和目标规划的核心执行流程。
- 不承诺聊天可以完成尚未验证的跨记录检索或任意数据查询。
- 不建设每日自动报告，不增加主动推送。
- 不默认建立心理画像，不从零散记录断言情绪、人格或因果关系。
- 不因展示推荐话题而自动创建任务、习惯或目标。
- 不将用户原始记录用于新增的分析埋点。

## 4. 完整方向：不同位置承担不同任务

| 位置 | 主要任务 | 展示内容 | 不承担的任务 |
|---|---|---|---|
| 新会话正文 | 帮用户开口 | 至多一个有依据的话题；无话题时展示少量能力示例 | 不做个人状态总览，不堆推荐信息流 |
| 输入框 | 承接用户表达 | 自由输入、发送、必要的明确模式提示 | 不要求先选功能才能聊天 |
| 单条回答之后 | 承接当前问题 | 至多两个相关下一步；没有合适动作时不展示 | 不反复展示通用功能菜单 |
| 固定能力入口 | 用户主动找功能 | 深度分析、周期回放、规划目标 | 不伪装成个性化推荐 |
| 报告页 | 发起、阅读、找回报告 | 分析与回放的发起入口、生成中和已完成报告 | 不把报告仅作为一次性聊天气泡 |

完整形态中，固定能力可通过对话页一个明确标识的「能力」入口访问，不建议仅藏在无文字的加号里。最终位置需在设计评审确认。已有附件或输入工具菜单不应被混为同一层。

## 5. 核心 Use Case 与用户动线

### UC-01：无明确问题，从记录线索开始

**前提：** 用户有允许 AI 使用的记录，其中存在可核对的线索。本文用「任务多次延期」举例。

**用户目标：** 看看最近有没有一件自己值得留意的事。

1. 用户主动新建会话。
2. 页面展示：「『整理作品集』的截止时间近两周调整了 3 次。」下面提供「这件事为什么一直没推进？」。
3. 用户可先点「查看相关记录」，也可点话题，把完整问题带入输入框。
4. 完整问题示例：「整理作品集这件事最近一直没推进。结合相关记录，帮我看看目前能确定的阻碍；不确定的地方先问我。」
5. 用户修改或确认后发送，Holo 才执行对应查询或分析；需要深度分析时，发送前明确模式与额度。
6. Holo 区分事实、解释假设与缺失信息，再问一个影响判断的问题。
7. 用户自由回答，继续讨论。

**成功条件：** 话题让用户开启了原本不容易提出、但与自己有关的问题；回答有可核对的帮助。

**失败与退出：** 依据失效则不展示该话题；用户可忽略、关闭或选「不再推荐这条」。不把没有点击解释为用户不关心任务。

注意：这个例子依赖任务延期历史真实存在且可读取。如果只有当前截止时间，就不能声称「调整了 3 次」，也不能用当前数据倒推出延期历史。

### UC-02：有明确困扰，直接聊天

**用户目标：** 「我想恢复运动，但每次坚持几天就停，怎么办？」

1. 用户直接输入并发送，不需点击任何话题。
2. Holo 明确当前困难，必要时询问中断原因。
3. 在能力与授权允许的情况下，结合用户过去相关记录；没有记录时明确说明，不编造过去经历。
4. 一起讨论可行的一步，不直接生成整套计划或写入记录。
5. 若用户希望执行，进入既有可确认的创建流程。

**后续阶段可出现的动作：** 「看看以前重新开始的记录」「讨论一个最小行动」。只有能执行对应行为时才展示。

**成功条件：** 用户表达不受推荐入口打断，建议能承接当前处境。

### UC-03：明确想做周／月回顾

**用户目标：** 周末集中回顾，而不是随便聊聊。

1. 用户进入报告页，或从对话页固定能力入口选择「周期回放」。
2. 选择周期，看到数据范围、必要隐私说明及额度提示。
3. 用户确认生成，沿用既有回放任务与恢复机制。
4. 在报告页或原有消息入口找回结果。
5. 若回放当前尚无报告内追问能力，提供明确的「带着这份回顾继续聊」承接；该能力需另行验证，不能套用深度分析已有追问能力。

**成功条件：** 常用回顾用户能稳定找到入口，生成结果没有丢失。

### UC-04：新用户或记录不足

1. 用户进入新会话，页面没有个人线索。
2. 新用户保留使用指南；其他用户展示少量真实可用的能力示例，例如「我可以让 Holo 帮我做什么？」。
3. 通用示例明确是「可以试着问」，不写「根据你的记录发现」。
4. 用户可以直接输入；不要求先多记几天才允许聊天。

**成功条件：** 没有数据时依然有清楚的起点，不产生被误读或被监视的感觉。

### UC-05：已有一段对话，想继续上次的事

1. 用户打开既有会话，保留原对话及输入内容。
2. 不在原对话顶端或底部插入新的开场推荐。
3. 如已进入目标规划或草案确认，仍按原流程继续，不被新话题抢占。
4. 想聊另一件事时，由用户主动新建会话。

**成功条件：** 新入口不破坏对话连续性，也不劫持当前规划或分析意图。

## 6. 记录话题的产品规则

### 6.1 话题必须同时满足四个条件

1. **事实成立：** 有明确可读取的记录支持；数量、时间范围、对比口径准确。
2. **值得继续：** 问题指向理解、核对或选择，答案不是把卡面上的事实再念一遍。
3. **能够承接：** 当前能力能读取依据并处理问题；不能只生成一个好问题却无法回答。
4. **用户允许：** 只使用 AI 可见、未删除、授权范围内的数据；排除规则覆盖推荐、解释、发送和回答全过程。

不满足条件时，不展示该话题。数据多也不意味着必须展示。

### 6.2 一条话题的必要内容

| 内容 | 要求 |
|---|---|
| 事实线索 | 一句话说明为什么出现这个话题，带必要时间范围 |
| 可聊的问题 | 一句用户能理解的问题，不使用「跨域关联」等内部能力分类 |
| 记录依据 | 可打开查看的来源，不能仅显示一个无法核对的数量 |
| 完整发送内容 | 点击后先预填，用户可以编辑与取消 |
| 执行类型 | 明确是普通对话还是深度分析；不能静默切换到付费／计次流程 |
| 反馈 | 关闭本次、不再推荐这条；主动线索功能提供独立开关 |

缩短后的胶囊文字只是展示标题；执行所需的时间范围和对象必须以可见方式带入完整问题，不能让模型根据「最近」自行猜测。

### 6.3 展示、更新与去重

初始建议，需通过试用校准：

- 每个新会话最多展示 1 条个人话题，不提供「无限换一批」。
- 优先近期、有新事实、能明确承接的问题。候选同等时优先非敏感主题，不用负面程度排序。
- 用户停留、打字、查看来源时，不刷新或换掉话题。输入草稿不被话题点击直接覆盖；草稿非空时先让用户选择保留还是替换。
- 近期候选可先考虑过去 14 天，比较类必须另有足够的可比基线；不拿不完整周期作同口径结论。
- 同一主题与同一批证据，7 天内不重复展示；有实质新记录才可重新评估。点击关闭仅关闭当前展示；「不再推荐这条」持续抑制同一候选，除非用户主动恢复。
- 问题已发送后，不再作为新会话推荐反复出现；不推断问题已经解决。
- 原记录删除、编辑或被排除出 AI 时，相关候选失效；展示前和发送前重新核对，不保留可用的敏感旧摘要。
- 话题准备失败或没有候选，不阻塞聊天，也不出现要求用户重试的全屏错误。

### 6.4 不应出现的话题

| 不合适的示例 | 原因 |
|---|---|
| 「你最近是不是越来越焦虑？」 | 从有限记录推断心理状态，并诱导用户接受判断 |
| 「加班导致你花钱变多了」 | 同期变化不足以证明因果 |
| 「你有 21 条记录，来看看吧」 | 没有具体讨论价值 |
| 「最近花费暴涨」但数据仅覆盖两天 | 缺乏可比范围，语气夸大 |
| 「你又没有坚持下来」 | 将记录缺失等同于失败，带评价意味 |
| 无依据却展示「你反复提到……」 | 冒充个性化发现 |

健康、亲密关系、财务困境等敏感内容不进入首轮主动话题试点；用户主动问时仍按既有授权和能力处理。

## 7. 会话后的下一步：完整方向，暂不进入首轮

这是与开场推荐独立的一项能力，不应为了视觉完整而一起开发。

| 当前回答情况 | 合适的动作 | 执行要求 |
|---|---|---|
| 给出了来自记录的判断 | 查看相关记录 | 打开真正对应的来源，不是发送「查看记录」四个字 |
| 用户想核对长期反复的情况 | 找找以前类似的时候 | 具备跨时段检索和可说明的范围；否则不显示 |
| 用户表达想改变，但尚未选行动 | 讨论下一步行动 | 预填可编辑问题，继续讨论；不直接写入任务 |
| 用户明确想建立目标 | 转入目标规划 | 用户确认后进入既有规划流程，携带必要上下文 |
| 回答尚在生成或需要用户澄清 | 不展示通用动作 | 优先等回答完成或用户回应 |

每次最多两个动作，放在对应回答之后，避免输入框上方长期占用空间。必须能从界面区分「查看」「继续提问」「创建」三种后果。

## 8. 现有入口的处理

### 8.1 完整形态的建议

| 现有入口 | 最终建议 | 撤除前的条件 |
|---|---|---|
| 深度分析 | 保留固定能力入口及报告页发起入口；保留场景选择 | 新入口可发现，显式场景和额度语义完整保留 |
| 今日状态 | 撤掉常驻胶囊；用户仍可自由询问 | 验证替代引导不使开场更困难 |
| 周期回放 | 报告页承担主要发起入口；对话页能力菜单可达 | 报告有无内容、生成中、失败态均能找到发起入口 |
| 规划目标 | 保留在固定能力入口；相关对话中可明确转入 | 能无损进入既有规划流程，不被普通聊天替代 |
| 使用指南 | 保留在新人空态或帮助入口 | 不重复占据常驻行 |

### 8.2 第一阶段不先调整的部分

首轮保留原有四项固定能力入口和处理流程，保持原有报告页结构。只在新会话空态试验一个替代的开场区域，避免与旧空态建议卡重复堆叠。新人使用指南单独保留。

因此，首轮既能验证新方向，也能在无效时直接退回原有空态；无需先承受全局入口迁移成本。

## 9. 分阶段范围与推进条件

### 阶段 A：新会话话题试点（推荐先做）

**核心问题：** 用户是否真的愿意围绕一条有依据的个人线索发起并继续对话？

范围：

- 一个开场话题位，先开放给明确愿意试用的用户，提供关闭选项。
- 仅支持一种经可行性验证的、非敏感数据场景，例如用户选择的任务主题。
- 先用可核对的结构化事实与模板提问，不做任意想法的语义扫描，不做跨域因果推断。
- 查看来源、预填确认、时间范围、明确路由、失效处理与反馈是完整链路的一部分，不能只做卡面。
- 不在每次打开聊天时调用模型全量扫描记录；本阶段不新增后台云端话题生成。
- 固定能力入口保持可用，不新增对话后的动态操作。

**场景选择闸门：** 先确认数据是否存在、用户是否需要讨论、当前 AI 是否答得出来。任务延期历史只是候选，不是默认已经具备。若只能做出「罗列逾期任务」这种已知事实，应换场景或停止试点，不能为完成入口而硬凑问题。

**完成标准：** 至少一条真实可执行的端到端动线成立，包括无候选、记录撤销、输入草稿及额度不足等状态。

### 阶段 B：固定入口整理

前提：阶段 A 有明确的价值证据，且固定能力入口的可发现性经过验证。

- 先补齐报告页始终可达的分析／回放发起入口。
- 再将对话页四项常驻入口收敛至一个带文字的「能力」入口。
- 移除今日状态常驻位，不删除相应自由提问能力。
- 验证老用户发起深度分析、回放与规划的成功率和操作步数。

### 阶段 C：更多线索与对话延续

前提：单场景线索已稳定带来价值，来源可核对、成本可接受、用户接受主动话题。

- 增加少量其他记录场景，语义类线索单独评估质量、隐私与成本。
- 加入回答后的相关动作，逐项验证检索、追问和转规划能力。
- 用户主动表达的困扰可以贯穿检索、理解和行动，但不把每次聊天都引向建立目标。

不设未经评估的工期；三个阶段分别评审，不自动顺延开发。

## 10. 能力依赖与隐私边界

| 能力 | 当前依据 | 进入开发前需确认 |
|---|---|---|
| 分析场景预填与明确发送 | 当前代码已有 | 新话题如何携带对象和范围，保持原有确定路由 |
| 回放任务与报告档案 | 当前代码已有 | 报告页各状态的直接发起路径 |
| AI 数据使用排除 | 当前工作区已有想法 AI 可见性判定 | 所有候选生成及缓存是否复用同一口径；不视为已完成验收 |
| 主动话题生成 | 本方案新增 | 候选、来源、去重、反馈、撤销，不能等同于已有分析结果 |
| 泛化的跨记录检索 | 不能据现有胶囊确认 | 各数据域的查询范围、引用与来源跳转能力 |
| 话题转规划／行动 | 有既有规划入口 | 上下文携带、草稿确认及避免重复写入 |

本方案不改变「默认不新增上传生活记录」的边界：阶段 A 在本地根据用户允许的数据准备候选；用户确认发送后，按既有通道、隐私说明和额度规则执行分析。未来如需云端主动生成话题，应作为新的数据使用场景单独评审，不能把既有聊天授权解释为持续后台扫描授权。

关闭主动线索后，不继续准备新的候选，也不展示既有个人候选；不影响用户直接提问。推荐文本和缓存同样属于个人内容，遵循来源记录的排除与失效规则。

## 11. 验证方式与指标

### 11.1 先验证问题，不只验证点击

先建立现有入口的基线：分别观察曝光、点击、预填后发送／确认生成、成功完成及退出位置。本文没有引用历史用量文件，不能据此给出历史指标数值。

试点建议保留对照：原有空态与新话题空态使用相同的固定能力行；按用户分组，避免同一用户频繁切换。活跃用户量不足时先做小样本任务访谈，不用少量点击声称留存提升。

| 指标 | 口径与用途 |
|---|---|
| 话题发起率 | 从可见曝光到确认发送；记录点击、预填、发送分步流失，排除仅加载未可见 |
| 有用反馈 | 用户对具体回答是否有帮助的自愿反馈；无反馈不能当作满意 |
| 主动续聊 | 回答后用户是否有实质回应，区分主动输入与点击建议；续聊也可能是在纠错 |
| 问题质量 | 人工核对事实成立、值得讨论、可承接、无越界推断；先用合成或经同意样本 |
| 关闭与纠错 | 不感兴趣、不准确、感觉被过度解读等原因，用来判断主动话题是否打扰 |
| 固定能力使用 | 分析、回放、规划的发起完成率和寻找成本，避免入口整理损害老用户 |
| 成本与响应 | 候选准备成本、打开对话耗时及实际分析消耗；不能靠每次全量分析支撑卡面 |

埋点仅记录必要的匿名／去标识流程事件、候选类型、状态及粗粒度错误，不上传话题原文、记录正文、财务金额或引用内容。具体接入复用项目已有隐私和产品事件规范。

### 11.2 是否继续的判断

- **继续：** 真实样本中出现用户认可的新问题，事实和回答质量通过核对，且没有明显增加打扰与原入口使用成本。
- **调整：** 点击高但发送低，优先检查问题和模式预期；发送高但负反馈高，优先检查回答质量，而不是继续优化卡面。
- **停止：** 只能复述已知事实、需要大量后台分析才能维持，或用户持续认为被误读。

上线数值门槛应在获得基线后制定，不能先拍一个转化率作为成功证明。

## 12. 产品验收清单

| 情况 | 应有行为 |
|---|---|
| 新会话有合格线索 | 最多一条，事实、范围和来源一致，点击不自动发送 |
| 没有合格线索 | 可直接聊天，显示适量通用引导，不冒充个性化 |
| 输入框已有草稿 | 不被推荐问题静默覆盖 |
| 用户进入已有会话 | 不插入新的开场话题，不打断规划或草案确认 |
| 话题涉及分析额度 | 发送前明确模式，耗尽时保留输入并说明原因，不静默降级或消耗 |
| 来源删除／被排除 | 候选失效，发送前再次核对，不能通过缓存继续使用 |
| 用户编辑了预填问题 | 时间、对象、模式保持可见一致；改变意图时可明确退出原模式 |
| 网络不可用或话题准备失败 | 不阻塞输入，既有长任务恢复规则保持有效 |
| 用户关闭主动话题 | 不再展示或生成个人候选，直接提问仍然可用 |
| 字体放大／辅助功能 | 事实、完整问题、模式及操作标签均可读，不靠横向截断传达关键条件 |
| 收起旧入口后（阶段 B） | 报告空态、已有报告、生成中及失败态均有明确的发起路径 |
| 创建或转入规划 | 明确确认后执行，无重复记录，普通追问不被误当作规划回答 |

## 13. 原型与本方案的关系

此前原型用于解释交互方向，不能直接作为开发规格。需要收敛的地方：

- 「线索邀请」与「轻量胶囊」是同一机制的两种呈现，不是两套都要开发的功能。
- 原型使用了虚构想法和任务记录；正式产品必须先有证据，后有提问。
- 原型中的任意发送、参考记录、继续讨论均为演示，不证明实际 Agent 能力已满足。
- 「找找以前类似的时候」「整理下一步行动」归阶段 C，不进入阶段 A。
- 原型的加号菜单不是最终入口决策；固定能力需保持可发现。
- 推荐优先评审「线索邀请」：它能解释为什么推荐这个问题；最终视觉应遵循 Holo 现有设计规范，不沿用概念原型的独立样式。

## 14. 本轮评审需要决定什么

| 决策 | 当前建议 | 决策影响 |
|---|---|---|
| 是否接受总体方向 | 接受作为待验证方向 | 后续围绕具体话题，而非仅换功能名称 |
| 首轮是否撤掉全部胶囊 | 不撤，先验证新会话话题 | 避免把话题价值与入口迁移效果混在一起 |
| 首轮选什么场景 | 一种非敏感、事实可核对且有讨论价值的场景 | 需要数据与能力核验后才能确定，不先承诺全域覆盖 |
| 主动推荐是否可关 | 提供独立开关，试点用户明确开启 | 控制主动分析的预期和打扰 |
| 是否同时开发动态追问动作 | 不同时开发 | 限定成本，避免一次性改造全链路 |
| 是否删除周期回放能力 | 不删除 | 另行验证其质量与主要使用场景 |

本稿建议的下一步是评审阶段 A 的价值与场景，形成更小的执行规格；不是直接照完整原型开始开发。
