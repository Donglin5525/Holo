# Holo 全模块精细化：实施与问题台账

## 产品目标与边界

东林确认：保留品牌橙、首页光球与品牌表达，系统精修业务页面。优先解决结果不可信、动作不完整、文字不可读、点击区域失效，再处理页面层级与细节。图表系列色、用户分类色、习惯色与纪念日仪式主题按原语义保留。

本轮在主副本直接实施；开工前保存了工作区基线用于核对增量。原有票据、任务日期/提醒、补签、导入结果等在途改动保留。验证使用独立无窗口模拟器，未安装到真机，未操作生产后端或 CloudKit 开发库。

**状态：确定性问题修复及公共规则已落到代码；整体观感、真机手感、iPad 横竖屏和双设备同步不能据此标记验收完成。视觉挑刺需要一次只读子代理授权，已向东林发出请求；未获回复前不执行判读。**

## 共性与实施规则

1. 视觉改版必须同时核对语音、复制、手势、反馈、返回和撤销，不只核对控件是否存在。
2. 成功提示由真实成功结果驱动；失败保留内容并能重试。保存后已写入回执，不再另补一次成功状态。
3. 导航、统计范围和显示日期用统一事实状态；列表选项必须点整行生效，不能只有文字可点。
4. 业务正文使用 Tool 语义色；状态淡底按合成后的实际颜色检查。禁用按钮用中性实底，避免把橙色压透明叠成泥棕。
5. 动态文字、少量数据与大字号必须有明确布局；数值连同单位展示，单点保留真实点，缺失不填零。
6. 重复提交和并行冲突有统一结果；失败只恢复本次涉及的字段，禁止通过共享上下文全局 rollback 丢掉其他编辑。

颜色、字体、热区和失败反馈的当前规则已并入 `docs/standards/设计规范.md`，以现有设计系统和资源为准。

## 继续收口的顺序

1. 完成只读视觉挑刺：正常、零数据、1～3 条记录、长文本、深色和大字号；以问题列表及对应截图为结果，不给笼统“全部 PASS”。
2. 对确认问题在共享组件或真实状态入口修复，逐批重新验收；P16/P17/P18 尚缺的专项不可伪装成已完整覆盖。
3. 真机验证返回、键盘、触觉、拖拽中断与滑动；iPad 再验证横竖屏与长内容。
4. 高优先级问题关闭且验证边界清楚后，按本轮增量限定提交范围。涉及后端/Prompt 的新增问题另做双端同步与部署验收。
