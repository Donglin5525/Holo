## 一、产品结论

记忆长廊的日历区域只保留一套时间尺度控制：

| 时间尺度 | 页面形态 | 用户要回答的问题 |
|---|---|---|
| 日 | 单日回放 | 我这一天经历了什么？ |
| 周 | 多日时间网格 | 这一周的时间和记录分布有什么规律？ |
| 月 | 热力月历 | 哪些日子有记录，我要找的那一天在哪里？ |

删除所有“网格 / 回放”“网格 / 列表”等二级视图切换按钮。

最终产品结构不是“三种数据页面”，而是同一段生活记录的三种观察距离：

```text
月：定位日期、观察活跃度
          ↓ 放大
周：比较多日时间分布
          ↓ 放大
日：阅读当天完整回放
```

这套结构的核心价值是降低选择成本。用户不需要先决定看哪一天，再决定用网格还是列表；时间尺度本身就决定最合适的浏览方式。

## 二、为什么要改

### 2.1 当前代码的实际映射

当前 `CalendarRootView` 已经完成“日 / 周 / 月”三档统一，但页面职责仍然是：

```text
.day   → WeeklyGridView      // 三日泳道网格
.week  → WeeklyListView      // 无限向过去加载的周列表
.month → MonthlyCalendarView // 热力月历
```

同时，当前工作区刚从旧的“周历 / 月历 + 网格 / 列表”双切换结构收敛到单一时间尺度，这是正确方向。但“日”仍然使用跨三天比较的网格，“周”仍然使用逐日列表，时间尺度与阅读任务没有完全对应。

### 2.2 用户面对的真实问题

用户进入记忆长廊通常不是为了管理未来日程，而是完成三个回看任务：

1. **回想一天**：今天发生了什么、完成了什么、记下了什么。
2. **比较一周**：哪几天最忙、习惯集中在什么时候、记录是否断档。
3. **定位历史**：快速找到某个月、某一天，再进入具体记录。

三种任务需要不同的信息密度。让用户在同一个时间尺度内继续切换“网格 / 回放”，等于把设计决策重新推给用户。

### 2.3 原回放原型的视觉问题

早期原型左右两侧都形成了独立视觉板块：

- 左侧像数据监控仪表：白色底板、密集彩条、图标堆叠，信息权重过高。
- 右侧像另一个深色应用：深靛背景、图片缩略图和高对比选中卡，与 Holo 温暖、克制的卡片体系割裂。
- 两侧同时抢夺注意力，中间真正的生活记录反而变窄、变弱。

本方案不取消时间轴和日期快速切换，但将它们降级为辅助导航：左侧是“时间脉络”，右侧是“日期记忆珠”，中间记录始终是视觉主角。

## 三、目标与非目标

### 3.1 产品目标

1. 用户进入日档后，5 秒内理解当天最重要的记录和时间顺序。
2. 用户在周档中能快速比较多日的记录密度和发生时段。
3. 用户在月档中能快速找到有记录的日期，并进入当天回放。
4. 日、周、月切换时保持同一日期上下文，不让用户重新定位。
5. 所有页面忠实呈现原始记录，不伪造时间、不静默隐藏加载失败。
6. 视觉上符合 Holo 的温暖、轻盈、克制，不做强装饰和重色块拼接。

### 3.2 用户体验目标

- **清楚**：每个时间尺度只有一种主要浏览方式。
- **可信**：时间、来源、记录数量和失败状态可解释。
- **有感情但不煽情**：页面像翻阅自己的生活，而不是看业务报表。
- **高效**：查找记录不因叙事化而变慢。
- **可持续**：数据从几条增长到几年后，仍然能定位和浏览。

### 3.3 非目标

- 不在日历中新增、编辑记录；它仍是只读回看入口。
- 不在本次改造中新增 AI 生成、Prompt 或后端能力。
- 不重构“洞察”Tab；日历负责事实，洞察负责理解。
- 不把未来计划与历史回放混成同一叙事。
- 不为了模仿参考图加入虚构照片、封面或不存在的媒体素材。

## 四、核心设计原则

### 4.1 一种时间尺度只对应一种浏览方式

用户选择“日 / 周 / 月”已经表达了浏览目的，不再增加二级视图按钮。

### 4.2 事实优先，洞察后置

日历页首先回答“发生了什么”。本地观察摘要可以轻量出现，但 AI 深度分析、跨域关联和周期回放继续放在“洞察”Tab，不混入每张事实卡。

### 4.3 同一日期是跨视图的唯一锚点

日、周、月不是三个独立页面。用户当前聚焦的日期必须在切换后继续被保留。

### 4.4 不制造虚假时间精度

有可靠时刻的记录进入小时脉络；只有日期、没有可靠时刻的记录进入“当天记录”区，不允许为了排版强行放到 00:00。

### 4.5 让辅助导航保持安静

时间刻度和日期导航默认使用中性色，只在当前时间、当前日期、选中事件上使用 Holo 橙。模块色仅用于小面积识别，不形成大色块竞争。

### 4.6 完整性优先于炫技

密集时段可以动态拉长或进入事件组详情，不能通过缩小文字、卡片重叠或直接省略来换取“看起来整齐”。

## 五、信息架构与公共页面结构

### 5.1 记忆长廊一级结构

```text
记忆长廊
├── 日历
│   ├── 日：单日回放
│   ├── 周：多日时间网格
│   └── 月：热力月历
└── 洞察
    ├── 理解档案
    ├── Daily Sense
    ├── 活跃热力图
    ├── 一起做的计划
    └── AI 回放 / 精选故事
```

“日历 / 洞察”回答的是“看事实还是看理解”；“日 / 周 / 月”回答的是“从多远的时间尺度看事实”。两级导航语义不同，因此可以并存。

### 5.2 日历公共头部

从上到下固定为：

1. 记忆长廊导航栏：返回、标题、日历/洞察。
2. 时间尺度行：前一周期、日/周/月、后一周期、今天/本周。
3. 当前日期标题：完整显示当前日、周范围或月份。
4. 模块筛选：全部、记账、习惯、待办、想法。
5. 部分失败提示：仅失败时出现。
6. 当前尺度内容。

不再出现任何“网格 / 列表 / 回放”按钮。

### 5.3 三档标题与导航语义

| 档位 | 标题示例 | 左右箭头 | 回正按钮 |
|---|---|---|---|
| 日 | `8月19日 周三` | 前/后一天 | 今天 |
| 周 | `8月17日 – 8月23日` | 前/后一周 | 本周 |
| 月 | `2026年8月` | 前/后一月 | 今天 |

周档中的网格内部横滑只在当前周内移动三日窗口；顶部箭头才负责切换整周，避免“箭头和手势到底差几天”的混乱。

## 六、跨日 / 周 / 月的日期连续性

### 6.1 单一聚焦日期

产品层只允许存在一个 `focusedDate`：

- 日回放展示 `focusedDate` 当天。
- 周网格展示 `focusedDate` 所在周，并尽量让该日处于三日窗口中间。
- 月历展示 `focusedDate` 所在月，并高亮该日。

当前代码中的 `anchor`、`gridCenterDay`、`selectedDay` 分别维护日期，容易在切换尺度后产生“标题变了、选中日没变”或“月历已翻月、详情还停在旧月份”等不同步问题。实施时应收敛为单一事实源，其他日期状态从它派生。

### 6.2 切换规则

| 用户动作 | 结果 |
|---|---|
| 日 → 周 | 保留当前日，进入它所在周，当前日保持高亮 |
| 周 → 日 | 进入周网格当前聚焦日（聚焦日贴边时同样成立） |
| 周 → 月 | 进入当前聚焦日所在月，并选中该日 |
| 月 → 周 | 进入月历选中日所在周；未选中则用当月今天或月首 |
| 月 → 日 | 进入月历选中日回放；未选中则用当月今天或月首 |
| 月历点日期 | 先在月档显示当天详情，不自动跳页 |
| 点“回放这一天” | 切换到日档并保留选中日期 |

避免用户点一下月历日期就突然进入另一页面；下钻必须由明确的“回放这一天”动作触发。

### 6.3 未来日期

记忆长廊默认记录的是已发生事实：

- 日回放默认不允许滑到今天之后。
- 当前周网格可以看到今天之后的空列，但要弱化显示，不暗示已有记忆。
- 若未来开放“按计划日期/截止日期”查看待办，必须用“计划”语义和独立状态表达，不能混入默认完成事实。

## 七、日视图：单日回放

### 7.1 用户任务

日回放不是“日程表的单日版”，而是帮助用户复原一天：

- 这一天什么时候发生了什么？
- 哪些记录最值得重新打开？
- 当天是否存在断档、密集时段或重复行为？
- 如何快速切换到前后几天继续回看？

### 7.2 页面结构

```text
┌──────────────────────────────────┐
│ 这一天留下了 5 条记录              │  单日可信摘要
│ 07:32—21:10 · 4 个模块             │
├─────┬──────────────────────┬─────┤
│时间 │      当天记忆事件流      │日期珠│
│07   │  ○ 晨间跑步             │ 22  │
│     │    07:32 · 5.2km       │ 21  │
│09   │                        │ 20  │
│12   │  ○ 午餐 ¥42            │ 19● │
│15   │  ○ 完成产品评审          │ 18  │
│18   │  ○ 随手记               │ 17  │
│21   │  ○ 晚间阅读             │     │
└─────┴──────────────────────┴─────┘
```

三列职责：

- 左：告诉用户事件处在一天的哪个时间段。
- 中：承载所有可读内容和点击入口。
- 右：快速切换日期，不承担内容展示。

### 7.3 单日摘要

日档摘要必须使用“这一天”语义，不再复用当前“这周有几天记录”的周摘要。

文案规则：

- 有数据：`这一天留下了 5 条可回看的记忆。`
- 证据：`07:32—21:10 · 4 个模块`
- 单模块筛选：`这一天留下了 3 条习惯记录。`
- 无数据：`这一天还没有留下记录。`
- 部分加载失败：摘要只统计已加载数据，并显示独立失败提示，不把缺失模块算作 0。

`CalendarObservationSummary.Scope` 需要新增 `.day`，日摘要只计算 `focusedDate` 当天数据。

### 7.4 左侧“时间脉络”

视觉规则：

- 宽度建议 32–36pt，不设置独立卡片底色。
- 使用中性小时文字和 1pt 淡线，默认每 2 小时显示一个标签。
- 事件发生处只显示 6–8pt 模块色节点，不显示密集柱状图。
- 当前时间使用 Holo 橙色小节点；历史日期不显示“当前时间线”。
- 时间线与中间事件位置共享同一个轴模型，禁止各自计算偏移。

用户感知应是“时间在旁边提供方向”，而不是“左边还有一张图表要读”。

### 7.5 中间事件卡

每张卡最多分四层：

1. 模块图标：小面积模块色浅底。
2. 标题：真实记录标题，最多两行。
3. 时间与关键结果：如 `12:18 · ¥42 · 餐饮`。
4. 可选上下文：只展示已有可信内容，不由 UI 自行生成结论。

模块示例：

| 模块 | 标题 | 关键结果 |
|---|---|---|
| 记账 | 午餐 | `12:18 · ¥42 · 餐饮` |
| 习惯 | 戒烟 | `18:30 · 第 11 天` |
| 待办 | 完成产品评审 | `15:40 · 已完成` |
| 想法 | 关于节奏的想法 | `18:26 · 2 个标签` |

交互：

- 单击事件卡：打开现有 `CalendarEventDetailSheet`。
- 详情底部“在 X 模块打开”：跳转原始实体。
- 关闭详情：返回原日期、原滚动位置、原筛选状态。
- 原始实体已删除：详情显示“原记录已删除”，不崩溃、不伪造内容。现状是点“在 X 模块打开”回查失败后才弹错误提示；实施时改为详情打开时后台回查 `originID` 存在性，不存在即直接呈现删除态。

### 7.6 时间精度与排列规则

日回放强调顺序准确，不追求像日程软件一样的分钟级几何准确。

规则：

1. 事件按真实时间升序。
2. 同一小时内保持分钟顺序，卡片依次排列。
3. 小时节点对齐该时段，不按分钟比例制造大段空白。
4. 没有可靠时刻的记录进入顶部“当天记录”区，并显示“未记录具体时间”。
5. 不得默认塞到 00:00，因为这会让用户误以为事件发生在凌晨。

### 7.7 密集时段

日档和周档都使用“密度驱动拉伸”，但卡片规格不同，不能直接复用相同高度常量。

日回放建议规则：

- 0 条：压缩为空白时段，仅保留时间方向。
- 1 条：按事件卡自然高度展开。
- 2–4 条：逐条展示，当前小时按卡片总高度动态拉长。
- 5 条以上：展示前 4 条 + `还有 N 条`事件组入口。
- 同标题、同模块、短时间内重复记录：允许聚合为一张“共 N 次”卡，但详情必须能看到全部原记录。

极端情况下宁可页面变长，也不能重叠卡片或把正文缩到不可读。

### 7.8 凌晨 0–7 点

沿用现有折叠契约：

- 默认折叠，顶部显示`凌晨有 N 条记录`。
- 无记录时不展示无意义的空条。
- 单条点击进详情，多条点击进事件组详情。
- 展开后恢复 0–23 点完整时间脉络。
- 折叠状态持久化，但日档与周档可以共享同一用户偏好。

### 7.9 右侧“日期记忆珠”

视觉规则：

- 宽度建议 44–48pt。
- 暖白半透明背景、Holo 边框和极轻投影。
- 不使用深色整条底板，不使用虚构缩略图。
- 默认日期使用中性文字；当前选中日使用 Holo 橙色实心珠。
- 每个日期最多显示 1–3 个模块色小点，表示当天有哪些类型的记录。
- “今天”使用文字标识，不同时叠加多个强强调效果。

交互规则：

- 点击日期珠：切换到该日。
- 在日期珠区域上下拖动：按经过日期连续切换。
- 每跨过一天提供一次轻触觉反馈。
- 松手吸附到最近日期，不停在日期之间。
- 拖动时在日期珠左侧显示`8月19日 · 5 条记录`轻提示。
- 手势必须从日期珠区域开始；中间内容区域的纵向手势始终用于滚动事件流。
- 默认不允许拖到今天之后。

日期珠不是永久日历替代品。远距离定位仍由月档完成，因此只需展示选中日前后的有限日期窗口。

### 7.10 日档空态

空白日期仍然是一段真实生活，不要用警告式空态：

```text
这一天还没有留下记录
你可以继续查看前后日期
```

保留时间脉络和日期珠，让用户可以直接离开空白日。完全新用户可在下方提供“去记录”入口，但不强迫只去记账，应打开 Holo 的统一记录入口。

## 八、周视图：多日时间网格

### 8.1 用户任务

周档主要用于比较，而不是逐条阅读：

- 哪几天最忙、哪几天空白？
- 某类行为通常发生在什么时间？
- 同一时段是否重复出现习惯、待办或消费？
- 本周最密集的时段在哪里？

### 8.2 使用现有网格的原因

当前 `WeeklyGridView` 已经具备：

- 三日可视窗口。
- 横向日期滑动。
- 纵向时间轴。
- 凌晨折叠。
- 密度驱动小时高度。
- 双指缩放和双击重置。
- 事件与事件组详情。
- 当前日期与当前时间强调。

这些能力天然服务“多日比较”，因此从日档迁移到周档比重新制作周页面更合理。

### 8.3 为什么不强塞七列

iPhone 上七列会导致：

- 标题只能显示极少字符。
- 模块色和时间信息难以辨认。
- 点击目标过小。
- Dynamic Type 和长文案几乎不可用。

因此周档仍采用三日可视窗口，整周七天通过横向滑动浏览。

### 8.4 周内导航

- 进入周档时，当前聚焦日期尽量位于中间列。
- 横向滑动：在当前周的七天内按天移动。
- 到周一或周日边界后保持弹性回弹，不直接跨周。
- 边界对齐：聚焦日为周一时三日窗口贴左（周一在首列），为周日时贴右（周日在末列）；伸出周外的位置显示相邻周日期的弱化占位，不响应点击。日期头与事件列必须统一使用同一份「本周七天」列表作为数据源——现状两者分别由 `centerDay±1` 和无限日期流（今天 ±180 天）两套逻辑生成，迁移时必须收敛，否则聚焦日落在周首/周尾时会出现日期头显示了周外日期、事件区却没有对应列的错位。
- 顶部左右箭头：切换前一周/后一周，并保持相同星期位置。
- 点击日期头：将该日设为 `focusedDate`。
- 切到日档：回放当前聚焦日。

这让“滑动”负责周内比较，“箭头”负责跨周定位，两个交互不冲突。

### 8.5 周共享动态轴

同一周七天必须共享一套小时高度，否则横向移动时同一时间会上下跳动。

现有 `WeeklyGridAxisProfile` 高度契约继续保留：

| 单日单小时最大事件数 | 小时高度 |
|---|---:|
| 0–1 | 42pt |
| 2 | 57pt |
| 3 | 84pt |
| 4 | 111pt |
| 5+ | 131pt |

需要修正当前实现中的窗口语义：`computeProfile` 目前按“今天前后 3 天”计算。迁移到周档后，必须按 `focusedDate` 所在完整周的七天计算；周内滑动时 profile 保持不变，跨周后再统一更新。

### 8.6 周摘要与叙事资产

当前 `WeeklyListView` 同时承载：

- 本周观察摘要。
- 日卡与事件 chip。
- 高光与里程碑。
- 向过去无限加载。

切换为网格后，不能静默丢失这些价值：

1. 本周观察摘要保留在网格上方，随内容滚动离场。
2. 高光/里程碑收敛为摘要卡上的轻量入口，如`本周有 2 个高光`。
3. 点击入口打开“本周高光”Sheet，里面复用 `MilestoneNode` 和 `GentleHighlightNode`。
4. 逐条事件改由网格和事件组详情承担。
5. 无限向过去加载不再依赖列表滚到底；跨周使用顶部箭头，远距离定位使用月档。

### 8.7 事件块

- 单小时 0–4 条逐条显示真实标题。
- 5 条以上显示 4 条明细 + `还有 N 条`。
- 点击普通事件进入事件详情。
- 点击溢出进入当前小时完整事件组。
- 模块色只用于浅底和左侧 2–3pt 色条。
- 文字不得小于可读下限，不使用多层卡片重叠。

### 8.8 周档空态

空周仍显示完整七天框架和轻量摘要：

```text
本周还没有留下记录
可以查看上一周，或切到月历寻找有记录的日期
```

不再通过“滚到底自动找上一周”改变用户正在看的时间范围。

## 十、模块筛选

### 10.1 筛选范围

- 全部
- 记账
- 习惯
- 待办

- 日日期珠的活动点只反映当前筛选模块。
- 筛选后为空时显示“这一天没有习惯记录”，而不是通用“没有记录”。

## 十一、视觉设计规范

### 11.1 整体调性

关键词：温暖、安静、可信、留白、生活感。

不使用：

- 大面积深蓝/深紫侧栏。
- 高饱和多色同时铺满。
- 伪照片、伪封面、随机插画。
- 过度毛玻璃和霓虹发光。
- 强烈 3D 翻页或纸张拟物。
- 为了“高级感”牺牲文字可读性。

### 11.2 颜色

严格复用 `DesignSystem.swift`：

| 用途 | Token | 色值/来源 |
|---|---|---|
| 品牌强调 | `holoPrimary` | `#F46D38` |
| 浅强调 | `holoPrimaryLight` | `#FED7AA` |
| 深强调文字 | `holoPrimaryDark` | `#EA580C` |
| 页面背景 | `holoBackground` | Asset，浅色为暖米白 |
| 一级卡片 | `holoCardBackground` | Asset |
| 次级表面 | `holoNestedCardBackground` | Asset |
| 边框 | `holoBorder` | Asset |
| 主文字 | `holoTextPrimary` | Asset |
| 次文字 | `holoTextSecondary` | Asset |

模块色只用于识别：

- 记账：橙。
- 习惯：绿。
- 待办：靛蓝。
- 想法：粉。

单个组件中模块色面积不超过约 15%，其余使用中性卡片体系。

### 11.3 字体层级

优先使用项目语义字体：

- 页面标题：`.holoHeading`。
- 事件标题：`.holoBody` 或 14–16pt semibold。
- 摘要证据：`.holoCaption`。
- 时间与模块标签：`.holoTinyLabel`。
- 金额/关键结果可以加粗，但不超过事件标题一个层级。

标题最多两行，副信息最多两行；长内容进入详情，不在卡片中无限展开。

### 11.4 间距与圆角

- 页面左右边距：16pt。
- 主要卡片间距：12–16pt。
- 卡片内部：12–16pt。
- 卡片圆角：16pt。
- 小按钮/图标底：8–12pt。
- 日期珠：完整胶囊或圆形，不使用不规则尖角。

### 11.5 阴影与边框

- 常规卡片以 1pt 边框为主，阴影只提供分层，不制造悬浮感。
- 选中事件可使用极轻 Holo 橙描边或光晕，不能整卡变橙。
- 日期珠选中态允许轻微品牌色阴影。
- 深色模式下优先提高边框和表面区分，不直接增大阴影。

### 11.6 动效

- 日/周/月切换：150–220ms 淡入与轻微位移。
- 日期珠切换：吸附动画 + 单次轻触觉反馈。
- 事件卡首次出现：仅轻微淡入，不做连续弹跳。
- 高光/里程碑 Sheet：系统 Sheet 动效。
- 开启“减少动态效果”后，移除位移、弹簧和连续动画，仅保留即时状态变化。

## 十二、状态设计

| 状态 | 用户看到什么 | 可执行动作 |
|---|---|---|
| 首次加载 | 保持头部稳定，内容区显示对应结构骨架 | 等待、返回 |
| 正常有数据 | 摘要 + 当前尺度内容 | 浏览、筛选、详情、切换尺度 |
| 当天无数据 | 温和空态 + 前后日期导航 | 切换日期、去记录 |
| 周无数据 | 空周框架 + 上一周/月历提示 | 前一周、月档定位 |
| 月无数据 | 空月历仍可翻月 | 前后月、回到今天 |
| 筛选后为空 | 明确说明当前筛选无记录 | 切回全部 |
| 单模块失败 | 顶部弱提示，其他模块继续展示 | 重试 |
| 当前筛选模块失败 | 内容区明确说明该模块未加载 | 重试、切换筛选 |
| 全部模块失败 | 保留日期上下文，显示失败卡 | 重试、返回 |
| 原记录已删除 | 详情说明来源已删除 | 关闭详情 |
| 密集小时 | 动态拉长或事件组入口 | 查看全部 |
| 只有日期无时刻 | 顶部“当天记录”分组 | 打开详情 |
| 正在续载 | 日期珠/周导航可用，边缘轻量进度 | 继续浏览当前缓存 |

### 12.1 加载骨架

- 日：展示时间脉络、2–3 张灰色事件卡和日期珠轮廓。
- 周：展示日期头、时间轴和浅灰事件块。
- 月：展示 7×N 月格轮廓。

骨架必须匹配最终布局，避免加载完成后大幅跳动。

### 12.2 部分失败可信表达

“没有记录”和“记录没有加载出来”必须严格区分。

文案：

```text
部分记录暂未载入
待办数据加载失败，其他记录仍可查看
[重试]
```

禁止将失败模块按 0 条参与摘要或热力计算。

## 十三、交互与手势冲突处理

### 13.1 日回放

- 中间区域纵滑：滚动当天事件。
- 右侧日期珠纵拖：切换日期。
- 左侧时间脉络：只读，不承载手势。
- 卡片横向不响应滑动，避免和返回手势/日期切换竞争。
- 页面左边缘保留系统返回手势。

### 13.2 周网格

- 网格纵滑：滚动时间轴。
- 网格横滑：移动周内日期窗口。
- 双指缩放：调整小时高度。
- 双击空白网格：恢复 1×。
- 日期头点击：聚焦日期。

手势方向锁定后再响应：横向位移明显大于纵向才翻日期，纵向明显大于横向才滚时间，避免斜向拖动误触。

### 13.3 月历

- 上下滑：滚动月历与当天详情。
- 点日期：选中，不立即跳页。
- 点“回放这一天”：进入日档。

## 十四、无障碍与可用性

### 14.1 触控

- 所有可点击区域至少 44×44pt。
- 日期珠视觉可以小于 44pt，但实际命中区域不得小于 44pt。
- 小型事件块点击区域扩展至完整小时单元格内可用区域。

### 14.2 VoiceOver

建议阅读顺序：

1. 页面标题与时间尺度。
2. 当前日期/周/月标题。
3. 观察摘要。
4. 当前内容事件。
5. 日期快速切换。

日期珠整体提供 Adjustable 语义：

```text
8月19日，今天，5条记录
向上或向下滑动切换日期
```

事件卡合并朗读：

```text
习惯，晨间跑步，7点32分，5.2公里，按钮
```

周网格每个事件必须能独立聚焦；时间轴和分隔线不进入朗读顺序。

### 14.3 Dynamic Type

- 使用语义字体，不硬编码不可缩放字号。
- 辅助级超大字体下，日回放右侧日期珠收敛为顶部“选择日期”按钮，点开系统风格日期 Sheet，优先保证事件卡宽度。
- 周网格事件块至少保留标题；副信息可以进入详情。
- 标题不通过无限缩小维持单行，必要时允许两行。

### 14.4 对比度与色觉

- 模块身份不能只依赖颜色，同时保留图标和文字。
- 浅色模块底上的文字使用主文字色，不直接使用低对比模块色。
- 选中态同时使用颜色、形状和语义标签。

## 十五、数据语义与信任边界

### 15.1 默认事实口径

| 模块 | 时间字段 | 页面语义 |
|---|---|---|
| 记账 | `Transaction.date` | 交易发生/记录时间 |
| 习惯 | `HabitRecord.date` | 打卡时间 |
| 待办 | `completedAt` | 默认展示完成事实 |
| 想法 | `createdAt` | 创建时间 |

区间继续统一使用 `[start, end)`，避免跨日、跨周、跨月重复计数。

### 15.2 不可靠时间

如果数据来源只能确定日期：

- 保留原日期。
- 标记为无具体时间。
- 放在当天记录区。
- 不进入夜间/高峰时段判断。

### 15.3 健康边界

`CalendarModule` 已包含 health，但当前日历主筛选与事件提供链路仍以四个主模块为核心。本次不借 UI 改造偷偷扩大健康数据范围：

- 月档移除跨口径的 `HealthStatusChip`，避免把周健康摘要误解成当月记忆事实。
- 日/周不新增 HealthKit 原始事件。
- 若某个“跑步”来自习惯打卡，按习惯展示，不伪装为健康事件。

### 15.4 AI 边界

本方案所有摘要优先使用本地可验证统计。日历页不因改造触发新的 AI 请求，不产生额外费用，也不依赖网络才能浏览历史记录。

## 十六、现有代码到目标结构的映射

### 16.1 页面映射

```swift
switch viewModel.scale {
case .day:
    DailyReplayView(...)
case .week:
    WeeklyGridView(...)
case .month:
    MonthlyCalendarView(...)
}
```

### 16.2 实际落地组件

```text
Views/MemoryGallery/Calendar/Daily/
├── DailyReplayView.swift
└── DailyReplayEventCard.swift

Views/MemoryGallery/Calendar/
└── MemoryTimeChapterHeader.swift

Models/Calendar/
├── DailyReplayPresentation.swift
└── MemoryTimeChapterPresentation.swift
```

职责：

- `DailyReplayView`：把日期组织成连续章节；向下自然进入下一天，连续空白日折叠，直到今天停止。
- `DailyReplayEventCard`：日回放与月历下钻共用的四模块事实卡。
- `DailyReplayPresentation`：同一分钟、同模块聚合为一个“记忆时刻”，并处理无可靠时刻与轻叙事。
- `MemoryTimeChapterHeader`：日 / 周 / 月共用的大时间、范围、证据和低噪音筛选。
- `MemoryTimeChapterPresentation`：三档标题和证据的纯展示语义，可独立测试。

早期三栏方案中的独立时间轴和右侧日期珠在手机实装后被取消：它们会重复表达日期与时间、压缩正文宽度。相关能力分别被章节内时刻标签、点击大日期选择、长按时间穿梭和连续跨日阅读承接。

### 16.3 `CalendarRootView` 调整

- `.day` 改为 `DailyReplayView`。
- `.week` 改为 `WeeklyGridView`。
- `.month` 保持现有结构。
- 不新增“网格 / 回放”按钮。
- 周摘要移动到网格上方。
- 月历当天详情增加“回放这一天”。

### 16.4 `CalendarViewModel` 调整

核心目标：用单一 `focusedDate` 统一日期。

建议状态：

```swift
@Published var scale: CalendarScale = .day
@Published var focusedDate: Date = Date()
@Published var moduleFilter: CalendarModule?
```

由 `focusedDate` 派生：

- 日标题与当天事件。
- 周区间与周网格日期。
- 月份 anchor 与月历选中日。

现有 `gridRawEvents + gridLoadedRange` 可以继续作为日/周共享的滑动窗口缓存，但应重命名为不绑定视图形态的 `timelineEvents / loadedRange`。月档可以继续使用月区间结果。

### 16.5 `WeeklyGridView` 调整

- 接收 `weekAnchor/focusedDate`，只渲染所在周七天。
- 三列可视窗口，周内横滑。
- profile 按当前完整周计算，不再按今天固定 ±3 天。
- 日期头点击更新 `focusedDate`。
- 周边界不自动跨周。
- 保留 0–7 折叠、缩放、当前时间线和事件组详情。

### 16.6 `WeeklyListView` 处理

第一阶段从用户路径中移除，但不立即删除：

1. 先确认周摘要、高光、里程碑和事件详情均有新承载位置。
2. 完成真实数据视觉验收。
3. 再删除 `WeeklyListView`、列表累积加载和不再需要的状态。

这避免把视觉改版和能力删除同时发生，便于回滚和对比。

### 16.7 `CalendarObservationSummary`

- `Scope` 新增 `.day`。
- 日档只统计当天。
- `.day` 走独立文案分支（条数 + 模块数 + 时间跨度，见 7.3 文案规则），不复用 `peakDay` / `dominantModule` / “有 N 天留下了记录”等周月叙事句式——这些句式套在单日语义上会产生“这一天有 1 天留下了记录”式破句。
- 周档只统计当前周。
- 月档只统计当前月。
- 过滤和部分失败状态必须同步反映。

### 16.8 后端影响

无后端、Prompt、数据库 schema 或 ECS 部署改动。本次是 iOS 端信息架构、视图和状态管理改造。

## 二十、成功指标与上线观察

### 20.1 核心行为指标

项目当前没有埋点体系（仅 os.log 日志），本版不为此新建埋点，与 15.4 的克制原则一致。以下指标留作未来接入埋点后的观察方向：

- 日/周/月三档使用占比。
- 月历选日后进入日回放的转化率。
- 日回放日期珠切换次数。
- 事件详情打开率。
- 模块筛选使用率。
- 周网格事件组入口打开率。
- 部分失败后的重试成功率。

### 20.2 体验成功信号

- 用户不再寻找“网格/列表/回放”按钮。
- 用户可以从月快速找到日期，再进入日回放。
- 周网格中不再出现小时轴错位、密集事件重叠或日期列漂移。
- 日回放看起来像生活记录，而不是排班表或数据仪表盘。
- 页面美观提升没有以牺牲查找效率为代价。

### 20.3 负向信号

- 用户频繁在日/周间来回切换，只为查找同一条记录。
- 日期珠拖动经常误触页面滚动。
- 周网格三列仍无法读清标题。
- 周列表移除后，用户找不到里程碑或高光。
- 空白时段过长导致用户误以为页面卡住。

出现这些信号时应优先调整交互和信息密度，不重新引入二级视图切换。

## 二十一、风险与产品取舍

### 风险 1：日回放变漂亮，但查找效率下降

应对：保留真实时间、模块筛选、日期珠和事件详情；月档负责远距离定位。叙事卡只增加可读上下文，不隐藏事实字段。

### 风险 2：右侧日期珠仍然占用内容宽度

应对：标准宽度控制在 44–48pt；小屏/超大字体改为顶部日期入口；禁止加入图片缩略图和长文案。

### 风险 3：周网格只有三列，不像“完整一周”

应对：标题明确显示完整周范围，日期头清楚，横向滑动限制在该周；不以七列缩小内容换取形式上的“完整”。

### 风险 4：移除 WeeklyListView 后丢失叙事资产

应对：先迁移周摘要、高光、里程碑入口，再移除列表；分阶段实施，不同时做不可逆删除。

### 风险 5：日期状态重构影响面大

应对：先独立完成 `focusedDate` 状态契约和测试，再换视图，不把状态重构与视觉改版一次性混在同一补丁里。

### 风险 6：数据时刻本身不可靠

应对：明确区分“有时刻”和“仅日期”，不以 UI 位置包装错误精度。

## 二十二、最终拍板项

以下内容视为本方案的固定产品决策：

1. 日档使用单日回放。
2. 周档使用原三日可视时间网格，在当前周内横滑。
3. 月档沿用原热力月历。
4. 删除网格/回放和网格/列表二级切换。
5. 日、周、月共享同一个聚焦日期。
6. 日回放左右辅助导航改为轻量时间脉络和暖白日期珠。
7. 周摘要、高光和里程碑必须在移除列表前找到新承载位置。
8. 不可靠时刻不伪装为 00:00。
9. 本次不改后端、不新增 AI 调用、不扩大健康数据范围。

以上决策共同保证：页面结构更简单，但不是通过删除能力和隐藏边界换来的“简单”。
