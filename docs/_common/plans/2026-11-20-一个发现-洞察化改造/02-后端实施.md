# 02 · 后端实施（HoloBackend）

> 前置：读 `01-方案总纲.md` §2、§5；读 `docs/standards/PROMPT_GUIDELINES.md`。参考实现：`src/discovery/discoveryTopicController.js`（v3）。

## 任务拆分

### B1 · 新 purpose 接入通用 chat 网关

- 走 `/v1/ai/chat/completions`，purpose = `discovery_insight_v2`，**不再新开独立 endpoint**，以便天然获得流式透传、App Attest 鉴权、限流和 `ai_call_logs` 日志。
- `src/config.js` 中新增路由配置：模型与 `portraitSynthesis` 同档，`reasoningEffort: "low"`（不要用 none，none 档会输出坏 JSON）。改配置前后用 `scripts/latency-benchmark.js` 实测一次并记录结果。
- 计入设备配额：每设备每天 ≤ 3 次（每天一条，再加重试余量）。

### B2 · Prompt `discovery_insight_v2`

加入 `src/prompts/defaultPrompts.json`。正文结构：

1. 人格前言：引用 PROMPT_GUIDELINES 中 Persona Preamble 的「陪伴观察者」姿态。
2. 任务：从画像、特征、用户意图中，找出**一条**此刻最值得说的洞察。
3. 洞察及格线：完整粘贴总纲 §2 的必要条件、加分维度、正例和反例。
4. 选题优先级：跨域 > 与 userIntents 呼应 > 新近变化 > 单域长期规律；`recentTopics` 和 `rejectedAngles` 中的角度不得再选。
5. 硬规则：
   - `headline` / `insight` / `prompt` 中不得出现任何数字（阿拉伯数字、中文数字、「两三」这类表达都不行）。
   - 解释性语句必须带推测标记。
   - 不诊断、不给医疗/理财建议、不评判人格；`prompt` 只能是提问或「可以试试」式的可选动作。
   - 称呼「你」，不用感叹号，不说教。
   - 都不达标就返回 `noneReason: "none_worthwhile"`，这是正确结果。
6. 输出 JSON schema（总纲 §5.2），`response_format: json_object`。

### B3 · 质量闸门 `src/discovery/insightGate.js`（新文件，纯函数，便于单测）

依次检查：
1. JSON 解析 + schema 校验（字段、类型、长度：headline ≤18、insight ≤90、evidence 模板 ≤40、prompt ≤30）。
2. 数字检查：headline / insight / prompt 中出现阿拉伯数字或中文数字 → 拒绝。复用 v3 controller L111-139 的检测逻辑，抽成共享函数。
3. 引用检查：`evidence[].refId` 必须存在于输入；`{slot}` 必须属于对应 feature 的 slots。
4. 复述检查：insight 命中「指标 + 涨/跌/增加/减少 + 无因果或对照连接词」这一模式且 `criteria` 少于 2 项 → 拒绝。规则启发式即可，不必做到完美。
5. 角度检查：`angleKey` 在 `recentTopics` 或 `rejectedAngles` 中 → 拒绝。
6. 安全词表：复用记忆系统画像安全闸门在后端的对应词表（若无，则从 `PortraitSafetyGate` 移植一份最小集，**先核实**是否已有）。

失败处理：先做轻量修复（去掉多余字段、截断超长），再带拒绝原因重试 1 次；两次均失败返回 `selected: null, noneReason: "gate_rejected"`，HTTP 200。沿用 v3 不返回 5xx 的做法。

### B4 · 流式下的闸门位置

后端透传流式时无法在中途校验。做法：**后端收齐完整内容后再跑闸门**，对 iOS 的流只输出心跳 / 进度事件，最后输出一个最终 JSON 事件。如果当前 `streamChat` 只支持纯透传，则：
- 方案 A（推荐）：为该 purpose 增加「缓冲后校验」模式，用 SSE 心跳保活连接，防止 NAT 断开；
- 方案 B：iOS 端收齐后自行校验，后端闸门只做日志标记。

实施 agent 先读 `streamChat` 现有实现再选，并在 PR 中说明理由。

### B5 · 开关与日志

- `config.discovery.insightV2Enabled`（环境变量，默认 false），关闭时直接返回 `noneReason: "disabled"`，iOS 回落 v3。
- `ai_call_logs` 额外记录：闸门结果、拒绝原因、`criteria`、是否重试。
- 不在日志中记录 `userIntents` 原文以外的新增敏感字段；`ai_call_logs` 现有的明细策略保持不变。

## 测试（TDD，覆盖率 ≥80%）

- `insightGate` 单测：每一条检查各准备 1 个通过用例和 1 个拒绝用例；中文数字（「三周」「两三次」）必须被拦截。
- controller 集成测试：mock provider 分别返回合规内容、含数字内容（触发重试后成功）、两次失败（返回 `gate_rejected`）、`none_worthwhile`。
- 开关关闭时的路径。
