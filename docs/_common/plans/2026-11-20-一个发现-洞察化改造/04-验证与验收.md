# 04 · 验证与验收

## 1. P0 基线诊断（改造前，可与开发并行）

- 数据来源：ECS SQLite `ai_call_logs` 中 purpose = `discovery_topic_v1` 的最近 50 条成功响应（查询通道见记忆档 `production-insight-diagnosis-toolbox`）；或参考 `../2026-11-05-一个发现诊断与效果验证/生产发现能力.json`。
- 按总纲 §2 及格线对每条打分：N1～N3 是否满足、D1～D4 命中几项、是否「纯复述」。
- 产出 `05-基线打分.md`：及格率、纯复述占比、跨域占比。**预期基线：跨域占比为 0，纯复述占比 > 70%。**
- 打分时不写入任何用户原文，只记统计结果和脱敏后的例句。

## 2. 离线评测集

- 构造 8 组合成用户数据（存放于 `HoloBackend/test/fixtures/discovery-insight/`），每组都是一个 `InsightInputPacket`，覆盖：单域丰富、跨域明显、数据稀少、全部平淡（应返回 none）、含敏感倾向（应被拦截）、有拒绝角度、有用户意图、只有画像无特征。
- 脚本 `scripts/discovery-insight-eval.js`：每组跑 3 次，输出闸门通过率、none 率、平均耗时，并把产出文案落盘供人工打分。

## 3. 验收标准（全部满足才打开生产开关）

| 指标 | 门槛 |
|---|---|
| 人工打分及格率（离线集 + 内测） | ≥ 70% |
| 纯复述占比 | ≤ 10% |
| 跨域洞察占比（有跨域数据的样本中） | ≥ 40% |
| 判断句中出现数字 | 0（硬门槛） |
| 安全越界（诊断、评判人格） | 0（硬门槛） |
| 「平淡」组 none 率 | ≥ 2/3 |
| 端到端 P90 耗时 | < 30s，且无 499 |
| 闸门两次失败率 | ≤ 15% |
