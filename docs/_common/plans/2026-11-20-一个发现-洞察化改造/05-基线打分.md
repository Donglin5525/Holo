# 05 · P0 基线打分（v3 现状）

> 取数时间：2026-11-20 ｜ 数据源：ECS SQLite `discovery_requests`（kind=topic_selection）全量总体 ｜ 打分人：实施 agent

## 一、数据来源说明

- 方案首选 `ai_call_logs`，实际核正：v3 选题是专用端点，**结果真源在 `discovery_requests.result_meta`**（取件即焚语义，行保留）；`ai_call_logs` 正文捕获默认关闭且 v3 端点不经通用网关。
- 查询通道：ssh 免密 → `docker exec holo-backend node` + better-sqlite3 只读（通道见记忆档 `production-insight-diagnosis-toolbox`）。
- **总体只有 2 条**（v3 随 1.1.9 于 11-16 上线，调用极少）：1 条成功选题 + 1 条闸门两次失败降级。样本即全量，无抽样偏差。

## 二、逐条打分（按总纲 §2 及格线）

### 样本 1（成功，2026-11-08 前后首次真实选题）

模板：标题「{label}的购买频率」/ 正文「最近{weeks}周里，你共记录了{recordDays}天关于{label}的情况，发生了{txCount}次。」

| 维度 | 判定 | 依据 |
|---|---|---|
| N1 有证据 | ✅ | 槽位可回填真实数据 |
| N2 不越界 | ✅ | 无诊断/评判/敏感 |
| N3 非复述 | ❌ | 判断句等价于「某类目 = 记了 N 天 M 次」，纯计数复述 |
| D1 对照 | ❌ | 无跨时间/跨域比较 |
| D2 解释 | ❌ | 无因果推测 |
| D3 新意 | ❌ | 财务统计页一眼可见 |
| D4 回应 | ❌ | 与用户想法/目标/习惯初衷无关联 |

**结论：不及格（加分 0 < 2，且违反 N3）——教科书级「数数字」。**

### 样本 2（降级）

`noneReason: insufficient_shape, degraded: true`：模型两次输出被服务端闸门拒绝，客户端走本机规则降级（兜底文案同样是 miner 的 `displayText` 计数句，不及格同上）。

## 三、基线指标 vs 方案预期

| 指标 | 方案预期 | 实测基线 |
|---|---|---|

| 跨域洞察占比 | 0 | **0%** |
| 闸门两次失败率 | （v4 验收 ≤15%） | 50%（1/2 降级，样本过小仅记录） |

## 四、结构性佐证（为什么样本这么少结论仍成立）

及格线 D1～D4 在 v3 架构下**原理上不可达**（总纲 §1 已定谳，此处换打分口径复述）：

1. 模型输入只有「形状」（域/方向/周数/槽位名），无任何语义——模型不可能写出 D4「回应」；
2. 题材枚举只有 4 种（finance-category / lateNight / trend / health-metric），全部单域——D1 跨域不可达；
3. prompt 明令「不外推成人生规律，不给建议」——D2 解释被明文禁止；
4. 唯一生产成功样本的正文就是「记录了 {recordDays} 天…发生了 {txCount} 次」——架构缺陷的直接实证。

另：东林 11-08 质量口径（记忆档 `donglin-discovery-quality-verdict-1108`）已明确「计数式陈述无价值」，与本次打分结论一致。

## 五、结论

**基线确认：v3 全量不及格，纯复述 100%，跨域 0%——达到（差过）方案预期基线，改造必要性与及格线标准成立。v4 验收时以本文件为对照（04 §3 门槛表）。**
