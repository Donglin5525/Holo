# 01 · 方案总纲

## 1. 问题根因（为什么现在是「数数字」）

v3 链路：`DiscoveryMemoryReviewService.scanLocal` → `HoloRecordedPatternMiner`（财务/健康规则统计）→ `DiscoveryTopicService.shape()` 只取「形状」→ 后端 `discovery_topic_v1` 选题 + 写带空位模板 → 端侧 `buildCard` 填数字。

| 根因 | 位置 | 后果 |
|---|---|---|
| 题材只有 4 种：`finance-category` / `finance-lateNight` / `finance-trend` / `health-metric` | `Services/AI/Discovery/DiscoveryTopicService.swift` `shape()` L194-235 | 习惯/想法/任务/目标永远进不来，没有跨域 |
| 模型输入只有统计形状（域/方向/周数/槽位名），无任何语义 | 同上 + `defaultPrompts.json` `discovery_topic_v1` | 模型只能挑题、改措辞 |
| prompt 明令「不外推成人生规律，不给建议」 | `defaultPrompts.json` L70 规则 6 | 天然禁止了洞察 |
| 本地兜底直接用 miner 的 `displayText` | `DiscoveryTopicService.localFallback` L158-179 | 兜底同样是数数字 |

结论：问题在架构，不在措辞。改 prompt 不能解决。

## 2. 洞察及格线（v4 唯一判定标准）

一条发现必须**同时**满足「必要条件」，并命中「加分维度」中**至少两项**。

**必要条件**
- N1 有证据：至少 1 条可追溯到用户真实记录的证据（证据 id 必须来自输入）。
- N2 不越界：不诊断、不评判人格、不涉及安全敏感（复用 `PortraitSafetyGate`）。
- N3 非复述：判断句不能等价于「某指标 = 某值 / 涨了 / 跌了」。

**加分维度**
- D1 对照：跨时间（过去和现在比）或跨域（A 变化时 B 也跟着变）。
- D2 解释：给出可能的「为什么」，并以「可能 / 也许 / 像是」标注为推测。
- D3 新意：不是任一模块页面一眼可见的信息。
- D4 回应：与用户自己写过的想法、目标、习惯初衷相关联。

**反例（写进 prompt）**
- 「最近 4 周你餐饮花得更多了。」→ 纯复述，违反 N3。
- 「你本周步数 8000，继续加油！」→ 复述 + 空泛鼓励。
- 「你可能有焦虑倾向。」→ 诊断，违反 N2。

**正例（写进 prompt）**
- 「你说想早睡的那段时间，深夜下单反而变少了，早睡好像在顺带帮你省钱。」（D1 跨域 + D2 + D4）
- 「断签的几天几乎都是任务逾期最多的日子，掉的可能不是自律，而是精力。」（D1 + D2 + D3）

所有维度都不达标 → 返回 `none`，当天不出卡。

## 4. 隐私决策（已拍板）

- 发给模型的内容与 `portraitSynthesis` 同级：画像条目的 `statement` 和 `evidenceSummary`，加上蒸馏特征包中**已去标识化**的字段。
- **禁止发送**：原始记录正文、精确金额、精确健康数值、人名/地名等识别信息。数值一律以「证据槽位」形式给出：只带槽位名、单位类型和方向，真实值留在端侧。
- 判断句里允许出现相对表达（「更多」「几乎每次」），**不允许出现数字**；数字只出现在证据行里，由端侧填入。
- 实施时必须复用记忆系统现有的去标识化与安全闸门，不另写一套。

## 5. 数据契约（P1 冻结，前后端共同依赖）

### 5.1 请求 `InsightInputPacket`（iOS → 后端，放在 `data` 字段）

```json
{
  "schemaVersion": 1,
  "kind": "insightInput",
  "requestId": "uuid",
  "window": { "days": 28 },
  "portrait": [
    { "id": "p_xxx", "dimension": "crossDomainInsight|recentState|longTermPattern|preference|identity",
      "confidence": "confirmed|inferred", "statement": "…", "evidenceSummary": "…", "sourceDomains": ["habit","task"] }
  ],
  "features": [
    { "id": "f_xxx", "domain": "finance|health|habit|thought|task|goal|profile",
      "description": "去标识化的特征描述，不含数字", "direction": "up|down|stable|divergent",
      "slots": [ { "name": "lateNightWeeks", "unit": "weeks" } ] }
  ],
  "userIntents": [ { "id": "u_xxx", "source": "goal|habit|thought", "text": "去标识化后的意图短句" } ],
  "recentTopics": [ "angleKey…" ],
  "rejectedAngles": [ "angleKey…" ]
}
```

数量上限：portrait ≤ 12，features ≤ 30，userIntents ≤ 10。超过时由端侧按「新近 + 置信度」截断。

### 5.2 响应 `InsightDraft`（后端 → iOS）

```json
{
  "schemaVersion": 1,
  "kind": "insightDraft",
  "selected": {
    "angleKey": "habit-break×task-overdue",
    "headline": "≤18 字，无数字",
    "insight": "≤90 字，判断 + 推测性解释，无数字",
    "evidence": [ { "refId": "f_xxx", "template": "≤40 字，可含 {slot}" } ],
    "prompt": "≤30 字的一个提问或可选小动作，可为空",
    "criteria": ["D1","D2"],
    "sourceDomains": ["habit","task"]
  },
  "noneReason": null
}
```

- `evidence` 1～3 条，`refId` 必须是输入中存在的 id，`{slot}` 必须是该 feature 的 `slots` 中已有的名字。
- `selected` 与 `noneReason` 二者必有其一。`noneReason` 取值：`none_worthwhile` / `insufficient_data`。

### 5.3 端侧卡片 `DiscoveryInsightCard`（存储）

在 `DiscoveryTopicStore` 现有卡片结构上**新增**字段：`version: 4`、`insight`、`evidenceLines[]`（已填好数字）、`prompt`、`portraitRefs[]`、`angleKey`。旧 v3 卡片照常读取（UserDefaults 编码新增可选字段即可，不需要迁移）。
