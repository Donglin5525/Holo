# Holo Agent 全方位体检与高可用改造

> 日期：2026-08-20  
> 状态：本地修复完成，待生产部署与真实链路验收  
> 范围：Agent 能力、工具、数据、证据、执行恢复、主动能力、界面交互与生产后端

## 一、目标与验收口径

Agent 的目标不是“能调用大模型”，而是稳定完成以下闭环：

1. 理解用户当前目标，并识别这是不是对上一份结果的追问；
2. 读取足够、最新且有授权的数据；
3. 选择正确工具，控制轮次、成本和超时；
4. 只交付有证据支撑的结论，并清楚披露范围与限制；
5. 中断、锁屏、弱网和冷启动后状态仍然一致；
6. 用户可以看懂进度、停止任务、继续追问，并确认任何有副作用的行动；
7. 行动完成后只在确有实现时进入效果回看，不能展示空按钮或伪闭环。

本轮验收以“用户连续完成一次分析、一次追问、一次行动确认，期间任意失败都能得到可理解结果”为主路径。

## 二、当前事实结论

- 已有 16 个生产工具，覆盖财务、健康、习惯、任务、目标、想法、记忆、档案、对话元数据、纪念日、项目、反馈与跨域查询。
- 已有 Tool → Evidence → Verifier → Renderer 的证据链，分析结果可以披露数据范围和限制。
- Agent Job、Checkpoint、Result、Evidence 已持久化；用户停止、网络等待、锁屏恢复和冷启动回填已有统一状态机。
- 后端 step 幂等、坏 JSON 恢复信封、配额和输出审核已有自动化覆盖。
- 2026-08-20 本地后端基线为 235/235 测试通过。

### 生产事实

- 生产 release commit 为 `fde90642396ed3a40298f15e38f912550c636ecc`。
- 最近 7 天 Agent Loop：24 次调用，22 次成功、2 次中止，成功请求 P50 约 16.5 秒、P90 约 30.2 秒。

## 三、问题分级

### P0：直接破坏主路径

1. **连续追问没有进入当前主线。** 历史分支虽然做过界面和 lineage，但没有把父 Result 的已验证结论与 Evidence 真正注入 child Job；即使直接合并，也只能“看起来在追问”，不能保证语义承接。
2. **领域记忆萃取仍走上游非流式请求。** 生产错误耗时集中在约 30.7 秒，和 ECS 到模型服务的空闲连接墙一致；后端只对 Agent/Insight 使用内部流式拉取，记忆萃取未复用这条可靠链。
3. **洞察卡存在可见但无执行实现的行动。** “设置消费提醒”会弹确认，但确认后没有任何动作；反思类行动刚跳到聊天就被记录为“已执行”，语义不真实。
4. **生产工具覆盖契约不完整且测试已漂移。** `cross_domain`、`discover`、`project`、`feedback`、`thought_reference` 未进入必备清单；现有测试期望值甚至漏掉已在清单中的 anniversary。

### P1：降低可信度或长期可用度

1. Observer 主动评分把 `userAuthorized` 硬编码为 true，授权语义不真实。
2. Outcome Review 目前只有待回看记录，没有基线冻结、调度、重读数据和用户可见回看；属于未闭环能力。
3. Prompt Builder 每轮重复附加同一条用户问题，增加输入体积和延迟。
4. v21 Prompt 已上线但没有真实调用样本，不能把“部署成功”当成“质量已验”。

### P2：后续演进

1. 任务、目标、想法的动态字段仍偏浅，长尾问题会更多依赖固定查询和模型规划。
2. Agent 结果缺少统一的行动回执和效果回看入口。
3. 生产只有调用级日志，没有完整的用户匿名任务成功、追问成功和答案有效性漏斗。

## 四、本轮产品与架构决策

### ADR-1：追问以 canonical Result 为锚点

- 每份新 Agent Result 回填 `jobID/resultID`；旧结果没有身份时不显示追问入口。
- child Job 只接受本地 Result Store 中能匹配的父结果，不能信任界面传来的摘要。
- explain/drillDown 可复用仍有效的父 Evidence；correct/changeScope/crossDomain 必须重查新口径，旧数值只能作为历史上下文。
- 父上下文随初始 Checkpoint 持久化，恢复后语义不丢失；lineage 纳入输入快照，防止恢复到错误父结果。
- 隐式追问只在同一会话、最近四小时、且命中确定性承接词时启用；不确定时按新问题处理。

### ADR-2：长结构化任务统一复用内部流式上游链

- 客户端仍收到普通 JSON，接口契约不变。
- 后端到模型服务改用 `completeViaStream` 持续收包，规避约 30 秒无首字节的空闲连接墙。
- 首批覆盖 Agent、Insight、领域记忆、跨域记忆与旧 Observer；provider 不支持时自动回退原 complete。

### ADR-3：只展示可真正执行的行动

- 暂无消费提醒实体和调度器，因此不再生成“设置消费提醒”按钮；改为进入 HoloAI 继续分析消费偏离。
- 反思跳转只算“开始讨论”，不记录为行动已执行。
- 用户从分析结果要求“执行第 N 条”时，只生成待办确认草案；多条但未指定序号时先澄清，确认前不写数据。
- Outcome Review 在基线、调度和回看 UI 完成前不对用户宣称闭环。

### ADR-4：工具覆盖是发布契约

- 16 个生产注册工具全部进入覆盖清单；动态数据集继续单独校验。
- 自动化测试以清单为唯一事实源；Release 不依赖会被优化掉的 `assert` 来保证能力完整。

## 五、验证矩阵

1. 纯逻辑：追问关系、lineage、防环、父上下文复用规则、输入快照、工具覆盖。
2. iOS：显式追问、自然相邻追问、改时间范围、跨域补查、旧结果不可追问、停止与恢复。
3. 后端：内部流式选择、SSE 完整性、memory purpose 契约、全量 Node 测试。
4. 构建：Debug Simulator build；XCTest target 有真实执行数量才算测试通过。
5. 生产：部署需单独确认；部署后再核对 release commit、Prompt v21 真实样本、记忆萃取错误率和 P50/P90。

## 六、明确边界

- 本轮不会直接部署生产后端；本地修复与生产生效必须分开验收。
- App Attest 全量强制、完整 Outcome Review 和更深的数据目录扩充不与本轮 P0 混做；它们保留在后续风险清单中。
- 不触碰当前工作区中日历、每日回放和记忆画廊重构的未提交改动。

## 七、本地验收结果

- HoloBackend 全量测试：236/236 通过。
- iOS Debug Simulator：完整 App 构建通过。
