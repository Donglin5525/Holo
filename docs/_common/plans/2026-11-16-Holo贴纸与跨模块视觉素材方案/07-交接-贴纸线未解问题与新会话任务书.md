## 未解问题排查起点（按嫌疑排序，未验证——先拿证据再动手）

### 嫌疑 A（高）：model.commit() 失败/卡死是静默的
`StickerMakerView.primaryAction` 的 editing 分支：
```swift
if let assetID = await model.commit() { onPick...; dismiss() }
// nil 时什么都不发生——没有错误提示！
```
若 commit 抛错（返回 nil）或 **continuation 永不 resume**（卡死），用户感知就是「点了没反应/贴纸没创建」。排查：
- 真机复现时看是否卡在「正在保存…」还是静默回到原样
- `VisualCommitCoordinator.commit` 的结构：`withCheckedThrowingContinuation` + `performCommitLocked { context.performAndWait { ... } }`——**串行 DispatchQueue.sync 内嵌 background context 的 performAndWait**，检查是否有线程/队列死锁（尤其 SwiftUI 主线程同时持有 viewContext 的情况）
- 建议先给 nil 分支加可见错误反馈，让失败不再静默（同时是用户体验正确性）

### 嫌疑 B（高）：照片模式不进「我的贴纸」是设计行为，可能被误判为「没创建」
`StickerMakerModel.fill`：`libraryVisibility = kind == .sticker ? "visible" : "recordOnly"`——**普通照片不入复用列表**（方案 01 §3.1 原文）。若东林用照片模式做的固定支出外观，素材库里没有属正常。确认他操作时用的是贴纸还是照片模式；若体验上易混淆，考虑在确认页明示「照片不进素材库」。

### 嫌疑 C（中）：fill() 的 guard 早退产出残缺素材
`StickerMakerModel.fill` 开头 `guard let sourcePNG = encodePNG(...) else { return }`——若 encodePNG 失败，asset 已 insert 但无像素字段即 save（残缺行入库）。「我的贴纸」查询 visible 过滤能看到空行。排查 DB 里是否有 kind/像素字段为空的 VisualAsset 行。

### 嫌疑 D（中）：编辑表单立即生效链路的 background context 写入后 viewContext 读不到
测试容器上端到端绿（testCreateAssetAndApplyEndToEndResolvesReady），但真机库（CloudKit 同步栈）行为可能不同：`automaticallyMergesChangesFromParent` 已配（CoreDataStack.swift:133）。用真机复现后直接查库：

Mac 侧同步库只读通道见记忆档 memory-rework-v33（开发库查询）。

### 嫌疑 E（低）：列表 IconSlot 刷新
列表页已挂 `.onReceive(.visualAssetsDidChange) { refresh() }`；通知只从 commit 路径发。若 A 成立（commit 没跑完）通知根本没发——修 A 大概率顺带修好「最外层看不到」。
