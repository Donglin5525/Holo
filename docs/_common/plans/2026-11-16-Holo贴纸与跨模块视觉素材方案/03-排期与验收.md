# Holo 贴纸：分期、验证与上线条件

> R2 · 2026-11-17。本文所有产品测试均为待执行计划，没有已通过的原生性能/设备结论。交接与门禁以00为入口；对抗发现见05。

## 1. 按可交付结果拆分

| 阶段 | 交付结果 | 初步工作量 | 下一步条件 |
|---|---|---|---|
| A：图像与外观验证 | 静态照片→主体→纸边；难例、深浅背景和真实机型 | 3–4人日 | 确认质量/设备范围，不把API可调用当效果通过 |
| B：共用基础 | 三实体、墓碑、幂等事务、修边/草稿、素材库、渲染、scope、素材包 | 7–10人日 | 失败重试/删除/unknown负载与恢复验证通过 |
| C：固定支出 | 列表图标、详情主视觉、编辑入口 | 2–3人日 | 财务逻辑和流水数量不变 |
| D：想法 | 头图、正文保存、附件去重、纸张、分享、纯图兼容门禁 | 5–7人日 | 不丢正文/草稿，不触发多余AI |
| E：记忆长廊 | 时间线投影、图片月历、日代表选择、漫步、视觉刷新 | 4–6人日 | 日期/计数/部分失败/返回锚点通过 |
| F：完整回归 | 迁移、外置素材恢复、两设备、旧端边界、资源、深色、无障碍 | 5–8人日 | P0无遗留，验收台账真实完整 |

首版含长廊与R2补齐的可靠性要求，估算 **26–38人日，约一位熟悉项目的开发者5–8个工作周**，不含审核等待。替代R1的17–25人日估计。A阶段后按实测重估，允许工作包内部复用，不用压缩数据门禁“追上原工期”。

第二批约8–12人日初估：习惯、目标、任务、少量图表；不再重复建设独立想法月历。第二批开工前重新核对各模块并行改造后的入口。

## 2. 第一版必须包含与可以后放的内容

| 必须包含 | 可以后放 |
|---|---|
| 统一入口、相册/拍照、透明 PNG 导入 | 自定义实时抠图相机 |
| 主体选择、基础擦除/恢复、白边 | 虚线、闪光、动态贴纸、复杂阴影编辑 |
| 我的贴纸、复用、导出 PNG | 商店、社区、AI 生图和识物搜索 |
| 固定支出、想法、长廊完整链路 | 所有业务模块同一天上线 |
| 工作图/遮罩/主体分离、透明缩略图、主题渲染 | 多层拼贴、无限画布 |
| 墓碑、幂等提交、iCloud真机、scope、旧库验证 | 自动远端垃圾回收、合并相似素材 |
| 素材包导入导出，准确说明范围 | 全 Holo 数据备份系统重构 |
| 列表性能和无素材空态 | 全新瀑布流或重做想法导航 |

如果时间必须压缩，先减少第二批模块和边缘风格，不压缩透明格式、删除隔离、同步与想法保存链路。

## 3. 第一阶段的图片评测集

使用获授权的原始照片建立至少 60 张样本，不使用用户参考截图作为唯一测试材料；每类记录能否选到目标、边缘是否可接受、是否需要修边、耗时、峰值内存。

| 类别 | 最少数量 | 重点 |
|---|---:|---|
| 单一清晰物体：耳机、书、水杯、鞋、汽车 | 20 | 主体完整、边缘干净 |
| 多物体/复杂背景 | 10 | 能否正确选择实例，不误把背景或人物带入 |
| 手持物体、相互遮挡 | 10 | 杯子与手、肉串与人，是否必须修边；不可恢复被遮挡部分 |
| 细线、孔洞、毛发、枝叶 | 8 | 白边能否保留形状，不能靠过度平滑掩盖问题 |
| 透明/反光/低对比/弱光 | 8 | 显示边界并提供照片出口，不宣传完美抠图 |
| 特殊输入：透明 PNG、HEIC 方向、超大图、损坏文件 | 4 | 透明、朝向、资源限制和错误恢复 |

初始门槛：清晰单物体样本中，不修边即可接受的比例目标 ≥90%；其余分组按真实结果报告，不给总体平均分掩盖困难类别。该门槛是产品质量目标，当前未验证。手持和复杂背景质量若不够，第一版必须保留修边和普通照片路径。

设备至少覆盖：一台最低支持系统的可用真机、一台主流机型、一台当前主力机型；Mac 覆盖实际支持的一台。记录系统版本、机型、原图来源、冷启动/热运行。模拟器只验证业务交互，不能替代端侧分割效果与性能。

### H. 对抗场景与数据完整性

| ID | 操作 | 预期 |
|---|---|---|
| R01 | 永久删除后，离线设备旧asset/位置晚到 | 墓碑优先，UI立即不可用，Binary清理重试，不复活 |
| R02 | 本机0引用、离线设备仍引用 | 不自动硬删；明确永久删时说明所有使用受影响 |
| R03 | 同设备两个提交同时开始 | 仓库串行分配clock，后操作更高；fixture稳定收敛 |
| R04 | save成功到UI回执之间杀进程再恢复 | 同operation返回已有结果，不重复建素材/父想法 |
| R05 | 墙上时钟相差一年、同clock多writer | changedAt不影响胜出，稳定tie-break一致 |
| R06 | 更高clock的未知payload版本、非法枚举 | 不退回旧选择；unsupported只读，坏数据corrupt |
| R07 | 素材/位置/父想法提交任一步注入失败 | 整个本次事务不提交，草稿保留，不出现半成功 |
| R08 | 重复应用同operationID；同ID不同hash | 前者幂等，后者完整性错误，不能按顺序任取 |
| R09 | 另一模块有未保存改动时本次保存失败 | 不rollback共享viewContext，不丢另一模块编辑 |
| R10 | 只有prepared头图/processing/空选择器分别关闭 | prepared按兼容策略保存或保留草稿，processing不能冒充已存，空选择不建记录 |
| R11 | 草稿写磁盘失败、manifest失败、回执后崩溃 | 错误可见，未成功持久化不宣称可恢复；回执对账，不提前清文件 |
| R12 | 导出到另一设备，解析owner | 业务UUID可解析，包内不出现NSManagedObjectID URI/绝对路径 |
| R13 | 素材包含已有墓碑ID | 跳过并报告，不自动改ID绕过删除 |
| R14 | 包内clock极大、恢复覆盖已有位置、重复批次导入 | 默认不恢复；确认后用本地新clock/operation；批次重试不重复 |
| R15 | 制作/保存/读取中切账号或store | 旧scope结果全部失效，不在新账号显示/落库/恢复草稿 |
| R16 | 已升级本地库用旧模型打开 | 门禁拒绝且保留原库；功能回滚用兼容新schema构建 |
| R17 | 含外置source/mask/content的库备份并隔离恢复 | 业务记录与Binary逐项hash一致；不足则阻止真实升级 |
| R18 | 反复超时、取消、快速换大图 | 实际重任务最多1个；迟到结果不更新、不无限排队耗内存 |
| R19 | 相同slot包络不完整、operation物理副本冲突 | pending/corrupt只读，不把旧版当确定结果开放编辑 |
| R20 | 隐藏/软删/永久删之后列表、日历、分享、导入、缓存分别读取 | 各读口径一致，分享不泄漏墓碑素材，不将占位导成成功成品 |

## 5. 性能与体验门槛

以下为建议起点，阶段 A/B 测量后校准，不能在尚未实测时对外承诺「秒出」。

| 项目 | 初始目标与测量方式 |
|---|---|
| 点击后的反馈 | 100ms 内出现取图/处理状态或结果，前台不假死 |
| 主流真机处理 | 已在本地的 2048px 工作图，冷/热分别统计；热运行端到端 P95 目标 ≤3 秒 |
| 超时 | 约 10 秒恢复可操作状态；取消立即响应，丢弃迟到结果 |
| 内存 | 单任务新增峰值初值控制在约 120MB 内，真实机型测量；不能以文件体积代替解码内存 |
| 列表滚动 | 200 个带头图条目的测试集合，比较同机改动前后的卡顿与长帧；主线程无图片 IO/分割 |
| 低内存 | 清理派生缓存后仍能显示与重建，不丢原始素材 |
| 素材库 | 500 张素材时按可见项加载；滚动不同时解码所有原图 |
| 分享 | 等待所需素材就绪再输出，不把占位图保存成最终分享卡 |
| 可访问性 | 大字号、深色、减少动态效果、VoiceOver、44pt 热区逐项走查 |

用户可感知的质量优先：若白边把耳机细杆吞掉、贴纸缩小后认不出物品、金额被挤走，即使编译与自动测试通过也不合格。

## 6. 测试执行与上线顺序

1. 先跑纯算法测试：alpha 保真、边界留白、朝向与命中坐标、位置版本选择、删除标记、附件去重。
2. 再跑数据集成测试：真实历史模型夹具、草稿事务、父对象处理中被删、导出导入、回收站联动。
3. 构建/测试一律通过 `BuildScripts/holo_build.py`，测试文件按当前工程注册；不沿用过时的“所有测试都无 target”假设。pbxproj 调整走专用脚本。
4. 模拟器按项目规则后台操作，集中验证关键入口和编辑手势；不把模拟器分割结果当真机性能证明。
5. 真机验证相机、系统分割、照片权限、iCloud 两设备、长期离线与旧版行为。
6. 模型增量变更先在隔离环境完成验证，真实 Development 数据不清空、不重置。进入实际设备升级前按项目要求完成备份告知和可恢复性验证。
7. 若需要将新增 CloudKit Schema 推到生产，另按生产变更权限执行；这不等于部署 HoloBackend。
8. 首版以客户端功能开关小范围开启；关闭入口后仍能读取既有素材，不删除用户已创建的内容。
9. 归档前按 `BuildScripts/archive_smoke_list.py` 输出页面清单，重跑受影响页面冒烟。此方案阶段不发包、不安装、不部署。

## 7. 产品验证指标

| 指标 | 定义 | 能回答的问题 |
|---|---|---|
| 制作完成率 | 点开始制作后得到可用预览的会话占比，分离主动取消与错误 | 制作是否可靠 |
| 首次应用率 | 成功制作后真正保存到一个业务位置的占比 | 结果是否有用，流程是否太长 |
| 七日复用率 | 首次使用后七天内再次使用同一素材的用户占比 | 素材库是否有价值 |
| 跨模块复用率 | 同一素材被应用于至少两个模块的用户占比 | 共用能力是否成立 |
| 想法回看变化 | 使用前后/实验分组的主动打开记录、编辑和分享行为 | 是否增加回看意愿；仅观察相关性不宣称因果 |
| 普通照片回退率 | 无主体或质量不满意后切到照片的比例 | 抠图边界是否影响体验 |
| 反向指标 | 页面卡顿、保存失败、同步失败、移除头图、取消制作率 | 个性化是否损害效率 |

沿用现有产品埋点通道，仅记录事件、模块、耗时、错误分类与尺寸等级；不上传照片、用户命名、识别内容、私人记录 ID 或跨设备可追踪素材哈希。第一阶段可先用本地诊断和访谈，不为指标另建后端服务。
