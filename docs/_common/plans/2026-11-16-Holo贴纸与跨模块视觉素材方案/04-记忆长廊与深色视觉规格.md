# 记忆长廊与贴纸深色呈现规格

> R2 · 2026-11-17。此文件是长廊、日代表图、月历和深色外观的唯一详细规格。

## 1. 长廊要补的价值

用户现在有记录入口，也有按日期回看的长廊；缺少的是看到一双跑鞋、一杯奶茶或一件纪念物，就能想起某一天的视觉线索。

此次增加三个相互配合的场景：**时间线里的生活主视觉、图片月历里的日期线索、随机漫步里的完整记录画面**。不把长廊变成另一个贴纸库。贴纸库回答“我有哪些素材”，长廊回答“这天我留下了什么”。

### 1.1 当前真正运行的入口

代码根：`Holo/Holo APP/Holo/Holo/`。

| 当前事实 | 实施落点 |
|---|---|
| `MemoryGalleryView` 顶栏已有「找日期」和随机漫步直达；旧洞察可通过兼容深链进入 | 保留现有入口和兼容路径，不增加第三个并列主 Tab |
| `CalendarRootView` 默认使用 `MemoryGalleryTimelineView` | 在当前时间线增加头图投影，不改成一进来就满屏月历 |
| `MemoryGalleryFindDateModel.swift` 同文件含 `MemoryGalleryFindDateSheet` | 图片月历主要改此处，旧 `MonthlyCalendarView`/`MonthCell` 不能代替真实入口接线 |
| `MemoryGalleryDayPreview.split` 已选每天主预览 | 改为共用日代表记录策略，月历与时间线使用同一选择 |
| `CalendarEventProvider` 提供财务/习惯/已完成任务/想法事件 | 复用来源、半开日期区间、去重与可见性，不复制生活数据 |
| `CalendarEvent` 现在带附件缩略图 Data，判等只看 id | 新视觉摘要不得只靠旧 `==` 刷新，详见 02 的 revision 合并 |
| `MemoryWalkThoughtReader` 在长廊内读全文，显式按钮才打开想法模块 | 增加头图后继续保留原月、选中日、展开日和漫步轮次 |

当前入口以代码为准。11 月 8 日旧“生活回顾”提案和 11 月 13 日减法设计不作为重新恢复周回顾/看板的授权；本次只扩展现有回看路径。

## 2. 时间线：每天一个主角，但不丢其他记录

推荐呈现：

```text
记忆长廊                       随机漫步  找日期

十一月
16 日 ──  [一张耳机贴纸或照片]
          今天终于换了耳机
          想法 · 原记录时间 / 标签
          当天 4 条记录  ›

15 日 ──  跑步完成 5 公里
          习惯 · 19:30
```

- 记录有头图：优先用其显式头图；贴纸完整显示，照片使用来源记录的取景意图。
- 旧想法只有附件：继续使用旧照片，第一张有效附件可作日代表图，不强制用户补头图。
- 无图片：保持文字、金额或次数的原有排版，不加空白图片区。
- 有多条记录：沿用“当天 N 条记录”展开；N 是去重后的原记录总数，包含主预览。不是贴纸数量，也不是聚合后可见行数。
- 习惯同日多次的聚合行仍按现有规则显示；记录数按原始有效事件，不因为合并行而减少。
- 头图在详情/时间线/日历只是呈现投影，不新增发生时间、不创建记忆、不计入统计。

### 2.1 日代表记录的确定性规则

所有候选先经过来源存在性、删除、归档、可见性和当天区间过滤；身份键使用 `(module, sourceRecordUUID)`。

按以下顺序选择：

1. 用户为这天明确指定的有效代表想法。
2. 有显式头图且未明确失效的想法；仅图片尚未下载仍保留候选身份。
3. 有有效旧附件的想法。
4. 有可读原文的想法。
5. 其他有可靠时刻的真实事件。
6. 仍无可靠时刻时，按稳定事件键选一条。

同级按业务发生时间倒序，再按事件键升序。不使用素材创建时间、上次编辑时间、AI 评分或“图片大小”排序。自动候选的头图已明确失效时，先按该记录有效附件、正文重新分级；不再享有头图优先级。首版自动图片候选只来自想法；财务项目封面、目标封面、习惯默认图标不能被当作当天拍摄的生活照片。

“手选日代表”可选当天带头图或旧附件的想法；存 sourceRecordUUID，不存一份脱离原记录的图片副本。从该记录的菜单选择“作为这天的封面”；日期菜单提供“恢复自动选择”。同一选择同时作用于图片月历和时间线，不在随机漫步中改变记录抽样权重。

### 2.2 缺图、失效和用户选择

| 情况 | 行为 |
|---|---|
| 手选记录元数据已到，图片仍在同步 | 保持手选身份，显示占位，不能静默换成另一张图 |
| 手选记录所属模块加载失败，无法确认是否存在 | 显示“部分记录尚未载入”，保留手选，不写 clear |
| 手选记录确认已删/已归档/不再属于当天 | 当前展示回退到自动规则，保留手选版本；以后恢复且重新满足条件时恢复手选 |
| 头图素材彻底删除，但原记录仍在 | 该记录先尝试自己的有效附件；无图则允许文字主预览，提供重新选择，不从别的记录偷换图 |
| 原记录更换头图 | 同一记录在长廊更新主视觉；明确长廊反映记录当前状态，不承诺历史不可变快照 |
| 素材仅从库里隐藏 | 继续显示所有已存在引用 |
| 当天无有效记录 | 显示空日；不能任意贴一张素材而制造生活事件 |

返回自动只写该日选择的 clear 版本，不改来源记录。修改来源图片通过“在想法中编辑头图”进入原记录；长廊首版不另开一个可以写业务正文的编辑器。

## 3. 图片月历放在「找日期」里

原入口不改名，面板提供「图片 / 日期」两种查看方式，默认图片，选择记在本机偏好；不增加独立“想法月历”页面。

```text
找日期                                 关闭
                  图片 | 日期
             < 2026 年 11 月 >
一    二    三    四    五    六    日
…
16    17    18    19    20    21    22
[耳机] [杯子]  ·    [书]   ·     ·     ·
4 条   2 条   1 条   3 条

11 月 16 日 · 4 条记录
[耳机] 今天终于换了耳机       想法
       另外 3 条记录
                 [在长廊看这天]
回到最近                         随机漫步
```

### 3.1 两种模式的交互

- **图片模式**：点日期选中，下方显示主预览及总条数，不立即关闭。点主预览在面板内部打开原记录阅读；“在长廊看这天”关闭面板并定位时间线。未来日期不可回看。
- **日期模式**：保留原先点日期即关闭并跳到当天的快速操作。两种模式共享月份、选中日和取数状态。
- 翻月不跳走底层时间线；关闭面板回到进入前锚点。使用跳转按钮才更新底层锚点。
- 打开面板跟随当前阅读月份；再次打开本会话保留上次模式。跨会话清理月份时沿用当前阅读位置规则。
- 在图片模式翻月，选择该月最近的有效日；未加载完成前不自动选择一个“无记录”日。若月内无记录则仅选今天（本月）或不选日，显示该月空态。
- 月份标题支持既有快速年月选择；远历史月份不得依赖从今天逐月遍历取数。
- 保留随机漫步直达与面板入口；模式切换不重置漫步已看集合。

### 3.2 网格尺寸与小屏

网格七列，日期行、缩略图、数量各有独立区域。图片模式每格建议高 68–80pt，缩略图 28–36pt，点击区域至少 44pt；320pt 宽时左右边距缩为 6–8pt、列间距 0–1pt，以完整七列为先，不能扩大重叠热区。

六行月＋标题＋预览超过当前固定 620pt 面板高度，因此图片模式默认 `.large` 并允许内部纵向滚动；日期模式保留现有紧凑档。不要沿用 620pt 硬高再裁掉月份标题或底部按钮。iPad/Mac 使用适合列宽的弹窗/分栏，不让图片被横向拉伸。

日期、今天标记、选中框始终在图片外。数量统一写“ N 条”；无图有记录显示小点和数量，不能伪装成没记录。图片模式不再叠加热力填色/模块彩条，以免抢画面；日期模式沿用既有标记。

### 3.3 加载与日期契约

日状态必须区分 `loading / loadedEmpty / loaded / partial / failed`。现有 `recordCount: (Date) -> Int?` 不能表达这些区别，应改为轻量 `GalleryDayVisualSummary`。某模块失败时写“已载入 N 条”，不写完整总数。

日期来源：财务业务日期；习惯原发生日；任务完成日期；想法原 `createdAt`，与当前 Provider 一致。仅更换头图不迁移日期。日期区间统一 `[start, end)`，跨日/DST 用宿主 Calendar 运算，不加固定 86400 秒。

日选择键按宿主日历的 `identifier + era + year + month + isLeapMonth + day + timeZone.identifier` 规范编码。不同日历/时区下重算分组与缓存；原时区的手选仅在对应键下生效，不自动移动到另一天或误覆盖另一时区选择。界面说明“按当前设备时区回看”；重新进入原时区可恢复原选择。首版不擅自改变全 App 日期政策。

只拉当前显示月的42格覆盖区间，允许预取紧邻月份的元数据；图片只取可见缩略图。纯图功能加入后不能让翻月把四个月的原图一起加载进来。

## 4. 随机漫步和日内阅读

- 抽到带头图的想法时，`MemoryWalkThoughtReader` 使用 `ThoughtHeroPresentation`，与想法详情一致。
- 随机漫步继续按现有日期/记录抽样规则；不给有贴纸的日子额外权重，避免只有精修过的日子总被选中。
- 同一贴纸出现在多篇想法里时，它们仍是不同真实记录；同一原记录的头图和附件不拆成两个回忆。
- 阅读关闭后回到原月/原日/原展开状态；漫步里“在长廊看这天”才切到时间线。
- 周回顾、每周报告不因本需求重新移入长廊首页；若以后分享回顾需要图片，单独以已有记录引用方式接入。

## 5. 深色模式：分清素材内容与 Holo 生成的纸边

### 5.1 三种输入，不用一个规则硬套

| 输入 | 深色模式处理 |
|---|---|
| Holo 制作的透明主体＋独立纸边 | 仅纸边、外轮廓和阴影适配；物体颜色保持不变 |
| 用户导入的透明 PNG，白边已烘焙进像素 | 默认原样显示，默认不再加第二层纸边；想换风格需显式重新制作，不按“接近白色”删像素 |
| 普通照片/带白色矩形背景的图片 | 作为照片完整显示，外部使用深色托底与轻边框；不自动抠背景，不将白纸/白衣/反光误删 |

默认不降低整张图片透明度、不反色、不把白色物体涂成灰色。真正需要压暗白底照片时，由用户打开本位置的“夜间柔光”，只影响深色预览，不改源文件。

Apple 建议支持动态深色颜色，同时保留用户明确选择的内容颜色；以下纸边方案属于 Holo 的设计选择，并非系统自动替我们完成。[Apple：Supporting Dark Mode](https://developer.apple.com/documentation/uikit/supporting-dark-mode-in-your-interface)

### 5.2 控件和默认值

- 纸边风格：`自适应纸边`（默认）/ `纯白纸边` / `无纸边`。
- 厚度：`细` / `标准`（默认）；无边时隐藏厚度。
- 从外部透明 PNG 导入：默认无新增纸边，可主动开启。
- “夜间柔光”：仅照片位置显示，默认关闭；打开时在 dark preview 对 RGB 乘 0.92、alpha 不变，配明确预览。全屏原图查看提供原色，导出时忽略此参数。
- 这些是当前位置的意图，不能修改共享素材的像素。系统切换主题只重新渲染，不写库、不新增位置版本、不触发同步或 AI。

### 5.3 明确 token 和渲染参数

以下为首版实现值，统一注册 colorset/DesignSystem，不能在组件散写 hex。长廊背景继续使用现有 `galleryPaper/gallerySurface/galleryInk`，不替换为另一套全局色板。

| Token / 参数 | Light | Dark |
|---|---|---|
| `visualStickerPaper` | `#FAF8F2` | `#D6D1C9` |
| `visualStickerPaperExplicitWhite` | `#FFFFFF` | `#FFFFFF` |
| `visualStickerEdge` | `#D8D3CB` | `#85817B` |
| `visualPhotoMat` | 现有浅色 surface | 现有深色 surface |
| 标准纸边 | 按角色取下表 | 同宽，不改物体占比 |
| 投影 | 黑色 alpha 0.10，y=2pt，blur=4pt | 默认关闭，不用黑色重阴影制造脏边 |
| 外纸边细线 | 0.5pt，仅包纸边外轮廓 | 0.5pt；增强对比设置时为1pt |

role 参数：icon 44pt→细0.75/标准1.25pt；calendar 32pt→细0.5/标准0.75pt；list 160pt→细1.5/标准2.5pt；hero 280pt→细2.5/标准4pt。其他尺寸按角色参考边长等比缩放并限在该角色的0.75–1.5倍；有无透明 padding 不应改变计算出的纸边厚度。日历禁旋转与投影，图标禁旋转；大头图旋转范围 −6°…6°。

外细线描的是纸边轮廓，不是图片矩形。无纸边时不偷偷加纸边；深色黑物体可由用户开启自适应边，编辑预览提供深浅背景切换帮助判断。额外托底只用于照片容器，不能把透明贴纸放进突兀的白色方块。

所有 token 和参数都要在白耳机、黑车、透明杯、细线、深色照片、白底扫描图上验证；颜色值确定的是初始实现，不代表已经完成视觉验收。

### 5.4 导出与跨设备一致性

- App 预览：跟随各设备本地外观，相同位置在白天/夜间可以有不同纸边色，这是呈现差异。
- 默认导出透明 PNG：使用固定浅色纸边的导出配置；若用户显式选纯白/无边则遵从，预览后导出。不可因导出时手机是深色而默默生成灰边文件。
- 分享整张想法：继续固定浅色纸面，使用同一个浅色导出配置；导出前与预览一致。
- 源 `contentHash` 不含系统主题；派生缓存 key 必须包含 theme、contrast、role、displayScale、pixelSize、参数和 rendererVersion。
- 主题切换使可见项重渲染，不能命中旧 light PNG 缓存。日历/列表之外的隐藏页只标脏，重新可见时按需更新。

## 6. 组件接口与接线责任

| 新/改组件 | 必须传入/返回 |
|---|---|
| `GalleryVisualProjection` | 时间范围、有效原事件、来源加载状态、视觉版本；返回无大图的日摘要 |
| `GalleryDayVisualSummary` | dayKey、loadState、totalLoadedCount、isComplete、featuredEventKey、visualDescriptor、selectionState、revision |
| `GalleryFeaturedRecordPolicy` | 同一套纯函数返回主预览，供时间线/月历调用；不访问网络、不运行 AI |
| `GalleryDayCoverSelection` | 作为 `VisualPlacementRevision` 的 `galleryDay/featuredRecord` 类型负载存原记录引用；不新增一张图片表 |
| `MemoryGalleryFindDateSheet` | 当前月、模式、selectedDay、日摘要、取数回调、明确的跳转/阅读回调；禁止默认空跳转 |
| `VisualAssetView` | descriptor、role、appearance、contrast、targetPixelSize；渲染层不查业务模块 |
| `MemoryWalkThoughtReader` / 时间线卡片 | 同一 `ThoughtHeroPresentation` 与附件去重结果 |

新 API 用值快照传递；来源记录的 NSManagedObjectID 只供本机 resolver，持久化/同步/导出只能使用业务 UUID 与模块名。
