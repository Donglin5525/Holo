# P0 基线与冻结契约

日期：2026-10-20。状态：**P0 完成，作为 P1/P2a 实施的冻结依据**。源码核对基于当前工作区（分支 1.1.3）。

## 1. 报告源清单与数据流

两类试点报告，五条产生/落库轨道，全部归一到统一报告适配层：

| 报告类型 | 轨道 | 落库点 | 完成事件 | 结构化程度 |
|---|---|---|---|---|
| 周期回放 | 本地生成 | MemoryInsightRepository.saveReady（MemoryInsight 实体） | memoryInsightDidGenerate 通知（含 payload+cards） | cards 含 memoryCandidate/evidence；usedMemoryIDs 已过滤 |
| 周期回放 | 云端异步 | persistCloudInsight → saveGenerating+saveReady | 同上通知（无 cards 键，payload 在） | 同本地轨道（同一解析器） |
| 周期回放 | 云端降级 | snapshotHash 缺失 → 只落卡不落档案 | **无通知** | 不进理解链路（P0 决策：来源可用率统计口径的一部分） |
| 深度分析 | 本地 Agent | ChatMessageRepository.finalizeAgentMessage（agentResultJSON） | 落库即完成（无通知） | HoloRenderedAgentResult（sections+evidenceReferences） |
| 深度分析 | 云端异步 | 同上（HoloCloudAnalysisService.finalizeCloudResult） | 同上 | CloudResult.claims（含 metricAssertions/evidenceIDs/type/confidence）+ evidence 池 + reportStructure（claimID 引用）+ snapshotCoverage |

**冷启动重扫来源**：周期回放=MemoryInsight 实体（ready 状态）；深度分析=ChatMessage 的 agentResultJSON（ReportArchiveDTO 同源查询，不使用报告 Tab 分页列表作学习源）。

**已核实的既有基础**（P0 探索结论）：

- 统一仓库 upsert 已具备：稳定 ID 身份（HoloMemoryIdentity）、按 lineageKey 合并证据（同证据不双计）、observationKey 幂等（hasSuccessfulObservation → duplicateObservation）、墓碑拦截（精确 ID + 语义匹配 HoloSemanticTombstoneMatcher）、用户裁决保护（无新证据不得覆盖）、敏感存储分流。**新链路产出规范记录即自动获得这些保障，不重复建设。**
- 聊天/Agent 消费已走 HoloMemoryQueryService（active 过滤+相关性排序+8 条/2000 token 预算+AnsweringAllowed 门控）→ 新链路写入的 active 记录天然可被聊天消费。
- 旧回放候选观察器（HoloLongTermMemoryCandidateObserver）挂在 memoryInsightDidGenerate + longTermMemoryWriteEnabled 开关，写旧 HoloLongTermMemoryStore；云端回放通知无 cards 键故实际不进旧观察器。
- 云端深度分析 claims 的 metricAssertions 已与工具 Ledger 对账（后端 v26 起），可作为数字真相直接核验。

## 2. 冻结契约（字段命名定稿）

### 2.1 HoloReportDescriptor（iOS 侧 `HoloReportUnderstandingContract.swift`）

| 字段 | 类型 | 说明 |
|---|---|---|
| canonicalReportID | String | `replay-{insightID}` / `analysis-{messageID}`；消息卡与洞察档案共用（R01） |
| sourceKind | enum periodReplay / deepAnalysis | |
| sourceRecordID | String | insight UUID 或 ChatMessage UUID |
| reportRevisionDigest | String | 内容摘要（标题/格式改动不产生新 revision，R03） |
| parentReportID / rootReportID | String? | 追问血统（continuationMetadata/lineage） |
| sourceSnapshotHash | String? | 回放快照哈希；深度分析为 nil |
| generatedAt / periodStart / periodEnd | Date? | 生成时间与分析窗分开 |
| domains | [HoloMemoryDomain] | 覆盖域 |
| truncated / coverageNote | Bool / String? | S03 截断如实标注（R14） |
| usedMemoryIDs | [String] | 防循环依赖（R06） |
| status | ready | 失败/流式/降级不登记 |

### 2.2 HoloReportFinding → HoloMemoryRecord 映射

- claimKey 身份 = 复用 HoloMemoryIdentity（scope+domains+claimKind+anchors）；**不另立报告专用身份规则**（§6.6）。
- claimKind 映射：云端 type observation→observedFact、change→phaseShift、pattern→recurringPattern、correlation→association（V1.1 才晋升可用）、suggestion→**不进 V1 事实库**（记 receipt 备查，R13）。
- 证据：evidenceIDs → CloudEvidence/metric → HoloMemoryEvidenceRef（kind=aggregateSnapshot/entityRef，lineageKey=`cloudAnalysis:{claimID}:{metricKey|dataset}`；回放卡 evidence → lineageKey=`insight:{insightID}:{cardID}:{index}`）。**lineageKey 指向报告证据本身而非底层业务事件**——底层事件不可回查时独立性=unknown（R04/R05 保守）。
- metricAssertions 数字核验：值/单位/方向三对程序核验，失败整条拒绝并记原因（R09/R10）。
- prohibitedInferences：correlation→禁因果表述；suggestion 类不进 V1。

### 2.3 处理台账（本地 JSON，不进 CloudKit）

`Application Support/Holo/ReportUnderstanding/ledger.json`：处理键 `canonicalReportID|reportRevisionDigest|extractorVersion|policyVersion`；状态 pending/running/succeeded/deferred/rejected/failed；记录 attemptCount/lastError/updatedAt。设备本地即可（多设备靠仓库幂等键保证语义单写，重复成本靠观测）。

### 2.4 消费契约（PersonalSituationBrief，与财务 S2 T03 共用）

`HoloPersonalSituationBrief`：≤8 条事实型条目（memoryID/versionID、displayText、conditions、timeWindow、allowedUse、caveat）；空背景=正常分析。挂 HoloCloudAnalysisSnapshotBuilder.Snapshot 新可选字段 `personalSituationBrief`（旧后端忽略），本地轨道经 HoloUnderstandingContextBuilder 同源注入。

### 2.5 开关（HoloAIFeatureFlags，默认全关）

`reportUnderstandingExtractionEnabled`（UserDefaults `holo_reportUnderstandingExtractionEnabled`，默认 false；且受 longTermMemoryWriteEnabled 总闸）、`reportUnderstandingAnsweringEnabled`（同键规则；受 memorySummaryInjectionEnabled 总闸）、`reportUnderstandingHistoryBackfillEnabled`（P3 前不实现）。

## 3. 后端预算端到端修复规格（本次实现代码+测试，不部署）

| 改动点 | 文件 | 内容 |
|---|---|---|
| 直调轨道 | backgroundCostGuard.js BACKGROUND_PURPOSES | 增 `replayDigest`（真实直调 purpose）；入口守卫已支持 chat/completions+purpose 判定，无需改 app.js 入口 |
| 云端轨道 | cloudAnalysisExecutor.js | replay_digest worker 的 callProvider 前，从任务归属（task.device_id）恢复预算主体并 run() 包裹每次真实上游尝试；不得复用已结束 HTTP 上下文 |

| 版本闸门 | backgroundCostGuard.js checkIngress | replayDigest 进后台集合后，旧客户端 UA 需被 426 拦截——核对 minVersion 表确保现网客户端版本号 ≥ 门槛，否则门槛低于现网版本 |
| 用途映射 | 不把 agent_loop 列入后台集合 | 云端摘要调用以任务类型建立主体，不改 provider purpose（B05 保护主动分析） |

## 4. 增量对照口径（§6.6 五分类）

报告候选进入仓库时按 upsert 结果+既有记录比对分类：①纯重复（updated 且无新 lineageKey、无条件/时间增量）；②同命题新增独立证据（新 lineageKey）；③新增条件/反证/时间窗变化；④首次可用（既有为 candidate/失效，本次补足核验变 active）；⑤新命题（inserted）。影子期（P1）只记诊断不写库；P2a 实写后按此口径出报表。

## 6. P0 结论

- 两类报告的稳定身份可建：回放=洞察档案 UUID；深度分析=消息 UUID+agentResultJSON 回读。云端回放降级分支（无档案）不入链，计入来源可用率。
- 回源能力：深度分析 claims→evidence 池映射完整；回放卡 evidence 携带 sourceID 摘录。历史回放（2026-10 前旧格式无 memoryCandidate）只产历史查阅级候选，不晋升事实。
- 阻塞问题：无。预算修复、S2 共享接口、去重口径均有明确归属（本文档）。
