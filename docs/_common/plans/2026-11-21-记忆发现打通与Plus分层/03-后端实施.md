## B1 · 撞墙与送达时回传额度信息（`quota` 字段）

### 目标

`discovery_insight_v2` 的响应信封新增可选字段 `quota`：

```json
{
  "schemaVersion": 1,
  "kind": "insightDraft",
  "selected": null,
  "noneReason": "quota_exhausted",
  "quota": { "used": 1, "limit": 1, "tier": "free", "resetAt": 1764224000000 }
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| used | int | 7 天滚动窗口内已送达件数（送达后的值，含本次） |
| limit | int | 本设备当前等级的每周上限；0 表示不限 |
| tier | "free" \| "plus" | 后端判定的等级 |
| resetAt | int(ms) \| null | 下一个名额释放的时刻；未达上限或不限时为 null |

**什么时候带 quota**：①撞墙（quota_exhausted）；②成功送达（selected 非空）。其他（disabled / none_worthwhile / gate_rejected）不带。

### 步骤

**1. `src/discovery/insightDeliveryStore.js`** —— 新增 `nextReleaseAt`：

在 `cleanupBefore` 之后加一条预编译语句：

```js
  const listSince = db.prepare(
    "SELECT delivered_at FROM insight_deliveries WHERE device_id = ? AND delivered_at > ? ORDER BY delivered_at ASC"
  );
```

在返回对象里 `record` 之后加：

```js
    /**
     * 已达上限时，下一个名额释放的时刻（ms）；未达上限或 limit<=0 返回 null。
     * 7 天滚动：窗口内共 n 条、上限 limit，第 (n-limit) 条（升序，0 起）滑出窗口时恢复一个名额。
     */
    nextReleaseAt(deviceId, limit, now = nowMs()) {
      if (!(limit > 0)) return null;
      const rows = listSince.all(deviceId, now - WEEK_MS);
      if (rows.length < limit) return null;
      return rows[rows.length - limit].delivered_at + WEEK_MS;
    },
```

**2. `src/discovery/insightGate.js`** —— `buildDraftEnvelope` 支持可选 quota：

```js
export function buildDraftEnvelope({ selected, noneReason, quota }) {
  const envelope = {
    schemaVersion: 1,
    kind: "insightDraft",
    selected: selected ? { /* 原有字段保持不变 */ } : null,
    noneReason: selected ? null : noneReason,
  };
  // 额度信息（2026-11-21 Plus 分层）：只在撞墙与送达时附带；iOS 用于显示恢复时刻与已看件数。
  if (quota) envelope.quota = quota;
  return JSON.stringify(envelope);
}
```

注意：`selected` 内部的字段映射原样保留，只是把对象先赋给 `envelope` 再 stringify。不带 quota 时输出与改前**逐字相同**（既有测试靠这个）。

**3. `src/app.js` · `handleInsightV2Completion`**

3a. 在 `const usedCount = insightDeliveryStore.countLastWeek(deviceId);` 下一行加：

```js
  const tier = plusActive ? "plus" : "free";
  const quotaInfo = (used) => ({
    used,
    limit: weeklyLimit,
    tier,
    resetAt: insightDeliveryStore.nextReleaseAt(deviceId, weeklyLimit),
  });
```

3b. 撞墙分支：`buildDraftEnvelope({ selected: null, noneReason: "quota_exhausted" })` 改为
`buildDraftEnvelope({ selected: null, noneReason: "quota_exhausted", quota: quotaInfo(usedCount) })`。
`finishLog` 里的 `gate.quota` 保持原样。

3c. `generate()` 里成功送达：在 `insightDeliveryStore.record(deviceId);` 之后**不要**立即算 quota（循环里）。在循环结束后、组装 `draftJSON` 的地方改为：

```js
    const draftJSON = accepted?.selected
      ? buildDraftEnvelope({ selected: accepted.selected, quota: quotaInfo(usedCount + 1) })
      : buildDraftEnvelope({ selected: null, noneReason: accepted?.noneReason ?? "gate_rejected" });
```

`quotaInfo(usedCount + 1)` 调用时 record 已写入，所以 `nextReleaseAt` 能看到本次这条。

## B2 · Plus 点名看（`focusFeatureIds`）

### 目标

请求包 `InsightInputPacket` 新增可选字段 `focusFeatureIds: string[]`（1~2 个，必须是本包 features 里存在的 id）。
- 后端：校验 → 非 Plus 丢弃 → 有值时闸门要求 evidence 至少一条引用其中之一。
- Prompt：告诉模型用户点名了哪几项。

### 步骤

**1. `src/discovery/insightGate.js` · `validateInsightPacket`**

1a. 解构里加 `focusFeatureIds`：

1b. 在 `normalizedIntents` 之后、`return` 之前加：

```js
  // Plus 点名看（2026-11-21）：可选，1~2 个且必须是本包已有 feature id；非法即 400（边界快速失败）。
  let normalizedFocus;
  if (focusFeatureIds !== undefined && focusFeatureIds !== null) {
    const featureIds = new Set(normalizedFeatures.map((f) => f.id));
    if (!Array.isArray(focusFeatureIds) || focusFeatureIds.length < 1 || focusFeatureIds.length > 2
        || focusFeatureIds.some((id) => typeof id !== "string" || !featureIds.has(id))) {
      throw new GatewayError("INVALID_REQUEST", "insight packet focusFeatureIds invalid", 400);
    }
    normalizedFocus = [...new Set(focusFeatureIds)];
  }
```
