# 02 · 对抗审查记录

## 一、动线审查（v1 原型 → v2 原型，东林亲测反馈「摸不着头脑、不知道该不该付费」）

根因：**用户付费前既不知道发现是什么，也看不到多付的钱换来什么。**

| # | 问题 | 用户视角的后果 | 改法（已落到 01 文案表） |
|---|---|---|---|
| U1 | 满屏术语：线索、认识、水位、证据门槛、解读、宁缺毋滥 | 看不懂 | 术语对照表 §3，界面禁用左列词 |
| U2 | 没讲「发现」是什么、和「记忆」什么关系 | 不知道这是干嘛的 | C01 顶部说明 |
| U3 | 撞墙卡只给「3 条线索 · 睡眠/消费」 | 没法判断值不值 | 本机拼具体问题（§5） |
| U4 | 付费页只写「每周 5 条」 | 没概念 | C62~C65：先回顾这周得到了什么，再两栏对比 |
| U5 | 「没有值得说的就不说」→ 付费后某周可能只有 2 件 | 事后觉得被骗 | C67 事先讲清 |
| U6 | v1 把「接着聊」「往期存档」锁进 Plus | 聊天本来免费，看过的东西被收回，困惑+反感 | 往期免费；接着聊延后（README 范围外） |
| U7 | 「下周一恢复」与后端 7 天滚动不符 | 周一来了还是看不到，信任崩 | 显示具体恢复时刻（{resetText}） |
| U8 | 开通后没有立刻的回报 | 付了钱还要等 | 开通后清除撞墙标记、立刻自动生成一件 |

## 二、工程审查（读代码后发现的坑，均已写进施工图）

| # | 坑 | 证据 | 不处理的后果 | 处理 |
|---|---|---|---|---|
| E1 | 撞墙标记按「自然日」，但恢复时刻是「滚动 7 天的某个钟点」 | `DiscoveryTopicStore.markInsightQuotaWalled` 写的是 dayStamp；后端 `countLastWeek` 用 `now - 7天` | 恢复日当天早上打开 → 仍撞墙 → 标记锁死一整天 → 恢复日当天一件也看不到 | I4：撞墙标记改为「截止到恢复时刻」 |
| E2 | 撞墙分支也调了 `markInsightV2Attempted` | `DiscoveryInsightService.applyDraft` 在 switch 之前统一调用 | 开通 Plus 后当天无法重新请求 | I5：quota 分支不写尝试标记；I4 提供 `clearInsightQuotaWall()` 同时清两个标记 |
| E3 | 后端撞墙响应没有恢复时刻 | `buildDraftEnvelope` 只有 selected/noneReason | iOS 无法显示 {resetText} | B1：响应加 `quota` 字段 |
| E4 | 今天的卡被消费后 `todayCard()` 恒返回 nil | `todayCard` 首行 `if consumedToday { return nil }` | Plus 点名看出来的卡永远显示不出来 | I4：`QueuedCard.isFocusedPick == true` 的卡不受当日消费限制 |
| E5 | 特征 id 是按下标生成的（`f_anomaly_0`） | `DiscoveryInsightCandidateBuilder` | 点名时重新组包，id 可能已变 | I5：用「短句文本」反查当前 id，对不上就回执 C45 |
| E6 | 开通后本机是 Plus，但后端会员判定可能有延迟 | 后端 `entitlement.isPlusActive` 与本机 `HoloEntitlementState` 两个来源 | 刚付钱就被告知「这周看完了」 | I5：后端回 `tier=free` 而本机是 Plus → 只墙 10 分钟 + 状态 D 文案 C50 |
| E7 | 付费说明页是弹层里的弹层，再从根部弹付费墙可能叠不上 | 付费墙由 `HoloApp` 根部 `fullScreenCover` 呈现 | 点了开通没反应 | I7：先关说明页，在说明页 `onDismiss` 里再调 `requirePlus`；I8 验收必须实点确认付费墙弹出 |
| E8 | 后端 `discovery_insight_v2` 每设备每天限 3 次请求 | `config.js` perDay=3 | Plus 点名太多会被限流 | 点名每天最多 2 次（自动 1 + 点名 2 = 3）；限流回执 C46 |
| E9 | 免费用户可能伪造 `focusFeatureIds` | 输入来自客户端 | 不构成越权（额度仍由服务端算），但不应生效 | B2：非 Plus 请求直接丢弃该字段 |
| E10 | 目标文件被其他会话改着未提交 | `git status` 显示 TopicStore / InsightService / ReviewSheet / 测试文件均为 M | 提交时把别人的半成品一起带走 | B0/I0 开工检查：有未提交改动就停，交回东林 |

## 三、刻意不做的防御

- 不为「旧版本 iOS 收到新 quota 字段」写兼容：iOS 解码 `InsightDraft` 用 CodingKeys 白名单，未知字段天然忽略。
- 不为旧的按日撞墙标记写迁移：旧 key 直接弃用，最坏情况是升级当天多请求一次，后端照样返回撞墙（零成本）。
