# 02 · AI 引擎与数据契约

本文件是 AI 实现的核心。两次模型调用各有独立职责，结果都视为待验证数据。V1 不要求新增多 Agent、自主无限工具循环、远端向量库或用户画像服务。

## 1. 组件及职责

建议新增 `Services/AI/Discovery/`，名字可调整，职责不可省略：

| 组件 | 输入／输出 | 负责什么 |
|---|---|---|
| `DiscoveryAccessPolicy` | 设置、授权、登录、范围、能力 → 访问决定 | 所有取数、网络、展示、续聊的统一门控 |
| `DiscoverySourceAdapter` | 变更 ID、窗口 → 来源快照 | 想法／任务／习惯的只读适配，真实版本与时间 |
| `DiscoveryEvidenceBuilder` | 快照 → FactAtom | 原文切片、事件归并、确定性事实与覆盖率 |
| `DiscoveryRetriever` | 变化主题／候选检索规格 → 材料包 | 初次召回与候选后反例召回，记录截断与限制 |
| `DiscoveryCandidateClient` | 初始材料包 → 0～3 候选 | 专用生成接口，无全局 UserContext 注入 |
| `DiscoveryStructuralValidator` | 候选＋材料 → 合格候选 | schema、引用、来源、独立性、数字、敏感边界 |
| `DiscoveryVerificationClient` | 冻结候选＋完整支持＋反例 → verdict | 一次独立批量核验，不做文案润色 |
| `DiscoveryPublicationPolicy` | 合格候选＋核验＋本地历史 → 一条或空 | 所有硬门槛、重复／否定抑制与排序 |
| `DiscoveryCoordinator` | 生命周期／数据事件 | 串联状态、预算、控制代数、提交前复核 |
| `DiscoveryStore` | 状态、来源索引、候选、反馈 | 新本机 store、原子提交、失效依赖索引 |
| `DiscoveryContinuationBuilder` | 发现＋草稿 → 最小对话上下文 | 来源重核、边界、用户最新表达优先 |

既有 `HoloMemoryObserverService`／`HoloContext*` 能力可复用算法或纯工具；禁止调用它们的顶层“自动形成记忆／个人规划”流程以间接绕开本功能开关，或把它们全部产物塞进模型。

## 2. 来源与 FactAtom：先决定能知道什么

### 2.1 首发来源字段白名单

| 来源 | 可以读 | 缺失或禁止推导的内容 |
|---|---|---|
| 想法 | 正文、真实记录时间、显式主题／标签关联、AI 可见性、原记录定位 | 原文中“我猜朋友认为……”不是朋友的真实态度；引用他人不当本人偏好 |
| 任务 | 标题、描述、创建时间、当前状态、已有完成时间、当前截止、已有显式子任务／目标关联 | 没有版本历史不推断延期次数；当前优先级不代表历史；未完成不等于拖延 |
| 习惯 | 已记录事件、数值、单位、真实记录日期、已有习惯标识 | 缺打卡不等于没有做；没有历史目标版本不推断当时是否达标；坏习惯缺记录不等于控制成功 |

GLM 在 G0 为每个字段填现有 DTO／Repository 的真实来源。没有字段就填写缺失，不可新增假历史补齐。首发不为发现修改任务、习惯或想法的业务模型。

想法仍使用全局 `ThoughtAIAudience` 口径，并检查软删除、归档等既有 AI 读取语义。任务／习惯历史是否可用按原读取政策；不能把当前已归档自动解释为过去没有发生。是否纳入归档材料须在适配器显式决定并测试，V1 默认不读取已归档正文。

### 2.2 FactAtom 本地模型

| 字段 | 要求 |
|---|---|
| `localSourceRef` | 类型＋本地 ID；不出日志或成本库 |
| `sourceRevision` | 原文与参与判断字段的稳定摘要；无版本号时由受控字段计算 |
| `evidenceID` | 批次内匿名短 ID，如 E01；服务器与模型不需要永久业务 UUID |
| `sourceKind` | thought／task／habitEvent／computedFact |
| `occurredRange` | 事件发生时间或 null，带精度；只知道月份不能伪造具体日 |
| `recordedAt` | 实际保存时间，与发生时间分开 |
| `sourceBlock` | 原文语义段，保留否定、条件、转折和附近上下文 |
| `quoteLocator` | 本地原文位置，模型无需生成字符偏移 |
| `lineageGroup` | 确认属于同一底层事件的组；不确定时标 ambiguous |
| `entityRefs` | 显式实体关联／本地主题，不让同名自动成为同一实体 |
| `coverage` | 查询范围、取到数量、是否截断、未知分母等 |
| `accessRevision` | 全局排除及发现范围的版本 |
| `computedFacts` | 指标 ID、公式版本、分子／分母、单位、窗口与值 |

原文和状态是证据；模型摘要、发现正文、旧报告、模型自述不是独立证据。V1 完全不取长期记忆和全量聊天历史。

### 2.3 引用对齐

模型只选择 evidenceID 与短原文 quote，不产生“第几个字符”的定位。客户端从不可变 sourceBlock 对齐到原文。

- 必须最终落到原文精确子串；如复用 `quoteAlignment.js`，只接受排版差异修正，保留精确原文作为展示引用。
- 同一段出现相同 quote 多次时，使用完整 sourceBlock 范围进一步定位；无法区分则拒绝，不能随意取第一个。
- 不允许模糊相似度把不同含义的句子对齐成证据，尤其否定词、人称、数值与时间。
- “原文存在”只是结构校验。核验模型必须看到整段上下文，避免截走“但后来没有继续”。
- Unicode／emoji／繁简文本必须有往返测试；Swift String 索引不能直接当 JavaScript UTF-16 索引使用。推荐本地保存段标识及精确 quote，不跨语言交换未定义的字符索引。

### 2.4 独立事件计数

同一任务完成被想法提到、又被摘要复述，不是三次独立经历。

- 有同一显式事件／实体关联：归为同一 lineage。
- 无显式关联但原文高度相似、时间重合且可能是复述：标 ambiguous，不能用它增加重复次数。
- 同一习惯不同日期的真实打卡可为不同事件，但“形成规律”还需覆盖不同情境／时段，不能把连续同步的副本当多天。
- 不把“不同来源 ID”或“不同数据域”自动当成独立性证明。
- 证明不足时可输出单次事实，但单次事实不满足本功能首发发现门槛，所以最终通常不展示。

## 3. 触发材料与初次召回

### 3.1 不把规则筛选伪装成 AI 理解

程序只确定许可、变化、主题召回与成本边界。观察内容由 AI 在材料中提出。不能使用「逾期 3 天 → 你在拖延」这样的规则替代理解。

首次开启是受限历史准备，之后按有实质变化的源更新。仅改样式、同步重复通知、查看记录、修改本功能展示状态不算新材料。

### 3.2 召回顺序与范围初值

1. 变化对象及明确关联记录。
2. 近 30 个本地自然日内的同主题片段，保存本次时区与确切区间 `[start,end)`。
3. 需要比较或理解反复经历时，定向召回近 90 天同对象／同主题的历史原文。
4. 预留反例预算，不把全部材料额度耗在生成阶段。

候选材料最多 24 个原文块；生成阶段建议最多 12 个，余量留历史与反例。每块建议不超过约 400 汉字，超长段落按语义切分，否定与转折不能丢；切断造成含义不完整则不用该块。

召回必须带 `coverage`：实际搜索的域／窗口、符合条件的块数、采用数、截断数、索引版本。未读历史不等于“从未发生”；补记不等于当天发生。

V1 使用本地显式关系、主题、全文索引与限定时间扫描。不新增外部 embedding 调用，以保持两次 LLM 的预算边界。如复用已有索引，只用已授权且当前可回源的数据；索引结果全部回到原记录核权和核版本，不能凭旧向量摘要直接入包。没有索引时可做有数量／时间上限的本地读取，不回退到联网全文 embedding。

大库读取分批，按修改游标增量；索引补建可中断。不能每次前台激活扫描所有历史正文。G0 根据现有存储索引确定批次大小，G6 用大样本测量主线程影响。

## 4. 候选生成：调用一

专用 purpose：`discovery_candidate_v1`。端点与权限见 03。系统 Prompt 在后端；客户端 user 消息只含结构化数据。禁用工具调用与动作执行，不允许模型自己读取未授权域。

输入包括：协议版本、runID、固定时间与时区、允许来源、匿名 evidence 块、覆盖元数据、可用确定性指标、允许发现类型、少量已展示主题的非敏感指纹／本地转成的抽象主题约束。不要发送完整历史发现正文或反馈内容。

输出符合 `ai-output.schema.json` 的 candidate 分支。每条候选：

- 有独立 candidateID、type、subjectKey、确定的 scopeKind、适用区间。变化类还必须给出 comparisonPeriods 两个明确区间；其他类型此数组为空。
- 标题也是一个需核验的 claim；正文由 claimID 序列组装。没有游离在核验之外的标题、开头语和结尾建议。
- 每个 claim 指向原文引用，区分直接事实与有限观察；任何解释都不能冒充事实。
- 可列出 `counterSearch`，仅为受限本地检索规格，模型不能指定文件路径、URL 或工具代码。
- 敏感分类不明确即按 uncertain，首发拒绝发布；不能默认 non_sensitive。
- 返回 0～3 条，不要求凑数量。空结果要有枚举原因，不额外写鸡汤。

V1 不输出多种修订稿，不允许验证阶段改写。理由：如果核验后又润色，润色后的新命题没有被验证；第三次模型调用还会增加成本与新的幻觉入口。候选不合格则拒绝，等待新材料，不当场无限重写。

## 5. 本地结构门禁

按顺序执行，失败记录类型，不把原文写日志：

1. 严格 JSON、版本、字段白名单、长度、数量与 ID 唯一性；拒绝未知字段和多重 JSON 文档。
2. runID 与服务端响应归属正确；candidateID、claimID 局部唯一，引用不得指向另一个候选的未声明内容。
3. evidenceID 真实且本批可用，quote 可回原文，标题／正文所有 claim 全覆盖。
4. type 与 scopeKind 匹配；两次联系需两个独立事件，有限重复需至少 3 个事件且覆盖至少两个时间段；时段变化需两段可比材料，每段至少 2 个独立事件为首发初值。comparisonPeriods 必须各有明确起止、按时间排序、互不重叠且在总范围内；材料分配以真实发生时间为准。有限重复的三个事件首发要求跨度至少 7 天，未达到时不能以 bounded_pattern 发布。
5. 区间不能超取数范围；缺发生时间的材料不能支持精确先后、时长或趋势。
6. 定量结论只能引用 computedFact／确定计数，不能由模型自由计算。正文数量须可由引用集复算，中文数词也检查；不能可靠核对的定量句直接拒绝。第一版不允许百分比／相关系数类句子，避免口径与小样本问题。
7. 无人格定论、诊断、因果断言、命令或越界敏感主题。字符串名单只作底线，语义核验仍必需。
8. 否定记录、过期、来源变更、用户屏蔽与权限再次检查。

不要以「有引用 ID」替代以上内容，也不要把任意 schema 失败静默吞成“无发现”；对用户可安静，对内部可诊断。

## 6. 反例检索：不再调用一次生成模型

结构合格后，对候选的主题／对象做第二次本地检索：

- 明确指向同对象但结果不同的记录。
- 同类行为在其他时间未出现、失败或有不同解释的直接表达；不通过“没记录”构造失败。
- 原文附近的转折、条件、取消、自我纠正。
- 本机用户对这一主题的明确否定／不适用控制。反馈不是新的事实证据，但可以阻止展示。

每候选最多三条受限查询，支持的筛选操作仅 domain／anchor／timeRange／keyword；所有查询由本地 builder 与权限相交。模型提议 health／finance、越界时间或任意文件路径，直接拒绝该查询并标检索不完整，不执行。

不能只按模型建议检索：程序还要执行同对象／同主题的中性回看，以免“证实自己”的 query 漏掉不相似的反例。生成时的支持块和相反块均保留全文上下文。

每候选最多 6 个反例／补充块，三候选合并去重后仍受总包预算限制。优先保留会推翻核心解释的块；资源不足标 `coverageIncomplete`。覆盖不完整时，repeat／change 类默认不发布；two_episodes 类可以只表达已核对的两次联系，但必须明确范围，不扩展成频率或有效性。

没有命中不等于找不到反例：区分「搜索完成且无命中」「没有可用索引／历史不足」「预算截断」。前者仍只说当前记录范围，后两者不能发布广泛模式。

## 7. 独立核验：调用二

专用 purpose：`discovery_verify_v1`。一次批量核验所有结构合格候选。与生成使用独立请求，没有生成阶段的思考、置信评分或肯定性理由。

输入：冻结候选、完整支持块、反例与相邻上下文、实际覆盖、程序核出的计数与来源限制。生成／核验的 runID、candidate 摘要与材料 revision 必须一致。

核验逐句输出：

- supported：这句话在给定边界内成立。
- contradicted：材料与核心表述冲突。
- unsupported：没有足够支持，或引用不相关。
- insufficient：覆盖、时间、独立性等信息不足以判断。

candidate verdict 只允许 accept／reject。所有要展示的 claim 都 supported 才能 accept；缺任何 claim 的核验结果均拒绝。核验不输出可展示新文案，不允许“帮它改得更温柔就通过”。

核验必须检查主语、否定、条件、时间、语气强度、数量、事件独立性、相关与因果、覆盖和敏感主题。支持 quote 必须与推断有语义关系，能解释为什么，而非只包含相同关键词。

同一个基础模型不同请求可以作为首发基线，但不独立于模型的系统性偏差。G4 必须单独评估「生成错且核验也放行」的误接受；必要时更换核验路由，仍由后端配置，不开放用户选模型。

## 8. 本地发布：不加第三轮润色

再次检查控制与数据版本后，用已核验的标题／正文 claim 原样组装，附程序生成的覆盖／范围说明。不能裁掉“不”“还不能”“这两次”等限定；为缩短字数删限定语属于改变结论，必须拒绝或重新生成。

硬门槛：双端结构合格、所有显示句被支持、独立计数合格、反例不冲突、敏感合格、来源仍有效、用户未否定、预算与版本归属正确。任何一项 false 均不发布。

硬门槛后排序：实际覆盖可靠性 → 个人相关性 → 与既有发现的新增信息 → 时效 → 明确反馈偏好；可用确定性优先级，不需要人为包装成“理解分 92”。点击倾向不参与证据评分。

输出最多一条。保留同批其他合格候选也必须有过期与源版本约束，不在用户否定后立刻自动顶上另一条，避免连续侵入。首发建议只持久化最终一条，其他在本批结束时清理。

## 9. 状态、依赖与存储

### 9.1 状态机

运行：disabled → waitingForMaterial → scheduled → preparing → ready／noFinding／backoff。cancelled 单独记终态，不能写成模型失败。

内容：candidate → verified → published → viewed；published／viewed 可转 rejected／invalidated／expired。已失效不可直接恢复，必须新批次核验。

### 9.2 一次运行必须冻结

`runID、accountSubject、deviceID、localGrantEpoch、serverControlRevision、scopeRevision、sourceManifestDigest、candidatePromptVersion、verifyPromptVersion、modelRouteVersion、policyVersion、anchorNow、timezone`。

数据更新不能复用原 runID 改 request body。来源重新核验、接收核验结果、提交、展示和续聊前均检查。关闭后重新开启是新 localGrantEpoch，旧结果即使已返回也不可复活。

### 9.3 本机独立 store

推荐新 `NSPersistentContainer` 或项目已有等价本机数据库，单独模型与目录 `Application Support/Holo/Discovery/`，不设置 CloudKit 选项，不改业务 store。

内容：ControlSnapshot、RunState、SourceManifest、SourceDependencyIndex、PublishedFinding、FeedbackTombstone、BoundedRetrievalIndex。正文缓存设置 iOS 文件保护，排除普通备份中的临时派生包；按系统与项目现状选可用保护级别并验证锁屏行为。

依赖索引不仅存支持来源，也存参与解释的反例、统计基线和版本。排除／删除触发以依赖集失效；无法保证精确范围时，保守撤销全部当前发现并清理旧材料，不能让缓存成为隐私旁路。

有效期初值 14 天，自事件时间范围与源生命周期可缩短。过期检查每次展示执行。关闭、注销、切账号、撤总授权时，清掉当前账号的候选、原文摘录、索引与在途数据；保留无原文 HMAC 否定指纹需按账号隔离，密钥在本机 Keychain 管理，禁止上传可逆主题文本或使用无盐短语 hash 作为隐私保护。显式重置本功能清理指纹；卸载不承诺仍记得否定。

服务器仅存控制、租约、日预算、幂等、阶段 hash 与成本元数据；不持久化记录原文或发现正文。第三方处理与临时内存是另一层，不将不落库宣传为无数据流转。

## 10. 契约文件的使用方式

`ai-output.schema.json` 的顶层 oneOf 区分 candidates／verification。Swift 与 JS 使用同样约束；schema 通过后还要执行引用存在、ID 全覆盖、事件独立和权限等跨字段验证。

合成 fixture 是语义测试材料，不是所有字段齐全的网络请求。GLM 需通过适配器构建完整输入，并记录输入 digest、输出、结构结果、语义人工判定。任何超 schema 的返回必须拒绝，不能在解析失败后退回普通字符串直接展示。
