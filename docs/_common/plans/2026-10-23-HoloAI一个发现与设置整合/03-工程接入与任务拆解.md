## 3. 后端专用控制与两个阶段接口

### 3.1 接口清单（目标设计）

| 方法与路径 | 请求重点 | 响应重点 |
|---|---|---|
| `GET /v1/discovery/capabilities` | 已鉴权账号／设备 | protocolVersion、enabled、policyVersion、可用域、预算参数版本 |
| `GET /v1/discovery/control` | 已鉴权 | enabled、controlRevision、当前 ownerDevice、scopeRevision、允许域 |
| `POST /v1/discovery/control/enable` | expectedRevision、范围、说明版本、requestID | 新 controlRevision、scopeRevision、当前设备 grant；必须 CAS |
| `POST /v1/discovery/control/disable` | idempotency requestID、reason 枚举 | enabled=false，新的撤权版本；本机离线时先待提交 |
| `POST /v1/discovery/control/scope` | expectedRevision、更新后范围、说明版本 | 范围与控制版本递增，旧运行失效 |
| `POST /v1/discovery/runs` | body 不含正文；版本、runID、sourceManifestDigest | 当日批次预留、run token、版本、租约与剩余阶段预算 |
| `POST /v1/discovery/runs/:id/candidates` | run token、不可变 request hash、匿名材料 | candidate envelope、规范化候选 hash、Prompt／模型版本、usage |
| `POST /v1/discovery/runs/:id/verify` | 规范化候选原样包与 hash、支持／反例 | verification envelope、Prompt／模型版本、usage |
| `POST /v1/discovery/runs/:id/cancel` | 原因与请求 ID | 本 run 不再接受新阶段，不承诺第三方从未处理 |

可将 controller 与 store 抽到 `src/discovery/`，不要把所有业务继续写进 app.js。对外路径可按仓库统一约定调整，但不得少掉版本／预算／鉴权与幂等语义。

生成和核验都属于后台自动处理，不映射到 chat、deepAnalysis、memoryInsight 用户次数池。新增 purpose `discovery_candidate_v1`、`discovery_verify_v1` 只能由专用控制器使用。

**防旁路：** 即使 purpose 注册到 serverPromptPolicy/config，也必须在通用 `/v1/ai/chat/completions` 拒绝这两个 purpose，或证明通用路径同样执行完整 run／授权／预算检查。建议直接拒绝，避免发现变成无控制的低成本通道。

### 3.2 身份和控制

服务端从已验证 Holo 登录主体和设备 session 导出账号／设备，不使用 body accountID/deviceID 作为鉴权依据；UUID 只是定位，不是许可。

每账号初始 disabled、revision=0。enable 必须携 expectedRevision，并绑定本设备、范围与说明版本。新设备不继承自动处理许可。V1 同时最多一台 owner 设备：设备 B 启用时提示“此设备将接替另一设备的自动准备”，用户明确确认才可接管并递增版本；A 的旧 grant 失效。

disable 可以从该账号任一已验证设备发起，保守覆盖旧 enable，服务端序列单调递增。重复同 requestID 返回同结果；旧 disable 请求迟到可以再次禁用，不能按客户端时钟判断谁新。重新开启必须用户明确操作并读取当前 revision，旧 enable 重放不得复活。

本机先关再发请求。离线设备 B 的关闭无法即时通知在线 A，UI 和文案不能承诺跨设备瞬时停用；服务端收到后阻止所有新阶段，在线设备下次控制检查清掉本地结果。本机没提交完撤权前不能再发原文。

run token 与账号、设备、控制／范围版本、runID 绑定，每个阶段服务端重新核对，不能仅验证 token 签名与过期。租约初值 10 分钟、最长 run 10 分钟，不做无限自动续租；过期保守结束，下一次资格再处理。租约只协调后台发现，不夺占用户手动聊天。

### 3.3 服务端持久化仅 metadata

增量新增三类表（命名可调整）：

- `discovery_controls`：账号主体、enabled、revision、ownerDevice、scopeRevision、允许域、说明版本、服务端更新时间。
- `discovery_runs`：runID、主体／设备、版本、状态、租约、批次请求 hash、日期桶、阶段 dispatch 状态与 hash、版本、token/cost 计量。
- `discovery_requests`：控制操作与阶段幂等键、规范化请求 hash、状态、元数据结果，不存记录正文、quote 或发现正文。

候选／核验响应可只在进程内短期保留供同请求重放，建议上限 5 分钟与严格数量／字节上限，不落 DB。进程重启或缓存淘汰后，已 dispatched 阶段响应遗失返回 `DISCOVERY_STAGE_RESULT_LOST`，不能再次调用模型来“补回”；本批终止并保留仍有效旧发现。这是明确的可靠性／隐私取舍，V1 接受偶尔无新发现，不接受隐式双扣与持久化原文。

请求 body 与 response 不进 metadata-only 日志。正常／异常／超时／stream 错误都不记录原文、Prompt 拼接全文或模型输出。最小日志字段：runID、阶段、错误码、数量、耗时、token、计费摘要、版本；不记录可逆的 subjectKey／业务标题，错误 message 不直接拼用户文本。

元数据建议运行明细保留 7 天、账号撤销版本在账号存续期间保留；实际政策按现有清理任务实现并验收。清理运行 metadata 不清当天预算记录，不让删任务绕过额度。

### 3.4 顺序与哈希

verify 只能在 candidates 已成功返回且本机结构门禁通过后使用。客户端提交的候选包必须与服务端规范化候选响应 hash 相同，不能在两次调用间换文案。

候选 hash 使用双端定义的确定性序列化（键排序、UTF-8、数字格式固定），不用语言默认 `hashValue`，不把对象字段顺序当内容。选定候选子集需以服务端响应中 candidateID 集合与对应不可变对象验证；不允许修改标题后沿用旧 digest。

sourceManifestDigest 只表明客户端的来源快照归属；服务器没有用户全库，不能声称据此证明原文完整。真实回源与权限校验仍在本机，语义核验只针对实际上传材料。

### 3.5 模型调用和结果限制

专用 Controller 复用已有 provider、后端 Prompt 注册与成本 guard，但结构化 JSON 严格校验；不绕入通用 UserContext 构建，不发完整档案或其他记录。

- candidates 输出 JSON schema candidates 分支；verify 输出 verification 分支。
- body 最大建议 96 KiB，所有字符串与数组再有字段上限，超限在调用上游前拒绝。
- 上游 response format 在 provider 支持时启用；不支持也必须本地 schema 验证，不能假定 JSON mode 保证语义。
- 断连／任务过期／撤权尽力 Abort 上游。provider 返回后服务端复核 controlRevision，本机再复核 own epoch。
- 模型返回错误 JSON、缺 claim verdict 或版本不匹配：本批不发布；不让模型修复重试突破两次调用预算。

## 4. 预算与调度初值

### 4.1 从早稿调整的输入预算

早稿约 8k 总输入是待测建议，未计入完整人格前置、Prompt、反例和第二次重复证据的实际占用。**本实施包以 16k 总输入为首轮硬上限：生成 ≤6k，核验 ≤10k（都包含 system 与上下文），不得按 16k 原始记录另加 Prompt。** 这不是必须填满的配额，G4 实测后可下调。

生成输出最多 3072 tokens、核验最多 2048 tokens；候选总数最多 3、每条最多 4 个 claim（标题计入），正文不超过两段。真实成本同时计算输入、输出及 provider 已返回的其他计费项，不只看业务数据大小。

预算由服务端冻结策略与配置约束。使用支持的 tokenizer；没有匹配 tokenizer 时保守估算并用请求字节／字符上限兜底，不把客户端 token 数当可信。自动准备不读取全量历史来追求填满预算。

### 4.2 批次规则

- 上海日界，与当前 `quotaPolicy` 日桶一致；源时间窗按用户本地时区，两者分开存储。
- 首发 free／plus 都是每账号每日最多 1 个已进入上游调用的批次，无会员扩权差异；独立配置可后续调整。
- 同批最多一次 candidates＋一次 verify；无结构合格候选不调用 verify。
- 运行创建先预留；调用上游前校验失败或未 dispatch 的取消可释放。dispatch 发生或结果未知即按已用计算，不猜“模型可能没跑”而退款重试。
- 当日并发 run 创建使用 DB 事务／唯一约束阻止双设备竞态，不依赖客户端 isRunning。
- 复用 `backgroundCostGuard` 的真实 provider 成本统计，纳入后台总体预算，再叠加本功能批次上限；不能 wrap 两遍导致成本翻倍。
- 旧记忆／主题整理等独立调用仍计算在全局后台成本里，16k 不是全 App 静默 AI 成本。

### 4.3 dirty 与资格

初值：有效来源变更后静默 15 分钟；至少有 2 个可独立定位的事件／表达材料再尝试生成，单条大笔记能否切出独立经历需真实明确，不按段数计事件。

首次开启可用受限历史准备，不需等待新增记录；若无材料不消耗批次。仅查看、同步相同版本、改显示设置不产生 dirty。主题变化只是让候选有资格，仍由 AI 判断是否值得理解。

前台激活只做轻量检查并安排 utility 任务；输入、录音、手动 AI、热状态紧张、低电量／低数据模式时延后。首发优先实现前台空闲补偿；后台只 best effort，不必须新加 BGTask identifier 才能上线，不把进入后台事件变成阻塞分析。

### 4.4 失败与退避

| 失败 | 动作 |
|---|---|
| 无网络／资源不足且未 dispatch | 保持 dirty，等资格，有限退避，不报假“生成中” |
| 账号或控制不合法 | 立即停止，隐藏相关缓存，设置解释 |
| 输入 schema／长度不合格 | 本地／服务端拒绝；记录错误，不发送上游 |
| dispatch 后 5xx／响应遗失 | 本阶段不重复调用，终止本批；保留有效旧发现 |
| 模型 JSON／语义拒绝 | 记已尝试与拒绝原因，不循环重生成；同材料不隔天重跑 |
| 后台总预算不足 | 采用服务端 resetAt；不轮询撞 429 |
| 旧发现来源失效 | 即使离线也撤下，不以失败兜底旧内容 |

`noFinding` 是成功终态，要记成功处理的 source digest；材料不变时下一天也不再跑。Prompt／策略版本升级可安排一次受控重新评估，仍受日预算，不因升级全量补历史。

## 5. 每个边界都检查撤权与来源

以下六个位置不能只在第一个位置检查：

1. 来源读取前：localGrant、总授权、范围、账号、来源排除。
2. candidates 发出前：本机代数与服务端控制／预算。
3. verify 发出前：源版本、候选 hash、控制／范围版本。
4. 返回及原子提交前：所有依赖源、包括反例与统计分母都未变；控制仍一致。
5. 胶囊／详情展示前：TTL、来源存活、权限与反馈有效。
6. 续聊发送前：重新取当前原文，不把旧摘录永久写入通用对话背景。

关闭／删除／排除时先使状态失效，再取消网络与删派生材料。取消失败不影响本机失效。重开后新 epoch 不接受旧 run。切换账号／注销清掉旧账号运行内存，迟到响应不得进入新账号。

用户已主动发出的聊天消息属于原对话记录，不擅自删除；但发现自动生成的来源包应独立存储，来源撤销后后续 AI 请求过滤该包，不能为了“保留历史消息”继续注入。界面旧引用显示“来源已不可用”，不继续展示隐藏原文。

## 7. 版本兼容与回退

- capability 决定是否可完成开启；新客户端遇旧服务器正常聊天、旧设置可用，不暴露空功能。
- 服务端支持新版本不自动打开老客户端功能；不影响现有 chat／insight 等 purpose。
- schema 不认识时明确拒绝；Prompt 版本改变不会修改已发布旧发现，旧内容依然遵循 TTL 和来源版本。
- server kill switch 停新生成；质量问题时客户端收到 stopPresenting 时撤下受影响版本，不把“停止调用”误当“旧错结论仍可展示”。
- 回退只涉及本功能控制／派生 store 与新页面路由，可隐藏新能力但仍给用户管理原设置的路径；不删原记录、原记忆、回放或通知偏好。
- 新后端端点／Prompt／策略需要部署才能在设备生效。GLM 准备可审阅的变更与发布检查表，东林另行明确授权后才执行部署。
