# HoloAI「一个发现」：洞察引擎与设置整合

> 2026-10-23 · V0.2 产品／技术评审稿。基于当前工作区源码盘点，非已发布能力说明。  
> 本稿替代 2026-10-22 方案中「规则选任务、点击后开始理解」的主方向：现在由 AI 提前理解记录，产出可核对的观察，用户自愿打开。  
> 本轮交付：源码盘点、引擎设计、设置迁移方案、交互原型；未修改 App、模型、授权状态或后端。所有阈值是试点初值，不是验证结论。

## 1. 产品主张与范围

「一个发现」让用户在自己的节奏里，看见一条来自真实记录、此前没有整理清楚的观察。入口短、内容具体、不催促、不强迫行动。

- 用一个胶囊替换「今日状态」，其他三个能力入口首轮保留。
- 只有合格发现才展示胶囊。不发送通知、不自动弹窗、不加数字角标、不循环换一批。
- 点击时读取已核验的本地缓存，不因这次点击才开始全量分析。
- 正文是一条观察、简短解释和必要的情境边界；「看看依据」可展开，「聊聊这个」承接对话。
- 功能默认关闭，位于正式用户可见的「HoloAI 设置」。开关开启不等于自动开启长期记忆、回答注入或回放生成。

范围不仅是增加文案生成：必须包括授权、取数、增量调度、候选理解、反例检索、事实与语义校验、展示筛选、去重撤销、反馈，以及设置整合。

## 2. 当前已有能力：复用基础，不把代码存在视为验收通过

| 基础 | 本次查到的实现 | 可复用与不足 |
|---|---|---|
| 领域记忆观察 | `HoloMemoryObserverService`、领域观察包、输出校验及应用流程 | 有结构化输入与结果校验；受自动记忆及授权限制，不能借新功能绕过 |
| 跨域候选 | `HoloCrossDomainCandidateBuilder` | 共同锚点、时间重合、不同领域、独立证据；适合部分关联，不足以发现跨时间的同域行为变化 |
| 融合理解 | `HoloCrossDomainFusionService` | 有 LLM 调用、伪造证据与锚点拒绝、敏感分类等；不是通用「一个发现」发布器 |
| 独立证据 | `HoloEvidenceLineageResolver` | 排除洞察摘要作为底层事实，按 lineage 去重；要扩展至新候选全链路 |
| 洞察过滤 | `HoloInsightCritic` | 过滤空话与没有 evidence ID 的结论；ID 存在不代表内容支持结论，需要新增语义核验 |
| 报告缓存 | `MemoryInsightService` | 授权、快照 hash、生成状态、相似度等；周期报告与轻量发现应独立缓存、预算及状态 |
| 偏好反馈 | `InsightFeedbackAggregator`、`InsightCardReranker` | 可借鉴反馈与排序；原关键异常保底、两次反馈提升稳定偏好等不能直接套用本功能 |
| 背景任务 | `MemoryInsightBackgroundService` | 有前台补偿、后台 best effort、额度退避；存在上周观察不依赖旧后台开关的分支，不能把旧开关直接当新功能总闸 |
| 授权 | `HoloAIDataProcessingConsent`、`HoloMemoryAccessPolicy` | 全局处理授权、自动记忆、记忆辅助回答是不同语义，整合界面不得合并为一个布尔值 |
| 数据排除 | 想法 AI 范围与标签排除流程 | 必须涵盖原始记录、派生摘要、历史记忆、候选与在途结果，需核验回溯失效覆盖 |

本次未运行这些服务或触发任何 AI 请求，不能认定其端到端质量已达新功能标准。

## 3. 一条发现的合格标准

同时成立才发布，任何一项失败均允许返回「没有发现」。

1. **属于这个用户：** 明确来自允许的数据，不是通用于任何人的建议。
2. **超出简单复述：** 识别变化、重复方式、具体情境或联系；只有「完成了三件事」不够。
3. **依据能支持句子的强度：** 两个例子只能说「这两次」，不能写「你总是」「常常」。
4. **核对过不同解释：** 有反例时缩小范围，不能只检索支持自己的记录。
5. **范围清楚：** 记录反映的片段不是完整生活；未记录不等于没有发生。
6. **克制且有新意：** 不夸大问题，不病理化，不用焦虑、人格、关系诊断吸引点击。

### 3.1 首发支持的发现类型

| 类型 | 需要什么 | 合适的表达 |
|---|---|---|
| 两段经历的具体联系 | 两个独立事件的直接记录，并能准确解释共同点 | 「这两次重新开始，你都先降低了第一步的要求。」 |
| 情境中的重复方式 | 试点要求至少 3 个独立事件，跨至少 2 个时间段，并检查反例 | 「在这几次已有记录中……」，仍不直接升级成人格 |
| 关注点或做法的变化 | 至少两个可比时段、足够原文上下文 | 「这几篇记录从讨论结果，转向了讨论具体尝试。」不能据此认定心理改善 |

跨域不是必选项。同一领域内的扎实观察，也可以比跨域猜测更有价值。首发不主动展示健康诊断、亲密关系推断、财务困境等敏感发现；已有健康数据只能按既有政策用于用户主动发起的能力，不自动纳入本功能。

## 4. 引擎工作流程

### 第一步：授权与变更登记（本地）

前置条件：功能开关开启、全局 AI 授权有效、发现范围已确认、服务可用。

- 记录变动只登记受影响的来源 ID、版本、领域与时间，不立即调用模型。
- 用户文本均作为待分析数据，不作为系统指令；记录中的「忽略规则」「上传全部记录」等内容不可改变工具权限或输出要求。
- 开关、范围、授权、删除、编辑分别更新控制代数／数据版本。删除和撤权即时失效，不等待下轮生成。

### 第二步：整理可追溯材料（本地）

每份材料保留：来源类型、来源 ID、来源版本、实际发生时间、记录时间、原文片段位置、时间范围、可用权限、底层事件 lineage。

- 同一事件在任务、想法和摘要中出现，仍只算一个独立事件。
- 记忆与报告可以用于定位原记录，不能互相引用来证明自己。
- 数字、占比和比较由程序计算，带分母、覆盖率及口径；模型解释，不自行编数。
- 记录整理成小块原文与确定性事实，避免多层摘要把「可能」压成「确定」。
- 已排除来源不能通过旧记忆、旧报告或向量索引重新进入材料包。

### 第三步：局部召回与 AI 提出候选

本地根据变化的主题、显式实体关联和时间段寻找上下文；语义相似只能用于召回，不直接证明是同一件事。

首轮可用最近 30 天作为主要窗口；需要历史对照时定向召回最多 90 天范围内的相关片段。这是取材初值，不是「30 天足以理解一个人」的结论。事件窗口和发生时间均保留，不能把补记日期当成发生日期。

AI 只输出 0～3 条结构化候选。每条包含：

- 类型、讨论对象、适用时间与情境。
- 拟展示观察和逐句声明。
- 每句引用的 evidence ID、对应原文片段。
- 直接事实与推断分别列出。
- 可能推翻它的情况、需要寻找的反例。
- 与用户已看发现的差异；敏感程度。

AI 可以返回空数组。不得要求凑够条数，不以自报的「95% 置信度」作为发布标准。

### 第四步：主动找反例，再核验候选

第一轮候选确定后，在允许数据中定向找相同主题但结果不同的事件、对比时段及用户明确纠正。候选生成和反例检索分开，避免模型只看自己选出的正例。

1. 本地检查：来源是否存在且有权限，版本是否一致，引用是否真实，数值能否复算，证据是否独立，时间范围是否正确。
2. 有候选时才调用独立的一次核验请求，输入候选、支持原文、反例及缺失信息；优先不带第一轮自信评分与劝服性解释。
3. 核验逐句给出「支持／需缩小表述／不支持／无法判断」，可改成更窄的观察，不能靠润色修补缺失事实。
4. 数量或因果等可确定问题以程序和明确规则为准。第二个模型也是可能出错的模型，不能替代原始证据和人工评估。
5. 没找到反例不等于不存在；检索覆盖不足时，保留范围提示或不发布。

**例子：** 运动与阅读各有一条「从小步开始」记录，只能展示「这两次有一个相似之处」。若其他记录显示小步也经常没有继续，就不能写「这就是对你有效的方法」，更不能声称因果。

### 第五步：选择值得展示的一条（本地发布策略）

先过硬门槛，再排序，不允许高新颖度抵消证据不合格。

排序优先级：证据与范围可靠 → 有明确个人相关性 → 相对已看内容有新信息 → 当前仍适用 → 用户表达的展示偏好。

- 同一观察换措辞不算新发现；用「对象＋观察类型＋语义主题＋底层证据集合」联合去重。
- 不按负面程度、焦虑程度、预计点击率排序。
- 没有合格候选就结束，不生成鸡汤填位。
- 展示最多一条，不边读边替换。看过后保留普通样式，直到过期或新内容合格替换。
- 初值：同主题 14 天冷却；新增实质证据或用户主动重看可调整。不能只用全文相似度判断是否重复。

### 第六步：反馈与续聊

- 「有点像」：记录这条观察被用户认可，不自动存成长期人格记忆，也不当作事实证明。
- 「不太准确」：立即撤下；可选原因：依据不对／理解不对／现在不适用。涉及事实错误时，不能只调整推荐权重。
- 「不想看这类」：减少或停止该主题展示，不等于事实被否定。
- 关闭面板／不点击：无偏好结论。
- 「聊聊这个」：携带发现 ID、当前证据版本、已知边界及用户问题进入可确认的草稿。发送前再次检查来源。普通续聊不隐式消耗深度分析额度。
- 续聊中新补充的信息与用户旧记录矛盾时，应修正或撤销发现，不让旧发现反过来影响新的理解。

## 5. 调度、预算和运行状态

### 5.1 建议首发调度

| 事件 | 行为 |
|---|---|
| 首次主动开启 | 确认处理范围后排一次非阻塞准备任务；无足够材料正常结束 |
| 新增／修改一批记录 | 更新脏标记，合并事件；初值静默 15 分钟后再评估，不每条记录调用 |
| App 下次回到前台且空闲 | 在冷却与预算内补偿准备；聊天、输入、手动分析优先 |
| 系统允许后台执行 | 尽力完成已符合条件的任务；不承诺每天固定时刻有发现 |
| 只是打开对话／点击胶囊 | 仅读取合格缓存，不启动新一轮全量分析 |
| 删除／排除／撤销授权 | 立即取消或作废相关任务与结果，清理派生内容 |

首发不做「永远在线的 Agent」，不每次刷新全量取数。仅传递受影响片段、少量相关历史和必要的既有上下文。

### 5.2 预算初值，进入开发时需压测

- 每设备最多 1 个发现准备任务；每账号每日最多 1 个自动生成批次，首发历史回看不额外无限补跑。
- 每批最多一次候选理解＋一次核验；无候选不核验。重复传输重试使用同一幂等标识，不算新分析。
- 材料预算初值总输入不超过约 8k tokens／批（包含核验重复材料），候选最多 3 个，线上测量后调整。
- 服务端按账号预算与幂等进行硬限制，防多设备放大。设备只在具备本地材料时发起，不为协调而上传生活原文。
- 自动发现使用独立产品预算，不静默扣减用户主动深度分析次数。具体免费／会员权益待成本实测后定，不在原型展示未确定的次数承诺。
- 离线、超额或服务失败后保留仍有效的旧发现；没有旧发现则隐藏。无立即重试循环，按失败类型退避；下次有资格再尝试。

这里的调用上限只约束发现层。若已有记忆抽取也运行，必须合并统计总成本，不能声称两次调用就是整套 AI 的总成本。

### 5.3 状态与在途撤销

运行状态：关闭 → 待材料 → 待调度 → 准备中 → 已核验可展示／无合格发现／失败退避。

发现内容另有状态：候选、有效、已看、用户否定、证据失效、过期。建议默认有效期 14 天，具体由发现类型缩短；永久模式不靠延长缓存伪装成立。

每次任务绑定账号、控制代数、数据范围版本、来源版本集合、模型与提示词版本。返回时任一权限或来源版本过期，结果不发布。关闭时不仅取消请求，还递增代数，防止已经返回或无法取消的迟到结果重新显示。

## 6. 新开关：设置、权限与多设备

### 6.1 用户入口

路径：HoloAI 对话页齿轮 → HoloAI 设置 → 一个发现。系统设置也进入同一页。

名称：**一个发现**。说明：**让 AI 从你允许的记录里，整理值得留意的变化与联系。只在这里呈现，不发通知。**

默认关闭。首次开启显示说明，写明自动处理、范围、外部 AI 服务、非实时生成，以及可随时关闭。开启按钮为「同意并开启」。未获得全局授权时先进入既有授权流程，取消就保持关闭；不能先亮开关却没有实际权限。

### 6.2 与其他开关的关系

| 控制 | 关闭后的含义 | 与一个发现的关系 |
|---|---|---|
| HoloAI 数据处理授权 | 全局禁止新的外部 AI 调用 | 优先级最高；发现暂停、失效缓存隐藏。恢复授权不自动恢复发现，需再次主动开启 |
| 一个发现 | 不再生成或展示本功能发现 | 立即停队列、撤下胶囊、删除本功能候选与派生缓存，保留防重复否定记录；不影响主动聊天和已有长期记忆 |
| 自动形成记忆 | 不再新增长期记忆 | 一个发现可在用户独立授权下使用原始记录做临时理解，但不得借此写新记忆；不绕过旧记忆萃取策略 |
| 记忆辅助回答 | 回答不读取长期记忆 | 发现层也不读取长期记忆作为理解上下文，仍可按独立范围使用原始记录；需在说明中区分 |
| 发现使用范围 | 仅限这个功能的上限 | 与全局想法排除、来源授权取交集，不能扩大其他 AI 能力的数据范围 |
| 回放自动生成与提醒 | 只管理回放生成／通知 | 不影响发现，不允许旧回放后台任务顺带生成发现 |

首次选择范围：想法、任务、习惯；健康和财务不进入首发范围。初次开启不默认全选，用户至少选一种。无选择时不允许完成开启。功能后续增加领域必须再次选择，不能升级后自动扩权。

### 6.3 多设备规则

授权不跨设备静默继承：新设备默认未开启，首次启用需确认。关闭与撤销是账号级拒绝信号，在其他设备收到后立即生效；离线设备不得开始新的外部处理，联网时先核对拒绝版本。未验证该通道前，首发仅允许一台设备开启自动准备，不能宣称「所有设备即时停用」。

用户开关偏好、来源范围与拒绝版本使用同步的控制状态；原始材料与发现缓存首发本机保存，不因普通记忆可 iCloud 同步就自动同步发现。实现需复用或扩展项目既有控制同步机制，不能用新增本机 UserDefaults 布尔值声称完成多端撤权。

### 6.4 关闭与删除的诚实边界

用户关闭后立即停止新的处理并隐藏内容。已经发送给外部服务的材料无法“撤回未发生”，应尽力取消、删除云端任务材料并拒绝本地采纳结果；不能在 UI 承诺第三方请求从未发生。云端任务、日志、保留期与销毁机制须验收后才能写入正式隐私说明。

## 7. HoloAI 设置现状盘点与归拢

### 7.1 分散现状与迁移表

| 配置 | 当前查到的入口 | 建议目的地与处理 |
|---|---|---|
| 全局 AI 数据授权 | 系统设置「AI 整理」区；聊天授权页；Debug AI 设置重复入口 | HoloAI 设置 → 数据与隐私；原入口改为跳转同一页 |
| 个人档案 | 个人 → 个人档案编辑器 | HoloAI 设置 → 关于你 → 个人档案；个人页保留快捷链接，不复制编辑器和状态 |
| 自动形成记忆／记忆辅助回答 | 个人 → 长期记忆 | HoloAI 设置 → 关于你 → 长期记忆；保留现有两个独立值 |
| 查看／纠正／删除记忆 | 长期记忆 → 记忆长廊 | 内容管理仍由记忆长廊负责；新设置页链接到原内容管理能力 |
| 想法智能整理、主题与相关笔记 | 系统设置 → 想法设置；想法模块入口 | HoloAI 设置 → 自动处理 → 想法智能整理；主题／标签内容管理保留想法模块，关联设置链接同一页面 |
| 想法 AI 标签排除 | 想法设置 → AI 分析范围 | HoloAI 设置 → 数据与隐私 → 不参与 AI 的想法；原模块保留跳转，所有 AI 共用同一排除状态 |
| 回放周月提醒与后台生成 | 系统设置「AI 回放」；通知设置 → AI 回放也可配置提醒 | HoloAI 设置 → 自动处理 → 周期回放；提醒时间仍用统一通知配置源；通知页作为另一个入口，不能存第二份值 |
| 目标主动提醒 | 各目标详情；通知设置有相关说明 | 按目标保留授权；HoloAI 设置的提醒入口可链接目标管理，不新增覆盖全部目标的开关 |
| 云端分析说明 | 首次深度分析／回放隐私弹层 | 数据与隐私 → 云端处理说明；保留每种处理场景必要的首次确认，不将「只用于本次」误写为后台发现授权 |
| API Key、Provider、温度、Token、Prompt、Agent 调试 | `AISettingsView` 与聊天齿轮均受 `#if DEBUG` 控制 | 仍属开发者配置，不放进正式 HoloAI 用户设置，不通过本次归拢恢复自接模型入口 |

### 7.2 新的正式设置首页

HoloAI 设置分为：

1. **一个发现**：独立子页，开关、当前状态、使用范围、自动处理说明。
2. **关于你**：个人档案、长期记忆（形成与使用两个开关、管理内容）。
3. **自动处理**：想法智能整理、周期回放。
4. **数据与隐私**：数据处理授权、不参与 AI 的想法、云端处理说明。

不要在首页平铺十几个开关。生成频率、模型、预算和评分均为产品内部策略，不交给用户配置。

### 7.3 迁移纪律

- 一个正式 HoloAI 设置首页，多条入口均导航到它。旧深链与模块快捷入口保留，指向同一个子页。
- 移动页面不迁移成一套平行偏好系统：沿用既有存储键、服务及调度响应。新增发现偏好独立建模。
- 不重置用户当前授权、自动记忆、回答注入、回放和提醒选择；每项逐一比对迁移前后值。
- 提醒只有一个通知调度源，多个页面不能重复注册通知。
- 回放需先纠正一个现有语义缺口：代码中的「上周观察」自动生成不依赖旧「后台自动尝试生成」开关。新子页应分别展示「自动生成每周观察」和「自动生成日／月回放」；后者沿用旧偏好，前者将既有产品自动行为显式化并提供停止控制，按迁移时真实有效策略保留状态。不能仅搬走旧开关就宣称关闭后所有回放都停止，也不能把旧的日／月关闭选择改成开启。迁移时说明这两个不同范围。
- 排除范围原有「开启表示排除」的语义保留；新发现范围使用「勾选表示允许」，两者文字明确，不能通过同样的开关造成反向误读。
- 原「AI 设置」改作内部开发者配置，用户设置单独建页面和路由，正式包具有可见齿轮入口。

## 8. 可信性与数据生命周期验收

| 场景 | 必须证明 |
|---|---|
| 一条事件被任务、想法、摘要重复描述 | 不被当成 3 次独立经历 |
| 原文说「试着走十分钟，后来仍未继续」 | 不被归纳成「小步让你坚持成功」 |
| 两条支持、数条反例 | 缩小表述或拒绝，不能只引用正例 |
| 仅有记录日期，没有发生日期 | 不构造精确先后与因果 |
| 数据稀疏或长期无新增 | 没有发现是正常结果，不制造每日内容 |
| 引用真实但与结论无关 | 语义核验拒绝，证据 ID 存在不算通过 |
| 来源删除、排除、编辑 | 对应发现、索引摘要与在途结果一并失效；旧缓存无法重新显示 |
| 用户在请求中关闭功能 | 迟到结果不落库不显示；重新开启也不能采纳旧代数结果 |
| 自动记忆关闭、发现单独开启 | 没有新增长期记忆；授权语义和实际调用一致 |
| 用户否定一个发现 | 同义改写不能绕过否定再出现 |
| 聊天中明确反驳旧观察 | 修正／撤下旧发现，不把发现当系统事实压过用户回答 |
| 多设备离线和重连 | 新请求前核对控制版本，按实际支持范围声明撤权效果 |

先用合成样本与经同意的测试材料建立正例、反例、稀疏、删除和越权集。程序门槛、模型语义核验、人工核对分别记录结果。首发阻断级问题包括伪造引用、越权使用、错误数值、未撤销迟到结果；不得以整体平均分抵消。

质量评估关注：事实与引用支持率、独立事件计数、对反例的敏感性、泛化表达、主动内容接受度、无发现比例、重复率、每个有效发现的总成本。点击和停留只作为流程指标，不作为理解准确性证明。

## 9. 建议实施顺序

1. **先打通统一设置与权限测试**：正式用户页、旧设置跳转、状态不重置、新开关与范围、全链路取消／失效。
2. **引擎离线质量验证**：材料包、候选、反例与核验；用合成样本证明能拒绝“看起来合理”的错误发现。
3. **用户明确开启的小范围试点**：增量调度与独立预算，观察质量和用户纠正，不强制每天产出。
4. **再扩展场景**：只有准确性、撤销与成本达标，才扩大领域和设备支持。

用户已接受「AI 提前理解」方向；具体阈值、计费权益、服务保留承诺和多设备上线范围仍需开发前验证。本次原型演示交互与状态，不执行 AI、上传数据或修改用户真实偏好。
