# 信用卡还款提醒 — 功能方案

> 2026-11-09 东林提出：财务模块信用卡到期希望有提醒，每张信用卡单独设置提醒日期。
> 本文为拍板后的定稿方案，可直接作为实施任务书。

## 一、拍板结论（2026-11-09）

| 决策点 | 结论 |
|---|---|
| 提醒日期定义 | **还款日 − 提前天数，自动推导**。不设独立提醒日字段；提前天数每卡可调 0-7 天，默认提前 1 天 |
| 商业化 | **免费 3 张卡 + 超额 Plus**（2026-11-09 第二轮拍板，推翻第一轮「整体 Plus 门控」）：免费用户可给 3 张信用卡设置还款日编辑 + 还款提醒，第 4 张起走付费流程；Plus 不限张数。**打破现状**：目前账单日/还款日编辑是纯 Plus 门控（非 Plus 全锁），本功能落地时改为数量门控 |
| 提醒方式 | 本地通知（手机上自己定闹钟），**免后端发版**；额度判定亦纯客户端（财务数据在 CloudKit 不经后端，本地计数无绕过后端的矛盾，属行业通行的荣誉制限制） |
| 提醒时间 | 一期固定早上 9:00（与既有 billDue 提醒默认时间一致） |

### 额度语义（2026-11-09 第三轮拍板：静默使用，第 4 张才拦）

- **名额 = 开启了还款提醒的信用卡张数**（`dueReminderEnabled == true`），动态计数：关提醒即释放名额。编辑权分档（2026-11-09 东林拍板解绑）：**Plus 账单日/还款日恒可编辑**（只看本期账单不收提醒也能设日期）；免费编辑权跟随提醒开关（共 3 张，开提醒才解锁日期）
- **平时零提示**：编辑页与详情页没有任何名额说明文字、没有锁图标；前 3 张一切静默
- **免费用户开第 4 张**（11-09 第六轮定稿：删免费路径行）：开关拨动 → 回弹 + **HoloQuotaNoticeCard**（居中卡片 + 压暗遮罩，`Components/HoloQuotaNoticeCard.swift`，两入口共用 `.holoQuotaNotice` 修饰符）。结构：状态式标题「免费名额已用满」+ 规则说明一行；**只保留升级路径一行**（crown 金图标「升级后不限张数 · 开通后会自动打开这张卡的提醒」，全弹窗唯一金色；东林红框删掉了「关掉一张腾出位置」免费路径行——弹窗不教替代方案，两条出路的设计被否）；操作区唯一品牌橙主按钮「升级 Holo Plus」+ 次要文字钮「知道了」。圆角 HoloRadius.xl（弹窗档）、遮罩点击=知道了、出现 spring 弹入 + warning 触觉、reduceMotion 退化纯淡入。点「升级」→ requirePlus（购买成功自动开回）。系统 alert 版（第四轮）被否：与 Holo 视觉不协调
- Plus 用户：不限张数，全程无感
- **Plus 过期**：已配置数据保留展示不删；提醒排程免费档只保留前 3 张（按 sortOrder 稳定排序），超额暂停，续费随重排自动恢复；超额时前 3 张仍可编辑 / 关闭（否则用户无法腾名额）
- 通知设置页入口行摘要保留「N/3 张已开启」——碰到付费墙的用户在这里能看懂原因（它是状态展示，不是事前说教）
- **日期落库条件（解绑后）**：开了提醒 / Plus / 存量本就配过日期，三者其一才写账单日与还款日；免费未开提醒且从未配过的卡仍传 nil（防假默认值回归）
- 存量数据：几乎不存在免费用户已显式配过还款日的场景，动态计数天然兼容，无需迁移逻辑

### 顺手修的现状缺陷：创建信用卡默认写假还款日

现状 `AddAccountSheet` 保存时信用卡**必然**写入默认「账单日 5 / 还款日 25」（:31-32 默认 state 原样传库，免费用户 Stepper 锁定也照写），详情页因此凭空显示假倒计时。本功能落地时一并修正：**新建时未开提醒的卡 billingDay / dueDay 写 nil**（开提醒时才写入用户设置值）；编辑时关提醒保留已有值（数据可进可退）。种子账户不受影响（`Account.create` 本就不写）。**已落库的历史 5/25 假值不动**：区分不出是不是用户选的，会一直显示到用户自己改掉

## 二、现状（地基已就绪，缺口只有排程器）

- **数据**：`Account` 已有 `billingDay` / `dueDay`（Int16?，1-31，仅信用卡用）/ `creditLimit`，定义在 `Models/CoreDataStack+FinanceEntities.swift:422-441`（纯代码模型，无 xcdatamodeld）
- **编辑 UI**：`Views/Finance/AddAccountSheet.swift:320-376` 信用卡专属「账单信息」区（账单日/还款日 Stepper + 额度）；现有门控在 :381-396（非 Plus 整块锁，`requirePlus(context: .billingCycle)`）——**本功能落地时改为数量门控**
- **门控基建**：`HoloPlusActionCoordinator.requirePlus` + `HoloPlusGateContext` 枚举（`Services/Subscription/HoloPlusActionCoordinator.swift:53`）；`.billingCycle` 现被三处复用（周期账单提醒设置 / 财务月起始日 / 信用卡账单信息），信用卡侧需拆新 case；「档位额度」有先例：taskSplit 月池免费 5 / Plus 100（`TaskSplitService.swift:41`）
- **详情页**：`Views/Finance/AccountDetailView.swift:727-798` `creditCardStatementCard` 已有账单日/还款日展示与**距还款日倒计时**（含逾期态）
- **通知基建**：`Services/BillDueReminderScheduler.swift`（周期账单到期提醒，针对 SpendingProject）为**完整可抄模板**——前缀清旧重排 / 监听 `.financeDataDidChange` debounce 1s / Plus 门控 `HoloEntitlementState.shared.isPlusActive` / 未授权静默清理 / 只排明天起不追发
- **通知点击路由**：category 机制在 `Services/TodoNotificationService.swift`（category 定义 :184-219，点击分发 :631），可挂新 category 跳账户详情

## 三、产品设计

### 用户看到的

1. **入口 A（主）**：编辑信用卡的「账单信息」区内新增「还款提醒」开关；打开后出现「提前提醒」选择（当天 / 提前 1 天（默认）/ 2 天 / 3 天 / 5 天 / 7 天）。免费用户已占 3 个名额时，第 4 张卡此区上锁走付费引导
2. **入口 B（快捷）**：账户详情页 `creditCardStatementCard` 还款倒计时旁一个提醒开关，打开即按默认提前 1 天生效（进编辑弹层可改提前量）
3. **提醒效果**：早上 9:00 通知，「**XX卡 明天是还款日**」，点击直达该卡详情页
4. **每月自动重复**，一次设置终身有效；关开关 / 删卡 / 账户归档即自动取消
5. 通知文案相对表述复用模板套路：当天→「今天」、1→「明天」、2→「后天」、N→「N天后」

### 边界行为（必须处理）

- **月底 clamp**：还款日 31 号的卡，2 月提醒贴到当月最后一天（28/29）。**与详情页倒计时必须同源**——实施时若详情页 dueDate 是内联计算，先把它提取成共用静态方法（建议挂 `BillingCycleCalculator`），排程器与 UI 共用，杜绝「详情页说还有3天、通知没来」的打架
- **提前量跨月**：还款日 2 号提前 3 天 = 上月 30 号；用 `Calendar.date(byAdding: .day, value: -leadDays)` 从当期还款日回推，天然处理
- **多设备**：iPhone / Mac 数据同步后两台都会弹（本地通知各排各的）。一期接受双端都提醒；若东林嫌吵，二期加平台过滤
- **权限未授权**：开开关时若通知未授权，走既有引导（参照 `NotificationSettingsView` 授权流程）；已排提醒但用户后来关了系统权限 → 排程器读到未授权时清旧静默退出（模板既有行为）
- **Plus 过期**：非 Plus 不排程、清旧（模板既有行为 `isPlusActive` 判定）；重新订阅靠下次数据变化/启动重排收敛
- **已过提醒日不追发**：只排明天 0 点起（模板既有行为）

## 四、技术方案

### 1. 数据层（CloudKit 增量兼容演进）

`Account` 实体新增 2 字段（插在 `CoreDataStack+FinanceEntities.swift` creditLimit 之后同区域）：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `dueReminderEnabled` | Bool，non-optional | `false` | 还款提醒开关 |
| `dueReminderLeadDays` | Int16，non-optional | `1` | 提前天数 0-7 |

- non-optional + defaultValue：老记录自动填充默认值，无迁移风险，符合 CloudKit 开发库红线（纯增量，不动旧数据）
- `Account+CoreDataProperties.swift` 补 @NSManaged 与 create 工厂参数默认值
- **CloudKit 部署**：随包自动上报新字段 → 生产环境部署一次（流程有先例；注意先 Console 核实字段真到位再下结论——踩坑档 `cloudkit-deploy-check-console-first-1102`）

### 2. 排程器（新文件）

`Services/CreditCardDueReminderScheduler.swift`，**照抄 BillDueReminderScheduler 骨架**，差异点：

- identifier 前缀 `holo.ccDue.`（`holo.ccDue.{accountUUID}`，每卡一条 → 每卡独立开关天然成立）
- 数据源：拉取 `type == creditCard && dueReminderEnabled && dueDay != nil && 未归档未软删` 的账户（billingDay 为空时开提醒阶段已补默认值，排程侧不再兜底）；**免费档按 sortOrder 稳定排序只取前 3 张**（Plus 过期降级的超额卡自动暂停，续费随重排恢复）
- **下次还款日必须用 `BillingCycleCalculator.dueDate(billingDay:dueDay:cycleStart:)`（`Models/BillingCycleCalculator.swift:193`）与详情页倒计时同源计算**——它处理了「还款日早于账单日 → 次月」的跨月语义（账单日 25 / 还款日 5，本期还款日是次月 5 号），裸算「下一个 X 号」会与详情页打架；月底 clamp（31 号 → 2 月 28/29）实施时确认 `makeDate` 行为并用单测钉死
- 提醒日 = 当期还款日 0 点 − leadDays（`Calendar.date(byAdding: .day)` 回推，天然处理提前量跨月），9:00 一次性 `UNCalendarNotificationTrigger`（repeats: false，`day:31` repeating 会漏小月，禁用）
- 提醒日：`当期还款日（clamp 月底，共用算法）− leadDays`，9:00，一次性 `UNCalendarNotificationTrigger`（repeats: false，`UNCalendarNotificationTrigger` 的 `day:31` repeating 会漏小月，禁用）
- 通知内容：title「{卡名}{相对日}是还款日」，body 带具体还款日期（M月d日）；category 新增 `TodoNotificationCategory.ccDue`，路由跳财务模块该卡详情页
- 每卡**预排未来 2 期**（本期 + 下一期各一条），触发或数据变化时重排。已知限制：本期还款日已过时实际只排得到 1 条，连续 1-2 个月不打开 App 提醒会断
- 触发重排：①账户写入（新建/修改/删除/归档/取消归档）在 `FinanceRepository+Accounts` 保存后显式 `refresh()`——**实施时核实账户保存并不广播 `.financeDataDidChange`，方案初稿写错了**；②监听 `.financeDataDidChange` 兜回收站恢复等路径；③监听会员状态变化（续费恢复 / 过期降级）；④`handleAppActivity()`（启动/回前台）。iCloud 同步过来的改动不发财务广播，靠④在下次打开 / 回前台收敛

### 3. UI 两处

- `AddAccountSheet`：账单信息区内、额度行之后加「还款提醒」Toggle + 提前量选择；**门控改数量制**——免费用户已开提醒的卡 = 3 张时整区上锁（锁图标 + 付费引导 + 「免费可设置 3 张」文案），替换现有 :381-396 的纯 Plus 锁定；**保存时未开提醒的卡 billingDay/dueDay 传 nil**（修假默认值，见额度语义节）
- `AccountDetailView.creditCardStatementCard`：倒计时行尾加快捷 Toggle（打开=enabled+默认提前1天，关=enabled=false 释放名额），编辑提前量引导进入口 A；同一名额判定
- 保存链路走 `FinanceRepository.addAccount/updateAccount` 现有通道（勿绕开，保持 `.financeDataDidChange` 触发）
- **文案同步**：`HoloPlusGateContext` 新增 case（如 `.creditCardReminder`，弹层标题「升级 Holo Plus，解锁更多信用卡还款提醒」），信用卡侧不再借用 `.billingCycle`（该值保留给周期账单 / 月起始日）；会员权益对比表（`HoloPlusBenefitComparisonTable`）无账单相关行，无需动
- **通知设置页统一入口（11-09 东林拍板追加）**：`NotificationSettingsView`「财务提醒」组加入口行——标题「信用卡还款提醒」、摘要免费档「N/3 张已开启」/ Plus「N 张已开启」（计数在 loadCounts 查好，不进 body）、点开就地展开说明「在财务 → 账户里点开信用卡，打开『还款提醒』即可」。提醒统一由设置 → 通知管理
- **说明文案（11-09 东林两轮反馈后定稿：零提示）**：编辑页底部说明整段删除（免费 / 会员都不显示）；免费限制只在实际触碰第 4 张时以付费墙形式出现

### 4. 本地化

三语词条走 xcstrings **文本级插入定式**（禁全量 dump——踩坑档 `xcstrings-jsondump-restore-chain-1101`）
