# 聊天输入舱放大重设计方案

- 日期：2026-11-07
- 状态：**已拍板已实施，编译绿，待东林真机验收**（东林 11-07 拍板「舒展」并下令开工；灰块舒展 + 打字舱放大两项都做，改动未提交）
- 需求来源：东林原话「我想把输入框拉长一点，放大一点」；典型场景 = 打 5–8 行长 prompt 时看不全自己输入的内容
- 交互原型：会话内可视化（`holo-input-dock-prototype.html`），可打字试玩
- 改动范围：仅 `Holo/Holo APP/Holo/Holo/Views/Chat/ChatInputView.swift`，其余文件零改动

## 定稿口径（东林 2026-11-07 已拍板）

1. 输入字体**保持** 17pt body 档不变（与消息正文同档）。「放大」由舱体高度、按钮热区、可见行数承担。
2. 可见行数上限 **5 → 6 行**。
3. **用户消息灰块按「舒展」执行**：字号不动，行距拉开 +4pt（17pt 字视觉行高 ≈26），内边距 14/10 → 16/12。这是需求本尊——东林两轮红框圈的都是用户消息灰块（「密密麻麻」），打字舱放大是附带项。

## 文案（本方案零新增文案）

零新增文案。占位符保持「告诉 Holo 发生了什么…」；无障碍标签保持「图片识别记账」「语音输入」「发送消息」「停止生成」。

## A. 四态规格

| 态 | 高度 | 结构与可见元素 |
|---|---|---|
| **A1 静止态**（未聚焦、无文字、无承接条） | **~102pt** | 单行占位符（secondary 色）+ 工具行。图片/麦克风正常色；发送钮 40pt 圆、`holoToolInset` 灰底、箭头 40% 透明 |
| **A2 聚焦输入中**（1–6 行） | 102 + (n−1)×22pt | 文字随行数即时撑高（不加动画，原生 TextField 行为，避免打字抖动）。有非空白文字 → 发送钮亮橙 `holoPrimary` + 阴影 |
| **A3 展开到上限**（>6 行） | **锁 ~212pt** | TextField 内部滚动，光标自动跟随；发送/停止钮始终固定舱底右缘可见。6 行依据：全显典型 5 行 prompt；8 行 prompt 可见 6 行滚 2 行 |
| **A4 流式响应中** | **~102pt**（与静止同） | 发送时文字已清空 → 自然回单行。发送位变停止钮（40pt 圆，样式沿用现状只放大）；图片/麦克风置灰禁用；快捷按钮排禁用 50% 透明（现状已有）。舱高不因流式状态变化 |

## C. 改动点清单（全部在 ChatInputView.swift）

1. **body → TextField**（L102–115）：`lineLimit(1...5)` → `(1...6)`；上下 padding 9/7 → 10/10。
2. **body → 工具行 HStack**（L123–192）：图片/麦克风（含 `isLoadingPick` 的 ProgressView）frame 36→44、icon 19→20；发送/停止钮改为「40 视觉圆 + 44 热区外框」双层 frame。
3. **body → 容器 padding**（L194–197）：4/14/8/8 → 6/16/10/10。
4. **不改** `ChatView` / `ChatScrollController` / `QuickActionBar`：输入舱在 ScrollView 之外，舱体长高 → 列表 viewport 变矮 → `handleViewportSizeChange`（ChatScrollController.swift L265）已处理——贴底时钉底跟随、非贴底仅钳制不跳。已验证成立。

```swift
TextField(String(localized: "告诉 Holo 发生了什么…"), text: $viewModel.inputText, axis: .vertical)
    .focused($isInputFocused)
    .lineLimit(1...6)                          // 5 → 6 行
    .textFieldStyle(.plain)
    .holoText(.body)
    .tint(Color.holoPrimary)
    .padding(.top, 10).padding(.bottom, 10)    // 上下对称
    .padding(.trailing, 6)

// 工具行：左图标 44 热区 / 右发送 40 视觉 + 44 热区
Image(systemName: "photo")
    .font(.system(size: 20, weight: .medium))
    .foregroundColor(imageButtonColor)
    .frame(width: 44, height: 44)              // 36 → 44
// 发送钮（停止钮同构）：
Image(systemName: "arrow.up")
    .font(.system(size: 17, weight: .bold))
    .foregroundColor(canSend ? .holoToolOnAction : .holoToolTextSecondary.opacity(0.4))
    .frame(width: 40, height: 40)
    .background(canSend ? Color.holoPrimary : Color.holoToolInset)
    .clipShape(Circle())
    .frame(width: 44, height: 44)              // 热区外框
// 容器：.padding(.top, 6) / .leading 16 / .trailing 10 / .bottom 10
```

## D. 边界行为

- **发送回缩**：`inputText` 清空 → 舱体自动回缩至聚焦单行 ~102pt；键盘保持不收（IM 连续追问动线，与现状一致）。
- **chips 排**：**保持可见，消息列表吸收压缩**，不隐藏。理由：QuickActionBar「对话全程可见」是既有拍板语义；成本仅 ~40pt。
- **长文内部滚动**：>6 行 TextField 原生内部滚动 + 光标跟随，零新代码；粘贴超长文本同路径。
- **Dynamic Type 最大档**：不加防御性 maxHeight，全部高度内容驱动，无固定高；AX 档下超限仍走内部滚动。
- **iPad**：宽屏 ≤720 居中收窄逻辑不变，行数上限与 iPhone 一致。

## E. 验收清单（截图走查用）

- E1: 静止态舱高 102±6pt，占位符单行完整显示
- E2: 输入 3 行文字，舱内 3 行全文可见，无内部滚动
- E3: 输入 8 行文字，舱锁 6 行可见，第 7–8 行内部滚动且光标始终可见
- E4: 6 行上限态下，发送/停止钮完整可见于舱底右缘，无裁切无遮挡
- E5: 图片/麦克风热区 ≥44×44pt，图标视觉 20pt 垂直居中
- E6: 工具行图标左缘 = 输入文字左缘（舱内边距 16pt 同口径）
- E7: 发送后舱体回缩至单行 ~102pt，键盘不收起
- E8: 流式中停止钮 40pt 圆位于舱底右缘，图片/麦克风置灰不可点
- E9: 舱体展开到 6 行时快捷按钮排仍完整可见
- E10: 深色模式下舱体/发送钮/置灰态正常，无穿帮白底
- E11: AX5 档输入文字无裁切，超 6 行内部滚动
- E12: 贴底状态下舱体长高全程，最新消息保持可见（钉底不跳）
- E13: 承接条出现在舱顶、下方 0.5pt 分隔线，舱高增量 ≤50pt
- E14: iPad 宽屏舱宽 ≤720 居中，行数上限与 iPhone 一致

## 现状问题备案（方案已含修正）

1. **图片/麦克风 36×36 热区低于 44pt 最低标准**（§8.1），误触率高——C2 修正。
2. **TextField 上下内边距 9/7 不对称**，命中 §8.7 第 4 类「上下不一致」——改 10/10。
3. **设计规范 §8.2 与已拍板一体舱冲突**：§8.2 写「背景 holoCardBackground + HoloRadius.md」，一体舱实际是 `holoSurface(.floating)` + `HoloRadius.xl`（原型即契约）。建议后续在 §8.2 注明聊天输入舱为拍板特例——文档口径问题，非代码 bug。
