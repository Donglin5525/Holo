# 一个发现 · 本机权威与服务端选题（修订稿 v3）

2026-11-08 · 第三稿。吸收东林第二轮拍板：**①文案由模型生成（本机模板只做兜底）；②一期七域确认；③每天最多一张，多出的存起来逐日展示；④在途线先收口；⑤拆旧与新做分版本走**。本稿在 v2 基础上重写文案生成设计（§5.2 填空制）、展示队列（§5.3）、版本规划（§8）。业务代码及线上配置未改。

> 架构主轴不变：**本机为主，iCloud 是唯一用户存储，服务端是无状态计算节点**（与聊天、记忆萃取同一模式：材料上送→模型计算→结果回本机→服务端即焚不落正文）。确认权威只有一个：本机+CloudKit。服务端不新建任何用户数据表。

## 1. 用户最终看到什么

用户照常记录。Holo 在后台整理记忆时顺带找出有依据、值得留意的规律，**每天最多给你看一条**——当天没有就老实说没有，多出来的存着，之后的日子逐条来。开启后「一个发现」随时可打开，有当天待看的卡时亮起。

| 用户看到 | 可以做什么 |
| --- | --- |
| 模型写的一句话标题+正文，讲清一个变化或重复模式 | 展开「查看依据」：记录日期、样本数、对照口径、例外，全部回本机原始记录 |
| 认可的规律 | 「对，记住」→ 写入本机知识库 → iCloud 同步 → 记忆中心出现同一条 |
| 有疑问或暂不想处理 | 「不太准确」撤下（可选填原因）；「先放一放」冷却几天再议 |
| 当天无卡 / 服务不可用 | 显示真实状态；断网或模型失败时，本地兜底模板卡照常可看，功能永不卡死 |

发现页不再有来源开关、手动重新整理、上次整理时间。数据授权留在 App 设置与系统权限。**所有确认、反馈、卡片历史只存本机，确认结果随 CloudKit 同步；服务端不保存任何一条。**

## 2. 架构总原则

业界对照（11-08 调研）：Day One 与 Apple Journal 把 AI 全放设备端（内容不出手机，但设备端模型挑不了题、写不了文案）；Craft 把「iCloud 存储」和「AI」做成二选一。Holo 用已在生产跑稳的第四种：**服务端=算完就忘的计算器**。

| 层 | 职责 | 存什么 |
| --- | --- | --- |
| 本机（CoreData） | 记录真源、确定性统计挖掘、观察池、展示队列、卡片与确认、敏感域全部内容 | 一切用户数据与派生态 |
| iCloud（CloudKit） | 同步原始记录与已确认知识 | 确认结果走知识库既有同步；观察池/队列等可重算中间态**不**同步 |
| 服务端（Hono/SQLite） | 选题+文案生成（一次模型调用）、异步任务、幂等与计量 | 仅任务状态（密文落存+取件后可焚，沿用 agent_cloud_analysis_tasks 模式）、幂等键（哈希）、计量账本 |

硬规矩：服务端日志与表**零正文、零金额、零健康数值**（拒因只留错误码，去掉旧 rawTail 300 字原文尾巴）。

## 4. 领域矩阵（一期七域，已核全集无遗漏）

全 App 模块清单核验（Views/ 目录逐个过）：任务、想法、财务、健康、习惯、对话（HoloAI）、目标、纪念日、事项（Matter）、档案（Personal）、日历/看板（任务时间视图，非独立记录源）、记忆中心/长廊（浏览层，非记录源）。聊天内的心情卡片属对话域。**一期七域=财务、健康、想法、任务、习惯、对话、目标，二期=纪念日、事项（补同套适配），档案只作上下文不作观察源——无遗漏。**

每域独立记录「有材料/已观察/暂缓/有结果」；某域缺材料、离线、无授权时其余照常。跨域结论（需双侧独立证据）放二期。

敏感路径：HealthKit 原始读数、健康派生正文、财务金额明细**不出本机**。选题上送清单是纯「形状」：域、命题类型、方向（升/降/对照）、窗口（几周）、计数（3/4 周成立）、新鲜度。**模型自始至终看不到任何金额和任何具体数值**——它是给句子填空的，不是看账本的。一期若法务口径对健康域形状描述仍从严，健康域降级本机选题，不阻塞其他域。

## 5. 一条链路怎么走

```mermaid
flowchart LR
    A["各模块记录+授权(本机)"] --> B["本机确定性挖掘+既有萃取"]
    B --> C["本机观察池(命题身份/跨链去重/时效)"]
    C -->|"形状摘要30条内,无数值无正文"| D["服务端:选题+写文案(一次模型调用)"]
    D -->|"选中ID+带空位文案"| E["本机回填真实数字→校验→入展示队列"]
    E -->|每日一张| F["胶囊亮起→用户判断"]
    F -->|对,记住| G["本机知识库→iCloud→记忆中心"]
    H["编辑/删除/撤权(本机)"] --> C
```

### 5.1 观察生产（本机）

记忆萃取后台窗口不动，确定性挖掘器挂同一次整理。产出统一入**本机观察池**：命题身份+域+时间窗+证据引用（本机 ID 与版本，可回源）+统计口径+计数+时效（如「四周对照」类观察默认 6 周过期）。同一底层记录经两条萃取链只计一次（命题身份+证据指纹去重）。

### 5.2 选题+文案：一次模型调用，填空制（本稿核心设计）

触发：后台整理产出新观察、或当日队列已空且池中有未展示未过期观察时，取「未展示+未过期+按新鲜度」的 top 30 条形状摘要，发起一次异步调用（创建即返、轮询取件、密文任务表、池指纹+当日键幂等防重复扣费）。输入带设备语言与「已展示命题方向」清单（避免连日同类重复）。

模型输出三样：**选中的观察 ID、角度枚举（变化/重复/对照/反常）、带空位的文案**（标题+正文）。空位制是文案准确性的根：

> 模型写：`最近{weeks}周里，有{matching}周你工作日的晚餐日均花销高于同周周末`
> 本机填：weeks=4、matching=3 → 用户看到真实的数字

**模型拥有句式、角度和灵性；数字、比例、日期全部是本机算好塞进空位的。** 模型手里的信息只有「形状」（几周、几周成立、方向），它想编也无处可编。护栏（服务端校验+本机复核双道）：

1. 空位白名单：模型只能引用该观察字段表里存在的空位，越界即拒；
2. 裸数字禁令：文案出现不带空位的数字（含中文数字）→ 拒因重试，修复层可把裸数字剥离；
3. 比例禁令：模型不得自己估算「将近一半/翻了一倍」，比例与倍数是本机算好的空位（如 {ratio_pct}）；
4. 方向一致：文案方向词（高于/低于/变多/变少）必须与观察 direction 一致；
5. 排版约束：标题≤14 字、正文≤80 字（卡片版式红线）；
6. 语气：与 HoloAI 聊天现行人称与语气一致，prompt 约束并纳入试评；
7. 三语：按设备语言生成，覆盖 App 现有三语。

降级：模型超时/格式坏/断网 → 当日卡改用本机兜底模板（挖掘器现成文案，无「精选」标识）并照常展示。**选题链路失败只是今天这张朴素一点，永远不会让功能卡死。**

### 5.3 展示队列：每天一张，多则存（东林拍板节奏）

- 选题成功的卡进入**本机展示队列**，按入选顺序排；每天（用户本地自然日）消费一张，次日有存货则胶囊再亮；
- 展示当日对队首卡做**时效复核**：观察过期或源记录已删改 → 跳过取下一条，绝不展示失效卡；
- 「先放一放」= 该观察冷却 7 天后重新入池；「不太准确」= 同命题永不重现（否定指纹），不连坐其他命题；
- 同一观察的文案在入选时生成一次并随卡存储，重复展示不重复调用、不重复计费；
- 队列无上限但观察自带过期，自然新陈代谢。

### 5.4 确认与同步（本机+CloudKit）

「对，记住」→ 本机知识库写入（在途线确认链路）→ CloudKit 同步 → 记忆中心同一条。多设备各自选题可能选出不同卡，但确认结果以先到 CloudKit 为准，后到的同命题自动去重——不需要任何跨端协议，这是权威回本机的红利。

### 5.5 失效与撤权（本机）

记录编辑/删除 → 源版本失效 → 观察池重算 → 队列中依赖它的卡即时撤下；撤权即停，派生数据随授权边界下线。一切在本机，即时生效，无服务端通知协议。

## 6. 模型风险护栏（选题+文案合一）

模型判断=选择题+填空题：事实由挖掘器算死，模型挑哪条值得看、用什么句子讲。它物理上编不了数字（不在输入里）、编不了记录（没有原文）。在此之上沿用两晚事故沉淀的流程纪律：

- 输出格式自检清单+确定性修复层（qwen 对 checklist 遵从好，prompt v4-v6 已验证）；
- 模型路由切换必须重跑真实材料试评（grant 漂移、qwen citations 两次实锤的纪律）；
- 真实材料全链试评先行（合成 18/18 与真实 25% 落差有前科），试评材料用东林真机数据的脱敏形状；
- 预算：独立 purpose 沿用发现已拆的 ¥1/日 ¥5/月池，一天最多一次调用+失败重试有限次，qwen 单次厘级，无预算风险。

## 7. 架构决定

| 决定 | 选择与代价 |
| --- | --- |
| 权威在本机，服务端无状态 | 代价：断网无选题（兜底模板顶上）；换来零服务端用户数据、零双权威协议、零迁移 |
| 观察池/展示队列不上 CloudKit | 可重算中间态不同步；代价：每台设备自己积累，首开几天才有货（与现状一致） |
| 文案模型生成+空位回填 | 灵性与准确兼得；代价：一次额外模型调用（厘级）+双道校验代码 |
| 复用 CloudKit 知识库同步确认 | 零新增部署 |
| 复用服务端任务/幂等/计量三件套 | 选题+文案端点是唯一新服务端工作；不新建用户数据表 |
| 旧链路整体退役，无兼容窗口 | 旧发现零产出史，无用户损失；回退=env 重开 |

## 8. 版本规划（东林提议的分版拆除，可行，排法修正如下）

东林提议「1.1.5 拆旧、1.1.6 做新」。**方向可行，但 1.1.5 这个号已被门禁急救包占用**（1.1.5(37) hotfix 针对 1.1.4 商店门禁事故，线上正在伤真实用户）。修正排法：

| 步骤 | 时点 | 内容 | 说明 |
| --- | --- | --- | --- |
| 0. 服务端关闸 | **立即可做，不等版本** | env `HOLO_DISCOVERY_ENABLED=false` | 旧包（1.1.3/1.1.4）优雅关闭发现入口，立即停止空跑烧钱（每次 60-150 秒模型调用是真金白银）。这是设计好的 kill switch 语义，零风险。**需后端发版（env 变更走 deploy skill）** |
| 1. 1.1.5(37) hotfix | 若未传 ASC 尽快传 | 只含门禁修复，**不掺拆旧** | hotfix 要小而快；拆旧动 20+ 文件会放大审核与测试范围。若已传则跳过此行 |
| 2. 在途线收口 | 1.1.6 线内先行（半天） | 「发现×知识联动」11 文件：三新文件挂 pbxproj→发现套件测试绿→单独提交 | 确认层底座先落库，再动拆除，防卷带 |
| 3. 1.1.6 = 退役版 | 当前分支 | 拆旧发现约 20 文件（Coordinator/Client/Scheduler/Retriever/Models/UI 等，-数千行）+ 每周回顾等已提交内容 | 拆除后线上出现功能空窗：发现入口消失（零产出史=零损失）；本地旧 discovery 库留档不清理（不删用户数据红线）；在途线的新评审页/挖掘器保留 |
| 4. 1.1.7 = 新版 | 退役版上架后 | 观察池+展示队列+服务端选题文案端点+确认闭环 | 独立版本线专注新做，不被 1.1.6 积压内容拖慢 |

升级路径：老包用户 1.1.3/1.1.4 →（服务端已关闸，功能静默关闭）→ 1.1.6 无发现 → 1.1.7 新发现自然接管。

## 9. 实施与验收

**阶段 0**：服务端关闸（§8 步骤 0）+ 在途线收口提交。
**阶段 1（后端 1-2 天）**：选题+文案端点（模型调用、空位校验、修复层、密文任务、幂等、计量）+ 契约测试（跨端接口契约规范管辖，双端夹具对拍）。
**阶段 2（客户端 2-3 天）**：观察池+展示队列+各生产器接入+跨链去重+空位回填与双道校验+胶囊。
**阶段 3（1-2 天）**：确认闭环（本机+CloudKit+记忆中心）、冷却与否定、失效撤卡、拆旧收尾。

**真机验收（放量前，两个率分开统计）**：
- 链路完成率：真实记录 → 挖掘 → 选题返回 → 回填校验 → 队列 → 当日卡亮起 → 确认 → 记忆中心同条 → 第二台 iCloud 设备同条。断网兜底、杀 App 恢复、重试幂等无重复扣费、失效卡跳过各一遍；
- 有价值产出率：真机一周，周均出卡数、确认率、否定率（metadata 统计）。目标值首周数据后定，先验收「每天至多一张、有卡必可核对依据、文案数字与依据完全一致」；
- 服务端抽检：新端点日志与表零正文零金额零数值；
- 必测场景：财务一条、健康一条、其他域一条、连续多日队列逐日出卡、无发现态、断网兜底模板、旧包升级接管。

**红线**（全部沿用）：CloudKit 开发库禁重置；引用逐字可溯源；撤权即停派生下线；预算独立分池；后端发版只走 holo-backend-deploy；真机验收前核对 UA build 号；模拟器无头跑。
