# Holo 记忆管理：可追溯性与有效性复盘

日期：2026-10-28。起点：东林反馈每条记忆看不到来源依据，无法评价质量；虽然记录很多，但缺少有用信息。

后续完整修改建议已形成：[Holo记忆与上下文重构方案v3.3最终实施交接](2026-10-28-Holo记忆与上下文重构方案/08-最终实施方案与GLM交接.md)，已融合GLM补充、现状适配及最后顺序对抗自审，区分首版闭环与后续增强。本复盘继续保留作为问题证据，不代表修改已经实施。

本文是对当前工作区的产品复盘和验收补充，不替代 [10 月 27 日 v2.2 通用方案](2026-10-27-Holo记忆从碎片到规律的产品与实施方案.md)，也不另起一套存储架构。本轮新增本文，未修改业务代码、真实记忆或 CloudKit 数据，未部署后端。审查包含尚未提交的实现，不能据此判断日用设备安装包已经具备哪些能力。

## 1. 产品结论

当前问题横跨三个层次：

1. **信任不足**：记忆里的来源 ID、摘要、统计快照，没有完整转化为用户能核对的依据；部分来源说明还会误导。
2. **信息增量不足**：流水、阶段观察、用户陈述和行为归纳仍混在不同入口中展示；有的内容是真的，但不值得长期记。
3. **收益无法证明**：已有引用提示和使用计数，却没有充分区分候选被检索、被传入模型、回答明确引用、实际帮助用户。

验收不能再止于“萃取成功、写入成功、列表能看、引用数增加”。每条对外称为记忆的内容，应能回答：**依据是什么、依据是否支持这句话、为什么值得保留、适用到什么时候、曾帮助解决什么问题、用户如何改变它。**

不能为了给用户更多卡片而降低准入，也不能靠把候选全部隐藏或拒绝来制造“质量变好了”的假象。记忆数量下降可以是正常结果，但必须同时验证有价值信息保留、可检索、能用于相关任务。

## 2. 当前发现：影响 → 调整决定 → 代码依据

### 2.1 来源有字段，用户仍核对不了

**影响**：看到“财务记录”“习惯记录”和日期，并不能知道具体哪些记录支持结论。统计类记忆尤其容易变成“相信 Holo 算过了”。

**调整决定**：单条来源展示原文或业务记录；统计来源展开计算口径、时间窗、样本与分母、缺失、比较对象，并能查看组成记录或回到原模块核验。健康等受限来源保留本机核验路径，不为追溯复制或外发原始健康数据。形成时依据与当前来源分开呈现，明确来源已修改、已删除、已撤权、暂无法核验。

**代码依据**：

- `Views/MemoryGallery/HoloMemoryRecordDetailView.swift:159–176`：`aggregateSnapshot` 仍是纯展示，不能展开核对。
- `Services/AI/MemorySignals/FinanceMemorySignalBuilder.swift:173–184`：聚合证据保留摘要性定义、时间窗、样本数和摘要哈希，没有在该证据中保留可展开的组成记录清单；数值事实在信号里，而用户来源行没有完整展示它们。
- `Views/MemoryCenter/HoloMemoryCenterDetailView.swift:293–330`：有可路由目标时可跳转；所有无目标来源统一写“汇总类来源，无单一出处”。
- `Views/MemoryGallery/HoloMemoryEvidenceRouter.swift:14–30`：只支持一部分证据种类与领域的直接跳转；对话用户陈述等无目标，不代表它真是汇总。

因此不能笼统说当前完全没有来源功能，也不能以“补了跳转”宣称追溯已经完成。

### 2.2 来源类型和形成方式混淆，可能把推断说成用户亲口表达

**影响**：用户无法区分“我说过”“记录里发生过”和“Holo 根据记录猜的”。这直接影响归因与确认是否有意义。

**调整决定**：来源载体与形成方式分别记录、分别展示。任务记录可以是证据，但不是用户在聊天里说过的话；用户原话也需要核对主体、否定、条件和时效。仅有来源引用，不等于结论被支持。

**代码依据**：

- `Services/AI/PersonalContext/HoloPersonalContextExtractor.swift:593–607`：个人情境的各域依据统一构造成 `explicitUserStatement`，不在这里区分其语义是 declared、observed 还是 inferred。
- `Views/MemoryGallery/HoloMemoryRecordDetailView.swift:242–244`：看到该证据种类，就解释为“你在对话里明确表达过”。
- `Services/AI/Knowledge/HoloKnowledgeSourceVerifier.swift:61–69`：`explicitUserStatement` 直接核验通过；这无法证明它仍有可核对的原始依据。真正独立保存的用户纠正应有自己的来源身份，不能和从业务记录抽取的片段混为一谈。

### 2.3 “值得记”仍缺少可解释的具体用途

**影响**：“你有某个习惯”“你记过一笔开销”可能都正确，却没有比原模块多提供理解；用户被迫管理大量重复摘要。

**调整决定**：保留三类信息：用户明确表达的重要事实/偏好/约束、与原模块关联的当前情境、有充分依据且经确认的行为规律。每条自动提炼的内容必须说明一个具体未来用途，例如影响安排、避免重复追问、在某个条件下调整建议。没有增量价值的流水留在原模块；重要单次事件可以保留，不要求重复出现。

**代码依据**：

- `Services/AI/MemoryCore/HoloMemoryActivationPolicy.swift:17–53`：已有 usefulness 过滤，但主要按部分血缘前缀、样本数和文本词组排除已知坏例，无法覆盖通用的低价值摘要。
- `Services/AI/Knowledge/HoloKnowledgeAdmission.swift:22–76`：有来源、结构、权限、形成方式等门槛；“未来具体作用”写在注释目标中，但准入尚没有相应具体判据。
- `Views/MemoryCenter/HoloMemoryWorthConfirmingSection.swift:100–110`：用途仍是通用文案“作为背景理解，给带限定的建议”，没有告诉用户这一条具体会改变哪种帮助。

具体用途应是可评审的语义与场景，不再新增一个没有解释力的模型分数。

### 2.4 规律准入要求与供给链脱节，记录多也可能没有成熟理解

**影响**：表面上系统持续积累，实际上候选无法达到成熟门槛；继续增加记录或要求用户逐条确认，都不能补上这个断点。

**调整决定**：让产生者真正提供所需的独立事件、机会分母、覆盖、对照窗口和反例检索结果。不能伪造缺失指标来通过门槛；积累不足时明确说不足。每个首发规律模板至少用一个有真实结构的隔离正例贯通，再用反例检验。

**代码依据**：

- `Services/AI/Knowledge/HoloKnowledgeIngestion.swift:107–133`：旧记录桥接的 `coveragePercent`、`holdoutValidatedPeriods` 固定为 nil；跨域无反例列表时直接标成 `searchedNoneFound`，未保留“是否实际查过”的证明。
- `Models/AI/HoloKnowledgeResolution.swift:207–235`：周节奏、窗口变化、跨域关联模板要求覆盖率，跨域还要求独立验证周期。
- `Services/AI/Knowledge/HoloKnowledgeAdmission.swift:102–120`：缺少这些值时留在内部。这条旧记录桥接路径不能靠增加同类记录自然满足覆盖门槛。发现侧有另一个证据构造路径，不能据此断言所有入口都没有产出。
- `HoloKnowledgeIngestion.swift:109–113` 用样本数与血缘数的较大值作独立事件数；而 `MemorySignals/HabitMemorySignalBuilder.swift:34–44` 的样本数是总天数。总天数不能直接充当实际发生的独立行为次数。

### 2.5 管理入口标准不一致，用户看到的数量与质量取决于入口

**影响**：新中心开始收敛碎片，长廊仍可能显示另一套候选和旧记录。用户无法形成稳定理解，也无法判断“正在使用”到底按什么标准计算。

**调整决定**：长廊、独立记忆中心、引用详情、确认与编辑共用同一个最终投影；页面只决定展示方式。主界面展示已记住与少量成熟候选。历史、停用与未成熟数据可以检索管理，但不在主界面铺成工作队列；隐藏不等于删除。

**代码依据**：

- `Services/AI/MemoryRepository/HoloMemoryManagementReadService.swift:109–118`：新中心排除 `autoLowValue` 和 `autoInferenceUnconfirmed`，成熟候选另走知识投影。
- `Views/MemoryGallery/DomainMemorySection.swift:801–831`：长廊读 `.all`，走 `HoloMemoryUserVisibility`，未沿用上述分流。
- 同文件 `392–425` 仍以旧状态做领域、候选和归档分组；组内最新更新时间还影响领域顺序，更新频繁不等于对用户重要。

既有 `2026-10-28-记忆长廊模块体检报告.md` 记载过 2512 条记录，其中 1682 条为过去/归档、635 条观察中、195 条正在使用。本轮未重新查询真实数据库；这些数字只能作为已有报告的历史观察，不能解释为有 195 条有用记忆，更不能作为本轮效果结论。

### 2.6 “引用了记忆”存在误归因，无法据此评价收益

**影响**：回答里出现同一个词就可能被标成引用。用户据此评价记忆质量，会混入没有发生的功劳，甚至把违背记忆的建议算作使用。

**调整决定**：区分检索到、进入上下文、回答声明引用、可核对的具体引用、用户认为有帮助。词语重合只用于诊断候选，不能直接显示为已证实的引用。模型返回的引用也需与具体结论及获准使用的记忆版本对应，不能视为因果效果的证明。

**代码与实测依据**：

- `Views/Chat/ChatViewModel.swift:3987–4010`：模型未返回引用标记时，用内容重合补出引用并记录使用。
- `Services/AI/HoloMemoryAttributionReconciler.swift:38–44`：任一不少于两个字的片段重合即可命中。
- 本轮用原文件与 `/private/tmp/holo-memory-attribution-review-20261028.swift` 编译运行的两个隔离反例，均被标成引用：

| 记忆 | 回答 | 实测 |
|---|---|---|
| 我周末会去游泳 | 周末可以安排一次室内阅读。 | 返回该记忆 ID，只因“周末”重合 |
| 我不游泳 | 你可以去游泳。 | 返回该记忆 ID；没有识别否定语义 |

这证明该兜底不能作为可靠引用判据，不证明所有模型主通道引用都错误。

### 2.7 历史引用展示当前记忆，事后无法准确还原

**影响**：记忆后来被纠正，旧回答展开时却显示纠正后的内容，用户无法判断当时为什么会回答错。

**调整决定**：引用绑定当时的语义修订、证据快照与回答位置。详情可以提示已有更新，并分别查看当时依据与当前理解。用户遗忘或撤权的内容按控制规则清除或遮蔽，历史可追溯不能成为永久保留个人正文的借口。

**代码依据**：

- `Views/Chat/ChatViewModel.swift:3474–3477`：气泡载荷保存引用数量和记忆 ID。
- `Views/Chat/MemoryAttributionBadge.swift:90–98`：按 ID 获取当前 `HoloMemoryRecord`，没有按回答发生时的版本还原。

### 2.8 评价体系偏生产和检索，缺少用户收益的证据

**影响**：命中率增加、使用数增加，可以伴随无关信息更多。低纠正率也可能只是用户懒得逐条检查。

**调整决定**：将“证据可核验、结论受支持、信息有增量、相关任务确有帮助、纠正持续生效”作为验收主轴。保留工程指标作为诊断，不把它们替代产品成功。

**代码依据**：

- `Services/AI/MemoryDiagnostics/HoloMemoryQualityMetrics.swift:10–36`：现有指标侧重产生、拒绝、检索、反馈、延迟和落库。
- `Services/AI/ReportUnderstanding/HoloUnderstandingContextBuilder.swift:81–86`：进入背景投影就计一次使用；与聊天引用后记使用的含义不同。

## 3. 每条记忆的产品契约

用户应能从一条记忆展开以下内容。主卡只露结论、形成方式、简短依据与适用范围，其他内容按需展开，不把管理页变成诊断面板。

| 用户问题 | 产品必须提供的答案 |
|---|---|
| Holo 到底记住了什么？ | 一条可独立判断的明确陈述，保留否定、条件、主体与时间，避免一句话夹多个结论 |
| 是我说的，还是 Holo 推断的？ | 你明确告诉的 / 来自当前关联记录 / Holo 提出且你确认的理解 |
| 根据什么？ | 原话片段及来源、业务记录、或可核验的统计；形成时来源修订与当前状态 |
| 证据真的支持吗？ | 结论与依据的对应、反例与覆盖不足；相关性不能升级为因果或人格判断 |
| 为什么值得记？ | 对某类未来任务的具体影响；单纯复述不算增量 |
| 现在还适用吗？ | 适用条件、有效期、最近支持/核验状态；观察窗口不等于结论有效期 |
| 帮过什么？ | 可打开的相关回答/规划与所用版本；没有可证明使用时如实显示，不能声称没价值 |
| 我能怎么改？ | 区分来源错、理解错、现在不适用、暂停使用、遗忘；说明生效范围和可撤销性 |

以下为说明产品结构的虚构示例，不是对东林真实生活的判断：

> **你希望周末尽量不排工作任务。** 形成方式：你明确告诉 Holo 的。
>
> 依据：10 月 20 日对话原话“周末我想留给家人，工作尽量排在工作日”。可定位到这句话及上下文。
>
> 适用范围：工作任务的安排建议；明确指定周末的紧急事项由你决定。持续到你修改。
>
> 用途：做一周计划时，优先安排在工作日。最近一次相关引用：某次一周计划，可打开核对。

行为规律采用同样结构，但必须显示真实的观察、分母、反例和不确定性，并在持续使用前确认准确命题。统计事实不要求用户替系统认证算术；确认的是对生活的解释与适用范围。

## 4. 调整顺序与取舍

这些是产品交付包，工程依赖仍沿用原方案 W0 → W1 → W2/W2D/W4 → W3 → W5。没有通过隔离迁移与发布验证前，不在日用数据上直接开放新写入。

| 顺序 | 交付内容 | 通过标准 |
|---|---|---|
| P0 可信 | 修正来源类型/提示；统一最终投影与核验；让单条与汇总依据可查；移除词重合即认定引用 | 每条对外记忆都可核验，或明确标为无法核验并限制使用；两个归因反例不再冒领 |
| P1 有用 | 落实具体用途与信息增量；收敛同一命题；补齐模板证据供给；历史低价值记录分流 | 正例能形成有用理解，反例不过关；不能靠全拒绝/全隐藏通过；主界面不再铺候选和历史 |
| P2 可归因 | 在实际问答/规划中显示有依据的引用，绑定当时版本；来源变更与纠正传播到全部消费入口 | 同一问题能解释用了什么、为何相关；纠正后不再沿用旧理解；旧回答不偷换成新版本 |

决策记录：

- **D01：复用统一知识与证据链。** 多个入口不能各自决定真假和可用性；代价是需要同时替换旧展示与消费入口，而不只是改一个详情页。
- **D02：主记忆强调少而有用。** 原始记录与历史仍保留可管理性；代价是主界面数量可能明显下降，必须用真实收益而非数量解释改进。
- **D03：引用精确性优先于引用数量。** 无法核对时不冒领；代价是短期可见引用量可能下降，但用户评价会更可靠。
- **D04：优先贯通高价值场景。** 先验证明确约束参与规划、可靠规律参与建议；不为追求“洞察感”强行制造跨域因果。其他领域从第一批就采用相同来源与准入规则。

## 5. 如何判断这次真的变好

不再新增一套仅看通过率的工程验收。沿用既有 99 场景矩阵，补充以下可人工复核的产品证据：

1. **逐条质量抽样**：从八域、各种形成方式、历史/新记录中分层选至少 30 条经授权或隔离合成的样本，列出结论、来源、支持/反证、增量用途、有效期、当前状态。成熟候选不足也保留原分母，不能只挑最好的。
2. **相关任务对照**：先冻结至少 10 个确实需要个人背景的问题，以同一批基础数据和条件比较有/无合规记忆的结果，评审是否少了重复追问、避开明确约束、改善安排、保留事实准确性。记录退步与无差异，不预设胜率。
3. **检索与失效反例**：有用记忆必须能按用户表达找到；无关记忆不得硬塞。覆盖来源修改/删除、撤权、过期、否定、转述、用户纠正、停用、晚到同步和恢复。
4. **端到端归因**：从回答的具体建议，回查当时的理解、支持依据和来源状态；从记忆也能回看相关使用。语义或证据改变时不能误用旧确认。
5. **控制与负担**：确认/修改/停用的结果跨入口一致；用户无需清理成百候选；历史管理仍可达。纠错需要几次操作、是否再次犯同样错误，单独记录。

新增抽样规模是本轮建议的起步评审规模，不是统计学质量保证，不取代真实设备、多设备和迁移发布门槛。评估数据不自动上传，不新增强制评分或用户每天清空的确认任务。

产品交付应附一份“样本结论—原始依据—具体用途—实际使用—控制结果”的证据表。构建成功、单元测试通过、页面顺滑都不能替代它。
