# 记忆长廊减法设计

2026-11-13 · 产品评审稿 · [交互原型](holo-memory-gallery.html)

## 产品决定

保留「记忆长廊」的名字和现有入口。打开就看见最近留下的一条记录，向下走到更早的日子。时间只有一条主线，月份划分章节，日期落在左侧细线上，记录沿右侧展开。

当前首屏把「我的积累」、日历／洞察、日／周／月／轴和多个日期控件叠在一起。页面在同时服务回看、排日程、看成就、查看 AI 的理解四件事。这轮把长廊专门留给「我哪天写了什么、做了什么」。首屏也收掉 11 月 8 日评审稿中的周回顾主卡，第一屏的空间优先给用户留下的内容。

## 怎么逛

| 用户想做什么 | 页面如何回应 |
|---|---|
| 随手翻一翻 | 进入后定位到最近有记录的一天，首屏可以接着看见更早的一天。只陈列有记录的日期，向下连续跨月。时隔几周回来时，开场就是最后一次真实记录的日期。 |
| 看那天还发生了什么 | 每天先露一条。两条以上才出现「当天 N 条记录」，点后在这一天原地展开其余记录。同一时间只展开一天。 |
| 找某个具体日期 | 右上角「找日期」打开轻量月历。点年月可以快速跳转，实心小点表示有记录。点一天直接回到长廊中的那个日期，多条时自动展开。定位到空白日期时保留这个日期，给出「去最近有记录的一天」。深翻后可「回到最近」。 |
| 核对记录 | 点想法、账单、打卡或完成事项，进入对应记录详情。关掉详情回到原日期和原展开状态。图片和文字指向同一条原记录。 |

首屏示例是「11 月 13 日」的一张咖啡照片和一行原文「下次路过，还是想坐窗边。」接下来是一行完成事项，再往下是更早的日期。只有一笔地铁账的用户，看到的就是日期、地铁和金额，页面高度由这条记录自然决定。原型中的图片来自 Holo 已有演示素材，文字和记录为示例。

## 哪些功能撤出长廊

| 现在的功能 | 处理 |
|---|---|
| 日回放、日／周／月／轴档位 | 日回放并入长廊展开。月历只做日期定位。七天并排网格退役，接受失去并排查时间块的能力。 |
| 轴档的任务拖拽、创建与系统日程 | 迁入任务日程。先在任务内验收同轴展示、创建、调整时间和原通知的目标，再撤掉长廊轴档。 |
| 「我的积累」常驻卡、成长里程碑 | 统一从个人页「我的积累」看，继续使用已有的统计和里程碑来源。 |
| 每周回顾 | 继续从个人页及现有通知进入。长廊首屏和章节中只放按日发生的记录。 |
| 洞察页、记忆待确认和报告入口 | AI 记忆及待确认去记忆中心，「一个发现」和报告从 HoloAI 进入。旧的「查看新记忆」链接逐一改到对应记忆或待确认。 |
| 热力图、每日感知、计划台账、精选故事等展区 | 撤掉独立区块。计划从原对话、任务或目标看。可核对的精选片段由其原记录所在日期自然呈现。 |

## 版式与取数规则

- 页面沿用 Holo 米白底、深灰文字、20pt 边距和深浅色语义色。月份和原文摘句使用长廊既有的衬线气质，金额、模块和时间沿用系统字。橙色用在当前日期、定位和操作上。连续内容用留白和细线分隔。照片仅在原想法有附件时出现。
- 每天优先露带照片的想法，其次有原文的想法，再其次最近一条实际记录。同一优先级按时间及稳定记录身份排序。其余记录按可靠时间倒序，只有日期的显示「当天」。标题为原文摘句或已有记录标题。无需调用 AI 生成开场内容。
- 沿用目前日回放的四类来源和时间规则。记账用业务日期，打卡用发生日，任务用完成时刻，想法用原记录日期。系统日历和未完成的计划留在日程。统计条数来自去重后的当天记录，照片和引用从属于原想法。更新、撤销或删除后重算该天和月历标记。
- 首屏按日期分批加载，用日期索引跳转到历史月份，继续在两侧翻阅。按需读取可见的附件缩略图和展开的原记录。首屏读取、滚动、回到原日期分别验收，避免复现旧长廊一次准备大量视图的问题。
- 点击热区至少 44pt。大字体下日期和正文允许自然换行，日期选择器标记同时提供旁白中的记录状态。焦点在选择日期后到该天，关闭原记录后回到入口。原型沿用 Holo Tool 基础色，操作文字在浅底用较深的橙色保证可读性。

## 稀疏、缺失与恢复

| 状态 | 页面表现 |
|---|---|
| 只有一天／一条 | 直接显示该条，无展开控件、空照片框或空月份。 |
| 初次加载 | 显示正在读取。能显示可信本地记录时保留它们，顶部轻提示同步。 |
| 全部来源确认无记录 | 显示一条说明及「写条想法」，接入既有编辑器；新增记录后更新该日期。 |
| 部分或全部读取失败 | 有可信内容时继续显示，标明暂缺的来源并提供重试。无可信内容时显示加载失败和重试。日期索引随可用性显示，未知日期状态用「暂无已载入的记录」。 |
| 打开详情时原记录已失效 | 详情说明原记录已无法查看，返回当天，并撤下失效的预览或计数。 |

## 原型评审与实施验收

建议用原型走三次。先点首日的「当天 3 条记录」和一条原记录，看看展开是否打断阅读。再用「找日期」翻到 10 月 28 日，看完原记录后回到最近。最后切「只有一笔账」和「还没有记录」，检查首屏是否仍然知道自己在长廊里。外侧可切换同步、错误和深色样式。

进入原生实现后，先验证历史日期、密集日期、跨月回滚、来源失效和原记录返回锚点，再验旧入口改接和任务轴迁移。上线判断用有记录用户的自然复访和指定日期查找用时，配合点击后的原记录到达率。当前交付是浏览器原型和产品方案，原生体验与性能留待实现后验证。
