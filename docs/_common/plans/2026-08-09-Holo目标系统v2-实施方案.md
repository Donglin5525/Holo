# Holo 目标系统 v2 — 实施方案

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking. 按三期顺序执行，期内有依赖。
>
> 配套产品设计：[2026-08-09-Holo目标系统v2-主线化方案.md](2026-08-09-Holo目标系统v2-主线化方案.md)
>
> v1 基础：[2026-05-17-Holo目标系统v1实施方案.md](2026-05-17-Holo目标系统v1实施方案.md)

**目标：** 让"目标"从挂件变成贯穿 Holo 的主线——目标能被手工创建和编辑、能被 AI 读写、AI 无论哪条链路都稳定感知目标、用户在日常和今日看板持续感知目标、AI 会主动围绕目标牵引。

**架构：** v2 在 v1 的 Core Data 程序化模型上扩展（新增 `proactiveNudge` 字段，镜像 `allowAIContext` 的定义模式）。Goal 与 TodoTask/Habit 的双向关系 v1 已建好，v2 只读取不改数据模型。AI 写目标接入旧 `IntentRouter` 体系（新 Agent 工具系统是纯只读，不在其内造写能力）。今日看板通过复用 v1 的关系字段 + 新查询方法实现关联。

**技术栈：** SwiftUI、Core Data programmatic model、Repository 模式、HoloAI IntentRouter + Agent 工具体系、xcodebuild。

## 重要架构发现（影响功能 2）

v2 调研发现一个必须事先明确的事实，直接决定功能 2 的实现路径：

**Holo 有两套并行的 AI 系统：**

| 系统 | 路径 | 写能力 | 目标现状 |
|---|---|---|---|
| **旧意图路由（IntentRouter）** | `Services/AI/IntentRouter.swift` + `ConversationCoordinator.swift` | **有**（createTask / recordExpense / checkIn 等） | 完全缺席（AIIntent 无 goal 写意图） |
| **新 Agent 工具（HoloDataTool）** | `Services/AI/Agent/Tools/` | **没有，纯只读**（10 个工具全是分析） | 已接入（HoloGoalTool，但只读） |

**含义：** 功能 2「AI 能在对话中改目标」不能简单地给 `HoloGoalTool` 加写方法（那套系统没有写工具的范式）。正确路径是在 `IntentRouter` 里新增 goal 写意图（如 `update_goal_field` / `link_task_to_goal` / `toggle_goal_visibility`），这是建任务/打卡的同款机制。

**因此功能 2 涉及后端发版**——意图识别的 prompt 配置在后端 `defaultPrompts.json`，新增 goal 写意图需后端同步识别规则。详见 Task 9/10。

**功能 2 的歧义处理（关键产品决策）：** 当用户说"把目标延期"但有多个目标时，**不能照搬打卡的纯文本反问**（用户很难在第二句精确复述）。现有代码里只有"待确认卡片"机制（`ConversationCoordinator` + `confirmationStatus`，目前只服务于 createTask / finance）是成熟的反问-回执闭环。功能 2 必须复用这套机制：多目标时渲染一张待确认卡片让用户点选 + 编辑新值，而非纯文本反问。`LinkedEntityType.goal` 枚举值已预留（AIModels.swift L78-86），但目前从未被使用。详见 Task 9/10。

数据层（`GoalRepository` 加 update 方法）是纯客户端工作，一期就做。

**Files:**

**模式参考：** 所有 mutator 统一四步——赋值 → `updatedAt = Date()` → `context.save()` → `loadGoals()`。直接照抄 `updateAIContext`（L89-94）。

- [ ] **Step 1: 加 updateFields（多字段批量更新）**

这是本文件首个多字段 mutator（现有只有单字段 `updateStatus`/`updateAIContext`）。在 `updateAIContext` 后加：
```swift
func updateFields(
    _ goal: Goal,
    title: String? = nil,
    summary: String? = nil,
    domain: GoalDomain? = nil,
    desiredOutcome: String? = nil,
    motivation: String? = nil,
    deadline: Date? = nil,
    proactiveNudge: Bool? = nil
) throws {
    if let title = title { goal.title = title }
    if let summary = summary { goal.summary = summary }
    if let domain = domain { goal.goalDomain = domain }   // setter 自动 bump updatedAt
    if let desiredOutcome = desiredOutcome { goal.desiredOutcome = desiredOutcome }
    if let motivation = motivation { goal.motivation = motivation }
    if let deadline = deadline { goal.deadline = deadline }
    if let proactiveNudge = proactiveNudge { goal.proactiveNudge = proactiveNudge }
    goal.updatedAt = Date()
    try context.save()
    loadGoals()
}
```
> nil 表示"不改这个字段"。注意 `goal.goalDomain` setter（Goal+CoreDataProperties L43-49）和 `goalStatus` setter 会自动 bump updatedAt，重复 bump 无害。

- [ ] **Step 2: 加 linkTask / unlinkTask**

```swift
func linkTask(_ task: TodoTask, to goal: Goal) throws {
    task.goal = goal
    goal.updatedAt = Date()
    try context.save()
    TodoRepository.shared.loadActiveTasks()
    loadGoals()
}

func unlinkTask(_ task: TodoTask, from goal: Goal) throws {
    if task.goal == goal { task.goal = nil }
    goal.updatedAt = Date()
    try context.save()
    TodoRepository.shared.loadActiveTasks()
    loadGoals()
}
```

**Files:**

- [ ] **Step 1: 新增 activeGoalSummaryMessage 静态 helper**

在 `buildPolicyContextMessage`（L1360）附近加，完全照其"可选返回"模式：
```swift
static func activeGoalSummaryMessage(now: Date) async -> HoloAgentMessage? {
    let goals = await MainActor.run {
        GoalRepository.shared.activeGoalsForAI(limit: 3)
    }
    guard !goals.isEmpty else { return nil }
    let lines = goals.map { goal -> String in
        let progress = GoalProgressEvaluator.evaluate(goal: goal)
        return "- \(goal.title)（\(progress.state.displayName)，\(progress.taskSummary)，\(progress.habitSummary)）"
    }
    let content = "## 活跃目标摘要\n\n用户当前正在追求以下目标：\n" + lines.joined(separator: "\n")
    return HoloAgentMessage(role: .system, content: content, /* metadata */)
}
```

- [ ] **Step 2: 在 startAnalysisJob 注入**

`startAnalysisJob`（L74-163）的 conversation 装配顺序（L130-150）：记忆 → 策略偏好 → 答案契约 → 用户问题。

**实现策略（开工时调整）：** 原计划复用 pending 卡片机制（`confirmationStatus` + `confirmPendingGoal`）。深入代码后发现，现有卡片系统是强类型的（每种卡片有专属 data struct + view + `ChatCardData` 枚举 case），加 goal 卡片要改 6+ 处分散的文件，风险高。**改为更务实的方案：直接执行 + 文本反馈 + 歧义时纯文本反问**，与现有 `handleCheckIn`/`handleCompleteTask` 的多候选歧义处理保持一致。
