# Holo 日常体验数据路由与工程接入

## 1 工程策略

这是既有产品的呈现改造。先定位当前源码与并行改动，再改最少的组件/只读查询。推荐新增的类型名可以按仓库风格调整；职责、状态边界、回执和验收不能省略。

默认不新增业务持久化实体，不做 Schema 迁移，不改变原记录日期和所有权，不因页面好看而调用 AI。若实施发现确需模型或后端变化，单列原因和兼容方案，不能在本包内顺手扩展。

## 3 想法内容投影

### 3.1 建议的最小结构

- `ThoughtListSection`：稳定 sectionID、日期或置顶类型、当前范围下有序的记录 ID。
- 原记录及正文渲染仍走既有 `ThoughtCardView`/内容子组件。若新增 `ThoughtFlowRow`，只抽呈现叶子，原标签/主题/附件/菜单回调原样注入。
- 明确将旧卡片样式用于哪些场景：分享、搜索引用列表等不一定一起去容器。不要全局修改 ThoughtCardView 后让所有调用点一起退化；可用一个明确的 presentation 参数或独立叶子实现，避免两个业务数据源。

分组过程仅处理当前已获得的值快照，不在 SwiftUI body 中遍历关系并请求 Core Data。图片和富文本解码继续使用已有缓存/叶子边界，不因一次菜单状态变化全列表重新解码。

### 3.2 刷新与定位

| 触发 | 数据处理 | 视口处理 |
|---|---|---|
| 自己新建并收到成功回执 | 查询/合并该 ID 的最新值，更新对应组与真实计数 | 用户刚完成新建时才定位这条，不为同步来的新记录抢滚动 |
| 编辑原条 | 更新原 ID；必要时依据当前 scope 移出 | 保留原位置或最近有效相邻项，不改创建日 |
| 删除/归档 | 沿原 Repository，成功后更新当前查询 | 空组移除；焦点给相邻行或空态主动作 |
| 云同步/自动整理 | 合并可信变化，不给每项庆祝 | 阅读中不强制滚顶；标签变化与排序原契约一致 |
| 查询/范围切换 | 有效请求替换对应结果 | 新范围有独立阅读现场；返回原范围可恢复 |
| 进入编辑器再返回 | 使用选中业务 ID 与稳定行身份 | 不能靠整棵 view 换 UUID 强制重建来“刷新” |

现代 SwiftUI 列表身份使用稳定业务 ID。禁止 `ForEach(enumerated())` 的 offset 作为最终稳定身份；当前已有引用 index 的分隔样式可保留，但记录身份不能随插入整体改变。

## 4 最近历史内容的真实查询

### 4.1 内容资格

近期预览只承接当前长廊已有的四类实际记录：想法、账目、习惯记录、已完成任务。沿各模块既有有效性、归档可见、父链与软删规则，不因为“归档”一词统一纳入/排除。自动导入允许纳入真实账务日期，但不能说成用户今天刚记下。

- 以业务日期决定是哪天，不用 `updatedAt` 把历史改动推成今天；补录也按归属日。
- 任务只创建/到期不等于已经做过；“最近留下的一段”不拿逾期事项充当完成事实。
- 当用户处于纯待办“到期”维度，本预览不适用，提供“切到完成记录”明确动作；不能静默改变 todoDimension。混合视图按已发生事件取最近，说明当前范围，保持用户既有安排视图。
- HealthKit、系统日历、相册、聊天全文不因最近预览额外授权或读取。时间轴既有授权下的日程能力保持，其安排不是本预览新增的数据源。
- 同模块重复 UUID 去重；跨模块身份使用 `(module, businessID)`。实体相等只比较 ID 不足以检测正文/金额变化，更新失效要靠来源修订/保存通知与请求版本。

### 4.2 最近日期算法

建议补 `GalleryRecentRecordResolver` 或在 provider 增加等价只读方法。它返回资格明确的结果，而不是一个可能把错误当空数组的 `[CalendarEvent]`。

1. 接受 `scope`（模块筛选、任务维度、数据可访问性）、`beforeDay`（不含目标日）、业务日口径和本次请求版本。
2. 对参与的模块各取最近一个合格业务日期。使用排序/limit 或等价索引查询，不逐天向过去循环 365 次，不为拿一条预览全量装载每条记录/图片。
3. 选这些日期中最晚一天。查询失败的模块必须显式标为 incomplete；不能证明全局最近时不标“最近”，可写“已加载记录中的一段”。
4. 只加载所选日的必要候选元信息，从该日按正文/图片、完成事项、习惯、账目次序选一个可读预览；同类型按真实时刻与稳定 ID 决定，选不到更换合法候选。
5. 来源时刻不可靠时只显示日期，不补造时分。预览正文直接截取原文，不用模型改写、不做 OCR/生成摘要。
6. 打开前复核记录是否仍有效；若已失效，移除当前预览并重查。关闭来源回到原日期和锚点。

已有 provider 仅支持范围查询时，可以新增“最近日期”轻查询并复用其有效谓词；不能直接将窗口扩大成从 1970 年到今天的全量附件读取。

### 4.3 展示状态

建议最小状态：`notApplicable`、`loading(previous?)`、`available(preview, completeness)`、`noEarlierRecord`、`failed(previous?, affectedModules)`。

`noEarlierRecord` 只在所有应参与查询成功且确实无合格项时成立。`CalendarDayPresentation` 尚未建立或窗口外未载入，不是 empty 的证据。保留上次快照时要及时撤下已删除/授权失效内容，不以“缓存稳定”绕过有效性。

预览值至少包含：来源模块、业务 ID/安全 origin 目标、业务日、可靠时刻（可空）、原文片段/事项、单位/金额语义、缩略图引用、当前范围与查询修订。对象快照不携带跨 context 的托管对象；大图不随 DTO 复制。

### 4.4 异步与刷新

查询身份建议包含 `(beforeDay, moduleFilter, todoDimension, permissionRevision, dataRevision)`。只接纳仍匹配当前身份的结果；Task 被取消后不写界面，跨 await 再核对。

- 进入今天空态时启动；切到有内容日期不再查；返回才按有效缓存决定是否刷新。
- 数据保存/删除/恢复/批量导入、同步可见变化、权限与业务日变化使相关结果失效。通知来源优先沿 provider/Repository 的真实保存通道，不只监听页面 .onSave。
- 新的最近查询不抢占首帧主线程。已有 CalendarViewModel 的首批取数/400ms 后预载/串行 pending 请求策略保持，必要时将轻查询合并到一次数据刷新，而非每个 View .onAppear 都重复请求。
- 只保留本次页面内必要快照，不为了恢复阅读位置新建持久化正文库；用户退出/撤权后按现有生命周期释放。
- Core Data 查询在其合法 context.perform 内；禁止把 NSManagedObject 直接送进 Task.detached 后访问。跨 actor 只传安全值或对象 ID，主线程更新 UI。

## 5 长廊连续章节与导航

### 5.1 保持连续河流

当前 DailyReplayView 以今天为上界，倒序章节，往过去在底部追加，每页 12 天，并维护 pendingInitialAnchor/scrollDrivenDate。保留这组约束。

本批改今天空章节的最小高度与 `DailyReplayRecentBridge`（推荐叶子名）即可。禁止将整天所有事件放回一个巨型 VStack；现有 LazyVStack 行与图片懒加载继续成立。若桥接条需要让下一章节进入首屏，按内容高度排版，不把另一段历史插到列表顶部再反复 scrollTo 补偿。

点击最近日期时：先校验目标业务日→确保该范围载入→让现有 `focusDay`/日回放锚定逻辑定位→保留从该日到今天的所有章节。用户往顶部仍可回今天。

### 5.2 路由上下文

对每条跨模块跳转保留：来源页面、scope、scale、focusedDate、可见行/章节锚点、必要的会话/编辑草稿。路由只携带 ID/日期/意图，不把原文作为导航参数传播。

来源解析继续走 `CalendarEventOriginResolver` 或 Discovery 当前来源路由。该解析器能到习惯详情不等于能到单次记录；显示层按实际能力标文案，需精确记录则先补最小日期意图。

单一 sheet/导航目的地状态负责呈现。关闭前后转场使用系统 dismissal/onDismiss/现有路由信号，不从网页复制“统一等 500ms 再开下一层”的时序猜测，不为聊天再加多层 .sheet 修饰符。

### 5.3 来源生命周期

| 状态 | 当前内容 | 允许动作 |
|---|---|---|
| 活跃有效 | 正常原文与当前实体 | 查看、按现有权限编辑 |
| 软删/父链已删 | 不再用其正文做当前预览 | 展示不可用说明，返回；不私自恢复 |
| 来源不在本设备/正在同步 | 依据真实状态说明 | 可重试/等待同步，不能伪称删除 |
| 授权已撤/AI 排除 | 清除受该授权限制的派生内容 | 普通想法仍可按本地读权限看；“不参与 AI”不等于从用户自己列表隐藏 |
| 编辑了依据 | 原始列表更新，发现按其真实失效服务处理 | 不继续以旧摘录声称新依据，不改用户原文来适配 AI 标题 |

## 6 聊天组件与栈预算

`ChatView.swift` 的结构已经多轮处理真机栈溢出。必须读 `quality-redlines.md`，尤其 §6：1800 行闸门、叶子拆分、禁止新增中间容器叠层、构造帧限重。

- 优先在已有 `MessageBubbleView`、输入器、QuickActionBar、Discovery 叶子中改样式。`ChatView` 只保留必要参数/状态/路由接线。
- 保留 ChatContentColumn、ChatMessageListPane、ChatNavBar 等已拆出的类型边界；不将它们重新内联，不新建层层包裹的 “NewChatContainer”。
- `showsAIHeader` 已存在。先核实分组调用点，再决定普通消息的视觉身份策略，不能盲设 false 后连发送者、错误/工具状态和 VoiceOver 都失去。
- 保存结果沿 `executionCards`/`ChatCardData` 及真实业务回执。消息历史快照与当前实体是两件事；链接解析更新，不能从历史消息覆写用户修改。
- 未取到原实体时合理显示不可用原因；不为美化卡片猜测 category/account/currency。
- 能力行新旧数量变化时不推开键盘或截断停止按钮；VoiceOver 顺序为内容→能力→输入→发送/停止。

## 7 Discovery 与独立记忆的集成约定

### 7.1 Discovery

使用现有 `DiscoveryService`、`DiscoveryCoordinator`、`DiscoveryContinuationBuilder` 与 UI presentation 模型。不得在新界面直接调用 Provider、重新扫描全库、复制 settings 键或另存“已读/否定”的并行状态。

UI 单独的“是否展开依据”允许本地管理；“功能启用/来源/当前发现/有效性/反馈落盘”由服务真源管理。关闭、撤权、来源缩小必须让当前详情和未发送上下文联动更新。

编写时发现服务/主链已经在途，性能费用与发版尚未最终验证。GLM 在 E0 记录实际 capability 和部署版本；服务缺失时展示真实不可用状态，不将本包新样式阻塞为“必须重写 AI 引擎”。

### 7.2 Holo 记忆

以 `../2026-10-23-Holo记忆管理独立与升级/02-拍板与冻结记录.md` 和对应方案为行为真源。此包不实现记忆写入/确认/停用/删除。对话顶栏保留其入口；统一设置的“管理记忆”接该目标，不再回到长廊重复管理。

两个项目都触及 ChatView/ChatViewModel/统一设置。实施前按职责建立文件协调表：谁拥有导航状态、谁提供业务服务、谁调整视觉叶子、谁验收真机入口。不能同时各自重写同一主视图后再整文件覆盖合并。

## 8 范围控制与回退

若项目已有内部 rollout 机制，分别接入想法内容流、长廊承接、聊天样式三个内部呈现开关；没有则使用最小内部策略，不新增三个用户设置。它们不控制授权、不控制业务写入、不控制记录数据迁移。

回退样式后仍可看到本期间保存的全部记录、原标签与日期；所有路由依然基于同一 ID。关闭新长廊呈现取消相应查询，不清原始记录。回退聊天样式不能恢复已关闭的发现或记忆权限。

## 9 性能与可访问性预算

| 关注点 | 实施与验证要求 |
|---|---|
| 首屏 | 同设备、同数据集对照改前改后；最近历史查询不阻塞首个可交互画面，记录可见延迟和失败重试 |
| 长列表 | 用 1000 条合成想法、200 张缩略图覆盖滚动；图片/富文本懒加载，菜单操作不触发全库重算 |
| 时间跨度 | 仅 180 天以前有一条记录时仍能定位；查询次数随参与模块/分页有界，不随空白天数线性增长 |
| 大字体 | 默认、AX 级别至少一个；正文可换行、44pt 热区、底部主动作可达。能力行可滚动而非缩字体 |
| 屏幕 | 窄 iPhone、常规 iPhone、iPad 横竖/分屏按项目支持档验证。大屏不把暖米底和全文拉成一条超长行 |
| 深色 | token 自动适配；正文/辅助字对比度达设计规范。图片不反色，不用运行时散落判断硬编码颜色 |
| 减少动态效果 | 到达/面板/切尺度可直接状态切换或淡变，信息与动作不丢失 |
| VoiceOver | 正文、图片数量、日期、来源、AI发言者、开关与展开状态完整；装饰线/圆点不单独抢焦点 |

性能门槛优先使用项目既有指标。无指标时 E0 先记录同设备可重复基线；不能在文档里预填“提升 30%”或“60fps 已通过”。

## 10 后端与发版

本批默认只动 iOS 呈现和本地只读查询。Discovery 项目已有后端改动，是否已部署必须单独核对，不能把本包文档交付视为生产生效。

任何实际涉及 `HoloBackend/` 的代码、Prompt、路由、依赖、配置或预算变化，都要明确提示：**后端改动需要发版/部署后端**。真正部署只在东林明确要求时，走 `holo-backend-deploy` 统一技能；本批不包含部署授权。
