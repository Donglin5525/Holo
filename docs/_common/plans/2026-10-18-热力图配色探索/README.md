## 第三轮判断：先解决递进，再选择色调

第一轮 A 的热力图缺少橙色，东林质疑品牌融合，已撤回首选建议。第二轮 D/E/F 仍被反馈「递进不足、感觉混乱」。此前只检查相对亮度单调，没有约束感知明度与颜色距离的步长；单调并不能保证相邻档位差距均匀。

第三轮参考成熟连续色阶和感知距离方法，以 G/H/I 与当前代码色值比较；前两轮保留在回看入口。

- G「品牌橙 · 均匀五阶」：固定品牌橙色相，有记录五档的 OKLab L 相邻间距约为 0.11；中档直接使用 #F46D38，随后逐步变深。等明度不等于完全感知等距。
- H「ColorBrewer 经典橙」：浅色有记录五档直接采用 D3 的 Oranges[5]；零值为本次独立补充。深色版是本次适配，不是官方色阶。
- I「清透橙 · 品牌收尾」：浅色五档从浅橙到品牌橙在 OKLab 直线上等距取样，不再进入深棕；递进跨度相对较小。深色版单独生成。

## 研究依据

1. [ColorBrewer 连续色阶说明](https://colorbrewer2.org/learnmore/schemes.html)：有序数量以明暗顺序表达。
2. [D3 连续色阶](https://d3js.org/d3-scale-chromatic/sequential)：可用连续插值或离散等级。
3. [D3 Oranges 原始色值](https://raw.githubusercontent.com/d3/d3-scale-chromatic/main/src/sequential-single/Oranges.js)：H 浅色的五档为 #FEEDDE / #FDBE85 / #FD8D3C / #E6550D / #A63603。
4. [Matplotlib 色阶设计](https://bids.github.io/colormap/)：关注相邻样本的感知差异及明度变化。本文借鉴其检查思想；G/I 不是 Matplotlib 官方配色，也不是 CAM02-UCS 验证结果。
5. [W3C OKLab / OKLCH](https://www.w3.org/TR/css-color-4/#ok-lab)：G/I 使用此类感知颜色坐标构造候选；超出 sRGB 时只降低彩度，不直接截断 RGB。

agent-reach 的 Exa 后端不可用，研究通过内置网页工具核对以上官方来源。

## 原型

打开同目录 index.html。第三轮默认展示规则递进测试数据，先看排序色阶，再切换日常 / 仅三天 / 密集 / 空数据。灰度对照辅助检查明暗，不等于色觉障碍模拟。三种场景：完成节奏 12 周、记忆活跃 13 周、记忆月历；深浅模式均可切换；选择日期在四组中同步。

固定演示数据不是用户真实记录。月历沿用既有五档（含零值），周网格六档（含零值），顶部色阶条按场景显示对应数量标签，不改变原统计规则。月历未复刻模块色条，仍需原生验证。

## 数值检查

以下只计算有记录的五档，零值作为独立中性背景，不强行参与等距。色值经 sRGB 八位量化，因此目标步长有微小误差。

已验证：180 组状态渲染逻辑和日期格数（轻量 DOM 替身，不是浏览器验收）、规则递进数据单调、第三轮颜色相对亮度顺序、黑白日期前景对比度 ≥4.5:1。G 的相邻明度差跨度 <0.006，I 浅色的相邻 OKLab 距离跨度 <0.006。

未验证：浏览器实际观感、原生编译、真实背景、模块色条、大字号、真机体验。数学检查不能代替观感验收。

## 原生落地边界

色阶唯一入口为 DesignSystem.swift 的 holoHeatmapColor；HoloHeatmap 用于完成节奏与记忆活跃，CalendarHeatmap / MonthCell 用于月历。若落地仍需同步图例、选中描边、今天标记、日期前景与徽章前景；保留现有数量分档和统计含义。习惯月历的完成/跳过状态不强行套入数量色阶。不改变品牌主色和全局按钮颜色。
