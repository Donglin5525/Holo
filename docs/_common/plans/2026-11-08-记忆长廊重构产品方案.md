# 记忆长廊重构产品方案

2026-11-08 · 产品评审稿

## 1. 产品决定

把记忆长廊改成「生活回顾」。首页底栏原位置改叫「回顾」，打开后直接看到这周或最近留下的一段生活。知道日期的人，点右上角「按日期找」直达那天。用户一进来就能读到东西，也能把它当作跨模块找旧记录的固定入口。

当前首屏先让用户在「日历 / 洞察」之间选，再在日历里选「日 / 周 / 月 / 轴」。「我的积累」又固定占一行。控件多只是表象，根因是回看过去、安排未来、查看成就、管理 AI 记忆共用一个入口。访问偏低来自当前反馈，现有模块打开埋点可以核对量级，具体流失发生在入口、首屏还是复访，仍需分开量。

Holo 各模块各自已经能回答「花了多少」「习惯做了几天」「完成哪些任务」。生活回顾的价值是把这些记录按真实发生的日期串在一起，让用户想起来「原来这就是我那天、那一周」。

## 2. 首屏与两条动线

**默认页只留一层导航、一张主卡、一列日期。** 导航栏是「返回」「生活回顾」「按日期找」。本周有至少两个记录日时，顶部用一张「本周回顾」，优先摘一条用户亲手留下、点进去能看到的真实内容。只有记账或打卡时，用一条事实，比如「这周有 3 天完成了晨间拉伸」。一条内容已经足以成页时，直接把它放进「最近的日子」，省掉周封面。首屏能露出第一条日期，让用户知道下滑可以接着看。

- **随便翻翻**。打开就读到本周一件真实的事。点「本周回顾」进入同一份周回顾详情，先看一两条可点开的原记录，再看已有的四项足迹和上周同期对比。下方「最近的日子」按日期倒序，只列有记录的日子。先加载最近三个记录日，向下继续翻到更早，点一天进入当天回放。照片有真实来源才展示，单纯记账或打卡的日子用同样完整的文字版式。
- **找某天**。「按日期找」打开可跳年月的月历，有记录的日子用一个标记提示。点日期直接进入同一套当天回放，按实际发生时间排列记账、想法、已完成任务和打卡。密集日期先合并同类记录，展开能看全；筛选放在当天详情。打开原记录再返回，恢复日期与滚动位置。

示例首屏可以是一张「本周回顾」，主句是「周三写下『周末去走一段没走过的路』」。下方是「最近的日子」，第一行是「11 月 7 日 · 1 条想法、2 件完成的事」。这句原话在周回顾详情里可以点开，避免首屏承诺的东西到了下一页找不到。

整页沿用 Holo 的纸感底色、20pt 页边距和字号层级。只让周回顾用独立卡面，日期列表用留白和细分隔线。周卡首句比总数醒目。真实照片是内容，文字版有自己的排版；无照片时页面不会留一块空相框。深色、大字、旁白与 44pt 点击区域进原型验收。布局上可参考 Apple 照片把「最近几天」的浏览与按日期定位分开，Holo 的主角仍是自己写下和做过的事。[Apple 照片按日期查找指南](https://support.apple.com/en-hk/guide/iphone/iph0ea0234e0/ios)

### 稀疏与异常状态

- 本周只有一个记录日时，最近列表直接以那天开场，有内容的当周仍可从个人页或通知查看周回顾。最近两周空白但有更早的记录时，只展示最近一次真实记录和日期入口。
- 全新用户看到一句话「你在 Holo 留下的记录，会按日期出现在这里」和一个「写条想法」入口，打开现有想法编辑器。已有记录但正在同步时，用同步状态承接。部分来源读取失败时先展示可用记录，注明哪些还未载入并允许重试。
- 原记录删除或权限变化后，首页和详情同步重算。缺失记录给出说明并返回当天，旧预览及时撤下。回顾用现有记录本地整理，首屏不等 AI，摘要不把推测写成发生过的事。

## 3. 删掉什么，能力归到哪里

| 现有内容 | 决定 | 用户还能在哪里完成这件事 |
|---|---|---|
| 日视图 | 保留记录回放，撤掉档位 | 最近日期、月历、周回顾里的日期都进入同一页 |
| 月视图 | 改为独立日期选择器，去掉热力强度和当天预览的第二次跳转 | 顶部「按日期找」一步选日 |
| 周网格 | 退役，接受失去七天并排看时间块的体验 | 「每周回顾」看一周，选日期看当天；不再为周网格建替代页 |
| 轴视图 | 从回顾迁到「任务 → 日程」 | 任务时间块与系统日程同轴、拖拽创建和调整时间都验收后，再撤旧入口。已有任务日时间轴是承接点，需补齐差异 |
| 我的积累 | 移除长廊置顶卡 | 个人页「我的积累」承接累计统计和里程碑 |
| 洞察 Tab、记忆列表与确认 | 撤掉整页，统一管理入口 | 个人页「Holo 记住的你」和 HoloAI「记忆」进入同一记忆中心。现有「查看新记忆」的链接按原意到待确认或对应记忆 |
| 报告卡、每日感知、热力图、计划台账与精选故事区 | 撤掉长廊的独立区块 | 报告回 HoloAI「报告」，计划从原对话或目标、任务看。精选故事中可核对的真实片段用于回顾。每日感知与全量热力图退出长廊，首期不为这两个区块再开入口 |

模块分工按用户意图区分。**今日**回答「接下来做什么」。**生活回顾**回答「我做过什么、哪天留下了什么」。**Holo 记忆**供用户查看和纠正 AI 对自己的理解。**一个发现**继续在 HoloAI 提供可核对的观察，确认后能进记忆中心。这个方案把上一版「洞察只露少量理解摘要」进一步收掉，管理能力统一由记忆中心承接。

## 4. 怎么让用户回来

首先让首页底栏的「回顾」讲清用途，再用真实的内容更新兑现。记了一次，能在当天看到它；记了几天，会出现一份可读的周回顾。上周同期对比保留在详情，首屏优先让用户想起自己做过的事。每周用一份回顾。长廊周卡、个人页快捷入口、已有周四通知都进入同一份详情。通知直达对应周，返回长廊；跨周点旧通知时按通知的周期定位。首期只复用现有提醒节奏，周末或月底是否值得再做一个入口，等复访数据判断。

改版前记录两个基线。现有 `module_view` 可量进入，现有 `weekly_review_viewed` 在生成快照后也会计入空页，需要区分有效内容。改版后按入口拆分自然打开和通知打开，按设备去重，以有可回看记录的活跃用户为同口径人群。

| 评估项 | 定义 |
|---|---|
| 有效回顾率 | 有可回看记录的周活用户中，至少一次打开有内容的周详情、当天详情或原记录的比例 |
| 自然复访率 | 首次有效回顾后的 7 天内，从非通知入口在另一日再次有效回顾的比例 |
| 找记录效率 | 从长廊进入后能否在 30 秒内找到指定历史日期的一条记录；同时检查原记录跳转和返回 |

先核对旧版基线，再用同口径对照至少两个完整周周期。自然复访和找记录效率决定改版是否奏效，通知点击率单独看。若打开量涨、有效回顾率不涨，先看周封面是否给出了值得点开的真实内容；若有效回顾涨、自然复访没起色，再查用户下次打开能否看到新内容。

## 5. 首轮原型评审范围

确认方向后，画四个关键场景。有正常记录的首页、稀疏首屏、月历找日并打开原记录、通知直达同一份周回顾。评审时看第一屏是否已经在回看生活，用户找旧记录要走几步，以及长廊、个人页和 HoloAI 的职责能否一眼分清。

实现顺序建议先打通首屏、日期和周回顾的三条路径，再接旧入口并迁移任务轴。记忆确认和历史详情等旧链接按意图逐一改接。周网格直接退役，月报、年度回忆、自动写故事、全局内容搜索不进入本期范围。
