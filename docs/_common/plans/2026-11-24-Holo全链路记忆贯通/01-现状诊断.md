## 2. 三个结构性问题

### 2.1 记忆有三个本子

| 本子 | 存在哪 | 同步 / 防复活 | 谁在写 | 谁在读 |
|---|---|---|---|---|
| 统一知识库（`HoloMemoryRecordMO` + `HoloMemoryKnowledgeRevisionMO`） | Core Data，App Group 容器 | ✅ CloudKit + 墓碑 + 准入 | 记忆萃取、理解引擎晋升、画像同步（有条件） | 记忆中心、聊天、分析、深度分析快照 |
| PortraitStore | 本机 JSON | ❌ 单机、黑名单只在本机 | 画像合成（72h 一轮）、一个发现反馈、画像区反馈 | 聊天注入、一个发现候选、记忆中心画像区 |
| 旧长期记忆 `HoloLongTermMemoryStore` | 本机 JSON | ❌ | 回放旧链路 | **[待 S0 核实]** |

同一个人在聊天、一个发现、深度分析里，Holo"认识"的版本不一样；在画像区点"不准"，知识库不知道。

### 2.2 认可信号散落在五处、写进两个本子

| 入口 | 位置 | 按钮 | 写到哪 |
|---|---|---|---|
| 记忆中心"值得确认" | 个人页 → Holo 记住的你 / 聊天页右上"记忆" | 对，记住 / 不对 | 知识库 |
| 记忆中心画像区 | 同上页面下方 | 准，记住 / 不准 | PortraitStore |
| 一个发现 | 聊天页"一个发现"弹层 | 对，记住 / 不太准确 / 先放一放 | PortraitStore |
| 周期回放卡 | 记忆长廊 → 卡片 → 反馈弹层 | 准确 / 不准（含原因） | 洞察偏好（不进记忆） |
| 报告收藏 | 聊天 → 报告 Tab → 右滑 | 收藏 | 只给界面用 |

**这就是东林"找不到升级入口"的原因**：入口有五个，分在四个页面，文案三种，背后写两个本子。最该出现确认的时刻——AI 用了一条推测来回答你——反而没有入口。

### 2.3 读取各取各的

| 消费方 | 读什么 | 怎么挑 |
|---|---|---|
| 聊天 | 知识库 ≤5 条 + 画像 ≤8 条 + 今日快照 | 知识库不看问题；画像按问题关键词 |
| 分析意图 | 知识库（带问题文本） | `requireQueryMatch: true` |
| 深度分析 | iOS 快照的 `confirmedKnowledgeBrief` / `personalSituationBrief` | 快照构建器各自挑 |
| 回放 / 洞察生成 | 知识库 background + 洞察偏好 | `MemoryInsightContextBuilder` 各自挑 |
| 一个发现 | PortraitStore | 自己挑 |

没有统一的"按场景分配篇幅"，也没有统一的"推测类怎么用"规则（画像注入器和知识库 envelope 各写了一套使用规则文案）。
