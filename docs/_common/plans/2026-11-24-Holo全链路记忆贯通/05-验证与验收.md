## 2. 跨入口一致性用例（本方案的核心验收，东林关注 G4）

在 Debug 构建、模拟器上逐条走，结果截图存 `证据/` 目录：

| # | 操作入口 | 操作 | 必须在哪些地方看到效果 |
|---|---|---|---|
| C1 | 记忆中心"等你确认" | 对，记住 | 聊天回答里该条以已确认身份出现、不再出现"这次参考了"条；一个发现不再拿它当新发现 |
| C2 | 聊天"这次参考了" | 不对 | 记忆中心该条进入停用 / 历史；下一轮画像合成后不复活；一个发现不再出现 |
| C3 | 一个发现 | 对，记住 | 记忆中心"已记住"出现（来自知识库，不是画像区） |
| C4 | 一个发现 | 不太准确 | 聊天不再引用；画像区不再展示；再次合成不复活 |
| C5 | 回放卡 | 准确 | 记忆中心该卡产出的条目变为已记住 |
| C6 | 回放卡 | 不准 + 语气不喜欢 | 条目**不变**（只影响下次洞察写法） |
| C7 | 回放卡 | 不准 + 数据不准 | 条目停用 |
| C8 | 报告 Tab | 收藏 | 该报告产出的条目在"等你确认"置顶，角标"来自你收藏的报告"；条目身份不变 |
| C9 | 报告 Tab | 取消收藏 | 置顶与角标消失 |
| C10 | 设置 | 关闭"记忆辅助回答" | 聊天上下文里没有记忆块、没有趋势块；趋势缓存文件被删除 |
| C11 | 双设备（非健康类） | A 设备否定一条 | B 设备同步后不再引用 |

## 3. 趋势记忆验收

| # | 场景 | 期望 |
|---|---|---|
| R1 | 有一年 Apple 健康数据 | 实验室页（Debug）能看到 ≥1 条睡眠或活动结论，数字与健康 App 里自己算的周均基本一致（误差在取整范围内） |
| R2 | 未授权 Apple 健康 | 没有健康类结论，不报错，其他域结论正常 |
| R3 | 刚装 App 两周 | 没有任何 recentVsBaseline 结论（基线不够），不编造 |
| R4 | 问"最近睡得怎么样" | 回答引用睡眠结论；不出现病因、诊断词 |
| R5 | 问"这个月花钱多吗" | 回答不出现睡眠结论 |
| R6 | 上下文体积 | Debug 日志打印趋势块字数，单次 ≤ 600 字 |
| R7 | 启动 | 冷启动到首页可交互时间与改动前无可感知差异（在同一台设备对比 3 次） |

## 5. 已知限制（写给东林，不是缺陷）

| 限制 | 原因 | 影响 |
|---|---|---|
| 健康类认识的确认 / 否决不跨设备 | 隐私政策承诺健康派生记忆只存本机 | 在 iPad 上要再否定一次 |
| 趋势结论只在本机 | 同上；且可随时重算 | 换设备后第一次启动需要重新计算一次（后台完成） |
| 旧版 App 写回记录会丢"关心"标记 | 旧版不认识新字段 | 收藏效果消失，可重新收藏；不影响正确性 |
| 聊天"这次参考了"条重启后不在历史消息上显示 | 不改消息表结构 | 只影响历史消息，最新回答正常 |
| 本方案上线前生成的报告不会自动拆成认识 | 不做历史全量补拆（成本与噪音） | 收藏这些旧报告时会补拆 |
| 回放旧链路写入的旧长期记忆存储 | 视 S0 K1 结论 | 若已是死数据，后续单独立项清理 |
