# 02 · 产品方案（含界面文案真源）

> 本文是产品口径和**全部新增界面文案的唯一真源**。执行模型不得自行改写文案；文案要改，先改本文。

## 1. 目标：用户能感受到的四个变化

| # | 变化 | 举例 |
|---|---|---|
| G1 | **问什么，Holo 就想起相关的** | 问"最近为什么总是累"，Holo 会带上"近 4 周入睡比之前晚了 40 分钟"和"你在戒烟期"，不会带上无关的消费偏好 |
| G2 | **认可过的，Holo 一直记得** | 在回放卡上点过"准确"的规律、在一个发现里点过"对，记住"的洞察，之后的聊天、分析都能用上 |
| G3 | **能看出长期趋势** | Holo 能说"和去年这个时候比，你的步数少了三成"，而不只是"这周走得少" |
| G4 | **一处纠正，处处生效** | 在一个发现里点"不太准确"，聊天里也不会再提这件事；换一台设备也一样（健康类除外，见 §5.6） |

## 2. 记忆的三层

| 层 | 内容 | 寿命 | 谁产生 | 例子 |
|---|---|---|---|---|
| **原始数据** | 每一笔账、每次打卡、每晚睡眠 | 永久（属于用户） | 用户 / Apple 健康 | 11 月 3 日 23:40 入睡 |
| **短期层：近期状态与趋势** | 和自己过去比的变化、正在进行的阶段 | 随新数据重算；条件不成立就消失 | **程序计算**（趋势记忆）+ 萃取 | 近 4 周入睡比之前晚 40 分钟 |
| **长期层：理解** | 角色、长期习惯、偏好、确认过的规律 | 持续有效，直到被纠正或证据断了（阶段类） | 萃取 / 理解引擎 / 用户确认 | 你在戒烟期；你很可能长期照料猫 |

原则：

- 原始数据**不常驻** AI 上下文，AI 需要细节时按需查（现有分析意图 / agent 工具）。
- 短期层**由程序算**，不调模型，零费用、不会编造数字。
- 长期层**必须过水位**（11-11 方案的水位体系）或用户明确确认。
- 短期层持续足够久（例如同一方向持续 8 周），可以**提名**进长期层，仍然要过水位或用户确认（§5.5）。

## 3. 认可信号分级（D1、D2）

### 3.1 分级表

| 级别 | 用户动作 | 对那条认识的效果 | 是否改变"是不是事实" |
|---|---|---|---|
| **确认** | 对，记住 / 准确 / 准，记住 / 用"你的说法"改写 | 升为"已确认"，相关回答可直接当背景使用 | ✅ 是 |
| **关心**（收藏） | 收藏一份报告 | 这份报告产出的认识**排序提前、不随时间淡出**；在"等你确认"里优先出现 | ❌ 否，仍保留原来的"推测 / 观察"身份 |
| **被动使用** | AI 用了某条认识回答，用户没有纠正 | 只记录使用次数 | ❌ 否 |
| **否定** | 不对 / 不准 / 不太准确 | 停用，并写墓碑，防止后台换个说法又生成出来 | — |
| **不再参考** | 记忆中心"不再参考" | 同否定（已有行为） | — |
| **取消收藏** | 取消收藏 | 撤掉"关心"效果，恢复正常排序与淡出 | — |

### 3.2 收藏 = 关心（D1）的具体规则

1. 收藏的对象是**整份报告**，不是报告里的某一句。所以收藏不能把报告里的每个判断都变成事实。
2. 收藏后：这份报告产出的每条认识带上"用户关心"标记，效果：
   - 相关性排序时加分（同等相关时排在前面）。
   - 不随时间淡出：新鲜度有下限，不会因为几个月没新证据就从回答里消失。
   - 如果它还是"推测"，优先放进"等你确认"队列，让用户有机会把它升成确认。
3. 如果这份报告**还没被拆成认识**（例如收藏的是本方案上线前的旧报告），收藏动作会触发一次补拆（S2 T2.2）。
4. 取消收藏 → 撤销上面三项效果，认识本身不删。
5. **AI 生成内容不算独立证据**（D2，维持现状）：收藏不会让一条推测的证据数增加，也不会让它跨过水位。

### 3.3 回放卡"准确 / 不准"的细分（新增口径）

回放卡的"不准"带原因。原因不同，处理不同——否则用户只是嫌语气不好，Holo 就把一条正确的规律删了：

| 原因（已有枚举 `FeedbackReasonType`） | 对认识本身 | 对洞察偏好 |
|---|---|---|
| 准确 | **确认** | 保持现状（已有聚合） |
| 数据不准 `dataWrong` / 关联不准 `relationWrong` | **否定** | 保持现状 |
| 重点不准 `priorityWrong` / 建议不适合 `suggestionWrong` / 语气不喜欢 `toneWrong` | **不动** | 保持现状（只影响下次怎么写） |
| 不准但没选原因 | **不动**，并把这条放进"等你确认"，让用户在那里明确说对或不对 | 保持现状 |

## 4. 统一确认入口（D2："升级入口我自己都不确认在哪儿"）

### 4.1 设计原则

1. **在被帮助的那一刻确认**：AI 用了一条推测来回答你，就在这条回答下面问你一句。这是最自然、最明显的入口。
2. **只有一个"待确认"列表**：所有等你确认的东西，不管来自萃取、画像还是报告，都在同一个列表里。
3. **按钮只有一套说法**：`对，记住` / `不对`。
4. **入口要露出来**：个人页入口和聊天页"记忆"按钮上显示待确认数。
5. **不打扰**：同一条认识 7 天内最多问一次；一次回答最多问一条；用户不理也不影响任何功能。

### 4.2 入口一：聊天回答下方"这次参考了"（新增，最主要的入口）

触发条件（全部满足才出现）：

- 这次回答实际用了至少一条记忆（模型输出了使用标记）。
- 其中至少一条是"推测 / 观察"身份，不是已确认。
- 这条 7 天内没在聊天里问过。
- 用户没有关闭"记忆辅助回答"。
- 这条不是高敏记忆（高敏的只在记忆中心确认，不在聊天界面露出摘要）。

形态：回答气泡下方一行轻量条，只展示**一条**（取用到的推测里相关性最高的）。

| 元素 | 文案 |
|---|---|
| 前缀 | `这次参考了：` |
| 内容 | 该认识的展示摘要（`displaySummary`，超过 24 字截断加"…"） |
| 按钮 1 | `对，记住` |
| 按钮 2 | `不对` |
| 点"对，记住"后 | 条变为 `已记住，之后会直接参考`，2 秒后淡出 |
| 点"不对"后 | 条变为 `好，以后不再参考这条`，2 秒后淡出 |
| 无障碍标签 | `这次回答参考了 Holo 的一条推测：{摘要}` |

如果这次用到的全是已确认的认识：**不显示**任何东西（不打扰）。

### 4.3 入口二：记忆中心"等你确认"（合并）

现在记忆中心有两块待确认（"值得确认" + 画像区"有 N 条新洞察等你确认"）。合并为一块：

| 元素 | 文案 |
|---|---|
| 分段标题 | `等你确认` |
| 说明 | `Holo 从你的记录里看出来的，确认后会直接用在相关回答里。` |
| 卡片按钮 | `对，记住` / `不对` |
| 空态 | `眼下没有需要你确认的。` |
| 来源标签（卡片角标） | 萃取来的：`从记录里看到`；画像合成来的：`Holo 的推测`；报告拆出来的：`来自报告`；收藏过的报告来的：`来自你收藏的报告` |

排序：用户关心（收藏）的 → 最近在回答里用过的 → 其余按更新时间。

画像区保留"已确立的画像"展示，**去掉**它自己的"准，记住 / 不准"按钮和"有 N 条新洞察等你确认"提示条（这些条目改为出现在"等你确认"里）。

### 4.4 入口三：待确认数露出

| 位置 | 现状 | 改为 |
|---|---|---|
| 个人页"Holo 记住的你"行 | 副标题 | 有待确认时，行尾显示小圆角数字徽标（数字 = 待确认条数，>9 显示 `9+`） |
| 聊天页右上"记忆"按钮 | 纯文字 | 有待确认时右上角加小圆点（不显示数字，避免焦虑） |

### 4.5 其他入口改文案

| 入口 | 现在 | 改为 |
|---|---|---|
| 一个发现 | `对，记住` / `不太准确` / `先放一放` | **不变**（三个选项有各自含义，`先放一放` 不是否定）；只改背后的写入 |
| 回放卡反馈弹层 | `准确` / `不准` | **不变**（它带原因细分，见 §3.3）；只改背后的写入 |

## 5. 趋势记忆（D3）

### 5.1 一句话

**程序每天在本机把你过去一年的数据按周汇总，再挑出"和你自己过去相比明显变了"的几件事，写成短结论；AI 只看这些结论。**

### 5.2 覆盖哪些数据

| 领域 | 指标 | 来源 |
|---|---|---|
| 睡眠 | 平均睡眠时长、平均入睡时刻、晚睡（≥23:30）天数占比 | Apple 健康 |
| 活动 | 日均步数、日均活动分钟、运动次数、站立小时 | Apple 健康 |
| 身体指标 | 静息心率、心率变异性（HRV） | Apple 健康（有读数才算） |
| 消费 | 周支出总额、前 5 大分类周支出 | 记账（排除代办 / 报销、排除转账） |
| 习惯 | 每个活跃习惯的周完成次数；数值型习惯的周均值 | 习惯打卡 |
| 任务 | 周完成数 | 待办 |

### 5.3 时间窗口：看得出趋势，但不被一两天带偏

| 对比 | 用来回答 | 例子 |
|---|---|---|
| 近 4 周 vs 之前 12 周 | "最近变了什么" | 近 4 周入睡比之前 3 个月晚约 40 分钟 |
| 近 13 周 vs 去年同期 13 周（有数据才算） | "和去年比" | 和去年同期比，日均步数少了约三成 |
| 连续同向周数 | "是一时还是持续" | 已经连续 6 周在下降 |

只说**显著且持续**的变化：变化超过阈值、数据覆盖足够、多数周同一方向（具体数字见 03 §5.3）。平稳的不说——"没变化"不占篇幅。

### 5.4 结论长什么样（模板示例，不是对东林真实数据的判断）

- `睡眠｜近4周平均入睡 00:35，比之前3个月晚约40分钟；连续5周偏晚（有数据 26/28 天）`
- `活动｜近4周日均步数约 5200，比之前3个月少约 28%`
- `活动｜和去年同期比，日均步数少约 31%`
- `消费｜近4周「外卖」周均支出比之前3个月高约 45%`
- `习惯｜「晨跑」近4周完成 3 次，之前3个月平均每4周 11 次`
- `数据｜近4周有 12 天没有睡眠记录，睡眠相关结论仅供参考`

规则：

- 每条 ≤ 60 字，带上**覆盖情况**，记录缺失时明说，不把"没记录"说成"没做"。
- 只描述变化，**不写原因、不下诊断**（"可能因为加班"这种话不写进结论；AI 回答时如要推测，按已有人格规范用温和语气）。
- 健康类不用医疗词汇（不写"失眠""心律异常"）。

### 5.5 短期 → 长期

- 同一结论连续 8 周成立，生成一条"阶段"候选，交给理解引擎按水位判定（11-11 水位：阶段类 ≥14 天且 ≥10 次行为证据），达标后进"等你确认"。
- 用户确认后成为长期认识（例如"今年秋天起睡得比以前晚"），之后随证据断开自然过期（阶段类规则，已有）。

### 5.6 隐私

- 趋势汇总和结论**只存在本机**，不走 CloudKit（健康类遵守隐私政策"健康领域的 AI 派生记忆只保存在本机"；为了实现简单，非健康类也一起本机存放——它们随时能从原始数据重算）。
- 只有用户**已同意 AI 数据处理**时，结论才会随对话发给 Holo 后端；没授权 Apple 健康的，健康类结论自然为空。
- 原始的每日数据不出本机，只发结论文字。这与隐私政策"必要的健康摘要会在您同意 AI 数据处理后通过 Holo 后端发送给第三方 AI 服务"一致，**不需要改隐私政策**。

### 5.7 token 怎么控制

| 手段 | 效果 |
|---|---|
| 只发结论，不发数据 | 一年的数据压成几行字 |
| 每次对话最多 8 条结论、总长 ≤ 600 字（约 400 token） | 篇幅有硬上限 |
| 按你这句话挑：问睡眠就优先睡眠类 | 无关的不进 |
| 没有显著变化的指标不出结论 | 平稳期几乎零开销 |
| 结论每天算一次缓存起来 | 发消息时零计算 |

对比：现在聊天上下文本身约 1500-3000 token，趋势块上限约 400 token，平稳期通常 0-200 token。

## 6. 用户动线（完整走一遍）

**场景 A：被帮助时确认**

1. 东林问："这周为什么老是犯困？"
2. Holo 回答里提到"近 4 周入睡比之前晚了约 40 分钟"（趋势结论），以及"如果你最近在戒烟，前几周睡眠波动也常见"（推测类认识）。
3. 回答下方出现：`这次参考了：你最近在戒烟期 [对，记住] [不对]`
4. 东林点"对，记住" → 条变为 `已记住，之后会直接参考` → 淡出。
5. 之后在深度分析、一个发现里，"戒烟期"都以已确认身份出现。

**场景 B：收藏一份报告**

1. 东林在报告 Tab 收藏一份"10 月消费复盘"。
2. 这份报告拆出的"外卖支出近期偏高"带上"用户关心"标记；它原本是"观察"，于是出现在记忆中心"等你确认"顶部，角标 `来自你收藏的报告`。
3. 东林没去确认 → 不影响任何功能；这条认识在相关回答里照常以"观察"身份、更靠前地被参考，几个月后也不会淡出。

**场景 C：一处否定，处处生效**

1. 一个发现推送"晚睡可能与下午喝咖啡有关"，东林点"不太准确"。
2. 知识库对应记录被否定并写墓碑；聊天里不再出现这条；下一轮画像合成也不会换个说法再生成。
3. 换一台设备打开 Holo，同样不出现（这条不是健康派生记忆，走 CloudKit；若是健康派生，见 05 的已知限制）。

**场景 D：长期趋势**

1. 东林问："和去年比我是不是动得少了？"
2. Holo 回答："和去年同期比，日均步数少了约三成；近 4 周活动分钟也比之前 3 个月少约两成（这期间有 3 天没戴手表）。"——数字来自趋势结论，没有调模型算。

## 7. 生效范围与放量（东林需要知道）

- S1-S3 做完后，**东林的开发构建立刻全部生效**。
- Release 用户：报告理解（`reportUnderstandingExtractionV1`）与理解引擎晋升（`understandingPromotionV1`）都是远程开关，默认关。开关关闭时，收藏和回放卡"准确"找不到报告产出的记忆，只会静默无效果（不报错）；聊天按问题挑记忆、趋势记忆、统一确认入口不受影响。
- 建议放量节奏：东林日用机跑满 7 天且 05 的跨入口用例 C1-C11 全过 → 远配放开 `reportUnderstandingExtractionV1`。

## 8. 不做什么（产品边界）

- 不因为收藏、使用次数多就把推测升成事实。
- 不在结论里写原因、不做医疗判断。
- 不在每条回答下面都放确认条；全是已确认认识时什么都不显示。
- 不新增设置开关：趋势记忆受现有"记忆辅助回答"和"AI 数据处理授权"两个开关约束。
