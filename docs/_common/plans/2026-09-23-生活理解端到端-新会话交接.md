## 6. 本会话新增坑（已进 memory 的不再列）

- **App 卸载重装会同时清 App 容器+AppGroup 容器**：种子/候选/开关/plutil 直写的 plist 全丢，「功能间歇消失」先查容器时间戳（`ls -la` 全 17:11 同分钟=被重建）
- **后端两套限流**：`quota_action_ledger`（额度台账）之外还有 **`rate_limits` 表**（usageStore 按分钟/日计数，intent 日限实测 50 次）——测试烧额度先清这张表+重启容器；「已达上限」文案在 ai_call_logs 无记录=在 LLM 调用前被 rate_limits 拒
- **模拟器 App 重装后聊天通道 device_id 会变**（UserDefaults 生成）而萃取通道不变（keychain 持久）——额度豁免要认聊天通道的新 id（本轮 BCA59F42）
- **ExtractionDebugLog 走 NSLog（subsystem=Foundation）**：log show predicate 用 `subsystem == "com.holo.app"` 滤不到，须按 `eventMessage CONTAINS "PLAN-DIAG prepare"` 抓
- **HoloMemoryRecord.primaryDomain 是 Optional**：`Dictionary(grouping:by: \.primaryDomain)` 推导成 `HoloMemoryDomain?` 编译错，用闭包 `{ $0.primaryDomain ?? .thought }`
- **情境记录在 AppGroup 主库 ZHOLOMEMORYRECORDMO（P2 分流）**，健康聚合在 App 容器 HoloSensitiveMemory.sqlite——查候选别找错库
- **五路决策与个人情境的语义衔接**：evidenceVerdict 读 admission 投影、admission 又由决策投影（单向）——存量 unreviewed 候选靠「新同文本数据 merge（admission 用新 payload）」自愈，纯重评估翻不了身
