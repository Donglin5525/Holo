## M2.1 观察索引 + 七域能力目录（地基，约 2-3 天）

**新文件**（均需挂主 App target，pbxproj 四处手术按坑档流程）：

1. `LifeObservation.swift`
```swift
/// 尚未被解释的线索（工程稿 §2.1）。本机可重建索引的条目；不进 CloudKit。
struct LifeObservation: Codable, Sendable, Equatable {
    var oid: String                 // domain:sourceRef:revision 派生
    var domain: ObservationDomain   // finance/health/thought/task/habit/goal/chat
    var sourceRef: String           // 原记录 ID
    var sourceRevision: String      // 修订摘要（失效判断用）
    var occurredAt: Date?           // 实际发生时间（nil=不可知）
    var recordedAt: Date
    var timePrecision: TimePrecision // minute/day/window/midnightDefault/unknown
    var concepts: [String]          // 非敏感概念（"猫粮"级，两字也算）
    var action: String?             // 行为语义（购买/照料/打卡/补账）
    var attribution: Attribution    // self/proxy/thirdParty/unknown
    var businessState: BusinessState // planned/done/negation/derived/quote
    var coverage: CoverageNote?     // 断档/设备更换/默认时间说明
}
```
2. `DomainCapability.swift`
```swift
struct DomainCapability: Sendable, Equatable {
    var domain: ObservationDomain
    var version: Int
    var supportedFields: [String]        // 如 weight:unit/measurementTime
    var timePrecision: TimePrecision
    var coverageSemantics: [CoverageSemantics]  // unavailableUnknown/healthkitOpaque...
    var supportedOperations: [EvidenceOp] // 七 op 中该域支持哪些
}
```
3. `ObservationProjector.swift`：`protocol ObservationProjector { var capability: DomainCapability; func project(now: Date) async throws -> [LifeObservation] }` —— 七域各一个实现（M2.1 期 finance + thought 两个样板，其余五域按样板铺）。
4. `ObservationIndex.swift`：投影结果的本地 JSON 索引（`Library/Application Support/UnderstandingIndex/`），键含 sourceRevision；**幂等重建**：来源版本不变不重投影。

**测试**（standalone swiftc，复用 run-thought-semantic-store-standalone.sh 模式）：
- finance 投影：备注概念提取（两字「猫粮」保留）、补账时间精度标记（midnightDefault）、归属标记（备注「帮X带」→proxy）；
- thought 投影：原句引用与转述区分（derived 标记）；
- 索引幂等：同版本重跑零变更；修订变化只重投影受影响条目。

**验收断言**：从 M1.1 caseA-normal 的合成输入（以 fixture 形式注入投影器入口）投影出的观察，与 `probe-materials.jsonl` 的 o1-o8 语义等价（概念/归属/窗口三字段对齐）。

## M2.2 主题包 + 双通道触发（约 2 天）

1. `ThemeIndex.swift`：词法锚点聚类（概念共现 + 同源记录），主题=成员 oid 集合 + 指纹哈希。**词法为主**；embedding 仅作补充候选源（走 personal_context_embedding 通道，缓存键含权限代际，权限变化才重建——P1-4 约束）。
2. `ThemeChangeDetector.swift`：主题指纹变化才触发行为理解通道；明确表达通道复用现有 `HoloPersonalContextExtractor`（不动）。
3. 探索名额：每轮一个新主题（未归类高信息概念），无有效材料不调模型。

**测试**：合成 M1.1 caseA/B/C 输入 → 三主题聚出、指纹稳定、修订变化不重聚。

## M2.3 本机取证路由（约 2-3 天）

1. `EvidenceRequest.swift` / `EvidenceResult.swift`（op/params/来源修订集/覆盖/计算定义/反例/缺口/失败类型——失败不降级为空数组）。
2. `EvidenceRouter.swift`：七 op 路由表 → 现有读工具（`HoloStrictHealthQueryService`/`FinanceRepository`/`TodoRepository`/`HoloScheduleDataSource` 等）；能力目录判 support，不支持返回 `capabilityUnavailable`（不生成占位数据）。
3. `alignEvents`/`compareConditions` 两个统计 op 是重头：直接借用 `CrossDomainCheckupLedgerBuilder` 的对齐与比较构件。

**测试**：七 op 各一例 + 两失败类型例（无权限域、能力未登记）+ 一防伪例（compareConditions 必须返回分母与排除原因）。

## M2.4 核验闸 + 分级采用（约 2 天，可与 M2.3 并行）

1. `ProposalGate.swift` 三闸（全部纯程序规则，无模型调用）：
   - **措辞闸**：词表扫描 `statement`/`whatWouldChange`（v1.1 清单：因果词/人格词/医疗词/身份默认/月龄精确化/药名反推病名/成瘾机制），条件句豁免；
   - **证据闸**：claimType × supportingRefs 类型对照表（role 需 ≥2 独立来源含归属证据；phaseState 需 baselineCompare；conditionalAssociation 需对照与反例检索记录；缺关键证据→降 observe）；
   - **强度闸**：档位模板（线索/可能/很可能/确定），claimType 限定最高档。
2. `UnderstandingAdmission.swift`：五类命题判定入口（扩展自 `HoloKnowledgeAdmission` 的判定思想，但独立文件不动旧类）。
3. **测试集直接用 M1.6 轮 1 的 31 条实测候选回放**：已知 2 硬违规必须被拦、10 拆台正确候选必须放行——闸的拦截率用真实分布校准，不造样本。

## M2.5 影子运行时（约 2-3 天）

1. `ShadowRuntime.swift` 状态机：`newEvidence → packaged → proposing → awaitingLocalEvidence → verifying → adoptable/observing/askWhenRelevant/rejected`；每阶段先落本地批次状态再发请求；请求键含（阶段/材料摘要/来源版本/策略版本/授权范围版本）。
2. **滞留超时降级**（P1-5）：>72h 未跑完的候选回证据池，等实质变化重打包（防僵尸——今晚 M0 的 BatchQuarantine 是它的同族先例）。
3. 影子存储：独立 UserDefaults 域 + JSON 导出，**不写 `HoloMemoryRecordMO`**、不进对话上下文。
4. 预算：与既有后台池共享（env 配额待东林点头后设，默认 0 调用——影子期用测试 purpose 计数不计费或极小额）。
