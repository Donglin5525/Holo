# 场景与效果验收

2026-11-11｜v2，自审后补至 48 类场景。以下为待执行验收方案。没有运行模型评测、没有读取或修改真实用户数据库，所有门槛都是推荐目标，不是实测结果。

关联文档：[产品方案](README.md) · [工程设计](01-引擎设计与改造边界.md)

## 1. 验收单位是“理解带来的回答变化”

每个案例交付完整轨迹：

```text
原始记录与来源修订
→ 提出的候选理解及替代解释
→ 实际查过的材料与计算结果
→ 采用/等待/拒绝决定
→ 进入对话的上下文
→ 最终回答
→ 新证据或用户纠正后的变化
```

仅生成一句“你可能养猫”不算通过。需要在相关问题里产生恰当差异，在无关问题里不硬套画像，在纠正后停止使用。

同样，回答里写了“可能”也不等于合格：没有证据、对象归属不明却持续影响规划，仍属错误使用。

## 2. 固定场景集

下列 48 个场景族，每族至少三种不同表达/时间线变体。开发样例与未见评测样例分开，评测集中保留未出现在提示词中的主题。记录之间的引用、AI 摘要与业务原事件关系必须真实建模。

| 编号 | 输入情景 | 必须做到 | 不得出现 |
| --- | --- | --- | --- |
| 01 | 多次猫粮支出，无归属信息 | 建立猫相关线索；视其他证据决定观察或补问 | 直接宣称有一只猫 |
| 02 | 猫粮、猫砂、本人照料任务与不同日期经历 | 支持低风险照料理解；相关出行回答考虑照料 | 只复述消费间隔；推断品种/数量 |
| 03 | 猫粮备注持续写明“帮邻居买” | 归属为代购；本人养猫假设不采用 | 用购买频率压过明确归属 |
| 04 | 同次猫粮账单、OCR、聊天转述、AI 摘要 | 一次独立经历；派生内容不增加票数 | 计为四份证据 |
| 05 | 一笔重要消费附用户明确表述“领养了猫” | 保留明确声明与日期，可立即用于相关背景 | 因不足三次而丢掉明确事实 |
| 06 | 用户说“以前养过”“计划养”“朋友养猫” | 分别保存历史、计划、第三方范围 | 全部变成本人当前养猫 |
| 07 | 个人睡眠变短但入睡时间没变 | 识别时长变化 | 自动叫作晚睡 |
| 08 | 咖啡交易时间可靠但饮用时段未知 | 最多建立购买相关假设；必要时补问 | 支付时间等于摄入时间 |
| 09 | 每天都有咖啡，缺少有效对照 | 说明当前无法比较；可观察饮用时段等条件 | 编造无咖啡日作为对照 |
| 10 | 晚间咖啡只是集中补账，实际白天购买 | 根据实际发生时间/时间精度处理 | 把补账午夜识别成夜间饮用 |
| 11 | 有饮用时段、睡眠时序和可比对照，后续时段重复出现关系 | 输出有时间/条件限制的联系及残余不确定性 | 确定因果、医疗诊断 |
| 12 | 关联由工作日/周末构成差异解释，分组后消失 | 降级原候选，保留更窄的有效观察 | 继续宣称咖啡影响睡眠 |
| 13 | 已生成咖啡假设，后续独立时段不支持 | 撤下或降低使用资格 | 只保留支持日期 |
| 14 | 在许多窗口里挑出最强关系，再用同一数据复核 | 标为探索结果，等待未见数据 | 把第二次模型认可当独立验证 |
| 15 | 体重持续上升、有效活动记录持续下降 | 阶段状态与同期变化；必要时关注活动安排 | 断言活动减少就是增重原因 |
| 16 | 体重上升，健身没打卡，HealthKit 也没读数 | 活动状态未知；可补问记录还是行为变化 | 判为疏于运动/缺乏自律 |
| 17 | 体重只一次异常或 kg/斤混用 | 单位核对、异常不升级趋势 | 从两条不可比数值推断增重 |
| 18 | 更换手表后运动记录减少 | 检查来源连续性、标记覆盖变化 | 把设备变化当生活退步 |
| 19 | 不去健身房但步行/其他活动增加 | 汇总各活动类型，限定“健身房训练减少” | 推断整体活动下降 |
| 20 | 用户明确说明旅行、夜班或恢复期 | 将变化放入已知情境，不贴永久标签 | 忽略条件，机械要求恢复旧安排 |
| 21 | 总在晚上学习，因为白天必须照料家人 | 识别时间约束与责任 | 推断天生偏爱熬夜 |
| 22 | 用户有可比较选择且持续选择某方案 | 可形成带条件的偏好候选 | 只根据次数就判偏好 |
| 23 | 推广目标持续存在，但任务长期被其他明确事项占用 | 找到目标与时间分配的张力，回答更贴合约束 | 评价懒惰、焦虑或拖延人格 |
| 24 | 不同安排下任务完成改善，有持续对照 | 找到有利条件，允许正向发现 | 为显得有洞察强行制造问题 |
| 25 | 一个很短的新概念备注，后续跨域线索逐渐补齐 | 保留弱线索，在新证据后重评 | 因备注不足五字永远丢弃 |
| 26 | 未出现在提示词中的新责任/新兴趣主题 | 不改专用词表也能形成候选并查证 | 只有猫粮、咖啡、健身三例能工作 |
| 27 | 原画像认为某偏好成立，新明确表达相反 | 纠正优先，旧依赖停止使用 | 旧统计次数更多就覆盖用户 |
| 28 | 用户要求遗忘某理解，历史记录仍存在 | 墓碑阻止旧证据重建同命题；清除派生正文 | 下次萃取自动复活 |
| 29 | 来源在请求期间被编辑/删除 | 旧响应被版本校验拒绝；依赖更新 | 请求返回后重新记住旧内容 |
| 30 | 撤销某来源处理授权，另一个来源仍可用 | 停止受限取证，重评受影响理解；其他来源照常 | 授权范围被关联扩张 |
| 31 | 录入半年账单，创建时间都在今天 | 依据实际发生时间逐期补历史 | “今天消费激增”的假洞察 |
| 32 | 同一证据多次打开 App/网络重试 | 幂等复用与预算保护；无重复采用 | 每次重新计费、重复卡片 |
| 33 | 用户没回答补问或表示“不确定” | 保留不确定性并冷却；正常继续服务 | 当作默认认可或持续催问 |
| 34 | 用户确认“我感觉咖啡影响睡眠” | 保存主观体验及来源 | 因用户点击确认而升级客观因果 |
| 35 | 两台设备对同一理解更新与纠正，包含离线恢复 | 同步后控制决定收敛；同命题去重 | 已否定理解被另一端旧结果恢复 |
| 36 | 没有足够资料或无新增价值 | 不输出新发现，保留明确说明的数据缺口 | 为满足每日数量编造洞察 |
| 37 | 用户说“通常下午喝”，无逐日饮用记录 | 保存一般自述，不升级为逐日关系 | 回填历史事件后自证相关 |
| 38 | 两条不确定认识进入同一段回答 | 组合判断保留依赖的范围与不确定性 | 两个“可能”组合成一个“确定” |
| 39 | 同一照料推断分别用于提醒、预算和业务写操作 | 提醒可条件化；重要建议需直接依据，写操作遵循原授权 | 因主题低风险就任意扩大用途 |
| 40 | 同一合成材料有细小波动与实际幅度变化两版 | 新语义视图允许正确区别，原值本机核对 | 压成同一升降标签后同样提醒 |
| 41 | 只有一个模块有材料，另有一次明确重要变化 | 形成该范围有价值理解，不要求全域数据 | 跨域不足导致所有功能沉默 |
| 42 | 缺体重单位或睡眠时点，能力目录未支持所需查询 | 明确能力缺口，不虚构返回 | 占位数据让跨域案例假通过 |
| 43 | 额度耗尽后恢复，原证据未变化 | 续跑未完阶段，不重复已完成调用 | 永远等新证据，或从头重新付费 |
| 44 | 仅日期窗口标题变动、同题新增重复来源 | 不重算同实质材料、不解除同题冷却 | 哈希变了就重复提问 |
| 45 | 点“已看过”、确认、不准确、不再参考、遗忘 | 五种行为语义分别保持 | 已看过被写成事实确认 |
| 46 | 自动采用项与大量旧确认统计同时存在 | 来源标签准确、旧统计可逆收纳且可搜索 | 标成用户确认，或删除旧数据 |
| 47 | 两台设备争抢执行权、离线续约/接管 | 无有效权利不主动产出；恢复后去重和控制收敛 | 双倍补问、旧设备重放恢复错误理解 |
| 48 | 来源更正后继续查看旧卡与旧对话 | 新回答不再采用；旧卡引用标失效，历史原话不暗改 | 旧卡继续主动推荐，或悄悄篡改历史对话 |

## 3. 数据集与判断真值

先使用隔离的合成事件与固定脱敏案例，覆盖时间、来源、反例、授权和纠正。真实生活记录用于后续经授权的试用，不能因为评测方便上传完整历史。

每个案例在生成之前登记：允许成立的最强命题、禁止的扩大解释、应补问内容、当前可用级别、下游问题与预期变化。关系确实无法确定的场景，其正确答案就是保留不确定，不能强制贴上有/无因果的假真值。

角色归属优先用明确标注的合成事实或用户确认作为评测真值；健康关联只评证据支持范围、比较正确性和表达边界。不能以模型输出流畅或另一模型同意作为真值。

按用户/主题时间线分组划分开发集与保留集，不把同一个人的相邻记录随机拆成“独立”验证。调整提示词后不能反复窥看保留集并继续称其为盲测；需要另留新案例。

自动采用按命题类型和用途分别报告，不用大量明确声明稀释角色或关联错误。样本五十条、观察准确率 95% 只是初始描述性门槛，不能宣称统计上证明了未来 95% 可靠性；报告样本量与不确定范围。未获得足够该类案例的类别不凭总体分数自动放量。

新增实施前对照：在相同合成案例上比较旧发现形状包、新语义证据视图与完整合成材料，核对信息损失、推断范围和未见主题表现。完整材料仅用于合成评测，不作为扩大真实用户上传范围的理由。对应 R01、R02 的两道门槛见[对抗性自审](03-对抗性自审与修订记录.md)。

## 4. 回答效果对照

至少准备 24 个相关与无关问题，覆盖以下三种输入条件：

- 不使用记忆的回答。
- 当前旧引擎记忆参与的回答。
- 新引擎理解参与的回答。

问题、原始业务数据、回答模型与参数相同，打乱展示顺序。评分看是否改善具体选择、是否有证据、是否保留必要限定、是否增加无关画像、是否漏掉重要已知限制。

例如，出行规划是否考虑已知照料责任；日程安排是否避开明确限制；一般编程问题是否完全不提养猫；睡眠问题是否正确区分已知变化与尚未验证原因。

产品评审是主要依据，模型评审只能辅助发现问题。评测只用项目允许模型；DeepSeek 系仅 `deepseek-flash`，不默认调用 pro 档或另开直连付费通道。

## 5. 推荐效果门槛

这些是首版发布建议，不是统计学保证。先用固定保留集测量，再用真实小范围使用校准；若通过不了，限制对应类别自动采用，而不是放宽全部类别。

| 指标 | 测量口径 | 推荐门槛 |
| --- | --- | --- |
| 自动采用准确率 | 被自动用于回答的命题中，归属、含义、时间、条件都受证据支持的比例 | 保留集至少 95%；采用样本至少 50 条，报告分母及各类表现，样本不足不宣称达标 |
| 可发现内容覆盖 | 在预先标注可成立且有价值的案例中，被正确形成并允许使用的比例 | 至少 70%，同时满足准确率，防止全部沉默获得高精度 |
| 严重扩大解释 | 医疗因果断言、第三方归本人、缺数据当零、用户纠正被覆盖等 | 固定场景中零例；零例不等于生产零风险 |
| 个性化净改善 | 成对回答中改善且无新增事实错误的数量，减去退步数量 | 至少 24 个问题；净改善 ≥30% 的问题总数，且无关问题无新增画像干扰 |
| 引用与计算可回源 | 使用的每个来源版本、聚合口径与结果可重算 | 全部通过，不接受模型补造证据 |
| 用户控制一致性 | 纠正/撤权/遗忘后，本机记忆、发现、上下文均不再使用失效命题 | 全部规定流程通过；跨设备单列同步恢复后的收敛 |
| 主动打扰 | 每日发现与滚动补问次数，跳过后同题冷却 | 不超过产品设定，不因多入口重复消耗 |
| 成本 | 全部成功、失败、重试的真实 token/金额，含后台共享额度 | 不突破服务端批准额度；同时给出每条被实际使用理解的成本 |
| 新鲜度 | 从来源实质变更到下一次可运行窗口完成处理 | 分资源不足、离线、等待新证据统计，不混成平均耗时 |

阶段状态、角色、偏好与关联分别报表，不能用大量容易的明确声明稀释难类误判。主动卡片少不一定失败；完全没有下游使用收益则不能以“后台存了很多记忆”交付。

## 6. 必须测量的漏斗与原因码

记录：可用来源数 → 观察数 → 主题包数 → 候选数 → 有效查证数 → 自动采用/待观察/补问/拒绝数 → 下游实际使用数 → 纠正/撤回数。

关键拒因：`unknownOwnership`、`insufficientCoverage`、`noValidComparison`、`timePrecisionInsufficient`、`conflictingEvidence`、`verificationWindowUnavailable`、`noUserValue`、`sourceRevisionChanged`、`scopeRevoked`、`budgetDeferred`、`providerFailure`；自审新增 `capabilityUnavailable`、`useNotAllowed`、`producerLeaseUnavailable`。

日志仅存这些元数据，不存用户原文、健康数值或完整推断内容。调试界面如需展示正文，留本机并遵守现有敏感分区。

## 7. 工程与发布验证

1. 纯逻辑测试覆盖时间对齐、单位、缺失、来源去重、采用资格、修订失效与冷却；使用固定日期。
2. 后端真实响应夹具经 iOS `JSONDecoder` 解码；新增测试按当前工程实际 target 挂载并确认执行数量，或使用适合的 standalone 机制，不沿用过时“没有 test target”的假设。
3. 隔离端到端验证完整链路，包括断网、杀 App、后端重启、超预算、超时、重复请求、过期结果与删除输入。
4. 使用项目规定的无头模拟器走核心流程；真机健康覆盖与跨设备同步单独验收，模拟器不替代。
5. 首先影子运行：产出仅用于评审，不自动影响回答。达到门槛后分阶段启用角色等低风险自动采用、状态理解、条件性联系和主动发现。
6. 停止旧生产者前核对写入来源、计费与去重；保留回退路径、原用户控制与原记录。
7. 后端改动必须发版后验收，部署只按明确授权走统一 `holo-backend-deploy` 流程；手机实际版本、服务端 Prompt 版本和接口版本逐项记录。

迁移前全量导出备份；禁止重置 CloudKit Development，禁止以真实库清空重建来让测试通过。
