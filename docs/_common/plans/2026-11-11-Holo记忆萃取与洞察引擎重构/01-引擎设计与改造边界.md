## 2. 最小新增结构：观察、假设、理解

### 2.1 `LifeObservation`：尚未被解释的线索

在本机可重建的观察索引中保存：

| 字段组 | 含义 |
| --- | --- |
| 来源 | `sourceRef`、`sourceRevision`、`lineageKey`、`domain`、记录类型 |
| 时间 | `occurredAt`、`recordedAt`、`timezone`、`timePrecision`、时间的业务含义 |
| 内容 | 本机原文引用、实体/概念、行为、对象归属、计划/完成/否定/转述状态 |
| 数值 | 单位、来源、序列引用、聚合定义；精确数值留本机 |
| 可观测情况 | `coverage`、`missingReason`、来源更换、是否完整导入、是否只有记录缺席 |
| 数据边界 | 可用领域、敏感等级、允许上送的字段投影 |

不同模块提及同一次经历，仍只有一个独立事件。对无法确认同源的事件保留不确定标记，不能为了凑门槛计成独立证据。

健康无读数使用 `unavailableUnknown`；本机确知的未配置、查询失败可另记原因。不得伪造 `readDenied` 状态。用户主动标注“当天未运动”可作为声明，但不能与设备没记录混同。

### 2.2 `UnderstandingHypothesis`：可查证的候选

最少携带：

```text
hypothesisID / revision
claimType: role | preference | recurringBehavior | phaseState | conditionalAssociation
subject / relation / object / conditions / timeScope
supportingObservationRefs / candidateCounterRefs
alternativeExplanations
verificationPlan / missingEvidence
expectedUseCases / whatWouldChangeTheAnswer
evidenceGrade / lifecycleState / sourceRevisionSet
```

`alternativeExplanations` 只要求与此候选直接竞争的合理解释，通常最多两个，不让模型列一大串泛泛可能性。模型的 `evidenceGrade` 只是建议，最终等级由核验规则产生。

### 2.3 `VerifiedUnderstanding`：统一知识库中的采用结果

沿用知识修订、证据快照、用户控制操作和既有记忆读取桥接，增量扩展：

- `epistemicStatus`：明确表达、直接观察、推断。
- `evidenceGrade`：线索、支持、充分支持；不展示未经校准的概率百分数。
- `adoptionMode`：明确背景、限定自动采用、待补问、仅内部、已失效。
- `conditions`、`validFrom/validTo`、`lastSupportedAt`、`reviewAfter`。
- `verificationSummary`、`counterEvidenceRefs`、`coverageSummary`。
- `allowedUses`、`useCases`、`derivedFrom`，以及现有控制版本。

补充 `intendedUse` 与 `useRisk`：同一认识在普通背景提醒与影响预算/安排的建议中，准入要求不同。衍生判断继承所有依赖中最严格的授权、敏感性、不确定性与适用窗口；推断之间的组合不能自动提高证据等级。

“已采用”与“用户确认”分开存储。自动采用不能写成用户确认；确认旧统计句也不能授权更强的“自己养猫”命题。

用户画像按需读取这些命题形成视图，不另建第二份可编辑长文档案。主题索引与候选是工作材料，最终采用结果与用户控制沿用现有知识库权威。

## 3. 通用发现机制

### 3.1 主题组织

用对象、行为、语义相近性、明确关系和时间条件共同召回。优先复用已有语义检索能力，建立可回源的主题成员索引；向量相似只负责找材料，不证明关系。

主题可以跨域，也可以只在一域有证据。“宠物照料”索引允许包含“猫粮”“猫砂”“寄养安排”；把它们聚到一起，不自动证明是本人的宠物。

新主题来源包括未归类记录、明确生活变化，以及不同主题之间反复共现的条件。探索不扫描所有指标的任意组合：每轮保留一个新主题探索名额，其余处理已有高价值变化；无有效材料就不调用模型。

### 3.2 双通道触发

| 通道 | 触发 | 处理 |
| --- | --- | --- |
| 明确表达 | 用户明确说出新事实、改变或纠正 | 复用现有个人情境萃取与校验；优先更新采用结果 |
| 行为理解 | 新线索改变主题证据、个人基线出现变化、候选满足复查条件 | 形成主题包，模型提案，程序取证，再决定采用 |

明确表达也检查主语、否定、引用、时间范围；“朋友养猫”和“以后想养猫”不记为本人当前养猫。不会对每条记账、打卡单独调用模型。

语义标准化与提案尽量同批完成，新概念不要求先写词表。短备注不按长度过滤；明确无语义变化的重复记录可通过增量计数更新主题。

### 3.3 查证协议

模型只输出受控 `EvidenceRequest`，由本机路由到现有读工具：

| 操作 | 用途 | 关键约束 |
| --- | --- | --- |
| `retrieveRelated` | 查找同主题的原记录、原话、明确归属 | 权限内、返回来源版本、限制数量 |
| `checkOwnership` | 区分本人、代购、他人、未知 | 无信息返回未知，不由默认值补本人 |
| `comparePeriods` | 当前与个人历史比较 | 窗口、单位、来源、可观测天数可比较 |
| `compareConditions` | 在两个可比较条件下比较结果 | 明确区分无记录与无行为，返回分母和排除原因 |
| `alignEvents` | 对齐行为与当晚/后续阶段 | 明确时间精度、时区、跨日与预设滞后 |
| `searchCounterEvidence` | 检索直接矛盾、替代解释、偏离样例 | 必须记录查过的范围，没查不能叫没反例 |
| `checkCoverage` | 判断比较是否有资格进行 | 设备切换、查询失败、完整性变化分开处理 |

这些是通用读操作，不是猫粮或咖啡专用规则。模型不能执行 SQL、任意代码或写业务数据；请求字段必须来自模块能力目录。查询失败返回具体失败类型，不能降成空数组后当作“没有反例”。

能力目录按来源分别登记 `supportedFields`、`timePrecision`、`coverageSemantics`、`supportedOperations` 与版本。七域都有入口不等于每域支持所有操作。三例需要的体重单位/测量日期、睡眠时点、活动序列必须在一期真实接通；不支持的请求返回 `capabilityUnavailable`，不能生成占位数据。

取证结果 `EvidenceResult` 包含：原请求与计划摘要、来源修订集合、实际覆盖范围、计算定义与结果、排除项、反例、缺口。模型不能更改程序计算值。

### 3.4 防止选出巧合再当成发现

数值型关联默认先做个人基线与同条件比较，再检查新时间段能否重复。连续多天属于同一次事件或连续一个阶段时，不能当成许多独立样本。

一个候选首次选定窗口、条件和滞后后登记 `analysisPlanDigest`；验证用未参与发现的后续数据。换条件、换窗口、换滞后寻找更强结果算新尝试，需要新的验证材料，不能继续借用已经看过的“验证集”。

按“主题×结果变量×观察周期”合并高度相近的尝试，限制每周期候选数并记录搜索次数。大规模数值搜索如引入统计显著性检验，需明确多重检验与自相关处理后才能作为证据；一期不把单个相关系数或 p 值设成自动采用开关。

现有 `CrossDomainCheckupLedgerBuilder` 有按日对齐和 Pearson 候选筛选，可借用读取口径、对齐和统计构件；不能把“相关系数最大三条”直接拿来当记忆真相。

## 4. 按命题类型核验，避免只有一套次数门槛

| 命题类型 | 自动使用需要什么 | 不足时如何处理 |
| --- | --- | --- |
| 用户明确表达 | 原话可追溯、本人范围明确、时间明确到足够使用 | 补限定或暂存，不做无条件事实 |
| 生活角色/责任推断 | 语义支持、独立来源、时间持续、本人归属有支撑、查过主要替代解释、低影响 | 只保留可能性；有必要时问归属 |
| 偏好推断 | 用户明说，或存在真正可选的多次选择与背景 | 只有次数则记行为；约束导致的选择不写为偏好 |
| 阶段状态 | 个人基线可比较、样本覆盖足够、变化有实际幅度和持续性 | 单次波动作为观察 |
| 条件性关联 | 有效对照、时间顺序、缺失处理、反例、独立时段复查 | 未验证只作线索；健康关系保持限定 |

“充分支持”不是模型报 0.95，也不是机械累计三条。每类命题有可检查的证据要求，门槛以固定评测集和真实误判校准。首版角色推断若无法稳定达到准确性门槛，保持待补问，而不是降低所有类别的门槛。

语义归属不是数字计算能证明的：程序负责核对引用与事件独立性，语义核验需明确说明哪项原证据支持“本人照料”、哪项支持“拥有宠物”等不同强度。核验器重复认可提案不计新证据；归属仍无法辨明则不得采用更强命题。低风险按“命题 × 具体用途”裁定，不能给一个主题永久贴低风险标签。

采用规则分两步：先判断是否允许使用，再决定展示优先级。展示需同时有当前价值、信息增量和可解释依据，随后按影响、时效排序；不以一个总分掩盖证据失败。

“暂不确定但有用”的内容可以在用户主动询问关联时，以明确假设方式回答并指出缺口；不能在普通规划中偷偷当成已成立的原因。

补问回答作为独立的声明记录，保留用户给出的日期/范围。一般性自述只支持一般性理解，不生成逐日观测、不补造对照组。选择问题时必须指出不同回答会改变哪个采用决定；用户跳过后，只有真正改变答案空间的新证据才可考虑解除同题冷却，仅条数或摘要哈希变化不够。

现有 `HoloKnowledgeAdmission.swift:50–55` 会按 `prohibitedInferences` 中的 medical 等前缀拒绝行为推断。新设计要分清“这个命题正在声称医疗原因”和“这个命题附带不得作医疗推断的限制”：前者不能进入自动事实，后者不应让一条合规的客观关联无条件消失。改造时通过命题类型、实际表达与证据级别判定，不能简单删除健康保护。

## 5. 运行、存储与授权

### 5.1 职责划分

| 位置 | 负责什么 |
| --- | --- |
| iOS/macOS 本机 | 来源授权过滤、观察索引、主题状态、数值查询、运行状态、最终采用与用户控制、对话读取 |
| CloudKit | 按现有分区策略同步可同步的知识修订与用户控制；不把健康本机分区自动改为云同步 |
| 后端 | 版本化提案与语义核验、协议校验、预算与任务状态；不持有长期用户画像权威 |
| 模型供应商 | 只接收本次已授权、最小化的推理材料；其数据处理条款需与现有承诺核对 |

自动采用的低风险非敏感理解推荐与现有知识同步；健康推断沿用敏感本机分区，跨设备各自判断可用性。若需要改变该边界，应单独明确后再实施，不能因“支持跨模块”而自动扩大。

### 5.2 上送材料的具体边界

| 材料 | 本方案默认 |
| --- | --- |
| 交易金额、余额、完整账本 | 本机计算，不进入洞察模型输入 |
| HealthKit 具体数值、逐日序列、原始样本、健康派生正文 | 本机处理，不直接上送 |
| 财务备注中的非敏感概念，例如猫粮 | 在现有 AI 授权覆盖时，可发送最小概念；不附金额与无关正文 |
| 想法/对话/任务中的必要原句 | 仅授权来源、按需截取；排除助手文本、他人无关信息及敏感片段 |
| 健康观察形状 | 与现有发现类似，仅受控的指标类型、方向、覆盖、比较是否通过；不含具体值和自由正文 |
| 跨域查证结果 | 上送条件代号、支持/不支持/未知、覆盖计数、反例类型；精确差额与实际日期留本机 |
| 既有理解 | 只取与本题相关且允许该处理方式的非敏感项，带推断/有效期标记 |

例如，服务端可以知道“咖啡相关条件 A 与睡眠时点变化的比较有支持，饮用时段来自用户补充，另有工作日差异”；不需要得到某天睡了几小时。涉及健康的结论以结构化关系和受控文案返回，由本机补充真实指标与依据。

为避免再次压成仅供填空的形状包，新增 `SemanticEvidenceView`：包括授权的概念/行为、主体归属状态、业务状态、条件含义、窗口粒度、来源代号与类型、覆盖等级、变化等级 `effectBand`、支持和反例的类型。`effectBand` 由预先定义且可审计的本机比较规则产生，区分数据不足、可忽略波动、有实际幅度；不能由模型随意给重要性分数，也不表示临床意义。实际差额、阈值和明细留本机供核对。

此投影是否足够有用要先做合成材料的三组对照：旧形状包、新视图、完整合成材料。若新视图无法支撑某类认识，补充授权范围内的必要结构；仍不足则明确暂不支持该能力。不能仅凭协议字段更多宣称已经解决“只会算术”的问题。

这比旧端点多了语义概念、替代解释和查证结果，但仍不是把完整生活数据交给模型。字段组合本身也可能泄露状态，必须纳入授权与隐私评审；不能声称“没有数值所以不敏感”。若现有授权不覆盖某字段，先不传，降级为本机观察或明确表示无法判断。

跨域取证要求所有参与来源分别被授权；有财务权限不能顺带打开健康权限。原文、备注和引用均视为数据，其中的指令不能改变取证范围、调用工具权限或采用规则。

### 5.3 可恢复的本机状态机

```text
newEvidence → packaged → proposing → awaitingLocalEvidence
→ verifying → adoptable / observing / askWhenRelevant / rejected
任意未采用状态 → invalidated（来源、授权或用户控制变化）
已采用理解 → rechecking / superseded / expired / forgotten
```

每阶段先记录本机批次状态，再发请求。请求键包含阶段、材料摘要、来源版本、分析计划、策略版本与授权范围版本；响应带原键。应用结果前再次检查这些版本，防止用户已经删除记录，旧请求却返回并重新记住。证据不变不重复已完成阶段，但预算或网络恢复可以继续尚未完成的阶段；窗口标签滚动或统计正文改写不单独构成重算理由。

云端生成需要新本机材料时，返回受控取证请求，等待下一次 App 可运行；后端不能直接读 HealthKit 或 CloudKit 私有原始记录。iOS 不活跃时不承诺全天候实时发现。超过证据有效期的运行重新检查，而不是直接交付旧判断。

异步计算复用既有云任务加密机制：任务完成/失败/取消销毁输入；结果回传确认后销毁；新用途建议二十四小时结果 TTL，超期本机根据来源版本决定是否重建。此为新策略，不能假称现有七天默认已经改变。服务端能解密计算，不称为端到端加密。

幂等元数据不存可读正文；日志只记录阶段、拒因、数量、耗时、版本和计费。明确区分网络重试与再次模型生成：结果未知时先查任务状态，不能直接再付费调用。已付费但不可恢复的任务按失败成本记录，不承诺一切失败零重复费用。

### 5.4 多设备

从一个主设备开始建立新链路，其他设备可读取符合分区规则的同步知识。可重建的候选索引留本机；正式知识按稳定命题身份去重，用户纠正/遗忘操作优先。

已有后端 `backgroundSubject` 使用购买主体或设备主体，不能拿它当所有免费设备之间的同一人身份。复用现有 CloudKit 账户范围做用户数据同步；不依靠客户端自报用户 ID 合并服务器画像。

一期允许不同设备有不同的待观察候选，但不得有互相覆盖的用户决定。首次放量只允许一个持有效执行权的设备进行后台生产与主动补问/展示；执行权不是普通本机布尔开关。推荐在同一 CloudKit 私有账户范围内用共享协调记录和条件保存表达 owner、租约修订与有效期，具体续约/接管和时钟口径必须独立验证，不默认现有旧发现设备主体机制可直接复用。

主动展示/补问的逻辑主题键及消费记录也需要同步。持有权利不足、无法确认当前租约或控制状态时，设备继续读取适用的已有理解和接受本机纠正，暂停主动生产/补问；不拿后台预算主体冒充同一用户身份。需要健康取证的任务只能由具有相应本机来源能力的设备执行。此机制未验收前只做明确限定的单设备试用，不宣称多设备体验已完成。

无法联网期间另一设备尚未收到纠正是明确限制：同步恢复后必须收敛，不能声称远端即时撤销。

## 6. 时效、冲突、遗忘与迁移

### 6.1 同一认识的连续更新

身份按主体、关系、对象与实质适用条件确定，主题名不能独立作为去重键。证据增加通常更新证据快照，不新建一条同义理解；含义变强或条件改变时产生新语义修订并重核验。

近期状态只在覆盖到的阶段成立；`reviewAfter` 是复查时间，不等于事实反转时间。长期角色没有新记录只能降低当前置信与引用优先级，不能推断角色消失。用户明确提供结束时间时，更新有效期并使相关主动卡片失效。

来源编辑、删除、退款/撤销、重复导入合并、权限变化，触发依赖它的观察、候选、理解和回答缓存失效。若仍有其他充分支持来源，可重新核验后保留。对外删除的用户原记录不能被证据快照暗中保留全文。

遗忘沿用控制操作和墓碑，阻止重跑复活；新画像不覆盖用户维护的档案。用户纠正过的命题不因模型更高评分被自动恢复。

### 6.2 存量记忆处理

1. 用户明确表达、纠正、确认和遗忘操作先保留，迁移不得改写其语义。
2. 已确认的“六个月三次猫粮”保留为用户确认过的统计命题，标记旧生产者；不得自动改为“养猫已确认”。
3. 旧统计可作为新候选的检索入口，但独立证据必须解析回原记录，旧记忆本身不增加票数。
4. 新旧语义相同且新记录只是证据更新时合并；不同语义关联展示，不强行合并。
5. 对新生成的纯统计结果停止直接占据理解列表；既有确认统计在展示层可逆折叠为“此前确认的统计”，保持可搜索和回源，不改变存储语义。未获迁移验收前不批量归档或删除。
6. Core Data/CloudKit 只做增量兼容；上线前提示全量导出备份，禁止重置 CloudKit Development。

不因为升级提示词清空全部游标。只重看受影响主题和来源，旧用户控制始终有效。回滚停止新生产者，保留新增数据与操作历史，旧客户端看不懂的新状态不得降级成无条件事实。

## 7. 调度、资源与可运行性

推荐一期可调整的内部预算，均需用评测校准，不做用户设置：

| 项目 | 默认设计 |
| --- | --- |
| 单轮主题数 | 最多三个，其中最多一个探索主题 |
| 单轮候选数 | 最多六条，不以凑满为目标 |
| 模型调用 | 每批通常一次提案、一次核验；若首轮发现具体且可解的材料缺口，可再补一次核验，总计最多三次；失败计入总预算 |
| 本机取证 | 通常一批，必要时仅增加一批具体取证；模型不能以“继续看看”无限扩展，来源不具备的数据则等待新记录/补问 |
| 输入/输出 | 按模型 token 与协议字节双限额；首版提案输入预算 8k、输出 1.5k，核验输入 6k、输出 1k，均为待测上限 |
| 同一证据集 | 同阶段和同计划不重复处理；允许恢复未完成阶段，策略变动需显式限定重看范围 |
| 未变化的主题 | 不按打开 App 次数重复调用 |
| 历史导入 | 先近期开窗、再按主题补历史；不按导入当天当作生活骤变 |
| 前台体验 | 后台低优先级任务，不阻塞记账、对话、页面打开；低电量/温升让位 |
| 离线/超预算 | 记录变更与待办运行状态；继续使用仍有效的旧理解，不用空结果覆盖 |

明确表达的原链路与新链路必须共享去重与预算，不能把“原来的两次调用”再加上“新引擎两次调用”。发现页只消费结果，不再额外重新萃取全量数据。

当前 `config.js:903–915` 的默认后台限额为日 ¥0.30、月 ¥2，且全局有限额；包括其他后台用途。实施先测量可分配的剩余额度，再给新 purpose 配额。金额预算、开发池与实际模型价格仍由服务端现有计费真源管理，不在客户端复制一套价格表。

预期新鲜度以“有可运行窗口且资源允许”为前提：明确纠正本机即时生效，日常增量在下一个合格运行周期处理；需要新时段验证的关系等待真实新证据。没有新证据时不以定时任务重复请求模型。

## 8. 双端改造清单与分阶段切换

| 工作包 | 主要位置/新增职责 | 完成条件 |
| --- | --- | --- |
| 统一观察 | `MemorySignals`、`HoloLifeSourceObservation`；新增观察索引与能力目录 | 七域来源口径核对；原事件时间/单位/缺失可表达 |
| 主题与提案 | 复用 `PersonalContext` 检索；新增主题包与本机运行协调 | 跨域原始线索能召回；陌生主题可进入探索 |
| 本机取证 | 复用严格查询、跨域读工具与对齐计算；新增 EvidenceRequest 路由 | 无任意写操作；返回真实覆盖与失败原因 |
| 语义核验与采用 | 后端新增版本化提案/核验用途；本机扩展 Knowledge 准入 | 明确表达、角色、偏好、状态、关联分别判定 |
| 记忆使用 | `HoloMemoryContextEnvelope`、个人情境检索及读取桥 | 上下文中保留条件、时效、推断身份；相关回答改善 |
| 补问与主动发现 | 既有澄清协调器、Discovery 选题层、记忆中心 | 同一知识权威，按价值提问、去重、不反复打扰 |
| 服务端基础设施 | 复用模型网关、预算、任务加密、认证；增加新 purpose 注册 | 新用途受所有预算和授权约束，任务销毁可验证 |

新契约至少带 `schemaVersion`、`policyVersion`、`sourceRevisionDigest`、`scopeVersion`、候选/证据引用与失败原因。后端真实响应是接口形状真源，iOS 必须用对应真实 JSON 夹具解码测试。

双端 Prompt 同步：iOS `PromptManager.swift` 后备模板、后端 `defaultPrompts.json`、`promptRegistry.js` 版本和用途注册一并改；实施后必须明确提醒部署后端。未经授权不部署，不把本地测试当线上生效。

先做影子运行，旧写入保持原样，新候选不影响用户回答；达到门槛后按生产者切换。自动采用、主动发现、补问分开启用但共享同一采用规则，避免一处认为“待验证”，另一处已经当事实使用。

旧客户端继续走原契约，新字段采用增量兼容。回退关闭新用途和新生产者，客户端保持可读、可纠正、可遗忘；不得回退用户控制版本。具体发版版本号在实施时根据当前分支重新确定。

兼容实现优先使用可选扩展元数据，避免向旧客户端必解码的枚举直接塞入新值。新理解回投旧记忆格式时，只有旧读取路径能够完整保留限定语义才允许投影；做不到则不把该理解暴露给旧消费端。任何路径都不能通过写成 `confirmed` 来绕开旧准入。此项必须用旧版本解码与回答读取夹具证明，不能仅靠新版本自测。

## 9. 验证范围与仍需实施取证的事项

已明确的架构选择不再把常规实现问题交给东林选择。实施前仍需通过代码和隔离测试确认：

- 习惯体重的单位、实际测量时间与历史编辑事件是否完整进入观察；财务补账时间精度能否可靠标识。
- 健康读取的数据覆盖、来源切换、空结果和查询失败是否在各入口保持不同状态。
- 知识修订/旧记忆桥接对新增自动采用等级的语义是否一致，旧客户端是否可能误当确定事实。
- 新上送字段是否全部在当前授权和用户承诺范围内；不满足则减字段，或在实施前明确需要变更的授权。
- 云任务新用途的重启恢复、密文清理与幂等成本是否真实跑通。
- 多设备控制冲突及敏感分区行为是否经真机/隔离同步验证。

这些是工程验收工作，不影响当前产品方案评审，也没有在本轮被宣称已验证完成。验收案例与量化门槛见 [效果验收](02-场景与效果验收.md)。
