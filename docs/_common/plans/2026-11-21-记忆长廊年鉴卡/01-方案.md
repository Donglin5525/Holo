> 状态：已实施（2026-11-21，三步同日完成；2b「附一句话」待东林看真机后再定）
> 原型：`docs/design/2026-11-21-年鉴点阵-替换热力图原型.html`（初版）、`docs/design/2026-11-21-年鉴点阵-去密集感方案.html`（定稿 D / A）

## 一、拍板结论

| 决策 | 结论 | 理由 |
|---|---|---|
| 长廊年鉴卡画法 | **D：目录式 12 条月度条 + 展开某月的每日刻度** | 365 个大小不一的圆点 + 空心圈有密集恐惧感；D 平时只有 12 条长条，需要细节时展开一个月 |
| 分享图画法 | **A：12 行 × 31 列，同样大小的点，只画记过的日子，3 档深浅** | 东林最初喜欢的点阵样子；分享图只看一次，密集感可接受；去掉大小差异与空心圈后孔洞感大幅降低 |
| 排法 | 按月排（行 = 月，列 = 几号） | 外行能直接找到某一天；365 天不出孤点 |
| 时间范围 | 自然年，可翻看往年 | 「年鉴」概念成立；年初是一本空白新本子 |
| 分享图文字 | 默认不附；「附一句自己的话」列为 2b 步，不阻塞 | 避免分享时意外带出个人内容 |

## 三、数据口径（唯一真源，不新增口径）

- 每天的「件数」= 记账（`Transaction.date`，未删除）+ 习惯记录（活跃习惯，排除取消打卡）+ 完成的任务（`completedAt`）+ 想法（`createdAt`，未归档未删除）。**与现有热力图、长廊「记忆总数 / 记录天数」口径完全一致。**
- 窗口：现有 13 周 → 自然年 `[1/1, 次年 1/1)`；翻看往年时按需加载该年。
- 「开始记录日」= 四类记录中最早的一条的日期（各取 `fetchLimit = 1` 升序），用于区分「还没开始」与「没记」。
- 档位（3 档，卡片刻度与分享图点阵共用）：1–2 件 = 少，3–5 件 = 中，6 件以上 = 多。

## 四、数据结构（纯值类型，可单测）

```swift
/// 某一年的年鉴：由「按天件数」+ 今天 + 开始记录日 纯函数生成
struct MemoryAlmanacYear: Equatable {
    let year: Int
    let months: [MemoryAlmanacMonth]   // 恒为 12 个
    let recordedDays: Int              // 有记录的天数（大数字）
    let totalCount: Int                // 件数合计
    let dayOfYear: Int?                // 仅当年有值（「今年第 N 天」）
    let startDate: Date?               // 开始记录日落在本年时有值（新用户副行）
}
struct MemoryAlmanacMonth: Equatable {
    let month: Int
    let state: State                   // .notStarted / .past / .current / .future
    let recordedDays: Int
    let dayCount: Int                  // 当月天数
    let days: [MemoryAlmanacDay]
    enum State { case notStarted, past, current, future }
}
struct MemoryAlmanacDay: Equatable {
    let date: Date
    let count: Int
    let level: Int                     // 0 没记 / 1 少 / 2 中 / 3 多
    let kind: Kind                     // .notStarted / .past（level 0 = 没记）/ .today / .future
    enum Kind { case notStarted, past, today, future }
}
```

生成器：`MemoryAlmanacBuilder.build(year:dayCounts:today:firstRecordDate:calendar:) -> MemoryAlmanacYear`。
查询：`MemoryDayCountQuery`（从 ViewModel 抽出，现有热力图口径原样搬迁，供年鉴与旧调用共用）。

## 六、交互与视觉规格（D 卡）

- 外框：`holoSurface(.independent)`，与洞察 Tab 其他卡同一语言。
- 刊头：「人生年鉴 · 2026」（metadata，字距）+ 左右翻年箭头（44pt 热区；最早到开始记录那年，最晚到今年）+ 分享按钮。
- 大数字：`holoHeroNumber(size: 44)`「244」+「天有记录」；副行「共 1,238 件事 · 今年第 325 天」/ 往年「共 N 件事」/ 新用户「共 6 件事 · 从 11月19日 开始记录」。
- 12 条月度条：长度 = 当月有记录天数 / 当月天数；右侧「18 天」，未来和开始前的月份显示「—」；当月末端橙点。
- 展开：默认展开当月（往年默认不展开）；点任意已发生的月份切换展开，再点收起；展开区是一行加高的每日刻度（3 档高度，没记留空，今天橙色）+ 日期轴 1 / 10 / 20 / 月末。
- 选日：展开区内点按或长按拖动 → 选中刻度加深 + 提示行「11月18日 周三 · 3 件事」→ 下方沿用现有「当天轨迹」伴生卡（`selectedHeatmapDate` / `ensureWeekLoaded` 原链路）。
- 动效：展开 / 收起用 `HoloAnimation.standard`，减少动态效果时直接切换。
- 无障碍：整卡读「2026 年，244 天有记录，共 1,238 件事」；每条月度条是按钮「11 月，17 天有记录」；展开区每天可聚焦。

## 八、对抗审查（动工前自查）

| # | 质疑 | 结论 |
|---|---|---|
| 1 | 全年查询会不会拖慢长廊首屏？ | 现有快照已在后台 context 计算；一年的按天计数是 4 个字典结果查询，量级与现有「记忆总数」统计相当。快照未就绪时卡片显示骨架，不阻塞（遵守「默认值先渲染 + 后台补数据」）。 |
| 2 | 大数字「天有记录」与长廊顶部「记录天数」不一致？ | 前者是**本年**，后者是**全部**，副行与刊头都写明年份，不会混淆；口径同源。 |
| 3 | 1 月 1 日刚过，本年几乎全空，会不会显得冷清？ | 刊头可翻回去年；本年当月展开后有今天的橙色刻度，原型已验证观感。 |
| 4 | 开始记录日之后又删光了数据怎么办？ | 开始记录日按「现存最早记录」实时计算，删光则整年为「还没开始」，大数字为 0、副行提示去记一条（空态四件套）。 |
| 5 | 展开区每天只有约 9pt 宽，点不准？ | 与现有热力图相同：点按或长按后左右拖动选日，命中按等分槽位计算，不要求点中细线。 |
| 6 | 新文件同时编进 macOS target？ | 是（文件夹同步）。手势覆盖层沿用现有 `#if canImport(UIKit)` 双分支；分享渲染沿用纪念日分享的双平台写法。 |
| 7 | `MemoryGalleryViewModel` 已超 800 行上限 | 本次只做净减：查询搬出，VM 只保留年鉴状态与加载调用。 |
| 8 | 分享图会泄露隐私吗？ | 默认只有数字和点阵，不含用户名、不含任何正文；「附一句话」需用户主动选择（2b）。 |
| 9 | 用户自定义的时区 / 周起始会不会错位？ | 统一用 `Calendar.current` 的 `startOfDay` 与 `range(of: .day, in: .month)`；不依赖周起始。 |

## 十、位置修正与验收（2026-11-21 东林反馈「没看到加在哪儿」）

- **根因**：年鉴卡沿用了原热力图的位置——在「域记忆」区块之后，而域记忆逐张排出全部记忆卡（真机 1900+ 张），等于不可达。原热力图同样埋在这里，属继承问题，实施时未核查入口可达性。
- **修正**：窄屏洞察页把年鉴卡上移到「它看懂了你」报告卡之后、域记忆之前；iPad 双栏右栏本就排第一，不变。
- **教训**：替换既有组件时，不能默认「原位置 = 合理位置」，交付前必须用真实数据走一遍用户入口，确认第一眼能找到。
