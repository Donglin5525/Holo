# Holo 目标系统 v2 — 主线化方案

> 本文是 [Holo 目标系统 v1 设计](2026-05-17-Holo目标系统v1设计.md) 的演进，不是另起炉灶。v1 搭好了"目标"的骨架（数据模型、AI 规划生成、授权感知），v2 要让目标从"挂件"变成贯穿 Holo 每一次交互的"主线"。

## 一句话定位

v1 解决了"目标怎么被创建出来"；v2 要解决"**目标怎么真正活起来、被持续看见、并主动牵引用户和 AI**"。

---

## 一、为什么要做 v2（现状诊断）

v1 的骨架是完整的：Goal 实体结构齐全、能持久化、有 iCloud 同步、AI 通过多条链路能读到它。但它落地后的实际状态是**"能跑，但没立住"**——目标更像一个挂在"我的"页里的挂件，而不是贯穿全 App 的主线。具体三个症状：

### 症状 1：目标"立不住"——生命周期是断的

- 目标**只能由 AI 通过多轮对话生成**，没有直接手填创建入口。
- 创建后，标题、说明、领域、截止日期、期望结果、动机这些核心字段**几乎全部锁死**——`GoalRepository` 没有 update 方法，详情页只能改状态和 AI 授权开关。
- 目标是会变的：用户的想法会变、deadline 要调、方向做着做着要修正。一个用户自己都改不了的目标，谈不上"持久"，只是"固化"。

> 类比：造了栋房子，盖完之后门窗位置都不能动。这房子迟早被嫌弃。

### 症状 2：AI"不主动"——感知是不稳定的

这是 v2 的核心驱动力。现状是 AI 对目标"看运气"：

| AI 链路 | 现状对目标的感知 |
|---|---|
| 普通聊天 | 硬编码只注入 **1 个**活跃目标（`UserContextBuilder.buildGoalContext(limit: 1)`）。多目标用户会漏。 |
| Agent 深度分析 | **默认完全不注入**目标，模型必须主动调 `goal` 工具才能看到。调不调看模型心情。 |
| 对目标本身 | AI 是**只读**的——能看，但不能改标题、不能关联任务、不能切换可见性。"会看不会干活"。 |

所以"HoloAI 时时刻刻围绕目标"，目前只能算"偶尔瞟一眼目标"。

### 症状 3：目标"连不上"——它是孤岛

- 任务有 `goal` 字段，但任务列表/今日看板根本不显示"属于哪个目标"。用户每天用任务页、开看板，完全感觉不到目标的牵引。
- 今日看板和目标完全隔离：看板展示"今天做了多少事"，但通篇不提"这些事跟目标有没有关系"。

## 二、v2 要做的事（功能清单）

共 6 项功能，分三层推进。**顺序不能乱**——地基不牢就搞上层建筑，后面会塌。

| 层 | 功能 | 一句话 |
|---|---|---|
| 🏛 地基 | 1. 目标可手工创建+可编辑核心字段 | 让目标"能活" |
| 🏛 地基 | 2. AI 能在对话中改目标 | 让 AI 对目标"能动手" |
| 👁 感知 | 3. 统一 AI 对目标的感知深度 | 让 AI 无论哪条链路都"稳定看见"目标 |
| 👁 感知 | 4. 任务/习惯反向展示目标归属 | 让用户在日常中"持续感知"目标 |
| 🌅 主动 | 6. 今日看板关联目标（Hero 点睛+行标签） | 让目标"登上第一屏" |
| 🌅 主动 | 7. AI 主动围绕目标的建议/提醒 | 让 AI "主动开口"牵引 |

> **关于跳过的功能**：东林决定不做"想法↔目标打通"。尊重这个取舍，但提醒：做完功能 4 后，任务和习惯都能挂目标，唯独想法不能，会出现不对称。留待后续评估，不影响 v2 主线。

### 分期与依赖关系

```
一期·地基（功能 1 + 4）
  ├─ 目标变"可活"，风险最低、相对独立
  └─ 同时让用户开始习惯"到处能看到目标"
        ↓
二期·AI 主轴（功能 3 + 2）
  ├─ 3 必须先于 2：AI 得先稳定"看见"目标，才有资格"动手改"
  └─ 这期做完，AI 才真正"围绕目标"
        ↓
三期·主线+主动（功能 6 + 7）
  ├─ 6 让目标登上第一屏（今日看板）
  └─ 7 是收尾高潮，依赖前面全部就位——AI 看得见、改得动、目标是活的，主动建议才不会说错话
```

## 三、功能详细设计

### 🏛 功能 1：目标可手工创建 + 可编辑核心字段

**要解决的问题**：目标只能 AI 生成、生成后锁死。用户掌控不了的东西，不会当真。

**设计**：

| 入口 | 现状 | v2 调整 |
|---|---|---|
| 创建 | 只有"让 HoloAI 规划目标" | 增加"手动创建"，直接进表单 |
| 编辑 | 详情页只能改状态、AI 开关 | 详情页增加"编辑"，可改全部核心字段 |
| 删除 | 已有 | 保持 |

**创建/编辑表单字段**（从上到下）：

1. 标题（必填）
2. 领域（学习/健康/职业/财务/生活/项目/其他——复用 v1 的 `GoalDomain` 枚举）
3. 期望结果（一句话：达成后是什么样）
4. 说明（补充细节）
5. 动机（为什么要这个——**这是功能 7 AI 主动建议的燃料**）
6. 截止日期
7. 是否允许 HoloAI 引用（默认建议打开——主线就是让 AI 围绕目标）

**关键场景**：
- 用户突然想到一个目标，想 10 秒记下来，不想跟 AI 啰嗦 → 手动创建。
- 目标做了两周，发现 deadline 不现实 → 进详情页改日期。
- 想法变了，把"学英语"的期望结果从"考过雅思"调成"能日常对话" → 编辑期望结果。

**实现要点**：
- `GoalRepository` 新增 `updateFields(...)` 方法（v1 只有 `updateStatus` 和 `updateAIContext`）。
- 手动创建走 `Goal.create(...)`，不走 `GoalPlanningCoordinator`。
- 创建/编辑表单复用 v1 `GoalDraftReviewView` 的字段 UI，提取为可复用的表单组件。

**验收标准**：
- 用户全程不碰 AI，能独立完成"创建 → 修改 → 删除"全生命周期。
- 编辑后，AI 那边能立刻感知到新值（下一轮对话注入的就是更新后的目标）。

---

### 🏛 功能 2：AI 能在对话中改目标

**要解决的问题**：现在 AI 对目标是"只读"。用户跟 AI 说"帮我把健身目标延期到下个月"，AI 做不到。

**设计**：给 AI 的 goal 工具增加"写"能力，覆盖三类操作：

| 操作 | 用户会怎么说 | AI 做什么 |
|---|---|---|
| 改目标字段 | "把英语目标的截止日期改成年底" | 更新 deadline |
| 关联/取消关联 | "这个任务归到我读书目标下" / "这个习惯别关联健身目标了" | 建立/解除 task↔goal、habit↔goal 关联 |
| 切换 AI 可见性 | "别让 AI 看到我的财务目标" | 关掉 allowAIContext |

**关键产品决策——改目标要不要确认？** 采用风险分档：

| 风险等级 | 操作 | 处理方式 |
|---|---|---|
| 低风险 | 关联任务、改 AI 可见性、改状态(暂停/恢复) | 直接改，改完告知用户（可撤销） |
| 高风险 | 改标题、期望结果、动机、deadline、**删除** | **改前弹轻确认**（复用 v1 "想法转任务"的确认交互） |

**为什么这样分**：目标对用户的心理权重高（不像记一笔账那么随意），完全免确认会让人不踏实；但每改一下都确认又太累。按风险分档是最合理的折中。改"身份"的字段要确认，改"关系"和"开关"的字段不用。

**实现要点**：
- `HoloGoalTool`（v1 是只读 data tool）新增写操作能力，或新增一个 `HoloGoalWriteTool`。
- 高风险操作走确认流——复用 Holo 已有的"AI 操作确认"机制（`想法转任务`的确认环节）。
- 工具的写入最终都调 `GoalRepository` 的对应方法。

**验收标准**：
- AI 能完成上述三类操作，高风险操作有确认环节。
- 所有 AI 改动，用户在目标页能看到结果，且能手动改回来。

---

### 👁 功能 3：统一 AI 对目标的感知深度

**要解决的问题**：v1 两条 AI 链路对目标感知深度不一致，是"HoloAI 围绕目标"的最大障碍。

**设计**：

**(a) 普通聊天链路**——把 limit 从 1 提到合理数量（**默认 3**，可配置）。注入优先级排序：
1. 最近有更新的（updatedAt 最新）
2. deadline 最近的目标
3. AI 可见（allowAIContext=true）的活跃目标

注入内容必须完整，不只标题：**标题 + 状态 + 期望结果 + 动机 + deadline + 关联任务/习惯的进度**。其中"动机"和"期望结果"是功能 7 AI 主动建议的关键燃料。

**(b) Agent 深度分析链路**——在 Agent 初始上下文里默认带上"活跃目标摘要"（一段精简文字），而不是让模型自己猜要不要调工具。详细的逐目标进度，仍保留让 AI 按需调 `goal` 工具拉取。

**实现要点**：
- `UserContextBuilder.buildGoalContext(limit: 1)` → 提到 `limit: 3`（或读取配置）。
- `HoloAgentPromptBuilder.build(...)` 当前完全不接收 UserContext（v1 设计如此），需要新增一个"轻量目标摘要"注入点，只注入目标摘要这一段，不全量注入 UserContext（避免 Agent 上下文过载）。
- **token 预算约束**：普通聊天注入"摘要级"（每目标 1-2 行，最多 3 个），Agent 工具保留"详情级"按需拉。这是成本与效果的权衡。

**验收标准**：
- 用户有多个活跃目标时，普通聊天里 AI 都"知道"，不漏。
- 深度分析时，AI 第一轮就能看到目标，不靠运气。
- 感知内容包含动机/期望结果，不只是标题。

---

### 👁 功能 4：任务/习惯反向展示目标归属

**要解决的问题**：任务有 goal 字段，但任务列表/详情根本不显示归属，用户感觉不到目标牵引。

**设计**：
- 任务列表行、任务详情：标题旁加目标标签（药丸样式），显示"📍 属于：XXX 目标"，点击跳目标详情。
- 习惯列表/详情：同样处理。
- **没有关联目标的，不显示标签**——保持干净，不强加视觉噪音。
- 标签用目标 domain 的颜色和图标（复用 v1 `GoalDomain` 已有的 SF Symbol 和配色：学习📚/健康💪/职业💼/财务💰/生活🌿/项目🔨/其他）。

**为什么值得做**：成本最低、对"目标存在感"提升最明显的功能。用户每天进任务页好几回，每回都瞥一眼目标标签，潜移默化建立"我的日常在服务我的目标"的认知。

**实现要点**：
- 这是一套实现，**同时用在今日看板（功能 6）和任务/习惯列表页**，开发成本摊薄。
- 数据层 v1 已就绪（`TodoTask.goal` / `Habit.goal`），纯 UI 工作。

**验收标准**：
- 任何关联了目标的任务/习惯，在列表和详情都能看到归属，点击可跳转。
- 不关联的不显示。

### 🌅 功能 6：今日看板关联目标（Hero 点睛 + 行标签）

> 说明：原方案 v2 曾考虑"首页加常驻目标进度卡"，东林明确否决——**首页结构不可变更，加任何东西都会破坏协调**。改为"寄生"在已有今日看板里。

**要解决的根本问题**：今日看板现在的叙事是"你今天做了多少事"。引入目标后，叙事应变成"**你今天做的这些事，有多少是在为你真正在意的事情添砖加瓦**"。目标给今日看板补上"意义锚点"。

**核心概念——区分"总进度"和"目标贡献"**：

| | 总进度（现有） | 目标贡献（新增） |
|---|---|---|
| 算什么 | 今天该做的事完成了多少 | 今天完成的事里，有多少关联着目标 |
| 回答的问题 | 我今天忙不忙 | 我今天忙得值不值 |
| 数据源 | 任务完成率 + 习惯打卡率 | 其中带 goal 字段的那些 |

这个区分很重要，因为它们经常**不一致**——而"不一致"恰恰是最有信息量的时刻：看板在诚实告诉用户"你今天很忙，但目标在原地"。**"做了多少"是效率，"做对了没"是意义。**

#### 落点：方案 B（Hero 点睛 + 行标签）

今日看板现状（`DailyKanbanView`）：6 个纵向堆叠的卡片——Hero 进度卡、预算卡、习惯卡、任务卡、记录卡、健康卡。和目标**零关联**（grep 整个 `Views/DailyKanban/` 只有习惯数值目标的 3 处命中，与 Goal 实体无关）。但底层数据已连好（Goal.tasks/habits），看板侧只需读取即可关联，不需改数据模型。

方案 B 做两件事，配合使用：

##### ① Hero 卡的"目标点睛"（最关键）

位置在 Hero 卡现有进度文案下方，加一行。根据数据分支显示：

**有目标 + 今天有相关行动**（最常见）：
```
80%  ·  5件事在为目标添砖加瓦 🎯
```
"5件事"= 今天完成/打卡的、且带 goal 字段的任务+习惯数量。

**有目标 + 今天的事都没关联目标**（最有教育意义）：
```
80%  ·  今天还没有行动落在目标上
```
看板在诚实提醒"你在空转"。语气平淡，不指责。

**有目标 + 今天还没做任何事**：
```
0%  ·  开始今天的第一件事，或为你的目标迈一步
```

**没有目标**：
```
80%  ·  设个目标，让每天的忙碌有方向 →
```
"→"可点击，跳到目标创建页（呼应功能 1 的手动创建入口）。**这是目标拉新的重要入口**——在用户最有"我做了这么多事，但图啥"感受的时刻递上入口。

**文案语气原则**：不用"加油""你真棒"这种空话。用陈述事实的语言。Holo 的调性是诚实陪伴，不是打鸡血教练。

##### ② 任务行 / 习惯行的目标标签

在任务名、习惯名旁加药丸标签：
```
✓ 复习英语单词第10课        [📚 学英语]
✓ 跑步30分钟               [💪 健身]
○ 写周报                    （无标签）
```

- 标签用目标 domain 颜色/图标（复用 v1 `GoalDomain`）。
- 没有关联目标的不显示标签。
- 标签可点击跳目标详情。
- **这是功能 4 的同一套实现**，在今日看板场景的复用。

##### ③ 为什么"目标贡献"不放进 Hero 底部那 4 个 stat 格

Hero 卡底部现有 4 格统计：打卡 / 待办 / 睡眠 / 今日支出。

**明确不放进第 5 格。** 原因：那 4 格是"客观量纲"（打卡数、睡眠小时、花了多少钱），而"目标贡献"是"意义量纲"——它不是第 5 个并列数字，而是**对前面那些数字的重新解读**。塞进第 5 格就降级成和"睡眠 7.2h"平级的数字，丢了"点睛"作用。**它应该是那句话，不是那个格子。**

#### 方案 B 成立的理由

1. **零结构破坏**：看板还是 6 张卡，顺序不变。只在 Hero 加一句话、行上加标签。协调感保住。
2. **第一眼建立连接**：用户打开看板，最显眼的 Hero 就有"5件事在为目标添砖加瓦"。
3. **诚实不打鸡血**：忙了一天但没碰目标时，直接说"今天还没有行动落在目标上"。

#### 待东林确认的点

Hero 那句话的"目标贡献"是否**始终显示**（哪怕今天没做事也显示"0 件/还没开始"），还是**只在有目标关联数据时才显示**？
- 建议始终显示——"今天还没有行动落在目标上"本身有提醒价值。
- 若大部分用户大部分天都不碰目标，会显得"挑刺"，则改为有数据才显示。

**实现要点**：
- `KanbanProgressHero` 增加目标贡献计算和文案渲染。
- `KanbanTaskSection` / `KanbanHabitSection` 的行视图增加目标标签（复用功能 4 的标签组件）。
- 数据源：复用 `TodoRepository+Kanban` 现有查询，额外按 `task.goal != nil` 过滤统计。

**验收标准**：
- Hero 卡显示目标贡献文案，且按四种分支正确呈现。
- 任务/习惯行显示归属标签，无关联的不显示。
- 无目标用户的 Hero 文案引导到创建目标入口。
- 看板整体结构（6 卡顺序）不变。

### 🌅 功能 7：AI 主动围绕目标的建议/提醒

**要解决的问题**：真正的"时时刻刻围绕"——不只是 AI 被问到能答，而是会**主动开口**。这是整个 v2 的制高点，也是 Holo 区别于普通记录工具的地方。**强依赖前面所有功能就位。**

**设计**：在 AI 决策层加规则——**当检测到用户当前行为与某目标相关（正向或偏离）时，在回复里自然关联目标**。

| 场景 | 用户行为 | AI 主动说什么 |
|---|---|---|
| 消费偏离 | 记了一笔大额非必要支出 | "这笔支出后，你这个月离'存 5000'的目标还差 1200，注意节奏。" |
| 习惯断档 | 连续 3 天没做目标关联的习惯 | "注意到你最近没跑步——离你的健身目标进度掉队了，要不要今天补一下？" |
| 任务脱节 | 创建的任务明显跟某目标相关但没关联 | "这个任务看起来跟你的'学英语'目标挺配，要归到那个目标下吗？" |
| 正向靠近 | 完成了一个目标关联的关键任务 | "这个完成了，你的'上线项目'目标已推进到 75%，势头不错。" |

**三条护栏（核心风险是"打扰"）**：
1. **频率控制**：同一目标短期内不重复提醒（默认**一天最多主动提一次**）。
2. **语气自然**：是"顺带一提"，不是"跳出来教育"。融入正常回复，不单独弹窗。
3. **可关闭**：目标详情里能针对单个目标关掉"主动提醒"。

**关键设计决策——"可关闭"和 allowAIContext 是两个独立开关**：
- `allowAIContext`（v1 已有）：AI 能不能"看"到这个目标。
- `proactiveNudge`（v2 新增）：AI 看到之后要不要"主动开口"。
- 逻辑：allowAIContext=false 时，proactiveNudge 无意义（看不到就谈不上主动）。allowAIContext=true 时，用户可单独关掉主动提醒，保留 AI 被动引用的能力。

**实现要点**：
- Goal 实体新增 `proactiveNudge: Bool` 字段（默认 true）。
- Prompt 层（`defaultPrompts.json` 的 system_prompt）增加目标关联建议规则。
- 频率控制：需要记录"某目标上次主动提醒时间"，可用现有记忆/信号机制（`MemorySignalDataAdapter`）承载。
- **依赖**：功能 3（AI 稳定感知目标，含动机/期望结果）+ 功能 2（AI 能动手）必须先就位，否则主动建议会"说错话"或"光说不做"。

**验收标准**：
- AI 在四类场景中，能给出与目标相关的、自然的反馈。
- 同一目标一天内不重复主动提醒。
- 用户能在目标详情关掉单个目标的主动提醒。

## 八、验收（v2 整体）

v2 完成后，"目标成为主线"应可被以下场景验证：

1. **目标能活**：用户不碰 AI，独立完成创建→修改→删除；AI 也能在对话中帮用户改目标。
2. **目标被看见**：用户有多个活跃目标时，普通聊天和深度分析里 AI 都知道；任务页、今日看板都能看到归属。
3. **目标会主动**：AI 在用户行为偏离/靠近目标时，自然地关联目标给出反馈，且不高频打扰、可关闭。
4. **今日看板有意义锚点**：用户打开看板，第一眼就知道"今天做的事有多少在为目标添砖加瓦"。
5. **首页结构不变**：没有破坏首页既有协调感，目标通过今日看板"寄生"呈现。
