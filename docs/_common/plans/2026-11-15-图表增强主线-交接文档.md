## 3. 致命缺陷诊断：现金流瀑布「所有内容堆叠」

### 数据链路（供验证假设）

`FinanceAnalysisState.cashflowItems(points:expenseAggregations:incomeAggregations:)`（纯函数，`Holo/Holo APP/Holo/Holo/Models/FinanceAnalysisState.swift`）：
- 期初 = 首桶余额回推（`balance − income + expense`，统计口径，首桶含对账调整有微小偏差）
- 收入取最大类命名 + 其余并「其他收入」；支出前三大类 + 「支出·其他」
- 期末 = 末桶余额（含对账调整，与余额线同口径）
- 渲染：`HoloWaterfallChart`（`Components/Charts/HoloWaterfallChart.swift`），锚点柱从 0 画到存量值，步骤柱按 delta 画增量，柱端 `.annotation` 数字标签，水位虚线连接，Y 轴 `niceDomain(含 0)`。

### 高置信根因（下一个模型请先验证再动手）

**存量与流量量级差两个数量级，锚柱把 Y 轴撑爆。** 东林真机数据：期初/期末锚柱画的是**账户余额存量**（可能 ¥10 万+），而中间步骤是**月度流水**（工资 ~1.2 万、房租 ~2200、餐饮 ~1200）。锚柱从 0 画到十几万 → Y 轴全域 0–15 万 → 所有流水段的柱高不足全高 1–3%，全部挤在水位线附近的一条窄带里，柱端数字标签互相叠死——这就是「所有内容堆叠到一块儿」。

**为什么测试没拦住**：画廊样板数据是我编的温和量级（320/900/420/260/540），量级差 <3 倍，视觉正常。**原型数据同样温和——原型假设在真实量级下破产，这是我的核心失误，不是测试通道问题。** 教训入档：涉及量级的图型，验收必须用真实量级的极端样本。

### 修复方向（按推荐顺序，A/C 可组合）

- **A（推荐）：瀑布按「流量」定标，锚柱退出 Y 轴竞争。** 期初/期末不再画 0→存量的柱，改为：Y 轴只覆盖流量区间（期初水位为基线，`chartYScale` domain 从期初水位减少量余量起）；期初/期末用左右两端的标注文字（「期初 ¥152,000」「期末 ¥163,406」）+ 水位基线表达。本质：瀑布讲的是「钱的流动」，存量只配当基线和终点标注。
- **B：Y 轴截断（不从 0）。** 保留锚柱但 domain 起点 = min(水位) − 余量；锚柱画不完整（视觉断裂），需加断裂符号，易被质疑误导，不如 A 干净。
- **C：小量级段的标签避让。** 段高 < 全高 8% 时柱端不标数字，改到点击读数或图下列单——无论 A/B 都建议带上。
- **D（如果 A 重做后东林仍不满意）：承认瀑布不适合「余额存量大、月流量小」的个人账本形态**，退回「净流入大数字 + 分类排行条」的表达（`HoloHorizontalBarChart` 现成）。原型第 7 条的本意是「钱去哪了一图讲清」，达成路径不止瀑布一条。
- 注意：`HoloWaterfallChart.levels(for:)` 纯函数语义（锚点重置水位）已被 12 例单测锁定（`HoloTests/Components/HoloChartEnhancementTests.swift`），改渲染层不用动它；若改数据结构（如去掉锚柱）测试同步改。
