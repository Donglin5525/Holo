# Holo 记忆管理独立与升级实施方案

版本：v1.0 · 日期：2026-10-23（北京时间）  
状态：产品与工程评审稿；本轮只交付方案，未修改 App、未运行功能验收、未部署后端。

## 0. 先看这一页

### 0.1 产品决定

建立独立的「Holo 记忆」页面，让用户回答三个问题：Holo 记住了我什么？这些理解从哪里来、现在是否适用？我怎样纠正或停止使用它们？

记忆长廊负责回看生活和阅读洞察；Holo 记忆负责管理被保存的理解。二者共用来源与数据，不复制一份记忆。

**硬边界：有圆球的 Holo 首页布局、圆球绘制与动效、模块位置、底部导航布局全部不改。本文“管理页”“默认视图”均指新记忆页面。** 必要的路由注册允许接入现有导航宿主，但不得借机调整首页视觉或交互。

| 决策 | 推荐方案 |
|---|---|
| 页面名称 | Holo 记忆；个人页保留熟悉的入口文案「Holo 记住的你」 |
| 固定入口 | 个人页直达；HoloAI 对话页右上角「记忆」直达 |
| 页面主要视图 | 「已记住」「观察中」；过去和停用内容放次级入口 |
| 默认组织 | 已记住按「最近这段时间」「长期了解」分组；领域作为筛选条件 |
| 确认定位 | 用户主动校准；相关对话中只询问会影响当前结果的关键歧义 |
| 管理能力 | 确认、纠正、标记过时、不准确、停用、恢复、删除、添加、批量整理 |
| 设置 | 复用统一 HoloAI 设置与既有记忆开关，不产生第二份配置 |
| 技术方式 | 复用现有 Repository、决策层和来源链；补统一管理投影、用户控制事务与必要历史 |
| 首批完成标准 | 找得到记忆，能查看依据和修改；保存成功后下一次相关使用遵守修改结果 |

### 0.2 首批与后续的区别

**首批 V1**：独立页面与入口迁移；全部记忆的基本搜索筛选；来源详情；确认/纠正/过时/不准确/停用及安全恢复；操作记录与撤销；所有消费者遵守用户控制；既有设置归位；删除与防重建的清理闭环。

**后续 V1.1**：主动添加、批量整理、到期日期编辑、辅助冲突处理、重复合并、完整使用追溯、单次对话关闭记忆。后续能力写在本方案中，但不拿未实现按钮占位，也不把它们算进首批已完成。

首批的“下一次回答生效”包括查询、缓存、请求提交和结果呈现的版本校验，不能只改列表文字。恢复和删除若未通过相应数据门禁，首批不得宣称管理闭环完成。

## 1. 当前实现与问题依据

以下来自 2026-10-23 查阅的工作区源码；工作区存在大量在途改动，不代表已发布版本或手机实际运行结果。实施开始前记录 HEAD、相关未提交文件和有效功能开关，不能覆盖其他会话的工作。

| 已核对事实 | 用户影响 | 本次处理 |
|---|---|---|
| `PersonalView` 的「Holo 记住的你」进入 `PersonalMemorySettingsView`，再进入长廊 | 管理内容要穿过设置中转页 | 个人入口改直达管理页，开关移至统一设置路径 |
| `DomainMemorySection` 在长廊洞察内承担领域分组、观察、过去记忆、反馈等 | 管理与阅读混在一起，长列表难定位 | 提取独立页面，长廊只保留短入口 |
| `HoloMemoryAttentionPolicy` 默认关闭每日确认收件箱 | 原待确认计数和队列默认不再形成日常任务 | 保持低打扰；重新设计主动校准的可发现性 |
| 「观察中」默认折叠，支持对/不对；详情支持纠正、停用 | 能力存在，但隐蔽、操作后效果不清楚 | 独立视图、明确状态、就地回执和撤销 |
| `noLongerUse` 已写 suppression 与语义墓碑；详情仍解释可能重新生成相似记忆 | 界面与底层语义不一致 | 统一停用文案、阻断范围与恢复规则 |
| `HoloMemoryRecord` 已有时间、来源、状态、决策元数据、版本号和使用计数 | 有基础可复用 | 不建立第二套记忆事实库 |
| 已见版本号与前驱引用，尚未发现完整历史正文实体 | 不能据此直接承诺完整版本历史和任意撤销 | 新增必要的用户操作记录；迁移前历史不伪造 |
| `HoloShortTermMemorySnapshot` 是单次流程组装的即时上下文 | “短期记忆”不全是可管理的持久化记录 | 管理页只管理持久化理解；当次上下文在回答依据中处理 |
| `HoloMemorySettings` 已有自动形成与回答使用两开关及迁移机制 | 重建配置会改变用户选择 | 保留原键和值，统一入口，不重新默认开启 |
| `AISettingsView` 是 Debug 配置页 | 直接公开会暴露模型、Key 等开发者配置 | 与统一 HoloAI 设置项目对接，不能解除 Debug 限制冒充用户设置 |

### 1.1 与既有方案的关系

延续 2026-09-16「低确认成本」方向：普通内容自动治理，只有关键歧义按需询问。此次提升管理可见性，不恢复每日审批队列，也不把所有 candidate 批量激活。

与 2026-10-23「一个发现与设置整合」项目共用正式 HoloAI 设置路由。该项目原“长期记忆 → 长廊管理”的目标更新为“记忆设置 → Holo 记忆”。「一个发现」的认可/关闭仍是发现自身反馈，不自动变成长期记忆确认。

## 2. 范围与不变量

### 2.1 本次涉及

- 个人页记忆入口、HoloAI 对话页导航操作、长廊中的记忆区块、记忆相关旧回执和深链。
- 新记忆管理页、详情、编辑/确认面板、过去与停用列表、记忆设置跳转。
- 用户控制的持久化、撤销、同步冲突处理；管理列表与 AI 使用规则的一致性。
- 原始来源编辑/删除/排除后的记忆失效；相关缓存、派生记忆和生成任务的处理。

### 2.2 保持不变

- 圆球首页及底部导航布局；日历、财务、任务、想法等主模块布局。
- 记忆长廊的日/周/月浏览、热力图、生活回放、洞察阅读等既有能力。
- 原始业务数据的所有权、授权与删除机制；管理记忆不直接修改账单、任务、习惯或目标。
- 已有关闭状态；不通过迁移替用户开启自动学习、外部 AI 处理或记忆辅助回答。
- 后端部署、签名、Bundle ID 和 CloudKit 容器配置。

### 2.3 必须始终成立

1. **可见不等于可用于回答。** 用户可以管理观察中、过去和停用内容，但它们不因此获得召回资格。
2. **确认不等于永久化。** 准确性、保存权限、适用时间和使用范围分别判断。
3. **用户控制优先于后台生成。** 延迟完成的观察、旧缓存、旧设备同步不得静默覆盖较新的停用、删除或纠正。
4. **保存成功才展示成功。** 失败保留草稿和最后有效状态；不把“按钮已点击”当成写入成功。
5. **不以管理界面重新生成事实。** 打开、搜索、筛选、普通编辑不调用模型，不产生分析费用。
6. **未实现不呈现。** 不显示无响应入口、不伪造修改历史、不补写假使用次数。

## 3. 信息架构与路径

### 3.1 入口矩阵

| 入口 | 目标 | 呈现与返回 | 特别要求 |
|---|---|---|---|
| 个人 → Holo 记住的你 | 管理页「已记住」 | 在个人导航栈内 push，返回个人页原位置 | 跳过设置中转；不关闭个人页再绕到长廊 |
| HoloAI 顶栏 → 记忆 | 管理页「已记住」 | 复用对话页单一 sheet 路由，内部 NavigationStack；关闭回原会话 | 保留输入草稿、会话、报告页状态、滚动位置 |
| 回答下「参考的记忆」 | 本次相关记忆列表 | 轻量面板 → 单条详情；关闭回原回答 | 不强迫用户在全部记忆里搜索 |
| 长廊洞察 → Holo 记忆 | 管理页「已记住」 | 依现有导航宿主进入，返回原洞察位置 | 长廊不再重复渲染完整记忆列表 |
| HoloAI 设置 → 记忆 → 管理记忆 | 同一管理页 | 正常 push/返回 | 与其他入口共享 ViewModel/服务契约 |
| 管理页 → 更多 → 记忆设置 | 统一设置的记忆子页 | 返回时保留列表视图、筛选、位置 | 不复制两个开关 |

HoloAI 右上角保留统一设置项目要求的设置入口，新增「记忆」文字操作；常规手机宽度下二者都有 ≥44pt 热区。大字体时可将设置收进同一更多菜单，记忆仍保持可发现。不得因此新增对话页 Tab 或改首页导航。

### 3.2 新页面组成

| 页面 | 主要内容 | 常用操作 |
|---|---|---|
| M01 Holo 记忆 | 标题、搜索、已记住/观察中、筛选、真实状态提示、列表 | 查看、筛选、进入详情；V1.1 增加添加 |
| M02 这条记忆 | 完整陈述、状态、适用时间、形成方式、来源、使用说明、操作记录 | 确认、纠正、过时、停用等 |
| M03 校准/编辑 | 陈述、原有时间范围、必要限定、来源提示 | 保存、取消；保留未保存草稿 |
| M04 过去的记忆 | 已过期、已被替代、来源失效等内容 | 查看原因、必要时重新核对 |
| M05 已停用 | 用户判错/主动停用的内容 | 查看、重新启用、删除 |
| M06 本次参考的记忆 | 与指定回答关联的条目及版本 | 查看/纠正；旧条目已删则显示不可用 |
| M07 记忆设置 | 两个既有开关、管理链接、明确数据说明 | 修改原配置 |

M04/M05 从 M01 更多菜单进入，不占据主分段。M03 作为当前导航宿主内的独立编辑页/统一弹层，不能在多个布尔 sheet 上叠加。

### 3.3 路由契约

建议新增目标（命名可遵循项目现有风格）：`memoryCenter(initialSection, focusRecordID?)`、`memoryDetail(recordID, versionID?)`、`memoryReferences(messageID)`。路由只携带 ID 和展示意图，不携带敏感正文。

- 内部旧“新记忆”提示改指管理页，不再借 `memoryGallery(focusNewMemories: true)` 进入长廊。
- 真正打开日历、回放、洞察报告的调用仍进入长廊。逐个审计调用点，禁止把所有 `memoryGallery` 一键替换。
- 已发布外部旧链接无法区分原意时，保留旧目标并给出迁移入口；可识别的“管理记忆”旧链接才转新页面。
- 记录不存在、已删除或不在本设备：展示具体不可用原因，不恢复正文、不自动跳到其他相似条目。
- 查看跨模块原始来源时，保留来源导航的 origin；返回不丢记忆筛选、编辑草稿或原会话。不能假设 dismiss 一个 sheet 就能正确穿越所有层级。

## 4. 管理页内容与展示规则

### 4.1 「已记住」

定义：仍处于适用期、来源与权限有效，决策允许作为事实或有限建议背景的持久化记忆。该名称不表示“每次回答都会使用”。

分组按确定性规则：

- **最近这段时间**：`currentState`、`phase`，或用户明确指定了临时适用范围的内容。
- **长期了解**：`durable`、`permanentFact` 且没有更窄的临时限制。这里包括偏好、明确事实和跨周期规律；“长期”不代表永远不检查来源和反证。
- 用户指定的更窄范围优先。未知类型不猜成长期，也不让用户替内部分类做选择。

组内默认按内容更新日期倒序，相同时间用稳定 ID 排序；使用计数/最后使用时间不能改变内容更新时间。正在阅读时不因后台更新突然重排，显示「有更新」供用户刷新。确认/纠正完成时允许局部移动并保留回执。

### 4.2 「观察中」

定义：有合理依据、值得保留，但当前尚不可作为确定记忆使用的内容，以及存在待厘清冲突的内容。

- 不显示红色待办数字，不在 App 图标、首页、推送中催用户清空。
- 页内说明：「这些理解还拿不准，暂不作为事实使用。你可以查看依据，或告诉 Holo 更准确的情况。」单条必须明确实际是“完全不使用”还是“仅可限定参考”，不能用总说明掩盖差异。
- 按现有决策模型，`qualifiedAdvice` 应在「已记住」中明确标“仅作参考”；`observeOnly`、未完成澄清的 `askWhenRelevant` 在观察中且不进入普通回答。
- 正常候选可提供「符合现在的情况」「改一下」「不符合」。来源已失效或权限已撤回时，不能靠“符合”按钮直接绕过来源门禁。
- 有多条时允许用户主动「逐条查看」，不默认进入审批流程；退出无损，无需处理完才允许离开。
- 不展示已被质量规则认定无价值或禁止保存的模型猜测，也不把垃圾候选移进此页让用户代为清理。

### 4.3 搜索、筛选与计数

V1 搜索为本地文本匹配，不新增向量检索/LLM 搜索。匹配允许显示的当前陈述与主题词；不搜索已删除正文、被排除的证据快照或旧日志。

筛选项：领域、近期/长期、形成方式（用户确认/用户纠正/自动形成）、本设备可见范围。不要将“来自对话”混同为“用户确认”。跨域记忆可匹配多个来源域，但一条只计一次。

默认搜索当前视图；可显式扩大到「包含过去与停用」。无结果区分“没有记忆”“筛选无结果”“加载失败”。计数与列表使用同一投影，禁止头部用 candidate 总数而列表用另一个判断。

### 4.4 列表行

标准行展示：完整意义可理解的摘要（常规最多约三行）、近期/长期、确认或推断标识、必要的适用日期、详情箭头。大字体可自然增加行数；长文在详情完整展示。

状态不依赖颜色。自动形成的明确事实不标“你确认过”；限定观察即使没有“新”徽章，也必须显示“仅作参考”。来源完整片段和内部评分不堆在列表里。

### 4.5 稀疏与异常状态

| 情况 | 呈现/行为 |
|---|---|
| 无记忆且自动形成关闭 | 解释当前关闭，提供记忆设置；不擅自开启 |
| 无记忆但自动形成开启 | 说明有合适信息时会逐渐形成，提供返回使用；不编造人物画像 |
| 只有一条 | 正常单行列表，隐藏空分组；不强行填满屏幕 |
| 已记住为空、观察中有内容 | 提供切换观察中，不称系统没有任何记忆 |
| 记忆辅助回答关闭 | 保留内容，显示“已保存，当前不用于回答”，链接同一设置页 |
| 全部记忆加载失败 | 显示失败与重试，禁止“0 条”假空态 |
| 来源已删除/被排除 | 标记来源变化，禁止继续展示失效摘要或旧快照 |
| 健康来源仅本机 | 显示“仅此设备”；其他设备不伪造正文或缺失原因 |
| 编辑期间被另一端修改 | 保留草稿并提示查看新版本；不静默覆盖 |
| 无网络 | 管理本地已保存内容；同步情况按真实可知状态提示，不阻塞本地编辑 |

## 5. 确认与纠正的完整体验

### 5.1 主动确认

用户在观察中查看一条内容 → 看清来源和适用范围 → 点击「符合现在的情况」→ 持久化用户确认 → 重新计算使用资格 → 显示结果。

成功回执示例：“已确认，相关回答可参考这条信息。适用于当前阶段。撤销。”此为示例文案，实际范围必须来自记录；不能固定写“以后都会记住”。

确认后条目进入已记住，原位置短暂保留完成行及「撤销」，供用户理解迁移结果。使用页面内回执与状态变化，不新建全屏 Toast 窗口。管理页不会处理一条后自动关闭。

不能确认的情况：禁止性推断、权限不足、已删除、来源丢失且没有独立用户声明、内容已被新版本替代。若用户愿意主动提供新事实，应走明确的编辑/新增声明，不把旧证据偷偷改成有效。

### 5.2 纠正

编辑表单预填原陈述，明确显示原时间范围；不能只改显示文案而继续给 AI 旧摘要。保存时同步处理：

1. 用户可见陈述、AI 使用摘要、结构化 personal-context statement。
2. 用户声明证据、确认方式、适用期和当前有效权限。
3. 原有 decision metadata、限定语、反证及依赖的再评估。
4. 内容版本与操作历史；受影响缓存和下游派生记忆失效。

若只是改措辞或同一命题的值，保留命题身份；若改变了主体、主题或事实类型，例如把“喜欢晚间运动”改成“对花生过敏”，不能沿用旧 ID/锚点/敏感级别。提示这是另一条信息，走新建与旧条目处置流程；首批没有新增能力时保留草稿并解释不能这样替换。

用户纠正优先于自动推断，但不能替代原始账务/健康数据核验。例如改写“本月支出总额”不修改账本，也不能作为已核算金额引用。此类情况提供前往原记录核对，必要时记为用户陈述而非结构化事实。

### 5.3 按需澄清

复用 `HoloMemoryClarificationCoordinator`，不另建一套确认调度：每次用户主动流程最多一个最小问题；当前既有普通入口预算为滚动 7 天最多一次、同题跳过后 30 天冷却，继续遵守，除非另行评审调整。

只问对当前结果有实质影响、无法从现有证据解决的变量。跳过/不确定允许继续给出不依赖该假设的回答，不把用户困在确认页。

仅本次回答不写长期记忆；当前阶段不自动延长为永久；用户明确“以后请这样”才按合法保存范围形成长期偏好。管理页由用户主动发起的校准不消耗上述打扰预算，也不触发下一次主动提醒。

## 6. 操作语义与状态变化

| 操作 | 含义 | 当前使用 | 自动重新形成 | 撤销/恢复 |
|---|---|---|---|---|
| 准确 | 内容符合当前声明范围 | 通过门禁后可使用 | 可补充来源，不覆盖用户声明 | 可撤回本次确认，不默认变成“错误” |
| 改一下 | 修订同一命题 | 使用新版本，旧版本退出当前使用 | 不用旧证据覆盖修订；实质新冲突进入核对 | 可撤销最近修订，但不得跨越较新控制 |
| 已经过时 | 过去成立，现在不适用 | 停止当前使用，转过去的记忆 | 同一旧时间段不复活；新时期新证据可另行形成 | 重新核对日期和证据后恢复 |
| 不准确 | 此判断错误 | 立即停用，保留纠错原因 | 相同命题和相同证据修订不得反复生成；真正新证据只可重新观察 | 用户主动恢复并重新核验 |
| 不再使用 | 用户不希望此命题继续作为记忆影响服务 | 立即停用 | 持续阻断同一命题及等价改写，直到用户主动恢复 | 查看停用内容后明确重新启用 |
| 删除记忆 | 清除该派生记忆内容 | 不使用、不展示正文 | 保留最小阻断标记，防止原证据直接重建 | 删除正文后不可恢复；需要时重新提供内容 |
| 恢复/重新启用 | 撤回之前的可逆限制 | 重新走来源、时效、权限和冲突校验 | 按恢复后的范围处理 | 本身产生新的操作，不抹去历史事实 |

### 6.1 停用与删除的边界

“不再使用”保留内容，便于查看和恢复；“删除记忆”清除记忆正文。两者都不删除原始笔记、账单或聊天。

停用阻断的是指定记忆命题，不是全面封锁其来源。用户主动查询获授权的原始数据时，仍可能看到原文。删除确认页应说明这一点，并提供来源管理路径；若用户要禁止任何 AI 使用某条来源，应由原始模块的排除能力执行，不能靠停用记忆冒充。

禁止为了防重建保留完整被删正文。阻断标记只保留必要标识和版本；涉及敏感来源的锚点也可能敏感，沿用敏感存储隔离。不能宣称“彻底删除所有痕迹”或保证已导出的外部副本随之消失。

### 6.2 恢复与撤销

撤销是一个新的受控写操作，不是把旧 record 全量覆盖回去。必须核对待撤销 operationID、当前内容版本和更新后的控制链。

- 在没有后续冲突写入时，撤销最近一次确认/纠正/过时/停用，恢复其业务效果。
- 其他设备已有较新操作时，保留最新事实，提示“这条记忆已有新修改，请先查看”，不能静默撤掉别人较新的删除或停用。
- 来源消失、权限撤回、期限已过时，撤销/恢复不得直接回到可使用状态；可落到观察/历史并解释原因。
- 恢复必须处理对应 tombstone/control 标记。只改 `state = active` 不算恢复完成；禁止调用仅供迁移使用的删除墓碑方法。
- 停用恢复与彻底删除分开。删除前提供二次确认，删除后不提供会恢复敏感正文的“撤销”。

## 7. 生命周期、时间与冲突治理

### 7.1 展示优先级

所有页面、计数和入口共用一个管理投影。按以下优先级判定，不能用单个 `state` 字段同时代表四种权限：

| 优先级 | 条件 | 展示位置 | 使用资格 |
|---|---|---|---|
| 1 | 删除/忘记已生效 | 不展示正文，深链说明不可用 | 禁止 |
| 2 | 用户停用/判错 | 已停用 | 禁止 |
| 3 | 过期、归档、被替代、来源已失效 | 过去的记忆，说明具体原因 | 默认不进入当前回答 |
| 4 | 存在未解决冲突 | 观察中：信息有变化 | 不作为确定事实；禁止静默放宽 |
| 5 | 观察/待相关澄清 | 观察中 | 按决策禁止普通召回 |
| 6 | 来源、时效、权限通过，factEligible/qualifiedAdvice | 已记住，后者标“仅作参考” | 按对应使用范围 |
| 7 | 未知版本/无法解释的元数据 | 管理可提示暂不可用，不作为正常已记住 | 保守不使用 |

总“记忆辅助回答”开关关闭时不改变内容分组，只给已记住统一标明当前暂停使用。管理权限独立于回答权限。

过去记忆首批只供用户回看，不新增“历史记忆自动召回”能力。未来要回答“当时的我”，必须另做时间范围与用途契约，不能借此把过去状态当成现在。

### 7.2 时间规则

- 复用 `validFrom/validTo/expiresAt/persistenceClass/lastSupportedAt`，区分“证据覆盖日期”“命题适用期”“系统复核/过期时间”。不拿来源最后编辑时间冒充适用期。
- 到期内容在读取时立即排除，后台归档只做持久化整理，不依赖调度及时运行来保证安全。
- “长期”内容仍能被新事实更新；用户确认不会清空已有过期时间、无限延长临时状态。
- 原有衰减规则不是精确到期承诺。未给出确定日期的条目写“当前阶段”，不虚构“将在 30 天后删除”。
- V1.1 用户自定义截止日期按其当前时区理解为当天结束，持久化明确瞬时时间及时区语义；跨时区设备显示当地日期并能核对原设定。

### 7.3 新旧信息冲突

区分：旧事实已变化、同一时段证据矛盾、主体不同、表达限定不同。不能只按最新写入时间覆盖，也不能因为旧内容被用户确认就永远拒绝新证据。

例如“以前早起运动、最近改到晚上”属于时间变化；“工作日晚上、周末早上”可以并存；两条来源都说“现在”且相反时进入核对。

首批保证冲突不误用并可查看/纠正；V1.1 增加并列对比面板，提供“已经改变”“两者都适用，分别是…”“旧理解不准确”。不让模型替用户作生活选择。

### 7.4 重复治理

先复用稳定身份、规范锚点和 lineage 去重。相同来源经聊天、报告再次引用，不能算新增独立证据。

V1.1 合并只在主体、命题、适用期、敏感级别和用户控制兼容时进行。合并保留可追溯来源；不能通过新 ID 绕过停用，不能把敏感内容迁入普通存储。仅措辞相近但范围不同的条目不自动合并。

## 8. 主动添加与批量管理（V1.1）

### 8.1 主动添加

入口为管理页「添加记忆」，表单包括：一句陈述；适用范围（长期/截至日期）；可选领域。默认陈述按用户主动要求保存处理，但敏感内容仍遵循现有保存授权和本地隔离。

不强制 AI 润色，不因自动形成记忆关闭而拒绝用户主动保存，也不能顺手开启自动形成。回答开关关闭时成功提示“已保存，当前未开启记忆辅助回答”。

用本次用户输入建立独立 `explicitUserStatement` 证据；没有原始笔记是正常情况，不伪造来源。检测相同命题已停用时，明确询问是否重新启用；不能靠新建 ID 绕开限制。

### 8.2 批量操作

支持在当前可见筛选结果中选择、标记过时、停用、删除；不提供“一键确认全部观察”。选择范围明确为所选 ID 集合，不能后台把新加载或其他筛选下的条目也选中。

批量破坏性动作先预览数量和影响，提交后按条返回成功/失败；失败项保留选择供重试。重试复用 operationID 保证幂等，不重新提交已成功项。批量删除不可承诺全部事务原子完成，跨存储时明确逐项结果。

## 9. 来源、隐私与删除清理

### 9.1 来源展示

原始记录可达时，展示真实日期、类型与必要片段，点击进入对应记录。聚合证据没有单条出处时，展示计算时间段、样本口径和可核对范围，禁止画一个不可点击的箭头。

展示保存的证据摘要前必须核验来源仍存在、未软删、未被 AI 排除且版本相符。不能“有缓存 summary 就显示”，更不能拿源记录刚删但缓存仍在来兜底。

用户声明来源显示“你在记忆管理中填写/确认”，与原始机器推断证据区分。来源撤权之后是否仍能保留用户独立声明，要按实际授权判断，不能为了保留内容临时生成一条假用户声明。

### 9.2 删除清理清单

现有 `forgotten` 分支已清空部分摘要和证据，但仍需逐字段审计，不能据此宣称彻底删除完成。实施必须检查并清理：

- displaySummary、aiUseSummary、personalContext 内 statement/原文、证据与反证摘要。
- subjectKey、锚点、禁止推断文本等是否包含可识别正文；保留最小阻断标识所需的形式。
- 新增用户操作历史中的正文差异/撤销材料、来源快照、搜索索引、临时缓存。
- 依赖该记忆的跨域理解与其他派生摘要；必须失效或按剩余合法证据重新计算。
- 正在生成任务持有的上下文快照、后台重试队列与新生成内容的回写。

原始业务记录、既有聊天正文、历史报告不在“删除这条派生记忆”的自动删除范围；明确告知用户并给相应管理入口。已保存报告不静默改写，涉及变化的依据可提示需重新核对。

### 9.3 设备范围

沿用现有普通记忆与健康来源隔离，不扩大同步/上传范围。新增历史、事件、索引、撤销数据必须与原记忆同等或更严格隔离。**尤其要审计现有墓碑/control 写在普通库时是否携带健康锚点，不能只隔离正文却把敏感标识同步出去。**

离线设备在收到同步前无法知道另一设备的新操作，不承诺全设备即时生效；只陈述“已在此设备保存”，能够确认同步状态时再展示真实同步状态，不伪造“已全部同步”。

## 10. 设置整合与相邻项目接口

正式路径为：HoloAI 设置 → 记忆。页面内包括既有两开关、管理记忆链接及范围说明。管理页只显示必要状态提示，不再复制两开关。

| 自动形成 | 辅助回答 | 应有行为 |
|---|---|---|
| 开 | 开 | 按授权形成新记忆，相关回答可参考 |
| 开 | 关 | 可形成和管理，回答不注入记忆 |
| 关 | 开 | 不自动新增；仍可使用已有有效记忆 |
| 关 | 关 | 不自动新增、不注入；仍可查看、纠正、停用、删除 |

不改既有存储键：`holo_memory_automaticMemoryEnabled_v2`、`holo_memory_assistedAnsweringEnabled_v2`。控制值仍通过 `HoloMemorySettings` 的既有持久化/同步机制修改，不直接另写 UserDefaults。

用户主动校准允许保存到本地合法范围，但不会开启自动学习或外部处理。外部 AI 授权与记忆两开关相互独立，任何新调用仍由 `HoloMemoryAccessPolicy` 决定。

与「一个发现」接口冻结：V1 发现不因用户点“有点像”写入长期记忆；停用记忆不自动意味着禁止整个原始主题的所有发现。未来若共享控制范围，必须有显式范围定义，不能两个项目互相猜测。

统一设置项目若先完成，本项目复用其页面。若尚未完成，先让既有记忆设置子页由新入口复用，正式统一设置路由由同一负责人合并交付；不复制一个同名设置页，不把 Debug `AISettingsView` 公开。

## 11. 工程结构与数据契约

### 11.1 分层

UI 只发送管理意图并展示结果；管理读服务生成统一投影；写入服务组织用户控制；Repository 持久化；既有决策与访问策略决定 AI 使用资格。

建议新增的职责（名称为建议，不代表现有文件）：

| 组件 | 职责 |
|---|---|
| `HoloMemoryCenterView / ViewModel` | 页面、查询状态、分页/筛选、条目刷新；不判定权限 |
| `HoloMemoryManagementProjection` | 管理分组、标签、可用操作、不可用原因、计数的统一纯逻辑 |
| `HoloMemoryManagementReadService` | 读取合法记录和控制状态，构建投影；不触发萃取 |
| `HoloMemoryUserControlService` | 扩展现有 Feedback/Forgetting 服务的统一编排，处理版本、幂等、恢复、撤销与失效 |
| `HoloMemoryUserControlEventStore` | 保存必要的用户操作、恢复关系和可清理历史，不成为第二份事实源 |
| `HoloMemoryReferenceListView` | 回答关联记忆的公共组件，依 ID/版本读详情 |

不要让新增服务与原 `HoloMemoryFeedbackService` 成为两个各自独立的写入口。可把原服务改为薄适配，所有 UI、聊天工具、澄清写回进入同一控制事务契约。

### 11.2 管理投影

最小输出：recordID、contentVersion、bucket（remembered/observing/history/stopped）、timeGroup、displayText、originLabel、useLabel、effectiveRange、sourceAvailability、allowedActions、unavailableReason。

来源为同一份 `HoloMemoryRecord` 与现有策略，不单独保存一份“UI 记忆”。用户配置关闭只影响 useLabel，不覆盖内容生命周期。投影计算接受固定 now 以便测试时区/边界；禁止各页面自行写 candidate/active 判断。

### 11.3 用户控制请求与结果

请求至少带：operationID（本次意图幂等标识）、recordID、expectedContentVersion、knownControlHeads、action、必要编辑内容与范围。重试复用 operationID；重新编辑提交才生成新 ID。

结果明确区分：applied、alreadyApplied、conflict、notFound、notAllowed、persistenceFailed；包含新的内容版本、管理投影和可撤销操作 ID。`apply()` 返回 false 不能让页面移除条目并显示成功。

### 11.4 历史与同步控制数据

当前版本字段不能替代历史存储。建议增量新增一个用户控制事件实体，记录：事件 ID、目标记录 ID、前序控制事件集合、动作、所基于的内容版本、动作版本、发生时间及可清理的变化载荷。它只记录控制与必要差异，不重新存储完整原始业务资料。

- 显式区分 confirmed、corrected、outdated、inaccurate、disabled、restored、forgotten、undo；不再把“判错”和“主动停用”永久挤在一个 rejected 标记里。
- 现有状态仍写入向后兼容的受限投影（如 suppressed/archived/tombstoned），避免旧读取代码把新状态误当 active。
- 撤销载荷可包含变化前后必要文字，但必须与原记忆同域存储，并在删除时一起擦除。历史展示为“本次升级后开始记录”，不能恢复不存在的旧正文。
- 时间戳用于展示，不单独决定跨设备优先级；控制事件采用可比较的因果关系。并发停用/删除与确认冲突时限制优先；并发两次编辑不静默二选一，形成需核对状态。
- 恢复必须明确基于已看到的最新限制事件；未看到另一端限制的旧恢复不能解除新限制。并发删除后的旧撤销不能复活正文。
- 新元数据为版本化可选信封；未知版本保留且保守不使用。不得往既有非容错枚举随意加原始值，导致旧库解码失败。

具体 Core Data 字段由 G0 结合现有模型冻结，但上述行为契约不可删减。新事件数据与记忆的双份状态通过“持久化控制意图 → 受限投影 → 完成标识”的可恢复事务处理，崩溃后按幂等事件重放；未完成限制意图也必须被读取门禁识别。

### 11.5 写入原子性与并发

版本校验与读-改-写必须位于同一 Repository 串行事务内。现有 replace 方法有写锁，不等于服务外部先 fetch 再 replace 就是完整原子操作。

动作顺序：验证最新版本与权限 → 持久化控制/变更 → 更新同域记录和必要阻断标记 → 递增控制代次并失效缓存/派生项 → 返回已保存结果 → UI 刷新。

恢复只允许专门业务 API 操作墓碑；不暴露 `deleteTombstoneForMigration`。跨普通/敏感存储操作不能假装一个数据库事务，必须有明确恢复点、限制优先读语义和故障测试。

### 11.6 命题阻断与动作落库的细化

阻断至少区分两种范围：`sameClaimAndEvidenceRevision`（判错后阻止同一命题由同批证据重生）、`sameClaimUntilExplicitRestore`（停用/删除后持续阻断）。命题标识由规范化主体、属性/关系、适用范围和既有稳定锚点构成，不由显示文案或模型临时生成的 ID 决定。仅“同一领域/同一个人”不足以判作同一命题，不能把整个人的所有记忆一起挡掉。

优先沿用现有语义身份和墓碑匹配；不足时补明确的命题键/作用域元数据。模型可建议合并，但不能独自决定解除限制。等价性无法确定时，不以“换了句说法”直接认定全新，也不宣称能完美识别任意语义改写；建立同义、反义、不同主体、不同阶段的对抗用例，记录不能覆盖的范围。

| 动作 | 必须写入/更新的最小效果 |
|---|---|
| 确认 | 用户声明证据与控制事件；重算 decision metadata；保留适用期；满足门禁后 active |
| 纠正 | 新内容版本、声明证据、结构化载荷及限定范围；清理旧决策/缓存；必要时换命题身份 |
| 过时 | 用户声明“截至现在已不适用”；归档并终止当前适用范围，不篡改原证据日期 |
| 不准确 | suppressed + 明确判错原因 + 当前证据修订阻断；不得只改变界面标签 |
| 停用 | suppressed + 持续命题阻断 + 可恢复操作；来源新增不自动解除 |
| 删除 | 持续最小阻断 + 内容清理任务/完成状态；tombstoned 受限投影；清理失败不报全部完成 |
| 恢复 | 基于最新控制链的新事件；解除对应可逆限制并重新校验，不直接删除全部历史墓碑 |

首批详情显示真实操作记录即可，不为显示完整“版本树”保存每次自动萃取的整条正文。若要扩展为自动版本历史，需另行定义保留期限、存储成本和删除传播规则。

## 12. AI 消费与生效闭环

### 12.1 接入范围

覆盖当前 `HoloMemoryAnswerConsumer` 中 chat、analysis、insight、planning、各 capability、agent、tool，以及旧 summary/profile/episodic 适配入口。逐个列出读取者，未接入统一策略的消费者不能绕过管理结果。

用户“停用记忆”不等于删掉当前聊天里原本已经存在的同一段文字。既有对话若仍包含相关信息，界面应说明边界，必要时建议新会话验证；不能用模型仍看得到的聊天原文来断言停用失败或成功。

### 12.2 缓存与在途请求

所有记忆上下文快照绑定相关记录版本和控制代次：

1. 查询/拼装时过滤一次。
2. 发往模型前重新核对记录版本、来源和当前控制。
3. 请求进行中若用户停用/删除相关记忆，取消能取消的任务；不能取消的结果不作为当前有效结果发布，不写回新的派生记忆。
4. 流式输出已到屏幕的文字无法撤回其已发生的外部处理；停止继续输出并提示理解已更新，可重新生成。不能显示“从未发送过”。
5. 新请求使用最新控制重新构造上下文。旧生成任务不能因晚完成而覆盖新修改。

缓存失效要从原记忆沿依赖传递至跨域摘要和个人情境。不能只清一个界面的数组。

### 12.3 “本次参考”真实性

首批用现有可核实的引用数据提供入口，但区分“作为参考提供给 Holo”和“回答明确引用”。仅被放入上下文的条目不能自动算作被答案采用；只有计数时不能伪造可追溯的历史回答列表。

V1.1 补齐回答 ID、记忆 ID/版本、消费类型和引用状态的最小关联，不复制记忆正文。条目已删除则引用页显示不可用；历史回答原文仍由聊天/报告自身管理。

### 12.4 单次对话关闭记忆（V1.1）

仅限新会话首条消息发送前设置：“本次不使用记忆，也不生成新记忆”。不改变全局开关；重试、后台恢复、语音路径都携带同一会话级策略。

这不是“无痕聊天”：聊天是否保留按原有记录机制。必须同时阻止本次聊天以后被记忆萃取/报告派生路径重新提炼；若通用历史检索仍能读这段聊天，界面必须说明，不能承诺全面不再参考。完整隐私隔离需要另行覆盖聊天搜索，不能假装由此开关解决。

## 14. 迁移、回滚与兼容

### 14.1 增量迁移

入口和展示迁移优先保持原记忆 ID、证据、确认、停用、期限与用户开关。不重跑全历史萃取，不批量升级观察，不把过去记忆当新记忆通知。

新增操作历史从迁移完成后记录。存量 rejected 可能来自“不准确”或“不再使用”，不能仅凭字段猜用户原意：有明确墓碑且无法区分原因时继续保持停用，标“此前已停用”，不要给出虚假的具体原因。没有可靠操作前状态则不提供历史撤销，只允许新的显式管理动作。

迁移具有版本号和幂等检查点，失败不清空旧库；读路径不得短暂暴露已停用正文。若需要新增 Core Data/CloudKit 模型，遵循增量兼容，并在动模型前提醒东林在 App 内全量导出备份。

**CloudKit Development 环境承载东林真实日用数据，禁止 reset、清库或以测试名义删除其中记录。** 测试在隔离本地存储/合成数据中完成。

### 14.2 混合版本设备

新增可选字段能解码，不代表旧客户端能遵守新控制。必须覆盖旧端回写剥离元数据、旧 active 副本回流、旧后台萃取、旧恢复操作等情况。

推荐发布顺序：先让所有受支持客户端具备控制数据的保守读取与保护能力，再开放新管理写操作。若不能验证混合版本安全，不承诺该版本组合支持跨端管理，尤其不能开放跨端恢复后声称全设备一致。旧客户端已持有的离线数据不能靠新端即时撤回。

### 14.3 回滚

新页面可由内部 rollout 开关回退到旧入口；用户确认、停用、删除、来源排除等控制结果不回滚。禁止“回退 UI”顺手恢复墓碑、清空控制历史或重新生成被删除内容。

安全控制读路径必须先于界面上线，且独立于 UI 开关。首批仍保留旧管理兼容页，直到旧路由和受支持客户端验证完成。

1. 纯规则：复用现有 memory standalone 测试入口，增加投影、动作语义、时间、控制因果和未知版本案例。
2. Repository 集成：隔离持久化、重启、幂等、故障点、删除完整性、敏感双库和迁移；仅内存 mock 不足以证明持久化行为。
3. 消费者集成：验证实际上下文组装而非只看 UI 状态；使用可控生成替身检查旧内容是否被注入，再做必要真实模型语义验证。
4. 原生 UI：合并一次主要动线走查；迭代只复测改动点。按项目要求无头模拟器运行，交付真机前完成五大入口冒烟。
5. 多设备同步：具备隔离同步测试条件才执行；没有条件时标“未验证”，不能用本地事件归并单测代替 CloudKit 真实同步验收。

ChatView 保持项目限重和单一弹层路由约束；构建绿灯不替代实际可交互验收。首页保护需对照布局与关键绘制文件差异，不只凭“没主动改首页”的陈述。

### 17.2 性能与成本

管理页打开/搜索/筛选不增加模型调用。沿用现有记忆查询关键路径零串行网络请求目标；其既有 p95 100ms 是待测目标，不是本方案已达成数据。

用 0/1/100/1000 条合成记忆记录首屏、搜索、滚动与写入耗时；先复用后台取值和增量刷新，不在 SwiftUI body 中反复全库 query/解码。超过现有规模时按测量结果增加分页或索引，不先引入独立搜索引擎。

## 18. 产品效果与埋点

首要判断：用户能否发现错误、看懂依据、完成修改，并确认下一次相关使用遵守自己的决定。记忆数量增长、确认次数多不算成功。

建议记录必要的流程事件：入口来源、列表视图、查看依据、操作类型、保存结果、版本冲突、撤销、深链不可用、生成因控制变化失效。错误码和耗时可记录；不上传记忆正文、来源片段、健康锚点、具体金额和可反推身份的主题。

评估指标：找到指定记忆所需步骤；纠正成功率；误确认后的恢复成功率；停用后违规召回次数；保存失败是否保留草稿；用户能否解释“已记住/观察中/已停用”的差别。先获得基线再设改进目标，不虚构提升百分比。

## 附录 B：开发者不得自行简化的六件事

1. 不通过改圆球首页或底部导航来“提高记忆曝光”。

6. 不创建第二套 HoloAI 设置或记忆事实库，不绕过现有权限与敏感数据隔离。
