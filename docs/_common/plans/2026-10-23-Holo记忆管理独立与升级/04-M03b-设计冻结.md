# M03-b 设计冻结 · 控制事件持久化 + 迁移前自动快照（2026-10-23 实施）

## 迁移前自动快照（HoloMemoryPersistenceController）

- **触发**：库文件存在 且 元数据与当前模型不兼容（`isConfiguration(compatibleWithStoreMetadata:)`）；元数据读不出 → 保守按需迁移处理。
- **动作**：拷贝 sqlite + `-wal`/`-shm` 边车到 `<storeDir>/MigrationSnapshots/<容器名>-<ISO时间戳>/`。
- **硬保证 1（快照失败=拒绝迁移）**：任一文件拷贝失败 → 删半成品目录 → init 抛错，原库不动。测试以「预占 MigrationSnapshots 路径的普通文件」注入失败复验。
- **保留**：成功加载后清理——每库最近 2 份、>14 天删除；清理失败不影响加载。
- inMemory 与新装（无库文件）不触发；同模型重复打开不重复拍。

## 控制事件实体（HoloMemoryControlEventMO）

字段：id / targetRecordID / kind / priorEventIDsJSON（CloudKit 无原生数组）/ basedOnContentVersion / resultingContentVersion / occurredAt / operationID / payloadDigest? / **appliedAt?**（nil=待重放）/ schemaVersion / 软删字段对（deletedAt+deletedBatchId，M05 删除清理用）。全属性默认值或可选，无唯一约束。普通与敏感双容器共用模型——事件随记录落同域库。

## 事件存储（HoloMemoryControlEventStore）

append（operationID+recordID 幂等，重复返回 false）/ events(forRecord:)（时间升序）/ latestEventID / markApplied / outstandingEvents（两库 appliedAt==nil）/ removeEvents(forRecordIDs:)（M05 配套）。
**同域路由 = 探测记录实际所在容器**（不复制敏感性判断逻辑，跟着记录走；两库皆无 → recordNotFound）。

## 写前先行事务（HoloMemoryUserControlTransaction）与重放（Reconciler）

三步：①落事件(appliedAt=nil) ②replaceRecordForUserControl ③markApplied。②失败不回滚①——**宁可多留待重放的限制意图，不可丢用户控制**。
重放规则（只收紧不放宽，判据 = M03-a 因果代数）：
- outdated→archived；inaccurate/disabled→suppressed+rejected；forgotten→tombstoned+forgotten（幂等写入）
- confirmed/corrected：仅当 priorEventIDs 覆盖该记录全部限制事件才执行，否则保守跳过并标记完成
- restored/undo：不盲放行（恢复需墓碑与校验链，M04 语义），保持 outstanding、记录维持受限
- 记录已物理不存在 → 标记完成（控制无从谈起，不悬挂）

## 实施注意（本轮踩坑）

被小组件目标共享的文件（`CoreDataStack+*`）引用的新 .swift，**除主 App 同步组外还必须手动挂 HoloWidgets 显式 Sources 清单**（三处：PBXBuildFile/PBXFileReference/Widget Sources phase），否则 `cannot find type` 且全量重建无解——与「主目录同步组自动编译」记忆互补。
