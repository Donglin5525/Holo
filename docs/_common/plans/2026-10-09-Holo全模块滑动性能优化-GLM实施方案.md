## 1. 产品结论与授权范围

东林反馈多个模块快速滑动掉帧、不跟手。此前录屏主要覆盖想法侧栏，因此其中确认的手势缺陷仍成立，但不能作为全 App 掉帧的统一根因。

2026-10-09 真机采样时东林反馈“现在不怎么卡顿了”，并说明 GLM 曾怀疑 iCloud 同步。**第一批实施聚焦同步后刷新放大，暂不要求同时重写所有模块。** 源码已确认中继未检查事件完成/成功、维修入口强制启动可绕过防重入、全局修复后六域广播与首页多次重算等具体缺口。它们是应修的触发与调度问题，尚未证明就是此前掉帧的主因。需要区分 CloudKit 导入、Core Data 主上下文合并、应用二次重拉三段成本；仅仅在卡顿附近看到同步日志不够。

**可以先实施已经确认的同步调度修复。** GLM 先做 P0 与本次新增的 C1–C3，再按调用栈决定是否扩展到 C4 和原 P2–P4。不要求以全模块大改作为交付条件。真机用来验证“有导入时也顺滑、同步仍正确”；没有“同步导致卡顿”的复现窗口时保留诊断，交付候选，不冒称已解决。

本方案授权范围是本地 iOS 性能优化的实施依据，不涉及生产部署、CloudKit 清库、模型破坏性迁移、自动提交/推送、修改系统配置或安装到东林日用设备。GLM 开工先复核当前工作区；没有东林明确请求，不调用 subagents。

### 成功后的用户体验

- 滑动时页面优先处理当前可见内容，不被切走的页面抢占刷新预算。

## 4. 公共规则与设计决策

### ADR-01：保留常驻导航，隔离展示生命周期

选择：保留路由、滚动位置、筛选、聊天与编辑现场。新增独立的展示生命周期信号，供需要昂贵展示投影的模型使用。不要通过删除隐藏页面解决问题，也不要复用 holoMotionSurfaceIsActive 表达数据可见性；动效开关和数据刷新需求不同。

可见至少分为 visible、covered、hidden；应用前后台作为另一维。HomeView 的 isTop 与实际 cover/sheet 遮挡确定信号，模块内今天/回顾、账本/统计再确定消费面。

隐藏：记录展示数据脏版本，不重建整页投影；恢复：最新查询只提交一次，不先清空旧页面。Covered 页面若仍可见，允许小范围展示更新，默认推迟昂贵重建；保存、撤回、同步、提醒和真实 AI 执行不受这个门控停止。

取舍：增加少量版本与可见状态，但避免隐藏页消耗和销毁现场。生命周期方法必须幂等；因为常驻视图 onDisappear 不一定触发，不能靠它实现隐藏判断。

### ADR-02：后台展示读模型，保留原写事务

选择：现有 Repository 的写入、保存、迁移、撤回与同步事实源继续由既有事务管理。新增可复用的后台只读快照入口，读取与取值都在所属 background context 的 perform 内完成，只返回值类型，不传递 NSManagedObject。

复用 `/Users/tangyuxuan/Desktop/Claude/HOLO/Holo/Holo APP/Holo/Holo/Models/CoreDataStack.swift` 的 newBackgroundContext / performBackgroundTask。纯聚合可用 dictionaryResultType；需要关系语义时在同一后台 context 查询/预取并投影为 DTO。不会把 NSDictionary、惰性闭包或托管关系装进 DTO 跨线程返回。

项目《开发规范》早期 §2 写“只用 viewContext”，后面的 §10 和现有 Chat/长廊实现已经有后台读约定。本次只增后台展示读取，维护原主线程写事务；GLM 应同步澄清这处文档口径，不删 MainActor 后把所有方法直接丢进 Task.detached。

取舍：需要值类型与失效管理，但能将读取、聚合和投影移出交互线程；绝不靠 @unchecked Sendable 放行托管对象。

### ADR-03：合并展示刷新，兼容现有通知

选择：先复用 financeDataDidChange 等业务通知，在消费层做最小刷新合并；可加入可选的 domain / changedIDs / revision / affectedRange 元数据，旧通知仍有效。没有范围元数据时将该域标脏，不伪造精确增量。

每个消费者最多一个后台准备请求和一个待刷新标记。事件到来时递增数据版本；有请求在途时合并范围，请求返回后若版本落后继续处理一次最新版本。防抖与 generation gate 解决不同问题：前者减少工作，后者禁止旧结果覆盖。

可见页外部批量通知先按现有 150–500ms 范围合并；首批建议最大等待 500ms，连续事件必须有上限，不能永久等安静。隐藏页只保留 dirty。用户自己的保存、删除、打卡、撤回要立即体现局部结果，后台再对账；失败按原契约显示，不假装成功。

可选的轻量 HoloPresentationRefreshCoordinator 只管理展示消费者，不变成所有仓库、AI 执行和同步的总调度器。先接财务、习惯验证，再推广，不一口气替换全部业务通知。

### ADR-04：一次准备、一次提交，缩小订阅范围

选择：后台按查询准备不可变展示状态；主线程验证请求身份后一次发布。拖动位置、图表选中点、流式文字等高频状态留在消费叶节点，不能使整个模块重建投影。

优先复用现有模型和独立叶视图，避免全项目切换 Observable 宏或无限拆分容器。对 ChatView 必须遵守栈预算红线：叶子封顶，不能为“优化”再加深容器链。

不无条件使用 .equatable() 忽略关系/内容变更，不只按对象 ID 判等；正确的失效依据是数据版本和完整渲染输入。

## 5. 最小数据契约

以下是新接口的要求，可按既有类型命名实现，不强制创建同名大框架。

### 查询身份

`PresentationQueryKey` 包含 domain、消费页面、筛选、排序、分页游标、日期范围；需要日期时带捕获的 Calendar / 时区口径。文本布局缓存另外带宽度档、Dynamic Type、语言和样式版本。

`RequestToken` 包含 queryGeneration、sourceRevision；开始、取消与切查询都会使旧代失效。结果提交同时检查查询代数与脏版本。已有 FinanceAnalysisLoadGate 和健康 dateLoadGeneration 保留或等价迁移，不建互相独立的双门控。

`PreparedSnapshot<Row>` 包含 queryKey、sourceRevision、rows、必要汇总与准备结果。Row 是 Sendable 值类型：稳定业务 ID、内容版本、已准备展示字段和动作所需 ID。点击编辑/删除时由原仓库在自己的上下文重新取实体。

dirty 只在最新快照成功应用后清除，不能在发起查询时清除。新请求使用新的后台读上下文或明确刷新旧上下文，避免复用旧注册对象。后台读以已提交数据为准；本地保存尚未完成时保留当前操作的局部展示覆盖层，收到保存成功回执、远端 merge 完成后再发布对应新版本，不能让旧 store 快照撤销用户刚做的动作。

1. 只接受 Holo 主 persistentContainer 的事件；若 object 无法直接匹配，使用已知 storeIdentifier 过滤。HoloMemory 的独立容器不可误触发所有生活模块刷新。记录 container/store 标识摘要，不记录账户信息。

| import 开始、失败结束、export、其他容器事件 | 不触发成功导入刷新；失败如实记录，不写“已落地” |
| 同一 import 成功结束通知重复到达 | 同 event ID 只接受一次；不重复 apply |
| setup 成功但首批数据未到 | 首载不死等；import 到达后补齐，新设备不永远空列表 |
| 连续 50 次事件，跨越多个防抖窗口 | latest dirty 不丢；最长等待生效，不无限延后；合并计数可核对 |
| setup 多入口、force、扫描超时后新事件 | 最大实际扫描并发恒为 1；超时不重开；pending 最终补做；旧 completion 无法清新 run |
| 无副本删除的正常导入 | 新账单/习惯/想法等正确出现，不能只靠 removed > 0 广播 |
| 修复删除、关系重挂、跨域变化 | 域范围完整；依赖域被失效；同批下游不会连锁重查多次 |
| 本机保存 / Widget / App Intent / 第二设备写入 | 都最终可见；来源过滤不误丢扩展写入；本机即时反馈不延后 |
| 持续拖动、切走、返回、后台恢复 | 不跳位；最长展示等待有效；恢复最新快照；没有隐藏展示重建风暴 |

事件判定使用可注入的值类型测试输入，不要求构造不可初始化的 CloudKit 系统 Event；存储测试使用隔离 store，不运行真实库查重或重置同步。

设备验收至少分三类窗口，同设备、同包配置、同操作：A 同步安静期；B 自然成功导入 + 滚动；C 隔离 fixture 的批量失效重放 + 滚动。每类至少三轮，分别记录页间导航与连续滚动；第二设备测试使用专用测试数据，不能为复现清空东林日用库。C 验证应用刷新调度，不能替代 B 的真实 CloudKit / SQLite / merge 成本。

P0 时间线必须能连接：event start/end/result → store / history / merge → batch invalidation → consumer requested/started/applied → Hitch。每段携带 batch/revision、域、可见状态及数量，**不输出用户正文、账单或健康数据**。记录修复 scan runID、并发数和真实结束时间。未取得成功导入窗口，写“同步归因未验证”；不能因 A 顺滑就推断 B 已修好。

同步主因的判断必须同时有时间重叠、阻塞栈/刷新放大路径、收敛该路径后的同条件对照；只有 os_log 时间接近不够。若 C1–C3 后 B 仍卡，以 trace 区分后台扫描/锁等待、主上下文合并、业务 reload 与视图布局，再决定 C4/P2–P4。实测的 CoachMark 位置汇总、富文本尺寸测量与多模块更新列为独立复测点：即使导览不显示也应核对是否仍持续收集全局 frame，但未经对照不要承诺其收益或把它改称同步热点。

### 先测规则，后测设备

| 场景 | 必测断言 |
| --- | --- |
| 隐藏页收到十次外部变化 | 不重建隐藏展示；dirty 记录最新版本；恢复后取最新数据且只提交一次 |

### 后续真机性能验收

同一设备/数据/发布优化配置/近似温度状态，分别采原版和候选版：进入后立刻滑、纯纵向快速滚动、侧栏快速反向、同步期间滚动、多个模块依次打开后再滚动、冷/热缓存。重复三轮。

工具：SwiftUI instrument + Time Profiler + Hitches / Animation Hitches，并对齐本方案 signpost。区分应用提交超时与呈现超时；平均 FPS 和模拟器流畅不单独证明改善。

报告必须列：模块、设备、数据量、包版本与源码身份、构建配置、操作、更新次数、P95/P99、最慢主线程区间、hitch 总时间、是否有跳位/错误动作。60Hz 周期约16.7ms、120Hz约8.3ms，这是系统共享预算，不能全分配给业务。

首轮性能目标按同基线比较：明显长卡顿不复现，主要问题场景 hitch 总时间至少下降50%，其他核心场景不恶化。50%是项目首轮目标，不是本次实测或 Apple 保证；未达标继续沿 trace 找热点，不改报告措辞掩盖。

## 8. 回退、约束与 DoD

### 回退

- 首批后台快照和展示刷新门控使用独立内部开关，按域渐进启用；旧读取路径暂留一轮验证。新查询失败时保留旧快照并表达失败，不把空库当成功。
- 只回退展示读模型与门控，不回退数据写入、CloudKit 模型或已保存记录。纯内存缓存可清，不需要用户清库/重装。
- 每个阶段范围明确，GLM 使用限定文件/hunk；发现并行改动冲突重新核当前事实，不整体 reset。
- 不在旧/新入口之间自动来回重复刷新；回退是明确配置/版本选择，避免“失败后重跑全套旧读取”再次阻塞交互。

### 明确禁止

- 不重置 CloudKit Development；它承载东林日用数据。此方案不需要 Core Data schema 迁移。
- 不停止真实保存、同步、AI 长任务或提醒，以此换取帧率。
- 不改 Prompt 或 HoloBackend；若实施另行引入后端变更，必须单列并提醒部署，未经授权不部署。
- 不全量迁移 SwiftUI 到 UIKit，不把所有容器换懒加载，不全局关动画，不为视觉减负删除品牌资产。
- 不跨 context 传托管对象、不靠信号量等待后台、不拿 Task 包装同步查询当后台优化。
- 不把源码改善、模拟器 build、普通 UI 测试或 MetricKit 长挂起报告说成真机滚动性能验收。

### 两层完成定义

**实施候选完成（本次同步优先版）：** P0 与 C1–C3 的第一批交付边界已实施；C4/原 P2–P4 根据计数与 trace 决定扩展，并列明未实施项；确定性测试与适当构建通过；数据与交互契约无回退；计数证明重复准备减少、隐藏展示更新被推迟；给出候选改动与可执行真机验收步骤。

**性能验收完成：** 同源 iPhone 对比 trace 达标，主要场景无可感知顿挫/错误动作，副作用门禁通过。没有真机时前一层可以完成，后一层必须写“待真机验证”。
