# Holo iPad 版 · 设计语言与布局规则 v1.1

> v1.1（2026-11-14 设计审查后修订）：弹层关闭钮统一左上 X；侧边栏收起开关定位顶部；补圆角/字号收敛映射与 AI 紫统一口径；账户详情承载特例；键盘态覆盖范围声明。

> 本文件是 iPad 重构原型的**总契约**：所有模块原型（HTML）必须遵守本文件，实现阶段再 1:1 落进 SwiftUI。
> 上游约束：`docs/standards/设计规范.md`（色板/字体/间距/圆角/组件唯一真源，全部沿用）+ 东林 2026-11-14 任务书（横竖屏、键盘、功能不删减、页面不遗漏、用户动线自查）。
> 手机版一切不变。本文件只管 iPad（regular 宽度环境）。

---

## 一、设计方向（一句话）

> 把 Holo iPad 版设计成**「摊在桌面上的生活工作台」**：沿用 Holo 暖纸底 + 品牌橙 + 光球的视觉语言与 iOS 调型，核心突破是**「一屏一事一上下文」**——手机上「一页只能干一件事」，iPad 上任何对象打开时，它的清单、上下文和下一步动作同屏常驻。

**必须保留（不可动）**：
- 品牌光球（永转，东林拍板）、品牌橙 `#F46D38` 系、暖纸 Tool 色板、卡片语言（16 圆角 + 0.5 描边 + 轻投影）、44pt 热区、全部功能与数据契约、iOS 原生调型（不做「桌面软件风」）。

**可以重构**：
- 壳层导航密度、列表-详情承载方式、弹层策略、键盘交互、横竖屏布局、各模块信息密度。

**现状最大的平庸源**：
- 手机页面放大塞进大屏——834 竖屏被 232 侧边栏挤成 602、详情一会儿弹层一会儿整页、大屏中央大片空白、AI 看报告要跳走聊天现场。

## 二、壳层（App 级导航）

| 环境 | 侧边栏 | 内容实得宽度 |
|---|---|---|
| 横屏（1194） | 常驻 232pt，可收窄成 68pt 图标条 | 962pt（宽档） |
| 竖屏（834） | 默认图标条 68pt，点任意图标或 ⌘⌥S 展开为覆盖式完整侧边栏（选完自动收回） | 766pt（标准档） |
| 13" 横屏（1366） | 常驻 232pt | 1134pt（宽档） |
| 13" 竖屏（1032） | 默认图标条 68pt | 964pt（宽档，享双栏） |

- 侧边栏 10 个目的地（沿用现有骨架顺序）：**今天 / 想法 / 财务 / 任务 / 习惯 / 记忆长廊 / 健康 / AI 对话 / 个人 / 设置**。「今天」置顶=首页精神在 iPad 的落点：光球问候 + 五入口（iPad 版式重排，不再是手机版竖排宫格）。
- 侧边栏底部固定：「＋ 快速记录 ⌘N」按钮（按当前模块分流：财务→记一笔、想法→编辑器、任务→新建任务、其余→新建任务）；收起/展开开关置于**侧边栏顶部左上**（iPad 惯例位）。
- 模块切换不销毁现场（滚动、筛选、聊天流、AI 会话全保留）——现有常驻栈机制继续用。
- **手机版首页冻结令不约束 iPad**（东林 11-14 确认方向：侧边栏壳 + 首页保留精神）。手机版一个像素不动。

## 三、内容宽度三档（布局唯一依据）

判定看**内容实得宽度**（扣掉侧边栏/安全区后的真实宽度），不看窗口宽度（9 月方案核心结论，沿用）：

| 档 | 实得宽度 | 布局决策 |
|---|---|---|
| 窄 | <680 | 单列通栏，交互与手机版同构 |
| 标准 | 680–1023 | 单列内容限宽 720 居中；网格/看板 2 列；图表卡 2 列 |
| 宽 | ≥1024 | **列表+详情双栏**（列表 360pt 固定 + 详情占余量）；网格 3–4 列；阅读正文限长 640pt；图表可并排 |

- 双栏是「就绪线 860」的延续：≥860 即可双栏，≥1024 双栏为默认形态。
- 旋转/分屏拖动只改变呈现档位，**不清空选中、筛选、草稿、滚动位置、AI 会话**。宽→窄时右栏内容自动转为该对象的详情页（返回即回到列表原位置）；窄→宽时右栏恢复显示当前选中。

## 四、详情与弹层政策（全 App 统一对象规则）

| 类型 | 宽档（≥1024） | 标准/窄档 |
|---|---|---|
| 列表对象详情（任务/交易/想法/记忆/目标/账户） | 右栏常驻详情（列表不消失，切换对象只刷右栏） | push 详情页，返回保留列表状态 |
| 记一笔 / 新建任务 / 新建习惯 等表单 | 居中 sheet 560pt | 居中 sheet 560pt（不变） |
| 小选择器（日期/优先级/重复规则/清单选择） | **popover 锚定触发点**（iPad 惯例）【拍板点 P1】 | 居中 sheet（同手机） |
| 阅读型长文（深度报告/每周回顾/洞察） | 右栏 640pt 或独立页，行长舒适 | 独立页 |
| 全屏编辑器（想法信纸/语音输入） | 想法编辑器改「纸面 680 居中 + 浮动工具栏贴底」【拍板点 P2】；语音保留全屏 | 同手机 |
| AI 报告/回放依据 | 右栏 inspector（点聊天里的报告卡即开，聊天不停）≥860 已有，升级为标配 | 页内切换（同现状） |

- 弹层通用规则沿用设计规范 §8.3/§8.8：holoSheetShell 暖底、三区骨架、**左上 X 圆钮（全 App 统一款，禁右上关闭）**、主操作贴底、拖拽条。
- **承载特例**：财务「账户详情」= 模块内推入二级页（右栏留给交易详情，避免双右栏歧义）；除此之外对象详情一律按上表。
- 删除当前选中对象 → 右栏回到「无选中默认态」（摘要+引导），禁止空白破版。

## 五、键盘

**已有（全保留，iPhone 外接键盘同样生效）**：⌘1–8 模块直跳、⌘9 个人、⌘, 设置、⌘N 快速记录（按模块分流）、⌘F 当前模块搜索、⌘W 关闭当前模块。

**本轮新增（拍板点 P3，均属 iPad 标准语义，不加业务功能）**：
- `Esc`：关弹层 / 退出搜索 / 收起侧边栏覆盖层
- `Tab / ⇧Tab`：弹层表单字段间移动
- `↑↓`：列表与详情双栏时，列表键位导航，右栏跟随
- `⌘⌥S`：侧边栏收起/展开

**软键盘**：输入框聚焦时布局上移不跳动；聊天/想法编辑器输入栏贴键盘上缘；数字金额键盘（记一笔）保持现有自绘键盘。

原型里键盘态的画法：**核心输入模块（任务/财务/想法/习惯/AI 对话）必画 1 张「键盘弹出态」场景**；其余模块（长廊/健康/目标/个人/设置）的键盘态随实现期补。全局快捷键用 `kbd` 角标注释在界面相应位置。

## 六、深链落点总则

28 条深链（通知/小组件/AI 卡片）在 iPad 上统一规则：**先确保目标模块在侧边栏选中 → 再落到模块内正确位置（右栏详情/弹层/页面）**。逐条落点表在验收包输出（`03-深链落点对照.md`），原型评审时逐条走查。

## 八、调性：灵性趣味的具体落法

- 文案彩蛋：空态/引导文案延续 Holo 人格（例：长廊空态「这一天还没留下痕迹，去补一笔？」），不写产品说明书腔。
- 微动效：光球永转、记录到达光痕、打卡暖光（全部已有，iPad 沿用不重做）；列表→详情转场用 `smooth(0.25)`。
- 不堆搞笑元素；趣味藏在文案与反馈里，界面本体克制。

## 九、原型产物规范（所有模块原型 HTML 必须遵守）

- **目录**：`docs/_common/plans/2026-11-14-iPad版全面重构/原型/`，每模块一个自包含 HTML（内联 CSS/JS，file:// 直开，无外部依赖），`index.html` 为总入口。
- **文件结构**（沿用目标模块原型已验证的惯例）：暗色画布 + 左侧控制栏（272pt）+ 舞台。
- **控制栏必备控件**：深浅色切换、横竖屏切换、场景 chips（该模块的关键页面/弹层/键盘态）、缩放自适应（JS 按可用空间等比缩放整台 iPad，保证任何窗口都看得全）。
- **机身**：iPad Pro 11 逻辑点尺寸——横屏 1194×834、竖屏 834×1194；圆角机身框；无刘海（iPad），状态栏细条。
- **token**：CSS 变量直接搬 `设计规范.md` 的 Tool 色板 Light/Dark 两套 + 品牌橙系；**AI 紫统一 Tool 色板 holoToolAI `#6D28D9`（深色 `#C4B5FD`），只许 AI 入口/徽章使用**；金额时间一律 `tabular-nums` 且**两位小数**；图标一律 1.7 描边 monoline SVG（禁 emoji 当图标）。
- **实现期收敛映射**（原型中允许的档外值，落 SwiftUI 时按下表收敛，不再逐个拍脑袋）：
  - 圆角：10→12、13/14→16、18/20→16 或 24（按钮/卡类归 16，弹窗/大容器归 24）、26→24
  - 字号：模块主页大标题 28 / 二级页与右栏详情标题 20 / 正文 17 / 辅助 15 / 注释 13
  - 开关绿色允许 iOS 系统绿 `#34C759/#30D158` 特例（原生惯例）；其余状态色一律 Tool 色板
  - 危险实底统一 Tool danger `#B91C1C`（深色 `#FCA5A5`）
  - 「待确认/待复核」徽章统一 `holoToolWarning` 系
- **标注系统**：键盘快捷键 `<kbd>` 样式；「拍板点」琥珀角标（P1/P2…编号对应本文件）；每屏角落标注对应底表条目编号（如 `底表 B`）。
- **验收三问内建**：每个模块必须画出**最惨稀疏态**（空数据/1 条数据）场景，不只画饱满态（设计规范 2026-10-12 硬闸门）。
- 根元素带 `data-zcode-design`，`lang="zh-CN"`。
