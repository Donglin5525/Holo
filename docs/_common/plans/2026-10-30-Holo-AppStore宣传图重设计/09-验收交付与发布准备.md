# 验收、交付与发布准备

## 1. 先分清四种状态

| 状态 | 意义 | 放置位置 |
| --- | --- | --- |
| captured | 有原始界面或实际导出，尚未充分验收 | raw/export |
| review | 已合成，存在未完成的内容或视觉核对 | review |
| approved_for_upload | 格式、内容、真实性、视觉和目标版本均通过 | upload |
| blocked/rejected | 原因明确，待解决或替换 | 报告保留，不混入upload |

这个命名是本地制作状态，不代表Apple审核批准。App Store实际状态须另查。没有读图能力时最高只能到review，不能把全部文件复制进upload后宣称可发布。

`config/production-manifest.json` 的 `status` 表示该页当前生产状态。`not_rendered` 表示还没有可用的目标设备成片；`blocked_source_quality` 表示证据源尚不能支持成片；`draft_visual_review_passed_pending_large_capture_and_release_match` 表示本地中屏草稿已过当轮视觉审阅，但大屏/iPad原生拍摄与发布版本核对仍未完成。每个有 `draft_output` 的页面还必须同步填 `draft_status`、`draft_visual_review_status` 和 `draft_output_sha256`。只有最终目标设备图通过本节全部门禁，才可将状态推进到 `approved_for_upload`。

## 2. 阶段通过条件

### G0：环境与授权范围

- [ ] 已记录实际源码根目录、commit、dirty状态与构建版本。
- [ ] 已记录公开可下载版本，说明两者是否匹配。
- [ ] 只操作本任务专用模拟器；不关停其他会话设备。
- [ ] 已核对CloudKit模拟器隔离guard和实际运行状态，实际store路径属于演示沙箱。
- [ ] 没有日用数据库、真实健康数据或Apple ID输入。
- [ ] 模型有明确工具与读图路径；未使用未授权子代理。
- [ ] 本轮如仅被要求写方案，没有越界执行生产命令。

### G1：数据蓝图与实际写入

- [ ] 历史108条、52/56分月、5410/5880总支出、1080/1400餐饮、184/450聚餐均与实际fetch一致。
- [ ] 所有日期是解析后的真实自然日；区间使用正确时区和边界。
- [ ] 项目预算与已有交易关联，没有重复加支出。
- [ ] 今日散步是一次真实UI记录，从36到37；阅读18条600分钟。
- [ ] 当前日记录与历史完整月份的统计分开。
- [ ] 余额对应实际执行阶段，不把净流入当余额。
- [ ] N01–N04如宣传AI整理，未先人工接好主题再冒充AI结果。
- [ ] 静态播种与真实操作来源可区分。

### G2：真实能力与回退

- [ ] mixed_input：重新打开真实账目/任务，数量和日期正确。
- [ ] receipt_single：图片真实识别；确认前后状态和保存结果正确。
- [ ] receipt_multi_review：三笔49.50元先核对；没把待确认写成已入账。
- [ ] expense_query_sources：1080/1400/320及提及的266都准确；来源真的属于该问题。
- [ ] plan_draft_save：草案与已保存任务分开，确认只执行一次。
- [ ] topic_organization：AI归类有实际过程；否则明确改成人工主题表达。
- [ ] weekly_report：范围、事实、未完成和习惯口径均核对。
- [ ] memory_sources/edit/forget：每项独立核实，不因管理页能打开就全部算通过。
- [ ] voice、自动入账、Plus暂停、小组件、项目预算等条件能力没有证据时，相关关键词和宣传承诺一起撤销。
- [ ] 每一次降级都写出受影响的pageID、旧承诺、新承诺、替代R素材与原因。

失败不能简单把整套改成“功能介绍”交差。先沿原用户任务找可证明的结果；没有合法替代就明确该图被阻塞，其他图片继续完成。

### G3：原图真实性与取景

- [ ] 每种设备使用自己的原生界面原图，带设备UUID和像素尺寸。
- [ ] 原图没有用生成模型重绘、没有修掉错误字段、没有替换金额。
- [ ] 选中对象、日期范围与标题相符；R15已完成和今日状态分开保存。
- [ ] 焦点框实际测量且未越界，没有裁掉单位、日期、重要条件。
- [ ] 不混入旧/tmp目录里的同名文件；SHA对应本轮原图。
- [ ] 同一笔金额和任务日期没有重复渲染到让用户误以为两笔/两次的状态。
- [ ] 无加载遮挡、系统弹窗、半露键盘、错误sheet、无关聊天上文。
- [ ] R29是App实际导出，有对应App截图和完整导出文件。

### G4：外层设计与可读性

- [ ] 一张图一个主结果；大标题没有用“智能强大”代替证据。
- [ ] 标题两行字宽测量通过，次文案没有裁切或自动省略号。
- [ ] 外部辅助图形和App内部界面明确分开。
- [ ] FOCUS的放大来自真实局部，PAIR的对应关系标注准确。
- [ ] 小尺寸预览能认出标题与主证据；大尺寸细节可读。
- [ ] 补充说明不是一堆看不见的小字；付费/授权条件没有被隐藏。

- [ ] A/B是不同表达候选，不把色差当作新的关键词策略。

### G5：图像格式与文件

- [ ] 每设备规格17套，每套D00为10张、其余为6张，合计106；这是跨默认页与多个CPP候选的素材库张数，不是单个产品页的上传张数。
- [ ] 候选创意母版库为iphone-large 1320×2868与ipad-13 2064×2752两组、每组106张；这不是单个产品页的上传数量。Apple要求iPhone Dynamic Island中屏有截图覆盖、支持iPad时要求13英寸iPad；若使用大屏图自动缩放，须在App Store Connect产品页预览核实。需要独立定制时再制作iphone-medium 1206×2622的106张库；三组全量候选库为318张。
- [ ] Apple每个产品页最多10张截图；本方案D00选择10张、每个CPP选择6张，A/B同词只择一。候选库可保留更多创意，实际上传列表不得超过单页上限。目标设备UI一致时允许由大屏图缩小到中屏；不得把较小源图拉伸成大屏原生截图。
- [ ] RGB、sRGB、8bit、PNG、无alpha；可被独立解码器实际打开。
- [ ] 像素尺寸与device键一致，不以文件名猜尺寸。
- [ ] 所有变量已解析，无{focus_month}、TODO、sample、测试占位语句残留。
- [ ] 文件名顺序01开始连续，没有08后跳10、大小写重复或同名覆盖。
- [ ] 机器配置、逐张卡、渲染报告与文件一一对应。
- [ ] 来源文件存在且哈希一致；不存在静默使用旧raw的fallback。

### G6：平台与宣传准确性

- [ ] 所展示能力属于将要发布素材所匹配的版本；开发版候选有明确标记。
- [ ] 不出现价格、折扣、未经证实的排名、奖项、用户数量和效果数字。
- [ ] 不出现竞品App名称或未授权商标；凭证图不仿冒支付平台。
- [ ] 使用虚构个人信息，照片权利和生成来源有记录。
- [ ] 没有承诺全离线AI、全部数据不出设备、每条记忆必确认、永不记错。
- [ ] 当前简中真实UI只分配给简中页面；繁中/英文不靠换大标题冒充本地化。
- [ ] CPP词表来自最新获批版本实际可选项；候选意图不是已覆盖热词。
- [ ] 各主题不同时争抢相同词组；A/B候选不是自动建立的同词两页。
- [ ] 只做了本地制作时，没有写“已上线”“审核通过”或“转化提升”。

## 3. 逐张验收记录格式

建议CSV字段：page_id,device,version,source_ids,raw_hashes,capability_status,format_status,data_status,copy_status,visual_status,rights_status,fallback_used,reviewer,review_time,notes。

每个status限定not_checked/pass/fail/blocked。reviewer写实际宿主模型或人工，不写一个没有参加验收的角色。OCR只填copy_ocr_status；不能代填visual_status。

示例（只是结构，不是已通过记录）：

```json
{
  "page_id": "K01-A-01",
  "device": "iphone-medium",
  "format_status": "not_checked",
  "data_status": "not_checked",
  "visual_status": "not_checked",
  "raw_sources": ["R05", "R06"],
  "fallback_used": false,
  "reviewer": null,
  "notes": "待真实截图与验收"
}
```

## 5. 预览与打包

每套生成三种预览：完整顺序缩略长条；前三张160px宽并排；前三张220px宽并排。预览图标注seriesID、device与本地审核状态，标注仅在预览外框，不进入正式宣传图。

index.html按“默认页/截图记账/消费理解/任务/习惯/想法/日记/自然表达/复盘”分组，A/B并排。用户能从预览定位到具体PNG、原始R素材和page配置。该预览是本地交付工具，不部署网站，不使用Sites发布。

压缩包每个只含一个device+series的正式有序PNG；不要带raw、预览、配置和日志混入上传zip。文件数量与清单一致，解压后再次核对尺寸和SHA。另提供完整工作资料包，供继续修改，和上传zip分开。

本地HTML预览可用宿主打开文件；如需本地服务，仅在实际使用时启动并记录端口，不为预览暴露公网。

## 6. 最终给东林的交付说明必须包括

1. 做了哪些规格、套数和张数；哪些仍是review或blocked。
2. 哪套推荐作为默认页，八个主题的A/B是什么表达区别；此处可推荐，不能声称市场胜出。
3. 哪些能力真实跑通、哪些用了合法替代，影响哪些图片。
4. 目标版本和当前可下载版的对应关系。
5. 一键打开的本地预览和可上传文件位置。
6. 没有做过的动作：上传、提审、发版等，只需如实说明状态，不长篇重复禁令。

“格式通过但缺视觉验收”要明确写，不藏在巨大报告最后。不要把212或318张生成成功等同于相同数量可用。

## 7. 后续页面选择与发布准备

先核对最新ASC：版本、语言、设备、当前默认截图顺序、现有CPP与PPO、实际可选关键词。能用已连接工具/CLI读取就先读，不能从public lookup猜私有词表。

建议保存mapping.csv：intent_id,selected_variant,locale,device,keywords_in_approved_version,cpp_id,cpp_url,approval_state,visibility_state,deep_link_verified,notes。未设置的字段为空并标not_configured。

默认页与CPP各有职责：默认页讲Holo主线；CPP前三张直接承接特定需求。每组先选A或B，不把两套同时绑定同词。CPP审批/可见/关键词分配都完成后，才查实际搜索呈现；不能只看控制台保存成功。

需要随机比较时，使用默认页实际支持的PPO；最多三个替代方案，CPP不适用。单变量实验保持其他资产和受众条件一致。换了标题、布局和来源的两套完整创意，可以比较方向，但不能把差异归因给某个字。[官方PPO说明](https://developer.apple.com/help/app-store-connect/create-product-page-optimization-tests/overview-of-product-page-optimization/)

## 8. 数据反馈

按地区、语言、来源与时间段查看展示、页面访问、首次下载及平台转化指标。记录分母和口径，不将它们混为一个“转化率”。没有足够流量或置信度就报告不确定，不宣布赢家。

下载后的首次价值动作对应该页承诺：识图核对并保存、实际建任务、习惯记录、笔记保存后找回、真实回顾查看。现有埋点不覆盖时只写缺口，另行评估补充，不能在本轮制图中悄悄扩大为业务埋点重构。

本包没有预设提升百分比或收益目标。所有“更省事、能回看”的宣传以可见操作结果为证；真正效果由后续用户使用与同条件验证判断。
