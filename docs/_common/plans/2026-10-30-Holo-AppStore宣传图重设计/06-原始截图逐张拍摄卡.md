# 原始截图逐张拍摄卡

本文件与 config/capture-manifest.json 对应。下面是生产要求，R编号定义取景要求，不代表每个设备状态都已捕获；原图状态以 capture-manifest 与交付目录 raw-index 为准。部分新增来源已由模拟器采集，设备级视觉通过/阻塞分别记录。R 编号不是已经存在的 App 路由；新 harness 如需直达，必须在 DEBUG + 模拟器入口显式实现。

取景顺序不是R编号顺序：先真实完成今日散步R23再拍R20/R21；先保留R05确认前态再拍R06；先拍R18草案再拍R19；R34/R35先拍30分钟版本再编辑R36。

每张素材先在 iPhone 中屏完成，再按相同语义在大屏/iPad 重新捕获。所有像素 sourceRect 要在实际截图后测量，当前只规定语义焦点。

通用前提：目标版本映射、隔离 store、日期、数据核算和权益核对通过；真实流程的对象 ID 写入证据。动作有变动时改本卡和对应 JSON，并记录实际页面标签，不照着旧截图找已经消失的按钮。

## 操作与截图的统一约定

1. 导航前存当前页面 AX；跳转后验证导航标题与唯一目标对象。
2. 若同名文本多个，选择可见且 isHittable 的元素；禁止对隐藏 Tab 的同名元素点按。
3. 请求结束以内容与状态为准，最多等待合理窗口；不使用固定 sleep 15 秒后无条件保存作为成功证据。
4. 先截完整原图，再记语义焦点框；焦点框保留必要日期、范围、单位、授权/Plus 状态。
5. 取景调整只滚动、展开和选择，不能修改业务结果让它好看。
6. 每个 R 保存 PNG、原图 SHA256、设备尺寸、来源 commit、实际对象 ID、动作记录、可读性结论。
7. R29 是 App 实际导出文件，还要附分享面板的原始截图；不要把渲染器做的宣传卡当作 App 导出。
8. 有些 source 文件名是检索入口而不是所有项目版本都保证存在的具体路径。先 rg 确认归属，不能照猜的方法签名直接编译。
