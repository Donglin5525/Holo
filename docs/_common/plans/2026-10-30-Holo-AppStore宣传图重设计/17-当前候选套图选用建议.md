## 2. Apple 规则与本套图的适配

本次按 Apple 当前 App Store Connect 截图规范复核：每种设备尺寸至少一张、最多十张；支持 iPadOS 时需要 13 英寸 iPad 截图；iPhone 需要覆盖 Dynamic Island 中屏。若不同屏幕尺寸的 UI 和本地化一致，可提交最高所需分辨率，由 App Store Connect 缩小到较小尺寸；提交后仍需在 Connect 预览中检查缩放效果。iPhone 大屏 1320×2868 和 iPad 13 英寸 2064×2752 都是 Apple 接受的尺寸，PNG/JPG/JPEG 可用，不能带透明通道。[Apple 截图规格](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)

当前规格页另列 iPhone Duo 截图要求：2027年4月起，对使用 iOS 27.1 SDK 或更高版本提交的 App 生效。该设备不在本轮成片库里；正式提审前按目标版本的 SDK 和生效日期复核，若适用，再补拍内屏/外屏的原生截图。

Apple 建议截图使用实际 App UI 展示体验；可加入文字或图片辅助，但仍须真实反映 App 正在使用。产品页最多十张；没有 App 预览时，前 1–3 张可能出现在搜索结果，因此本文件把每组的前 3 张作为第一优先级。宣传内容必须和实际功能一致，使用虚构账户信息而非真人个人数据。[产品页截图建议](https://developer.apple.com/app-store/product-page/) [App Review 2.3.3 / 2.3.9](https://developer.apple.com/app-store/review/guidelines/)

本套候选的图片尺寸、格式和视觉审阅只证明素材规格与画面构成；模拟器截图不是目标 App Store 版本证明。上传前仍需用准备发布的实际构建包核对功能、权益/授权条件、文案、日期、数值、屏幕布局，并在 App Store Connect 检查中屏缩放、顺序和设备覆盖。

## 3. 各组前三张怎么讲

下面推荐只依据现有截图证据、组内连贯性和前段信息层级，不是假称跑过搜索量、点击率或下载转化实验。A/B 是同一搜索意图的两套创意表达；每次选一套，不要把 A、B 混在一个 CPP 里，否则同一批原生截图和证明点会连续重复。

### D00 默认产品页：03 → 02 → 05 → 06 → 08 → 10

1. **D00-03：今天的待办和习惯，放在一页看清。** 用跨模块的今日概览说明 Holo 如何减少查看入口。审阅边界：证明当天任务和习惯状态能在概览里查看，不代表 CloudKit 同步。
2. **D00-02：餐饮支出，按月看变化。** 以 8 月到 9 月同一类别金额、笔数和差额证明“记录可以用来比较”；只说可见的金额变化，不归因原因、不说 AI 给了建议。
3. **D00-05：习惯记录，按月与日期回看。** 把“记录有积累”落实到摘要和日历，不宣传连续打卡或终身累计。
4. **D00-06：想法按主题，集中回看。** 讲人工归入后的主题查看，不称 AI 自动归类。
5. **D00-08：回到那一天，找到留下的记录。** 讲日期定位与当天记录的回看路径。
6. **D00-10：随手记的一天，也能好好分享。** 用 Holo 实际导出的卡片收尾，突出文字、照片与日期如何成为可分享的记录。

视觉复核建议把 D00-03 放到最前：餐饮比较是窄场景，单独作为默认产品页首图不足以代表 Holo。推荐顺序不改变现有 PNG 文件名；选图时按本节编号调整上传顺序。

### K01-A/B：REC-01 iPad单笔部分通过，R41补齐“记账后回看”

R41证明生活回放把同一天的两笔支出摘要和散步打卡按时间列在一起；它适合作为收尾页，但不证明票据识别或AI分类。R05/R06现有iPad本地单笔候选；R07多笔入口实测未生成可核对卡，R08附件路径未测。四张REC-01 iPad候选只说明一笔演示记录，其他设备和其余页面未补齐，故K01仍不能视为完整套图。A/B是同关键词意图的备选，不应混在同一个CPP。

A版标题“当天的账目，之后可以回看”直接承接记账后的收益；B版标题“消费记录，和日常一起回看”强调消费与习惯在同一日回放。两版不是转化实验结果，也没有ASC关键词表现数据。

### K02-A 收支理解：01 → 02 → 03 → 04

1. **K02-A-01：月度收支，一眼看清。** 先回答记账用户“整月收支和结余在哪里看”。
2. **K02-A-02：前后两个月，变化看得见。** 再证明采用相同自然月口径比较，解释为什么可比。
3. **K02-A-03：餐饮账目，分类明细看得见。** 进入具体类别并把金额/笔数和流水相连。
4. **K02-A-04：打开餐饮明细，看清每一笔。** 以具体流水结束。

这组是“总览 → 可比 → 分类 → 记录”路径。A 版直说用户拿到的结果。当前只有四张候选；不要为了补足六张而塞入来源不合格的项目预算或凭证图。

### K02-B 收支理解：01 → 02 → 03 → 04

1. **K02-B-01：收入支出，整月账目有数。** 以整月总览建立口径。
2. **K02-B-02：收入相同，净收入少了 ¥470。** 用账面事实提出差异；这是两个月支出差异对净收入数字的算术结果，不声称支出变化造成了个人行为或财务后果。
3. **K02-B-03：想查餐饮花在哪，打开月度分类明细。** 承接问题到类别总额。
4. **K02-B-04：大类下面，具体花了什么？** 下钻到餐饮流水。

B 版以问题/数字切入，但和 A 共用多数源画面。二者是备选创意，不是两套可以首尾拼接的独立故事。

### K03-A 待办与时间：01 → 02 → 03 → 04 → 05 → 06

1. **K03-A-01：把出行想法，拆成三步行动草案。** 先展示真实 contextual-planning 路由生成的待确认草案。不得称已保存、已创建任务或使用个人记忆。
2. **K03-A-02：近期安排，时间一眼可见。** 由草案转到首页已显示的近期安排。
3. **K03-A-03：今天的待办，按清单逐项看。** 回答今天还要处理什么。
4. **K03-A-04：重要和紧急，分开看清。** 展示四象限视图。
5. **K03-A-05：任务截止时间，日期时刻都清楚。** 展示具体任务时间字段。
6. **K03-A-06：做过的事情，也有迹可查。** 以已完成任务和时间记录收尾。

前三张的推进是“从想法到草案 → 看下个时间点 → 管理今天”，不把 AI 草案夸大为执行完成。

### K03-B 待办与时间：01 → 02 → 03 → 04 → 05 → 06

1. **K03-B-01：短途出行，准备步骤先排清。** 从用户任务直接切入，展示待确认的旅行准备步骤。
2. **K03-B-02：项目周会，明天10:00。** 让日期时间信息可见。
3. **K03-B-03：怕漏掉今天的事？先看这张清单。** 展示今天到期筛选。
4. **K03-B-04：都说重要，先理清轻重缓急。** 展示四象限。
5. **K03-B-05：任务提醒提前设，间隔时间自己选。** 仅说明界面配置能力，不宣称提醒已送达。
6. **K03-B-06：完成了哪些任务，时间都记着。** 展示已完成清单。

B 版用情境与问题开场，和 A 版共用 R18/R03/R15 等核心画面。不要把 A、B 都设为同一轮搜索入口的连续页面。

### K04-A 习惯追踪：01 → 02 → 03 → 04（06 可选）

1. **K04-A-01：10月散步记录共12天。** 首张给出截至拍摄日的月度记录量。
2. **K04-A-02：空白和记录，都在月历里看见。** 具体显示哪些日期有记录/无记录。
3. **K04-A-03：近37天阅读累计600分钟。** 以另一习惯显示时长汇总，不让用户误以为前两张与这张是同一习惯统计。
4. **K04-A-04：习惯打卡，今天完成一项。** 展示当天打卡状态。
5. **K04-A-06（可选）：习惯有没有记录，今天就能核对。** 以今日概览连接任务和习惯状态。它与默认页 D00-03 共用 R04 今日概览；若本组核心是习惯历史，前四张已形成“月度数量→日期→另一习惯→当日打卡”的完整故事，06 不必为凑数加入。

跳过 K04-A-05。R20/R21 的“完成率482.9%”与图表100%坐标上限矛盾，不能覆盖或裁掉矛盾字段后宣传终身/长期完成率。

### K04-B 习惯追踪：01 → 02 → 03 → 04（06 可选）

1. **K04-B-01：这个月散步记录了几天？** 用问题开场，给出同一月度总量。
2. **K04-B-02：哪几天没记录？回顾日历逐天查看。** 把习惯记录空白讲具体。
3. **K04-B-03：读书投入多少，回看记录就知道。** 切换阅读时长，避免连续五张都讲散步。
4. **K04-B-04：散步完成后，打卡状态看得见。** 展示今日状态。
5. **K04-B-06（可选）：今天要做哪些事？习惯有没有记录？** 展示今日待办和习惯状态的一页查看。它与默认页 D00-03 共用 R04；若搜索意图是习惯追踪，优先保留前四张的独立习惯证据。

这组同样跳过 K04-B-05 的全历史完成率页面。

### K05-A 灵感笔记：01 → 02 → 04 → 06（05 仅作样式补充）

1. **K05-A-01：工作想法，先分条记下来。** 先让用户看到具体工作问题、行动和复盘记录。
2. **K05-A-02：工作想法，归入「工作节奏」。** 明确这是手动归入的主题，不把人工操作说成 AI 自动整理。
3. **K05-A-04：想法记录，接上已有思考。** 展示引用旧想法与实际查看来源入口。
4. **K05-A-06：留给自己，也能分享出去。** 用实际分享卡收尾，展示可带走的结果。

K05-A-05展示选择样式，和06实际分享卡在画面结构上相近，但对“灵感笔记/想法记录”的新增证明较弱；核心序列不放05。只有目标关键词明确包含手账样式或笔记模板时，再把05作为第五张候选。

不纳入 K05-A-03。它重复使用已在 K05-A-02 作为主证据的 R25，未增加新的用户收益；不是因为缺少文件而待补的页。

### K05-B 工作备忘：01 → 02 → 04 → 06（05 仅作样式补充）

1. **K05-B-01：工作备忘，准备与复盘逐条记下。** 先展示按时间留下的具体记录。
2. **K05-B-02：工作想法，按主题集中回看。** 说明手动主题与归属来源。
3. **K05-B-04：会议备忘，引用复盘想法。** 展示会前准备如何连接已有记录及查看入口。
4. **K05-B-06：想表达的时候，不用从零排版。** 展示实际分享卡，强调从工作备忘到可分享结果。

K05-B-05展示样式选择，和06分享卡的视觉主物相近；核心工作备忘序列不放05。只有目标关键词明确指向模板/样式时，再作为第五张补充。

不纳入 K05-B-03；该页与 K05-B-02 使用同一 R25，没有新增价值。手动归属与自动归属必须清楚区分。

### K06-A 照片日记：01 → 03 → 05 → 02 → 04 → 06

1. **K06-A-01：写下生活，再选一种样式。** 介绍记录后选择样式。
2. **K06-A-03：记录里的片刻，可以直接分享。** 尽早展示同一条记录的实际导出结果，避免连续两张都停留在选纸界面。

4. **K06-A-02：换一张纸，换一种记录心情。** 补充实际可选的风格。
5. **K06-A-04：一条生活记录，把文字和照片放在一起。** iPhone 版可用；iPad 版因来源正文句首被截断而拒绝，iPad 顺序中不得加入。
6. **K06-A-06：照片和想法，一起回看那一天。** 展示同日时间线。

1. **K06-B-01：今天的一点小事，留一页给它。** 先从普通日常记录切入。

## 4. 不同关键词组之间的证据复用

只要 CPP/产品页确实面向不同搜索意图，跨组重复使用一个真实原生画面可以接受；风险出现在把多个组的页面拼进同一条截图序列、让用户连续看到同一证明。选择时按“搜索意图是否匹配”优先，并在同一产品页内去重。
