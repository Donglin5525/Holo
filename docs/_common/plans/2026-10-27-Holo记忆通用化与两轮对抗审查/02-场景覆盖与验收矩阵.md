# 场景覆盖与验收矩阵

日期：2026-10-27。用途：约束通用方案与实施验收；下列是应有结果，不是已通过的 App 测试。场景数量不是完整性的替代，覆盖逻辑是“信息性质 × 证据形态 × 生命周期 × 使用入口”。

每个场景必须同时检查：保存的准确命题/范围、来源与独立性、前台位置、是否询问、各消费者可用范围、控制结果、业务数据是否受影响。模型只返回漂亮摘要不算通过。

## 1. 八类直接来源（S01–S40）

| ID | 来源与输入 | 必须得到的结果 |
|---|---|---|
| S01 | 财务：一笔便利店饮料、多日普通餐饮 | 明细可查；无个人记忆或逐条确认；不能由消费推偏好/身份 |
| S02 | 财务：同一账单同时导入支付宝、银行卡且带可关联事件标识 | 一份事件支持；实际业务去重由财务处理，记忆不擅改账单 |
| S03 | 财务：连续三个完整缴费周期的同一项目，含一次退款/调整 | 按项目与周期核验，排除转账/调账口径；退款不是新增正向支持 |
| S04 | 财务：只导入部分账户/账期，某类支出突然变多 | 限定已记录范围；不能认定生活整体支出变化或真实缺失为零 |
| S05 | 财务：明确“替朋友买”、变更币种/分类/商家名称 | 正确归属、可比单位与稳定实体关联；不认定本人拥有或喜好 |
| S06 | 习惯：正向、负向、数值型均命名为“戒烟” | 按真实定义解释；不能靠名字把 1.0 当戒烟成功 |
| S07 | 习惯：同日真实发生多次、重复同步、明确未发生与未记录 | 真实数量保留，重复事件去重；有效观察天数不膨胀，未知不等于零 |
| S08 | 习惯：四周完整可比数据与跨周重复，附完整对照/反例 | 一条有范围成熟候选；确认前不跨会话作为个人规律使用 |
| S09 | 习惯：中途更改目标/单位/记录方向或归档 | 分段比较、原状态及时退出；不能通过跨口径相加制造改善 |
| S10 | 习惯：按周/月记录、隔天计划、某周一次请假 | 使用适当自然周期和应观察机会；一次例外不改掉整条规则 |
| S11 | 健康：两个体重点、单夜差睡眠、设备缺测 | 不形成稳定变化或疾病判断；查询精确值仍能回答 |
| S12 | 健康：足够可比测量，单位或设备在中途改变 | 正确换算/分段，记录覆盖与适用范围；不把采样密度当实际健康频率 |
| S13 | 健康：用户说“未来两周不宜跑步”并给出个人限制 | 按用户报告保存时间限制，相关安排使用；不要求反复受伤或推断诊断 |
| S14 | 健康：用户授权撤回、健康来源与财务数据结合 | 所有派生取最高敏感级别，本机分区；停止不允许的读取/外发，不扩大同步 |
| S15 | 健康：用户自述“我觉得睡眠不好让我想抽烟” | 保留用户的解释及不确定性，不升级为系统证实的因果 |
| S16 | 任务：未完成“买猫粮”、完成交通卡准备 | 状态与计划按原模块读；不推养猫或长期出行习惯，不逐条入记忆 |
| S17 | 任务：同一任务重复延期，多个子任务属于同一项目 | 可分析任务事实；不把多次改期算多个独立失败，不贴人格标签 |
| S18 | 任务：计划时间、截止时间和真正完成时间不同 | 分开解释；不能用创建/截止时间推实际工作节律 |
| S19 | 任务：周期任务某次跳过，以后改为双周 | 实例例外与规则修订分开；当前规划按新规则，原确认不无限扩范围 |
| S20 | 任务：删除/回收站恢复/远端修改无 updatedAt 增长 | 变更对账发现；来源支持及时变化；恢复不撤销记忆遗忘 |
| S21 | 目标：同时有减脂、储蓄、学习，单位不同 | 每个目标保留自己的协议和单位；来源关联，不拼成统一虚假进度 |
| S22 | 目标：“想健身”但近期无锻炼记录 | 目标意愿不被行为反证取消；可指出执行记录不足，不推断用户不想做 |
| S23 | 目标：修改/暂停/完成/撤销目标，保持同 goalID | 记忆相关背景实时更新；不复制过期进度，不后台改目标协议 |
| S24 | 目标：AI 提议目标、用户未接受 | 建议不成为用户承诺，不生成跨会话的已接受目标 |
| S25 | 目标：一个目标联到任务、习惯、财务，均描述同一事件 | 来源各自可查；独立支持按底层事件计，记忆不建立第二套执行工作台 |
| S26 | 想法：引用文章“人要早起”，没有本人立场 | 不保存成用户偏好或承诺；原想法可查 |
| S27 | 想法：“如果辞职就去云南”“我不打算辞职” | 假设与否定正确；不生成已离职/将搬家事实 |
| S28 | 想法：一次重要搬家、工作变化或丧亲的本人陈述 | 经授权保留准确事件/阶段，不要求重复发生，不扩为人格/医疗判断 |
| S29 | 想法：同文含“负责接送家人”和家人敏感信息 | 用户责任可表达；第三方详情最小化并遵守敏感分区及权限 |
| S30 | 想法：长文后半段限制、同名不同人、隐含指代不明 | 不静默漏后半、不按名字误合并；歧义保留，当前确需才澄清 |
| S31 | 对话：“今天简短一点”与“以后都简短一点” | 分别为本次范围与持续偏好；不把所有用户句子长期化 |
| S32 | 对话：“我喜欢短回答，也喜欢徒步” | 两个不同命题均保存；不因相同 claimKind/锚点覆盖 |
| S33 | 对话：“朋友说我适合养猫”、助手建议养猫、用户仅回应“嗯” | 转述/建议不构成本人养猫事实；含糊回应不充当广泛确认 |
| S34 | 对话：“记住去年那次旅行对我很重要” | 用户明确记忆意图可保留一次事件；不要求命中固定用途白名单 |
| S35 | 对话：用户纠正“不是我，是朋友”，旧请求稍后返回 | 归属更正生效，旧自动结果不能复活本人断言 |
| S36 | 档案：工作地点/沟通偏好已填，用户在原处修改 | 来源关联读最新，不复制另一份档案值或后台反写档案 |
| S37 | 档案与聊天对同一当前事实冲突 | 先解析时间/条件；确冲突时按明确纠正与因果处理，不按最后时间戳抢写 |
| S38 | 档案为空，但有可用本人陈述和规律 | 通用引擎仍能工作；不把 profile 信号为空当全部记忆覆盖为空 |
| S39 | 档案中的约束不属于既有分类，如特别的照料时段 | 开放关系可表达，无需新增该人物/责任专用条件分支 |
| S40 | 档案被排除 AI 或用户关闭自动学习但保留辅助回答 | 尊重各自开关及来源权限；不重新默认开启，也不借关联读取绕过排除 |

## 2. 派生、跨模块与时间（S41–S48）

| ID | 输入 | 必须得到的结果 |
|---|---|---|
| S41 | 同一事实出现在想法、周报、发现、本地/云端报告 | 一个原事件；派生文字不增加独立支持，不形成循环证明 |
| S42 | 周报建议“周末散步”，用户点赞报告 | 点赞不等于执行、偏好或个人规律确认 |
| S43 | 多领域同日变化，但无可比样本/共同实体或窗口 | 不生成因果；无法支持的并发现象不进入成熟规律 |
| S44 | 数据充分的条件差异/跨域关联 | 保留比较、分母、限定与反例；确认后仍不升级为因果或诊断 |
| S45 | 半夜集中导入几个月历史记录，事件发生在白天 | 按真实发生时间分析；不生成熬夜消费/凌晨打卡规律 |
| S46 | 跨时区旅行、月末、闰日、自然周边界与夏令时 | 使用冻结 Calendar/timezone 与时间精度；不把一日拆成双倍支持 |
| S47 | “去年这样”与“最近这样”；历史窗与滚动窗 | 原确认不变成当前永久事实；滚动窗按确认的规则更新，不悄改成无限长期 |
| S48 | 系统检索很多条件后找到一次巧合 | 原发现样本不当验证样本；按模板的后续周期验证或保持内部，不因用户愿意确认而伪造证据 |

## 3. 历史兼容与迁移（M01–M16）

| ID | 输入/中断点 | 必须得到的结果 |
|---|---|---|
| M01 | 可靠旧用户陈述/纠正 | 原意与范围保留，不批量要求二次确认 |
| M02 | 旧 active 自动碎片、未确认推断 | 不继承认可；退出持续个性化，业务明细不变 |
| M03 | 旧已确认单次事件与已确认规律混在一库 | 分别保留历史事实与原范围规律；不把事件自动拼成新已确认规律 |
| M04 | 旧不准确、停用、遗忘、clear 基线 | 先导入限制及别名；晚同步/换 ID/重萃取均不得复活 |
| M05 | 新字段经过旧模型 round-trip、未知 decision/schema | 新知识不依赖旧 recordData 保留；未知不作为允许使用的 fallback |
| M06 | 外层新枚举或单条损坏 | 逐条诊断隔离，原字节保留；其他记录与业务数据正常可用 |
| M07 | 旧客户端使用统计回写、自动生成或更晚时间戳 | 作为 legacy 输入处理，不能覆盖新命题、确认和限制；不比较时间戳决定权威 |
| M08 | 旧控制重放器看不见新实体中的目标 | 新控制存储隔离；旧重放器不能错误标记新操作完成或丢失遗忘 |
| M09 | 迁移中断于写修订/写操作/写收据的任一点 | 重启可续，重复不新增确认/知识；分区完成前总水位不越过失败项 |
| M10 | 两台新设备并行导入同一旧记录，或语义槽位并发创建 | 确定性处理键与别名最终收敛；控制不丢，语义冲突不静默合并 |
| M11 | 旧 UserDefaults 已完成迁移但换设备/换 Store/同步晚到 | 以 Store、源修订和策略收据为准；不能用一个本机布尔值声称全量完成 |
| M12 | 仅有旧摘要、证据被删除/排除、无法证明来源仍有效 | 保留原历史及用户控制；不冒充已验证规律，也不重读被排除源 |
| M13 | 普通知识后来加入健康敏感证据，含索引/别名/历史 | 新敏感修订与所有派生先分区再写；不先同步出去再移动 |
| M14 | 回滚到迁移前快照，但之后已发生遗忘/纠正 | 正常回滚采用保留 Schema 的修复版本；显式灾难恢复需重放更新控制，不能复活已忘内容 |
| M15 | 远端变更保留旧 updatedAt、游标丢失、大批导入相同时间戳 | 存储变更/修订目录对账补漏；稳定 tuple 分页，预算受控，不无限重扫 |
| M16 | 关闭自动学习、未授权外部 AI 或预算耗尽时升级 | 必要本地格式与控制迁移可执行；语义重建不绕过权限/预算，不悄悄全量送模型 |

## 4. 控制与消费（C01–C12）

| ID | 操作/消费者 | 必须得到的结果 |
|---|---|---|
| C01 | 确认 v1，后台产生含义不同 v2 | 确认只绑定 v1 语义摘要；v2 不继承，旧版若失效不继续用 |
| C02 | 只是同语义新支持、新统计快照 | 不产生新确认义务；确认提交可按同语义当前证据复查，不因无关统计刷新一律冲突 |
| C03 | 修改为用户新的明确陈述，原行为来源后来删除 | 修改成为独立用户来源；不因旧行为样本删除抹掉用户亲口补充，但数字样本不凭修改产生 |
| C04 | 暂不处理、明确不准确、停用、忘记当前命题 | 各自语义不同；不准确不封禁整个主题，忘记涵盖该命题修订与派生，不以跳过当认可 |
| C05 | 证据充分性变化、失效、长期无新增、一次例外 | 分别重算/复核；不因已确认或曾达到门槛永久有效，不因一次例外全盘推翻 |
| C06 | 两台设备并发确认与忘记，或同时不同纠正 | 限制优先，编辑冲突需核对；旧确认不静默解除未见限制 |
| C07 | 生成中用户停用/改权限/改来源 | 提交与呈现依据当前控制；旧响应不能进入新一轮帮助，在途结果明确处置 |
| C08 | Chat、规划、能力入口、Memory Tool、本地 Agent | 同一知识同一当前资格；不能直读 active 绕过新策略 |
| C09 | 云端 memory.entries、报告背景、旧摘要入口 | 传必要范围/用途/版本与禁止推断；不支持新协议时不注入，不偷偷退成裸文本 |
| C10 | 精确问“某天花了多少/吸烟几次” | 查询原模块事实；记忆作为背景，不替代数值真源 |
| C11 | 清空全部记忆/AI 排除/删除账户数据/回收站恢复 | 统一盘点新旧实体、控制、缓存、向量与派生；保留必要阻断，恢复不能解除遗忘 |
| C12 | 旧 ID 深链、引用已删记忆、纠正的撤销 | 指向准确历史或说明不可用；撤销只对允许的因果版本生效，不误跳相似条目或恢复已撤权限 |

## 5. 体验、成本与新能力（U01–U05）

| ID | 输入/状态 | 必须得到的结果 |
|---|---|---|
| U01 | 有 20 条成熟候选、几百条内部线索 | 推荐最多 3 条，成熟候选主动可查；没有待清空半成品数字或配额生产 |
| U02 | 未积累足够证据、加载失败、模型超时、数据覆盖未知 | 四种状态可区分，不把失败当无发现、不输出假规律 |

| U04 | 前后台重复触发、预算不足、请求返回空候选 | 共用队列与收据，空结果也去重；不重复计费、不因打开页面扫描全历史 |
| U05 | 新的偏好对象、责任关系、稀疏周期、未登记数值指标 | 开放事实可表达；数值模板必须有可测试口径；不得靠新增实体关键词“修好样例” |

## 6. 一个发现与记忆联动（D01–D18）

| ID | 交叉场景 | 必须得到的结果 |
|---|---|---|
| D01 | 两次经历的发现、用户点击“有点像” | 允许有限观察；不创建长期规律、确认事件或额外独立样本 |
| D02 | 发现中的准确理解已成熟，点击确认并记住 | 统一事务只保存该语义一次；发现回执与记忆页一致，无第二轮审批 |
| D03 | 同命题已在记忆确认/在另一入口已询问且暂缓 | 已确认无新信息不重复主动推荐；暂缓共用冷却；管理仍主动可查 |
| D04 | 记忆页纠正或判错，发现仍显示旧解释 | 准确映射的旧发现撤下/重核；旧续聊草稿不得继续注入错误语义 |
| D05 | 发现点击不太准确，未选原因或选择依据/理解/时效错误 | 最低否定即时生效；按准确映射与范围影响知识；不伪造原因或整主题封禁 |
| D06 | 不想再主动提示某类；已有该类有效知识 | 两个主动推荐入口不互相绕过；不把知识判假，主动管理仍可查看 |
| D07 | 发现开、自动学习关；之后手动确认并记住 | 自动过程不写长期候选；手动仅保存明示结论，不打开自动学习 |
| D08 | 辅助回答关，保存成熟发现；另有更广记忆 | 可保存与管理；不注入一般回答或发现生成背景，不读取更广正文补充发现材料 |
| D09 | 已从发现保存知识，随后关闭发现/缩小范围 | 清理发现目的缓存，不删除有独立授权的已保存知识，不擅改其记忆开关 |
| D10 | 已保存知识的原发现 TTL 到期/本地发现缓存被清理 | 知识按自身来源和时效判断；记忆来源入口可解释原发现不可用，不依赖卡片存活 |
| D11 | 支持、反例、基线之一编辑/删除/排除/撤权 | 两侧按同源变更重核；当前发现撤下，知识重算；在途保存/续聊重查 |
| D12 | 记忆用八域数据，发现仅获想法/任务/习惯授权，含敏感联系 | 不借共享核验或删引用扩大发现范围；不将敏感记忆转成自动发现 |
| D13 | 保存成功但发现回执刷新失败，或保存前来源/语义已变化 | 成功保存不回滚，回执可重建、重试不重复；变化/失败不显示假成功 |
| D14 | 旧有点像、旧否定 HMAC、旧发现缺少 claim 映射 | 不批量提升或反解反馈；可验证才补链接；重置发现反馈不解除知识控制 |
| D15 | 同一获准材料两功能同时需要；一方关闭或预算耗尽 | 兼容的证据/核验可复用，一次外部成本不双计；不混用授权/预算，不让另一方变成绕过通道 |
| D16 | 从发现续聊，用户发送附带观察，另补一句真实偏好 | 附件保留派生血缘，不算用户自述；只有新 authoredText 按本人陈述独立核验 |
| D17 | 一张发现含多个 claim，只有一项成熟/被用户认可 | 只保存界面明示的那项语义与范围，不能暗中认可全卡或更广概括 |
| D18 | 在记忆中停用/遗忘命题，再从原始记录生成同义发现 | 最小跨入口限制阻止复活；不删原业务事实，明确恢复仍走控制因果校验 |

## 7. 验收方法与判定

99 个场景分三层：确定性逻辑与存储夹具、开放语义模型评测、真实入口/设备与跨设备。原 81 个场景保留编号，D01–D18 补足发现联动。矩阵描述的是职责，不要求为每行机械复制一份实现测试。

- 确定性层冻结来源、单位、时间、独立性、版本、控制与预期用途；source ID、数据值、别名、冷启动/中断点必须可复核。
- 语义层每种核心信息性质至少给正例、近似反例、改写及一个未见实体；使用留出的盲测材料，不能把同一句改几个数字当泛化证明。关键的主体、否定、确认越权与权限错误必须为零。
- 对规律评测同时统计被拒绝的真实规律与错误晋级，避免只靠“全拒绝”获得零误报；支持不足必须解释为不足，不能制造确定结论。
- 效果层必须证明一次重要信息可被记住，行为模式能聚合，用户确认后下次相关帮助确实改变，修改/遗忘后不再使用；无关问题不得硬套画像。
- 后端 Prompt 身份、旧/新模型隔离、多设备控制、CloudKit 与真实设备是各自的发布验收项，本轮没有执行这些项。
