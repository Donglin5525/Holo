# Holo 记忆：从碎片记录到可用理解的通用方案

版本：v2.1，两轮对抗审查后修订。日期：2026-10-27（北京时间）。
范围：产品、数据契约、全来源接入、消费、历史兼容与实施安排。仅文档工作，未改业务代码、Prompt、用户数据或生产环境。

**开工结论：可以进入 W0–W5 实施。** 两轮发现的 24 项设计问题已落实到本方案与 81 个场景判据；本结论不代表代码、模型、真实迁移或发布验收已通过。审查由本会话主代理先后切换产品/证据与兼容/并发视角完成，没有使用子代理，不冒充外部独立审查。

## 0. 产品决定

记忆保存的是能帮助未来理解和选择的知识；单条流水仍由原模块负责。行为归纳达到证据门槛后才请用户确认，内部候选不变成用户待办。

完整能力包含三类有价值信息：

| 类别 | 例子 | 进入与使用方式 |
|---|---|---|
| 用户明确表达的重要事实、偏好与约束 | 喜欢徒步；回答简短；负责接送家人；一次重要搬家 | 核对本人/转述/假设、时间范围、授权与冲突；持续信息直接保存，重要事件按原发生时间保留，不要求重复出现 |
| 关联来源的当前情境 | 旅行筹备、进行中的目标、短期不能跑步、当前账户或预算设置 | 关联现有业务实体或用户明确陈述；按有效期和原状态提供上下文，不复制进度、不延伸成长期属性 |
| 从多份证据学到的规律 | 某种时间节奏、阶段变化、条件差异、跨域并发现象 | 证据、反例、范围与用途都合格后进入“值得确认”；确认准确命题后才用于持续个性化 |

原始事件、统计查询、AI 建议、助手回复、报告正文分别保留职责。统计不用用户认证算术，建议不变成用户偏好，已生成文字不充当独立生活证据。

首版通用主流程覆盖财务、习惯、健康、任务、目标、想法、对话、档案及报告派生输入。习惯可以作为首个贯通样本；其他领域从第一批就执行相同准入与消费规则，不能继续沿旧流程制造碎片。

## 1. 泛化边界与场景覆盖

领域只负责解释原始数据：金额与转账、正负习惯与数量、测量单位、计划与完成、观点作者与引用等。系统不根据“戒烟”“宠物”“夜宵”等实体词编写晋级分支。

跨模块使用同一流程：来源规范化 → 同命题关联 → 证据计算/语义核验 → 统一价值与用途裁决 → 可见与确认 → 按需使用 → 变化重核。

场景至少包含：稀疏和高频记录、一次重大事件、稳定偏好与临时请求、照料责任与第三方信息、周期规则与单次例外、来源冲突、转述和假设、历史导入、跨时区、反证、用户纠正及遗忘、新旧设备、多写入入口和所有消费者。具体编号另见场景矩阵。

不通过领域专用关键词兜底，不以固定“出现 N 次”代替规律判断，不把模型数值置信度作为通行证，不新增独立于统一 Repository 的个人画像系统。存储的新版本实体是同一仓库的兼容演进，原因见 §7。

## 2. 通用知识契约

### 2.1 分开四种身份

| 身份 | 含义与稳定规则 |
|---|---|
| topicID | 用户能理解的主题容器；同一主题可含多个不同命题，主题不直接作为事实注入 |
| propositionID | 主体、对象、观察维度和适用条件下的一项独立知识；存在不同观点、职责或条件时分别保留 |
| semanticRevisionID / digest | 该项知识的准确语义版本：关系、肯否定、对象值、条件、适用范围与限制；用户确认绑定这里 |
| evidenceSnapshotID | 支持语义的来源修订、事件、时间窗、统计与反例快照；普通证据刷新不自动改变已确认的语义 |

实体有业务 ID 就沿用；名字、商家、习惯名称、模型生成的标题不能充当唯一身份。自由语义维度采用持久化槽位与既有候选引用；模型可提出同义关联，程序验证主体、维度和条件。无法确定同一身份时保留区别，不通过误合并消除列表。

已有 HoloMemoryIdentity 算法不原地改写。旧 ID 作为 provenance/alias 保留；claimKind 或范围的实质变化建立明确替代关系，不能把多个旧确认拼成一个已确认的新结论。

### 2.2 一份知识最少携带的语义

- 主体/对象引用、开放关系与维度；直接表达/来源关联/行为推断的形成方式；原文归属、语气和必要限定。
- 事件时间、观察范围、命题适用范围、周期规则、单次例外和复核条件。创建时间不替代事件时间。
- 原始来源 ID/修订/权限/分区、事件血缘、可验证指标及单位、覆盖形态、反例和反例检索覆盖状态。
- 具体帮助意图与允许操作：背景理解、带限定的建议、精确查询所需的源关联；禁止把记忆作为执行命令或精确实时统计。
- 当前语义版本、已确认版本、用户控制因果关系、有效性与前驱；不以一个 confirmed 布尔值授权以后所有改写。

用户明确要求记住的重要经历本身就有价值；程序校验保存与消费权限，不要求命中某个业务场景白名单。新名词、新责任或偏好对象无需修改实体策略代码。

### 2.3 事实真源与用户权威

档案、账户设置、习惯定义、任务/目标状态由原模块拥有。记忆只持有引用，相关查询实时解析；不后台反写档案、目标协议、提醒或交易。

当前输入优先于记忆。同主体同条件下，用户明确纠正优先于自动推断；两个用户声明相冲突且不能由时间/条件区分时，保留冲突，相关时做最小澄清。用户说“喜欢咖啡”与记录很少买咖啡不构成直接反证；目标“想健身”与最近未锻炼也不相互否定。

用户说“我觉得加班让我更想抽烟”，保存的是用户的个人解释及其限定，不改写成系统验证过的因果。当前问题需要以此为前提讨论时清楚保留形成方式。

照料责任表达为用户本人需要考虑的条件，不扩建第三方画像；来源敏感级别及既有权限继续适用。一次购买不能证明本人拥有或喜好，一条未完成任务不能证明已发生。

### 2.4 修订、确认与当前权威版本

语义修订一经生成即不可原地改正文；每次修改产生新修订。语义指纹只归一化结构事实，不用全文摘要作身份，不让模型自报“语义没变”直接通过。

指纹包括主体/对象、关系与肯否定、关键对象值、条件、绝对适用范围或相对窗口规则、必要限定和允许用途。例如“月租 5000”中的 5000 属于语义；支持“近期周末日均更高”的本次样本量和展示统计属于证据快照。把一个月扩成长期、把相关改成因果，必须改变语义版本。

确认操作绑定 propositionID、semanticDigest 和发起方见过的控制事件，而非仅绑定 recordVersion。提交时重新核对同一语义的当前证据与权限；只有快照更新可继续提交，语义改变或出现未见限制时返回明确冲突，保留草稿。

同一命题可以同时有“仍有效的已确认版本”和“待确认的新建议版本”。只有前者可被持续使用；若反证已使前者失效，则两者都不能作为当前确定知识。不能在一个 record 上先覆盖正文，再保留旧 confirmed。

用户纠正提交的新内容是一份有独立来源的用户陈述，连同修订与操作在同一存储分区事务保存。它可承接用户权威，却不制造新的行为次数或替用户认证错误统计。

跨设备并发采用既有控制代数：未见过的限制不能被旧确认/恢复解除；两次不同纠正保持冲突。主题相同不代表可以二选一，最后时间戳和更大的版本数字均不能替代因果判断。

## 3. 证据与规律形成

### 3.1 证据形态决定计算方式

| 形态 | 适用输入 | 如何判断充分性 |
|---|---|---|
| 明确语义事实 | 用户陈述、纠正、明确记忆请求 | 主体、语气、作用范围、持续性和原文支持；不要求重复 |
| 独立事件集合 | 消费、任务完成、负向习惯发生等 | 原始事件血缘、发生时间、自然周期与来源覆盖；没有事件不自动当零 |
| 采样数值序列 | 体重、睡眠测量、按日记录 | 单位、测量口径、可比较样本与缺失；导入、目标或设备口径改变时分段 |
| 有效区间/周期与例外 | 每周责任、月付费用、临时限制 | 规则、自然周期、适用起止与实例状态；一次例外不覆盖整条规则 |
| 多来源语义关系 | 责任、依赖、条件关联 | 原文支持、主体/范围一致性、独立来源与反例；相关不能写成因果 |

同一事件在账单、想法、周报中出现只计一次。重叠聚合窗口必须回溯底层事件或证明区间独立，不能按“报告数”计证据。用户确认表示认可语义，不增加行为样本量。

每个可推出的统计命题先固定比较、时间窗、分母、方向、最小实际变化及适用证据形态，再计算。规则参数以命题模板和指标单位登记，避免把打卡天数门槛套给月度账单。没有可比覆盖就只描述“已记录范围”，不宣称全生活占比。

### 3.2 准入的统一问题

每个候选都要回答：原文是否支持？数据独立吗？观察跨度足够吗？搜过反例吗？范围、时间、单位和缺失是否正确？未来有什么具体作用？是否仍适用且允许保存？

“数据是真的”与“这个归纳有用”分别判断。重复很多但仅表达日常流水的内容退出；低频但明确重要的约束保留。未知和证据不足停留后台，不能把半成品交给用户判真假。

规律模板需覆盖趋势、重复节奏、周期负担和条件差异。每个模板具有明确的最低跨度/样本/对照/实际变化定义与反例要求；参数作为可测试配置登记。未经支持的新统计模板不自动上线，开放语义事实仍可通过同一通道保存。

### 3.3 变化、反证与确认

| 变化 | 处理 |
|---|---|
| 新证据仍支持同一已确认语义 | 更新证据快照与展示数字，不增新记忆、不反复确认 |
| 关系、方向、范围、例外或关键对象值改变 | 生成新的语义修订，待确认；不得继承旧确认 |
| 只是历史一次例外 | 记录例外与范围；检查原规律是否允许例外，不立即推翻整体 |
| 新反证使原规律不再成立 | 暂停相应当前用途，保留历史；不能因曾确认而永远有效 |
| 用户直接纠正 | 生成用户权威的新陈述及其证据，保留因果链；新自动批次不能覆盖 |
| 来源删除、排除、权限撤回 | 相应证据退出；重算剩余支持与用途；不靠旧摘要维持有效 |

阶段趋势只覆盖那个阶段。相对滚动窗口与明确历史窗口必须区分；不能把用户确认的“三月如此”自动改成“现在一直如此”。

### 3.4 首发模板与参数归属（实施默认已定）

主流程支持所有来源；数值归纳先开放下列有明确契约的模板。没有登记统计定义的指标仍能查询、关联事实和保存用户陈述，不能凭模型编一个数值规律上线。

| 模板 | 最低支持与验证默认 | 对缺失/阈值的要求 |
|---|---|---|
| 周期规则/固定负担 | 至少 3 个完整独立自然周期；实例确属同一规则，时间与金额容差在规则定义中登记 | 频率可为周/月等已声明周期；没有声明周期时先做候选周期估计，须后续完整周期验证 |
| 可比较窗口变化 | 两个完整同口径窗口；按日场景默认各 7 天、至少各 5 个有效观察；更稀疏序列扩窗而非补零 | 存在应观察机会时覆盖至少 70%；事件型数据不套日历分母；单位/目标改变则分段 |
| 周内重复节奏 | 默认覆盖 4 个完整周，至少 3 周方向一致；每周被比较分组均有有效可比观察 | 只有命中的日期不够；不同长度分组比较单位机会频率/强度，不能直接比事件总数 |
| 开放条件/跨域关联 | 条件、对象、对照、机会分母和时间范围明确；数据探索得出的候选冻结后，至少增加 1 个未参与选择的完整自然周期验证 | 无可定义的可比机会或反例覆盖不完整则不晋级；只表达关联，不表达因果 |

数值指标必须注册单位、分辨率/误差处理、聚合方法、有效观察与最小实际变化规则。优先沿用原统计模块的已核对定义；没有相应定义时该数值模板不开放，不随意采用统一百分比。这里不要求临床显著性，也不把记录变化称为诊断。

以上参数是可测试的首发工程定义，非普适科学证明。预先定义的比较与从大量候选中挑选的结果区别处理；不能把检索命中证据再送一次模型就称独立验证。模型与反例评测仍是 W5 的发布门槛。

## 4. 从形成到使用的状态契约

保持保存、可见、确认与可使用四件事分开。一个最终决策由现有 HoloMemoryDecisionPolicy 承担；HoloMemoryUsefulnessPolicy、RecallPolicy、AnswerEligibility 和管理投影消费同一判定，不再各自成为最终规则。

| 决策 | 前台 | 可使用范围 |
|---|---|---|
| 无价值/不支持/禁止保存 | 不展示为个人记忆 | 不沉淀；原模块仍按自身权限提供事实查询 |
| 内部积累或身份待明确 | 不列为待确认事项 | 不作持续个人理解；当前问题需要时可查允许的原记录 |
| 已有直接陈述或有效来源关联 | 已记住，显示真实形成方式与范围 | 相关问题中使用，受当前权限、源状态和时间约束 |
| 成熟但未确认的行为规律 | 值得确认 | 只可用于展示该结论及依据，不能暗中改变持续个性化 |
| 已确认且仍有效的规律 | 已记住 | 按准确语义与允许范围提供背景和建议 |
| 失效、过期、被替代、冲突、停用 | 次级历史或停用；冲突相关时澄清 | 不当作当前确定知识 |

普通事实分析可以直接计算趋势并回答用户问题，不能因为未形成个人记忆而停摆。当前对话中提出一次有根据的观察，不等于永久保存并跨会话使用。

所有请求携带所用语义/证据/权限与控制代际，提交和呈现时复查。资格变化只重新组装受影响请求或给出明确结果状态，避免在每层堆叠相同判空和重试。对正在输出的回答，相关控制变化后停止继续输出受影响内容，已展示部分保留为历史并标记更新，不把它作为新一轮有效上下文。

来源核验不以 Unknown 默认放行。每个接入来源必须能返回存在/版本匹配、已删除、已排除、权限撤回或当前未知，以及可影响命题的业务状态；未知只保留历史和待核状态。用户独立陈述/纠正本身的来源与原行为证据分开，不能因旧账单删除而抹掉用户后来明确补充的偏好。

权限沿用现有开关，不新增一组记忆授权。自动学习关闭时不后台产生/补建新知识，辅助回答开启时可用既有合规知识；辅助回答关闭时可在原授权下继续形成知识，但不注入一般回答。管理查看始终可用。用户明确发起的“请记住/修改”按手动操作处理，不暗中开启自动学习；涉及外部 AI 仍需现有处理授权。来源排除与敏感限制在全部组合下都优先，处理授权撤回后不外发该数据。

## 5. 管理与交互

独立“Holo 记忆”入口保留；主视图为“已记住”“值得确认”。已记住按主题组织，主题下保留不同命题、条件和有效期；不把不同领域的生活拼成单一人格故事。

“值得确认”推荐区一次最多 3 条，用户可主动查看/搜索全部成熟候选；不展示后台半成品数量，不做红点/推送或每日清空任务。排序考虑当前需求、用途与新增信息，不能为了凑三条降低质量。

暂不处理的同语义候选默认冷却 30 天，冷却期间仍可主动查到。新证据造成重要语义变化时按新修订评估，不能仅换措辞绕过冷却或否定。聊天中只在影响当前任务时询问一项，跳过后继续解决当前问题。

每条给结论、最少充分依据与适用范围、为何有用；支持符合/修改/不准确/暂不处理。确认绑定当前语义修订，保存成功才回执。暂不处理不是否定；不准确不等于忘掉整个主题；停用/遗忘继续遵守用户控制。

来源编辑、删除、过期、加载、处理中、无成熟结论和失败分别显示真实状态；保留编辑草稿与可用的撤销。操作至少 44pt，动态字体与 VoiceOver 可读；不靠颜色表达状态。查看来源与管理操作分开，不打开页面即调用模型。

形成方式如实标记“你告诉 Holo 的”“来自关联记录”“你确认的理解”，不把来源关联伪装为用户亲口陈述。更多入口保留历史、停用与全部已保存理解的检索/管理；隐藏半成品不等于用户失去对已持久化数据的控制。后台证据索引优先只留必要引用，未成熟模型猜测不无限保存成一份隐形画像。

## 6. 全链路接入与替换职责

| 层 | 当前入口/拥有者 | 本次职责 |
|---|---|---|
| 领域与个人情境产生者 | MemorySignalDataAdapter、HoloMemoryObserverService、HoloPersonalContextExtractor、HoloLifeSourceObservation | 全部输出同一来源/候选契约，进入统一准入；不直接用候选状态授权当前理解 |
| 报告与旧记忆产生者 | HoloReportUnderstandingCoordinator/Extractor、HoloLongTermMemoryCandidateObserver、HoloEpisodicMemoryStore | 派生只回指原始事实；旧生成器在新客户端退出写入所有权，历史文件作为导入输入 |
| 聚合与数值 | 原模块统计、HoloPatternMiner、证据血缘工具 | 使用同一单位/业务语义，按受影响主题增量计算；不另抄一套统计 |
| 档案/目标/任务等权威状态 | HoloProfileService、相应业务 Repository | 关联读取，不复制状态；当前变更进入失效与重核 |
| 用户控制 | HoloMemoryUserControlService/Transaction/Algebra | 复用因果与限制优先语义；确认绑定语义，修改、停用、遗忘有完整事务 |
| 查询与上下文 | QueryService、SummaryProvider、ContextEnvelope、PersonalContext 检索/规划 | 共享一个 ResolvedKnowledge 决策结果，携带必要限定与版本，不直读 active 代替资格 |
| 分析与 Agent | 本地 Agent、Memory Tool、云端 memory.entries、报告/回放上下文 | 传递限定、时间、用途与版本；只支持纯摘要的消费者先接协议再开放使用 |
| 旁路 | HoloLifePatternService、旧长期/情境摘要、档案原文注入 | 用户明确反馈的表达偏好可适配；行为归纳必须走同一确认与授权；禁止绕路提供个人规律 |
| UI | MemoryCenter、参考记忆、旧回执/深链 | 使用同一投影与计数；旧 ID 经别名解释，不跳到相似却不同的命题 |

对纯逻辑计算、语义抽取、最终决策和存储分别明确归属。已有 Usefulness 中的摘要关键词/lineage 前缀特判随通用契约替换，不叠加更多特判；业务模块真实数值口径继续由模块拥有。

统一消费载荷 ResolvedKnowledge 必须包含命题/语义/证据版本、形成方式、适用条件与范围、来源状态、允许用途和控制代际。消费者只能按自己的操作能力缩小用途，不能重新裁决为更高权限；云端或旧摘要协议不支持这些限定时，该入口暂停注入相关新知识，普通数据分析照常工作。

W1 要落实八域来源核验适配；档案、任务、目标的当前状态直接读取所属 Repository，事件来源核对软删/AI 排除/修订，健康来源沿用本机访问与撤权机制。适配器返回共同结果，不让每个页面自己猜未知含义。

## 7. 历史与版本兼容

### 7.1 已确认的现状与必要的隔离

当前 HoloMemoryRecord 整体存入 recordData。新顶层可选字段会被不认识它的旧 Codable 解码/重编码剥掉；外层枚举没有未知值容错；部分读取只认 active；未知 decision envelope 也并非所有消费者都会阻断。只加字段和 schemaVersion 无法保证旧端行为。

冻结选择：在同一 Repository 中增加以下两个 vNext 实体，旧实体保留作单向兼容输入与历史。

| 新实体 | 保存内容与不变量 |
|---|---|
| HoloMemoryKnowledgeRevisionMO | propositionID、semanticRevisionID/digest、主题与源别名、完整语义及初始依据引用；修订正文不可原地覆盖。必要物理属性带默认值/可选，符合 CloudKit 增量约束 |
| HoloMemoryKnowledgeOperationMO | 幂等操作 ID、目标命题/语义、前驱控制、操作种类、证据快照/别名/迁移收据等版本化载荷；用户确认/纠正/限制在这里形成权威事件 |

两个实体同属现有普通/敏感分区，由一个仓库 API 访问。当前已接受版本、待确认版本、主列表及召回均从这些内容投影，不另维护两套可变 active/confirmed。读取投影及反向依赖索引是可重建缓存。

**新控制不能写入旧 HoloMemoryControlEventMO。** 旧重放器遇到不存在于旧实体中的目标会标记完成；因此只复用其因果/限制优先代数，新操作的读取、重放和分区解析与新实体一起隔离。缺少对应修订的晚到操作保留待解，限制操作先按目标阻断，不能当作目标不存在而丢弃。

同分区的一次用户操作、必要新修订和收据用一个 Core Data 事务保存；不沿用旧跨 context 三步写法再加重试。普通与敏感分区分别提交，按收据汇合，不伪造跨库原子性。

CloudKit 不依赖唯一约束：重试复用同 operationID；观察收据用源/修订/策略处理键；同步出现相同逻辑 ID 的重复行在 Repository 归并。并发创建的自由语义槽位只有证明同命题时才加别名；限制控制跟随全部别名传播，不以合并丢掉冲突。

不向旧 recordData 双写新知识。新端每个命题只有一个权威投影；旧记录从兼容适配器进入相同决策，拥有新投影后不再被直接当作第二份事实使用。

普通知识延续现有普通分区；健康或敏感来源及其派生、证据、向量和操作历史留在既有本机分区，不通过迁移扩大同步范围。多来源取最高敏感级别，任何快照、操作、标题或索引都须先决定分区再写。包含敏感关系的跨分区连接只在本机解析，不把敏感摘要或关系通过普通别名带上云。

分级同时考虑来源限制与命题内容；不能把“来自聊天/想法”当作普通信息的证明。分类不明时不写入普通同步分区，保留可诊断的待分类结果；不在多个页面用敏感词列表补判。

本机敏感理解只承诺在拥有相应来源的该设备使用；不暗示它会完整同步到其他设备。其他设备上的非敏感独立事实继续按自身来源与范围判断，不把本机敏感信息变更伪装成已全局同步。

CloudKit 模型只做新增实体/属性，保留旧类型；不能把本地可迁移等同云端 Schema 已部署。[Apple 官方说明](https://developer.apple.com/videos/play/wwdc2022/10120/)将云端 Schema 演进限制为新增字段与类型；本地模型迁移不会替代云端 Schema 发布。实际新旧设备镜像兼容须实测，不因“增加实体”自动宣称通过。不重置开发库，不以清库解决不兼容。

### 7.2 存量分流

| 存量 | 导入规则 |
|---|---|
| 可靠用户陈述、用户添加或纠正 | 保留精确原意、范围、用户权威及来源；不批量二次确认 |
| 已确认的行为规律 | 原确认仅适用原命题；来源足够则沿用，失效则保留历史并暂停相应用途 |
| 已确认的单次事件 | 保留确认及历史可查；不自动扩成持续个人属性，也不占主确认队列 |
| 自动生成的单次流水/低价值内容 | 退出主记忆与持续召回，原业务事实不动 |
| 自动规律/关联但未确认 | 有原始支持才进通用聚合与成熟度检查；不因旧 active 自动当已认可 |
| 不准确/停用/遗忘/墓碑 | 原因与阻断范围先导入；新 ID/别名不能复活 |
| 未知版本/无可核对来源/歧义身份 | 单条保留原数据、排除新能力并记录原因，不猜事实、不让一条坏数据拖垮整个列表 |
| 旧文件长期记忆/短期记忆/生活模式摘要 | 有用户明确表达或底层来源才映射；AI 摘要本身不成为独立证据 |

### 7.3 分批迁移

先读控制与基线，再规范化来源、分类旧记录、生成别名映射、写入新知识、校验分区与范围、标记单项完成。每个处理键包含 Store/分区、旧 ID/修订与新策略版本；收据记录 scanned/classified/committed 或受限/需重建等明确状态。游标只在持久化成功后推进，重复执行不重复确认或新增知识，不以本机 UserDefaults 的单个完成标志代表全账户完成。

迁移批次固定来源水位；批次中新变更进入增量队列。每个旧 ID 只有一个新投影所有者，别名与导入收据同事务生效；未完成项通过同一策略的 legacy 只读适配得到受限投影，不通过旧 active 查询悄悄回退。只有明确受影响的项暂停新能力，不阻断原业务模块。

先迁移有效用户陈述、现有目标相关知识及有效阶段，再补历史；结构化本地能判断的不用模型。只有需要语义重建且获得原授权的数据进入正常预算队列，不全量无界重萃取。远端同步/导入/恢复用存储变更及源修订目录对账，不能只靠 updatedAt 水位。

从迁移开始，新客户端所有写入者转统一流程；旧客户端仍可能生成旧记录，后续同步按相同兼容输入处理。新端不能远程承诺旧应用不展示碎片；旧设备升级后才获得新体验。

### 7.4 恢复与失败边界

按现有迁移前自动快照保护本地库；迁移进度可断点续跑，业务记录始终可用。跨分区不做虚假的原子提交，分区收据完整后才推进总进度。

回滚采用保留新 Schema 的修复版本或停止新生成，保留用户控制及已经接受的知识；不承诺旧二进制能逆向打开升级后的本机库。新 Schema 的健康检查、隔离库演练和多设备验证是发布门槛，不是清空用户数据的理由。

迁移前快照只用于灾难恢复，不能常规覆盖正在使用的库。恢复时必须先合并快照之后的遗忘、纠正、权限限制与学习基线，再开放记忆；无法确认控制完整性时暂停记忆使用，保留业务数据与恢复材料。不得因修复“升级丢记忆”而把已忘内容全部重放。

### 7.5 旧写入、同步晚到与逐行读取

新客户端关闭旧生成器对旧 Store 的写入所有权；旧 JSON 文件只读导入，不双写新结果回去。仍在运行的旧客户端可以继续写旧格式，新端将它作为待分类输入，而非权威覆盖。

旧确认只能确认当时可核对的原语义；旧纠正必须有准确正文与可关联操作，缺少正文只保留控制事实并待核，不从 payloadDigest 反推内容。旧限制经旧 ID/命题别名作用于相应新知识；未知因果的放宽不得解除新限制。旧行的自动重写或较晚 updatedAt 不构成用户新授权。

旧记录缺少真正来源时不从 AI 摘要重建“事实”。若可靠历史操作足以证明用户当时认可该准确陈述，可以保留“此前由你确认”的原范围历史；不能伪称来源已核验，也不能恢复已删除正文。

原始持久化边界按 MO 单行 decode，返回可用项、隔离项与覆盖状态。未知/损坏的原字节保留，不新建非法外层枚举让旧整批解码崩溃；不能在消费者最外层 catch 成空列表掩盖整批失败。逐行隔离属于格式边界处理，所有下游只消费标准结果。

学习基线保留原含义。清空后旧源的导入、改写或较晚 observedAt 不能自动变成全新生活证据；兼容清单记录旧源/修订边界，明确请求重新学习才放开相应范围。

### 7.6 清理、源失效与派生数据

删除与失效在同一个依赖清单中盘点：新旧知识、语义修订、操作正文、旧别名/导入快照、证据目录、主题投影、向量/搜索索引、Prompt/报告缓存与在途任务。新实体必须加入现有回收站、全清、导出/恢复及源排除入口清单，不能只改管理页按钮。

“不准确”阻断当前被否定命题/语义，不封禁整个主题；“停用”停止该命题使用并保留可恢复历史；“忘记”清除该命题正文与相关派生，仅留最小无正文阻断。来源 AI 排除另行覆盖该来源及其派生，不能靠别名或报告再次进入。恢复原账单/想法不等于恢复用户遗忘的知识。

新加入健康/敏感来源的修订及其操作在写入前归本机分区；原普通来源的独立事实可保留原身份，但不能继续暴露新增敏感联系。若原行本身曾错误包含敏感内容，应作为单独数据纠正处理，不能假装移动一行就能撤销历史同步。

## 8. 调度、性能与成本

复用现有 dirty/receipt 调度思想，由来源变化定位受影响主题；独立事件去重、统计和初筛在本地完成，模型仅做开放语义关联、归纳与必要核验。同源同修订同策略仅处理一次，空结果也写完成收据。

依赖是来源 → 证据快照 → 命题修订 → 使用上下文；来源、控制或策略改变后只使相关结果失效。文本、索引和向量都是受同一权限约束的派生物，不能因为没有出现在主列表就继续被检索。

前台、后台和手动刷新共用队列与预算；后台 best-effort，回前台续跑。打开页面不扫描全历史；历史补建按现有分页/字符/候选预算执行，有明确暂停与失败状态。

证据/向量/主题投影按实际容量做缓存回收，可从允许的来源重建；未接受且过时的候选退出内部工作集。不能靠删用户明确保存的知识或永久保留全部模型草稿控制容量；纠正、遗忘和必要历史各有明确保留/清理职责。

### 8.1 不写防御性补丁的实施约束

- 保留必要的格式/引用/权限/源版本校验，集中在外部输入、仓库事务提交与请求呈现边界；数据契约一旦成立，下游按类型消费。
- 既有 Usefulness、Recall、AnswerEligibility 不各自扩一份规则；统一决策输出同时驱动展示、确认和消费，允许的是明确语义适配。
- 不加实体关键词黑名单、不从摘要猜成功/失败、不把缺字段补成高置信默认、不以 try? 返回空结果隐藏持久化/协议错误。
- 只为实际异步竞态与跨版本格式做一次因果/版本处理，不在每层重复状态检查和重试。无法处理的输入有明确隔离状态，系统错误可诊断。
- 不引入新模型供应商、第二套任务系统、全量知识图谱服务或无需求的分布式锁。新实体只承担已实证的版本隔离和不可变控制职责。

## 10. 设计完成与效果完成分别判断

设计层须关闭两轮审查中的阻塞，方案没有留给实施者重新拍板的存储/控制语义空白。实现层以场景矩阵验证：关键权限和控制错误为零，八域样本都具备从来源到使用的证据，模型的支持与不足能够复核。
