## 最重要的修订

- 重要的一次信息、用户责任、偏好约束、当前阶段和行为规律全部有路径；重复性要求只用于行为归纳。
- 分开主题、命题、语义修订和证据快照；确认只认可准确语义，普通证据更新不会天天要求重确认。
- 所有写入者与消费者共用统一决策；原始查询照常，未确认的行为推断不在其他入口偷偷持续使用。
- 增量增加专用知识修订与操作实体，沿用一个 Repository 与原普通/本机敏感分区；旧格式单向导入，不双写新知识回旧表。
- 历史保留来源、用户陈述、精确确认、纠正及限制；旧 active 不等于已认可，旧晚到写入不能覆盖新控制。
- 常规回滚采用前向修复；快照恢复必须先合并较新的遗忘和控制。清空、源排除、索引与在途结果按同一依赖清单处置。
- 新实体的格式、权限和提交校验集中在真实边界；替换摘要关键词/lineage 前缀特判，不堆新兜底、重复规则或第二套画像。
- 发现与记忆共用观察/证据/命题身份，成熟发现可“确认并记住”；双向纠正、来源失效和跨入口去重属于首批必做，不能只互加跳转链接。一个发现仍只在自身获准范围工作。

## 开工与发布的界线

可以按 W0 → W1 → W2/W2D/W4 → W3 → W5 实施。W0 落实已经选择的类型、存储和夹具，不再留给实施者重新决定产品语义或数据去向。发布前须完成确定性与持久化测试、模型盲测、隔离迁移演练、发现与记忆真实联动、设备/多设备以及实际后端 Prompt 验证。

本轮实际运行的是现状兼容性探针，复现 6 类缺口；没有修复业务代码，没有做实际迁移或修改个人数据，没有部署后端。两轮审查均为同一主代理的顺序自审，不声称获得外部或子代理独立评审。
