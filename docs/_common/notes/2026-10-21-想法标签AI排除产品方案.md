## 一、需求

用户给想法打的标签里，有些是私密方向的（如日记、心情、家庭）。这些想法：

1. **不参与 AI 主题归类与自动打标签**——AI 不许碰它们；
2. **不参与任何 AI 分析与复盘**——洞察、报告、聊天背景、深度分析等全部通道一律过滤；
3. **选择权在用户**——想法模块里要有入口，用户自己决定哪些标签排除。

一句话口径：**AI 完全看不见这些想法，连「存在多少条」都不知道；但用户自己看想法的一切功能照常。**

## 二、三个拍板口径（2026-10-21 东林拍板）

| # | 决策点 | 拍板结果 | 含义 |
|---|---|---|---|
| 1 | 存量追溯 | **连存量一起清** | 开启排除时，该标签下想法已有的 AI 主题归属（ThoughtTopicLink）、AI 打的标签（ThoughtTagAssignment source=ai）、向量索引一并撤下/删除；历史已生成的洞察/复盘报告**成品**不重算。关闭排除后可重新归类 |
| 2 | 单次主动请求 | **一刀切不让用** | 带排除标签的想法，「帮我想想」「想法转任务」等 AI 按钮置灰并说明原因；想用先到设置里关掉该标签的排除 |
| 3 | 入口 | **双入口 + 卡片角标** | 主入口=想法设置页「AI 分析范围」子页；副入口=标签管理页每行盾牌开关；列表卡片右上角淡金盾牌角标 |

## 三、生效范围（用户视角）

**AI 从此看不见（排除）：**

- 主题归类、自动打标签、向量索引（organize / semantic-relate / embeddings 全链）
- 每周洞察、深度洞察（想法原文通道，含 ≤20 条全文摘录）
- 复盘报告、回放摘要
- 聊天的「近期想法」背景资料
- 深度分析（agent）里的想法数据集（thought.daily）与想法工具
- 个人情境萃取、记忆信号观察
- 标签收敛、主题命名与简介、类别理解（brief）
- 「帮我想想」「想法转任务」（口径二，一刀切）
- **连「有多少条」都不进入任何 AI 统计/计数**

**照常运转（不动）：**

- 想法列表、搜索、筛选、想法统计页（那是给用户看的）
- 用户手打的标签、iCloud 多设备同步
- 想法编辑、附件、回收站与恢复
- 不带排除标签的其他想法一切如常
- 「AI 智能整理」总开关等既有设置

## 四、界面设计（对应原型画板）

| 画板 | 内容 | 要点 |
|---|---|---|
| ① | 想法设置页 | 在「智能整理」与「内容管理」之间新增独立分区「AI 参与范围」，一行入口「AI 分析范围」，右侧值实时显示「N 个标签已排除」（无则「未设置」）。独立成区的原因：它管的是隐私边界，和「开关整理功能」是两件事 |

| ③ | 开启确认弹窗 | 首次开启某标签排除时弹。四要素：干什么/彻底到什么程度/存量怎么办/随时可关 |
| ④ | 标签管理页副入口 | 每行右侧盾牌开关，行为与画板②一致；原有标签管理操作不动 |
| ⑤ | 想法列表 | 排除卡：右上角淡金盾牌角标、排除标签棕色带小盾、无主题徽章；正常卡不变。角标刻意低饱和，提示而不喧宾 |
| ⑥ | 想法详情 | 「帮我想想」「转为任务」置灰（不隐藏）+ 米色提示条指路设置入口；「相关笔记/主题」区块停用并说明 |

**交互细节：**

- 开启排除：弹确认（口径一、二都写在正文里）→ 确认后开关变橙、盾牌出现、摘要计数联动；
- 关闭排除：**不弹窗**直接关 + toast「已恢复参与 AI，稍后自动归类」——恢复参与是低风险方向，AI 自动重新归类；
- 弹窗策略（待定项）：v1 简化为「每个标签首次开启必弹，之后不再打扰」；备选「仅该标签下有已被归类的想法时才弹」。倾向前者，实现简单且不打扰。

**文案定稿（原型已按此渲染）：**

- 子页标题卡：「有些想法，只想留给自己。」「在这里标记的标签，Holo 不会交给 AI——不归类、不分析、不进任何报告。」
- 弹窗标题：「把「日记」留给自己？」（动态标签名）
- 弹窗正文：「带「日记」标签的想法将退出所有 AI 处理：不归类主题、不打自动标签、不进洞察与复盘——AI 不会知道它们的存在。已有的 AI 归类会一并撤下，随时可以关闭恢复。」
- 摘要小字：「AI 看不到这些想法——连「存在多少条」都看不到。」
- 设置页 footer：「有些标签下的想法，可以只属于你自己。标记后它们不参与任何 AI 归类与分析。」
- 详情页提示条：「这条想法带有不参与 AI 的标签（#日记），AI 功能已停用。想在它身上用 AI？到「想法设置 › AI 分析范围」关掉该标签的排除。」

## 五、技术落地要点（10-21 第一轮对抗审查后修订版）

### 架构判断（三路代码探索核实）

- **无需后端发版**：想法与标签只存 iOS（CoreData + iCloud 私库）；自建后端是无状态 AI 网关，每次请求由 iOS 组装内容上传、用完即焚。过滤做在 iOS 组装层，后端天然接触不到被排除数据。
- AI 读想法共 9 组通道。**整理 V2 队列（organize）当前整体停用**（`ThoughtAIClassificationPolicy.isEnabled` 硬编码 false），挂点照做防未来开闸，实施重点是 V3 语义管线（embed/relate）与各 builder。

### 数据模型

- `ThoughtTag` 新增 `excludeFromAI: Bool`（默认 false），照 `autoSuggestionBlocked` 模式（`CoreDataStack+ThoughtEntities.swift` 属性 + `ThoughtTag+CoreDataClass.swift` @NSManaged）。轻量迁移兼容；上架 Production 时需部署 CloudKit schema（Development 自动推，增量兼容不碰红线）。
- **排除判定谓词（关键修订）**：thought.tags 关系被 AI 标签污染（编辑器保存的 `rebuildTagsRelation` 会把非 rejectedAI 的 assignment 含 source=ai 并集写回 tags），因此判定**只认用户关联**：
  `SUBQUERY(tagAssignments, $a, $a.rejectedAt == nil AND $a.source IN {"manual","inline","confirmedAI"} AND $a.tag.excludeFromAI == YES).@count > 0`
  —— 用户手打（manual/inline）或确认采纳（confirmedAI）的排除标签才触发；AI 自动打的不触发（避免「AI 打标反而把想法踢出 AI」的自缠绕）。
- 与 `autoSuggestionBlocked` 语义区分：后者=「AI 不许自动用这个概念名」（想法仍参与）；前者=「带此标签（用户关联）的想法整体退出 AI」。
- `Thought.organizedStatus` 新增值 `"excluded"`，加入 `ThoughtAIClassificationPolicy.manualBatchTerminalStatuses`（防 countUnprocessed 永远算它）；关闭排除时置回 `"pending"` 重新入队。

### 过滤策略：AI 受众分离（关键修订）

**不改任何用户 UI 查询的语义**，按方法调用方分类处理（10-21 核实结论）：

| 方法 | 调用方 | 处理 |
|---|---|---|
| fetchAll / search / fetchById | 用户 UI + AI 混用 | 方法不动；AI 调用方取数后按排除判定过滤（UserContextBuilder / MemoryInsightContextBuilder / MemorySignalDataAdapter / ThoughtSemanticCandidateEngine / HoloContextSemanticSearchRuntime / HoloLifeSourceObservation / SemanticEvaluationExporter） |
| getThoughtTexts / getTopTags / getMoodDistribution / getThoughtCount / fetchConvergenceCandidates | 纯 AI | 方法内加排除过滤 |
| getThoughtCountByDay | AI + 周观察（用户） | 加 `aiVisibleOnly: Bool = false` 参数，AI 调用方传 true |
| fetchThoughts(from:to:) | 纯用户（日历） | 不动 |

新建 `ThoughtAIAudience`（静态谓词 + isExcluded(thought) 判定 + 数组过滤 helper），以上全部引用它。

### 过滤挂点清单（iOS）

1. **入队时**：`ThoughtSemanticChangeFeed.handleSave`（保存事件源：排除想法不入 embed/relate 队列，且命中排除时触发单条清理兜底）、`enqueueEmbedIfNeeded/enqueueRelateIfNeeded`、`reconcileAllThoughts`（分页扫描谓词加排除 + 「命中排除但向量活跃」则清理——覆盖多设备同步与本机漂移）、`ThoughtOrganizationQueue.enqueue/enqueueBatch` 入口、`fetchPendingThoughtIds/fetchUnprocessedThoughtIds/countUnprocessed` 谓词
2. **执行时（双重过滤，防队列滞后）**：`ThoughtSemanticEmbeddingExecutor`（fetch 谓词 :50-57/:133-145 + `revalidateBeforeCommit` :210-231）、`ThoughtSemanticRelateExecutor`（fetch :60-72，照 thought_unavailable 模式 finishJob cancelled + errorCode excluded_from_ai）、`ThoughtOrganizationService.organizeThought`（软删拦截 :58-69 紧贴加排除拦截，置 excluded）
3. **AI builders/数据集**（上表混用类调用方 +）：`HoloThoughtReferenceDataSource.swift:22`、`HoloPersonalContextRuntime.swift:31-40`、`HoloAgentRuntimeShared.swift:112-125`（thought.daily rows）、`HoloCloudAnalysisSnapshotBuilder`（快照 rows 同源）、`ThoughtAnalysisContextBuilder`、`MemoryInsightContextBuilder`（search/texts/counts）、`HoloReplayDigestService`、`ThoughtTagConvergenceJob`
4. **单条 AI 按钮门控（口径二）**：编辑器「帮我想想」(ThoughtRelatedSection 挂载条件 ThoughtEditorView:220-224)、转任务 sheet「AI 智能识别」按钮 (ThoughtTaskExtractionSheet:118-135)、编辑器「重新整理」菜单 (ThoughtEditorView:1355-1362)、语音智能总结 (排除想法不挂 ThoughtVoiceSummaryProcessor，语音输入照常)、「相关笔记」区块（排除想法不显示）——置灰或隐藏并提示。分享卡/SuggestionPanel 标签候选均为纯本地无 AI，不动。

### 存量清理（口径一）——`ThoughtAIExclusionService`

触发三路：①UI 标签开关开启（批量：该标签用户关联的全部想法）②EditorCommit 保存后发现命中排除（单条）③ChangeFeed/reconcileAllThoughts 兜底（覆盖「已归类想法事后补打排除标签」与多设备同步）。

单条想法清理动作（幂等）：
- AI 打的标签：`ThoughtTagAssignment(source=="ai" 且 active)` → `indexState = superseded`（照 setAutoSuggestionBlocked 做法）；manual/inline/confirmedAI 不动
- 主题归属：`ThoughtTopicLinkProjection.recordManualRemove`（rejected 墓碑，AI 不得重建该 pair；关闭排除后重新归类可能不回原主题——AI 建议性质，可接受）
- 向量：`store.tombstoneItem(thoughtID:)` **+ 显式 `LocalSemanticIndex.remove(id)`**（tombstone 不自动剔内存索引，已核实）+ 丢弃在途 semantic_job（无按 thoughtId 取消 API，执行时过滤兜住）
- `organizedStatus = "excluded"`
- 长期记忆（两种库，证据含排除想法即删——宁可少记不可漏）：`HoloLongTermMemoryStore` 新增按 `evidence.source == .thoughts && sourceID ∈ 目标` 遍历 delete；`CoreDataHoloMemoryRepository` 新增按 `evidenceRefs[].sourceDomain == .thought && sourceID ∈ 目标` 全量拉取过滤后 `deleteRecord`（观察器会从剩余想法重新沉淀记忆）
- 受影响 classification 主题成员归零（`effectiveActiveThoughtCount == 0`）→ `.hidden`（无自动退场规则，已核实，此处补上）；用户手动激活过的 active 主题不 hide
- 关闭排除（恢复）：状态置回 pending、assignment 不复活（AI 重打）、ChangeFeed 重新入队 embed/relate、长期记忆不恢复（由观察器重新生成）

### 标签合并与删除（核实修订）

- 合并 `mergeTag`（mergedIntoTagID 是死字段无写入者，实际走物理迁移）：**源标签 excludeFromAI=true 时目标标签自动继承为 true**（隐私泄漏方向，宁可多排除）。合并进assignments 的用户关联会触发排除，方向安全。
- 删除 `deleteTagGlobally`：tags nullify + assignments 级联 → 排除自然失效，无需处理。

### UI 实现适配（对照原型的偏差说明）

- 画板④标签管理页现状是「名称数组数据源 + ellipsis 菜单 + 行点击进列表」，无 Toggle 空间：实现为**行名称旁盾牌角标（点击即切换）+ 菜单项「不参与 AI 分析/恢复参与 AI」**，与原型功能等价；仅「我的标签」页签提供（AI 建议页签不给，与判定口径一致）。
- 画板②子页列表=用户标签（indexKind=user），数据走新 repo 方法取实体+活跃关联计数。

### 第二轮红队审查修订（10-21）

**P0 泄漏修复：**
- **V3 主题管线 5 处「按 id 取正文上传」补过滤**：`ThoughtAutomaticTopicDiscovery:94-100`（cluster.memberIDs 直连 fetch）、`ThoughtTopicVerifier:148-155`（候选代表成员）、`ThoughtCategoryBriefMaintainer:125-143`（成员样本）及 `:146-160`（removalSamples）、`ThoughtKnowledgeTreeView:210-224` / `ThoughtSidebarView:185`（簇命名）、`TopicDetailView:234`（摘要刷新）。原则：**任何取想法正文的 fetch 一律过滤**，向量 tombstone 只是其一。
- **清理墓碑改用 `superseded`**（`ThoughtTopicLinkProjection.recordSuperseded`）而非 rejected：rejected 会被类别理解当「移出反证」捞正文上传（自我泄漏），且永久阻止 AI 重建该 pair；superseded 不被捞、非有效成员、关闭排除后可重新归类。

**P1 功能修复：**
- **双向 reconcile**：`ThoughtAIExclusionService.reconcile(thoughtIDs)` 幂等双向——命中排除→excluded+清理；不命中但 organizedStatus==excluded→置回 pending+重新入队。触发：标签开关（开/关）、EditorCommit 保存后、`mergeTag`（继承后显式触发，ChangeFeed 看不见 ThoughtTag 保存）、`deleteTagGlobally`（删前记录关联想法 id，删后 reconcile）、ChangeFeed handleSave / reconcileAllThoughts 兜底。解决「标签删除/去关联后想法永久困在 excluded」。
- **跨域融合记忆级联**：删 thought 域记忆时，同时删 `upstreamMemoryIDs` 含被删 id 的 crossDomain `HoloMemoryRecord`。
- **竞态**：ExclusionService 为 actor，每次 reconcile 读 CoreData 事实源按当前值收敛（最后状态胜出而非最后写胜出）；批量在后台 context；长期记忆单次 mutate 批量删。
- 执行器丢弃检查同时认 `organizedStatus == "excluded"`（多设备 CloudKit 传播窗口内，先到的字段提前生效）。
- `fetchPendingThoughtIds` 只认 pending，无需改（删冗余项）。

**P2 决定：** 侧栏「未归类」含排除想法——保留（它们确实无主题，用户自己看合理）；`LifePlanGenerationService` 想法计数过滤；回放 digest 消化历史成品属已声明边界。

**实施环境核实：** 主 target 是 filesystem sync group（新 .swift 免挂 pbxproj）；HoloTests 是传统 PBXGroup（**新测试文件必须手工挂 file ref + group child + Sources phase**）；已脏重叠文件：HoloAgentRuntimeShared / HoloCloudAnalysisSnapshotBuilder / HealthInsightContextBuilder / HoloApp / ThoughtTopicVerifier / ThoughtSemanticPipeline / ThoughtSemanticStore / ThoughtSidebarView / project.pbxproj——只做增量、不提交。
