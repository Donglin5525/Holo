# 2026-10-27 开发版启动无响应诊断与修复

## 产品结论

用户反馈：iPhone 打开 Holo 后首页已显示，所有按钮点不动；杀掉重进仍然无响应，约一分钟后恢复。用户记忆时间约北京时间 08:50。

这次已取得真机同一时段的实际阻塞栈：**开发期 CloudKit 结构上报工具在主线程同步等网络/同步引擎**，并非普通记录同步本身要求用户等待。日常启动不应承担这个管理操作。取消自动触发，并把显式开发请求固定在独立后台队列；普通 CloudKit 记录同步不受此改动影响。

## 真机证据

- 手机安装版本：`com.tangyuxuan.holo-app`，1.1.3 (35)。
- 报告：`Holo-2026-10-27-084618.ips`，incident `94E006A2-9731-426B-A79A-49C07A43097A`。
- 启动：2026-10-27 08:45:51 +0800；捕获：08:46:16；报告时间：08:46:18。
- 系统原因：`FRONTBOARD / 0x8BADF00D`，`process-exit`，无法在 5 秒内正常退出；应用 CPU 约 0%，符合等待而非大量计算。
- 主线程已符号化调用链：

  ```text
  __ulock_wait
  _dispatch_group_wait_slow
  -[NSPersistentCloudKitContainer initializeCloudKitSchemaWithOptions:error:]
  static CloudKitSchemaInitializer.run(container:)
  closure in CloudKitSchemaInitializer.runIfNeeded(container:)
  completeTaskWithClosure
  ```

- 同时 CloudKit 队列停在 `eventUpdated` → `NSNotificationCenter` → `NSOperation waitUntilFinished`。与主线程同步等待镜像引擎形成交互阻塞风险。
- 手机偏好中的 `holo_cloudkit_schema_initialized_v2` **未设置**；旧逻辑每次启动都再次尝试上报，成功前不落标记，因此强退不能阻止重试。
- 该报告主程序 UUID 为 `f6bdff95-7d6f-3e25-a6fd-5695ce37b543`，debug dylib UUID 为 `f7639f69-1be2-30d1-8d52-aec044132c23`。系统已提供函数符号；当前本机留存的候选产物 UUID 不匹配，未拿其他包的地址映射冒充源码行号。
- `Documents/HangDiagnostics` 暂无报告目录，不把“未收到 MetricKit 报告”解释为“没有卡顿”。
- 电脑上的 `Holo-2026-10-27-085221.ips` 属 Mac 运行的 1.0.9 (31) iPad 版，已排除，与本次 iPhone 事件不同。

原始日志和偏好只读拉到 `/private/tmp/holo-startup-20261027/`，不提交个人诊断或完整偏好文件。

## 根因与修改

1. 工程 `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`。原工具 enum 和 `run` 未显式隔离；`Task.detached { await run(...) }` 在调用 `run` 时会回到主线程。注释写“后台”与实际执行不一致。
2. `CloudKitSchemaInitializer` 改为显式 `nonisolated`；同步管理 API 由独立 utility 串行队列执行，入口用 `HOLO_INITIALIZE_CLOUDKIT_SCHEMA=1` 显式请求，默认不运行。失败只在下一次显式请求时重试，成功标记仍只在真实成功后写入。
3. 同时复现另一处启动锁隐患：后台先建库时，加载完成回调持状态锁配置 `viewContext`，setter 又同步等主队列；主线程读 `isReady` 等同一状态锁，双方死锁。完成回调改为异步排入主队列配置，配置完毕才在短锁内发布终态；唤醒 continuation 在锁外进行。
4. 首轮曾先建立主容器再启动后台服务。第二轮进一步把建模、预检和备份完整移到后台，业务根视图及服务只在库成功后挂载；见同日《开发包更新后启动闪退诊断》。本工具修复自身没有改变业务模型字段。

第 3 项是隔离测试实证的独立隐患，不把它冒充本次真机报告的直接原因。

## 已发 1.1.3 的影响核查

- 发布标记提交为 `aa40c7efd`（1.1.3 / 35）；当时 Holo scheme 的 ArchiveAction 使用 Release，Release 未定义 DEBUG。修复前的结构上报入口与私有实现均受 `#if DEBUG` 保护。
- 不只检查源码：已直接核查本机留存的归档 `/Users/tangyuxuan/Library/Developer/Xcode/Archives/2026-10-25/Holo 1.1.3 (35).xcarchive`，App Info 确认为 `com.tangyuxuan.holo-app` / 1.1.3 / 35。
- 实际归档可执行文件 UUID：`86BE742B-1C92-317B-97A2-0FFF53283AB5`，无 `Holo.debug.dylib`。二进制字符串中 `initializeCloudKitSchema`、`[SchemaInit]`、`holo_cloudkit_schema_initialized_v2` 均为 0；Objective-C 元数据中该系统方法 selector 为 0；符号表中也无该工具或系统调用。
- 因此可确认：**该正式归档中不存在本次导致主线程阻塞的结构上报路径**。按这个归档发布的用户不会触发同一条故障。
- 当前没有完成 App Store Connect 在线版本与本地归档的身份对账：后台页面两次读取超时；同时间的 xcdistributionlogs 目录已为空。不能把本地归档检查描述成已核验线上二进制，也不能把本次特定原因排除扩大为所有正式版卡死原因均已排除。
- 独立发现的 CoreDataStack 锁问题不受 DEBUG 限制；已本地修正，但尚无正式用户触发证据。基于当前证据，不建议仅因本次开发版 schema 阻塞紧急上架。
