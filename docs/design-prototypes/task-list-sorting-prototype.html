任务模块 · 排序功能规划

2026-08-17 · 基于「任务页三合一 + Hero 仪表」版本 · 原型可交互

👉 试用方法：右侧手机里点击筛选条最右边的 「⇅ 排序」胶囊，选排序方式、切换方向；也可以先切「已完成」标签，再看完成时间排序。列表重排动画即为实际效果示意。

1先厘清概念：用户说的其实是「排序」

用户反馈里说的「过滤逻辑」，和过滤（决定哪些任务出现在列表里，App 已有：今日 / 全部 / 已完成 / 已过期 / 按清单）不是一回事。真正的缺口是排序——决定「这些任务按什么顺序排」。目前任务首页的顺序是写死的：先按时间分组（过期→今天→明天→本周→稍后→未安排），组内按截止时间早晚排，用户完全没有可调的空间。这个功能就是把「排法的决定权」交给用户。

2排序维度盘点：除了用户提的，还有这些

维度说明建议
截止时间用户提到「完成时间」时，进行中任务对应的就是截止时间。现版本的默认顺序就是它（只缺可选和方向切换）P0
优先级即「紧急程度」。现有四级：紧急/高/中/低，数据齐全但首页排序完全没用上它P0
完成时间用户反馈原话针对的维度，只在「已完成」标签下有意义（进行中的任务没有完成时间）P0
创建时间「我最近建了哪些任务」的场景，顺手补上P1
更新时间概念模糊（改个标点也算更新），用户难以预期不做
标题字母序中文场景基本无价值不做

另外说明：用户说的「完成时间距离今天的远近」不需要专门算一个「距离天数」字段——按完成时间排升降序，效果完全等价，实现简单得多。

3九个容易漏的逻辑决策点

排序和现有「时间分组」打架怎么办？
这是本功能最关键的结构决策。选「按优先级排」时，如果还保留时间分组，紧急任务会散落在「过期 / 今天 / 稍后」各组里，用户「一眼看最紧急」的目的就落空了。建议：每种排序方式自带分组策略——按截止时间排＝保持时间分组（现状）；按优先级排＝切换成「紧急 / 高 / 中 / 低」四个分组，组内再按截止时间排；按创建时间排＝平铺不分组；已完成页＝保持按周分组，只调周内顺序。
「紧急程度」到底指什么？
用户脑子里的「紧急」是混合概念（快到期 + 优先级高）。方案A：紧急程度＝优先级，组内再按截止时间细排——简单、可解释，用户能明白为什么这条在前。方案B：用算法把「时间×优先级」加权算一个紧急分——不可解释（用户看不懂为什么A在B前面），不建议 v1 做。建议 v1 用方案A，菜单里直接叫「优先级」，不发明新概念。
「升序/降序」的文案不能只写升降
「优先级升序」对普通用户是反直觉的（数值上低→高是升序，但用户预期「高的在前」）。所以方向切换要说人话：「早→晚 / 晚→早」「高→低 / 低→高」「最近在前 / 最早在前」「新→旧 / 旧→新」，界面上配方向箭头。每个维度要有符合直觉的默认方向：截止时间默认早→晚、优先级默认高→低、完成时间默认最近在前、创建时间默认新→旧。
没有截止日期的任务，切了降序会跑到最顶上吗？
不能。无日期任务无论什么方向都固定沉底（时间分组里也维持「未安排」组在最后的习惯）。这类「空值锚定」是最容易被漏掉的细节，切换方向时如果空值跟着翻转，列表会显得乱掉。
两条任务排序值一样时，谁在前？
必须定义次级排序，否则并列任务的顺序看起来随机。建议：按优先级排时，同优先级内按截止时间早→晚；按时间排时，同截止时间按创建时间新→旧。一级乱序有次级兜着，整个列表顺序才稳定。
「按完成时间排」出现在哪个页面？
进行中任务没有完成时间，这个选项只在「已完成」标签下出现（并作为该页默认排序）；反过来「优先级」「截止时间」在已完成页也可以用（比如「看这周完成的高优先级任务」是有价值的）。实现上：一个全局排序菜单，选项随当前标签动态增减。
用户选的排序要不要记住？
要。过滤器已有记忆机制（下次进来还在上次选的标签），排序用同一套：全局记一份，每个标签共用。已完成页特例：默认锁定「完成时间·最近在前」（即现状），用户主动改过才覆盖。
用户怎么知道列表当前是被排过序的？
排序状态必须可见、可发现：筛选条最右端放一个排序胶囊，非默认排序时胶囊高亮并显示当前排法（如「⇅ 优先级」），点击即可改或一键「恢复默认」。否则用户排过序、几天后忘了，会以为列表顺序「不对劲」却找不到原因。
切排序时列表要动效吗？
要，且成本低。任务列表现有框架按任务身份做差异更新，排序变化时套一层系统动画，卡片会平滑地各就各位（原型里的重排动画即示意）。没有动画的话，顺序突变会被感知成「内容换了」而不是「顺序变了」。

4界面方案

入口：筛选胶囊条最右端，与过滤胶囊同族样式、用虚线边框区分身份；生效中（非默认）变为浅橙高亮 + 显示当前排法。
菜单：底部弹出（实现时用系统菜单或底部弹层均可，原型以弹层展示）——排序方式单选四项、方向二段切换（文案随维度变化）、恢复默认。
即点即生效：选维度立即重排，弹层不关闭，方便继续调方向。

5明确不动的范围

以下页面各有自己的固定排序、语义不同，本次一律不动，避免范围蔓延：搜索结果页（按相关度）、今日看板（按仪式/优先级）、归档页（按更新时间）、任务卡片里的「最近已完成」折叠抽屉（保持「最近」语义）。首页小组件不受影响。

实现备注：纯客户端改动，数据字段（截止/完成/创建时间、优先级）全部现成，不需要后端发版。工程上唯一真正的排序落点在任务首页的组内排序函数处扩展，Core Data 侧已有按优先级/时间取数的现成工具可复用。

分期建议：P0 ＝ 截止时间 + 优先级 + 完成时间（含方向、分组策略、持久化）；P1 ＝ 创建时间、按标签筛选；P2 ＝ 智能紧急度算法（时间×优先级加权，需产品先想清楚可解释性）。
