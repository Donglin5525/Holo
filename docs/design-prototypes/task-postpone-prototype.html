任务延期 · 交互原型

「今天做不完的事，顺手推到之后」。延期是改截止时间的高频快捷操作——不是新建、不是编辑，是任务滑走之前的那次「再宽限一下」。 左边手机可完整点按体验：左滑卡片、点时间胶囊、延期后看撤回横幅与换组动画。
模拟时间基准：2026-08-25（周三）16:20。

1一句话方案

在任务列表左滑操作里新增「延期」主按钮，弹出底部选项面板；选项按任务的时间形态动态生成 （定时任务给分钟档＋跨天档，全天任务给天数档，过期任务第一档永远是「今天」）； 延期后卡片自动迁到目标日期分组，顶部出可撤回横幅，卡片上留下「已延期 N 次」痕迹。

2三个入口，按顺手程度分层

入口说明定位
左滑卡片 → 延期 现有左滑是「归档 / 删除」两键，新增橙色「延期」排在最前。归档、删除保持原位不动（高频老操作不降级）。 主入口

任务详情页 现有「日期与时间」弹层顶部插一排同样的延期快捷 chips，复用本面板的选项生成规则。 兜底入口

4延期后的世界

  • 卡片迁组：从「今天」滑到「明天 / 本周 / 稍后」分组，组头计数同步刷新；延期到「三天后」会看到「本周」组被自动展开。
  • 撤回横幅：「已延期到明天 17:00 · 撤回」，与现有「任务已完成 · 撤回」同一语言；点撤回完全还原（含延期计数）。
  • 延期痕迹：卡片 meta 行出现灰色「已延期 N 次」小胶囊（N≥1 才显示）。这是本设计最重要的一笔——允许拖延，但让拖延可见，连续延 3 次的任务自己都会不好意思。演示里「还信用卡账单」预置了 2 次的样子。
  • 提醒自动跟随：现有提醒是「截止前 N 分钟」的相对偏移，跟着截止时间走，延期免费带提醒，无需用户重设。绝对提醒（无截止日任务）不存在延期概念，不出现本面板。

5边界情况

场景处理
23:50 的任务延 30 分钟落点跨天，选项小字直接写「明天 00:20」，不藏在主词后面。
重复任务只改当期这一件，重复规则不动，下次照常按规则出。与习惯模块「补签 ≠ 补记」同一语义纪律：单次操作不改长期设定。
通知上的「稍后提醒」那是只重发一次通知、不改截止时间的贪睡，与本功能两回事。一期不动它，仅在文案上区隔（通知里叫「稍后提醒」，App 内叫「延期」）。见决策 D5。
过期积压成串过期组头提供「全部 → 今天」批量入口，一次清债。见决策 D6。
延期次数上限不设硬上限，靠「已延期 N 次」胶囊自省。设上限会把用户推向「删了重建」，反而丢历史。

6实现要点（开发侧）

  • 数据：TodoTask 新增 postponedCount(Int16) 一个字段即可承载痕迹；lastPostponedAt 可选，为将来 AI 信号留料。纯客户端，CloudKit 字段随 App 发版，无需后端。
  • 延期动作 = 改 dueDate（跨天保时刻复用现有 selectDatePreservingTime 同一规则）+ 计数 +1 + 重排该任务的提醒通知。
  • 选项生成收敛成一个纯函数（任务形态 → 选项列表），三入口共用，永不出现两个入口选项不一致。
  • AI 呼应：任务信号提炼层已有关注「积压与延期类型」的设计，postponedCount 让「这事被拖了三次」第一次成为可感知的事实。

7待东林拍板

D1 · 入口组合推荐照此实施

左滑主入口 + 胶囊加速入口 + 详情页兜底，三层是否 OK？归档 / 删除维持原位不降级。

D2 · 全天任务的「本周末」档

全天任务面板要不要保留「本周末」？现有日期弹层的快捷选择里有「本周末 / 下周」先例，延期内也可用；嫌四个天数档太密可以砍。

D3 · 「已延期 N 次」胶囊

这是本设计的灵魂，但也有「给用户压力」的另一面。保留 / 换成只在延期第 2 次起显示 / 不做，三个态度。

D4 · 重复任务只改当期

默认只改当期、规则不动。另一种做法是「此次延期 + 之后也顺延」，更重，不建议一期做。

D5 · 通知「稍后提醒」是否升级

现状：通知按钮 15 分钟后重发一次通知，不改期。可升级为「延期 15 分钟」（真改期）；一期建议先不动，靠文案区隔。
