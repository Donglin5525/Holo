工程量分级（全部纯 iOS，无后端发版）：A / B / E / F 常规，半天级——E、F 只是把现有右上角分段换成小控件＋标题改绝对居中，是改动最小的路线；D 横滑 = 分段换 TabView 分页常驻，约一天；C 缩放轴最大——日/周/月之间做连续捏合缩放并把洞察接成第四档，周历双指缩放已有底子但仍是一个小专项（数天级）。
E / F 的取舍：E 图标开关两个状态都直接可见、可逐个点选；F 拨动开关更「开关」、动画更像 iOS 系统控件，但只显示当前态，另一个视图藏在一拨之后（发现性略弱）。两者宽度都只有 50–64pt，标题行两侧基本等宽（左返回 44pt），是「不动布局结构就解决挤标题」的最轻解。
取舍提醒：C 概念最正（洞察=拉远的俯瞰），但档位多、发现性靠标尺兜底；D 最省控件但滑动与页面内上下滚动需实测手感；3C 零信息量全氛围；3D 信息量最高，进度条每分钟走一格，「还在继续」不言自明。
· 章节头、事件卡、洞察内容均为示意，仅还原布局与配色（取自 App 深色模式真实色值）。
· 无论选哪组，标题的绝对居中与「两视图常驻不销毁」的性能底座不变。
