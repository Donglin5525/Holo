## 1. 背景与目标

Holo 目前与 iOS 系统日历完全无交集（工程内无 EventKit 引用、无日历权限声明，已验证）。用户的真实时间由两部分组成：Holo 里的任务/打卡/记账，和系统日历里的会议/约会。两边割裂导致：

- Holo 不知道你几点有会——让 AI「安排明天写报告」可能建议到与会议冲突的时段
- 记忆长廊回放不了「那天下午都在开会」
- Apple 手表 / iPad 上看不到 Holo 的时间安排

目标：让 Holo 成为「AI 时间管家」——**读得到日程、排得开时间、写得出日历、回放得了历史**。

## 2. 已确认的产品决策（2026-08-30 东林拍板）

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 融合深度 | 双向同步（读 + 写） |
| D2 | 写入范围 | 仅**带时间段**（计划开始/结束）的任务自动同步；未安排时间的待办不进日历 |
| D3 | 读取范围 | 用户按日历勾选哪些进 Holo（日历级多选开关，选择权交给用户） |
| D4 | 外部日程身份 | **只读背景块 + 可勾完成**；勾完成状态仅存 Holo，系统日历不受影响。永久不可在 Holo 内编辑外部日程的标题/时间/备注 |
| D5 | AI 感知 | 全量：对话能查能排 + 周规划自动避让 + 记忆回放与深度分析 |
| D6 | 交付节奏 | 三期：看得见 → 写回去 → 会复盘 |

**一个必须分清的概念**（避免看似矛盾）：

- **外部日程** = 从用户勾选的非 Holo 日历读进来的日程（公司会议、私人约会等）→ 适用 D4：只读 + 勾完成，不可编辑。
- **任务镜像事件** = Holo 写到专属「Holo」日历里的任务事件 → 它是任务的镜像，在系统日历 App 里改它 = 改任务，二期会同步回流。这不违反 D4。

## 3. 与原时间块方案的关系（合并声明）

原时间块三决策（2026-08-14 定稿）全部继承，映射如下：

1. **字段**：任务新增「计划开始 + 计划结束」一对可选字段，不动 `dueDate`（截止日期语义贯穿提醒/重复/取数，不动）；禁止只填一个、禁止跨天 → 并入本方案**一期 ①**
2. **反写视图**：记忆长廊新增「时间轴」子 Tab（纵向 0–24 点刻度），与现有 日历/洞察/明细 并列，不改造现有明细视图 → 并入本方案**三期**
3. **一期不区分计划 vs 实际**，统一显示计划时间段 → 继续有效；计划 vs 实际对比在**三期**实现

原方案的分期（二期=时间轴+拖拽、三期=计划vs实际）已并入本方案三期，原方案不再单独存在。

## 4. 总体架构（四层）

1. **权限与来源层**：申请日历「完全访问」权限（iOS 只有「完全访问 / 仅添加」两档，无纯只读档；一期只读也须申请完全访问，一次到位，后续写入不再二次弹窗）。设置页管理：读取日历多选（默认勾选用户在系统日历中可见的非订阅日历，可改）+ 写入目标日历（默认自动新建专属「Holo」日历，可换，但不允许选非 Holo 新建的日历，避免污染工作/个人日历）。**勾选处文案明示：勾选后 AI 也可在对话/规划中读取此日历**（不另设「仅展示不给 AI」开关，避免设置复杂化）。
2. **同步服务层**（纯客户端，不依赖后端）：读取分**双窗口**——「活跃窗口」（前后数月，常驻缓存，供今日视图与 AI）+「回放按需拉取」（长廊翻到任意历史日时当场查询，不常驻）；监听 EventKit 变更通知（防抖后重拉对账）。写入 = 任务 ↔ 事件映射与跟随（二期），**多设备一致性是同步引擎的第一设计约束**（见第 6 节）。日程完成态存本地 CoreData 实体。
3. **展示层**：今日视图日程背景块（与 Holo 任务视觉区分：任务是可操作卡片，日程是带日历颜色的底色块）；**展示落点三处口径一致**：今日看板（DailyKanban）、首页今日区、任务页今日视图。三期记忆长廊时间轴同轴展示。
4. **AI 层**：Agent 新增日程工具（查询、排时避让）+ 周规划感知 + 深度分析时间洞察。**这是唯一涉及后端发版的部分**。工具在权限被拒/无数据时返回「无日程数据」空态语义，对话自然降级不报错。

**命名约束**：现有 `CalendarEvent` / `CalendarViewModel` / `CalendarEventProvider` 均为记忆回放日历的既有命名，与系统日历无关。新功能一律使用独立命名（`Schedule` / `CalendarSync` 系列），避免混淆。

## 5. 一期「看得见」

### ① 任务时间段地基（原时间块一期并入）

- `TodoTask` 新增「计划开始 / 计划结束」一对可选字段（CoreData 模型迁移）；不动 `dueDate`
- 约束：两字段要么都填要么都空；不允许跨天
- 新建/编辑任务可设置时间段；带时间段的任务在今日视图按时间排布
- **发版前置**：新字段须先部署 CloudKit schema（见第 9 节）

### ② 系统日历只读接入

- 设置页新增「日历」入口：总开关 + 日历来源多选清单
- 首次开启弹系统权限（完全访问，见架构层 1）
- 进 Holo 的日程显示在**今日看板、首页今日区、任务页今日视图**（三处一致），以带日历颜色的背景块呈现，与 Holo 任务视觉区分
- **全天日程折叠**：假期、生日等全天日程不占时间轴，折叠为顶部一条轻提示（如「今天：国庆假期」），可展开查看

### ③ 日程可看、可勾

- 点日程块看详情（标题、时间、地点、所属日历），提供「去系统日历打开」跳转
- 可勾完成：带撤回窗口（与任务交互一致）；完成态**仅存 Holo 本地**
- **勾完成按单场实例记录**（键 = 日历标识 + 事件标识 + 该场发生日期）：重复日程（如每周例会）勾掉一场只影响这一场，系列后续场次不受污染
- **存储载体**：独立 CoreData 本地实体（不走 CloudKit；需按天聚合、三期供长廊回放，不适合塞系统偏好）
- 编辑日程 = 跳系统日历 App，Holo 下次刷新自动跟上

### ④ AI 感知

- 对话：「明天下午有什么安排？」→ AI 合并日程 + 带时间段任务回答，并指出空闲时段
- 排时间：「帮我安排明天写报告」→ 自动避开已有日程再建议时段
- 周规划：Life Agent 排周计划时感知日程密度，任务往空闲日放
- **后端发版项**：Agent 日程工具注册 + 周规划 prompt 更新

### 一期明确不做

- 不向系统日历写任何数据（二期）
- 不在 Holo 编辑外部日程（永久边界）
- 记忆长廊时间轴、拖拽反写（三期）
- 重复日程按单次实例处理，不做系列编辑（永久边界）

## 6. 二期「写回去」

**同步引擎第一设计约束：多设备一致性。** Holo 任务经 CloudKit 多端同步，iPhone/iPad 各自写入会制造同一任务的重复镜像事件。防护三件套：

1. **映射随任务走**：任务 ↔ 事件的映射记录作为任务派生数据存 CoreData 并经 CloudKit 同步；写入前先查映射，已映射则更新、未映射才创建
2. **事件内埋任务 ID**：每条镜像事件在保留字段（备注或链接）埋入 Holo 任务标识，作为对账时的**最终认领依据**
3. **认领不靠事件 ID**：iCloud 事件的 `eventIdentifier` 在编辑/服务器重排后可能漂移——ID 只作加速索引；失联事件通过扫描「Holo」日历内事件的任务 ID 重新认领，漂移只触发一次重扫，不产生重复

### 写入与跟随规则

- **写入目标**：首次开启写入时在系统日历自动新建专属「Holo」日历；带时间段的任务自动写成事件
- **跟随规则**：
  - 任务时间段/标题变了 → 日历事件跟着变
  - 任务删除 → 日历事件删除
  - 任务完成 → **事件保留**（日历作为历史记录，与系统日历产品逻辑一致）
- **双向回流**：在系统日历 App 改了「Holo」日历中事件的时间/标题 → 同步回 Holo 对应任务；在系统日历删除 → Holo 任务保留、断开同步、轻提示一次
- **冲突规则**：两边几乎同时改 → 以**后改的一边为准**（按修改时间戳；两端时钟偏差容忍，轻提示兜底），Holo 内轻提示发生了覆盖。不做合并（业界通行简化，诚实提示优于假装合并）
- **AI 排时确认闸**：AI 在对话中建议的时间段，须经用户明确采纳（如点击「采纳」）才落地为任务计划时间段——从而才会按规则进入系统日历。**AI 不得未经确认把时间写到日历这种对外可见的 surface**（手表/家人共享日历）
- **目标日历被删/改名**：检测「Holo」日历消失 → 自动重建一本，对账兜底，不打断用户
- **日程转任务**：点外部日程 → 「添加跟进任务」（如「会后写纪要」），生成真正 Holo 任务并可关联该日程；原日程日后被删，任务自包含不受影响（关联失效容忍）

## 7. 三期「会复盘」

- **记忆长廊时间轴**：纵向 0–24 点刻度子 Tab，带时间段任务 + 系统日程 + 打卡/记账时间锚点同轴摆开，回看某天「时间都去哪了」（原时间块二期升级版）。历史日程使用**回放按需拉取**（见架构层 2），回放任意历史日不受活跃窗口限制
- **拖拽反写**：时间轴空白处拖一块直接生成带时间段的任务（15 分钟吸附）；拖现有块边缘 = 调整时间（任务 ↔ 长廊双向打通，差异化核心）
- **计划 vs 实际**：完成任务可选确认实际用时，与计划对比；积累后可见「计划 1 小时实际 2.5 小时」（原时间块三期）
- **深度分析时间洞察**：会议密度 vs 任务完成率、空闲时段分布等进深度分析报告（后端发版项）

## 8. 技术要点与风险

| 项 | 处理 |
|----|------|
| 查询窗口 | 双窗口：活跃窗口（前后数月常驻）+ 回放按需拉取；变更通知**防抖**后窗口内重拉（系统通知是无差别广播，不指明哪条变了） |
| 权限路径 | 覆盖三种状态：未请求（首次弹窗）、**首次拒绝**（iOS 不再弹，设置页检测后引导跳系统设置）、授权后被收回（日程展示自动隐退不报错，引导重开） |
| 日历库初始化 | EKEventStore 首次访问可达数百毫秒~秒级，**异步初始化**，不进启动链路 |
| 重复日程 | 永久按单次实例读取展示，不做系列编辑；勾完成按单场实例记录（见 5.③） |
| 上架合规 | 日历权限用途文案（App Store 审核硬检查项）+ 隐私清单新增日历数据访问声明；并入下次上架体检 |
| 隐私边界 | 仅当次对话/规划需要时发送相关时段的日程摘要给后端推理，不整本日历常驻上传；日历勾选处明示 AI 可读（见架构层 1） |
| Agent 降级 | 权限被拒/无数据 → 日程工具返回空态语义，对话不报错不中断 |
| 命名避坑 | 新功能独立命名，不碰记忆回放日历的既有 Calendar* 命名 |

## 10. 测试策略

- **单元测试**：同步引擎（改/删/冲突/断链对账/**多设备双写幂等**）、时间段字段约束（只填一个、跨天拒绝）、**重复日程勾完成只影响单场**、完成态按天聚合
- **模拟器验证**：权限弹窗流程（含首次拒绝）、今日视图展示、勾完成交互；用模拟器**本地日历**造数（iCloud 日历同步在模拟器不可靠）
- **真机终验**：照惯例交东林

## 11. 永久边界（明确永不做）

1. 在 Holo 内编辑外部日程的标题/时间/备注（要改去系统日历 App）
2. 重复日程的系列编辑（按单次实例）
3. 未安排时间的待办写入日历
4. 全量日历数据常驻上传后端
5. AI 未经用户确认将时间写入系统日历

## 12. 实施说明与注意事项

### 实施说明

- 实施计划按期分别编写（writing-plans），**先做一期**
- 一期动工前置：本文档获东林最终确认

### 实施注意事项（对抗审查 P2 存档）

- 跨时区旅行当天，「今天」与日程时间跟随设备时区显示，不做双时区
- 全天日程的系统存储无时区属性，按当天本地日期处理（EventKit 特殊行为）
- 两端设备时钟偏差可能翻转「后改为准」判定——容忍，轻提示兜底
- 日程转任务后原日程被删 → 关联失效容忍，任务自包含
- **一期实施首日需验证的 API 事实**：① 事件外部标识（`calendarItemExternalIdentifier` 等）的读取路径与稳定性；② iOS 26 EventKit 是否提供新能力（如事件原生完成态——若有则替代 Holo 本地完成态）；③ 任务 ID 埋入事件哪个保留字段（notes/url）最稳、是否会被系统剥离
