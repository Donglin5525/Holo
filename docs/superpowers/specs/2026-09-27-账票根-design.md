## 1. 产品叙事

Holo 是「人生数据库」：账本是数字，照片是瞬间。一笔账不只是一个 ¥128 的数字，而是那顿饭、那张机票、那双鞋。给每笔账贴**票根**——照片不是表单附件，而是「从账本出票口吐出来的小票」：凭证感 + 记忆感，账本从流水表变成有画面的人生记录。

设计原则：
- **轻量入口，无表单附件区**：不做备注附件、不做表单字段；无照片时仅保留出票槽与一枚轻量入口，贴上后才有实体存在感
- **贴纸语言**：照片以微倾斜、底部锯齿撕边的票根形态存在，错落叠贴，最新在上
- **物理隐喻**：出票槽 → 吐出 → 贴在账上 → 长按撕掉
- **词汇统一**：全链路只用「票根」一词（入口按钮「📷 添加票根」），不与「凭证/附件/图片」混用（「识图凭证自动归档」作为设置项名称保留，因需说明照片来源）

> 2026-09-27 对抗性自查修订（4 处交互修正，详见文末「自查记录」）：长按改弹菜单、识图确认页加知情提示、设置补清理入口、词汇统一。

## 2. 交互规格

### 2.1 记一笔页（AddTransactionSheet）

**出票槽**：信息卡正上方一条视觉槽（宽 ~210pt 深色横条，内高光缝），仅在「可贴/已贴」语境中出现——空态时槽 + 下方虚线胶囊「📷 添加凭证」一起显示（轻量、低调），这是唯一的可见入口。

**吐出动画**：添加照片（拍照或相册选图）后，票根从槽后向下缓缓吐出（容器 max-height 展开 + 票根自上而下位移，spring 曲线），落定轻微回弹。

**票根形态**：
- 白色相纸底 + 顶部照片区（4:3）+ 底部小票头 + **底部锯齿撕边**
- 小票头内容 = **来源 + 时间**小字（如「相册 · 今天 12:24」「识图凭证」），不重复交易名称/金额（交易自身已有，原型画板中的名称+金额仅为演示数据）
- 微倾斜：1 张 rotate(-3°)；2 张 (-4°/+4°) 错落；3 张扇形错落（-8°/+2°/-3°），最新 zIndex 最高，下层露出边角可点
- 轻点 → 全屏查看（黑底、横滑切换、双指缩放；内含「撕掉」入口）
- **长按 → contextMenu（撕掉 / 查看大图）**：撕掉必须经过菜单确认，防误操作（iOS 用户长按心智=弹菜单；且 SwiftUI `onLongPressGesture` 挂 ScrollView 内容在 iOS 26 有压死滚动的已记录坑，contextMenu 为系统组件天然规避）——技术实现禁止用长按序列手势直撕
- 满 3 张：入口按钮变「已贴 3 张 · 长按票根可撕掉」禁用态

**选图来源**：添加凭证 → action sheet「拍照 / 从相册选择」。复用 PhotoLibraryImageLoader（含 loadTransferable 失败回退转码）与 CameraView 权限链路。

**编辑态**：编辑已有交易时票根照常展示，可撕可加，与新建同构。

### 2.2 交易详情页（FinanceTransactionDetailPane）

属性区上方「票根」区块：放大版贴纸语言（单张 / 多张扇形）。识图来源的票根带「⚡️ 票根来自识图凭证」小角标。轻点进全屏查看。

### 2.3 识图凭证自动归档（ReceiptBooking）

现状：识图凭证照片（evidence/<draftID>.jpg）在确认落账后即删除。改法：
- 确认落账时，若设置开关开 → evidence 图走压缩管线转存为该笔交易的票根（sourceType = receiptBooking），一图拆多笔时**每笔都挂**
- **知情提示**：识图确认页确认按钮下方一行小字「确认后，凭证照片将自动归档为票根」（开关开时显示；默认开的状态下用户必须能预期到照片会被保存）
- 开关关 → 维持现状（确认即删），提示不显示
- 放弃确认 → 照旧删除，不受开关影响

### 2.4 设置

设置 → 记账：「识图凭证自动归档」开关，**默认开**，副文案说明压缩与占用（原图上限 2048px、约 200–500KB/张；缩略图 300px），随 iCloud 同步。**关闭开关只影响未来，不追溯删除已归档票根**（文案需说明）。

配套存储出口（一期纳入）：
- 「设置 → 存储」新增票根行：显示票根总占用（按 imageData+thumbnailData 汇总）
- 「清理识图票根」按钮：一键删除全部 sourceType = receiptBooking 的附件（交易本身不动）——默认开的存储顾虑必须有释放出口

## 3. 技术设计

### 3.1 数据模型（代码定义实体）

新实体 `TransactionAttachment`（对齐 ThoughtAttachment 已验证模式，不碰想法模块在途文件）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID, required | |
| fileName / thumbnailFileName | String? | 沙盒 `Documents/TransactionAttachments/<transactionId>/<attachmentId>.jpeg`（及 `_thumb.jpeg`） |
| imageData / thumbnailData | Binary | 原图 2048px/0.8 + 缩略图 300px JPEG 双存（iCloud 同步载体） |
| sourceType | String? | photoLibrary / camera / receiptBooking（为 AI 看照片预留） |
| createdAt | Date | |
| sortOrder | Int16 | |

关系：`Transaction.attachments` to-many ↔ `TransactionAttachment.transaction` to-one，**cascade 删除**。软删除走宿主 deletedAt，附件随行、恢复即回。

定义位置：`CoreDataStack+FinanceEntities.swift` + 新文件 `TransactionAttachment+CoreDataClass.swift`。轻量迁移自动兼容（新增实体/关系，optional 关系）。

### 3.2 存储层

- 新建 `TransactionAttachmentFileManager`（同构 AttachmentFileManager，不动想法模块）：写/读/删档，后台线程降采样（复用 ImageDownsampler 同参数）
- CloudKit：二进制走 CoreData 变长字段自动映射 `_ckAsset`，**不开** allowsExternalBinaryDataStorage（全 App 仅头像开，维持一致）

### 3.3 保存链路

- `FinanceRepository`：新增 attachPhotos / detachPhoto；`TransactionUpdates` 扩展附件变更
- `TransactionSaveHandler`：保存时落附件
- `ReceiptBookingResultStore`：确认落账分支按开关转存 evidence 图为附件

### 3.4 UI 组件

- `TransactionReceiptStack`：票根堆叠（1–3 张布局、吐出/撕掉转场、轻点全屏）
- `ReceiptSlotView`：出票槽视觉
- 全屏查看器：新建轻量 `ReceiptGalleryView`（黑底/横滑/缩放），不耦合 Thought 数据源

### 3.5 动画技术路径

吐出 = 票根区**固定高度容器** + `.transition(.move(edge: .top).combined(with: .opacity))` + clipped + spring——不用 `maxHeight`/`frame(height:)` 动画（ScrollView 内高度动画会挤压相邻视图产生弹跳，速查表「顶部插入滚动跳动」坑的缓解措施）；撕掉 = 自定义 removal transition（旋转+位移+透明）。票根若用 Button 承载，`contentShape` 必须放 **label 内部**（2026-09-17 想法卡片坑：挂外面整体点不中）。SwiftUI 原生实现，无 UIKit 依赖；撕掉走 contextMenu（禁用长按序列手势，iOS 26 压滚动坑）。

### 3.6 已知坑对照（自查命中的记录）

| 坑 | 出处 | 本设计的规避 |
|---|---|---|
| iOS 26 长按+拖序列手势挂 ScrollView 压死滚动 | 踩坑记忆 2026-09 | 撕掉用 contextMenu，不用 onLongPressGesture |
| Button contentShape 挂 label 外=点不中 | 速查表 2026-09-17 | 票根 Button 的 shape 进 label 内 |
| 顶部插入内容滚动位置跳走 | 速查表 2026-08-22 | 小体积+用户焦点在场，固定高度+move transition |
| CoreData 跨上下文/跨线程传对象 | 速查表 | 后台写档传 UUID 不传 NSManagedObject |
| 代码定义模型须 @NSManaged 扩展模式 | 修复笔记 2026-07 | 对齐 ThoughtAttachment 现行模式 |

## 4. 范围

**一期（本设计）**：模型、存储、记一笔贴票根（形态B）、详情票根、识图自动归档（默认开+确认页知情提示）、设置开关、存储占用显示与识图票根清理、翻译（简中先行）。

## 8. 自查记录（2026-09-27 对抗性审查，东林指令）

**已命中已知坑（self-check skill 结论，用记录的方案）**：
1. iOS 26 长按序列手势挂 ScrollView 压死滚动 → 撕掉交互改 contextMenu
2. Button contentShape 位置坑（想法卡片事故） → 实现约束写死「shape 进 label 内」

**对抗性审查修正的交互问题（用户视角）**：
1. 长按直接撕掉无确认 = 误操作陷阱（iOS 长按心智是弹菜单）→ 改 contextMenu「撕掉/查看」
2. 识图默认开但确认页无告知，用户不知照片被保存 → 确认页加知情小字
3. 画板④向用户承诺「一键清理」但原范围没做 → 清理+占用显示纳入一期
4. 「凭证/票根」词汇混用 → 全链路统一「票根」；小票头真机显示「来源+时间」而非演示数据的名/额（避免验收落差）

**原型同步修复的 bug**：长按菜单弹形态切换不关闭；B 形态撕完最后一张空槽闪现。
**风险确认无问题**：一图多笔每笔挂图（压缩后成本可控）；ScrollView 顶部插入跳动（小体积+焦点在场+固定高度 transition 缓解）；CloudKit 二进制同步路径（ThoughtAttachment 同模式生产已验证）。
