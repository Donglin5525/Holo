## 1. 产品背景

**Holo 是什么**：一款 iOS 个人生活管理 App，定位是「记录你的全部生活，并由此理解你」。模块包括：

- 财务：多账户记账、预算、信用卡账单周期、外部账单导入、趋势分析
- 习惯打卡、任务/清单/子任务、目标系统（含 AI 会话式规划）、纪念日（含仪式感设计）
- 想法/笔记：富文本、标签、AI 自动整理（主题归类/打标签）、分享卡
- 记忆长廊：按时间轴浏览全部人生记录（含照片）、日/周/月 AI 回放
- 今日看板、桌面小组件、锁屏配件、语音输入（ASR）、三语（简/繁/英）

**商业化**：免费 + Plus 订阅（定价待定），AI 额度按场景分池是核心订阅权益。

**阶段与团队（重要约束）**：产品刚上架 App Store（v1.0.x），种子用户期，用户量很小。团队 = 产品经理背景的一人开发者 + AI 结对开发，没有其他工程资源。所有方案必须按「一个人能实施」来设计。

**产品气质**：陪伴感与仪式感优先于效率工具感；数据主权归用户（数据在端上 + 用户自己的 iCloud，云端拿不到原始数据）；信任叙事是三级——「它认识我 → 我能看到它认识我什么 → 它记得我们一起做过什么」。

## 2. 现状速览（我方自述底稿，请以你的代码复核为准）

### 2.1 端云分工
- 用户全部数据在 iOS 端（本地数据库 + iCloud 私有云同步）；所有工具执行、记忆读写、证据校验都在本地完成
- LLM 推理全部经自建网关（Node.js，`HoloBackend/`）代理到 DeepSeek：轻任务用 deepseek-v4-flash，Agent 循环用 deepseek-v4-pro；embedding 用 Qwen，语音转写用 Qwen-ASR
- Prompt 后端托管可热更新；服务端有设备级配额、设备风控、功能急停开关
- 已有云端异步深度分析：加密快照上传云端执行重分析，失败回落本地，结果 7 天内领取

### 2.2 对话主链（轻路径）
- 用户消息 → LLM 意图识别 + 槽位抽取（**约 26 个枚举意图**：记账/预算/任务增删改查/习惯打卡/目标字段/纪念日/清单/查询等；端上编排与执行，模型经网关调用）→ 端上结构化执行直接写库
- 支持一条消息解析为多个动作顺序执行；低置信度走澄清追问
- 意图识别时注入轻量用户上下文摘要（交易/习惯/任务/想法/目标/记忆摘要）

### 2.3 深度 Agent（重路径）
- 触发：深度分析类问题（**8 个场景胶囊**：跨域洞察/财务/习惯/睡眠健康/任务/想法/目标/长期模式）+ 复杂查询 + 周规划
- 本地多轮 Agent 运行时（actor 模型）：
  - 前置确定性步骤：域识别、歧义检测、数据敏感度分级、预算档位选择、时间范围解析（规则优先，模型兜底）
  - **自定义 JSON 结构化协议（非原生 function calling）**：模型输出 need_tools / need_more_analysis / final_claims 三态
  - **17 个本地只读工具**（财务/习惯/健康/任务/目标/想法/记忆/洞察/用户画像/纪念日等），支持声明式查询计划
  - 收口时逐条结论做本地证据验证，不合格可注入纠错重试
  - 工程能力：checkpoint 断点续跑（锁屏/杀 App 后恢复）、step 级幂等、旧结果写回防护、iOS 后台处理
- **关键架构边界：Agent 只能「读+说」，不能「写」**。一切写操作走 2.2 的结构化意图，两者互斥。

### 2.4 记忆系统（四层）
1. 原始记录（任务/习惯/财务/健康/想法/聊天原文）
2. 理解层：长期记忆（LLM 萃取，8 个领域、8 种命题类型、状态机含「墓碑」防删除后换说法重生）＋ 用户画像快照 ＋ 主题知识树 ＋ 域观察流水线
3. 工作产物：洞察卡（持久化、用户可反馈）＋ Agent 证据台账（30 天回收）
4. LifePlan 状态机（周规划的显式对账台账，语义是「我们一起做过什么」，区别于长期记忆的「你是什么样的人」）

配套机制：脏数据检查（数据没变不调 LLM）、敏感数据分库（健康类只存本机）、检索注入（2000 token 预算、默认 8 条、本地检索零网络）。记忆注入已全量开放。

### 2.5 洞察与主动性
- 首页洞察胶囊（本周观察/上周洞察投递）、日/周/月回放（云端轨道 + 本地回落）、跨期累计摘要
- 推送中心（分级管理、深链跳转）；主动交互总体是「定时批处理」型，非实时情境驱动

### 2.6 成本与额度（经营数据，不在代码内，直接采信）
- 单活跃用户日均 AI 推理成本约 ¥0.6–0.8（治理前基线），已完成第一批治理（思考档位矫正、缓存友好化、全链路 token 计量）
- 高频轻任务（想法自动整理）实测约 ¥0.008/条
- AI 额度五池分池计费，免费/Plus 双档

## 3. 我们已经知道的事（帮你避免误判）

### 3.1 已完成、不要当缺口的
记忆萃取/遗忘/去重闭环并全量开放；深度分析云端化；三类回放；周规划状态机；AI 时间语义治理；数据读取缺口审计后第一批 7 项修复；对话体验体检两轮共 25 项修复；额度终态协议与恢复链；锁屏后台续跑可靠性。

### 3.2 我们自评的短板（请你在代码中验证，可直接推翻）
1. **意图路由范式**：26 个枚举意图 + 槽位抽取是「分类器」思路，长尾诉求落到兜底闲聊；每加一个能力要人工注册意图。它与「Agent 泛化理解用户」之间存在范式张力——要不要向「工具调用型通用 Agent」收敛？
2. **Agent 不能动手**：深度 Agent 只读，写操作走结构化意图。跨「分析→行动」的多步任务（例：「帮我把这个月的账理一理，然后调整预算」）被架构切断。
3. **自定义 JSON 协议 vs 原生 function calling**：协议遵循度靠校验器兜底，维护成本高；DeepSeek 对自定义协议的遵循有波动。
4. **主动性弱且粗**：定时批处理型洞察，不是「懂用户当下情境」的主动陪伴；防打扰与价值密度未验证。
5. **记忆「资产厚、出口薄」**：四层记忆在后台运转，但用户几乎没有「它认识我」的感知界面（引用署名/出处/成长可视化缺位）。
6. **多模态缺失**：照片完全不可理解（想法配图、小票、截图账单都进不了 AI 链路）。
7. **数据注入策略未验证**：轻路径注入摘要、重路径靠工具按需拉取——这个平衡是否最优没有数据支撑。

### 3.3 已尝试且效果不好的方向（不要建议原样重做）
基于向量召回的主动内容推荐做过两版，效果不佳已下线，第三版方案未落地。评估「主动性」时请把这个历史纳入。

## 4. 硬约束（方案必须满足）

1. **一人工程带宽**：必须分期，每期 1–3 周内独立产生用户价值；警惕需要多系统长期联动才能见效的方案
2. **成本**：以 DeepSeek 系为主力；如建议引入更强模型，必须给成本测算与分级调用策略（什么任务配什么模型）
3. **隐私底线**：原始数据在端上与用户 iCloud；任何新数据上云需过内部隐私评估（有先例：想法整理上云前做了专项拍板）。方案要标明哪些环节碰了数据边界
4. **架构延续性**：端上优先、网关代理、prompt 热更、额度分池这些骨架不宜推翻；可以演进，不建议重写
5. **用户量小**：不要建议依赖大规模基础设施或海量数据训练的方案

## 6. 交付物格式

一份中文 Markdown 文档，8000–15000 字，结构如下：

1. **执行摘要**（≤500 字，直接给唯一答案）
2. **现状诊断**：Holo Agent 成熟度评估（可用业界框架），真实差距在哪
3. **核心判断与论证**：最该补的能力是什么，为什么是它而不是其他候选（对主要落选项逐一说明为什么不优先）
4. **改版方案详述**：目标架构、关键机制、交互形态、数据流；标注哪些复用现有设施、哪些新建
5. **分期路线图**：P0/P1/P2，每期含范围、工程量级（按「一人 + AI 结对」折算人日）、独立价值说明
6. **度量体系**：北极星指标 + 护栏指标 + 验证方法
7. **风险清单与规避**
8. **成本影响测算**（逐期）
9. **待拍板决策点**：需要产品负责人拍板的清单，每条附你的推荐选项
10. **附录：任务书自述与代码事实不符之处**（无则写「无」）

要求：判断必须有论证；拒绝「都重要」式并列；关键事实判断标注代码/文档依据（文件路径）；引用业界案例时说明与 Holo 的可比性；对不确定的事实明确标注为假设。
