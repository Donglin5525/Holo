财务 · 账户卡片视觉方案

现状问题：所有账户都是同款白底小卡平铺，只有「图标 + 名称 + 类型 + 余额」四样信息，视觉上没有层次，信用卡的额度、账单日、还款日等关键信息在列表层完全不可见，净资产卡与账户卡也不分主次。

以下三个方案参考了 Apple Wallet / Apple Card 的卡片准则（卡片即身份、金额用大号圆角数字、信息按重要性分层）与主流财务软件（Money Pro / MoneyWiz 的彩色账户卡、银行 App 的渐变卡面、Revolut 的余额主视觉）。三稿均使用 Holo 现有设计语言：米白背景 #FDFCF8、品牌橙 #F46D38、16-20pt 卡片圆角、深色暖调渐变卡。账户示例数据统一，方便横向对比。

账户基本信息清单名称 · 类型 · 图标 · 账户色 · 余额 · 默认标记 · 归档标记；信用卡另有：总额度 · 已用额度 · 账单日 · 还款日 · 本期账单
信用卡专属信息额度 ¥30,000 · 已用 ¥8,420.50 · 账单日 5 日 · 还款日 25 日（浦发信用卡示例）
对应工程字段Account: name / type / icon / color / initialBalance+流水 → 余额 / isDefault / isArchived / creditLimit / billingDay / dueDay
方案 A

卡面沉浸式 · Wallet 大卡

每个账户一张全宽彩色渐变大卡，卡片本身就是账户的「身份证」。余额是卡面主角，底部按账户类型定制信息区：信用卡显示额度水位与账单节奏，普通账户显示本月收支。参考：Apple Wallet Pass 分层 + 银行 App 卡面渐变。

设计要点

  • 卡面颜色由账户自身颜色驱动（现金=绿、钱包=蓝/青、储蓄=靛、信用卡=琥珀，均为现有默认色加深成的渐变），深色卡面在浅色/深色模式下都稳定，暗色模式零适配成本。
  • 信息分三层：顶部身份区（图标+名称+类型）→ 中部主数字（余额）→ 底部服务区（收支/额度）。完全对齐 Apple Wallet「卡片即身份，数字是主角」的层级。
  • 信用卡卡面把「额度水位条 + 可用额度 + 账单日/还款日」一次给全，账户列表层就能看懂负债健康度，不用进详情。
  • 净资产卡用 App 已有的 Plus 暖调深色卡语言，与彩色账户卡形成「深色锚点 + 彩色成员」的主次关系。
  • 金额统一大号圆角数字（SF Rounded · tabular-nums），负数/欠款在卡面上仍为白字，靠「已用额度（欠款）」标签消歧，避免卡面出现红字破坏统一感。

✓ 优势

  • 视觉冲击力最强，账户辨识度靠颜色即可建立
  • 信息承载最全（信用卡五行信息全在卡面）
  • 深浅色模式同一张卡，不用维护两套配色

✗ 取舍

  • 账户多时页面较长（一屏约 2.5 张卡）
  • 彩色面积大，风格强烈，需接受页面变「重」
  • 「已归档」账户建议折叠到页尾一个灰卡组
方案 B

钱包卡阵 · 银行卡比例小卡

账户做成标准银行卡比例（1.586:1）的小卡，两列排布，像一张张实体卡收在钱包里。最紧凑、最「像钱包」；信用卡账单节奏等细节让位给点击后的展开态（附 Wallet 式堆叠交互演示，可点击体验）。

设计要点

  • 标准银行卡比例 1.586:1 + 16pt 圆角，视觉上直接唤起「实体卡」心智；两列网格让 5 个账户只占一屏 2/3，账户多也不怕。
  • 卡内信息极简三行：名称 → 余额（主视觉，右下大数字，参考实体卡排版）→ 一行状态小字；额度水位用 3.5pt 细进度条暗示，不做完整说明。
  • 网格尾部常驻「添加账户」虚线卡，把右上角 + 的能力在网格内再给一次入口。
  • 账单日/还款日/本期账单放不下，收进点击后的账户详情（或长按快捷 glance）；这是本方案与 A 的核心取舍。
  • 若未来给账户增加「卡号尾号」字段，可在卡面右下角加 ••1234，拟真感还会再上一档（当前数据模型无此字段，方案先不依赖）。

✓ 优势

  • 页面最短最紧凑，扫视效率高
  • 「钱包」心智最强，和 iOS Wallet 的卡片比例一致
  • 网格可扩展：加卡、删卡位置感清晰

✗ 取舍

  • 单卡空间小，信用卡账单节奏信息缺失
  • 两列并排时金额长度受限（86,420.00 已接近上限）
  • 账户名过长需截断（示例已按 6 字内设计）

方案 C

精编分组列表 · 原生克制升级

不改变现有「按类型分组 + 列表」的骨架，只做精修：同类型账户合并进一张组卡（iOS 设置列表的分组语言），行内升级为渐变色块图标 + 双行信息 + 右侧余额带小字，信用卡行内嵌迷你额度条。最稳、信息密度最高的一版。

设计要点

  • 组卡 = iOS 原生「设置」分组的视觉语言：类型名 + 组小计做组头，行间细分割线。小计让「这一类我共有多少钱」一眼可得，这是平铺卡片给不了的信息。
  • 行内三层：42pt 渐变色块图标（账户色的 12% 淡底 + 深色描边图标，近似 App 图标质感）→ 名称+徽标+副标题 → 右侧余额 + 信用卡迷你水位条。
  • 信用卡副标题一行给全「账单日 · 还款日 · 额度」，右侧「已用 28% + 迷你条」，负债节奏在列表层完整可读。
  • 「已归档」独立组，降透明度、不参与小计，明确表达「存在但冻结」。
  • 改动范围最小：复用现有 NavigationLink 跳详情与所有交互，视觉翻新不动结构。

✓ 优势

  • 信息密度最高，账户多时浏览效率最好
  • 最贴近 iOS 原生习惯，长期使用不腻
  • 实现风险最低，交互全部保留

✗ 取舍

  • 视觉冲击力一般，「惊艳感」不如 A/B
  • 彩色只出现在图标块，账户辨识度靠文字
  • 组小计需要每类多做一次余额聚合计算

综合建议

推荐 A 为主方向、C 为回退底线：账户数量通常在 3-6 个（现金 + 两个钱包 + 一两张卡），A 的一屏 2.5 卡完全够用，且信用卡负债信息只有 A/B 的卡面能放全；A 同时给了最强的「专业财务工具」第一印象。若上线后用户反馈账户多、嫌页面长，A 与 C 可组合——信用卡/储蓄卡用 A 大卡，现金/钱包类高频小额账户用 C 行（混合形态），因为信用卡的信息才需要大卡承载，钱包类看余额即可。B 的银行卡比例与堆叠交互适合未来做「卡片管理」彩蛋页，不建议做默认列表。

注：三稿均为浅色模式示意；A/B 卡面为深色渐变，深色模式下无需变化，仅页面背景切换（#FDFCF8 → #1C1C1E）。净资产卡沿用 App 现有 Plus 深色暖调卡语言（#1C1614→#321E18）。本期已同步修复两个账户页问题：① 账户交易列表不再显示未到期的分期期次（与余额口径一致）；② 交易分组日期跨年时显示完整年份（如「2027年1月5日 星期二」）。
