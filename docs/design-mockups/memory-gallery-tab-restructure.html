记忆长廊 · 头部减负细化稿

方案 A（日·周·月三档合一）+ 双行导航已定。本轮解决「头部看着一坨」：减负三档梯度（控件块 7 → 5 → 4 → 3），全部可点击。左一为现状对照。
问题 1洞察 → 日历 切换卡顿
现在的写法是「切到洞察时，把日历整页销毁；切回来时重新建」。重建那一刻要一口气做三件重活：重新拉当前一周 + 预载前后 60 天（4 个模块各查一遍库）+ 重建 3 日泳道网格，全部挤在切换动画的同一帧里，所以肉眼可见地顿一下。
修法与布局无关、不用选：两个 tab 都常驻不销毁（切走只是隐藏），切回来零加载，卡顿直接消失。
问题 2四层切换器叠罗汉
页内控件从上到下叠了四层（见左一手机上的红色标号）：①周历/月历 → ②翻页导航 → ③模块筛选 → ④网格视图/列表视图，加上页级 tab 与摘要卡，头部合计 6 行，内容区被压掉近 1/3。
关键洞察：「网格视图」其实是按日看（3 日泳道），「列表视图」是按周看，它们和「月历」本质是同一件事——时间刻度（日/周/月）。三档合一后，两个切换器变一个。
已拍板（2026-08-19）：采用方案 A；「标题缩短为 8月17日 – 23日」的妥协被否决——标题保持完整显示，通过重新分工解决拥挤。
本轮新诊断——「一坨」的三个来源：①「日历|洞察」满宽大分段是全场最重控件，只为两个选项占了整行；②五个彩色筛选胶囊常驻头部，颜色噪音最大却是个中低频操作；③原型此前切洞察 tab 时误挂日历控件（App 实际不会），本轮已修。
命名对照：「网格视图」= 日档（3 日泳道，支持双指缩放）·「列表视图」= 周档（无限上翻 + 叙事卡）·「月历」= 月档（热力格 + 当日详情）。三档都保留现有全部能力，只是合并入口。
定死的设计规则：日期标题完整显示、永不缩写、永不截断（缩短标题的方案已被否决）。
两版通用改动：观察摘要卡（「这周过得挺稳」）从固定头部迁入内容区顶部，随滚动离场，再让出一行空间；模块筛选条保留现状。
技术注记：无论最终选双行还是置顶，卡顿修复（tab 常驻 + 视图模型上提共用）随本次重构一并落地；日档预载的 ±60 天数据在切 tab 后直接复用，不再重查。
