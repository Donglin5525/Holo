## Key Questions

1. 预设分类是否应该允许删除？结论：应该，`isDefault` 只表示来源，不应表示删除权限；只有 `isSystem` 是真正的保护标记。
2. 删除有账目的分类时默认怎么处理？结论：默认保留数据并转移，删除账目必须作为二次确认的次要危险选项。
3. 一级分类删除是否可以把所有子分类账目压到一个目标？结论：不可以，应优先把子分类整体迁到另一个一级分类，或按子分类逐项映射。

## Decisions Made

| Decision | Rationale |
|---|---|
| 移除页面右上角垃圾桶 | 其真实语义是批量清理导入分类，与当前对象删除不一致，且与侧滑删除重复 |
| 所有非系统分类允许侧滑删除 | 预设只是初始推荐，不应剥夺用户对个人财务分类的控制权 |
| 二级分类转移目标必须是同收支类型的二级分类 | 记账业务不允许交易挂在一级分类，收支类型也不能被改变 |
| 使用统一预检报告驱动 UI 和执行 | 避免 UI 只查账目，仓库却隐式删除预算或留下固定支出悬空引用 |
| 删除使用软删除批次 | 与 Holo 已有 30 天回收站契约一致，也能阻止预设分类在下次启动被补种“复活” |
