# 记账分类点击、排序与二级科目展示

日期：2026-10-27。状态：东林已批准「名称优先」方案，客户端实施及验证记录见文末。

## 产品结论

用户需要在账本中直接知道钱花在什么分类，管理分类时可以点击整行，并把常用分类排到前面。本次建议沿用现有账本和两级分类结构，调整信息层级与点击、排序行为。

默认推荐「名称优先」：名称为第一行，分类路径为固定第二行，二级分类比一级分类更醒目；金额继续在右侧对齐。备选「科目优先」将二级分类放到第一行、名称降到下一行，方便比较，但会降低查找具体消费内容的效率。

## 一、整行点击的统一规则

- 一级分类整行进入二级分类页，包含图标、文字、留白、箭头和行内边距；不再要求精确点文字。
- 一级行内不嵌套独立编辑按钮；一级编辑收敛到侧滑或二级页的「更多」操作。二级分类整行编辑，系统分类仍沿用既有编辑限制。
- 点按、长按排序、侧滑分工明确：点按进入/编辑，长按提起排序，侧滑保留编辑与删除。拖动结束不触发点按。
- 具有开关、展开箭头等独立动作的复合行，主体点击区和独立控件分别定义，不能用外层点击覆盖整个控件。
- 共用规则落在行内容的布局层：先占满可用宽度、加内边距，再定义矩形点击区域；点击动作留在外层 `Button` / `NavigationLink`。不要用全局按钮样式拦截全部页面。
- 有效按钮区至少 44pt；支持 VoiceOver，拖动有“上移/下移”等等效操作。

## 二、分类排序

- 默认状态长按任意分类行即可提起拖动，轻触反馈后浮起，原位留占位，其他行随位置让开，松手保存。
- 顶栏保留「排序」入口，进入后显示标准拖动手柄，点击「完成」退出。入口只提高可发现性，长按无需先进入排序模式。
- 一级在同一支出/收入类型内排序；二级只在当前一级下排序。一级移动时子分类整体跟随；拖动不改变父级归属。
- 支出与收入独立排序。新增分类追加到所属分组末尾。
- 排序同步应用到管理页和记账分类选择器。原有“最近常用”区域仍保持按使用频率推荐，其余手动浏览区域遵循用户顺序。
- 系统分类的编辑/删除限制不等同于禁止排序；如需固定特殊分类，应有明确产品规则，不能误用现有只读判断。
- 移动只改排序值，不改分类 ID、父子关系或历史记账归属。保存失败恢复上次顺序并就地提示，不显示假成功。
- 长列表使用原生边缘滚动；离开页面、切换收支、收到同步更新时，不留浮动行与过期拖动状态。单行不显示无效排序入口，空分类页提供新增入口。

当前 `FinanceRepository+Categories.swift` 已按 `sortOrder` 查询一级和二级分类，并支持更新该字段。实施应增加同层级的一次性保存，避免每移过一行就逐条写入；保留现有数据结构和历史关联。跨设备最终顺序及并发同步仍需专项验证，原型不能证明 CloudKit 行为。

交互方向参考 [Apple 列表排序说明](https://developer.apple.com/documentation/SwiftUI/Making-a-view-into-a-drag-source)：优先沿用适配当前最低系统版本的原生列表排序能力，不为了原型效果提高系统要求。

## 三、账本中的二级科目

推荐结构：

```text
[分类图标]  楼下简餐                         −32.00
            餐饮 › 午餐

[分类图标]  通勤打车                         −26.50
            交通 › 打车
            下雨，早点回家 · 支付宝
```

- 名称依旧是首行，固定第二行显示分类路径。一级使用次级文字色，二级用正文色和适度字重，不用彩色大胶囊抢金额和名称。
- 没填名称时，二级名称直接成为首行，第二行只显示一级，避免「晚餐 / 餐饮 › 晚餐」重复。
- 只有一级分类时如实显示一级，不虚构二级；未分类明确写“未分类”；关联分类失效时沿用已存在的真实展示信息，不能根据名称猜分类。
- 非默认账户放在金额下方，右侧对齐，与左侧分类路径平行，避免把每笔记录都撑成三行。备注、财务项目放在分类之后；过长截断，完整信息进详情。分类先于这些辅助信息展示。
- 退款和分期标记继续保留。退款与科目信息各自占位，退款不计作收入，不挤掉分类。
- 金额保持右侧、使用等宽数字。长名称截断；长分类优先保留二级可读区域；大金额保留完整意义，实施沿用项目现有金额格式规则。
- 统一修改 `TransactionRowView`，覆盖账本、搜索、账户明细、项目明细、预算明细、分类分析与证据复核。搜索结果需要同时保留日期、账户，避免分类展示修好了却失去定位上下文。
- 分类路径使用共用、可缓存的数据投影，不在每个可见行里单独发起父分类查询，避免大账本滚动变慢。

## 原型覆盖与实施验收

交互原型包含：两种账单信息层级；一级、二级分类页面；整行进入/编辑；长按拖动与显式排序；收入切换；空二级分类；名称编辑。设计状态还包括常规账单、长名称与大金额、仅一笔、空账本。

原型仅使用演示数据，暂存的顺序仅属于原型，不改 App 数据。真实 App 的侧滑删除、iCloud 同步、触觉与自动滚动属于实施验收。

实施需实际验证：点击行左/中/右留白均有效；正常滚动不误排序；长按拖动首尾、二级、收入均正确；取消拖动不保存；退出重进、重新启动、分类选择器和两设备同步顺序正确；删除/恢复分类不串归属；搜索、退款、分期、长名称、动态字体、深色模式与 iPad 均保留信息与操作。

原型阶段未修改 iOS、后端和真实数据，也未执行编译、装包或部署；这些不能由原型验收代替。

## 客户端实施记录

- `HoloRowHitArea` 统一定义满行宽度、最小点击高度和矩形命中范围；接入共用设置行、分类管理、两套分类网格（`CategoryPicker` 与实际新增记账使用的 `TransactionCategoryGrid`）和预算分类选择器。网格内容保持居中。共用设置行目前有 15 处调用，包含财务设置、导入导出和 HoloAI 设置；未增加外层手势来覆盖独立开关与展开按钮。
- 分类管理使用系统 `List.onMove`，支持默认长按和显式排序手柄。行内嵌套编辑按钮已移除，一级编辑保留侧滑并增加二级页顶部入口。二级页排序时保留背后一级导航入口的身份，避免排序状态被导航刷新复位。
- 同收支、同父级一次性保存顺序，分类集合变化时拒绝旧指令；同 ID 的活跃同步副本一起更新。失败只恢复排序字段，保留其他未保存编辑；原位放回不做无效保存。新增分类排在所属分组末尾；历史同权重分类按稳定 ID 决定次序。
- `TransactionRowView` 共用“名称 + 分类路径 + 辅助信息”布局，非默认账户位于金额下方；搜索结果仍保留全部账户、日期、备注，退款和分期仍展示。`FinanceCategoryNameCache` 一次构建父分类名称索引，分类编辑或上下文合并后刷新，行渲染只读内存。
- 验证脚本：`python3 scripts/run-finance-category-tests.py`。使用内存 Core Data 和临时编译目录，运行真实生产排序方法、分类名称缓存和展示规则；测试支撑不访问 App 单例、真实数据库或 CloudKit。
- 33 项断言通过：一级/二级排序、收支与父级隔离、同步副本、回收站排除、过期/重复/跨组指令拒绝、保存失败恢复、无效保存跳过、历史交易归属、换上下文持久化、稳定平局顺序、全量分类保留收支分组、分类改名/软删缓存失效、名称及缺失分类展示。
