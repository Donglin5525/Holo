# 分类父级断链修复

状态：实现与隔离回归完成；真实账目未迁移，未做跨设备验收。

## 产品结论

管理页原先只从有效一级向下展示，缺失父级的二级分类无法进入这棵树。历史账目仍按分类身份引用它；另一条同名分类拥有正常父级，不能证明历史账目引用的也是这一条。因此会同时出现完整路径和只有二级名称的记录。

代码中存在两条可能制造断链的路径：按名称合并不同 UUID 的父级并物理删除旧身份；在云端引用尚未到齐时清理当前无引用的默认分类。晚到子分类仍可能指向已删除的旧父级。另有匹配容错主动放行孤儿，导致新账目继续使用异常分类。上述路径可解释风险，但缺少对应历史操作日志，不能断言某条存量记录的唯一成因。

## 决策

1. 分类管理显示“归属待修复”，按旧父级和收支类型展示分类与关联账目数。用户明确选择有效一级、核对影响后恢复归属；不从名称自动猜测父级。
2. 保留不同 UUID 的同名分类；停用按名称合并删除和默认分类自动清理。仍保留 FinanceDuplicateRepair 对同 UUID、内容一致且云记录身份可确认副本的修复。
3. AI 候选、收据解析、导入缓存与入账边界统一要求有效、同收支类型的一级父链。AI 候选只能返回二级，不以一级替代失效二级。
4. 历史账目继续展示真实二级与“归属待修复”。一级统计缺少有效父链时跳过分类明细并留数量日志，总收支仍保留这些金额，不让二级冒充一级。恢复后按真实一级归组。
5. 一级名称缓存也发布子分类归属变更，避免修复后列表仍显示旧路径。

## 写入与冲突规则

修复预览为纯值，不携带账目正文。版本指纹包含分类身份、名称、父级、删除状态和关联交易身份/删除状态；执行前重新计算。新增或恢复分类、关联账目变化、目标删除或更名、同 UUID 分类冲突，均拒绝旧预览并要求重新核对。

专用后台 context 独立保存，只修改同组分类的 parentId。事务不改变分类 ID、交易关系或删除状态，不合并同名项，不连带保存共享 context 的其他编辑。保存冲突采用错误策略；失败恢复该操作改动的父级值。主界面只刷新已注册的相关对象并发送财务变更通知。

目标是本机预览到保存的校验，不提供离线多设备的全局串行事务保证。其他设备尚未同步的记录到达后若仍断链，会再次出现在修复入口，不能冒充已全量修复。

## 删除、恢复、读取三侧

- 删除：继续使用现有分类影响预检与去向处理；删除一级不能绕开子分类及引用处置。移除两条无完整引用证据的自动分类物理删除路径。
- 恢复：现有回收站恢复继续联动可找到的父级。已彻底缺失父级的记录通过显式归属修复处理；同旧父级下的软删分类纳入预览并只改父级，保持删除状态。日后恢复或迟到的其他异常记录继续显示待修复。
- 读取：选择器/候选与新增写入拒绝缺失父链；历史账目明确标识，一级统计不混层、不改总收支。

## 取舍与回退

不新增 Core Data 字段或迁移，不建立仅存在本机的父级别名，避免跨设备不同解释。代价是同名但不同身份的分类可能同时可见；合并需要独立的显式迁移与迟到引用契约，不能重新启用旧的按名称删除。

代码回退不自动逆转已经确认的真实归属变更。真实数据恢复须保留执行前分类 ID/旧父级清单，并在独立预览中确认回退范围；不能通过删除分类来撤销。
