# 分类父级断链自动恢复

状态：后台自动恢复及专项、隔离数据与启动交互验收完成。用户自己的真机数据已手动处理，本轮不再写入真实数据。

## 产品决策

历史分类关系异常由产品内部恢复，不要求用户理解数据库、寻找一级分类或进入维修入口。撤销此前新增的“归属待修复”区块、选择父级弹层和账目技术状态提示。

App 启动和云同步后的既有后台修复轮次都会检查缺失父级的分类。默认分类在名称、图标、颜色、收支类型和完整默认目录均匹配时，恢复到唯一有效的默认一级；包括只同步到一个子分类的情况。默认目录同时读取简体、繁体和英文定义，不依赖当前界面语言。

自定义、编辑过标识、多个可能父级、原父级仍存在、同身份冲突等缺证情况不猜测归属；保留记录并记内部诊断，交由开发排查，不向用户展示修库流程。不能承诺从缺失信息中恢复任意自定义历史意图。

## 根因与防复发

管理页按有效一级向下展示，缺失父级的二级无法进入该树；历史账目仍引用其身份，同名的另一条分类关系正常不能证明它也正常。代码发现的风险路径包括：按名称合并并物理删除不同 UUID 父级、在云端引用尚未到齐时自动清理默认分类，以及允许孤儿进入 AI 新账目候选。缺少对应历史操作日志，不断言每条存量记录的唯一成因。

前一轮已经停用按名称删除不同身份分类及无可靠来源证据的默认分类自动清理，保留有云记录身份验证的同 UUID 副本修复。AI、收据、导入和入账边界继续检查完整父链，避免新增错误引用。

## 自动写回规则

- 使用独立后台 context 的既有修复轮次，不阻塞界面、不弹确认；纯值目录从主线程传给后台队列。
- 每组写回前重新核对分类及关联账目版本。保存采用错误合并策略，事务标记为 `finance.categoryParentRepair.automatic.v1`，结束后恢复原 context 配置。
- 写回前先在 App 私有 Application Support/FinanceCategoryRepairReceipts 原子保存回退映射；映射落盘失败时不改数据，下轮可重试。
- 只修改分类的 parentId，保留分类 ID、账目关系、金额、日期、账户、备注和软删状态；同名项不合并或删除。
- 不使用一次性“已修复”标记。新启动、晚到同步和恢复后仍会检查；已恢复数据再次运行零修改。
- 自动合并通知及财务变更通知更新列表、父级名称缓存和统计，无需用户重选分类。

## 删除、恢复、读取三侧

删除继续走现有影响预检与迁移/同批软删，不再用自动清理删除父级。回收站恢复继续联动能找到的原父级；彻底缺失的默认父级由后台规则恢复。同旧父级下的软删分类只改归属，不复活分类或交易。

读取继续保留历史账目的真实二级；缺失有效父链时不让二级冒充一级进入分类统计，总收支金额保留。成功恢复后按真实一级归组。读路径不自行猜测或写回归属。

## 风险与验收

不新增 Core Data 字段或迁移，不改变分类和账目身份。代价是保留不同身份的同名分类；不能重新启用旧的按名称删除来消除重复。离线多设备不构成全局串行事务：新记录到达后由后续后台轮次处理，旧版本设备仍需升级才能获得新规则。

验收使用合成内存库、实际默认目录的模拟器 XCTest、历史手机备份的隔离副本，以及专用无头模拟器启动流程。真实用户库不作为测试夹具写入；所有个人数据副本与回退映射留在私有临时目录，不进公共仓库。尚不宣称 App Store 已发布或真实双设备同步全部验收。

## 本轮验证

- 生产逻辑隔离内存库 67 项断言通过：单个/整组默认分类恢复、三侧隔离、冲突与自定义保护、回退映射、落盘/保存失败、重复执行、完整父链、独立 context 等。
- 原有分类排序、缓存与账目呈现 33 项回归通过；测试工厂明确绑定上下文实体，避免多内存模型的类实体歧义。
- 实际默认目录、三语名称与图标、单个饮品自动恢复、AI 匹配、原孤儿修复、欢迎笔记清理，共 29 项模拟器 XCTest 全部通过。
- 历史手机备份的一致性隔离副本使用生产完整模型工厂、真实默认目录和生产自动写回逻辑；逐字段核对全部业务实体、关系、对象 URI、交易内容，只有分类 parentId 改变，第二次执行零修改。个人数据及数量仅留私有临时报告，不入库。
- 专用无头模拟器构造默认午餐断链，启动 App 即自动恢复；只通过普通搜索核对名称/一级/二级同时展示，没有点击修复操作。分类管理保持普通列表，无手动修复入口。只读复核交易所有字段和分类身份不变，私有回退映射生成成功。
- 本轮不安装真机、不修改用户已手动处理的实际数据。真实多设备同步与发布仍是独立验收层级。

最终主 App 与 Widgets 双架构模拟器构建通过，新增自动恢复服务与默认目录文件无编译警告。
