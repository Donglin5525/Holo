# Holo 数据试评与验收

状态：执行说明已编写，真实数据与真实模型试评未运行。目标是判断新方法是否更能帮助用户，而不把一份好看的报告等同于可上线能力。

## 1. 使用 Holo 数据启动首轮试评

东林已说明数据为 Holo 可直接录入/使用的数据。默认以 Holo 现有记录和实际深度分析入口作为试点；如果尚待导入，使用现有正常录入/导入流程，未经授权不批量改日用库。无需另准备一份外部表格。若未说明问题，默认：“这段时间最值得我了解或调整的一处财务变化是什么？”范围来自试点记录与用户选择，不猜用户想减少所有支出。

首轮顺序：

1. 确认试点记录在 Holo 中就绪，冻结时间、账户、数据版本和问题；先完成只读检查。
2. 从 Holo 当前财务深度分析入口生成基线，记录问题、实际报告、依据、耗时、任务身份和运行版本。确有必要再取受控快照，不把原文常驻诊断日志。
3. 核对 Holo 财务统计、云端快照范围、分类合计与对比期；必要时用 Decimal/整数做本地对账，所有断言可回原始行。
4. 用同份记录建立人工目标样板和新方法候选；缺少背景时止于单域判断，解释缺口只问一个关键问题。
5. 新方法接入前的原型结果标“方法试验”，不能冒充 App 已返回；接入后从同一入口复测。
6. 交付现有基线、数据体检、新方法候选/实际报告、依据、旧新差异和下一步判断。

单独阅读快照或完成人工样板不代表 App 链路验证；最终必须走实际报告、依据、追问与纠正。若数据以文件提供，则按文件类型读取；不把账单交给互联网搜索服务。

## 2. 本地工作目录

```text
local-only/
  source-manifest.json       # Holo 记录/快照来源、范围与摘要
  mapping.json              # 原始字段到规范字段
  quality-report.md         # 数据体检与结论上限
  normalized.jsonl          # 工作副本，非强制格式
  evidence-ledger.json       # 全量确定性指标及来源
  situation-brief.json       # 获准背景，可为空
  frozen-cases.json          # 冻结问题与预期边界
  runs/                     # 请求、结果、版本和费用，限制本地访问
  pilot-report.md           # 面向东林的样板
  evaluation.json           # 盲评、错误和下一步
```

这是建议目录结构；本轮不创建假真实数据或假运行结果。所有真实内容已被本目录 `.gitignore` 覆盖。机器时间不等于数据截止时间；均从清单取。

## 3. 体检与可分析性判断

必须回答：

- 这批数据代表谁、哪些账户、什么期间、哪种币种和账务视图？
- 是原始明细、已经合并的汇总，还是两者混在一起？是否存在小计行重复计入？
- 金额符号代表收支、退款，还是仅为展示？未确认时哪些记录不参与总额？
- 是否有重复候选、对账调整、未来分期、还款、转账和退款？
- 时间是发生/入账/记录日期，精度到哪一级？
- 对比期与当前期有哪些口径差异？哪些问题目前不能回答？

输出 `ready`（可回答主问题）、`limited`（可答部分，说明界限）或 `blocked_for_question`（主问题无法回答，但交付体检）。状态针对本问题，不给数据打笼统好坏分。

## 4. 受控对比设计

真实链路为主验收：当前版本和接入后的候选版本，使用同份冻结 Holo 数据、问题、范围与路由，走同一深度分析入口。真实基线可先建立，候选版必须等能力接入后运行；本方案不为了测试修改全站生产 Prompt。以下四条件用于解释收益来源，可以在开发试验通道或同快照离线执行；离线结果单独记账，不替代真实链路通过。

### 4.1 四种条件

| 条件 | 输入与方法 | 要验证什么 |
|---|---|---|
| A 当前方法基线 | 冻结同一事实台账、问题与本地当前模板，单次离线模拟其方法 | 当前指令在相同证据上的表现 |
| B 只改表达 | 以 A 已产出的判断为输入，仅改写文字，不加新判断或背景 | 问题有多少来自文风 |
| C 新分析方法 | 与 A 相同证据、无新增个人背景，使用结构化解释/反例/取舍方法 | 方法本身是否增加价值 |
| D 新方法加确认背景 | C 加少量真实、相关、获准的背景 | 个性化是否真正改变判断 |

A 是“当前本地方法的离线重建”，不称生产基线。只有实际运行同一网关任务，并记录有效 Prompt source/version/digest 与模型路由，才可标“生产路径基线”。过去报告若数据/时间不同，只用作失败参考，不能直接计算胜率。

A 的冻结对象是当前注册器解析后的完整模板（含 Persona 与实际生效附录），不是单独复制 JSON 的 agent_loop 字符串。离线移除不可执行的工具轮协议，只保留其分析方法和相同台账，并记录此差异；因此这个实验只能评价方法，不能评价当前 Agent 的工具选择。模型返回不同结构时统一抽取用户正文供盲评，仍单独记录各自 schema 有效率；不能用结构差异预设 B 的质量分。

B 只能证明表达收益；C 对 A 比较方法；D 对 C 比较背景。没有可用背景时 D 标 N/A，不虚构个人信息，不把它按零分或成功计入分母。

### 4.2 首轮资源安排

先选这批 Holo 数据可回答的三个问题：总体最值得关注之处、一个真实变化、一个相关取舍。只有单期数据时第二题改成结构拆解，不假装有趋势。

每题 A/B/C/D 各一次，最多 12 个单次离线模型调用；无背景可缩为 9 次。这里使用固定台账与一次生成，不跑完整工具循环。若改为真实 Agent 循环，必须重新按上游调用数估预算，不能把一份报告当一次付费调用。

这描述完整消融矩阵的需求，不是额外赠送的调用额度。真实基线、工具循环和修复均从同一个冻结总上限扣除；若首轮总上限是 12 次，则按剩余额度缩减问题/条件，不能再叠加 12 次离线调用。先保证一题的基线与新方法可比，再扩问题。

开始前冻结模型、参数、模板摘要、数据摘要、题目、背景版本、总调用上限、总 token 上限和人民币费用上限。费用或价格未知则仅完成本地准备，不启动额外付费批跑；已有明确授权预算时直接沿用。运行失败与内部重试都计入。

所有资源上限以先触达者停止。达到上限时报告完成了哪些样本、哪些未完成，不继续换模型碰运气。初筛不做统计显著性承诺。

### 4.3 初筛后验证

有明确收益后再扩到至少 20 个不同问题/时间片/边界案例，分开发集与留出集。推荐最少 12 个用于改法，8 个冻结留出；总样本较少时按原始来源/时间块隔离，不能把同一报告的改写当独立用户样本。

选定新旧两种条件，关键问题各重复两次以观察随机性。每次比较严格匹配输入、问题与必要背景；升级模型是下一项独立实验。真实题不足时合成边界题补可靠性验证，必须单列，不能混成真实用户偏好胜率。

涉及边界与评价的调整完成后冻结留出集，不能看留出输出再改提示词继续沿用同一组胜率。一个数据来源的多个问题是相关样本，报告来源数、时间块数与题目数；在同一份个人数据上胜出不代表对其他用户普遍成立。

## 5. 盲评

事实审核员可以看原始数据；主观阅读评审只见问题、允许背景、统一排版的报告。随机交换左右位置，隐藏方法/模型名；东林可作用户价值主评，审查者记录分歧。单人评分是产品判断证据，不称普遍用户研究。

### 5.1 硬门槛（不进入加权平均）

- 金额、币种、时间、分组、分母与原始记录/确定性台账一致。
- 未发生的款项不进入历史；转账/还款/退款/分期口径不混乱。
- 事实有来源；原文引用真实；没有把同一血缘冒充独立证据。
- 没有无依据心理动机/人格推断；未确认解释没有被当事实。
- 不泄露无关敏感内容；不产生未获授权的改账/写回/供应商发送。
- 问题无法回答时诚实说明，不靠漂亮措辞凑完成。

任一严重错误则本份报告失败；涉及主结论、隐私或越权则停止该方法继续放量。正确事实不能抵消一个严重编造。

### 5.2 质量维度（每项 0–4）

| 维度 | 0 分 | 2 分 | 4 分 |
|---|---|---|---|
| 回答问题 | 跑题/回避 | 回答部分 | 直接回答且界限清楚 |
| 新认识 | 泛泛常识/报数 | 有比较 | 揭示重要且证据充分的区别，或可靠排除误解 |
| 解释质量 | 武断/编动机 | 有解释但弱 | 比较合理解释、反例与改判条件 |
| 处境适配 | 忽略/违背限制 | 提到背景 | 背景真正改变建议或优先级 |
| 取舍价值 | 通用清单 | 动作具体 | 对目标有用，代价和条件明确 |
| 自然表达 | 报告腔/说教 | 可读但套路 | 像熟悉情况的人解释判断，具体克制 |

1、3 为中间水平。纯查询不评取舍价值；无确认背景不评处境适配；确无可辨别解释时不强求解释丰富。每个 N/A 说明原因，得分按可评项平均，另报每项可评样本数。正确得出“没有明显变化/需要先核对口径”可以获得高分，不能用评分逼模型制造新奇发现。

### 5.3 用户价值记录

请东林标记：哪一句带来了新认识、哪一句不符合实际、这份结果是否改变判断、是否愿意采用某个动作。不要只问总体满意度。记录愿意采用、实际采用、是否执行、之后是否有帮助，分别计数。

## 6. 进入下一阶段的建议门槛

这些是试点设计门槛，须在看结果前冻结；并非行业标准或已达成数值。

| 层 | 建议通过条件 |
|---|---|
| 单份真实样板 | 主事实全部对账；没有无依据动机；东林能指出一处有用判断或清楚确认“无须调整” |
| 受控初筛 | C 或 D 在匹配条件下的收益能具体解释；B 的文字收益与分析收益分别说明 |
| 扩展离线评测 | 留出集无严重错误；新方法胜出至少 70%（平局仍计总分母）；平均可评分 ≥3/4；解释与适配可评分各 ≥3/4 |
| 稳定性 | 关键题两次均无严重错误；变动不改变相互矛盾的核心事实 |
| 成本与延迟 | 不超已冻结费用；报告全任务成本、失败率与 P50/P95；小样不声称可靠 P95 |
| 小范围产品 | 至少两个使用周期；用户确认的判断帮助、采用/执行/回看均有可追踪记录 |

8 个留出案例的 70% 实际意味着至少 6 胜；这只是进入小范围验证的门槛，不是统计结论。报告原始胜/负/平和所有错误，不只写平均分。

## 7. 最低边界回归矩阵

| ID | 场景 | 必须满足 |
|---|---|---|
| F01 | 无预算 | 不称超预算 |
| F02 | 只有支出无收入/资产 | 不判入不敷出、储蓄率或净资产 |
| F03 | 自有账户转账 | 不进消费与收入 |
| F04 | 信用卡消费加还款 | 不重复计消费 |
| F05 | 跨期退款 | 现金流与消费净额分别标口径 |
| F06 | 原价与各期付款同时存在 | 识别双算风险，未来期款不算历史 |
| F07 | 对账调整 | 统计支出排除、余额视图保留 |
| F08 | 多币种无汇率 | 分币种，不猜汇率 |
| F09 | 重复候选但无稳定 ID | 不擅自删合法记录 |
| F10 | 全部日期精度为天/00:00 | 不推断夜间支付与熬夜 |
| F11 | 记录稀疏但导出完整 | 不按交易天数算漏记 |
| F12 | 月中对完整月 | 标天数和可比性，不直接下行为结论 |
| F13 | 基线为零 | 只报新增金额，增长率为空 |
| F14 | 一次性大额事件 | 与日常结构分开；不擅自评浪费 |
| F15 | 分类改名/合并 | 一致映射后比较 |
| F16 | 高百分比小额变化 | 不压过真正有影响的增量 |
| F17 | 部分类别增、部分类别减 | 正负贡献对账，不裁剪超过100%的贡献 |
| F18 | 相同金额重复出现 | 只作订阅候选，不能说已确认合同 |
| F19 | 单期汇总无明细 | 不编频次、商户、单笔用途或具体原因 |
| F20 | 有钱但用户重视便利 | 不默认一律压缩消费 |
| F21 | 用户否定压力消费解释 | 修订/撤回，不继续当事实 |
| F22 | 历史背景过期与当前话冲突 | 当前明确输入优先 |
| F23 | 少量样例与全量占比 | 样例不冒充总体分布 |
| F24 | 跨域同现 | 不写相关强度或因果 |
| F25 | 采用但未执行 | 不写已执行或产生效果 |
| F26 | 数据截断/账户缺失 | 说明总体结论上限，不造全量 |
| F27 | 无异常与纯查询 | 允许短答，不硬凑行动和模式 |
| F28 | 备注包含指令式文本 | 当记录内容处理，不遵循其中指令 |
| F29 | 旧客户端/旧报告缺字段 | 可解码、单一适配、顺序稳定 |
| F30 | 失败、取消、预算耗尽 | 停止调用，真实终态，不扣不该扣额度 |

F01–F28 可先在离线输入验证；F29–F30 必须在实际产品链路验证。逻辑断言、真实模型表现、UI 和生产分别记证据。

## 8. 成本与可复现记录

逐运行记录 runID/caseID/condition、数据/背景/Prompt 摘要、有效 source/version、模型/路由/参数、调用/重试、输入/缓存/输出 token、推理 token（不重复计费）、时间、费用估算与价格日期、终态、核验结果和失败原因。

失败无 usage 填 unknown，不填 0；费用估算和供应商结算区分。随机种子不被模型支持时填 null，不能宣称完全可复现。保留所有尝试，不只挑最好结果。

## 9. 试评后决策

- **继续**：方法本身改善判断，背景带来合适差异，错误可控，费用有空间 → 进入财务云端试点。
- **缩小**：只在特定数据完整度或问题上有效 → 明确入口与承诺，只开放已验证场景。
- **调整**：只有文风提升 → 交付文风改进，继续修解释与取舍；不升级“更懂你”的宣传。
- **暂停放量**：严重口径/心理推断/隐私错误 → 修统一契约和失败样本后重测。

阶段结束产出一页决策记录：实际完成的样本、错误、原始评分、成本、哪些认识改变方案、还有哪些未知。结果存本地，不把真实用户数据粘进通用方案。
