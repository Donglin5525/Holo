## 3. 实施任务

### T00：Holo 实际数据基线与样板（基线不依赖新业务实施）

输入：已就绪的 Holo 试点记录、范围和账户；本轮问题或默认问题。数据如待导入则沿用现有正常流程，未经授权不批量写日用库。

交付：当前 Holo 入口生成的基线报告、任务/版本、记录清单、排除/待确认项、确定性证据台账、目标样板、需要的唯一关键澄清、评分和下一步。

验收：所有主数字可回原始行；无背景时不产生心理机制；不改原数据、不使用未授权供应商、不把真实结果入库。只有汇总时降低结论粒度。

### T01：财务语义统一（S2 的前置）

目标：云端统计、本地统计与财务页面使用同一“已发生消费”语义。

主要位置：

- iOS 根下 `Services/AI/Agent/Tools/HoloFinanceDataSource.swift`
- iOS 根下 `Models/FinanceRepository+Aggregation.swift`
- iOS 根下 `Services/AI/Agent/Cloud/HoloCloudAnalysisSnapshotBuilder.swift`

决策：统计行源使用统一统计规则；需要对账明细时单独声明明细用途，不能通过扩大所有统计范围解决。验证对账调整、未来发生、软删、重复副本及 scope 一致性。

验收：相同规范输入下，财务统计/本地 Agent/云端快照聚合一致；含一笔对账调整的合成案例必须排除该笔，余额视图保留其意义。先写有意义的失败回归，再改读源。

### T02：任务与口径快照

在既有 AnswerTask 上增量增加 analysisVersion、questionIntent、comparisonPolicy、financeSemantics 与完整性信息；字段命名以最终代码风格定稿，语义服从 [02](02-财务数据与分析契约.md)。可选字段为旧客户端兼容服务，不能用 unknown 自动猜业务事实。

### T03：相关个人处境投影

2026-10-19 跨方案接口约定：与 [报告融合理解方案 §7.2](../../../_common/plans/2026-10-18-HoloAI报告融合理解升级/README.md) 共用 PersonalSituationBrief 契约和单一背景注入入口。先实施的一方可从既有合格记忆构造最小投影，后续报告理解增加来源适配；不另建第二层注入，也不要求本财务升级等待完整报告学习链路。背景为空时仍正常分析。此为实施规格同步，未表示 T03 已实现。

验收：背景会改变判断的案例可解释；无关、过期、否定、已遗忘内容不被当当前事实；背景为空正常分析；统计所有被选条目的实际使用，不以“看到8条”声称理解用户。

## 4. ADR：方法与系统关键决策（均为 Proposed）

### ADR-01：复用现有云端任务与统一答案

背景：已有运行、加密快照、领取和报告链路，重建会增加兼容与数据风险。

决策：沿既有系统添加任务相关处境、解释契约、核验和反馈。

收益：单一事实源、复用取消/额度/报告；代价：需处理旧协议兼容和部分现有口径债务。

替代方案：另建专家多 Agent 服务、独立报告与记忆库。当前样板价值尚未证明，运维和成本不值得先承担。若以后多领域任务确有并行收益，再以数据论证。

### ADR-02：先固定模型验证方法

背景：用户同时反馈深度和文风不足，直接换模型会混淆原因。

决策：用 A/B/C/D 条件区分文风、方法与背景，之后单独比较模型。

收益：知道收益来自何处；代价：需维护冻结证据与人工评审，首轮速度稍慢。

替代方案：一次更换模型/Prompt/上下文/报告。无法判断哪项有效，不作为首轮实验。

### ADR-03：一次生成，按需修复与审核

背景：深度任务已有多轮成本，固定增加分析师/咨询师/规划师/写手可能大幅放大费用。

决策：角色能力落在方法与契约，默认一轮判断＋正文；程序核验；只在明确失败或风险时修复/语义审核一次，共享预算。

收益：控制延迟与费用；代价：单模型同时组织判断与语言可能仍有质量上限，需要评测。

替代方案：每份报告固定多阶段 LLM 串联。仅当真实对比证明质量增益大于成本时采用。

### ADR-04：解释作为可修订对象

背景：消费事实不等于心理动机，长期记忆可能放大一次错误解释。

决策：解释附来源、竞争解释、状态与改判条件；用户确认/否定进入既有反馈，未确认推断不升级稳定事实。

收益：可信、能纠正；代价：增加状态管理和用户确认设计。

替代方案：自由文本写入长期记忆，后续直接引用。错误难撤回，不采用。

### ADR-05：Holo 真实链路为主，同快照核算辅助

背景：东林确认试点数据可直接用于 Holo，现有云端快照限制仍可能影响完整性。

决策：先用 Holo 实际记录和当前入口建立基线，再用同份快照核算与验证新方法；候选接入后必须复测同一入口。快照离线实验只能辅助归因。

收益：直接评价用户实际拿到的报告，复用现有数据与导入；代价：新方法完整链路需 S2 能力接入，不能用离线样板跳过。

替代方案：只做外部文件分析或把全量记录全部发模型。前者无法证明真实产品效果，后者可能截断、昂贵且难对账，不作为主验收路径。

## 5. 风险与回退检查

| 风险 | 检测 | 行动 |
|---|---|---|
| 口径不一致 | 同一合成数据三路径对账 | 暂停新解释，先统一统计读源 |
| 更会说却没有帮助 | B/C/D 消融与用户逐句反馈 | 保留文风收益，缩小深度承诺 |
| 心理解释越界 | 无背景案例、否定解释案例、人工审查 | 撤回解释、记录纠正、修失败样本 |
| 个性化成本放大 | 每次输入组成、实际调用/费用 | 相关性投影、后台分池、停止无边界扩张 |
| 试评数据泄露 | 本地存放、Git ignore、日志字段检查 | 不入库，既有授权通道最小发送 |
| 旧客户端无法解码 | 缺字段/旧结果/新老组合测试 | 能力协商，V2 关闭回原报告 |
| 回看伪因果 | 执行未知、干扰、窗口差异案例 | 只报告变化与限制，不称行动有效 |
| 不可恢复/反复重试 | 稳定任务 ID、调用上限和终态 | 一次针对性修复，仍失败就停止 |
