# 财务数据与分析契约

状态：设计契约 v1，供 Holo 实际数据试评、辅助核算与后续增量实现。结构名为方案命名；未表示现有代码已实现。

## 1. 输入形式与能力上限

本轮主来源是 Holo 内的实际财务记录或可通过现有流程录入的 Holo 数据。冻结记录 ID、范围、数据版本与任务快照摘要，不要求用户另做一份表格。若实际提供的是 Holo 导出/导入文件，先映射其现有字段，保留原件与来源定位；表格/CSV/JSON/汇总稿作为兼容输入。

| 数据形态 | 能做什么 | 不具备的证据 |
|---|---|---|
| 分类与月份汇总 | 总额、分类变化、集中度与同口径对比 | 单笔用途、真实频次、商户、退款原单 |
| 交易明细 | 构成、次数、每笔均值、日期节奏和样例核对 | 未提供的动机、合同和真实使用频次 |
| 汇总加备注 | 有原始定位的事件解释 | 不能把少量备注外推到整个类别 |
| 明细加确认背景 | 结合目标与限制给出取舍 | 不等于已经验证因果或长期规律 |

只有不完整数据时，照实分析已知部分。不得把缺少收入当收入为零，或者把只导出一个账户说成全家收支。

## 2. 数据说明清单

使用 [input-manifest.template.json](templates/input-manifest.template.json)，字段包括：

- 本地来源与摘要、文件格式、工作表、行号/记录 ID 映射、导出时间。
- 用户问题、主范围与可比基线、用户时区；日期只有天时不补时分。
- 包含账户/币种、收支与退款口径、是否含未来交易、是否汇总、已知遗漏与截断。
- 用户是否确认覆盖完整；未确认填 unknown，不能因为表内求和正确就声称完整。
- 允许使用的背景及其来源；未提供的目标、预算、负债、家庭责任等均未知。

清单的 `externalModelUse` 默认 `not_started`，表示本轮没有额外调用；它不是对既有会话处理的追溯授权。未来真实 API 试评按已授权范围和具体费用上限冻结。

## 3. 规范化交易行

每行至少有稳定来源定位、日期、金额和收支类型。以下是内部设计字段；不要求用户提供所有列。

| 字段 | 语义与缺失处理 |
|---|---|
| recordID/sourceRef | 工作副本稳定 ID；指向文件摘要、表名与行号或原始记录 ID |
| occurredDate/time/zone | 发生日期、可选时刻与时区；不清楚是入账日期还是交易日期则声明 dateSemantics=unknown |
| timestampPrecision | day/minute/second/unknown；只有可靠支付时刻才分析夜间消费 |
| amountDecimal/currency | 金额使用十进制字符串或 Decimal；币种必须显式提供或经用户确认 |
| entryType | expense/income/transfer/refund/repayment/adjustment/unknown，来自明确字段或已确认规则 |
| categoryPath/categoryID | 保留用户分类与层级；合并映射需可审计，不靠模型偷偷重分 |
| accountID/projectID | 可选；一致假名替换可脱敏，不发送完整账号 |
| note/merchant | 可选脱敏内容；引用需对应原文，备注不自动等于动机 |
| relatedRecordID | 转账对、退款原单、分期原单等关系；不确定不填 |
| planStatus | posted/scheduled/unknown；历史只纳入已发生，未来承诺另列 |
| qualityFlags | 重复候选、缺分类、时刻不可靠（补录默认值，如整批 08:00）、口径不明、疑似缺失、**多笔合并行**等 |

模型不得直接改规范化表。分类建议、同类词候选或重复候选作为待确认结果；确认/确定性规则完成后生成新版本。

## 4. 财务口径硬规则

| 主题 | 处理规则 | 不允许的结论 |
|---|---|---|
| 转账 | 明确内部转账从消费/收入统计剔除；现金流视图按账户另列 | 把充值、自己转自己当作消费或收入 |
| 信用卡还款 | 有明确标识时记为偿债/账户流动，不与刷卡支出重复计算 | 消费加还款得出双倍开销 |
| 退款 | 现金流按实际退款日期；消费净额可关联原单另算，明确是哪种视图 | 不说明就跨期回写、重复扣减或把退款当工资 |
| 分期 | 已发生消费与分期付款视图分开；未来期款单列承诺；未知原单关系先提示风险 | 原价加各期付款双算，或未来期款算已花 |
| 对账调整 | 从收入/消费统计排除，余额对账单独体现 | 把修正余额解释为行为变化 |
| 多币种 | 无经确认的汇率日期/来源时分币种分析 | 直接相加 CNY/USD，或模型猜汇率 |
| 账单时刻 | 只有原始交易时刻可信才做时段；补录/00:00 默认值不视作真实支付时刻 | 从记账时刻推断熬夜、情绪或压力 |
| 分类修订 | 显示映射与版本；跨期合并一致口径后再比较 | 把分类重命名或重新归类说成消费突变 |
| 重复 | 强 ID 可确定去重；相同日期金额商户只标候选 | 静默删除看似重复的合法消费 |
| 事件缺失 | 区间无记录可表述未发现记录；导出完整性另看账户与导出说明 | 用有账单天数/日历天数宣称覆盖差或漏记 |
| 多笔合并行 | 一行金额实为当日多笔合并时标注合并数；频次类分解按合并数还原或排除该行 | 把合并行当一笔做次数×均值分解 |
| 账户归并 | 上游把多账户合并为单一账户（如恒「现金」）时在数据说明声明 accountSemantics=collapsed | 把「账户恒为现金」解读为用户只有现金账户并下账户级结论 |
| 补偿入收入 | 报销/理赔等补偿被映射进收入类目时，现金流视图可用；结余、储蓄率类结论须剔除或明确口径 | 把含报销的收入直接当可支配收入评估结余 |
| 合同条款 | 利率、费率、提前还款规则、贷款方方案等未在台账或确认背景中提供时，不得用外部常识假设；分期类建议只基于月供现金流并标注「未含利率信息」（2026-10-17 S1 实锤：模型编造车贷利率3-4%，实际≈零息） | 用编造的利率论证「提前还款不划算」等结论 |
| 预算 | 只与相同币种、范围、分类和周期的已设预算比较 | 没预算却宣称超支，拿本月预算评全年 |
| 收入/资产 | 需对应明细或截至时点；消费记录不代表全部资产负债 | 没收入列就说入不敷出、存款不足或净资产下降 |
| 周期负担 | 已确认合同/订阅/分期才列固定承诺；重复金额仅为待核对候选 | 多笔相近金额就断言自动续费或可取消 |
| 使用价值 | 必须有用途、使用情况或用户评价 | 仅按金额把耐用品评为浪费或投资回本 |

收入、消费净额、现金流和资产变化是不同问题。一次报告选定主口径并标明，必要时并列补充，不能互换。

## 5. 确定性指标

所有计算由本地脚本/领域计算模块完成，模型不心算出新指标。使用 Decimal 或整数最小币种单位，舍入只在展示边界发生；原始值、单位、币种及精度留在台账。

### 5.1 必要基础指标

按问题计算本期/基线的支出净额或毛额、收入、笔数、分类/项目贡献、单笔均值、大额事件、已确认周期承诺。没有必要不生成全部指标菜单。零数据与查询失败分开。

### 5.2 变化与贡献

- 差额 = 本期 − 基线；增长率仅在基线 > 0 且口径可比时计算。
- 基线为零时说新增金额，不写增长无穷大或随意百分比。
- 分类增量贡献按金额拆解；有负贡献时可能抵消，某分类贡献占比可超过 100%，应说明抵消，不截断成漂亮比例。
- 优先级考虑绝对金额、持续性、可调整性和用户目标；不按百分比最高直接排序。
- 完整月对完整月可报总额变化，但要标天数差；评行为强度时补同口径日均/星期构成。月中不与完整上月直接下行为结论。

### 5.3 次数与每笔金额的拆分

当交易语义可比且各期笔数均大于零，令 N 为笔数、P 为每笔均值：

```text
总变化 = N1 × P1 − N0 × P0
次数贡献 = (N1 − N0) × (P1 + P0) / 2
每笔金额与构成贡献 = (P1 − P0) × (N1 + N0) / 2
两项之和 = 总变化
```

这是对“笔数 × 每笔均值”的对称算术分解，不是因果归因，也不证明商品涨价。不同商品/餐型混在一起时只能称“每笔金额与构成变化”；只有同商品/同规格证据才讨论单价变化。任一期无笔数则不做此分解。

### 5.4 趋势、异常与情景

- 两期只说明变化；三期或更多可比时点可描述连续同向，必须给时点数，短序列不宣称长期稳定规律。
- 异常优先相对个人可比历史，样本少时直接指出某笔较大，不输出无依据异常评分。
- 情景节省来自已核验的可调整项目、单价/次数与用户愿意接受的改变；同时列假设、代价与不确定性。不由模型生成目标金额后反推证据。
- 周末/工作日日均按相应自然日数计算；“有交易日均值”必须单独命名，不能混用。

## 6. 证据台账 EvidenceLedger

每条指标至少有：evidenceID、metricID、value、unit、currency、primaryRange、baselineRange、population/filter、denominator、sourceRefs、lineageID、calculationVersion、dataRevision、completeness、limitations。

例子数字不在本文件出现，真实指标在 `local-only/` 生成。指标存在不代表解释成立；同一批账单的总额、占比和均值是同一血缘，不能当作三份独立动机证据。

当前云端数值核验用 metricKey 与结果值，存在分组/口径绑定需要增强。新协议应优先绑定唯一 evidenceID 对应的指标、分组、范围与币种，不以“其他地方出现过同一个数字”作为该句核验通过的依据。不能放松现有核验来容纳新表达。

## 7. 个人处境 PersonalSituationBrief

每项字段：contextID、statement、sourceKind、sourceRefs、assertionStatus、validFrom/validTo、sensitivity、allowedPurpose、revision、relevanceReason。

状态：userStated / userConfirmed / inferred / disputed / expired。当前原话优先；确认背景可以影响取舍，inferred 只能作为待核对线索，disputed/expired 不作为当前解释依据。

选择顺序：会改变当前判断的目标/限制 → 相关事件 → 已试办法与用户纠正 → 相关历史观察。试点上限 8 条，不补满；不能触发后台补建完整人生档案。若不存在允许使用的背景，输入空数组并正常完成单域分析。

## 8. 结论与解释 InsightAssessment

| kind | 最低要求 | 示例表达边界 |
|---|---|---|
| fact | 指标或原始证据、明确范围和口径 | 本期增加主要来自已标项目 |
| pattern | 足够可比样本、范围、反例与记录限制 | 样本内多次出现，不能外推所有生活 |
| interpretation | 支持证据/确认背景、竞争解释、反例、改判条件 | 用户确认的临时安排可解释部分变化，保留其他可能 |
| recommendation | 支撑事实、用户目标或明确问题、限制、代价与适用条件 | 同意尝试后才连接行动 |
| limitation | 具体缺项及其影响 | 未提供收入，无法评价整体收支结余 |

每条有 id、displayText、evidenceIDs、contextIDs、status、scope、alternatives、counterEvidence、revisionTrigger。status 为 supported / tentative / contradicted / unresolved，不输出假装经过校准的“87% 确信”。旧 confidence 字段为协议兼容可保留，但不作为已测概率展示。

心理动机解释除了消费记录，必须有相关第一方表达等依据；即使有，也只表述用户表达和待核对的联系。多个无关数字不能替代心理证据。用户否定的解释记录为 disputed，不能只在句首加“可能”后继续使用。

## 9. 行动与回看

DecisionOption 至少有 actionID、title、rationale、evidenceIDs、goalRef、constraints、tradeoff、conditions、scenarioEstimateRef?、reviewPlan?。用户没有行动诉求时可为空。

ReviewAnchor 至少有：reportID、claimID、actionID、decision(adopted/deferred/declined)、execution(unknown/not_started/partial/completed)、adoptedAt、executedAt?、baselineEvidenceIDs、baselineRange、followUpRange、metricDefinitionVersion、dataRevision、contextRevision、reviewStatus。

“愿意试”不能写成“已执行”。指标下降不自动是成功：若用户重视便利或体验，要同时询问代价。执行情况未知时不推算效果；比较窗口遇旅行/收入变动等干扰时缩小解释。重测数据变更保留修订身份，不能每轮生成互不相干的新结论。

## 10. 服务端与客户端增量兼容

快照拟加可选 `analysisVersion`、`personalSituation`、`financeSemantics`、`datasetCoverage`；只在能力协商支持时发送。明确隐私开关，不能为了透传新字段将所有个人背景自动上云。

`financeSemantics` 最小装载清单（2026-10-17 试点实测增设；缺失时按 unknown 处理并限制对应结论，不猜）：

| 字段 | 语义 | 影响的结论边界 |
|---|---|---|
| timestampReliability | 各来源时刻为补录默认值的行数占比（如历史段 08:00 占比、00:00 行数） | 占比高时禁做夜间/时段推断（F10） |
| accountSemantics | collapsed（多账户已归并单一账户）/ native / unknown | collapsed 时禁账户级结论与"只有现金账户"推断 |
| mergedRowCount | 当日多笔合并行行数及识别方式 | 频次×均值分解须按合并数还原或排除 |
| reimbursementCategories | 补偿性收入类目清单（如「工资收入/退款」承载报销） | 结余/储蓄率结论须剔除或标注口径 |
| futureRowCount | 窗口外未来承诺行数（窗口上界=快照时刻，未来行不入窗） | 提示存在未入窗的分期承诺，防"近期无负担"误判 |

结果拟加可选 `assessments/decisionOptions/reviewAnchor/verification`。由统一答案适配器转换成既有 claim/类型化 recommendation 与补充说明；旧客户端只收到有依据的保守文本。完整迁移前保留现有字段和 schema，缺字段可解码，不重解析自然语言推断范围或建议等级。

`personalSituation` 的新结构只是已授权内容的任务投影，不另建长期事实库。确认/否定/遗忘写回现有个人情境与记忆体系；具体调用边界见实施任务。
