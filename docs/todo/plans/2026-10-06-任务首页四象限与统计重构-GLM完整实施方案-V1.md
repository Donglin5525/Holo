4. 统计页：可切换真实期间的新增、完成、按时率、趋势、清单分布及对应任务明细；当前待处理事项单独展示。

## 3. 产品规则：四象限是分类，不替用户安排时间

### 3.1 两个独立维度

重要性：

- `unknown`：暂未判断，进入待整理。
- `important`：重要。
- `notImportant`：不重要。

紧急判断方式：

- `auto`：按截止日期判断。
- `urgent`：用户手动指定紧急。
- `notUrgent`：用户手动指定不紧急。

“自动”是保存的判断方式，“当前紧急/不紧急”是随日期变化计算的结果。不要保存一份会过期的自动结果，也不要额外持久化象限编号。

### 3.2 自动紧急规则

每次解析注入同一个 `now` 和本地 Gregorian `Calendar`，时区跟随设备：

1. 通过 `TodoTaskDatePolicy.effectiveDueDate` 计算有效截止时刻。
2. 取 `todayStart = calendar.startOfDay(for: now)`。
3. 使用日历增加三天得到 `urgentBoundary`，即大后天 00:00。
4. 有截止时间且 `effectiveDue < urgentBoundary`，建议紧急；包括所有逾期任务、今天、明天和后天到期任务。
5. 大后天 00:00 及以后、无截止日期，建议不紧急。
6. 手动模式直接采用用户指定值，日期变化不覆盖手动选择。

自动不紧急不表示事情不重要；无日期的重要任务归入“留出时间”。

| 重要性 | 解析后的紧急程度 | 象限名称 | 引导 |
|---|---|---|---|
| 重要 | 紧急 | 优先处理 | 先推进这些事 |
| 重要 | 不紧急 | 留出时间 | 安排具体执行时段 |
| 不重要 | 紧急 | 集中处理 | 合并处理零碎事项 |
| 不重要 | 不紧急 | 稍后再看 | 按需要保留或归档 |
| 暂未判断 | 任意 | 待整理 | 判断这件事是否重要 |

重要性未判断时即使已经逾期，仍在待整理；行内显示真实逾期信息，“现在需要处理”的逾期列表也能找到它。

### 3.3 必须保持的独立性

| 操作 | 允许改变 | 不应随之改变 |
|---|---|---|
| 调整重要性/紧急方式 | 两个分类字段、`updatedAt` | 截止、时段、提醒、今日选择、完成、旧优先级 |
| 调整截止日期 | 截止、全天标识、现有提醒重排 | 重要性、手动紧急方式、时段、今日选择 |
| 自动紧急随日期变化 | 展示及分组结果 | 所有持久化字段 |
| 安排执行时段 | 计划开始/结束 | 截止、提醒、分类、今日选择 |
| 加入/放下今日安排 | Today 当日计划版本 | 截止、时段、提醒、分类、任务完成事实 |
| 完成/撤回 | 既有完成业务及必要子项/重复实例处理 | 新增分类和日期规则 |
| 归档/恢复 | 既有归档状态 | 完成时间、分类、历史记录 |

## 4. 任务首页：从总览进入行动

### 4.1 iPhone 页面结构

从上到下固定为：

1. 顶部返回与标题“任务”，右侧搜索、更多。
2. 标题下范围菜单：默认“全部未完成”，可看到当前范围名称。
3. 紧凑 2×2 象限总览。
4. 一行待整理入口。
5. 四个象限的分组任务列表，之后可放待整理任务组。
6. 底部任务、统计、纪念日、新增入口。

删除任务首页顶部的大幅今日进度卡；今日推进属于 Today 和统计，不挤占任务总览首屏。删除横向堆叠的范围胶囊。不要把任务模块改成四列塞满任务的棋盘。

正常字号下 390×844 首屏应看到四象限全部数量、待整理入口及至少三条完整任务行。这里的“三条”按实际安全区、导航和底部操作占位验收，不隐藏系统栏来凑数。超大字号以完整操作和阅读优先，不强求同样首屏条数。

### 4.2 范围菜单

| 范围 | 纳入任务 | 页面模式 |
|---|---|---|
| 全部未完成 | 未删除、未归档、未完成 | 四象限与待整理 |
| 今天到期 | 上述任务中截止日期属于本地今天 | 同上；与“已加入今日安排”有别 |
| 逾期 | 上述任务中有效截止时刻早于现在 | 同上；保留现有逾期入口 |
| 收件箱 | 上述任务中没有清单归属 | 同上；与“未判断重要性”有别 |
| 指定清单 | 上述任务中归属该有效清单 | 同上 |
| 已完成 | 未删除、未归档、已完成 | 历史连续列表，按完成时间降序 |
| 归档 | 未删除、已归档，可含完成或未完成 | 归档连续列表，按更新时间降序 |

历史范围不显示“当前四象限待办总览”或“开始整理”来误导用户；详情仍能看到已有分类，恢复后可重新参与当前分组。没有完成时间的已完成任务放在列表末尾，明确“完成时间未记录”。

清单管理、归档、提醒设置、已有排序入口保持可达：清单管理放在范围菜单末尾；提醒设置放在更多；归档在范围菜单与更多都可进入。纪念日等原有深链继续由原容器路由。

### 4.3 象限点击、计数与分组

- 象限数量只统计**当前范围**的活动未完成任务；待整理不混进四个数量。
- 四个数量加待整理数必须等于当前范围活动任务总数。
- 完成撤回窗口内，首页行和计数采用同一份 pending 展示投影，暂时移出待办并同步减少相应数量；撤回恢复该投影。真实任务与统计快照在确认前不变，不能为动画提前写库。
- 默认四组按“优先处理、留出时间、集中处理、稍后再看”显示；每组先显示三项，剩余用“展开全部 · N 项”。展开后可“收起”。
- 组内默认有效截止升序，无截止放末尾；再按创建时间升序、UUID 字符串稳定排序。
- 旧排序偏好保持兼容入口，选择后只改变组内顺序，不改变象限判定。不要用旧优先级改变四组顺序。
- 点一个象限后仅显示该组全部任务，顶部出现“返回全部象限”。再次点该象限也可返回。
- 当前组为空时显示明确空态及“在此添加任务”；添加预填此象限。
- 切换范围清除象限选择及展开状态；当前访问内保存各范围滚动位置即可，不把细碎状态写到 CloudKit。
- 分类变化导致任务移出当前组时，显示“已移至『…』”和可点击“查看”；不要把成功保存看成数据消失。

### 4.4 任务行

行内只保留：完成按钮、任务标题、截止信息与清单、更多入口。

- 标题为阅读主角，正常 17pt，最多两行；长标题详情可完整读取。
- 无截止显示“未设截止日期”；全天只显示自然日，不展示内部 23:59:59。
- 今天、明天、后天采用自然语言；具体时刻截止附上时间；逾期追加“已逾期”。
- 清单无归属显示“收件箱”。已有来源、附件、检查清单、分步推进进入详情。
- 点击标题/行主体进入详情；完成按钮和更多独立，点击不触发详情。
- 更多包含调整轻重缓急、修改截止、安排时段、加入/放下今日、归档及已有删除入口。
- 不依赖左滑、长按或拖动才能发现关键动作；已有手势可继续作为快捷方式。

### 4.5 搜索、导航、初始偏好

- 搜索直接可达，搜索未删除任务，包含已完成和归档；结果按状态分段/标识，明确“搜索全部任务”。
- 默认搜索标题、描述、当前有效清单名称；搜索不修改首页范围，也不改变四象限计数。
- 零结果显示查询词与清除入口，不能显示整个模块没有任务。
- 使用新首页范围偏好键：首次升级默认全部未完成，不照搬旧版默认今日；此后保留用户选择的活动范围。
- 已完成/归档为临时历史访问，下次冷启动默认全部未完成，避免误以为没有待办；清单不存在则回到全部。
- 从任务/纪念日深链、通知和来源想法进入的路线保留；不要为轻量新增切断现有详情初始化入口。
- 底部导航在弹层关闭后恢复当前页面；统计页点新增保存后切到任务并定位新增记录。

## 5. 添加任务：四象限逻辑必须在页面上可见

### 5.1 结构与默认状态

普通新增使用独立轻量原生弹层，不再把全部详情字段一次铺开：

1. 标题“添加任务”，取消按钮。
2. 标题输入“想做什么？”；打开后直接可输入。
3. 重要性：**重要 / 不重要 / 暂未判断**，普通默认暂未判断。
4. 紧急程度：**按截止日期 / 紧急 / 不紧急**，普通默认按截止日期。
5. 一行解释当前判断依据。
6. 截止日期（可选），设置后可清除；支持全天/具体时刻的原生日期编辑。
7. 折叠区“清单与描述”；高级设置入口保留提醒、重复、标签、检查清单、附件及已有来源信息能力。
8. 底部持续可见的归属预览“将进入『…』”和主按钮“添加任务”。

只有标题是必填项。标题空白禁用保存，提交时再次验证去除首尾空白与换行后的标题，不能空串写库。不人为新增更短长度上限；与现有输入约束保持兼容。

| 今天到期范围新增，未选象限 | 暂未判断 | 自动 | 今天全天 | 收件箱/既有明确清单上下文 |
| 今天到期范围内选象限再新增 | 继承象限 | 继承象限手动方式 | 今天全天 | 同上 |
| 统计/已完成/归档内新增 | 暂未判断 | 自动 | 无 | 收件箱 |
| 其他模块既有日期/清单明确入口 | 暂未判断 | 自动 | 保留原明确上下文 | 保留原明确上下文 |

保留已存在“今日入口预填今天截止日期”的便利，但字段明示且可取消；**点击加入今日安排不适用这一预填规则，更不能自动写今天截止。**

来自象限时，在重要性上方显示“来自『留出时间』，已预填分类，可调整”。从象限新增采用手动紧急方式，确保没有截止日期也可保持所选象限，不悄悄伪造一个截止日期。

### 5.3 动态归属与提示文案

预览使用与首页同一个解析器；重要性、紧急方式、日期/时间一有变化就重新计算，不等待保存：

- 暂未判断：**将进入『待整理』**；“先记下来，之后再判断重要性。”
- 重要＋自动＋无日期：**将进入『留出时间』**；“未设截止日期，暂按不紧急判断。”
- 重要＋自动＋后天到期：**将进入『优先处理』**；“后天到期，按日期建议紧急。”
- 不重要＋手动紧急：**将进入『集中处理』**；“紧急程度已手动指定。”
- 重要＋手动不紧急＋逾期：**将进入『留出时间』**；“手动指定不紧急；截止日期已经逾期。”

归属预览是反馈，不是第五个需要用户选的字段。颜色仅辅助，文字必须明确。选择“暂未判断”不能自动落入“稍后再看”。

更换选项不得丢标题、日期、清单、描述、附件或高级字段；不得重建表单、失去输入焦点、收起键盘或把滚动拉回顶部。切到手动紧急后仍可改日期，但仅改日期不改变手动方式。

### 5.4 保存、取消与失败

- 一份草稿承载全部字段，保存一次创建任务及可选检查项/关联；保存过程防重复点按。
- 预填上下文本身不算用户编辑；空白草稿直接关闭。标题或其他字段已被用户改动时，取消沿用现有未保存提示。
- 高级设置编辑同一份草稿，不能先创建空任务再用详情补字段。
- 保存成功后才关闭；显示“已添加到『优先处理』/『待整理』”。
- 新任务不属于当前范围时切到全部；不属于当前象限时清除象限选择。展开相应任务组并定位刚创建的 UUID，避免组内前三项截断使其不可见。
- 保存失败保留草稿，提示“没有保存成功，请重试”，可重试原操作；检查未保存的插入对象，避免第二次生成重复任务。
- 新增的本地操作 UUID 在同一次草稿重试中保持不变，可在视图提交层防重；不为此另加一套 CloudKit 任务身份字段。
- 键盘出现后保存和预览在键盘上方可操作；小屏/超大字号允许预览折行，输入区域滚动。不能设置忽略键盘安全区导致保存按钮被遮住。

## 6. 连续整理、详情及独立行动

### 6.1 连续整理

- 待整理入口显示当前范围数量；数量为零显示“已整理”，不制造强制提醒。
- 点击“开始整理”，冻结当前范围未判断重要性的 UUID 队列；按首页组内默认规则排序。
- 显示标题、截止、清单、描述摘要、当前位置“第 2 / 8 项”，以及重要性与紧急方式。
- 主动作“保存并继续”，次动作“先跳过”；保存要求用户选择重要或不重要，跳过不写数据。
- 默认保留任务原有紧急方式。自动模式解释建议，手动模式明示来源，允许切换。
- 保存成功才进入下一项；失败停留并保留本项选择。队列中的任务被删除、归档、完成或被其他设备整理后，重新读取并跳过，不写失效对象。
- 新进入待整理的任务不插入当前冻结队列，下一轮处理；防止队列越整理越长。
- 用户可随时关闭；已经保存的保留，当前未提交的选择放弃。结束显示本轮整理/跳过数量与“返回任务”。
- 单项分类失败恢复该任务操作前字段，禁止对整个共享主上下文 `rollback()` 撤销其他模块在途编辑。

### 6.2 详情

在现有详情基础上调整层级，保留已有功能和来源跳转：

1. 标题、描述。
2. “轻重缓急”：当前象限/待整理＋“按日期判断”或“手动指定”。点击编辑两个维度。
3. “截止日期”：独立编辑/清除，支持全天和具体时刻。
4. “执行时段”：独立安排/取消。
5. 所属清单、今日安排。
6. 检查清单、分步推进、提醒、重复、附件、标签、来源等现有内容。
7. 完成、归档/恢复与已有删除操作。

旧 `priority` 不再是新首页和新增的主分类控件。旧任务在详情的兼容信息中可看到“原优先级：高；重要性待判断”。需要保持其他模块调用时，在高级设置保留旧优先级编辑，明示“原优先级”，不要把它伪装成四象限。

详情已有整体保存流程需纳入新字段的变更判断。打开分类子弹层后，选择先写详情草稿，点击确定回到详情；沿用详情现有保存时点，不能一部分自动落库、一部分关闭后悄悄丢弃。首页更多的直接分类弹层则有独立“保存”动作。两者都通过同一仓库接口。

### 6.3 安排时段

- 复用 `plannedStart/plannedEnd`，成对保存或成对清空；开始早于结束且在本地同一天。
- 提供日期、开始、结束；不支持跨天伪造合法值。非法时段在字段附近解释，不能闪退。
- 保存仅修改时段，并显示结果；不调整截止、不自动改象限、不自动加入 Today、不创建系统日历事件。
- 当前待处理中的“重要但未安排时段”只指没有合法成对时段的活动重要任务；已有合法的过去时段也属于曾安排，不在本版偷偷扩展为“需要重新安排”。
- 部分字段缺失或时段非法按未安排处理，详情提示检查原记录；不要读路径悄悄补时段。

### 6.4 今日安排

读取当前真实 `HoloTodayDayScope`、计划 heads 和状态：

- 未加入时通过 `HoloTodayPlanService.addTask` 加入，默认目标 `.taskResult`。
- 已有当日目标为某个步骤时显示既有目标；再次加入不把它重置为整项完成。
- 放下/移出复用 `deferTask`；涉及既有截止约束确认时沿用 `HoloTodayDeadlineAcknowledgement`，不给它自造另一种含义。
- `syncing/unavailable/conflict` 不得当成空计划覆盖；说明当前状态，提供已有冲突处理或重试入口。
- heads 变化后刷新让用户重试原动作，不自动重放旧快照覆盖另一设备的选择。
- operationID 在单次操作重试中保持稳定，提交成功后更新状态。
- **禁止调用 `TodoRepository+Kanban.planTask(_:for:)` 来加入今日，因为它会写截止日期。**

### 6.5 完成、撤回、重新打开、归档

- 列表、详情、统计明细的完成按钮统一调用 `HoloTaskCompletionCoordinator`。
- 三秒内显示暂时完成视觉与撤回入口；真实 `completed/completedAt` 未提交，期间统计保持已保存事实，可显示“有一项完成待确认”。撤回后列表恢复、统计无虚增。
- 三秒后提交成功才更新统计和清单分布；失败恢复可操作状态并说明失败，不能弹成功文案。
- 连续完成遵循现有协调器：开始另一项会显式确认上一项，当前项获得三秒窗口；不要实现第二个计时器。
- 从统计明细完成时，撤回条必须位于当前可见弹层内；跨页面只能呈现一个有效撤回动作。
- 重新打开已完成任务走原仓库完成切换，清除完成事实按现有契约执行；期间完成统计随最新记录减少。不要保留一个与真实状态矛盾的假完成次数。
- 重复任务下一实例具有新 UUID，继承本项重要性及紧急方式；自动方式依新截止重新计算，手动方式保持。撤回未提交时不生成下一实例。
- 归档的完成任务保留历史统计；归档未完成任务离开当前待处理。恢复不重置分类、截止或完成时间。

## 7. 统计产品方案与精确口径

### 7.1 页面问题与顺序

页面依次回答：

1. **这段时间推进了多少？** 期间选择、具体范围、新增/完成/按时完成率。
2. **任务是否越来越难处理？** 新增与完成双系列趋势、规则可核对的观察、完成来自哪些清单。
3. **现在有哪些事需要调整？** 当前逾期、重要未安排、待整理，明确“截至现在”。

统计默认覆盖全部未删除任务，不跟随任务首页的清单/象限筛选。页面明确“全部任务”，避免首页在某清单时误以为统计也只看该清单。本版不再增加一套统计清单筛选。

### 7.2 周期与日期范围

- 默认本周，周一为一周开始；本月、今年/本年、自定义。
- 始终展示完整日期，例如“2026年10月5日—10月11日”；进行中周期补“截至10月6日15:30”。
- 周/月/年左右箭头切换上一/下一自然周期；不能进入尚未开始的完整未来周期。
- 自定义开始和结束为含首尾自然日，结束不得晚于今天，开始不得晚于结束；错误就地说明。
- 内部 `start` 为开始日 00:00、`endExclusive` 为结束日之后一天 00:00；时间字段判断 `>= start && < endExclusive`。
- 当前周期再用同一个 `asOf` 限制事件 `<= asOf`，不将未来时间记录统计为已发生。
- 自定义前后切换同等自然日天数，下一范围完整结束晚于今天时禁用；可改选新范围。
- 使用日历加天/月/年；禁止以 86400 秒乘天数推日期。Locale 用中文，时区用设备当前值。
- 统计日历明确 Gregorian、`firstWeekday = 2`、`minimumDaysInFirstWeek = 4`、当前设备时区；不能依赖地区默认周起始日恰好为周一。
- 日期范围更改后，数字、对比、趋势、清单分布及明细 query 一起重算。禁止图表换日期而数字未换。

### 7.3 统计共同事实源

先读取任务记录，再使用项目当前规范的稳定 UUID 副本去重，得到唯一任务集合。以下所有指标和明细从同一集合派生：

- 使用 `DuplicateRowFilter` 的稳定物理行选择语义；不能照搬 HTML 的同 ID 最后一条覆盖。
- G1 用真实临时 SQLite `objectID` 验证物理行解析及选择稳定性，不能只相信工具注释。若不能稳定选出规范行，修复统一选择器并回归其现有消费者，不在统计里另造 last-wins；写入口按 UUID 获取同一规范副本。
- 应在状态与时间条件过滤前确定同 ID 的唯一记录，避免一个副本已删除、另一个仍活动而被误计。
- 删除状态复用当前统一 `deletedAt` 契约，兼顾 `deletedFlag` 遗留状态：任一标记为删除均不进入本版统计/列表；不在读路径自动恢复。
- 根 `TodoTask` 每个 UUID 计一项；`CheckItem`、execution step、receipt 不计独立任务。独立重复实例是独立任务，不同 UUID 正常计数。
- 历史期间新增、完成和按时率包含已归档任务；当前待处理不包含归档。
- 排除已删除记录意味着用户删除/恢复任务会改变历史期间统计。这是基于当前保留数据的回看，不承诺不可变历史账本。
- 清单归属使用任务当前保存的清单，不宣称为完成时的原清单；挪清单会改变历史分布。
- 清单被删除/同步未达时归“未归属清单”桶，普通 `list == nil` 归收件箱；不读取已删除清单的名称冒充有效归属。已归档但未删除清单仍保留名称并可标记归档。

### 7.4 新增和完成

```text
新增集合 = 唯一未删除任务中，createdAt 落在所选期间且不晚于 asOf 的任务。
完成集合 = 唯一未删除任务中，completed == true，completedAt 有值，
           completedAt 落在所选期间且不晚于 asOf 的任务。
新增数 = 新增集合大小；完成数 = 完成集合大小。
```

完成数不是“本期新增中完成多少”，也不是“本期到期中完成多少”。上月创建、本周完成的任务计本周完成，不计本周新增。无截止的任务可以计新增、完成。

完成时间缺失的已完成任务不能用创建时间、更新时间或今天补齐：排除期间完成统计，并说明“有 N 项已完成任务缺少完成时间，未计入期间完成统计”。这里 N 为当前全部未删除的已完成缺失记录数，**无法归属具体期间**，说明该边界；可点开缺失记录列表。

不开展未经确认的历史时间批量回填。时钟异常导致未来完成时间的记录不计已发生事件，并留可查的异常数量，不把它们当缺失时间。

### 7.5 按时完成率：同一批到期任务的结果

候选到期集合 D：唯一未删除任务中，有有效截止、有效截止位于所选期间，并且 `effectiveDue <= asOf`。

缺失完成时间集合 X：D 中 `completed == true && completedAt == nil` 的任务。

有效分母 E = D 排除 X。未完成但已经到截止的任务必须留在分母。

按时集合 O：E 中 `completed == true`，且 `completedAt <= effectiveDue`、`completedAt <= asOf`。

```text
按时完成率 = |O| / |E|，仅 |E| > 0 时有数值。
|E| == 0 显示「—」，不要显示 0%、100% 或强塞分母 1。
展示实际分子/分母，例如「3 / 5 项按时完成」。
```

- 刚好在截止时刻完成算按时；超过算延迟；完成在本期之前但截止在本期已成熟，仍可计按时。
- 全天今天的截止尚未到时，不进入分母；有具体时刻且该时刻已过则进入。
- 无截止、未来到期，不进入分母；不能据此说它们“未按时”。
- 分母永远与分子是同一任务集合，不能用期间完成数除以期间到期数；比例不能超过 100%。
- 明示 X 数量及排除原因；点按时率打开 E 明细，同时提供 X 的独立查看入口。
- 规则说明固定包含：“依据当前保存的截止日期计算，修改截止日期可能影响历史结果。”
- 不称为最初承诺履约率，不暗示保留了改期历史。本轮不增加截止历史版本表。
- 本版按时率不做上一周期百分比对比，避免成熟任务队列差异混淆。

### 7.6 未结束周期的比较窗口

新增/完成指标显示与上一周期**同等已过窗口**的数量差值，不能把本周两天与上周七天比较：

1. 已结束周期：当前完整自然周期 vs 上一完整自然周期。
2. 未结束周期：当前 `[start, asOf]` vs 上一自然周期起点后的同等本地日历经过窗口。
3. 取当前起点到 `asOf` 的完整自然日天数，再取当天小时/分/秒；在上一周期起点加相同自然日和日内时间。
4. 若上个自然周期更短，比较终点截到上个周期结束，并明确“上期较短，对比至上期结束”；不假装等长。春节/闰年/DST 用注入日历计算。
5. 自定义区间用紧邻之前的等自然日长度窗口；今天尚未结束时也按同等已过窗口比较。
6. 上期为 0 时显示“较上期多 N 项/少 N 项/持平”，不显示无穷增长率。本版统一用数量差，不做百分比增长。

例如现在周二 15:30：本周一 00:00 至周二 15:30，与上周一 00:00 至上周二 15:30比较。图表仍展示所选完整自然周期，未来日期用未到来状态区分。

### 7.7 新增与完成双系列柱状图

- 周、月按日；年按月；自定义自然日数 ≤31 按日，否则按月。
- 月桶必须与选择范围相交，跨月自定义首尾桶不能带入范围外事件。
- 每个桶的新增/完成必须来自上述两个集合，桶合计分别等于指标总数。
- 新增用低饱和暖橙，完成用低饱和绿/青；保持固定图例及文字，不只靠颜色辨认。
- 正整数刻度、Y 轴从 0 起；无数据不画假趋势。数据密集时横向滚动或稀疏标签，不把柱子压成不可点击细线。
- 未来桶显示“未到来”，不能呈现为已经发生的零完成；今天桶标“截至现在”。
- 点桶展示该桶新增、完成两个数及对应任务，提供“新增/完成”明细切换。
- 若合并显示任务，同一 UUID 仅一行，但可同时带“本桶新增、本桶完成”两种标识；合并行数不要求等于两个指标之和。
- 提供“查看趋势明细”入口及 VoiceOver 可读日期/两组数量，无须精确点中某根柱子才能核对。
- 不让图表横向选点拦截页面纵向滚动。

### 7.8 本期完成来自哪些清单

- 按完成集合任务当前的有效清单 ID 分组，显示清单名、完成数量、占比和横条。
- 数量降序；同数量按清单名称/稳定 ID，收件箱和未归属桶也有明确名称。
- 分布数量合计必须等于完成数；同名但不同 UUID 清单不能合并。
- 占比以完成数为分母；展示百分比四舍五入可能合计 99%/101%，数量才是核对依据。零完成显示空态。
- 点击清单行打开同期间完成明细，不跳到当前未完成清单列表冒充统计来源。

### 7.9 可核对观察与当前待处理

期间观察仅由确定规则生成：

- 新增比完成多： “本期新增比完成多 6 项，可以回看哪些事情需要继续推进。”
- 完成比新增多： “本期完成比新增多 4 项。”
- 相等： “本期新增与完成数量相同。”
- 双零： “这个期间还没有新增或完成记录。”

不要把两数之差命名为“积压增加/减少”：归档、删除、重新打开及跨期任务使其不等于真实积压变化。本版不增加虚假的效率评分、AI 鼓励或生产力排名。

“现在需要处理 · 截至现在”读取同一个快照时刻的活动任务：

| 项目 | 规则 | 行动 |
|---|---|---|
| 当前逾期 | 未完成、未归档、未删除，effectiveDue < asOf | 打开逾期任务，改期/完成/安排/归档 |
| 重要未安排 | 活动任务 importance == important，没有合法成对时段 | 打开列表，直接安排时段 |
| 待整理 | 活动任务 importance == unknown | 查看列表，开始连续整理 |

三组可能重叠，不能把它们相加为任务总数。切换历史周期后这些数不随周期变化；页面仍显示真实“截至现在”时间。

### 7.10 明细与快照一致性

- 数字、柱子、清单都存 query/UUID 集合，明细从同一聚合结果生成，不能另外拼一个不同谓词。
- 明细显示范围、纳入依据及行数；按时率行显示截止/完成时间与“按时、延迟、未完成”。
- 单纯打开明细保持原快照；有任务保存/完成/归档/删除或云端合并时，刷新整页和明细的同一新快照，并标明数据已更新。
- 快速切换日期时旧异步响应不得覆盖新选择；用请求版本或取消旧请求保证最新请求生效。
- 返回详情/明细后保留原周期与滚动位置；不自动重置本周。

## 8. 数据模型、兼容与迁移

### 8.1 新字段（本版唯一新增任务持久化字段）

在程序化 `TodoTask` 实体与 `@NSManaged` 属性两端同步增加：

| 字段 | 类型 | 默认 | 取值 |
|---|---|---|---|
| `importanceRaw` | Int16 | 0 | 0 unknown；1 important；2 notImportant |
| `urgencyModeRaw` | Int16 | 0 | 0 auto；1 urgent；2 notUrgent |

沿用当前 Int16 属性“非可选＋明确默认值”的模型约定，满足项目 CloudKit 的可选/默认要求。完整校验以实际 CloudKit schema 验证结果为准，不只看 Swift 类型。

- 新建 Swift 枚举 `TaskImportance`、`TaskUrgencyMode` 和只读 `TaskQuadrant`（含 unclassified）。
- `TodoTask` 计算属性集中转换 raw；未知 raw 读取为 unknown/auto，并记录非正文诊断，不崩溃、不批量改写。
- `priority`、`status`、全部现有字段与关系保留，不能重命名/改类型来借壳存分类。
- 不增加 Core Data uniqueness constraint，不改变 task UUID，也不移动 App Group store 路径。
- 不存 `quadrantRaw`，避免与自动日期判断产生两份事实。
- 两字段由现有 Core Data/CloudKit 同步；UserDefaults 只能放页面偏好，不能存真正任务分类。
- 需要扩充现有 Codable DTO 时新字段用兼容缺省解码，旧载荷不存在字段时仍能读取；未知枚举显式容错。不要给财务 `HoloBackup` 塞两个任务字段就称为任务备份。

### 8.2 写入契约（拟新增接口，非当前已存在）

以下为参数契约示意，不是可直接复制编译的完整文件；实际方法应结合当前声明补齐。

```swift
enum TaskImportance: Int16 { case unknown = 0, important = 1, notImportant = 2 }
enum TaskUrgencyMode: Int16 { case auto = 0, urgent = 1, notUrgent = 2 }

// createTask / TodoTask.create 新增有默认值参数，旧调用者保持源码兼容。
importance: TaskImportance = .unknown
urgencyMode: TaskUrgencyMode = .auto

// updateTask 新增可选参数；nil 表示不修改，unknown/auto 是明确设值。
importance: TaskImportance? = nil
urgencyMode: TaskUrgencyMode? = nil
```

- 普通新增一次保存标题、两轴、日期、清单和可选内容；禁止先调用 createTask 落库再写分类二次保存。
- 变更广播与提醒调度应在保存成功后发生；保存失败不留下未保存任务的提醒。新入口不得绕过现有仓库自行调度一套通知。
- 分类直接操作可以封装 `updateTaskClassification(taskID:importance:urgencyMode:)`，内部委托现有仓库一次保存和变更通知。
- 操作前按 UUID 重新获取同一规范副本，验证未删除、可编辑状态；不要把失效托管对象跨异步闭包。
- 两轴变化只发送必要任务数据变化，不触发截止变化、通知重排、完成或延期计数。
- 保存失败恢复本次操作改动或使用隔离写上下文；不能吞错，也不能回滚整个共享上下文。
- 原有截止 `.set/.clear`、清单 `.set/.clear`、计划时段 `.set/.clear` 明确更新意图继续使用；不能把 `nil` 混用为清除与未改。

### 8.3 旧数据与其他任务创建入口

- 旧记录新字段默认 unknown/auto，全部可见，可渐进整理；不给旧高优先级偷偷设为重要。
- 不要求启动时全量写回旧任务，不因模型增加而更新全部 `updatedAt`、发送成百上千通知或 CloudKit 写入。
- AI、想法转任务、目标、Matter、纪念日自动生成、Today 空态新建等现有入口：未明确包含两个新维度时默认 unknown/auto；原优先级与日期照原约定保留。
- 低层 `TodoTask.create` 也明确设新默认值，覆盖绕过 `TodoRepository.createTask` 的创建路径。
- 重复下一实例显式传入原任务两维，不因调用默认值丢失分类；小组件完成路径共用同一逻辑。
- 系统通知、App Intent/小组件只用原操作创建或完成，不通过优先级推断新重要性。
- 本轮不改 AI Prompt 把模型优先级映射过来；未来若增加 AI 建议，仍需用户确认，并另立协议及验收。

### 8.4 模型升级硬要求

当前模型是运行时组装，打开 `NSInferMappingModelAutomaticallyOption` 不代表旧源模型一定可找到。G1 必须交付可验证的源/目标模型及兼容迁移链：

1. 冻结本次变更前的模型构造与实体 version hash，确认覆盖实际待升级构建，而不是只覆盖当前未发布工作区。
2. 将所需旧源模型保留为可匹配的版本化模型资源或等价的明确源模型构造；目标模型只增加两属性，其余模型定义保持对应关系。
3. 在隔离 SQLite store 上由旧模型写入 fixture，再由新模型迁移打开；校验 ID、行数、关系、附件引用、日期、完成时间、旧优先级全部保留。
4. App 与所有读取该 App Group store 的扩展必须用同一目标模型；小组件先后启动都要验证，不允许不同模型指纹交替触发恢复。
5. 本次升级模型不匹配/迁移失败必须终止加载并进入现有可恢复失败 UI，原 store 留在原地；**不能借当前自动冲突恢复分支重建空库再称迁移成功。** 只针对此迁移门禁收口，不趁机改造所有历史恢复策略。
6. 孤立迁移验证失败可继续做纯逻辑/页面开发，但禁止将新模型装到东林日用设备或日用 CloudKit 数据环境。
7. CloudKit schema 仅增量验证/发布；Development 是东林实际日用数据，禁止 Reset、清空、批量删记录。正式 schema 发布与安装验收包按实际授权范围执行。

### 8.5 备份与旧版本边界

- 按仓库规则，动实际日用模型前提醒东林导出。**当前财务 JSON 不覆盖任务，也没有对应完整恢复入口，不能把这一步当作任务保护完成。**
- GLM 应先核对是否有本次读取之外的完整备份能力；若没有，使用经过验证的、包含 SQLite/WAL/SHM、CloudKit 元数据及附件的完整本地保护流程，并在隔离位置验证恢复读取。
- 不在 App/小组件仍写库时随手复制单个 SQLite 文件作为备份；不通过重置云端补救。具体备份/恢复路径要在 G0/G1 记录并验证，不向源码提交个人备份。
- 新版本 UI 回退时仍保留目标模型与新增字段。迁移后直接安装旧二进制读取新 store 的安全性尚未证实，不能作为默认回退方案。
- 旧版本跨设备仍可能写旧优先级或日期，但不会主动理解新分类。必须以双版本兼容测试确认它不会清除新字段或重建 store；失败则明确要求相关设备同步升级，不能宣称无条件兼容。
- 不为此扩大为全模块备份产品重构；如缺少可信的数据保护导致真实安装无法进行，明确报告这一安装门禁，纯逻辑与隔离测试继续推进。

## 9. 实现结构与刷新策略

### 9.1 单一计算链

```text
Core Data TodoTask（同一源模型、当前保存事实）
  → 唯一副本选择 + 删除/归属规则
  → TaskRecordSnapshot（不可变值，统一 asOf/calendar）
      ├─ TaskQuadrantResolver → 首页计数/分组/新增预览/详情
      └─ TaskAnalyticsAggregator → 指标/趋势/清单/明细 UUID/当前待处理

用户命令 → 草稿/明确更新意图 → 既有 TodoRepository / Today 服务 / 完成协调器
       → 保存成功 + 既有数据变化通知 → 重新构建同一快照
```

### 9.2 建议职责

| 类型（拟新增） | 职责 |
|---|---|
| `TaskQuadrantResolver` | 纯规则，注入 now/calendar，解析紧急依据与象限 |
| `TaskExperienceSnapshot` / `TaskRecordSnapshot` | 可跨队列纯值，不暴露 NSManagedObject，保存 UUID/可显示事实 |
| `TaskAnalyticsPeriodResolver` | 周/月/年/自定义、对比窗口、桶边界 |
| `TaskAnalyticsAggregator` | 用一份唯一任务集合生成完整统计快照和 query 结果 |
| `TaskAnalyticsService` | 在正确 context 队列读取；去重、快照、错误传递、请求版本 |
| `TaskExperienceViewModel` | 首页范围/象限/展开/搜索及页面操作，不再各 View 独立计数 |
| `TaskStatsViewModel` | 期间选择、加载/失败/最近快照、明细查询 |
| `TaskCreationDraft` | 新增/高级设置共用草稿和上下文，无提前落库 |

旧 `StatsPeriod` 与其他模块的日期类型容易同名，使用新的 `TaskAnalyticsPeriod` 明确语义，不继续扩充一个全局含糊枚举。上述名称是建议落点，已有等价类型可复用，但不得产生两套象限规则或两套统计口径。

### 9.3 读取、性能与一致性

- `context.perform` 内读取与去重，再转纯值；不跨 actor 传递 `TodoTask`/`TodoList`。
- 活动首页快照和历史统计可以复用任务值源；确保一次统计请求使用同一 asOf 与版本，不能分别数三次取出三个时间点。
- 先保留同 ID 规范副本再过滤；通过批量读取避免明细 N+1 查询。以 1,000/10,000 任务 fixture 检查，不以真实生活数据制造压力测试。
- 纯聚合可在后台处理；不要在 SwiftUI `body` 中反复 fetch、全量排序或计算全年图表。
- 数字和 UUID 集合共存于同一结果；同一按时率明细不是另一条独立 SQL。
- 详情操作重新读取当前任务，处理 deleted/archived 等状态变化；不使用旧对象强行写入。
- 已有 repository 变更、Core Data 合并/远程变更、Today 计划变化均触发相应刷新。仅监听本机按钮点击不够。
- 前台恢复、系统日期变化、时区变化刷新；午夜重新计算自动紧急，具体截止时刻到来时刷新逾期/成熟分母。
- 设置下一相关时间边界触发刷新；前台恢复兜底，避免每秒轮询整个仓库。每个请求使用一个冻结时钟。
- 发布最新请求版本，旧请求结果丢弃；保存/刷新并发时不要造成统计数字短暂倒退。
- 第一版仅做内存快照缓存和请求合并，不增加一张持久化统计汇总表，也不引入新的后端查询。

### 9.4 加载、失败、空态

- 首次读库期间显示结构清楚的加载态，新增在仓库就绪后可用；不显示假 0。
- 已有快照时刷新不清空页面；失败保留上次结果，显示“更新失败，以下为上次数据”，可重试。
- 一次聚合读取失败不能返回空数组伪装为无数据；旧 helpers 的 `try? → []/0` 行为不用于新统计主链。
- 任务全空：四格 0、无任务文案、添加入口；所选象限空、清单空、搜索无结果采用各自空态。
- 期间零数据仍保留日期选择及当前待处理；按时率无分母显示“—”。
- 单项写入错误保留草稿/选择；禁止 toast 成功后才暴露实际保存失败。
- 原型外的演示控制区不带到真实产品。原生 fixture/seeder 仅隔离测试构建启用，不能写入用户 CloudKit。

## 10. 视觉、适配与无障碍

### 10.1 视觉落地

- 复用现有 `holoToolBackground/Surface/Text/TextSecondary/Border/Action` 和 V2 文字角色；避免全局替换已有品牌色。
- 标题正常基准 28pt，任务正文 17pt，辅助 13–15pt；用可缩放角色实现，禁止所有字体写死。
- 页面正常边距 20pt；小屏和分栏根据可用宽度适配，不把 HTML 手机壳尺寸抄成固定 frame。
- 象限只放标题、数量和一行引导；背景浅暖红、浅绿、浅暖金、浅灰紫辅助区分，主文字仍为高对比深色。
- 象限颜色新增局部语义 token/颜色资产并提供 Dark 值；主动作保持品牌橙，不做四个高饱和抢眼按钮。
- 连续列表靠分隔与留白，不给每个任务大圆角、渐变、阴影和一串徽章。
- 已有容器用 `.continuous`，独立区域用合适的 `.holoSurface`；图表按照现有 V2 图表规范，右侧 Y 轴、轻网格、固定图例。
- 主动作、选中态、错误态可辨识；文字与背景一般 ≥4.5:1，大文字 ≥3:1，不能仅通过浅色文字区别选中。

原型象限色值如下，用于局部颜色资产参考，实际对比度需原生核对；不要把 hex 散写进各个 View：

|---|---|---|
| 优先处理 | `#A74532` / `#F8E9E3` | `#F0A48E` / `#3C2927` |

| 集中处理 | `#876321` / `#F7EFDD` | `#DDC07E` / `#383222` |
| 稍后再看 | `#646876` / `#EEEDF2` | `#C4C3D4` / `#30303D` |

### 10.2 尺寸与输入

- 所有关键点击区域至少 44×44pt；小图标可小，实际触摸区不能小。
- 320pt 宽度无横向页面溢出；普通字号四象限 2×2，辅助文案可折行。
- 辅助功能大字号时象限/指标允许单列或重排；完整显示名称与操作，不用缩小字体强保 2×2。
- 新增选项在超大字号下可转纵向按钮，语义和选中状态一致。
- 弹层中间滚动，底部通过 safeAreaInset 管理；横屏、键盘、软硬键盘切换可正常操作。
- iPad/宽屏保留既有分栏能力：左侧范围与总览列表，右侧选中详情；统计用合适宽度，不能把整张手机截图拉宽。
- 无选中任务时右栏明确提示；跨栏保存保持 UUID 选择，任务移组/归档不留下失效对象。

### 10.3 无障碍与动效

- 象限 VoiceOver 读“留出时间，重要不紧急，7项，查看任务”；选中状态可读。
- 重要性和紧急方式选项有明确 selected trait；实时预览只在实际分类变化时温和播报，不每个输入字符打断。
- 完成按钮读任务名及动作；三秒撤回入口可被焦点找到，主行动不能仅以颜色变化表达。
- 柱图支持可访问列表及“查看明细”，数字按钮读标签、期间、单位。
- Reduce Motion 使用淡入/即时位置更新，不因动效延长或缩短三秒业务窗口。
- 保存、完成沿用已有品牌反馈；日常筛选和阅读克制。不要改全局首页品牌资产或另建完成特效状态机。

## 12. 分阶段实施与验收门禁
