# Holo 动效语言与任务体验设计方案

> 2026-09-18 · 产品与交互设计稿 · 未实施。交互预览：[光痕手帐动效原型](../../design-mockups/2026-09-18-holo-motion-study.html)。原型是方向与节奏演示，界面细节以 iOS 实现评审为准。

> 后续评审：东林指出本版的节点轨迹仍有进度条感。现已补充 [B/C/D 无进度条方向对比](2026-09-18-Holo无进度条动效方向对比.md)。本文件作为 A 版候选与现状诊断保留；下文 D2 的 A 版做法暂不视为最终实施决定。

## 1. 产品结论

Holo 的高级感应来自行动的连续性：用户触碰一件事，界面有准确的回应；完成后留下可见痕迹，下一步自然浮现；一天结束时得到安静的收束。动效承担状态解释和情绪表达，帮助用户感到自己的生活正在向前推进。

建议采用 **「光痕手帐」** 作为全 App 动效语言：暖纸、细光、刻痕、沉稳的卡片位移。保留现有米白、品牌橙和语义色；变化主要发生在运动、层级和反馈中。任务模块先做一个可验证的切片，再扩展到 Today、Matter、习惯和记忆。

这是一项产品假设：更明确的行动反馈和更有个性的收束，可能提高用户对完成过程的满意度与持续使用意愿。留存改善需要试用和数据验证，不能由原型推定。

## 2. 当前体验事实

| 位置 | 当前实现 | 用户感受上的问题 |
|---|---|---|
| 任务页 Hero | 同时展示大数字、环形进度和横向进度条；比例变化时环和条各自补间 | 三次表达同一个百分比，变化有量感，缺少行动的去向 |
| 子任务页 | 6pt 横向进度条用 0.62 秒填充，满额后延迟出现彩带 | 每个子任务都回到数值反馈；满额庆祝与任务本身无关 |
| 任务卡 | 清单行末还有 3pt 迷你进度条 | 进度条的重复密度高，缺少信息层级 |
| 习惯页 | 同样使用橙色今日进度条、完成后“全部点亮” | 跨模块的动作语义被同一种进度视觉覆盖 |
| 完成状态 | 任务列表先进入 3 秒可撤回状态再落库；Today 页直接切换持久状态 | 同一动作在不同入口有不同的确认含义，无法设计一致的完成动效 |
| 现有规范 | `HoloAnimation` 已有五个基础 token；设计规范要求新动效使用 token、支持 Reduce Motion | 可以在同一体系内扩展，不需要另造动画框架 |

代码依据：`TaskListView.swift` 的 `heroRegularCard`/`heroRing`/`heroProgressBar`，`ChecklistView.swift` 的 `ChecklistProgressBar`/`CompletionCelebrationView`，`TaskCardView.swift` 的迷你进度条，`HabitTileView.swift` 的 `HabitProgressHeader`，`TodoRepository.swift` 的 `startPendingCompletion`，`DailyKanbanView.swift` 的 `completeTask`。

## 3. 视觉方向：光痕手帐

### 核心意象

把屏幕当作一页正在写下的生活手帐。完成留下一个有温度的印记，任务沿一条轻微发光的路径向前。光只在用户动作发生时出现；静止界面保持安静。

| 层次 | 表现 | 作用 |
|---|---|---|
| 材质 | 现有 `holoBackground` 米白与 `holoCardBackground` 卡片底；极淡纸张层次 | 维持 Holo 现有品牌气质 |
| 光 | 品牌橙短暂沿路径流动，停下后成为小面积暖色实体 | 指出状态从何处变化、落在何处 |
| 形 | 圆点、短线、时间轨迹、卡片轻微抬起与归位 | 用空间关系解释“完成”和“接下来” |
| 文字 | 数字作为辅助证据；行动标题和下一步是视觉主角 | 让用户看到推进的内容 |
| 触觉 | 触点轻反馈；最终确认一次明确反馈 | 与视觉节奏一致，避免持续震动 |

### 三个具体设计方向与取舍

| 方向 | 画面特征 | 最适合的位置 | 结论 |
|---|---|---|---|
| **光痕手帐** | 纸面、暖光、短刻痕、沉稳卡片 | 任务、Today、习惯日常操作 | **主方向**：辨识度与高频耐看性平衡最好 |
| 生活星图 | 事项和记忆在长时间尺度形成点与线 | Matter、记忆回看 | 用于低频纵览，避免日常任务操作过重 |
| 沉浸舞台 | 大幅背景变化、粒子和镜头运动 | 年度回顾、重大里程碑 | 留给少数仪式时刻，首轮不做 |

## 4. 动作脚本：先做任务模块

### A. 完成一个任务：触碰 → 留痕 → 继续

1. **触碰，0–120ms**：勾选圆点向内收紧，卡片抬起约 2pt；一次轻触觉。文字和按钮立刻进入“正在完成”视觉态，不等待动画结束。
2. **可撤回，120–420ms**：一束短暖光从勾选点沿卡片左侧刻线流向“已完成”位置；卡片缩成一条安静的完成记录。撤回入口持续可见，仍可直接操作其他任务。
3. **下一步，420–700ms**：Hero 中相应的任务节点变成实心，下一件可做的任务轻微上移，副文案说明“接下来可以……”；数量只做一次轻量数字过渡。
4. **提交，3 秒撤回窗结束后**：状态真正落库。界面不再播放第二次庆祝；若落库失败，恢复原卡并显示清楚的失败信息。
5. **撤回**：沿原路径反向归位，焦点保持在该任务；不出现失败感或惩罚感。

**重要状态门**：只有从未完成成功进入已完成，才播放完成反馈。冷启动、同步刷新、筛选切换、重复进入页面都只显示最终状态，不重播。连续完成多件时，合并 Hero 更新，卡片各自快速确认，不叠加多层粒子。

### B. 子任务：把横向填充改为「章节刻痕」

- 顶部呈现任务标题与一条竖向章节脊线；每个子任务对应一个短刻痕。完成时当前刻痕从描边变成实心，细光传到下一刻痕。列表本身保持稳定，避免每次勾选大面积跳动。
- `2/4` 保留在角落作为精确进度；默认不再同时放一条 6pt 进度条。任务卡外层只展示“已走到第 2 步”及四个微刻痕，空间不足时保留 `2/4`。
- 全部完成时，所有刻痕汇成一个完成印章和一句与内容相关的收束文案，例如“准备工作已完成”。不撒彩带；可选的温暖光晕只出现一次且不遮挡列表。
- 添加、删除、反选子任务会重新计算章节数。减少进度时刻痕自然退回，文案直接更新；用户不会看到“完成了又被夺走”的夸张逆向动画。

### C. 今日 Hero：把双重百分比改为「今日轨迹」

- 以今日时间顺序排出最多 5 个可见节点，超出部分以“还有 N 项”折叠；节点对应真实任务，不是装饰点。
- 主区展示 **当前下一步** 与“已完成 N 项”，全量清单仍可进入。到期、过期、未排期各有文字和形态差异，不能只靠颜色。
- 完成一项时，只点亮其节点，并把可见焦点平滑交给下一项。当天事项全部完成后，轨迹收成一条安静的暖色地平线；用户得到“今天已经向前走了”的总结，并可查看已完成事项。
- 当日没有任务时，画面提供“开始一件事”入口和留白，不能显示 0% 圆环或一条空进度线。

### D. 完成整个清单 / 一天

完成单项属于高频反馈，短且克制；完成整个清单或一天属于低频收束，可以用 600–900ms 的一次性场景转换。文字从事实出发，例如“今天完成了 3 件事”，在晚间可以提醒休息。避免“完美的一天”这种对未完成日子带压力的评价。

## 5. 跨模块扩展

| 旅程 | 触发与动效 | 用户获得的意义 | 优先级 |
|---|---|---|---|
| Today → 任务 | 今日焦点卡与任务详情共享标题/位置关系；关闭返回时回到原位置 | 知道自己从哪里来、做完去哪里 | P1 |
| 任务 → Matter | 完成真实关联任务后，在 Matter 时间轴增加一枚小刻痕；下一行动卡适度前移 | 看见一件长期事项在积累 | P1，依赖真实 `MatterLink` |
| 习惯 | 一天内首次打卡时在当天日期上留下暖点；连续日形成轻微节律 | 感到日常在积累，无额外积分压力 | P2 |
| 健康 | 趋势变化用平滑路径揭示，读数和日期保持稳定 | 看清变化方向 | P2 |
| 财务 | 记账成功后收据卡归入时间流，金额保持稳定、分类明确 | 确认已记录并知道去向 | P2 |
| 记忆回看 | 内容像翻开一页纸一样展开，来源与时间随内容一起出现 | 强化生活轨迹的真实感 | P3 |
| HoloAI | 只对确定的阶段事件做状态转场：理解中、准备建议、等待确认、行动完成 | 长任务有进展且不伪装已完成 | P3 |

跨模块复用的是**动作语法**，不是每页同一条进度条。完成业务动作须以真实回执为依据；后端、CloudKit 或 AI 未确认的内容只能展示相应等待态。

## 6. 动效系统与制作约束

### 运动分级

| 级别 | 场景 | 目标时长 | 规则 |
|---|---|---:|---|
| M1 触点 | 按压、勾选、选择 | 80–150ms | 每次操作可见，无等待门 |
| M2 状态 | 卡片归位、节点点亮、下一步出现 | 220–450ms | 只由用户动作或真实状态变更触发 |
| M3 章节 | 清单完成、一天收束 | 600–900ms | 同一事件一次；用户随时可继续操作 |

这些时长是原型目标，iOS 实现需在真机上调整。新增角色作为 `HoloAnimation` 的语义 token 统一定义，业务视图不写散落时长。颜色、间距、圆角、触觉继续使用 `DesignSystem.swift` 和 `HapticManager`；扩展 token 时同步更新 `docs/standards/设计规范.md`。

**运动预算**：一个触发事件最多一个主运动与一个辅助运动；列表滚动时不播放背景循环；同屏新动效最多两处。屏幕边缘不持续闪烁。大面积位移不超过用户追踪内容所需的距离。动效结束前按钮可继续使用，快速连点按业务状态合并。

**无障碍与设备**：Reduce Motion 下保留勾选、文字、节点的静态状态切换，以淡入替代位移和光流；VoiceOver 宣读“已完成，可撤回”“已保存”“完成失败”；动态字体下轨迹可折行；深色模式沿既有 colorset 适配；低电量或性能较弱设备不使用连续粒子与持续模糊。

Apple 的设计建议强调动效服务于反馈与状态、频繁操作保持简短，并允许用户不等动画结束就继续操作；SwiftUI 提供受状态触发的阶段与关键帧能力，可供实现时选用。[Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)、[SwiftUI animation timing](https://developer.apple.com/documentation/swiftui/controlling-the-timing-and-movements-of-your-animations)。

## 7. 实施顺序和决策门

| 阶段 | 具体任务 | 验收 | 回退 |
|---|---|---|---|
| **D0，动效基线** | 用真机录下任务列表、子任务、Today 的正常完成、撤回、连续完成、冷启动；记录现有时长和状态差异 | 形成每个动作的前后对照与事件表；确认入口语义 | 只读，无回退 |
| **D1，统一完成状态** | 对齐任务列表和 Today 的完成、3 秒撤回、保存失败语义；定义事件 ID 防重播 | 两入口对同一任务给出一致反馈；撤回与失败不误报完成；冷启动不重播 | 可切回现有视图，数据层保持可恢复 |
| **D2，任务首切片** | 实现勾选留痕、卡片归位、子任务章节刻痕、今日轨迹；移除对应重复进度表达和彩带 | 用户能说清刚完成了什么、去向和下一步；Reduce Motion/VoiceOver/大字/深色通过 | 功能开关切回旧呈现，业务状态保持同一来源 |
| **D3，审美调校** | 在小屏和大屏真机录制逐帧回看，调节力度、时间和触觉；5–8 位目标用户做任务旅程试用 | 常见操作无等待感，无误触和过度庆祝反馈；原型与真机差异有记录 | 逐项降级 M3，再降级 M2 |
| **D4，扩展** | 把同一动效语法接入习惯与 Matter，再评估健康、财务、记忆 | 每个新动效都表达真实业务状态，提供对照与可撤回路径 | 单模块开关回退 |

**D2 评审门**：先只做任务与 Today。若真机上“今日轨迹”没有比当前 Hero 更快地让用户找到下一步，就保留任务完成留痕，重新设计 Hero。Matter 等跨模块效果不随首切片一起上。

## 8. 成功标准与观察方式

- **可理解性**：让试用者完成一项任务后复述“完成状态、能否撤回、下一步在哪里”；至少 80% 无提示答对。这是设计目标，不是现有结果。
- **审美与疲劳**：连续完成 10 项后询问“是否仍愿意保留这个反馈”，收集不喜欢的具体帧和原因；对高频动效单独评估。
- **行为指标**：在同等任务量与入口条件下比较任务完成率、撤回误触率、打开下一项的比例、7 日回访；只有达到一致的埋点与样本条件才判断变化。
- **性能与无障碍**：真机滚动与快速操作无明显掉帧；Reduce Motion、VoiceOver、动态字体、深浅模式均可完成相同任务；电量和发热无异常。
- **验收证据**：原型、iOS 录屏、逐帧问题单、真实任务 ID 与回执、无障碍录屏、指标口径。`BUILD SUCCEEDED` 只能证明代码可编译。

## 9. 给实施方的交付模板

每阶段提交：`改动范围 → 用户可见前后对照 → 状态事件表 → 录屏（普通/Reduce Motion）→ 真机与性能结果 → 失败和撤回演示 → 未解决问题 → 回退方式`。涉及 Matter 时补真实 `MatterLink` 和来源键；涉及跨设备时补同步前后状态，不用演示数据替代。
