# Holo 动效视觉统一诊断

> 2026-09-20 · 基于当前 SwiftUI 实现的代码审查。结论针对视觉系统与组件职责，不把 HTML 原型或构建成功视为真机视觉验收。

## 产品结论

动画方向可以保留，当前主要问题是**任务模块的稳定页面被整体换成了另一套纸张品牌**。Holo 其他模块以系统中文字体、品牌橙、语义白卡、16pt 圆角和轻阴影为共同骨架；任务模块同时换成衬线字体、暖纸色、不对称圆角、棕红色、印章和深色撤回条。用户每次进入任务页都会持续看到差异，因此感受到的是“换了一个 App”，而不是“Holo 在完成任务时有一个有记忆点的动作”。

建议采用一个明确规则：**稳定界面统一使用 Holo，用户主动完成的瞬间才使用纸页动效。** 保留收页、印章、轻微上浮和落定节奏；任务头部、任务卡、完成后的长期记录和基础按钮回到 Holo 的共同字体、颜色、圆角和卡片结构。

这不需要推翻已完成的状态协调层。完成、撤回、父子任务恢复和防重播逻辑有产品价值，继续保留；需要调整的是渲染层。

## 代码事实

### 1. 当前只有任务 B 形成了完整新视觉

- `Views/Tasks/Motion/TaskPaperMotionViews.swift` 已实现纸页头、纸页任务行、事簿记录、完成回执和深色撤回条。
- `TaskListView.swift` 把纸页头用于列表首屏，把所有任务卡换成纸页皮肤，把完成中和已完成任务长期换成事簿记录行。
- `TodayPrimaryFocusCard.swift` 仍是标准 Holo 白卡；`MatterDetailView.swift` 仍是标准 Holo 信息卡和事件列表，没有对应的 C 聚光与 D 拼贴实现。

因此目前视觉不是“三种动效分布在三种使用时刻”，而是“任务模块先独立换肤”。这会放大割裂感。继续照原方案给 Today 和 Matter 各加一套完整皮肤，会把一处割裂扩成三处风格岛。

### 2. 任务纸面主题替换了过多基础变量

`HoloTaskPaperTheme` 独立定义了纸页行、描边、完成记录、棕红色条、回执、深色 toast、头部渐变和不对称圆角；`holoSerifTitle` / `holoSerifBody` 又引入第二套主标题字体。它们同时作用于稳定页面，覆盖了 Holo 已有的：

- `Color.holoCardBackground`、`Color.holoBorder`、`Color.holoPrimary`
- `Font.holoHeading`、`Font.holoBody`、`Font.holoCaption`
- `HoloRadius.md/lg` 与 `.holoCard()`
- `Color.holoPaper`、`Color.holoSealRed`（现有记忆册纸感语义）

纸张语言本来可以作为 Holo 的情绪层，现在却形成了平行设计系统。

### 3. 同一个页面内部也存在两套语言

任务页的筛选胶囊、分组标题、清单色条、延期、归档、删除、导航和详情字段仍是标准 Holo；它们外面的头部与任务行变成纸页。用户不是只在模块切换时感到割裂，在同一屏内也能感到控件与容器来自两套产品。

### 4. 完成后的稳定状态过度强调仪式感

完成回执是一瞬间，适合较强表达；`TaskPaperRecordRow` 则会长期留在列表中，印章、衬线字、牛皮纸底持续抢占注意力。完成项越多，页面越像事簿，任务工具的扫描效率越低。这也是“第一眼好看，长期使用可能累”的根因。

## 推荐统一方案

### 稳定页面：回到 Holo 的共同骨架

| 位置 | 当前实现 | 调整建议 |
|---|---|---|
| 任务顶部 | 暖纸渐变、衬线句子、异形纸角 | 使用标准 Holo 卡片和系统字体；保留“还有 N 项 / 已清零”的文字判断，不恢复百分比、圆环和进度条 |
| 未完成任务 | 所有任务卡都是暖纸与异形圆角 | 回到 `holoCardBackground + HoloRadius.lg + HoloShadow.card`；清单色条、子任务直显继续保留 |
| 待确认任务 | 整行换成事簿记录 | 保持原任务卡位置与结构，完成圈切换、内容轻微收拢，尾部出现“可撤回”状态；减少布局跳变 |
| 已完成任务 | 牛皮纸记录、衬线标题、印章长期存在 | 回到 Holo 完成态卡片：弱化文字、显示完成时间；小号橙色完成标记可以保留，避免大印章常驻 |
| 撤回条 | 任务专属深墨 capsule | 抽成全 App 可复用的操作回执；用同一组件承载任务完成、延期、保存等可撤回动作 |
| 任务详情 | 基础字段是 Holo，完成反馈是纸页 | 基础结构不变；只在完成瞬间叠加同款回执，撤回使用全局操作回执 |

### 动画：保留已建立的记忆点

保留 `TaskPaperCompletionReceipt` 的动作编排：用户主动完成后，真实任务标题随轻微收页、上浮和印章出现，约 0.75 秒后淡出。视觉上改用 Holo 语义卡片底、品牌橙和现有阴影；纸感可以通过极轻的暖色和边缘形状表达，不需要让整个任务页永久变成纸张。

保留以下业务与运动规则：

- 只在用户主动完成时播放一次；冷启动、同步和重新进入不重播。
- 撤回期间事实明确，保存失败不展示稳定完成态。
- Reduce Motion 下保留文字回执，取消位移与旋转。
- 连续完成时回执不阻挡下一条操作，危险操作层不得在换形动画中露出。

### Today：使用 Holo 自己的深色表达

后续 C 聚光不要复刻一整块陌生的炭黑舞台。可复用 `HoloPlusTheme.darkGradient` 的暖深色、`holoPrimary` 光晕和标准圆角；标题继续使用系统字体。卡片内部只保留一个主行动、真实来源和下一条子任务。这样它会像 Holo 首页橙色球体的展开状态，也能承接原型的“聚光”感。

### Matter：纸片属于内容，不属于页面外壳

D 拼贴可以存在于“最近变化”区，但每张纸片使用已有 `Color.holoPaper` / `Color.holoSealRed`，外围仍是标准 Holo 卡片。新变化落下时有轻微旋转与层叠，稳定后成为可读、可点击的事件卡；没有真实事件时不摆装饰纸片。这样能与 Memory Gallery 的册页语义形成同一来源，而不是再建立 Matter 专属调色板。

## 建议实施顺序

1. **先修视觉骨架**：任务头部、未完成任务、已完成任务回到 Holo 卡片和系统字体；不动完成协调层。
2. **保留并收敛完成动效**：纸页只作为瞬时 overlay；印章从长期状态移到完成瞬间。
3. **统一操作回执**：将任务深色撤回条抽成全 App 组件，延期与完成先接入，后续保存操作复用。
4. **再实施 Today 聚光**：只复用 Holo 暖深色、橙光和标准字体，不建立 C 专属完整皮肤。
5. **最后实施 Matter 变化纸片**：复用现有 Memory 纸张 token，只改“最近变化”内容区。

每一步都可独立关闭表现层，不改任务和 Matter 数据。第 1–2 步完成后应先真机连续使用一天，再判断纸感是否还要继续减量；不要先把另外两个模块也全面换肤。

## 删除按钮闪烁 Bug

根因在 `Components/SwipeActionView.swift`：归档/删除操作层始终绘制在任务卡背后。任务完成时，普通卡片动画换成更矮的完成记录行，中间帧会短暂露出最右侧的红色删除按钮。这不是删除状态被触发，也不是数据问题。

修复规则：闭合状态不绘制也不响应操作层，只有用户真实左滑产生负向位移后才显示。该修复适用于所有使用 `SwipeActionView` 的页面，也避免其他卡片换形时泄露危险操作。

## 验收标准

- 进入任务页时，第一眼仍能认出与习惯、想法、财务相同的 Holo 页面骨架。
- 不看百分比和进度条，也能知道今天还剩什么、具体下一步是什么。
- 完成瞬间仍有清晰而独特的纸页反馈；3 秒后页面恢复安静，不留下大面积材质噪声。
- 连续完成 5–10 条任务不会积累大量印章视觉，也不会阻碍扫描下一条。
- 完成、撤回、落库以及卡片换形全过程中，归档/删除按钮不闪现；只有真实左滑才出现。
- Today 与 Matter 后续动效复用 Holo 颜色、字体、圆角、阴影及既有纸张语义，不新增平行设计系统。
