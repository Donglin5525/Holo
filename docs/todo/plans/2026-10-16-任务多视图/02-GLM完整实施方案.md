## 3. 页面结构与状态

### 3.1 布局顺序

顶部安全区 → 当前返回/任务标题/搜索/更多 → **三段视图切换** → 当前范围及数量 → 当前视图内容 → 原统计/任务/纪念日模块导航。右下保留唯一橙色 FAB。

- 三段属于任务页，不替换底部模块 Tab。
- 搜索查全量任务，延续现有行为；搜索打开详情后返回恢复原视图和日期，不强制跳列表。
- 日历/四象限/列表分别按日期、轻重缓急、清单组织。新版列表取消象限胶囊和象限分组，复用任务行、子任务与原动作。
- 四象限不会同时出现在顶部作为第二套筛选条。
- 页面只让内容区滚动，顶部返回、切换和范围固定。四象限用一个外层滚动区，每格预览不单独滚动。

### 3.2 状态的归属与持久化

| 状态 | 归属 | 持久化 / 复位规则 |
|---|---|---|
| 当前视图 | `TaskPresentationState`，由 TasksView 会话持有 | 新模块会话初始化为calendar；不读写旧模式偏好，异常值回日历；会话内保留手动选择 |
| 当前范围 | 现有 model.scope | 原持久化机制不重写；三视图同一份 |
| 列表滚动/子任务展开 | 列表专属会话状态 | 切换视图保留；改变范围清定位；取消旧象限筛选状态 |
| 日历选中日 | 会话状态 | 同次打开保留；冷启动今天 |
| 日历展示月份 | 会话状态 | 与选中日月份一致；冷启动今天月份 |
| 月览/日程 | 会话＋UserDefaults `taskPresentation.v1.calendarMode` | 记住上次，首次月览 |
| 显示已完成 | 日历独立偏好 `taskPresentation.v1.calendarShowsCompleted` | 首次关；只影响日历投影 |
| 选中详情/单格展开 | 统一 sheet 路由 | 关闭回来源视图，不改变范围 |
| 拖动 | 矩阵临时状态 | 取消、切换、后台、同步使对象不可用时清理 |
| 保存/撤回 | action coordinator | 不存任务实体，需防重复提交 |

实现建议一个会话对象由 `TasksView` 使用 `@StateObject` 持有并注入任务子页，避免 switch 到统计后销毁任务页而丢失日期与手动选择的视图。从首页新进入或冷启动时创建新会话，视图回日历；同一模块内统计/纪念日往返不是新会话。不要读取旧 `taskPresentation.v1.mode` 覆盖默认值，也不要删除其他偏好或用户数据。不要用 `@StateObject` 包全局单例。旧版任务开关关闭时继续走旧页面；只停用新 UI，数据和偏好都保留。

### 3.3 范围与切换规则

- 普通活动范围（全部未完成、今天到期、逾期、收件箱、具体清单）原样保留，日历在范围集合上再投影日期。`今天到期` 永远是**真实今天截止**，不是当前选中日。
- `已完成` / `归档` 是历史列表范围：选择它时进入列表；用户之后点日历/四象限，显式切回全部未完成，并提示“已切回全部未完成”。不是禁用按钮。
- 日历的“显示已完成”是在同一**范围条件**下补入完成任务，不能取全库完成项混进具体清单。归档/删除仍排除。
- 逾期范围开启显示已完成也不补已完成项：已完成不再属于当前逾期事实。
- 从日历到四象限，不继承选中日为额外过滤。四象限看当前范围所有未完成；日历返回时恢复之前日期。
- 列表不再有象限胶囊筛选；三视图只共享当前范围。日历选中日不会裁掉列表的其他日期或无日期任务。
- 范围对应清单删除/失效，复用原规则回全部；不让日历单独停在失效 ID。

### 3.4 列表视图的独立职责与详细规则（V1.1新增）

- 用于完整管理当前范围的任务，按清单组织，不能继续按四个象限或紧急程度分四组。
- 全部未完成：收件箱置首，其他有效清单依现有清单顺序；失效归属桶按原删除契约置末。不改清单模型/排序/文件夹关系。原型演示清单顺序固定为收件箱、Holo、工作、生活、成长。
- 每组仅中性清单标题、未完成数与完整任务列表；不显示四色象限色线/象限数字面板/象限胶囊。0项清单在此任务结果页隐藏，清单管理入口仍沿用原功能。
- 切到某个具体清单时，只列其全部成员，省略与范围名称重复的组标题。今天到期/逾期等活动范围先按原规则过滤，再按清单分组。
- 未安排、无截止、unknown重要性都正常显示在所属清单内；unknown不在列表末尾另开“待整理”组。整理专用入口归四象限，任务详情仍可编辑分类。
- 组内复用现有defaultOrder，不为去重而移除重要性排序。去掉的是重复的象限组织层，不是任务属性或编辑能力。
- 保留行内子任务展开/加一步、完成/撤回、详情、计划编辑、轻重缓急、Today、清单归属等原动作。四象限动作在行菜单/详情中可到达，不再成为列表主布局。
- 新增任务保存后，按实际清单定位并高亮该行，不调用“展开目标象限组”旧逻辑；未知重要性也定位到清单内。
- 历史已完成/归档仍保留原连续历史列表与时间排序，不强制改清单分组。
- 页面轻说明“按清单查看任务，包含未安排与待判断重要性的任务”；不加每日计划摘要，不复制四象限教学。
- 空态/读取失败沿原规则；375pt仍是一列连续行，组标题16pt、任务行最小72pt，现有任务行复用。

## 4. 数据与派生契约（必须逐项实现）

### 4.1 单一数据源

沿用 `TaskSnapshotReader.readAllSnapshots`：规范副本选择 → 值快照 → 活动/历史过滤 → pending 完成投影 → 范围 → 视图派生。不得新写不一致的删除过滤、重复去重或清单失效判断。

`TaskRecordSnapshot` 新加计划原值可选字段，旧测试/构造入口提供默认 nil；`hasValidPlannedRange` 与原值校验结论一致。不能仅补一个 Bool 后在每个格子/行反查 repository。

所有涉及 `now` 的计算一次刷新使用同一 `asOf` 和 `TaskAnalyticsPeriod.makeCalendar()`。默认按本地 Gregorian；周一为起始日，按 Calendar 加日/月，不用 86,400 秒推日期。切时区/前台/午夜更新 today、象限、范围和月索引。

### 4.2 活动与日历成员

定义 `A` 为当前范围未删除、未归档、未完成、排除 pending 完成任务的集合。清单自身归档的处理继承现有 scope，不额外发明隐藏规则。

对本地日期 D：

- `P(D)`：A 内有合法计划时段且开始日期=D。
- `C(D)`：A 内截止日期=D，使用原始日期的本地日比较；全天截止按现有策略解释为日末。
- 日任务 `U(D)=P(D)∪C(D)`，按任务 UUID 去重。
- 月历数字=`|U(D)|`，不是“计划数＋截止数”。同一任务同日两个事实只计一次。
- 日期不同的计划和截止，可以让同一任务分别出现在两天；这是同一任务的两个事实，不是复制任务。
- 日历显示已完成时，将同范围的完成任务纳入同样的 P/C 计算，完成样式区分。范围徽章仍表示未完成数，日摘要表示当天可见任务数；不要混用两个口径。
- 没有日期但有计划 → 出现在计划日；没有计划但有截止 → 出现在截止日；两者都无 → 不落月格，但在待安排。
- 半缺/非法计划按未安排处理；若还有截止则截止日可见。不得自动修改脏记录以“修好”读取。

### 4.3 两个时间概念

- `plannedStart/plannedEnd` = 打算做的时段；`dueDate/isAllDay` = 完成期限。
- 安排/改计划/移除计划只写 planned 字段和该操作正常的 updatedAt；不改截止、提醒、重复规则、Today 选择、延期计数、分类。
- 当前只有同日合法时段。V1 不加跨日或全天计划字段，也不把 `isAllDay` 用作计划全天。
- 只有截止的任务不能自动画成 60 分钟块。
- “全天截止”在日程上显示于截止事项，而不是标成“全天安排”。
- 计划晚于截止、过去日期或冲突允许保存；明示事实，不偷偷推迟截止或挤走其他计划。
- 计划设置为今天不自动调用 Today 加入服务，移除计划也不调用 Today 放下服务。

### 4.4 排序与守恒

- 列表和单象限完整列表：复用 `TaskRecordSnapshot.defaultOrder`（紧急分降序 → 有效截止升序 → 创建时间升序 → UUID）。不要重写成只按日期。
- 日明细：当天有计划任务先按开始时间升序；同开始按结束时间、现有稳定序；其后截止独立项按有效截止、现有稳定序。
- 四格预览取同格完整列表前 2 条，隐藏数量不影响格标题总数。
- `四格总数 + 待整理数 = |A|`。完成/撤回、外部编辑、切范围、同步后都必须成立。
- 待安排=`A 内没有合法计划时段`，**与有无截止无关**。有效但已过去的计划仍算安排过，不自动放回待安排。
- 逾期=`有效截止 < asOf` 的活动任务；跟计划是否过去无关。

## 5. 日历详细交互

### 5.1 月览

从上往下：年月/前后/今天 → 月览/日程二级切换 → 星期行 → 日期网格 → 计数说明 → 待安排 → 可选逾期入口 → 选中日标题/新增 → 当天摘要 → 当天任务连续列表。

1. 首次今天选中；切视图回来保持日期。年份变化显示完整年/月。
2. 每月补齐自然周，4/5/6 行由实际月份决定；邻月日期浅色可点，点后切到该月并选中。周一开始，不补固定 42 格浪费高度。
3. 日期格包含日期数字和“n项”；0 不写 0；今天有橙色细圈，选中日橙底反白；今天同时选中只保留实底。选中格用浅 inset 底承接。
4. 前后箭头月览每次一月，保持日号并夹到目标月最后一天，例如 1/31 → 2/28；“今天”回真实今天并切对应月。
5. 点击日期只改选择，不弹新增。下方内容立即刷新，不自动跳走用户视野。
6. 计数说明固定“数字为当天任务数（去重） / 计划、截止均计入”；原型视觉紧凑，正式版可分两行。
7. 当天摘要“5项任务 · 3项有时间安排 · 已占用2小时30分钟”。占用按时段并集计算，不能重复累加冲突时间。
8. 每行显示标题、清单、计划时间、明确“截止”字样；同日同时有计划/截止仍只一行。
9. 没有当天任务时保留月历和日期标题，显示“这天还没有安排”，主入口“从待安排中选择”。不能误写“没有任务”。
10. 左右轻扫月份可作为箭头的等价操作；避免与页面边缘返回冲突，不将手势作为唯一入口。

### 5.2 单日日程

1. 月览/日程切换保持选中日期；日程上方改为包含选中日的周日期条。
2. 前后箭头每次一周，选择日期加/减七个日历日；跨月同步年月标题。“今天”回当日。
3. 截止事项区：当天到期但没有当天计划块的任务，显示“标题＋全天/具体时间截止”，不占时间轴高度。同日已有计划块的截止改附在块内，不重复放事项区。
4. 24 小时全部可滚动，默认每小时 64pt。进入日程首次滚到当天最早计划开始前一小时；没有安排滚到 08:00。同会话返回保持原时间轴滚动位置。原型与正式版均遵循本条。
5. 当前时间线仅真实今天显示，每分钟前台刷新；其他日期无“现在”线。原型固定 11:00 仅作演示。
6. 计划时间决定块的纵向位置与持续高度；块最小可点击高44pt。少于44pt的真实时长采用紧凑块与标记连接，不把显示增高误当真实占用。相邻短块发生**视觉**重叠时也要分列/聚合，不能遮住触点。
7. 真正重叠的计划按开始/结束/UUID排序，区间扫描分冲突组，再分最少列。组内等宽、列间4pt；结束等于下一开始不是冲突。
8. 两列时块内标题最多两行，显示实际时间；加文字“时间重叠”。达到三列且块净宽<88pt时改成可点“n项重叠”的组块，打开该冲突组列表，不能把字挤成竖排。
9. 计划块色用现有象限浅底和左色线；未判断用中性底与“待整理”，不能涂成优先处理。完成块文字划线并显完成标识，不仅靠透明度。
10. 点击计划块进现有任务详情；详情“计划时间”打开统一编辑。点击空白整点进入新建草稿，预填该日该点起一小时；23点默认至23:59，不能跨日。
11. V1 没有日历块拖动/缩放/双指缩放；不要实现看起来能拖但实际改截止的假交互。

### 5.3 待安排与逾期

- 待安排入口显示真实数量，0仍保留，便于理解功能；打开为 sheet，标题“待安排 · 10月16日”。
- 列表继承当前范围和原稳定排序；每项可详情、安排时间、完成。标题下提示“没有计划时段的任务，包括已设截止的任务”。
- 进入已有任务的安排弹层时，**新安排日期默认当前日历选中日**；有现成计划的“修改计划”默认原日期。
- 选今天默认下一个15分钟刻度起一小时；若无法保持同日一小时，缩到23:59；23:59无可用余量则保留日期，要求用户选开始时间，不静默换到明天。选其他日默认09:00–10:00。默认值只落草稿，用户保存前可见。
- 日历单独“查看当前范围逾期任务 n项”入口，仅 n>0 显示；点开**全部该范围逾期任务**，与选中日无关；不能把按钮指向待安排导致漏掉已安排但逾期项。
- 待安排和逾期两集合可以重叠，数量不能相加当任务总数。
- 逾期不自动出现在今天的安排中；过去计划也不自动滚动到今天。

### 5.4 计划时间弹层

- 标题“安排时间”/“调整计划时间”；左取消、右保存；字段为计划日期、开始、结束。
- 顶部展示任务名和“此次只调整计划，截止时间保持为：……”；不放修改截止的快捷开关。
- 新建先复制草稿；保存前不更新实体。取消、点遮罩、下滑关闭都丢弃草稿，已编辑才确认放弃；系统返回与取消等价。
- 开始/结束同日且end>start；不合法保留输入，字段下明确报错“结束时间需晚于开始时间，且安排在同一天”，保存禁用或触发同一错误，不能自动颠倒。
- 与其他任务冲突显示“与n项任务时间重叠”；计划结束晚于有效截止显示“计划晚于截止，截止时间不会改变”；二者均非阻断错误。
- 已有计划可“移除计划时间”，只清计划，不删除任务。保存成功后投影和数量一起刷新。
- 成功提示“已安排到10月16日11:15，截止未改变”；成功后选中新的计划日，月标题同步；原任务若移出原日不留假行。
- 保存失败保留草稿与弹层，显示“暂时未能保存，修改仍保留在这里，请重试”；禁止成功提示；原对象字段恢复到操作前，不能全局 context.rollback() 误回滚其他并行编辑。
- 如果对象被同步删除/归档/完成，提交前重读：已删除不可保存；归档/完成提示当前状态并退出写入路径。禁止按旧快照复活。

## 6. 四象限详细交互

### 6.1 固定四格与任务预览

| 坐标 | 标题 | 副标题 | 数据条件 |
|---|---|---|---|
| 左上 | 优先处理 | 重要且紧急 | importance P1，effective urgency P1 |
| 右上 | 留出时间 | 重要不紧急 | importance P1，urgency P2/P3 |
| 左下 | 集中处理 | 非重要且紧急 | importance P2/P3，urgency P1 |
| 右下 | 稍后再看 | 非重要不紧急 | importance P2/P3，urgency P2/P3 |

- 四格始终存在，即使全部0；不套用列表胶囊的“零值隐藏”。固定位置，不重排。
- 每格：淡底标题区（标题、总数、副标题、44pt新增热区）→ 前2个任务 → 超过2条时“查看全部n项”。
- 任务预览：完成圆圈＋两行标题＋一行清单/截止信息；不展示备注、全部子任务、AI徽章或操作按钮群。
- 预览行点击标题进详情；点完成只完成，不同时打开详情；长按正文启动拖动，完成按钮不启动拖动。
- 格内不独立滚动；四格同在一个竖向内容滚动区。点击标题与“查看全部”都进单格完整 sheet。
- 空格保留标题、0和新增；分别用原型简短引导，不重复整页教学。
- 下方单独“待整理n项”；不是第五格。点击复用当前整理队列/分类编辑，不自动猜重要性。
- 规则说明展示现有P档折算、自动紧急性阈值、移动后手动判断的说明。

### 6.2 象限移动的唯一写入规则

只在有效目标格松手后提交。移动前若目标等于**当前实时解析格**，no-op：不写入、不改自动判断、不更新时间、不弹成功提示。

| 目标 | 重要性写入 | 紧急方式写入 |
|---|---|---|
| 优先处理 | P1 | 手动P1 |
| 留出时间 | P1 | 当前手动P2/P3则保留，否则设手动P3 |
| 集中处理 | 当前重要性P2/P3则保留，否则设P2 | 手动P1 |
| 稍后再看 | 当前重要性P2/P3则保留，否则设P2 | 当前手动P2/P3则保留，否则设手动P3 |

说明：移动到“非重要”只表明不是P1，不应把已有“一般”硬改“不重要”；自动模式为让用户指定的目标持续生效，转成手动判断。移动弹层先说明这一点，拖动完成提示“已移至『留出时间』，时间未改变”。用户可在详情轻重缓急编辑中恢复“按截止日期自动判断”。

不动：dueDate、isAllDay、plannedStart/End、提醒、重复规则、清单、Today、完成、延期次数、旧priority列。象限本身不落库。

### 6.3 拖动规格

1. 正文长按350ms启动，位移>8pt且未启动时交还列表滚动。原生 drag API 可采用系统标准长按时序，语义保持一致；不得拖动一触即发影响点详情。
2. 启动轻触觉一次，原位置保留占位；拖动影像显示标题和原格色线。不是截图形式的新任务。
3. 命中目标格高亮2pt描边；原格也可命中。进入标题/空白/任务区域均视为该格。
4. 拖到上下可视边缘40pt区，按帧小步自动滚动外层；只滚任务内容，不滚整个模块导航。
5. 松手在目标格外、系统取消、切后台、视图切换：清理影像和高亮，零写入。
6. 提交前按UUID取当前对象，重算来源与属性；如果同步已改变分类，用**最新值**判断目标及生成补丁；不可用则提示“任务已发生变化，请重新查看”。
7. 保存期间锁定该任务的重复动作，不锁整页浏览；成功后整份快照更新、格数守恒、目标格前2预览依排序刷新。
8. 失败恢复来源显示和这次修改的字段，提示“移动未保存，请重试”；不同时显示成功toast。
9. 成功允许3秒撤回，按精确原值恢复，包括 auto。若期间其他操作/同步又改变该字段，不覆盖新值，提示“任务已更新，无法撤回这次移动”。
10. VoiceOver的“移动到象限”自定义动作打开同一移动sheet；必须有不依赖拖动的完整等价路径。

### 6.4 单格完整 sheet

- 标题象限名，副标题语义、当前范围、数量；右上新增，关闭回原矩阵滚动位置。
- 连续完整任务列表，不截2条；复用列表行的子任务、分类、时间、Today、完成等能力。
- 移出当前格成功后该行消失，数量减一并提示去向；最后一项移走显示该格空态，sheet不突然关闭。
- 从这里新增默认目标格分类；用户改分类到其他格，保存后说明实际归属，不强行纠正用户选择。

## 7. 创建上下文与原有功能保留

### 7.1 创建来源表

| 入口 | 计划时段 | 截止 | 两轴 | 清单 |
|---|---|---|---|---|
| 普通列表/FAB | 不预填 | 保留现有今天到期范围预填 | 现有规则 | 指定清单才预填 |
| 四象限页全局FAB | 不预填 | 保留原范围行为 | unknown + auto | 指定清单才预填 |
| 某象限＋/单格新增 | 不预填 | 保留原范围行为 | 目标映射；新任务非重要侧默认P2 | 指定清单才预填 |
| 日历选中日新增/FAB | 当天默认规则或其他日09:00–10:00 | **不预填**，即使范围是今天到期 | unknown + auto | 指定清单才预填 |
| 日程空白整点 | 选中日该点至后一小时，23点到23:59 | 不预填 | unknown + auto | 指定清单才预填 |
| 统计页新增 | 沿用现有 | 沿用现有 | 沿用现有 | 沿用现有 |

日历不把“计划日”偷存为截止。现有新建页要显式呈现计划摘要和“截止未设”，用户可以调整或移除计划预填。对于日历来自“今天到期/逾期”等范围且新任务未设截止而不在当前范围：保存后不改截止迁就筛选，提示“已新增，当前范围不包含此任务”，提供查看全部；采用提示＋“查看”按钮，用户点击才切范围。

### 7.2 单次创建与保存后定位

- `TaskCreationContext` 加 `plannedStart/plannedEnd` 或等价成对草稿结构；初始默认值不算用户编辑。
- `TaskCreationDraft.canSave` 同时验证标题与可选计划合法性；计划的修改标记 userEdited；取消丢弃，不提前建任务。
- 当前 `createTask` 已支持 planned 参数，直接与分类/截止一次传入，不先创建后update计划。不能因第二次失败留下半创建任务。
- 保留 localOperationID 与 isSaving 防重；创建失败重试使用同一个本地操作身份，不重复任务。
- 创建成功回执由统一 route 消费，不再一律调用旧列表的 handleCreated 切视图：日历定位计划日；矩阵展开/高亮实际格；列表按实际清单定位，不再展开旧象限组。没有计划但有截止的日历任务定位截止日；两者都无则提示已加入待安排，不编造日期。
- 新任务标题先 trim；空白不可保存，保留现有标题边界规则，不在本功能擅加500字业务限制（HTML maxlength 仅演示）。

### 7.3 旧能力不得退化

现有子任务展开/勾选/加一步、详情富文本/图片/来源、提醒与重复、Today加入/放下、清单管理、归档/回收站、新旧版开关、统计、纪念日、通知/小组件深链、搜索都应保留。矩阵预览可以简化，打开详情/完整列表必须能到达原动作。

深链目标任务：不为了展示而偷偷改scope；统一详情可直接按ID打开，关闭回原视图。只有已有明确的“查看该任务所在范围”动作才切范围。

## 8. 完成、撤回、保存与同步

- 三视图勾选都走 `HoloTaskCompletionCoordinator.requestCompletion`；3秒内 pending 不落库，确认才执行原完成级联/重复生成/通知逻辑。
- pending 期间活动范围、月格、待安排、象限、待整理计数共用同一投影；显示已完成开启时可将pending任务显示为“完成待确认”并允许撤回，不能当真实已完成再二次提交。
- 完成撤回由已有协调器拥有；移动/计划撤回由 action coordinator 持有独立短期patch，UI同一时间只展示一条操作提示。新操作开启时明确结束旧提示：旧完成按协调器原规则confirm，旧分类/计划已保存则只结束可撤回期；不撤销既有业务。
- 计划/分类撤回只恢复这次拥有的字段；若当前字段不等于本次提交值，拒绝覆盖后续更改。撤回保存失败如实报错，显示真实最新快照。
- 读取失败有旧快照：保留内容＋顶部失败条/重试；首次读取失败无快照：整页失败态，绝不显示四个0冒充无任务。
- 已知读取失败期间禁止新写入动作，避免拿过时范围作编辑；详情可只读打开，重试成功恢复。
- 保存失败不能泄漏已修改的 NSManagedObject 值给其他视图；先校验、捕获本次字段前值、保存、失败限定恢复并reload。不得 context.rollback() 抹掉共享上下文其他编辑。
- 更新事件：原 `todoDataDidChange`、完成pending变化、CloudKit import原有通知、前台、系统时区变化、显著时间变化、午夜边界；在主线程更新发布快照。
- 拖动payload只放任务UUID，不跨actor携带托管对象。后台纯计算只用不可变值快照。
- 不增加同步字段、不新建CloudKit记录类型；不把本地视图/日期偏好同步到其他设备扰乱对方浏览。

| sheet | 顶圆角24，横内边距20 | 句柄34×4；顶部动作44，正文滚动，键盘不遮保存 |
| 保存按钮 | 至少48pt，圆角12 | 文本15–16 semibold；saving防重；失败保留表单 |
| toast | 最小48pt，圆角12 | 距内容左右20，在FAB/模块导航上方；撤回触达44 |

字型尺寸为基准，不裸写固定字号导致动态字体失效；映射到现有 holoText/holoFont 或局部 ScaledMetric。不得通过 minimumScaleFactor 把可操作正文无限压小。

### 9.4 动效、无障碍和窄屏

- 视图切换淡入/交叉150–180ms，不左右整屏滑动暗示导航；减少动态效果时取消位移。
- 日期选中100–150ms；保存/完成刷新复用原有动效；移动落位180ms，不加持续弹跳。
- 深色正文≥4.5:1；图形/大文字≥3:1，重点状态还有文字或符号。
- VoiceOver日期读“10月16日，5项任务，今天，已选中”；矩阵读“留出时间，重要不紧急，3项”；行分开暴露完成和打开详情。
- 无障碍操作包含安排时间、移动到象限；iPad键盘切换和Esc关闭保留，不能只依赖拖动。
- 字号达到accessibility或有效内容宽<350pt时，矩阵降为单列四个区，保持左上→右上→左下→右下阅读顺序；说明“已按大字号展开”。此为适配例外，不把默认四象限改成列表。
- 375pt默认字体仍用2×2，不横向滚动；标题不能每字单独换行；英文副标题容器允许换行。
- iPad沿用当前 `HoloListDetailSplit` 与模块导航断点：新增视图在原master容器，detail显示原详情；只在内容宽足够时增加内容宽度。不得另写未经原型设计的桌面仪表盘；具体宽屏观感列入实施后验收。

## 13. 实施顺序与质量门槛

### G0：冻结现状

记录HEAD、工作树、现有任务入口与样例；确认主target文件同步组和当前测试target实际情况；不要仅依据旧文档声称没有test target。备份方案沿用项目红线，不能清测试库代替迁移验证。

### G1：状态、快照和纯规则

先实现 TaskPresentationState、计划原值快照、TaskCalendarProjection、TimelineLayout、MovePolicy，纯逻辑测试跑通C01/C03/C09/Q01/Q02/Q04。不先把UI搭完再临时补口径。

### G2：切换与矩阵

接三段、单一范围、四格预览、展开、待整理、非拖动移动；再接原生拖动。复用原任务行组件，按本版明确把新版列表组织层改为清单分组；移除旧象限胶囊调用，旧版回退页面保持原样。

### G3：日历与创建

实现月格/日明细/日程/待安排；扩计划编辑、创建上下文和外层FAB；检验截止/计划/Today三者互不误改。时间块复杂布局遵循聚合与短块规则。

### G4：保存、同步和异常

接动作协调、撤回、最新对象检查、错误恢复、时间变化与CloudKit刷新。空态和失败态用真实注入测试，不制造业务数据污染日用开发库。

### G5：验收与交付

1. 跑对应纯规则单测（项目如仍无可用test target则按standalone机制；如已有test_sim脚本则按当前机制）。
2. 模拟器编译通过，再执行任务模块定点交互矩阵。不要用整仓不相关测试失败遮蔽或覆盖其他会话改动。
3. 375/390/430、深浅、大字号、空/稀疏/拥挤、iPad按本次scope做界面验收。用户未允许subagents时不擅自派发，记录实际可验边界。
4. 装真机前仍要满足项目五入口/崩溃红线；模拟器通过不能写成真机/CloudKit双设备已验证。
5. 给东林交付改了什么、保留了什么、已跑检查、未验边界和可点击文件。不部署后端：本方案不要求后端改动；若实施扩大到后端须单独说明并主动提醒发版。

建议新增测试：`TaskCalendarProjectionTests`、`TaskTimelineLayoutTests`、`TaskQuadrantMovePolicyTests`、`TaskPresentationStateTests`、`TaskPresentationActionCoordinatorTests`。测试应验证日期边界、计数守恒、独立字段、失败恢复和并发，不只断言组件名字或固定文案存在。
