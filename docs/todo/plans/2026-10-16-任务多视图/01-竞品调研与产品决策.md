# Holo 任务多视图：竞品调研与产品决策

- 版本：V1.1；调研日期：2026-10-16。
- 对象：Holo iOS 当前任务模块；主竞品：滴答清单。
- 交付用途：东林评审产品方向、GLM 按原型实施。本文是产品理由；具体执行以 `02-GLM完整实施方案.md` 为准。
- 调研方式：在线检索并阅读官方帮助内容、检查 Holo 当前源代码。**没有登录或安装滴答清单进行实机走查**，不把官方说明当作最新版 iOS 像素、手势手感或付费权益的实测结论。

## 1. 产品结论

在现有任务页顶部增加「日历 / 四象限 / 列表」三段切换，共享任务、范围、详情和完成行为。新进入任务模块默认日历；模块内切换/统计往返保留本次视图。现有统计、纪念日和右下角新增入口保留。

三种视图分别回答一个问题：

| 视图 | 用户的问题 | 最短操作闭环 |
|---|---|---|
| 列表 | 各个清单里总共有些什么任务？ | 按清单管理 → 编辑 / 展开步骤 / 完成，覆盖无日期与未分类任务 |
| 日历 | 每一天有什么任务，打算什么时候做？ | 看月份 → 选日 → 查看计划 / 截止 → 安排时间 |
| 四象限 | 什么值得优先做，什么可以晚一点？ | 看四格实际任务 → 判断 / 移动 → 留出时间 / 完成 |

这次是观察方式的扩展，不引入三份任务，不新增一套优先级，不重构所有旧页面。

### 1.1 视图重复的结论与收敛（东林反馈后的V1.1）

**同一任务在多个视图出现是正常的数据共享；同一种组织方式重复出现才会增加理解成本。** 前版将列表保留为象限分组，与独立四格视图职责重叠，本版取消这个重复。

- **日历是默认工作入口**：只展示选中日期的计划与截止事实，解决“哪天做、一天放得下吗”。下方日明细保留，它是日历选中日的操作区。
- **四象限负责取舍**：展示当前范围全部未完成任务的轻重缓急，解决“先做什么”。不跟随日历选中日过滤。
- **列表负责完整管理**：按收件箱/工作/生活等清单组织当前范围全部任务，包含没有日期、未安排时段、未判断重要性的任务。取消象限胶囊、四色分组、重复的象限总览；保留详情、子任务、完成等操作。

列表仍有独立价值：日历不会把完全无日期的任务落入日期格，四象限中的unknown任务需要单独整理入口，而列表能让用户按清单连续管理全部任务。不删除列表，但明确减少其重复展示。

模块生命周期：从首页新进入或冷启动默认日历；同次模块会话中手动切换后保留当前视图，查看统计/纪念日再返回不强制跳日历。视图选择不跨模块会话记忆，避免旧“列表”偏好盖过默认日历。

## 3. 滴答清单的核心设计拆解

### 3.1 日历：从清单走向时间资源

传统列表擅长列出“要做什么”，难以表达“一天放得下吗”。日历以时间承载任务，让安排和冲突可见。滴答的周视图说明了时间轴与非定时任务分层的必要性，月视图承担更大范围概览。[S2](https://help.dida365.com/articles/6950641140068515840)、[S3](https://help.dida365.com/articles/6950640298334617600)

**对 Holo 的推论：** 页面需要同时容纳整月分布、选中日明细和没有计划时段的任务。只有一个月历加日期点、没有明细和安排入口，无法完成每日规划。

### 3.2 四象限：任务清单的另一种分组

四象限并非独立任务库，而是同一任务按规则投影。滴答允许用不同规则组织；拖动会对应调整规则所依赖的属性。[S4](https://help.dida365.com/articles/6950361734683033600)、[S5](https://help.dida365.com/articles/6950381682822217728)

**对 Holo 的推论：** 每格要展示任务和动作，不能只是四个数字。手动归类后必须解释实际改了什么，详情里的分类值也应同步。

### 3.3 配置能力：成熟产品的厚度不等于首版必选项

滴答提供较多显示和分类配置。官方问答也呈现了“任务因范围被隐藏”的理解成本。[S1](https://help.dida365.com/articles/6950361611617959936)、[S6](https://help.dida365.com/articles/6950670128287580160)

**对 Holo 的推论：** 首版应清楚显示当前范围、截止与计划含义，采用唯一规则。自定义四象限规则、重命名、重排和更多日历类型不作为本次前置条件。

## 6. 本次冻结的关键产品规则

### 6.1 同一个任务的两个时间概念

- **计划时间**：我打算在 10 月 16 日 10:30–12:00 做。
- **截止时间**：最晚 10 月 20 日完成。
- 在日历安排到 10 月 17 日，只改计划；截止仍为 10 月 20 日。
- 没有计划的截止任务，出现在截止日明细与待安排；不会自动占用一个小时。
- 计划结束晚于截止可保存，但标明“计划晚于截止”；不擅自延期。
- 今天没有完成的安排保留原日期，不自动滚到明天。
- “加入今日安排”是现有 Today 选择机制；**不因设了今天计划时段就自动加入，也不反向改截止**。

### 6.2 现有 P 档如何落入四格

| 重要性 | 当前紧急性 | 结果 |
|---|---|---|
| P1 | P1 | 优先处理（左上） |
| P1 | P2/P3 | 留出时间（右上） |
| P2/P3 | P1 | 集中处理（左下） |
| P2/P3 | P2/P3 | 稍后再看（右下） |
| 未判断 | 任意 | 待整理 |

“非重要侧”包含“一般”和“不重要”；不把用户已有 P2 改成 P3。自动紧急性按**真实今天**和截止计算，切到未来日历日期不改变象限。

### 6.3 V1 与后续能力的边界

V1 必须包含：三视图、月览、周日期条＋单日时间轴、每日明细、截止与计划分层、待安排、计划编辑、四格实际任务、象限内新增、拖动及菜单移动、待整理、详情/完成/撤回、范围继承、异常和空态。

后续再做：七列周时间轴、日历任务拖拽和时长拉伸、任务跨日/多计划时段、全天计划字段、外部日历、重复未来实例预览、自定义象限规则、象限排序与重命名。它们不是隐藏入口，也不放占位按钮。

**为什么首版不做日历自由拖拽：** Holo 当前计划与截止是独立数据，先用已有日期/计划编辑建立可靠闭环。长按任务移动象限仍在首版；日历改日期和时段通过明确的“计划时间”弹层完成。此处是 Holo 的产品取舍，不宣称与滴答完全相同。

## 7. 完整用户路径

1. 每日规划：任务 → 日历 → 选日期 → 看已有时间块与截止 → 待安排 → 任务 → 安排时间 → 保存 → 日明细/时间轴刷新。
2. 整理优先级：任务 → 四象限 → 待整理 → 调整轻重缓急 → 保存 → 相应象限出现。
3. 重新判断：长按任务 → 拖到另一象限 → 松手 → 两轴更新 → 提示“时间未改变” → 可撤回。
4. 非拖动替代：任务 → 详情 → 移动到象限 → 点目标 → 同样结果。
5. 从格子添加：右上“留出时间”＋ → 新建页预填分类 → 填标题 → 一次保存 → 该格显示；计划时间仍可之后安排。
6. 从日历添加：选 10 月 18 日 → ＋ → 新建页预填该日同日计划时段，截止未设 → 保存 → 18 日显示。
7. 时间冲突：日程内看到重叠块与文字提示 → 点任务 → 改计划 → 冲突消失；不硬拦截保存。
8. 完成与反悔：勾选 → 三视图活动计数同步减一 → 3 秒内撤回 → 三视图恢复。

## 8. 有效性、风险与度量

以下是上线后要验证的假设，**没有现成转化数据或效果提升结论**。

| 假设 | 验证方法 | 风险信号 |
|---|---|---|
| 显眼切换让用户找到新视图 | 视图曝光后 7 日内切换比例 | 用户仍以为只有列表 |
| 日历让任务真正安排起来 | 待安排打开 → 计划保存的完成率；看任务数变化 | 只看不安排；把截止误认作计划 |
| 四象限能促进判断 | 未分类任务被分类比例；移动后立即撤回比例 | 全部塞进重要紧急；误移动频繁 |
| 数据规则可理解 | 走查提问“移动后截止有没有变” | 用户找不到任务或误以为任务被延期 |
| 新视图没有拖慢列表 | 1,000 活动任务切换/滚动基准 | 每格重复取数、切换卡顿 |
