# Holo 动效融合用户动线

> 2026-09-18 · 产品交互规格 · 尚未实施。东林已选定[从入口到完成的 HTML 原型](../../design-mockups/2026-09-18-holo-motion-integrated-journey.html)作为视觉基准；开发与验收以[定稿与实施方案](2026-09-18-Holo动效融合定稿与实施方案.md)为准。方向来源：[B/C/D 无进度条对照](2026-09-18-Holo无进度条动效方向对比.md)与[A 版对照](../../design-mockups/2026-09-18-holo-motion-study.html)。

## 产品结论

把几种动效放在不同的使用时刻，能让 Holo 有统一的行动叙事，同时避免每个页面都成为一场表演：**Today 用 C「聚光」帮用户找到眼前的一件事；任务用 B「活页归档」回应高频完成；Matter 用 D「生活拼贴」回看一件长期事项真实发生的变化。子任务保留当前 Holo 已有的直接展示与勾选方式，用简洁清单替代 A 的独立章节页。** 首页保留现有入口位置，主要改变其表达方式。

这份原型回答“从哪里进、看到什么、做完去哪里”。它是设计提案，不是 iOS 已实现的页面或数据验证。示例任务“整理日本旅行证件”仅用于串起三个 use case。

## 入口与页面地图

| 用户从哪里进入 | 当前 Holo 的导航事实 | 原型展示的页面 | 融入的动效 | 性质 |
|---|---|---|---|---|
| iPhone 首页中央球体 | 打开 Today 全屏页 | Today 顶部焦点、Matter、今日安排 | 球体去掉三环比例；焦点卡用 C | 入口现有，视觉提案 |
| iPhone 首页五角形「任务」 | 打开任务模块，默认今日任务；卡片当前可平铺最多五条子任务 | 卡片内可勾选步骤、任务详情 sheet | 子任务保持可见；完成反馈用 B | 入口与子任务平铺现有，视觉提案 |
| Today 顶部焦点「查看任务」 | 打开对应任务详情 | 任务详情 sheet | 完成后 B 归档，返回 Today 时 C 换到下一件事 | 路由现有，完成状态需统一 |
| 任务详情中的子任务 | 当前已在详情中直接展示完整清单 | 标题与属性下方直接显示所有真实步骤 | 轻量勾选状态，无进度条和单独章节页 | 内容与操作现有，视觉简化提案 |
| Today 的事项卡 /「全部进行中的事」 | 进入 Matter 详情 / Matter 列表 | 事项详情、列表 | 详情中用 D 展示真实变化 | 入口现有，视觉提案 |
| Matter 详情的关联任务 | 通过现有深链进入任务模块与任务详情 | 任务详情；完成后任务模块 | B 完成反馈；显式「返回进行中的事」 | 深链现有，返回来源桥接为新增提案 |
| iPad 侧边栏「今天」「任务」 | 分别进入相应页面 | 对应 Today 与任务内容 | 沿用同一页面角色，重新适配宽度 | 入口现有，iPad 视觉待单独设计 |

主入口不增加一层“动画首页”。C 是 Today 的首屏焦点卡，并露出当前任务的下一条真实子任务；D 只出现在具体 Matter 详情及未来的日回顾；B 在用户完成任务时发生。任务列表直接展示子任务标题和勾选状态，不增加横向进度表达。

## Use Case 1：早上只想推进一件事

**情境**：东林打开 Holo，想到国庆日本旅行还有准备工作，但不想先浏览整个任务库。

1. 首页中央球体显示“今天”与简短的当日线索；点它进入 Today。
2. Today 顶部 C 焦点卡展示真实规则选出的“整理日本旅行证件”、来源，以及下一条未完成的真实子任务。卡片下方仍有进行中的事、今日安排等内容。
3. 点“查看任务”打开该任务详情 sheet；所有真实子任务直接展示，可在原位勾选，无需再次进入子任务页面。
4. 完成任务时，B 的纸页反馈短暂出现，并持续提供可撤回入口。若未撤回且保存成功，Today 由同一份任务状态更新，下一条有依据的行动进入焦点。
5. 返回 Today 后仍能在安排中找到已完成任务，不因焦点替换而丢失刚才的事实。

**用户得到的感觉**：先知道“此刻做什么”，做完马上知道“刚完成了什么、接下来是什么”。焦点不依赖百分比或持续闪烁。

## Use Case 2：有明确清单，连续处理任务

**情境**：东林知道自己要逐条核对旅行材料，想快速完成和撤回。

1. 首页五角形的「任务」进入任务模块，默认今日筛选；保留统计、任务、纪念日、新增等模块入口。
2. 任务卡直接列出真实子任务；用户可以在列表勾选，也可以点任务标题进入详情查看和处理完整清单。示例三项全部展示，正式设计沿用当前卡片“最多先展示五项，超出时明确提示”的规则。
3. 最后一条子任务完成时，沿当前 iOS 的父子联动规则完成主任务；也可从任务详情主动完成。任务收为一条写有真实标题的 B 记录，下一任务留在列表可立即操作。3 秒内撤回，记录回到待办状态；由最后一条子任务触发的完成也需恢复该条勾选状态。
4. 重新打开列表、筛选或冷启动时，只渲染最终业务状态，不重播完成动效。

**用户得到的感觉**：做过的事留下可读记录，连续操作仍然轻快。大数字、环和横向条不再同时争夺注意力。

## Use Case 3：从一件长期事项返回行动

**情境**：东林想回看“国庆去日本”推进到了哪一步，并处理其中一条相关任务。

1. 首页中央球体 → Today → 事项卡，或 Today →「全部进行中的事」→ 选中事项。
2. Matter 详情上方保留“现在最值得做”的真实下一行动；下方 D 用少量纸片承载已发生的任务和事件。每片都可追溯标题、时间、来源；缺少关联证据就显示普通记录。
3. 点“查看任务”沿现有深链进入任务模块和任务详情。完成后在任务模块提供“返回进行中的事”来源桥接，这是新增导航提案。
4. 返回 Matter 后，只有真实任务完成回执与 `MatterLink` 确认时才增加新纸片、更新下一行动。撤回窗口内不生成永久纸片；撤回或取消完成后，当前完成呈现必须同步更新。

**用户得到的感觉**：一件事不再只是抽象的完成率，而是能看见具体哪几步曾被处理。用户可以从回看到行动，再回到原事项。

## 页面与状态规则

| 状态或事件 | Today C | 任务 B | Matter D |
|---|---|---|---|
| 未完成 | 一件可执行焦点，注明来源和下一条真实步骤 | 卡片内直接展示子任务，可勾选或进入详情 | 当前下一行动 |
| 用户点完成，撤回窗内 | 焦点可先切换但显示可撤回反馈 | 当前行收为标注待确认的临时归档记录 | 不增加永久完成纸片，维持已确认的最近变化 |
| 撤回或保存失败 | 恢复原焦点与任务状态 | 恢复待办行，失败说明可读 | 移除临时变化，不留已完成纸片 |
| 保存成功 | 新焦点来自真实 Today 规则 | 留下稳定的完成记录 | 有真实关联时新增可追溯变化 |
| 冷启动、同步、重新进入 | 只显示当前状态 | 不重播归档动效 | 不重播纸片落下动效 |
| 无任务或无关联事项 | 显示可行动或休息的清晰空态 | 保留新增与筛选 | 保留文字记录，不编造拼贴素材 |

**实现门槛**：当前 `TaskCardView` 已平铺子任务、最多先显示五项；`TaskDetailView` 已内嵌完整清单，且全部勾选会联动主任务。原型上一版把子任务藏进独立页面，与现状不符，现已修正。现有任务列表支持待撤回完成，Today 的直接完成流程不同；先统一完成、撤回、落库失败的业务语义，再接同一套跨页面动效。Matter 必须使用真实实体 ID、`MatterLink` 和回执，不凭标题猜测关联。聚光焦点必须遵循本地 Today 规则，不能由视觉层虚构推荐任务。

## 原型交互与实施顺序

HTML 左侧选择三个 use case，手机内可点入口、任务卡内的子任务、详情中的完整子任务、完成、撤回和返回；右侧同时解释该步哪些是当前 Holo 已有的页面或路由，哪些是新提案。页面不连接用户数据。原型的固定日期、任务名和 3 秒撤回仅用于展示节奏。

1. **先确定完成状态契约**：Today 与任务列表共用同一事务和撤回语义，失败不播放“已完成”。
2. **先落 B 的任务切片**：保留卡片和详情内的子任务平铺，移去重复进度条；验证连续勾选、父任务联动、归档和撤回，在真机上调到高频使用不拖沓。
3. **再落 C 的 Today 焦点卡**：焦点来自现有规则，验收是否更快找到下一件事。
4. **最后用真实关联事项落 D**：完成、撤回、冷启动、跨设备同步均能追溯同一任务；补 Matter 来源返回入口。
5. **A 不进入当前融合方案**：独立章节页增加一次点击，也让子任务变隐蔽。保留 A 原型作为对照，当前方案采用直接可见的简洁清单。

验收应让试用者不看说明，从首页分别走完三条路线，并复述“刚完成什么、可否撤回、返回哪里、下一步从何而来”。再连续完成多项检查疲劳感，使用 Reduce Motion、动态字体、VoiceOver、深浅模式和小屏设备检查可用性。此轮只交付设计原型与规格，尚无 iOS 实现、真机结果或留存证据。

## 视觉评审结论：保留原版

东林已选择本文开头链接的**原版融合动线 HTML**。它的宋体标题、纸张底纹、印章、胶带和深色聚光舞台，是本轮局部页面需要保留的审美特征。此前的[Holo 风格版 HTML](../../design-mockups/2026-09-18-holo-motion-holo-style.html)保留为评审记录，交互动线相同，视觉不进入本轮实现。正式 iOS 实现仍需将选定语言转成设计 token，而不是复制 HTML 色值或时长。

| 页面 | 已选原版 | 未选的 Holo 风格候选 |
|---|---|---|
| 首页 | 橙球周围有纸面、暖棕和手帐感 | 保留橙色光球、五角形玻璃入口与柔和环境光；球体不承担三环比例 |
| Today | 深色聚光舞台 | 白色圆角焦点卡，仅在焦点区域有一处橙色柔光；标题、来源、下一子任务和按钮稳定可读 |
| 任务 | 活页、纸边、印章和“今日事簿” | 白卡直接展示子任务；完成后收成写有真实标题的轻量记录，短暂浮层确认，无纸张翻页 |
| Matter | 倾斜纸片与胶带拼贴 | 真实事件成为两张简洁微卡，保留标题与来源；没有虚构图片或装饰性时间线 |

本轮继承 B/C/D 的**交互职责与原版材质**：B 解释完成去了哪里，C 帮用户看见眼前行动，D 让长期事项能回看真实变化。动效只在主动操作或真实状态更新时触发；减少动态效果下以直接状态切换表达同一事实。实施顺序、数据门槛和回退见[定稿与实施方案](2026-09-18-Holo动效融合定稿与实施方案.md)。
