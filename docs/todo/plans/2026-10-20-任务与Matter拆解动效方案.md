# 任务与 Matter 拆解动效方案

日期：2026-10-20。阶段：产品动效提案；未修改原生业务代码，未接真实模型，未做原生或真机验收。

## 产品结论

拆解动效要让用户感知三个事实：原任务仍然存在；小步骤来自这个任务；现在知道可以从哪里开始。推荐「原任务展开成小步骤」的统一视觉语言，以卡片展开、父子关系和第一步落位形成仪式感。

空间叙事：一张原任务卡 → 卡片下面展开真实的小步骤 → 用户检查或修改 → 确认保存 → 小步骤落回原任务，第一步获得轻强调。原任务始终保留标题与未完成身份。

动效成功不以华丽程度判断，而以用户看完能说清楚「拆了哪件事、拆出了什么、准备先做哪一步」判断。拆解不等于已经完成任务。

## 推荐动效编排

以下是首轮参数，真实等待时间由服务决定；动画不制造额外的固定等待。

| 时刻 | 用户看见什么 | 参数与意义 |
| --- | --- | --- |
| 点「拆成几步」 | 原任务带着完整标题进入拆解页的顶部，周围内容退到次层级 | 180–240ms。优先稳定标题与卡片位置，避免只看到一个没有对象的转圈 |
| 等待真实结果 | 卡片轻托起，边缘低频呼吸；保留「琢磨怎么拆…」和取消 | 呼吸周期约 1.8s；不展示虚构进度、阶段完成或子任务数量 |
| 结果准备好 | 原任务略收拢，底部卡片轮廓展开为步骤；每张步骤卡从父卡底缘移动到自己的位置 | 单卡约 500–620ms，错开 70–85ms；四步约 850–950ms 完成。父卡稳定保留，连线在关系清楚后降低存在感 |
| 检查建议 | 全部文字保持完整可读，显示「拆成这 N 步」，沿用当前可改、可删、可加 | 不逐字打字；不要求逐张点击揭晓；提供「直接查看」跳过剩余展开 |
| 点「行，按这个来」 | 按钮显示正在添加；真实保存成功后，拆解页退场，原任务下的新步骤展开落位，第一条可行动的新步骤轻强调 | 保存后的过渡目标 350–450ms。任务详情展开子任务区；Matter 在原下一步卡中显示所属任务与第一步，并提供查看全部入口 |

触感：默认最多两次轻反馈，分别在结果展开的关键瞬间和保存后落位时；避免每出一步震一次。默认无声音。降低动态效果时取消空间位移与呼吸，直接展示结果，最多约 120ms 淡入。

正常路径在真实结果可用后的额外动效预算约 1.3 秒，分布在结果展开与确认后落位两个阶段。用户阅读和编辑时间独立计算。

## 任务与 Matter 的差别

- 任务详情：原任务 → 本任务的子任务。采纳后返回原位置展开新步骤；用户无需再次寻找新增内容。
- Matter：Matter 标题维持上下文，演出对象是「当前下一步对应的任务」。例如「准备上海出差 → 订好往返交通 → 确认日期、选车次、订票、分享行程」。不把整件 Matter 消失成一堆平级待办，也不把子任务计成 Matter 新增的顶层计划任务。
- 两处共用展开时长、弹性、卡片形态与触感。差别放在落位位置及上下文，不各做一套独立动画。
- 第一步强调仅是视觉指引，不自动开始计时、完成、改日期或加入今天。若首步处于等待态，保留等待含义，不提示它立刻执行。

## 边界与异常

- **AI 需要澄清**：原任务卡保留，下面出现「先问一句」。只有真实步骤返回后再展开；不先播放成功动画。
- **生成失败、额度耗尽或暂时无法帮助**：保留原任务，展示对应原因及可用操作；不出现步骤轮廓落位或成功触感。
- **保存失败**：建议与用户编辑保留在当前页，说明未添加并允许重试；不关闭、不出现成功回执。
- **只有一步**：仍保留父子关系，以展开一个步骤呈现，不伪造多个块营造拆分数量。
- **已有子任务再补拆**：只让本次新增的 N 步出现；已有步骤、完成状态与等待态保持稳定，文案使用「补充 N 步」。不重播整份清单。
- **步骤较多**：最多前 3–4 条依次展开，其余同批就位；动画总时长不随数量无限增长。仅在当前可见区域演出，不自动滚到列表底部。
- **长标题、大字体、横屏、iPad**：动态测量卡片与锚点，支持换行；不固定文字高度或假设每一行一样高。
- **关闭、切换任务或进入后台**：本轮演出结束。回到页面直接呈现真实的草稿或保存结果；不因界面刷新、CloudKit 同步重新播放。
- **VoiceOver**：一次播报「已生成 N 个建议步骤，待确认」及保存后的「已添加 N 个子任务」；不逐帧播报，不移动阅读焦点。

## 原生实施方向

1. 在共享 `TaskSplitSheet` 内新增生成结果的呈现阶段，保持现有澄清、失败、额度与编辑分支。拆分「数据已经准备好」与「动画正在展开」两个概念；跳过动效直接进入可编辑建议。
2. 提取 `TaskSplitRevealView` 和 `TaskSplitMotion`，统一卡片、节奏、辅助功能及结束策略；按实际布局计算原任务与步骤锚点，动画只改变呈现，不改变步骤顺序或内容。
3. 把当前 `onConfirm: (...) -> Void` 改为可明确返回保存结果的接口。当前宿主捕获写入异常后，sheet 仍无条件 `dismiss()`；接动效前应先让成功/失败有真实反馈，成功结果携带本次提交的子任务 ID。
4. 任务详情和 Matter 接收同一份保存回执，只对本轮新增 ID 做一次落位动效。跨 sheet 的过渡以源与目标快照/布局锚点衔接，不假设跨展示层的 `matchedGeometryEffect` 自然连续。
5. 如目标列表尚未展开或尚未完成布局，先确保正确目标可见，再做短距离插入；动效结束清理快照，真实列表恢复全部交互。

首轮聚焦原生呈现与保存反馈，无需为动效增加模型调用或修改后端 Prompt。

## 验收

- 不提示用途，用户看完能指出原任务、至少一个子任务及推荐起点；同时知道建议未采纳前还未添加。
- 等待 1 秒与等待 15 秒都不会播放虚构结果；结果可用后约 1 秒内完成展开，且可跳过。
- 首次拆解、补拆、澄清、失败、保存失败、退出与后台恢复均有对应真实状态。
- 两入口保存的子任务完全相同；动效重播、快速点击和数据刷新不重复创建步骤。
- 保存后回到原入口可立即找到新增内容；Matter 顶层计划数量与原完成规则不被动效改变。
- 大字体、降低动态效果、VoiceOver 与真实设备性能单独验收；HTML 示意不作为这些项目通过的证据。
