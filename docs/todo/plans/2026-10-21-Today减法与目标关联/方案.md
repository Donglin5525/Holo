## 产品结论

截图对应 `DailyKanbanView` 的「今天」，不是目标管理列表。问题在于它承担了太多职责：替用户判断优先级、展示安排、展示 Matter、承接 AI、习惯和财务摘要。模块分别有用，聚在一起却让用户不断重新判断看哪里。

建议把今天页收敛为一个问题：**今天准备做什么？这些行动在推进什么？**

目标负责方向、成果和回顾；今天负责当日选择与执行。强关联通过同一行动的双向可见、一次完成和结果回看建立，不通过添加目标看板建立。

延续 10 月 20 日《目标闭环：最终方案与 GLM 实施交接》的固定边界：不增主导航，不合并目标与任务系统；目标管理仍从「个人 → 我的目标」进入。今天的目标文字是直达对应目标详情的上下文入口，不把目标列表搬进今天。本方案仅重新评审今天页的信息层级，不覆盖昨天的目标计划/报告/修正确认契约。

## 页面做哪些减法

| 现在 | 建议 | 用户得到什么 |
|---|---|---|
| 大号主行动卡 + 下方另一份安排 | 合为一份连续行动列表；同一行动只出现一次 | 看一处、做一件，减少上下反复找 |
| 红色「需要马上处理」和安抚句 | 普通历史逾期压成一行事实提醒；具体任务可查看 | 保留风险，不把逾期天数自动等同于当下最重要 |
| 橙色大按钮「查看任务」 | 点任务正文进入详情；左侧一个完成控件 | 一个圆只承担一个动作，消除两侧圆形的歧义 |
| 「帮我理一理」单独占一张卡 | 顶栏「调整」，进入现有 TodayReliefSheet | 有困难时随手可用，日常不抢执行位置 |
| 每个模块一个小标题、一张底板 | 主要列表 + 必要的轻量入口 | 去掉多层容器和弱信息标题 |
| 习惯统计区 | 普通情况只留一行「习惯 0/6」，进入原习惯模块 | 不在今天再造一套打卡页 |
| 支出 ¥0 / 预算正常 / 对 Holo 说 | 撤掉常驻财务摘要和重复 AI 入口 | 无需在做任务时顺带处理财务 |
| 「正在推进」Matter 独立摘要墙 | 已有可执行行动归入同一列表，并按真实任务 ID 去重；无独立行动的 Matter 留在原入口 | 少一个列表，保留原执行对象和上下文 |

移除的是常驻摘要，不撤销原模块入口、日程、提醒或风险数据。财务异常若确实需要行动，进入原有风险处理路径；不能因隐藏摘要而把真实提醒吞掉。

默认折叠展示前三件今日选择，更多项用「展开其余 N 件」；这是展示阈值，不是三件的硬限制，也不自动删除、延期第四件。固定日程、正在进行的事项、带具体时刻的临近截止必须及时可见，不能被三件折叠挡住。同一任务同时被选中且有期限，在原行携带时间，不再复制。

未建立今日计划时，显示候选和「选入今天」，不能把系统推测包装成「你今天决定做」。用户明确选择今日休息时，展示主动留白；与无计划、全部做完、正在同步、读取失败分别处理。

## 目标强关联的四个接点

### 1. 从方向落到今天

目标详情继续组织关联任务、习惯与成果。关联任务可「选入今天」，调用统一日计划服务；只选择已有真实行动，不复制任务，不把整个目标全部塞进今日。

「调整今天」在原选择流程中展示来源目标，也允许按目标筛选候选。优先尊重已确认的固定安排、临近风险与用户顺序；目标相关性辅助用户选择，不默认让有目标的事压过看病、缴费等日常必要事项。AI 可以提出建议，确认后才改变今日选择。

### 2. 执行时看见为什么

有关联的任务，在标题下加一行「目标名 ›」；有可信的主要数值结果时可呈现「北海道旅行 · ¥4,800 / ¥18,000 ›」。用次文字色、小型目标图形及可读标题，不加彩色标签墙、多条目标进度条、领域、优先级等并列信息。点任务看任务，点这行看同一目标；两个热区各自明确，至少 44pt。金额长时在同一关联入口内自然换行，不压缩字号。

无关联任务不显示「未关联」、空标签或强制补齐入口。任务详情提供「关联目标」可选项，允许「暂不关联」。AI 只建议，不按标题自动替用户建目标或绑定。

已有计划绑定支持共享对象时，今天仍只出现一行；多目标只露出主要展示目标及「另 N 个」，展开后选择。主要展示目标只是 UI 选择，不能改写旧父关系或新增一套互相矛盾的归属规则。

### 3. 完成后形成真实反馈

完成反馈只说「已完成一项行动」，可带目标名并允许撤销。原任务完成一次，今天和目标读取同一事实。完成现有子步骤时仅反馈步骤完成，不自动完成根任务；不能因为完成一个任务就把长期目标判为达成。

目标详情将「成果」和「行动」分开：发布类目标展示是否通过约定验收，运动量类按真实累计量，体重类按实际观测。任务完成率最多叫行动完成情况，不作为通用目标成功率。

例：完成「记忆萃取支持 push」后，Holo 发布目标显示多完成一项行动；仍需发布验收和上线结果才能确认目标达成。原型中的任务名称来自截图，目标名称、关联及状态均为合成示例，不代表用户现有数据。

### 4. 回到目标看结果和下一步

点目标先查看主要成果进度，再看行动与下一项可选行动；下一步由用户选入今天，不在完成上一件后自动加任务。回顾沿 10 月 20 日的目标分析方案进入同一 HoloAI 报告和修正确认链，不创建第二套报告。数值目标在详情顶部保留当前值、目标值与进度条；本次减法不删除原有量化进度。

两类判断必须清楚：行动做了而结果未变，需要回顾方法；缺结果记录，只能说尚不能判断成果。暂停目标停止目标专属催促，但不自动取消独立任务、共享习惯或原截止日。详情返回保留今天的选择和滚动位置。

## 2026-10-21 补充：保留成果进度，覆盖旅行资金闭环

已重新读取会话《梳理目标与模块关联并补齐能力》中东林的原始要求及 10 月 20 日最终规格。原故事是：过年去北海道，每月存 3,000；两个月后发现进度落后，分析支出原因，按需新增四周阶段习惯，确认后将后续每期调整为 3,300。东林同时明确：这是一条适用于存钱、减重、学英语等目标的通用闭环；保留产品现有布局，记录仍回原模块，报告由目标和 HoloAI 承载。

上一版原型只画了发布类目标的行动和待验收说明，遗漏了量化成果展示。**这属于原型覆盖缺口，不能成为删除既有进度、记录或统计能力的实施依据。** 任务的日历/四象限/列表、目标的数值记录/进度、各模块设置、提醒及归档等原有功能保留；本次改造范围仍是今天的信息层级与上下文关联。

### 三处展示，各有职责

| 位置 | 旅行目标显示什么 | 控制信息量 |
|---|---|---|
| 今天的关联行动下面 | 北海道旅行 · ¥4,800 / ¥18,000；点击目标详情 | 只带一项主要成果摘要，不增加整排目标卡片，不默认挂所有目标 |
| 原有目标列表 | 当前金额 / 目标金额、26.7%；与详情同源 | 保留原列表及入口，进度不能依赖用户是否把任务选入今天 |
| 目标详情顶部 | 已准备 ¥4,800、目标 ¥18,000、还差 ¥13,200、26.7% 进度条、来源与更新时间 | 主要成果优先；行动完成数和阶段习惯放在下面分别展示 |

这里的 18,000 / 4,800 / 6,000 皆沿用已讨论规格的**合成示例数字**，不代表东林账户或实际储蓄。原始用户故事只给出 3,000 → 3,300 的计划变化。

### 保留完整的计划与反馈链

1. **设置与拆解**：确认主要结果、实际截止日期、六个存入期次、可承受投入和资金来源；不能只靠「过年」自行假定某日，也不能靠打卡制造储蓄结果。
2. **确认建立**：复用已有任务/习惯/预算或按需建立；用户逐项确认，不因目标变多重复创建相同行动。
3. **原模块执行**：财务记录资金、核对余额，习惯记录次数，任务完成行动。各自只记一次，目标只读取。
4. **看进度找差距**：两期后原计划应有 6,000，实际 4,800，少 1,200；后续四期所需为 `(18,000−4,800)/4=3,300`。行动完成本身不改变资金余额。
5. **回顾原因**：区分财务明细证据和推测。餐饮总额不能单独证明奶茶/宵夜增加；需要明细或用户确认。可选阶段习惯由用户确认每周次数等规则，不套一个默认的健康或消费标准。
6. **确认修正**：展示每期 3,000 → 3,300，可单独选中；四周阶段习惯可不采用；既有预算如需调整须单独展示全局影响。总目标 18,000 和原截止约定不静默改变。近两期实际平均 2,400，新安排多 900，不能把预计节省当成已经存入。
7. **再验证**：财务补齐余额至 6,000 后，成果更新为 33.3%、还差 12,000；旧的 3,300 建议标记需刷新。新计算是每期 3,000，但必须确认后才更改已采纳的计划，不能自动降回。

### 资金事实与通用成果规则

- 首期可读取用户确认确实用于旅行的单一财务账户余额；已有起始资金只计算一次。目标不再造一份存钱账，不替用户转账或自动创建账户。
- 选择全账本净结余增加时必须使用这一真实名称，不改称专项旅行资金。账户不专用于旅行或多个目标共用同一笔钱而无法分清时，不伪造已经分配完成；多目标资金分配仍是未覆盖边界。
- 没有可靠来源显示「资金来源待补齐」，保留目标总额，但不显示 0 元、0% 或失败。来源与更新时间必须可查看；来源变化时复核建议。
- 减重目标显示最新真实观测、目标与趋势；能力/成果型目标显示里程碑和证据。两者均不由任务/习惯完成率代替结果。通用链路和报告复用继续以 10 月 20 日最终规格为准。

## 版式与状态

沿用 Tool 品牌色、系统字体、页面 20pt 边距；浅色 `#FDFCF8`，深色 `#0E0E10`；品牌橙用于选择和操作，不给所有次级入口上橙色。正文 17pt、次文字 15pt、元信息 13pt，控件至少 44pt。连续列表不逐项套卡；独立浮层 24pt 圆角；尊重减少动态效果。

| 情况 | 页面表现 |
|---|---|
| 日常已有计划 | 一份今日列表、条件性风险提示、习惯一行、全部任务入口 |
| 只有一件事 | 一件正常大小的任务，不靠放大卡片或加统计填满屏幕 |
| 暂无目标 | 普通任务照常可做，不强迫建立目标；详情可主动关联 |
| 全部完成 | 已完成收起，允许展开和撤销；不自动推送下一批候选 |
| 长标题 / 大字体 | 正文换行，目标链接独立一行；不截掉唯一关键动作 |
| 同步中 / 读取失败 | 分别显示真实状态；已有缓存可继续查看，失败可重试；不显示假空态 |
| 临近具体截止 / 进行中日程 | 必须可见的约束条；与选中任务合并去重，可进入详情处理 |
| 历史逾期 | 事实摘要入口，可查看和选择；非一律当成最高优先级 |
| 无今日计划 / 主动休息 | 分别显示待选择 / 已明确留白，不和加载或全部完成混淆 |

原型覆盖上述日常、少量、无目标、完成、长标题、同步、失败、临近截止、无计划和主动留白；额外提供深浅模式与大字号切换。原型交互仅使用内存模拟，没有接真实数据、AI 或同步。

## 建议实施顺序与验收

1. **先减页面**：统一列表、收起重复 AI/财务/Matter 摘要、单一完成控件；保留硬时间约束、更多项和真实状态。可单独回退页面排列，不迁移数据。
2. **再接目标**：有效关联投影 → 目标详情跳转 → 选入今天 → 同一完成/撤销事实回流。无关联保持可用，共享对象不改原归属。
3. **最后联动回顾**：按昨天的目标闭环规格接同一报告和修正确认；需要 AI/后端变更时另走双端与发布流程。本轮没有新增后端工作。

验收重点：同一任务只出现一行；一个完成控件；第四件和临近截止能找到；选入今日不改 `dueDate` / `plannedStart` / `plannedEnd` / 提醒；完成/撤销双向同步；步骤完成不变成目标达成；无目标不被强迫绑定；有效/结束/删除绑定不串；同步失败不回退成空白；窄屏长标题和大字号可用。原生实施再分代码专项、模拟器、真机、iPad 与双设备验收，本地 HTML 不代替这些结果。
