# Today：只读概览与原模块边界

2026-10-21。东林明确修正：今天不承担与原模块冲突的功能，记账去记账模块，任务去任务模块。此边界已经明确；下列页面外观仍为原型评审稿，本轮没有修改原生代码。

## 已明确的职责

今天只汇总当天事实、展示关注目标的进展、跳到原模块的对应对象或范围。

- 不在今天新增/编辑账单，不做自己的记录入口、任务完成、习惯打卡、任务拆解或当天重排。
- 不把原模块编辑器包在今天自己的新增流程里，也不在保存后强制拉回今天。
- 跳转到原模块后，按原模块自己的导航、编辑器和规则操作。用户正常返回今天时，再从同一事实源重读摘要。
- 今天不创建第二份安排、财务数据、习惯记录或跨模块日志，也不在今天新建一套模块管理菜单。
- 目标本身的规则、进展、回顾和长卷仍属于目标；其中原始事实的处理仍回其来源模块。

上一版 `holo-today-one-flow.html` 中“＋统一新增、今天内调整/预览/采用、内嵌记录表单”的方向不再作为实施依据，不能只改文案继续保留这些操作。

## 新页面逻辑

1. 页首只给事实：今天有多少待办、有没有日程，不替任务模块选择“现在必须先做哪件”。
2. 关注中的目标显示少量进展摘要。旅行专款与准备任务分别展示；多个习惯各保留单位、要求和覆盖，不求平均完成率。无目标时整块不出现，不强制新建目标。
3. 今天的安排只读任务/日历已有内容。任务点击定位原任务详情；日程点击原日程；“查看全部”进入原任务模块。
4. 当天近况只显示有上下文的事实，例如阅读今日尚未记录、今天真实支出。点击是到习惯或记账模块核对，不是今天的快捷编辑。
5. 当天没有内容时不给虚构的0分、健康正常或假完成率；提供原模块的清楚去向，建立内容的操作仍在原模块。

## 路由契约

| 今天的内容 | 目的地 | 返回后的读取 |
|---|---|---|
| 某条任务 | 原任务模块的同一taskID | 完成状态与待办数 |
| 今天阅读 | 原习惯模块的同一habitID、今天范围 | 当天真实时长，缺失仍是未知 |
| 目标内阅读条件 | 同一原习惯、目标统计范围 | 最近7天时长与目标判断 |
| 今日支出 | 原记账模块的当天范围 | 原账单求和，不另存今天总额 |
| 旅行专款 | 原记账模块的既定账户 | 账户实际余额；任务完成不增加专款 |
| 目标摘要 | 原目标详情的完整长卷 | 继续读取同一目标版本和来源事实 |

返回路径保留来源与目标上下文。记录在原模块保存后停在原模块；不利用“完整动线”把所有功能塞回今天。原有全局导航与全部模块入口保持原职能。
