# Holo 动效融合定稿与实施方案

> 2026-09-18 · 视觉方向已选定，iOS 尚未实施。东林选定的唯一视觉基准：[从入口到完成的 HTML 原型](../../design-mockups/2026-09-18-holo-motion-integrated-journey.html)。[Holo 风格版](../../design-mockups/2026-09-18-holo-motion-holo-style.html)仅留作评审记录，不作为本轮实现基准。入口与页面说明见[用户动线规格](2026-09-18-Holo动效融合用户动线.md)。

## 1. 产品结论与范围

让用户感到“做过的事被 Holo 认真记住，眼前的下一步更清楚”，而不是看百分比不断增长。保留原型最有辨识度的三种表达：**C 深色聚光**只用于 Today 的一件焦点行动；**B 活页归档**用于任务完成的一次性反馈和可读记录；**D 生活拼贴**用于 Matter 详情里的真实变化。首页保留中央球体与任务入口；子任务始终在卡片和详情里直接可见。

本轮只覆盖首页入口、Today、任务列表/详情、Matter 详情及三者之间的导航。任务统计、习惯、财务、AI 对话仍用现有信息结构。原型中的宋体标题、纸边、印章、胶带与暖纸色是**已选的局部视觉语言**，不要在实施时统一改成白色卡片，也不要把整款 App 重做成手帐。日式感由 Holo 的品牌橙、现有球体和真实个人内容来平衡，不削弱原版的审美张力。

**本文件是开发规格与验收门槛，不代表 SwiftUI 已实现、真机走查或线上效果已通过。** HTML 使用固定示例数据，不能当作数据链路证据。

## 2. 用户从哪里进入、看见什么

| 入口与动作 | 目标页 | 承担的视觉职责 | 返回规则 |
|---|---|---|---|
| iPhone 首页中央球体；iPad 侧边栏「今天」 | Today | 首屏 C 聚光焦点；下方继续显示 Matter、安排、习惯和概况 | 关闭回原入口 |
| iPhone 首页「任务」；iPad 侧边栏「任务」 | 任务模块默认今日筛选 | B 纸页任务行；每行直接显示最多 5 条子任务，超出可展开 | 保留原筛选、滚动位置 |
| Today 焦点或安排点任务 | 任务详情 sheet | 完整子任务原位勾选；完成时 B 收页反馈 | 关闭回 Today，不额外压一层页面 |
| 任务列表点任务标题 | 同一个任务详情 sheet | 同一清单与完成规则 | 关闭回任务列表 |
| Today Matter 卡或「全部进行中的事」 | Matter 详情/列表 | D 仅在具体 Matter 详情展示 | 按进入路径返回 Today 或列表 |
| Matter 的真实关联任务 | 任务模块深链到任务详情 | B 完成反馈；展示“返回「事项名」”来源桥 | 完成/关闭后可一键回原 Matter；桥只保存导航上下文 |

不新增“动效首页”或独立子任务章节页。焦点卡只展示真实的下一条未完成子任务；若焦点不是任务，沿现有行动类型呈现对应按钮，不拼造清单。Matter 无可追溯变化时用文字记录/空态，不生成装饰纸片。

## 3. 视觉与动效规范

| 场景 | 静态基准 | 触发与运动 | 必须保留的信息 |
|---|---|---|---|
| 首页 | Holo 橙色球体、原位模块入口，减少环形比例视觉 | 点球体进入 Today 的一次过渡；待机不持续涨缩 | 「今天」「任务」等入口名称与可点击性 |
| Today C | 原型的深炭色聚光卡、暖橙局部光、克制的衬线大标题；其他区块维持清晰纸白层级 | 首次入场轻微显现；**只有焦点 ID 真正变化**时才柔和换位 | 焦点标题、来源、下一步、主按钮、风险提示 |
| 任务 B | 暖纸色任务行、细纸边、完成后带真实标题的纸页/印章 | 用户主动完成时一次收页与短暂回执；连续完成时后一次不遮挡前一次操作 | 子任务勾选、完成结果、撤回入口、错误信息 |
| Matter D | 少量有层次的纸片、轻胶带与纸张材质，不用虚构照片 | **首次确认真实新变化**时落下一片；重进页、同步和冷启动只显示静态结果 | 事件标题、发生时间、来源和可打开的原实体 |

静态内容优先可读，动效不承担唯一的信息传达。衬线字只用于聚光标题、任务回执和 Matter 纸片标题；正文、按钮、清单继续使用 Holo 的系统中文字体。沿用 `DesignSystem.swift` 的品牌色与语义色，新增纸面、墨色、暗光等局部 token 时必须分别定义浅色/深色。不要直接复制 HTML 的 px、hex 和缓动值到业务视图；运动从 `HoloAnimation` 取值，确需新节奏则先在 token 层命名。原型的 3 秒是交互目标，开发须在同一完成状态契约下实现。

减少动态效果时，收页、落纸、光晕位移全部变为即时状态切换，保留文字回执和撤回。VoiceOver 按“任务标题—子任务状态—完成/撤回”播报，纸片读出标题、时间和来源；动态字体放大后清单可换行，点击区域不能缩小。聚光卡是局部深色区域，系统深色模式下仍需独立检查对比度。

## 4. 完成与撤回：先统一事实，再播放画面

目前 `TaskListView` 走 `TodoRepository.startPendingCompletion`，3 秒后落库；`TaskDetailView` 与 Today 直接切换完成状态。`TaskCardView` 子任务全勾会触发父任务完成，但子项先保存，撤回父任务不等于撤回最后一项。`HoloMatterLinkedEntityChangeCoordinator` 已按真实 task ID 处理变更，不过当前关联任务事件在 Matter 详情只显示“关联了新内容”，不足以支撑原型的完成纸片。因此第一阶段要统一业务契约。

HTML 为了快速演示，在完成按钮点下后就能看见 Matter 新纸片；**正式产品按下表执行，以保存成功为新增永久纸片的时点**。这是对演示数据时序的校正，纸片的视觉样式仍以所选 HTML 为准。

| 状态 | 任务列表/详情/Today | Matter D | 导航与回执 |
|---|---|---|---|
| 未完成 | 清单可操作，父任务是未完成 | 显示已确认的旧记录 | 无完成动效 |
| 用户完成，撤回窗口内 | B 可以显示**明确标注为待确认**的临时记录；撤回始终可见 | 不增加永久纸片、不刷新成“已完成”结论 | 保留来源页与任务 ID |
| 用户撤回 | 父任务回未完成；若由最后一条子任务触发，恢复该条先前状态；其他已完成子项保留 | 无新增完成纸片 | 取消回执/动画，焦点回到原状态 |
| 窗口结束且保存成功 | 稳定完成记录；Today 用同一份真实状态重新选焦点 | 有 `MatterLink` 才生成对应变化；用真实任务状态和事件证明完成 | 完成一次只播一次，不因视图刷新重播 |
| 保存失败/任务已删 | 恢复可操作状态，说明失败并允许重试 | 不显示完成纸片 | 不吞错误，也不让 UI 长留“已完成” |
| 取消完成、同步覆盖、冷启动 | 依最终业务状态显示；本机主动取消完成可有轻反馈 | 已撤回/取消完成的任务不再以“当前已完成”展示；历史事件需有明确撤回语义 | 不补播用户没有亲手触发的动效 |

建议由一个**完成操作协调层**持有 `taskID`、来源入口、可选 `checkItemID`、变更前快照、操作状态、撤回期限和持久化结果。所有入口调用同一条业务操作，视图只订阅结果。若窗口内连续完成多项，不要沿用“新任务把上一项直接确认”的隐含规则；应明确每项的撤回责任，至少确保 banner 所指任务、父子项状态和实际落库一致。重复任务的“生成下一实例”、计划时间任务的实际时长询问也须走同一状态协议，不可被纸页动画跳过。

**Matter 事实契约**：通过 `HoloMatterLink(matterID, entityType=.todoTask, entityID=taskID)` 找到关联任务；依据持久化后的任务完成状态和类型化完成/撤回事件建纸片视图模型。事件需要可稳定去重的键和准确发生时间；同一任务重复投递不生成双份纸片。`HoloMatterEvent.kind=.completed` 当前表示 Matter 本身完成，不可借用来表示关联任务完成。当前 `.linkAdded` 的通用文案也不能直接改成“任务已完成”；应为关联任务变更建立清楚的事件语义/映射，并让旧事件仍可解码。AI 的 `nextAction` 投影若已过期，不用旧结论装作新下一步；优先显示已验证的当前任务或明确空态。

## 5. 子任务：可见且简洁

- 列表：保持现有“默认最多 5 条，超出可展开”；行内显示真实标题与勾选态，空白任务不显示清单壳。任务详情显示全部真实子任务。勾选区域与打开详情区域分开，防误触。
- Today：当焦点对应真实任务且有清单时，只提示**下一条未完成**的步骤；点主按钮仍进任务详情。所有项已完成时不显示旧步骤。
- 移去任务卡和详情中重复表达完成比例的迷你条；可保留“已完成 2/5 项”这样的辅助文字，但文字也不能盖过具体步骤。统计页的总体任务数据另行评估，不在此轮一刀切删除。
- 最后一项触发父任务完成时，撤回必须恢复最后一项的原值；父任务手动完成时按现有不变式级联勾选全部子项，重开任务时先确定恢复策略，避免“父未完成但所有子项已完成”造成再次自动完成的循环。
- 列表、详情、Today 展示同一 `taskID` / `checkItemID` 的结果，页面往返不能出现一处已勾一处未勾。

## 7. 验收用例与交付证据

**主旅程**：用自然输入“国庆要去日本，要提前准备什么”产生真实 Context Plan、任务和 Matter，核对真实任务 ID、来源键与 `MatterLink`；从首页分别走 Today、任务、Matter 三条路线。完成“整理日本旅行证件”的最后一条子任务后，检查父任务、B 回执、撤回、Today 下一焦点、Matter D 纸片与“返回进行中的事”。不要用 `MatterDemoSeed`、固定标题匹配或 HTML 状态模拟替代。

**边界用例**：0/1/超过 5 条子任务；最后一项后立即撤回；手动完成/取消完成；连续完成 5–10 项；重复任务；带计划时间段任务；保存失败；关联任务被删除；无 MatterLink；相同变更重复投递；重进页、冷启动与跨设备同步。每项检查“画面说的是否与持久化事实一致”，尤其是撤回后旧纸片和旧焦点不能残留。

**体验门**：iPhone 小屏与大屏、iPad 双栏与旋转、浅/深色、动态字体最大级、VoiceOver、Reduce Motion；高频点击时按钮可用、动画不遮挡撤回、没有常驻循环动画。需要上真机安装包时，先按 `HOLO/AGENTS.md` 的五大入口模拟器冒烟规则完成文字结论，随后补真机任务旅程；双设备 CloudKit 是独立证据，不以单机截图代替。

交付时按以下格式回报，避免把方案或编译误写成上线：

1. **完成范围**：G 阶段、绝对文件路径、用户可见变化、视觉开关状态。
2. **业务证据**：任务 ID/子任务 ID、MatterLink、完成/撤回状态、冷启动与重复投递结果。
3. **体验证据**：模拟器入口走查、真机三条动线、iPad/无障碍/Reduce Motion、双设备同步分别标记通过/未跑/失败。
4. **遗留与回退**：未过用例、风险、打开或关闭哪个视觉开关；若有后端改动，单列部署与生产验证状态。
