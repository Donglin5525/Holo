# Holo 锁屏待办展示与交互可行性方案

> 日期：2026-09-20  
> 状态：调研完成，待产品确认后实施  
> 范围：iPhone / iPad 锁屏待办，不包含本轮代码实现  
> 推荐系统基线：iOS 17+（与 Holo 当前 Deployment Target 一致）

## 1. 产品结论

**可行，而且 Holo 已经具备大部分基础能力。**

推荐第一期做一个 `accessoryRectangular`（锁屏矩形）“今日焦点”小组件：

- 常驻展示 1 条当前最值得处理的待办；
- 同时展示“今日剩余 N 项”或今日完成进度；
- 点击圆圈可原地完成 / 撤回，无需进入 Holo；
- 点击其余区域打开 Holo 的待办页，后续可升级为打开对应任务详情；
- 任务标题标记为隐私敏感，遵循用户的系统锁屏隐私设置；
- 空态显示“今日已清空”，而不是展示演示数据。

第二期可补 `accessoryCircular` 圆形进度组件，但它只适合显示进度或“一键完成当前焦点”，不适合呈现任务标题。

**不建议把普通待办列表做成 Live Activity。** Live Activity 更适合“已经开始、几个小时内结束”的单次活动。可在以后把它用于“专注执行某一项任务”，但不能代替常驻锁屏待办。

## 2. 用户最终会得到什么

### 2.1 推荐形态：锁屏「今日焦点」

矩形区域只承载一个决策：现在做哪一件。

```text
○ 交付锁屏待办方案
  今日还剩 4 项
```

完成后的系统刷新：

```text
✓ 交付锁屏待办方案
  下一项：整理发布说明
```

交互规则：

1. 点左侧圆圈：完成当前任务；重复任务沿用 Holo 现有规则生成下一次。
2. 点已完成圆圈：撤回完成。
3. 点标题 / 组件其余区域：打开 Holo 待办页；若补齐任务详情 Deep Link，则打开该任务。
4. 完成后自动换成下一条最高优先级任务。
5. 真正锁定时，系统先要求 Face ID / 密码；认证完成后动作在小组件内执行，不需要进入 App。

### 2.2 信息排序

首版严格复用 Holo 当前今日待办口径：

1. 候选范围为“今日到期未完成 + 逾期未完成”，按任务 ID 去重；
2. 按优先级从高到低；
3. 优先级相同按截止时间从早到晚，因此同优先级下逾期任务自然靠前；
4. 再相同时按标题稳定排序。

这能保证 App 内“今日”和锁屏显示的是同一套事实，不额外发明一套“焦点算法”。以后若 Holo 建立统一的 Today 排程规则，再把锁屏改为读取统一排序结果。

## 3. iOS 能力边界

| 能力 | 是否可做 | 真实边界 |
|---|---:|---|
| 锁屏常驻展示待办 | 是 | iOS 16 起支持锁屏 accessory widget；Holo 基线为 iOS 17 |
| 锁屏直接完成任务 | 是 | iOS 17 起矩形/圆形 accessory widget 支持 Button / Toggle + App Intent |
| 点击后不打开 App | 是 | App Intent 默认在 Widget Extension 进程执行 |
| 完成后视觉更新 | 是 | 交互完成后系统保证重新加载 timeline；Toggle 还可先做乐观视觉变化 |
| 设备完全锁定时直接改数据 | 否 | Apple 明确规定锁定状态下按钮/Toggle 不执行，必须先认证解锁 |
| 点击标题打开任务详情 | 是 | 通过 `widgetURL` / Deep Link；Holo 目前已有 `holo://tasks`，任务详情路由需补齐 |
| 在锁屏放 3–5 条完整清单 | 不推荐 | accessory widget 空间很小，信息密度和触控命中都会变差 |
| 自动把组件加到用户锁屏 | 否 | 用户必须在系统锁屏自定义页手动添加，App 只能做引导 |
| 常驻 Live Activity 一整天 | 不适合 | 单次最多活跃 8 小时，之后最多再留在锁屏 4 小时；产品语义也要求明确开始/结束 |
| 任意高频动画 | 否 | Widget 是系统归档与刷新模型，只支持系统允许的状态过渡，不是常驻 SwiftUI 页面 |

## 4. Holo 当前基础与缺口

### 4.1 已具备，可直接复用

1. 已有 `HoloWidgets` Extension，主 App 和 Extension 已配置同一 App Group。
2. 当前最低系统为 iOS 17，不需要额外维护 iOS 16 的“只能打开 App、不能原地勾选”降级分支。
3. 已有桌面“今日待办”组件和今日待办轻量快照。
4. 已有 `HoloTodoToggleIntent`，可在组件扩展进程直接完成 / 撤回待办。
5. 已有统一 `TodoCompletionCore`，普通任务、重复任务和子项联动不会出现两套完成语义。
6. 已有原子 JSON 快照、App Group 共享 Core Data 和 timeline 刷新链路。

### 4.2 仍需补齐

1. `HoloTodoWidget` 当前只声明 `.systemMedium` 和 `.systemLarge`，尚未声明 `.accessoryRectangular`。
2. 当前视图按桌面尺寸设计，不能直接压缩到锁屏；需要独立锁屏布局。
3. 任务标题还没有锁屏隐私标记与隐私占位样式。
4. 当前按钮是 `Button`，适合功能执行，但完成态即时反馈可评估改为 `Toggle`；二者都必须真机验证。
5. `HoloTodoToggleIntent` 对“任务不存在、数据库加载失败、保存失败”没有用户可见的失败状态；目前存在静默返回的情况。
6. 当前只支持打开待办列表，未见 `holo://tasks/detail?id=...` 的任务详情 Deep Link 契约。
7. Widget 进程直接写共享 Core Data、主 App 负责 CloudKit 镜像的链路，需要补做并发写与双设备同步验收，不能只以本机勾选成功作为完成。

## 5. 推荐架构

```text
主 App 创建/编辑任务
        │
        ▼
共享 Core Data（App Group） ──► 生成轻量 Todo Snapshot JSON
        ▲                              │
        │                              ▼
锁屏 Button/Toggle ──App Intent──► 锁屏 Widget Timeline
        │
        └── 完成/撤回后：保存数据库 → 重建快照 → timeline 自动重载

主 App 下次运行/系统调度
        │
        └── NSPersistentCloudKitContainer 将共享库变更同步到 CloudKit
```

架构原则：

- 锁屏只读轻量快照，避免每次渲染都打开完整数据库；
- 只有用户点击完成时才进入共享数据库执行原子写入；
- App 和 Widget 共同复用 `TodoCompletionCore`，完成语义只有一个真相来源；
- 先落库成功，再刷新快照；失败时不伪造“已完成”；
- 锁屏不联网，不依赖 HoloBackend；此功能没有后端发布要求。

## 6. 数据契约

首版无需破坏现有 `HoloWidgetTodoSnapshot`。锁屏从现有字段派生：

| 字段 | 来源 | 锁屏用途 |
|---|---|---|
| `items[].id` | TodoTask.id | App Intent 精确完成任务 |
| `items[].title` | TodoTask.title | 当前焦点标题，标记 privacySensitive |
| `items[].isCompleted` | TodoTask.completed | Toggle / 圆圈状态 |
| `items[].priority` | TodoTask.priority | 排序与辅助状态 |
| `items[].isOverdue` | 统一日期策略 | “逾期”提示 |
| `pendingCount` | 今日 + 逾期未完成去重总数 | “还剩 N 项” |
| `completedToday / totalToday` | 今日进度 | 圆形组件或进度文案 |
| `updatedAt` | 快照生成时间 | 诊断过期快照，不建议直接展示给用户 |

若第二期需要“指定清单”“仅今日不含逾期”“手选锁屏任务”，再将 Widget 改为 `AppIntentConfiguration` 并新增配置参数；首版不要先引入配置复杂度。

## 7. 交互与隐私决策

### 7.1 完成动作

首版推荐继续使用 `HoloTodoToggleIntent`，但锁屏布局优先尝试 `Toggle(isOn:intent:)`：

- 好处：点击后立即呈现乐观完成态，感受更接近系统提醒事项；
- 真实写入失败后，timeline 必须回滚到未完成，并显示可理解的暂时错误态；
- 如果真机上自定义 Toggle 样式或命中区域不稳定，则回退为现有 `Button(intent:)`。

### 7.2 认证策略

- 不试图绕过 Apple 的锁屏保护。
- 用户看向手机完成 Face ID 后，可直接在锁屏小组件点击完成。
- 不额外强制二次认证；待办完成属于低风险、可撤回动作。
- 删除任务、修改标题、批量完成不进入锁屏首版。

### 7.3 隐私策略

推荐默认：

- 任务标题使用 `.privacySensitive()`；
- “今日剩余 N 项”和进度可保持可见，不泄露具体内容；
- 系统允许显示锁屏数据且设备已认证时，显示真实标题；
- 隐私隐藏时显示“今日待办 · 还剩 N 项”；
- 不对整个 Extension 使用 `NSFileProtectionComplete`，否则会让组件在常见锁屏场景完全失去价值，也会影响 iPhone Widget on Mac；除非产品决定“任何任务标题都绝不能出现在锁屏”。

## 9. 非功能要求

### 一致性

- 锁屏、桌面组件、App 内 Today 必须共享同一今日 / 逾期 / 重复任务口径。
- 本机数据库写入成功是第一层；CloudKit 到第二台设备可见是第二层，验收报告必须分开写。

### 性能与耗电

- timeline 渲染只读 JSON 快照；
- 不在 Widget 渲染路径发网络请求；
- 不以高频 timeline 刷新模拟实时界面；
- 交互完成后由系统保证 timeline reload，不轮询。

### 可用性

- 长标题单行截断，VoiceOver 提供完整标题和“完成 / 撤回”动作描述；
- 点击目标按系统 Widget 交互规范设计，不能把多个小复选框硬塞进矩形组件；
- Always-On、深色壁纸、浅色壁纸和系统着色模式下必须可读。

### 安全与隐私

- 日志不记录任务标题；
- 不在锁屏提供删除、批量修改等高影响操作；
- 具体标题受系统隐私策略控制；
- Widget 不接入 HoloBackend，不新增网络或凭据暴露面。

## 10. 验收矩阵

### 10.1 逻辑自动化

- 普通任务完成 / 撤回；
- 重复任务完成后只生成一个下一实例；
- 主任务完成时子项联动；
- 今日 + 逾期去重与排序；
- 空数据、旧快照、损坏快照；
- 快速连续点击同一任务；
- App 与 Widget 同时写入时不丢数据；
- Intent 失败时快照不伪造成功。

### 10.2 Simulator

- iOS 17 最低支持版本；
- 当前主力 iOS 版本；
- accessoryRectangular 的真实尺寸；
- 深浅壁纸、vibrant、monochrome、长中文 / 英文标题；
- 空态、1 项、很多项、逾期、全完成；
- 点击完成后的过渡和下一项切换；
- 桌面 `.systemMedium` / `.systemLarge` 无回归。

### 10.3 真机门禁

以下任一未过，都不能写“锁屏待办已完整上线”：

1. 首次添加、移除、重新添加组件；
2. 锁屏未认证时点击，系统正确要求认证；
3. Face ID 认证后不打开 Holo 即可完成；
4. App 被杀、后台、前台三种状态均可交互；
5. 重启后第一次解锁前 / 后的显示符合隐私预期；
6. Always-On 显示可读且不泄露被标记的标题；
7. 弱网、离线不影响本机完成；
8. 双设备 CloudKit 最终同步且不重复生成周期任务；
9. 同时在 App 与锁屏操作同一任务无冲突；
10. Plus 有效、失效、离线缓存三种权益状态符合现有小组件策略。

建议完成标准：

- 本机点击后数据库立即写入；
- 正常情况下锁屏视觉在系统完成 reload 后更新，不承诺毫秒级固定 SLA；
- 100 次完成 / 撤回压力操作无崩溃、无重复周期任务、无丢失；
- 第二台设备同步结果与本机最终状态一致；
- 无任务标题进入错误日志或分析事件。

## 11. 风险与处理

| 风险 | 用户影响 | 处理 |
|---|---|---|
| 误以为未解锁也能直接完成 | 点击没有立即生效 | 产品说明写“Face ID 后可直接完成”，不宣传“无需解锁” |
| 锁屏空间太小 | 标题难读、按钮难点 | 只显示 1 条焦点，不做微型多行清单 |
| 乐观 UI 与真实写入不一致 | 看似完成后又弹回 | 落库失败必须回滚并给出过期/失败状态 |
| Widget 与 App 并发写共享库 | 丢状态或 SQLite 错误 | 串行事务、持久历史、真机并发压力测试 |
| CloudKit 延迟或未出口 | 第二台设备状态滞后 | 将本机与云同步分层验收；主 App 前台后核对出口 |
| 隐私泄露 | 他人看到任务标题 | `.privacySensitive()` + 系统锁屏设置 + 不记录标题日志 |
| 组件权益快照过期 | Plus 用户看到锁定态或反之 | 沿用现有 entitlement snapshot，并在 App 激活时刷新 |
| Live Activity 被误用为常驻清单 | 8–12 小时后消失、审核体验差 | 仅用于用户主动开始的“专注任务” |

## 12. 回退方案

该功能不涉及数据模型迁移，回退成本低：

1. 从 `supportedFamilies` 移除 `.accessoryRectangular` 即可停止新用户添加锁屏形态；
2. 保留原有桌面中号 / 大号组件与 `HoloTodoToggleIntent`；
3. 若锁屏直接落库出现稳定性问题，临时把圆圈改为打开 App 对应任务，展示能力继续保留；
4. 已写入的任务完成状态是正常业务数据，不需要回滚数据库；
5. 不删除 App Group、不迁移 Core Data，避免影响现有桌面组件。

## 13. ADR-001：锁屏待办采用 WidgetKit，而非 Live Activity

### Status

Proposed

### Context

Holo 需要长期、低打扰地把今日待办放在锁屏，并允许用户快速完成。待办列表没有天然的短期“进行中事件”生命周期。

### Decision

首版采用 WidgetKit `accessoryRectangular` + App Intent；Live Activity 只保留给未来用户主动开始的专注任务。

### Positive

- 常驻、用户可自行配置；
- 与现有 HoloWidgets、App Group、快照和完成 Intent 高度复用；
- 无新增后端成本；
- 符合 Apple 对 Widget 和 Live Activity 的产品语义。

### Negative

- 空间有限，只能展示一条焦点；
- 更新时间与动画受系统管理；
- 用户必须手动添加；
- 真正锁定时必须先认证才能交互。

### Alternatives Considered

- **Live Activity 常驻待办**：放弃。时限和产品语义都不匹配。
- **锁屏通知 + 通知动作**：只适合提醒某一时刻，不适合稳定展示今日状态。
- **iOS 18+ Control Widget**：适合作为快捷动作，不适合呈现待办内容；作为后续补充。
- **只点击打开 App**：技术更简单，但失去锁屏直达完成的核心价值；仅作为故障回退。

## 14. 交付模板

实施完成后的交付报告必须按下面顺序：

1. **产品结果**：锁屏展示、完成、撤回、隐私和 Deep Link 分别是否通过；
2. **代码证据**：改动文件、统一完成语义、失败处理；
3. **自动化证据**：逻辑测试数与结果；
4. **Simulator 证据**：系统版本和各状态截图 / 录屏；
5. **真机证据**：认证前后、App 被杀、重启、Always-On；
6. **双设备 / CloudKit 证据**：同步耗时和最终一致性；
7. **未完成项**：不得用 `BUILD SUCCEEDED` 代替真实锁屏旅程；
8. **回退状态**：是否可仅移除锁屏 family 而保留桌面组件。

## 15. 最终建议

批准实施 **Phase 0 → Phase 1 → Phase 2**，首版只做一个矩形“今日焦点”锁屏组件，不做 Live Activity，不做多清单配置，不做多任务密集展示。

这是当前价值最高、风险最低的路径：Holo 已经具备主要底层能力，新增工作集中在锁屏布局、隐私、错误反馈和真机验收，不需要重建一套待办系统。
