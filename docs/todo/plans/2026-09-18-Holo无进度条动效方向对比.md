# Holo 无进度条动效方向对比

> 2026-09-18 · 第二轮设计探索 · 未实施。[并排交互预览 B/C/D](../../design-mockups/2026-09-18-holo-motion-alternatives.html) · [第一轮 A 版](../../design-mockups/2026-09-18-holo-motion-study.html)

## 产品结论

东林指出第一轮「光痕轨迹」仍然以进度表达为核心，这个判断成立。虽然 A 版取消了传统填充条，但一排顺序节点和逐段点亮仍然让用户把注意力放在“完成了多少”。本轮改为探索三种与比例无关的表达：**完成后去了哪里、眼前该做什么、做过的事留下了什么**。

建议用 **B 活页归档** 承担任务模块的日常完成反馈，**C 聚光舞台** 用于 Today 的单一焦点入口，**D 生活拼贴** 用于 Matter 与日回顾。共享业务状态，按场景使用不同的视觉语言。A 版保留为对照稿；当前还没有真机审美与疲劳度结果，不把任何一版视为最终定稿。

## 四版对照

| 版本 | 完成的视觉结果 | 主角 | 最适合 | 高频使用风险 |
|---|---|---|---|---|
| A 光痕轨迹 | 节点点亮，线索向前 | 路径和完成量 | 有明确步骤的长流程 | 仍有进度条感 |
| **B 活页归档** | 当前卡片翻页，成为一条可读的事簿记录 | 任务内容 | 高频任务、清单 | 层数过多会显得厚重 |
| **C 聚光舞台** | 当前任务退场，下一件事进入光域 | 当下行动 | Today 焦点、专注入口 | 不适合同时浏览多项 |
| **D 生活拼贴** | 任务标题成为一张日常纸片，留在当天画面 | 生活内容的积累 | Matter、日回顾、分享 | 项目多时容易拥挤 |

四版的目标都不是增加完成压力。进度数字可以在统计或无障碍详情中保留，主界面无需用比例定义一天的价值。

## B · 活页归档

**画面**：像一本经过精心排版的纸质事簿，当前行动是一张略微抬起的活页，完成记录以小票和朱红印章落在下方。主要使用 Holo 既有米白和品牌橙，靠纸张层级、阴影和文字留白建立审美。

**动作脚本**：点按完成 → 当前卡片轻抬并翻入下方 → 记录出现真实任务标题 → 下一张卡片从纸堆前方呈现。3 秒可撤回期间，记录仍可被取回；保存失败时回到原卡并显示原因。连续完成多项时动作可快速合并，无需看完整翻页才能继续点按。

**用户价值**：完成不再是一个抽象百分比，而是一件确实被处理并收好的事。适合用户每天反复操作，且完成记录可直接承接日回顾。

**边界**：列表内不让每张卡都翻页，避免滚动时满屏运动。默认只对用户主动完成的当前卡播放完整动作，其余列表行用轻量状态变化。需要保留标题、来源、截止时间及撤回入口；纸张质感不能牺牲动态字体和深色模式可读性。

## C · 聚光舞台

**画面**：深暖背景承托一件正要做的事，标题占据视觉中心；其他任务暂时退到背景。完成后视线在同一位置等待下一行动，减少扫视和选择成本。

**动作脚本**：点按完成 → 当前标题与象征图形淡出 → 场景短暂停顿 → 下一件事在原位置出现；底部一行明确告知“刚刚完成什么”。用户可立即撤回并恢复上一件事。没有任务时，画面转为休息或自由选择的空态。

**用户价值**：适合用户只想迈出下一步的时刻，尤其是 Today 的 Primary Focus。产品辨识度最强，但应作为专门入口，让用户随时返回完整列表。

**边界**：光效只在状态转换时出现，不做呼吸循环、景深摇晃或持续闪烁。焦点必须来自真实的本地 Today 规则，不能让展示层编造一个“系统推荐任务”。Reduce Motion 下只切换标题与状态文字。

## D · 生活拼贴

**画面**：每完成一件事，就留下一张写有真实标题和所属事项的纸片，随时间形成当天的小幅拼贴。色彩根据事项主题和业务语义选择，装饰只作为内容的容器。

**动作脚本**：任务确认完成 → 一张小纸片落入当天画面 → 可点开查看原任务及来源；撤回则取走纸片。到一天结束时，用户看到的是“今天发生了什么”，而非一个达成率。

**用户价值**：最能表达 Holo 的“个人数据资产”定位。行动会成为生活记忆的一部分，适合 Matter 详情、日回顾以及未来的分享卡。

**边界**：一屏最多展示少量纸片，超出后用日期、事项或自然分组收纳；不凭任务标题猜图标、地点或情绪，不自动生成虚构的旅行照片。进入拼贴必须能回到真实任务 ID 和 `MatterLink`。高频任务列表里不放整块拼贴画面。

## 推荐的组合与实施门

1. **先统一完成状态**：对齐任务列表与 Today 的“可撤回、已保存、保存失败”；三版原型的 3 秒撤回只是交互演示。业务规则先定，视觉才能真实表达。
2. **先做 B 的任务切片**：只替换当前任务完成和完成记录的呈现，保留现有任务数据与入口。与 A 版做并排真机对照，检查频繁操作后是否仍耐看。
3. **C 只进 Today 焦点卡**：检验用户能否更快找到眼前可做的事，并且能一键返回完整清单；不覆盖任务总览。
4. **D 在真实 Matter 旅程中试验**：至少使用一件完整事项和真实关联任务，从创建、完成、撤回、冷启动到回看。来源缺失时直接展示普通任务记录，不造假拼贴。
5. **选定视觉语言后再改第一轮 D2 清单**：A 版原方案的“今日轨迹”和“章节刻痕”不自动进入开发范围。

### 评审时看什么

- **第一眼**：不解释概念时，用户能否知道当前任务、刚完成的任务、撤回入口在哪里。
- **第十次完成**：连续处理 10 件事后，是否仍觉得反馈有质感；哪一帧开始显得拖沓。
- **真实旅程**：完成一件与 Matter 关联的任务后，Today、任务列表与 Matter 显示同一事实；关闭重进不重播庆祝。
- **无障碍与性能**：Reduce Motion、VoiceOver、动态字体、深色模式、老设备均可完成操作。Apple 建议高频反馈简短精准，用户无需等待动效结束即可继续使用，并为减少动态效果提供替代呈现。[Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)、[Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)。

## 当前状态

本轮交付了三版可点击的 HTML 方向稿和产品取舍，未修改 iOS 业务代码、没有真机动效或用户留存结论。HTML 演示里的任务和完成记录是示例数据；实施必须绑定真实业务 ID 与持久化回执。项目现有并行改动需要保持原样。
