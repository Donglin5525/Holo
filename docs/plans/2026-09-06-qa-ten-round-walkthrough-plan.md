# Holo 1.0.1 发布后系统性 QA 走查计划（10 轮）

> 起草日期：2026-09-06　|　发起人：东林　|　执行：AI
> 基线分支：`release/1.0.2`（修复随下个版本发出，每轮独立提交，可随时发版）

---

## 一、背景与目标

1.0.1 已经发布，但整个发版过程暴露了大量 bug：小组件简体中文缺失与布局问题、手势冲突、页面布局不合理、交互不顺畅等。这些问题里有相当一部分**不是第一次出现**——删除闪退、手势被吞、列表卡顿、弹窗异常、断网无兜底等，在记忆档案里都反复发生过。

本项目的目标：借东林留出的完整时间窗，做一次**系统性**的 QA 走查 + 修复，而不是哪里报错修哪里。具体三个目标：

1. **把记忆里反复出现过的每类问题，做一次全模块的专项排查**，从根上治理，不再按次打补丁；
2. 覆盖东林点名的四类：**页面交互不合理、用户流程不合理、网络交互不合理、其他（性能/数据安全/多语言/系统集成）**；
3. 每轮修复都做回归验证，保证修一个稳一个，不引入新问题。

---

## 二、总体工作模式（每轮固定节奏）

每一轮都按同一个循环走，共 10 轮：

| 步骤 | 做什么 |
|---|---|
| ① 修上轮 | 把上一轮走查发现的问题清单里 P0/P1 全部修复；P2 视改动大小决定（小瑕疵直接修，涉及设计改版的先出方案给东林拍板） |
| ② 回归 | 修复项逐条复验 + 编译零错误 + 相关自动化测试全绿（能补回归测试的必须补）；同时抽验上上轮的修复没有退化 |
| ③ 查本轮 | 按本轮专项，逐模块走查（模拟器实际操作 + 代码审查双通道），每个模块都过 |
| ④ 立清单 | 新发现的问题记入问题台账，分级 P0/P1/P2 |
| ⑤ 收尾 | 更新台账 + CHANGELOG + 独立提交推送（绝不和在途素材/其他改动混提）；给东林一份轮次简报 |

**轮次简报格式**（每轮结束发一条）：本轮发现 X 个问题（P0 几个/P1 几个/P2 几个），修复并回归 Y 个，待你拍板 Z 个，需要真机验收 W 个，涉及后端发版的 N 项。

### 工作纪律（长期铁律，写进每轮）

- **同一问题连续改两轮没修好，必须停下来跑 self-check**，查踩坑速查表，不凭印象继续改。
- UI 类改动，如果本质是「重新设计」而不是「修 bug」，先出方案/截图给东林拍板，再动手写代码。
- 每轮修复独立提交；工作区里的在途改动（素材、多语言等）绝不混入。
- 涉及后端发版的改动，当场单独记入「后端发版清单」并同步告知东林。
- 模拟器验不了的项（CloudKit 同步、推送、内购、锁屏、真实桌面小组件），标记为「真机验收项」汇总，不假装验过。

## 三、10 轮排期总览

| 轮次 | 专项关注点 | 一句话说明 |
|---|---|---|
| 第 1 轮 | 稳定性与数据安全 | 崩溃、删除流、数据丢失风险——最痛的先治 |
| 第 2 轮 | 手势与触控交互 | 滑动/长按/双击/拖拽冲突、按钮热区 |
| 第 3 轮 | 滚动与性能 | 长列表卡顿、分页、加载策略 |
| 第 4 轮 | 页面状态与生命周期 | 弹窗/表单/前后台切换/未保存退出 |
| 第 5 轮 | 网络交互 | 断网弱网、超时取消、错误提示、重试 |
| 第 6 轮 | 跨模块用户流程 | 端到端流程走通、新旧入口映射 |
| 第 7 轮 | 多语言与文案适配 | 简繁英三语、截断溢出、口语词 |
| 第 8 轮 | 小组件与系统集成 | 小组件、推送、深链、锁屏、权限降级 |
| 第 9 轮 | 边界数据与极端场景 | 空态、海量数据、极端日期、重装同步 |
| 第 10 轮 | 视觉细节 + 全量回归总验 | 暗黑/iPad/字号放大，收口出真机验收清单 |

### 第 1 轮：稳定性与数据安全

**走查范围**：全模块（想法/任务/习惯/财务/日历长廊/健康/AI/设置）的增删改查主流程。重点是**删除流**：删除后界面是否残留、是否闪退、关联数据是否级联清理干净；保存后回读是否真的落盘；中断操作（保存中途退出）数据是否损坏。

**记忆里的已知病灶（本轮重点排查同类）**：
- 删除闪退的统一根因：先清界面数组再删库——要确认所有删除入口都遵守这个顺序；
- 卸载重装后 seed 数据与云端恢复行重复（图标叠印）；
- 更新接口 nil 语义不清导致「删除截止日期不生效」类问题（表单 nil 语义通用坑）；
- 「工具报成功 ≠ 落盘」，保存后必须回读验证。

**验证**：本轮开始先跑一遍全量自动化测试，建立基线。

### 第 2 轮：手势与触控交互

**走查范围**：所有页面的滑动手势（列表滚动、侧滑返回、单元格右滑操作、长按菜单、双击、拖拽排序、抽屉），以及按钮点击热区（尤其小尺寸胶囊按钮、iOS26 plain 按钮）。

**已知病灶**：
- 长廊「轴」档：长按拖选被 ScrollView 吞手势 + 坐标系错位（标准解：highPriorityGesture + 命名 coordinateSpace）；
- 双击手势挡住子级翻页（应改 onTapGesture(count:2)）；
- 「轴」档滑动被隐形手势劫持（0.3 秒分界 + 14pt 隐形把手）；
- 财务右滑守门误杀（误触发了其他手势）；
- iOS26 plain 按钮热区缩水，还有 3 处胶囊待修。

### 第 3 轮：滚动与性能

**走查范围**：长列表滚动流畅度——想法列表、记忆长廊、AI 聊天页、日回放、任务列表、账单流水；分页加载策略；图片加载与内存占用。用造数工具灌入大数据量后实测。

**已知病灶**：
- 想法「…」卡顿修了三轮的教训：弹菜单触发全列表重算、每张卡重复解码内容 JSON、无障碍文本急切全量重建——检查其他列表有没有同款问题；
- 日回放分页：**禁止顶部插入**（会导致跳屏），展开/收起要滚动重锚定；
- GeometryReader 在 iOS18 起滚动中不触发，须用 onScrollGeometryChange。

### 第 4 轮：页面状态与生命周期

**走查范围**：所有 sheet/弹窗（下拉关闭是否该禁用、聚焦输入框时菜单弹不弹得出）、页面间跳转后状态残留、App 前后台切换、键盘遮挡、编辑页未保存退出的提示、筛选条件在刷新后是否保持。

**已知病灶**：
- confirmationDialog + 聚焦 TextView 的竞态（标准解：改 sheet(item:)）；
- 新 sheet 禁下拉必须配套 sheetDismissGuard；
- 「同值赋值不触发 onChange」——刷新保持筛选上下文的坑；
- @AppStorage 引发的浮条异常。

### 第 5 轮：网络交互

**走查范围**：把每个联网功能（AI 对话、深度分析、记忆萃取、想法整理、回放生成、云端同步）分别放到**断网、弱网、超时、中途取消**四种场景下走一遍。检查：有没有兜底（离线回退/重试入口）、加载态是否明确、错误提示人话与否、取消后会不会复活。

**已知病灶**：
- 想法离线整理：断网回退 pending、网络恢复续做——检查其他联网功能有没有同款兜底；
- 403/400 回退链、额度终态协议（额度用完要有终态而不是永远转圈）；
- 流式取消三层 onTermination 防复活；
- 错误文案：「AI 服务不可用」实为供应商欠费 503、中文报错实为无 token——错误提示要翻译成人话并给下一步动作；
- 萃取超时 = 缺 reasoningEffort 类参数问题。

**本轮附加产出**：需要后端配合的项单独成清单，同步东林（走 holo-backend-deploy 通道）。

### 第 6 轮：跨模块用户流程

**走查范围**：端到端流程走通——想法→转任务（确认页+AI 预填）、记账→对账→趋势、打卡→统计、目标→规划→任务、记录→日回放→周期回放→报告收藏、洞察胶囊→AI 页直达；每次模块改版后的**新旧入口映射**逐一核对（长期铁律：改版自查必核对映射）；新人引导 V2 完整重播。

**已知病灶**：
- 周期回放「本月」歧义（回退拆行、进行中可选）已修，标签动态化待拍板；
- 月初/周初显示上一期是设计（回退阈值周 3 天/月 7 天），但标签要动态化；
- 洞察胶囊 openScheduledInsight 静默无提示缺陷待拍板。

### 第 7 轮：多语言与文案适配

**走查范围**：简/繁/英三语切换后全模块遍历：缺失键、文字截断、按钮/卡片随文字变长后的布局溢出、日期数字格式、词表口语词缺口（🚗搜不到「车」类）、emoji 搜索排序。

**已知病灶**：
- xcstrings 源语言不生成 lproj + 小组件无开发语言兜底 → 就近匹配繁体（小组件简体缺失根因）；
- 三陷阱字（帳/項目/補簽）；
- 小号圆环溢出叠印、forecast 截断、habit 缩字；
- CLI 只提取不写回、fill 脚本补齐的工具链约束；
- 种子语言固化机制下切换语言的完整链路。

### 第 8 轮：小组件与系统集成

**走查范围**：小组件（四尺寸×明暗×三语、编辑模式添加、时间线刷新、数据及时性）；推送（权限拒绝后的体验、深链跳转直达正确页面、通知管理三态开关）；锁屏 Live Activity；全部 URL Scheme 深链；系统权限（日历/健康/通知/相机）被拒绝后的降级引导。

**已知病灶**：
- iOS26 小组件编辑模式没有「+」、无 widget 实例时 timeline 不请求（两个坑都在档）；
- 小组件图例文案泄漏待东林点头；
- Agent 锁屏假失败 = Live Activity 被系统收回（可靠性收口已做，复验）；
- 推送统一中心 P3/P4 东林挂起——本轮只复查已上线部分。

### 第 9 轮：边界数据与极端场景

**走查范围**：全新用户空态（每个页面的空态是否引导建数据）；海量数据（千条想法、万条账单的加载与统计）；极端日期（跨年夜 23:59 记录、闰年 2/29、农历纪念日、凌晨 0-5 点的「今天」归属）；金额极值与超长文本；卸载重装恢复；双设备 CloudKit 同步冲突（真机项，模拟器侧做能做的部分）。

**已知病灶**：
- 周期回放回退阈值（周 3 天/月 7 天）边界；
- 凌晨时段的轴档折叠；
- 测试里的「时间炸弹」类问题（依赖 Date() 的不稳定测试）；
- 重建工具（交易重建/aiCandidate 重放）作为丢数据补救通道要验证可用。

### 第 10 轮：视觉细节 + 全量回归总验

**走查范围**：暗黑模式全模块；iPad 适配（侧边栏、分屏、Cmd 快捷键、三模块 tab）；系统字号放大到最大档的布局；间距对齐、图标、动效一致性。然后做**全量回归**：把前 9 轮所有修复项逐条复验一遍。

**收尾产出**：
1. 完整 CHANGELOG；
2. 「待真机验收清单」交给东林（含记忆里全部存量「待真机验收」项的汇总复验单）；
3. 「后端发版清单」与「CloudKit schema 待部署清单」（历次发版多次被 schema 前置卡住，这次提前列全）；
4. 项目总结：哪类问题在 10 轮里反复出现，沉淀为长期规范。

## 四、问题台账与分级

- 台账文件：`docs/qa-10-rounds/ledger.md`（第 1 轮开工时创建）。
- 每条问题记录：编号（R{轮次}-{序号}）/ 模块 / 现象 / 根因 / 修复方式 / 回归结果 / 是否需拍板 / 是否真机项。
- 分级标准：
  - **P0**：崩溃、数据丢失/损坏、安全问题——发现即修，不等下一轮；
  - **P1**：功能不可用、明显卡顿、流程走不通、错误提示误导——本轮内修，下一轮开头收尾；
  - **P2**：体验瑕疵、文案问题、视觉细节——记录在案，小瑕疵顺手修，设计类的攒到拍板后统一处理。

## 五、拍板与后端同步机制

- **需要东林拍板的**：攒到每周或每轮简报里集中给，附方案/截图，不逐条打断；
- **后端发版清单**：单独维护，每轮简报同步一次改动内容、是否需发版、影响范围；
- **CloudKit schema 前置项**：从记忆里已知的有——TodoTask 三字段 + TaskScheduleMirror、isLunar、类别学习映射实体、4 个对账字段等，第 10 轮汇总成部署清单。

## 六、开工前置（第 0 步，进第 1 轮前必须完成）

1. **在途改动分拣收口**：当前工作区有 386 个改动文件在途（多语言主体、小组件修复、素材图标、若干功能收尾）。分批按主题独立提交（多语言一批、小组件一批、素材一批、各自功能收尾一批），做到 QA 开始时工作区干净。素材类在途改动勿混提交——长期教训。
2. **确认验收环境**：模拟器走查为主（视觉链路可用）；真机项单独标记。全量测试须独占工作区跑。
3. **存量「待真机验收」项汇总**：记忆里有大量已修但未真机验收的项，汇总成底单，第 9/10 轮做复验。

## 七、验收标准（整个项目的「完成」定义）

1. 10 轮全部走完，台账里 P0/P1 清零（P2 允许有明确记录的遗留）；
2. 每轮修复都有回归记录：编译零错误 + 相关测试全绿 + 模拟器复验通过；
3. 产出物齐：问题台账、CHANGELOG、真机验收清单、后端发版清单、CloudKit schema 部署清单；
4. 东林点名的四类问题（页面交互/用户流程/网络交互/其他）每类都有专项轮次的走查记录。

## 八、时间预估

每轮约 1 天左右的 AI 全力工作量（走查 + 修复 + 回归 + 简报），10 轮 + 第 0 步预计 **2~3 周**。涉及设计改版需要东林拍板的项不阻塞主线（拍板前先修其他），但拍板响应速度会影响 P2 项的清零时间。
