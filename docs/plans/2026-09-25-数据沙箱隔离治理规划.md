# 数据沙箱隔离治理规划

> 2026-09-25 立项。原则（东林拍板）：**回收站里面的东西不能影响到线上的内容——看不见的数据必须对活数据视图零影响，如同沙箱隔离。**
> 规范本体已固化为 [质量红线 §7](../standards/quality-redlines.md)，本文是治理落地规划。
> 起因事故：财务统计饼图一级二级混层（回收站部分恢复不联动父级 → 孤儿二级分类冒充一级进饼图）。

---

## 一、现状盘点（2026-09-25 快扫）

### 1.1 软删实体全景（28 个）

全 App 遵从 `SoftDeletable` 的实体：待办链（TodoTask/TodoList/TodoFolder/TodoTag）、习惯链（Habit/HabitRecord）、财务链（Transaction/Account/Category/Budget）、想法链（Thought/ThoughtTag）、Topic、Anniversary、目标链（Goal/GoalMetricLog）、ChatMessage、记忆库（HoloMemory*×5）、生活规划（LifePlan*×6）。

**结论：软删已是全 App 事实标准，但「沙箱隔离」三侧纪律只在财务分类域完整过了一遍。**

### 1.2 三侧现状

| 侧 | 现状 | 缺口 |
|----|------|------|
| 删除侧 | 分类域有完整预检+原子执行（9-19 治理）；其余域各自实现 | 各域删父级容器时的子级处置未统一审计 |
| 恢复侧 | `RecycleBinRestoreEngine.restoreLinkedParents` 联动分支：Transaction→账户+分类、HabitRecord→习惯、TodoTask→清单、Category→父分类（本轮新增） | **Budget→分类/账户无联动**（恢复预算但其分类在回收站→预算页挂死分类）；GoalMetricLog→Goal、TodoTag 关系、ThoughtTag 关系未入表 |
| 读路径 | 统计聚合有孤儿留痕日志（本轮新增）；自愈链 `runRepairPass` 挂孤儿修复（本轮新增） | 其余「按 UUID 找关联」的读路径未逐一过语义（徽章、提醒、额度、报告快照） |

### 1.3 已知 UUID 挂靠引用（读路径高风险点）

- `Category.parentId`（本轮已闭环：联动+自愈+日志）
- `Budget.categoryId` / `Budget.accountId`（恢复预算时挂靠对象可能在回收站）
- `HabitRecord.habitId`（已有联动，走托管关系）
- `FinanceRepository.swift:904` 附近实体的 `categoryId`/`accountId`（固定支出域，待核对）

## 二、分期计划

### P0 分类域闭环（✅ 本轮已交付，待真机验收）

- 恢复引擎补 Category→父分类联动
- `CategoryOrphanRepair` 自愈挂修复链（存量孤儿拉回正常态；悬空暴露）
- 统计聚合孤儿冒充留痕日志
- 7 单测锁定（含同 id 副本优先活行、悬空不崩）

### P1 联动分支表补全（小改动，一个会话可完成）

1. 盘全量可软删实体的父子/挂靠关系，把 `restoreLinkedParents` 的 switch 从「分支表」升级为「覆盖 28 实体的对照表」，每行有联动语义或显式「无需联动」结论；
2. 优先补：Budget→Category/Account（预算页恢复场景真实存在）、GoalMetricLog→Goal；
3. 回收站恢复预检（`restorePreview`）增加「父对象仍在回收站将联动恢复」的提示行，让用户知道恢复会连带。

### P2 读路径全量审计（静态盘点，零模型成本）

1. 全仓库扫「按 UUID 找关联对象」的查询点（`parentId`/`categoryId`/`accountId`/`habitId` 等 keyPath 的 fetch 与字典索引）；
2. 每个点按红线 §7 三选一语义归类：**归未分类桶 / 跳过并留日志 / 触发自愈**，禁止静默冒充；
3. 产出对照表入 `docs/`（读路径 × 语义 × 状态），作为后续新增读路径的检查基线；
4. 重点域：习惯徽章累计、任务看板分组、目标进度聚合、记忆检索（HoloMemory 检索若召回软删锚点属泄漏）。

### P3 自愈链扩展（视 P2 审计结果）

1. `runRepairPass` 里按域加自愈器（仿 `CategoryOrphanRepair`：单文件、单职责、有 Result、有日志）；
2. 悬空引用（父行彻底不存在）无自动修复语义，只计数暴露，超阈值人工介入——避免自愈器替用户做数据决策；
3. 自愈器每个配一组 Core Data 集成单测（内存栈，仿 `CategoryOrphanRepairTests`）。

---

## 三、验收口径

- P1/P3 每个联动分支、每个自愈器：集成单测绿；
- P2 产出读路径对照表，无一处「静默冒充/静默吞」语义；
- 回归：分类删除→回收站→部分恢复→统计页，四步走查饼图不混层（可脚本化 XCUITest）。

## 四、不做的事（防止过度工程）

- 不把「未分类」实体化成系统分类（影响面：记一笔/AI 建分类/导入映射，为小概率态不值）；
- 不在自愈里替用户迁移/删除孤儿数据（只恢复父级这一种「回正常态」动作，语义与用户恢复意图一致）；
- 不给读路径堆兜底判空——异常态靠自愈消灭，读路径只留痕。
