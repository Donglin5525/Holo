# 睡眠详情页优化与 REM 根因修复

日期：2026-10-21。范围：iOS 睡眠详情、共享的健康趋势均值、相关专项测试。未修改个人健康记录，未部署后端，未安装真机包。

## 产品结论

REM 长期不显示有明确代码原因。Holo 读取系统「健康」中的设备分期，不自行从心率推测 REM；旧实现复制了错误的 HealthKit 数字编号，导致阶段错位。页面同时存在阶段行拥挤、指标与说明矛盾、日/晚统计口径混用和无依据的固定关联文案。

## 页面调整

阅读顺序：总睡眠与时长目标 → 主睡眠时间轴 → 各阶段时长及比例 → 近七晚统计与趋势 → 实际记录覆盖情况。

- 顶部大圆环改为紧凑时长摘要。百分比紧跟「时长目标」，避免误读为睡眠质量评分；不在页头重复百分比。
- 阶段行采用两层：名称/时长共用基线，下方独立的长比例条/百分比。取消深睡独占主视觉；核心、深睡、REM 同级。百分比列使用随系统字号缩放的固定宽度，保证各行条带右端对齐。
- 卡片内边距 16pt；名称到比例条 8pt；信息组间距 24pt。时间条与刻度 8pt，指标与分隔线留足间距。保留 Holo 原有语义色和卡片体系。
- 时间轴指标由四列改为两列。图例空间不足时分行；大字号减少时间刻度，仍使用真实时间坐标。
- 时间轴与阶段色一致；未分期采用独立语义色，不能冒充核心睡眠。保留短清醒段与没有记录的时间空隙。
- 无 REM 样本显示「未记录」，不再显示「0 分钟」；清醒独立展示，不计入睡眠阶段比例。无分期时解释记录前提，并指向系统「健康」中的阶段和来源。
- 「记录结束」表示最后一个可见主睡眠样本的结束时刻，避免把晨间在床尾巴直接称为起床。
- 睡眠详情的总量、阶段和七天趋势统一按起床日归属。每晚窗口仍为前一日中午至当日中午，总量含窗口内小睡，时间轴仅展示主睡眠，并单独说明小睡。
- 删除睡眠页未经成对数据计算的「任务完成更稳定」「咖啡支出上升」固定结论，以有记录晚数、时长达标晚数及缺失数量替代。空记录统计显示未知。

## REM 根因与算法修正

本机 Apple SDK `HKCategoryValues.h` 核实如下。明细构建、时间轴、主睡眠切分和 mock 全部改用 SDK 枚举，不再手写数字对应表。

| Apple 阶段 | SDK 实际编号 | 旧代码按什么解释 |
|---|---:|---|
| 在床 | 0 | 在床 |
| 未分期睡眠 | 1 | 忽略，可能丢失这类睡眠 |
| 清醒 | 2 | 清醒 |
| 核心睡眠 | 3 | 未分期睡眠 |
| 深睡 | 4 | 核心睡眠 |
| REM | 5 | 深睡 |
| 不存在的阶段 | 6 | 被错误当作 REM |

旧测试与 mock 也复制了错误编号，能通过测试却不能正确识别真实设备数据。新增用例直接使用 Apple SDK 枚举，先确认旧代码失败，再确认修复通过。

其他同链路修正：

1. 移除未经依据的 5 分钟 REM 过滤；对有效 REM 区间合并后计算片段数与首次出现时间。短段也保留，片段数不解释为睡眠周期数。
2. 没有 REM 原始样本时，时长和结构指标均保留未知。
3. 上床与入睡同刻时，入睡耗时为真实 0 分钟；在床开始晚于入睡才视为不可得。
4. 深睡前半夜比例 `<40% / 40%..<60% / ≥60%` 分别显示后半夜/均匀/前半夜；数字标签与说明同边界。删去仅凭单晚分布或 REM 片段数判断「质量」「正常」的文案。
5. 读取时间轴时，从整晚在床/未分期底层区间中扣除已有明确阶段的区间，避免遮色和触摸读到错误阶段。
6. 显示层不再跨越两分钟内的缺记录间隙合并，也不再隐藏 40 秒内的清醒段。
7. 健康趋势共用增量均值，修正相同样本反复求和造成「平均 8.5、最高 8.4」的边界舍入问题。

Apple 参考：[HealthKit 睡眠阶段枚举](https://developer.apple.com/documentation/healthkit/hkcategoryvaluesleepanalysis)、[Apple Watch 睡眠记录说明](https://support.apple.com/en-gb/108906)。阶段编号另以本机 SDK 头文件及 SDK 驱动测试交叉验证。
