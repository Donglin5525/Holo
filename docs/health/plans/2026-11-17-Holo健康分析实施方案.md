# Holo 健康分析实施方案

2026-11-17 · 执行稿 · 首版范围为 iOS 健康与「今日」

从第一步开始，依次完成三步。先校验睡眠数据，再接页面，三步一起交付。健康首页和「今日」须同步切换口径。 [Holo 健康分析产品方案](2026-11-17-Holo健康分析产品方案.md)

## 首版交付物

- **健康首页**支持查看所选日期的主睡眠。当天缺记录时，明确显示「今天暂无可用睡眠记录」，有近期记录则单独带日期展示。相邻位置显示截至昨天的近 14 天作息回顾，点击能看到计算依据。
- **睡眠详情**显示入睡、记录结束、实际睡着时长、主睡眠时间轴与来源。午睡和待确认睡眠段单列。心率、呼吸、HRV 按实际睡着区间读取，按各自覆盖显示。
- **「今日」**用同一份主睡眠结果。健康页原有步数、站立或活动时长、运动入口继续可用。新分析使用现有 HealthKit 读取范围，计算及证据留在手机上，离线可查。

首版验收题是「昨晚睡了多久，最近是晚睡了还是醒得早，我能在哪里看到依据」。先交付这条体验，再开展生活对照与指标扩展。

## 第一步 · 统一一晚睡眠

从 `HealthRepository.swift` 接入一条按睡眠结束日查询的路径。复用 `HealthSleepSessionSplitter`、`HealthSleepTimelineBuilder` 和 `SleepStructureAnalyzer` 中适用的纯计算，使用同一批整理后的记录构建摘要、时间轴与阶段。保留自然日合计和按晚结果的独立入口，避免把已有查询悄悄换口径。 [现有 Repository](<../../../Holo/Holo APP/Holo/Holo/Models/HealthRepository.swift#L387>) · [现有切分器](<../../../Holo/Holo APP/Holo/Holo/Models/HealthSleepSessionSplitter.swift#L28>)

| 要实现的规则 | 试用版默认行为 |
| --- | --- |
| 分段与归属 | 查与范围重叠的样本，范围首尾多读一天。在关心的睡眠段仍连接到读取边界时才继续补读，边界无法确认则标作记录可能不完整。会话分段暂沿用现有 3 小时睡眠间隔规则。先整合睡眠段，再按**最后一段可信的睡着记录结束时刻**归日期，时长用实际经过时间。整晚可以跨午夜、跨中午。时间轴保留空隙，缺样本间隔不累加到时长。 |
| 同来源重叠 | 保留样本标识、来源、可用设备信息与起止时间。同来源同类区间合并。在床是独立轨道。有明确分期的睡着段覆盖笼统的睡着记录。有证据表明在睡但细分冲突时记为未分期。睡着和清醒相互冲突的区间标为未知。 |
| 多来源重叠 | 先各自还原，再对照覆盖同一段睡眠的候选。首尾各相差不超过 30 分钟、且记录可以相互印证时，优先选分期覆盖更完整的整段候选。同一时刻只采用一套分期。若只有时长一致且分期难以裁决，保留能相互印证的时长，阶段显示待确认。时间偏差明显且没有可信的优先依据时，展示带来源的候选记录，将这段标为待确认并退出趋势。 |
| 主睡眠与额外记录 | 同一结束日选可信睡着时长最长的一段作为主睡眠。试用阶段，两段都至少 2 小时、且相差不到 60 分钟时，先展示为两个睡眠段，暂缓主睡眠对比。其余额外段有依据识别为小睡时才用「小睡」，其他用「其他睡眠」。孤立的短记录先展示为「睡眠记录」，样本不足时不推断主睡眠。 |
| 时区与证据 | 使用来源提供且彼此一致的时区线索。没有时区线索时按本次查询使用的本地时区展示，并保留这一归属依据。发现时区发生变化、记录归属无法核实时，暂停该段参与钟点比较，保留有依据的时长。图表和首页采用同一归属规则。 [Apple 睡眠时区说明](https://developer.apple.com/documentation/healthkit/hkmetadatakeytimezone) |
| 数据状态 | 复用 `HoloHealthQueryOutcome` 的成功、无数据、锁屏待解锁和读取不可用。成功但结果为空显示「暂无可用记录」。部分指标有数据时各自渲染。查询中、锁屏或失败的状态单独显示，用户能重试。 [Apple 读取权限说明](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data) |

UI 消费的最小结果包含归属日期、主睡眠区间、睡着时长、已证实的阶段与夜醒、额外睡眠段、来源和各指标的覆盖状态。「记录结束」与入床、起床的生活事实分开标注。有可靠在床起点时，详情可以保留现有入睡耗时。首版的主睡眠模块不依赖这一辅助字段。

**完成条件。** 输入 23:00 到次日 07:00，再在同一结束日加一段 30 分钟午睡，按晚接口只给出一个 8 小时主睡眠与一段额外记录，时间轴和摘要来自同一结果。再验证整晚跨查询边界、跨中午、多来源冲突与分段缺失。模拟数据和实际 HealthKit 走同一个计算入口。

## 第二步 · 算个人趋势与夜间体征

### 作息回顾

1. **固定窗口。** 最近 14 个完整归属日截至昨天，向前再取不重叠的 28 天作为个人参考。详情写出两段的具体日期。今天同步的记录可进入日卡，在进入完整归属日窗口后纳入周期分析。用户切到历史日，首页近期回顾仍标清自己的时间范围，所选日期和历史趋势中的数据点跟着切换。
2. **按指标筛选。** 主睡眠时长、入睡和记录结束时间分别统计。最近窗口至少 7 晚，参考窗口至少 14 晚的有效记录，缺记录不入分母。比较只用同类来源和有可比口径的样本。优先使用两段均有足够覆盖的相同日型，有明确日程时用用户设置，其余按系统日历的周内与周末作对照。只有日型构成接近才合并比较。试用默认两期周末样本占比相差不超过 20 个百分点。遇到覆盖不足、来源或日型显著变化时，仍展示近期事实。
3. **算变化。** 用两段中位数的差作显示值。钟点沿午夜连续换算，23:50 和 00:10 相差 20 分钟。两段钟点无法落入同一个小于 12 小时的钟点范围时，先展示时间点，省略单一典型时间和变化值。试用默认的变化门槛取 **30 分钟**与参考期四分位距一半中较大的值。近 14 天前后各 7 天均至少 3 个同指标可比点，且两个半段的中位数相对参考方向一致，才可展示持续变化。刚好达到阈值可展示。
4. **只突出一条。** 首屏在有资格显示的变化里，先选主睡眠时长，再选入睡时间，再选记录结束时间。只有同一组有效日期对两个指标都满足条件，才组合成一条解释。用户点开可以看到每段范围、参与晚数、中位数、变化与对应日期。无达到展示门槛的变化时，用「近 14 天有 10 晚记录 · 典型入睡 23:50」这类事实结尾。

### 同一晚的体征

用已经接入的心率、呼吸频率和 HRV 样本。每项按时间范围批量拉取，按选定主睡眠的可信睡着区间匹配，区间外样本不进入该晚统计。对静息心率保留独立日粒度，沿用已有取值规则。详情先给实际采样点数、时间和单位，达到覆盖门槛后才给该晚中位数。 [现有体征查询](<../../../Holo/Holo APP/Holo/Holo/Models/HealthRepository.swift#L807>) · [当前体征页](<../../../Holo/Holo APP/Holo/Holo/Views/Health/VitalsView.swift#L84>)

试用门槛为心率、呼吸各至少 3 个有效样本，HRV 至少 2 个，且该指标在主睡眠累计睡着时长的前后两半各有样本。少量样本可以作为观测点查看，图表保持实际时间间隔。身体状态页显示每项采样日期与覆盖，移除统一 ±3% 的偏离判定。本阶段的持续变化只在作息指标中发布。这里的覆盖和变化数字是便于实现和试用的默认值，集中配置并用真实记录校准。

**完成条件。** 合成样本可稳定复现「晚睡但起床时刻近似」和「没有足够历史」两种结果。给同一晚再插入午后的呼吸和睡前 HRV 样本，夜间结果保持一致。对外输出来自同一结构化计算结果，用户能按日期复算。

## 第三步 · 接页面并完成切换

| 顺序 | 改动入口 | 用户验收 |
| --- | --- | --- |
| 1 | `HealthView` 的日期区与周期区 | 日期区显示所选日的主睡眠与额外记录。周期区替换为近期作息回顾，明确日期。切日、返回、手动刷新都保持所见日期和数据一致。步数、站立及运动仍可进入详情。 |
| 2 | `HealthDetailView`、睡眠时间轴与阶段组件、`VitalsView` | 点同一晚数字一致。可点图表查看实际时段。没有分期时仍有时长和来源。有样本时，睡眠体征展示清楚采样覆盖。底部引导沿用现有权限入口。 |
| 3 | `KanbanHealthSection`、`KanbanProgressHero`、通过 `HoloTodaySnapshotBuilder` 供数的 `TodayRoutineStrip` | 「今日」展示同一结束日的主睡眠，点击进入对应日期。无记录时从摘要中省略数字或显示缺失，历史最新一晚须带具体日期。 |
| 4 | `HealthInsightViewModel` 和 `HoloApp` 调用的 `HealthInsightScheduler` | 新的本地回顾启用时，同时退出旧健康页专用生成触发。反复打开健康页或切回前台，端上回顾可更新，旧生成调用和旧缓存文案都不再出现在该页。 |

同步核对 `fetchSleepRange`、`fetchSleepDetailRange`、`fetchDailyRangeStrict(.sleep)`、`todaySleep` 的调用方。健康页和「今日」用明确的按晚读取或独立展示字段。睡眠目标、日历回顾和周报逐项记录现行口径，确认需要切换再同批迁移对应展示和测试。AI 对话、健康深度分析、Daily Sense、记忆保留现有输入和权限，本地新增结果留在首版页面范围内。优先复用既有图表和证据弹层组件。 [图表规范](../../standards/图表设计规范.md) · [设计规范](../../standards/设计规范.md) · [旧生成任务入口](<../../../Holo/Holo APP/Holo/Holo/HoloApp.swift#L439>)

显示路径优先读当前已确认的结果。查询按范围分批，覆盖同一范围的并发读取合并。锁屏恢复、前台返回和手动刷新时重读，查到睡眠样本补写或删除后更新受影响窗口。历史聚合在健康页使用时才加载，快速切日取消过时请求或只接收仍匹配选中日期的结果。端上结果视为可重算的内存数据，通过当前成功查询更新。不可用时恢复相应数据状态。

有已设置的个人睡眠目标、且用户进入趋势详情主动查看怎么调整时，最多给一个可撤回的尝试。默认入口仍是「查看依据」。

## 验收与交付

| 必验场景 | 通过标准 |
| --- | --- |
| 跨午夜、跨中午、夏令时 | 跨午夜的 8 小时主睡眠在首页、详情、「今日」数字一致。额外的 30 分钟单列。跨中午按实际记录结束日归属。夏令时时长按实际经过时间，时间轴钟点标注正确。 |
| Apple Watch 和 AutoSleep 同时记录、同段分期冲突 | 总睡着时长和分期均无双算，来源可核对。无法裁决时显示候选和原因，趋势不消费这晚。 |
| 单一来源、只有时长、缺分期或缺体征 | 时长仍可看。无 REM 或无 HRV 样本显示独立缺失，缺口留白。日间呼吸、睡着前的 HRV 和正午运动心率不进入睡眠统计。 |
| 少量记录、单次离群、来源变化、睡眠跨午夜 | 首页不会把数据不足或单晚波动显示成持续变化。两周方向一致且达到门槛时，趋势与点击后的数值及日期一致。23:50 到 00:10 的差为 20 分钟。 |
| 锁屏、权限变化、补写/删除、快速切日 | 解锁后可恢复。无样本与暂不可用文案准确。返回前台重读，旧数据从相关摘要失效。快速切日时，旧请求不能覆盖新日期。 |
| 真实使用与性能 | 在断网真机核对最新一晚、来源、已有体征和回看入口。至少各核对一份完整 Watch 分期和一份仅时长或低覆盖记录，双来源要有真实样本佐证。用同一设备对比改动前后的打开与连续切日表现。 |
| 用户理解 | 让用户自己找最近一晚，并指出一条趋势的依据。测试有变化和无足够记录两种情况，观察是否误把缺失当零，是否误读为健康诊断。 |

先复用现有 `HealthSleepSessionSplitterTests`、`HealthSleepTimelineBuilderTests`、`SleepStructureAnalyzerTests` 及 `HealthPhase2WalkthroughUITests`。补齐跨入口同值、源冲突、个体趋势、样本匹配与日期竞态等当前测试覆盖不到的回归行为。UI 走查进入健康首页、睡眠详情、身体状态，以及「今日」的入口，验证内容和按日期跳转。新增测试文件按项目规范挂载实际测试目标。 [质量红线 §§8–9](../../standards/quality-redlines.md#8-归档窗口重跑红线-2026-11-12-随每周回顾-117-带病上架设立)

从仓库根目录使用项目构建包装器。以下两个测试命令的计数来自当前测试文件，用例增删时把 `--expect` 更新为实际预期执行数。将 `<模拟器 UDID>` 换成仓库规范所要求的无头模拟器实例 ID。

```bash
python3 "Holo/Holo APP/Holo/BuildScripts/holo_build.py" build
python3 "Holo/Holo APP/Holo/BuildScripts/holo_build.py" test --dest 'platform=iOS Simulator,id=<模拟器 UDID>' --only HoloTests/HealthSleepSessionSplitterTests --expect 12
python3 "Holo/Holo APP/Holo/BuildScripts/holo_build.py" test --dest 'platform=iOS Simulator,id=<模拟器 UDID>' --only HoloUITests/HealthPhase2WalkthroughUITests --expect 13
```

**首版发布判定。** 三个入口同晚一致，足够的记录能解释变化，稀疏数据能如实显示，旧健康页生成入口已退出，现有健康入口均可跳转。提交前核对范围及变更日志，真机安装和归档遵循项目闸门。源冲突或钟点趋势无法通过真机验证时，采用表里的待确认状态或记录摘要，先收窄到已有证据支持的体验。

## 首版通过后的推进顺序

1. **生活关联。** 先做一个端上对照，按运动结束对齐下一段主睡眠，比较同类日期有明确运动记录和能确认无运动的两组。给出两组各自有效天数、典型入睡时间差和日期。两段独立窗口均有足够对照且方向一致后，才进入首页。运动记录不完整时只回看已记录的运动。第一条对照跑通后，再接「短睡后当天已有计划的习惯完成情况」。
2. **按需接入腕温、血氧。** 先在真机确认各设备和地区可读样本，再在相应用途申请权限。腕温只展示个人基线差值，血氧展示原始采样覆盖。用户在这些新数据上能回答具体问题后，再扩展心肺适能和环境等主题。

本稿的多来源时间差、主睡眠识别、比较窗口和采样门槛为试用默认值。真实样本覆盖与真机表现待实施阶段记录，验收时以用户看到的结果为准。
