## 1. 用户现在可以完成什么旅程

- Today 主行动卡后有「帮我理一理」入口 → 说一句当前情况（文字/语音/快捷语）→ AI（或手动模式）给出一份候选 → 原位逐项调整（加入/放下/只推进一步）→「采用这个安排」→ 安排区变三分组（今天选择推进 / 固定安排与截止 / 今天先放下·可展开）→ 回执可「撤销安排」。
- 原任务截止、执行时段、提醒、清单、优先级全程不被改动；放下只对当日生效。
- HoloAI 聊天说「今天事太多帮我理一理」→ 同一候选卡（采用/调整/过期重整理）；混合「记账+整理」先问处理哪个，未选前零写入。
- 任务详情 / Matter 执行区有「加入今天 / 今天先放下」轻量出口（今天到期任务直放需走理一理确认）。
- 未启用本功能的用户：Today 完全保持原基础体验（resolver 旧路径逐字节保留，20 个既有 resolver 测试全绿佐证）。

**设计差异（与规格的偏离，均为实现判断）**：
1. 空库建任务未加显式 taskID 参数——`TodoTask.create` 本就是无副作用 context 工厂，原子性由「同一次 save」+ 幂等回执（revision.createdTaskID）保证，重试不重复建（测试实证）。
2. 后端意图能力门禁（today_relief_v1 capability header 过滤）未建 header 基建——以 iOS 侧未知意图兜底（AIIntent 解码未知值→.unknown，不执行写动作）达成 R44「旧客户端不接未知新 intent」的实际安全性；header 通道留待后续真有第二个新意图时一并建。
3. intent prompt 长度红线 8000→8100（随功能扩容重划，prompts.test.js 留档注释，沿用仓库五次先例）。
4. TodayReliefSheet 的「需要留意」约束行在 G2 首版传空数组（constraints 由安排区「固定安排与截止」分组承担同一职责）——AI 请求仍携带 constraints 字段位。
