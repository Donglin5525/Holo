# Holo 1.1「今天减负」产品评审方案

> 版本：V0.1，2026-10-03。用途：评审产品范围、交互和验收标准。
> 工程接续：以 [GLM 完整实施方案 V1](/Users/tangyuxuan/Desktop/Claude/HOLO/docs/homepage/plans/2026-10-03-Holo1.1今天减负-GLM完整实施方案-V1.md) 为准。V1 已明确首版不取消既有执行时段、截止事实与主动选择分离，以及当日步骤目标/同步/撤销规则；本文保留原评审过程，不再作为直接实施指令。
> 状态：产品提案；未修改 App、后端或 Prompt，未验证实际模型效果、真机与线上体验。
> 结论：在现有「今天」中增加「帮我理一理」，将用户当前情况转化为可审阅、可执行的当日安排调整。1.1 的主线是跨任务减负；单任务拆解继续复用现有能力。

## 1. 用户价值与版本定位

面向已经有生活安排、临时忙不过来或不知如何开始的人。用户要解决的问题是「现在的情况和原计划不匹配」，希望少做一些安排上的决定，并知道接下来具体做什么。

产品承诺：**说说现在的情况，Holo 帮你理清今天，保留真正要紧的事。**

完整体验：表达当前情况 → 看懂调整 → 一次采用 → 原任务与今天同步变化 → 完成后继续下一件。

成功的结果可以是减少今天主动推进的事、保留必要承诺、恢复一件中断的事。任务越多、建议越长，均不代表效果越好。

## 2. 现状与新增范围

以下只确认当前工作副本的实现基础，不代表已完成商店、真机或生产验收。

| 已有基础 | 当前可复用价值 | 本次产品调整 |
|---|---|---|
| 今天主行动、今天的安排、正在推进 | 用户已有每日工作台 | 增加当日安排的主动调整与采用后的持续状态 |
| 主行动「稍后」 | 暂时换一个主行动 | 明确其为「先看其他事」；与持久化的「今天先放下」分开 |
| 任务截止日期、计划时间段 | 已有期限与执行时间的部分区分 | 建立统一的「今天选择推进」语义，所有入口使用同一选择结果 |
| Matter 与带背景的讨论 | 同一件事可以持续讨论 | 继续引用原事项和任务，不为调整再建一套事项 |
| 帮我拆开、卡住了、分步推进 | 单任务内部的开始、修订与恢复 | 从当日安排直接进入现有任务和当前步骤 |
| 个人情境规划、记忆、健康/财务记录 | 可提供有依据的个人背景 | 首版按需取最少相关信息，用户当前表达优先 |

当前「今天」主要聚合逾期、今日到期和少量无日期任务；`plannedForToday` 存在于读取候选中，不能据此认定已具备独立、持久化的今日选择功能。主行动的「稍后」目前只在当前会话内降级。任务已有 `plannedStart/plannedEnd` 字段，但不能把截止时间当成计划执行时间。

## 3. 1.1 首版边界

### 必须交付

- Today 常驻入口「帮我理一理」，HoloAI 对话可进入同一流程。
- 基于用户当前表达、真实未完成任务、已有日程与事项，生成一份当日调整。
- 调整支持「今天保留」「今天先放下」「今天推进已有步骤」。
- 原任务已有今天的执行时间时，撤销这段时间必须在采用前显示具体变化；首版不替用户安排新的精确时间段。
- 一次采用后真实保存今日选择和获准的执行时间变动；重启仍然有效。
- 完成与撤回沿用现有规则，完成后自动显示当前安排中的下一件。
- 已有分步任务可以显示真实的下一步，并保留未完成的根任务。
- 空任务库可以用一句话提出一个任务，经过同一审阅创建并加入今天；不要求用户先积累一周数据。

### 后续版本

- 智能安排整周、自动寻找未来时间段、多事项完整重规划。
- 从健康指标自动决定用户今天能做多少，或自动修改习惯目标。
- 常驻主动催促、每天必须签到、独立教练页、新的生活评分。
- 财务预算变化的自动处置、自动变更真实日程或对外发送消息。

「中断后继续」首版只恢复现有任务/步骤的真实进度；完整历史回顾、跨事项恢复建议留到后续。保证主线可用后再扩展主动提醒。

## 4. 页面与入口调整

### 4.1 主入口：今天首屏

保留现有主行动卡，在卡片下方增加一个轻量按钮「帮我理一理」。有无紧急事项、有无历史数据均可进入，不依赖超载检测，不弹出强制引导。

将主行动卡原「稍后」文案调整为「先看其他事」，继续保持临时换焦点的含义；真正放下今天的安排必须经过下文的审阅与采用。

主流程原位使用品牌底色的单一弹层；从打开到采用保持在同一弹层内，不从 Today 跳到聊天后又要求用户自己找回 Today。

### 4.2 表达情况

标题：「今天怎么安排更合适？」

输入框示例：「突然加班，只剩半小时，帮我看看先做什么。」沿用现有语音输入方式。

输入框下有两个可选快捷表达：「时间不够了」「今天想轻一点」。点按填入可编辑文本，不立即发送。主按钮「帮我理一理」。

不要求先填写情绪分数、时间问卷或生活档案。已有输入够用时直接给建议；决定性约束缺失时只问一个问题，例如「你今晚最晚到几点需要停下来？」。回答后仍存在重要未知，保守保留原安排并明确未知，不进入循环问答。

### 4.3 审阅调整

顶部只用一句话讲结果，例如：「先保留报名，旅行推进一步；整理资料和照片今天先放下。」

按以下顺序展示，不额外叠加总分、环形进度或新仪表盘：

1. **今天保留**：通常 1–3 个主动推进对象；每项一个短理由。1–3 是默认呈现目标，必须处理的事实多于 3 个时如实显示。
2. **今天先放下**：只显示要调整的任务，注明留在原事项/清单，以及撤销的今日执行时间（若有）。
3. **需要留意**：存在尚未解决的截止、固定安排或超出时间限制的义务时才显示，禁止隐藏冲突。

列表行就是审阅入口，可点选「保留在今天」或「今天先放下」；保持一份调整内容，不另外打开全功能任务编辑页。不熟悉的专业字段、内部状态和模型名称不上页面。

已有具体执行步骤时，在原任务下展示「今天只推进：……」。没有步骤时展示根任务，并提供现有「帮我拆开」入口；不能把临时生成的小动作说成已经保存的步骤。首版不在每日调整内再生成一套分步计划。

默认主按钮「采用这个安排」；次要操作「再说一句」。无变化时主按钮改为「按原安排继续」，不要制造一次假的保存。

用户标为「必须」的事项保留为只读约束；用户要撤回这个约束，可在「再说一句」中明确表达。固定日程、今日到期与逾期事实不提供一键隐藏或改期；有未来截止的任务可以移出今日主动安排，其原截止继续保留。紧急义务超过可用时间时，不提供「已经轻松安排好了」式承诺。

### 4.4 采用后回到今天

弹层关闭，原主行动卡显示第一件有效行动。回执例如：「已更新今天的安排，2 件事今天先放下。」并提供撤销。

「今天的安排」调整为同一列表内的两个小标题：

- **今天选择推进**：用户已采用的真实任务，按照采用顺序；根任务带当前具体步骤时，在行内说明。
- **固定安排与截止**：真实日程、到期与逾期事实，保持可见。同一任务已在上方出现时，仅保留它的截止标签，不重复列一遍。

「今天先放下」收成列表底部可展开的一行，可将任务重新加入；用户无需离开 Today 才能纠正。

未采用过安排的用户继续看到原有 Today，不强制建立每日计划。未完成的主动安排不自动搬到明天；次日恢复原来的基础显示，截止事实继续按真实时间判断。

### 4.5 其他入口

- HoloAI 中用户明确表达「今天做不完/帮我理清今天」时，显示同一份调整卡。一次采用后可直接「查看今天」，不再创建一个 Matter。
- Matter/任务详情沿用现有「帮我拆开」「卡住了」；增加轻量的加入今日/今天先放下出口，读取同一安排事实。
- 首页仍使用现有 Today 入口，不新增导航栏入口或第二个 AI 助理。

## 5. 必须统一的产品规则

| 概念 | 含义 | 可调整范围 |
|---|---|---|
| 截止时间 | 原任务何时需要完成 | 首版调整卡不修改；需要改期时走原任务的明确编辑 |
| 固定日程 | 已记录、按时间发生的安排 | 保持事实，不由调整卡改动 |
| 计划执行时间 | 用户给任务安排的时间段 | 首版只允许明确审阅后撤销今天的执行段，不生成新时间段 |
| 今天选择推进 | 用户今天愿意投入注意力的任务 | 可加入、移出，采用时保存建议顺序；不等同于任务完成 |
| 今天先放下 | 今日暂不主动推进 | 不删除、不归档、不标完成、不默认移到明天；期限仍生效 |
| 具体步骤 | 完成原任务结果所需的动作 | 引用已有步骤；做完一个动作不自动完成原任务 |

重要补充：

- 所有已有截止日期都先按真实约束保留，不从标题猜「这只是我随便填的日期」。
- 正在进行或即将发生的固定日程仍优先提示；其他可灵活任务按用户采用的顺序推进。所有 Today 出口遵循同一规则。
- 用户已选的顺序可以被新的紧急事实影响；主卡说明「接下来有固定安排/截止已临近」，不默默改掉已保存选择。
- 用户说的可用时间是约束；任务耗时只有实际信息或明确估计才能展示，估计必须标注，不能承诺「30 分钟一定做完」。
- 空白日程不等于用户全天有空；缺健康数据不等于状态良好；没找到安排不等于用户没有安排。
- 当前表达优先于旧记忆。「我今天很累」仅作为本次/当日约束，默认不写入长期人格或生活事实。
- 没有可放下的事时如实说明。可协助用户确认最重要的一项或去原任务协商/修改期限，不伪造可行计划。
- 习惯继续独立打卡统计。日计划中说「今天轻一点」不等于习惯已打卡、已暂停或连续天数被保护。
- 今日安排按明确的当地日期生效；跨午夜不继续采用旧日草案。时区变化后的日期归属必须清楚，不跨日静默迁移。

## 6. 贯穿首版的完整用户旅程

以下为模拟数据，用于评审与验收，不代表已读取东林个人任务。

场景时钟：2026-10-03 20:00，用户在正常入口已有以下任务：

| 原任务 | 真实约束/状态 | 原今日选择 |
|---|---|---|
| 提交活动报名 | 当晚 21:00 截止，未完成 | 是 |
| 预订旅行机票 | 10 月 10 日截止，已有分步计划；当前步骤「查看两个合适航班」 | 是 |
| 整理旅行资料 | 无截止，无精确执行时间 | 是 |
| 整理照片 | 无截止，无精确执行时间 | 是 |

1. 用户进入 Today，看到报名主行动、今日安排和「帮我理一理」。
2. 用户说「突然加班，只剩半小时，今天先轻一点」。
3. Holo 提议优先完成报名，剩余时间允许时再推进机票的当前步骤；资料和照片今天先放下。报名能否完成的时长未核实时，不保证能在半小时完成。
4. 用户看到截止仍为 21:00/10 月 10 日，两个放下项仍保留在原位置。此时尚未更改任何任务或今日选择。
5. 用户点击采用。保存今日选择：报名、机票；两项自主整理任务标为今日暂不推进。保持原 4 个任务与已有事项、步骤关联。
6. Today 主卡仍是报名，报名完成后切到机票。固定日程若突然临近，优先提示该事实。
7. 用户进入机票原任务，完成「查看两个合适航班」；展示真实后续步骤。机票任务仍未完成，今天已完成的这一步不强迫继续推进全部剩余步骤。
8. 同一任务的当日推进目标完成后可从主动安排中收起，标注「今天推进到这里」；根任务和截止继续在原任务/事项中保持真实状态。仍有其他截止时留意区继续展示。
9. 用户退出并重开 App，今日选择、已完成报名、机票步骤与未完成根任务均一致；不会把已处理步骤再推荐一次。
10. 用户把照片手动重新加入今天，真实选择同步到所有入口。
11. 次日两项放下任务仍在原清单，不变成自动创建的「明日负债」。机票截止未改，继续按原规则显示。

采纳本示例只调整原任务的今日安排。**不生成重复任务、不再建事项、不把步骤升级为独立待办。**

## 7. 上下文：用得少，但确实有帮助

| 信息 | 首版用途 | 使用规则 |
|---|---|---|
| 本次用户表达 | 时间、当前负担、明确必须做的事 | 最优先，只对本次/当日有效 |
| 未完成任务、原截止、当前步骤 | 决定可推进对象与保留约束 | 正常取数、真实状态，不只取 Today 首屏的少量项目 |
| 已记录日程 | 避免撞上固定安排 | 在授权且数据可用时参与；不推断所有空闲时段 |
| 当前事项 | 理解任务目的与已有背景 | 只读本次相关事项，不要求用户重说整段背景 |
| 财务、健康、想法 | 在确实相关时解释建议或约束 | 不作为首版必须接齐的前置；不从相关性推断原因 |

相关历史依据以折叠的「为什么这样安排」提供可追溯来源；简短说明「你刚才说只剩半小时」「报名今晚截止」即可。无需为了显示懂用户而暴露无关私人记录。

## 8. 加载、空态与异常

| 状态 | 用户看到什么 | 必须兑现的行为 |
|---|---|---|
| 正在生成 | 「正在结合你的安排整理」＋可取消 | 页面仍可关闭；取消后迟到结果不自动改变安排 |
| 无历史任务 | 「说一件你现在想处理的事」 | 审阅后创建最多一个明确根任务并加入今天；不凭空建一串任务 |
| 信息不足 | 一个能影响结果的具体问题 | 不进入反复问卷；可返回原安排 |
| 没有变化 | 「当前安排已经比较精简」 | 给继续原行动的出口，不假报已更新 |
| 超出可用时间 | 明确指出必要事项仍有冲突 | 不承诺可完成，不自动修改期限 |
| 网络/生成失败 | 「这次没整理好，原安排已保留」 | 保留输入和真实原安排，提供重试与手动调整 |
| 数据局部不可用 | 「目前只根据可用任务整理」等具体范围说明 | 不把缺数据当作零安排或零负担 |
| 审阅期间任务被完成/删除/改期 | 「安排有变化，需要重新看一下」 | 保留表达，刷新调整；不采用旧结果 |
| 保存失败 | 「没有更新成功，原安排已保留」 | 本次变化全成或全不成；不留下混合态 |
| 重复点击采用 | 显示同一次结果 | 不重复写入、不重复创建对象 |
| 跨午夜 | 「已经是新的一天，重新整理今天」 | 不把昨晚草案采用为今天的安排 |

撤销恢复本次采用改变的今日选择及被撤销的执行时间；不撤销用户后来完成的任务。采用后短暂显示「撤销」，当日「本次调整」中也可恢复。来源已删除或又被编辑时说明冲突，不强行覆盖新变化。

## 9. 视觉与文案

沿用 Holo 现有暖底、品牌橙、卡片圆角与字体。页面水平边距 16pt，主要区块间距 20pt，主按钮与行操作至少 44pt 可点；品牌色和排版最终以现有设计系统为准。

- Today 保持一个主行动，不叠两张竞争的专注卡。
- 审阅采用短句、真实任务名称和明确前后变化；依据默认折叠。
- 弹层沿用统一品牌壳，大字和 VoiceOver 能完整阅读任务、变化与采用按钮。
- 语音是文本表达的另一入口，不另建语音模式；键盘不盖住采用按钮。
- 避免「你今天又没完成」「积压 12 件」「效率下降」等审判式文案。
- 允许放下，也允许把一天安排得很满；产品如实说明冲突，最终保留用户的明确选择。

## 10. 实施顺序（用于产品排期）

| 阶段 | 产出 | 进入下一阶段的标准 |
|---|---|---|
| P0：今日安排语义 | 截止、执行时间、今日选择、暂不推进的统一规则；手动加入/移出今日 | 重启和不同入口一致；事实期限不变 |
| P1：表达与审阅 | 一个弹层、可理解的变化、取消/失败/无变化/冲突状态 | 真实用户能说清采用后会改变什么 |
| P2：真实采用与继续 | 一次保存、撤销、完成后下一步、现有步骤接入 | 上述完整旅程通过；失败无混合状态 |
| P3：真实 AI 与版本验证 | 接入原有上下文与模型能力，核对费用、延迟、后端发布 | 少量真实用户连续试用；真机和线上分别有证据 |

新增能力预计需要 iOS 与后端的 AI 请求/Prompt 协同；后端改动需要发版。本文未执行这些改动。不能只靠本地文案、演示数据或生成成功就认定能力已完成。

## 11. 验收与效果判断

产品必须通过：

1. 用户不懂 Matter/模型/计划实体，也能从 Today 找到入口并完成采用。
2. 一份真实调整既能保留要紧事，又能放下可灵活项；不会靠隐藏期限达到减负。
3. 用户在采用前能理解任务、日期、执行时间的实际变化；取消时原安排完全保留。
4. 原任务、关联、步骤及统计口径不被重复或伪造；部分步骤完成不等于根任务完成。
5. 重启、返回、重复点击、失败、撤销与来源变动时状态可信。
6. 无历史数据可以完成首个明确任务的审阅与加入今日。
7. 没有可放下的事、任务超出可用时间时能够诚实表达。
8. 次日不自动累计昨天放下的任务；到期事实仍正确。

先招募 5 位真实用户试用 7 天，覆盖「临时没时间」「不知先做什么」「中断后回来」。观察是否理解调整、实际采用、进入并完成一个具体动作，以及第二次遇到问题是否主动回来。小样本用于发现问题，不据此宣称留存提升或市场验证完成。

发布后的核心观察：入口到采用的流失原因、采用后实际开始行动的比例、再次使用、手动纠正和撤销原因。任务完成总数与模型调用次数不作为减负效果的主要判断。
