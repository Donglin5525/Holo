# Holo 锁屏习惯打卡

2026-11-20 · 降为候选方案 · 等其他小组件原型一起评审

时钟下方的组件要求先完成系统认证。根据本轮评审，锁屏打卡暂缓排期。若继续验证完全锁定时的打卡体验，先测试底部控制按钮能否在真机落库，再决定是否排入开发。

## 1. 产品决定

给一个常做的习惯一个固定位置。完成拉伸后，用户亮屏，看见「拉伸」，点「打卡」，看到「已打卡」，始终停留在系统界面。再次打开 Holo 时，同一条记录已经出现在习惯详情，相应的今日进度和关联目标按原规则更新。

候选组件名为「习惯打卡」，每个实例绑定一个习惯。时钟下方的长条和桌面小号可共用配置和动作。首版支持仍在进行的正向「打卡」型习惯，包括每日、每周和每月目标。周、月目标已经达成时，仍按 Holo 既有规则允许当天记录。累计、测量和「想减少的事」放到后续评估，各自需要明确的输入或记录语义。[现行习惯记录方式](2026-11-18-习惯记录方式与主题文件夹产品方案.md)

首版建议沿用现有小组件的 Holo Plus 权益。免费用户看到明确的权益说明。已确认有效的 Plus 用户可以离线打卡。使用系统编辑器添加和更换习惯，快捷打卡入口跟着用户选择走，组内顺序、置顶和文件夹变动均通过同一习惯 ID 解析。

### iPhone 锁屏上的两个位置

| 位置 | 用户体验 | 实施决定 |
| --- | --- | --- |
| 时钟下方 WidgetKit 小组件，iOS 17+ | 看见名称与状态，就地完成。设备尚未认证时，需先用 Face ID 或密码完成系统认证。 | 候选入口。若进入实施，实测已通过认证时的一次点击，以及未通过时如何恢复。 |
| 锁屏底部系统控制按钮，iOS 18+ | 占用一个手电筒／相机位置。系统提供可配置的后台动作和认证策略，按钮空间更紧。 | 评审决定继续时，先做独立真机探针。只有能在设备仍锁定时成功落库、有清楚反馈且符合隐私规则，才考虑提供「免 Face ID」选项。 |

## 2. 用户动线和状态

1. 长按锁屏 →「自定」→ 添加 Holo 的「习惯打卡」→ 点刚添加的组件 → 选「拉伸」→ 完成。组件库用示例说明用途。加入实际锁屏后，未选择时显示「编辑小组件，选择习惯」。用户可以配置多个实例，每个实例独立选择。
2. 完成拉伸后点「打卡」。保存过程中沿用系统交互反馈。保存确认后显示「已打卡」和对勾。再点完成态只会刷新，连点旧打卡按钮也只会确认同一天的记录。误打卡可在 Holo 习惯详情撤销。
3. 下一个习惯日重新出现「打卡」。例如结算设为 04:00，凌晨 02:00 的打卡算前一天，04:00 起进入新的一天。按这个时间预排下一条组件状态。系统刷新延迟时，点旧对勾可就地更新，再对新一天打卡。

```text
日常使用                     完成
拉伸              [打卡]     拉伸              ✓ 已打卡

没有可选习惯                 保存失败
习惯打卡                     拉伸
先创建一个打卡习惯           保存失败           [重试]
```

| 状态 | 组件表现 | 恢复途径 |
| --- | --- | --- |
| 没配、没有符合条件的习惯 | 分别显示「编辑小组件，选择习惯」和「先创建一个打卡习惯」。 | 在系统编辑器选择，或在 Holo 新建。组件只在创建态提供明确标注的 App 入口。 |
| 名称变化、移动、重排 | 原选择随真实名称更新，动作仍指向同一个习惯。 | 原位置继续使用。 |
| 暂停、计划恢复 | 显示「已暂停」。到计划恢复日按 Holo 的习惯规则恢复，临时无法确认时显示「更新状态」。 | 手动恢复或等计划恢复，原选择可继续用。 |
| 归档、删除或类型不再支持 | 显示「重新选择习惯」，停用打卡。 | 用户可另选。原习惯恢复且仍被选中时继续使用。 |
| 跨日、旧状态、加载中 | 显示「更新状态」或「正在加载」，依据本机库刷新。 | 点旧「打卡」或对勾都能更新，刷新后按新状态操作。 |
| 存储临时不可用、读取或写入失败 | 显示「暂时无法读取」或「保存失败」，保留明确的重试方式。 | 再试一次。重复请求读取同一归属日的真实状态。 |
| 系统隐藏敏感内容、Holo 应用锁开启或隐私状态未知 | 只显示「习惯打卡」。遮罩状态移除组件上的打卡按钮，应用锁开启或状态未知时也拒绝旧按钮发来的写入请求。 | 系统认证或应用锁设置生效后，按最新权限刷新组件。 |
| Plus 权益变更 | 已确认无权益时显示「Holo Plus 功能」。权益状态缺失时显示「打开 Holo 更新状态」。 | 在 Holo 恢复／刷新权益后原配置继续使用。 |

长条组件用系统字、系统前景色和直观的空圈／对勾。优先保证动作与状态可辨，长名称末尾截断，VoiceOver 读完整名称、状态和可用动作。桌面小号沿用 Holo 小组件样式，保留 44 pt 可点击区域。实测浅色、深色、着色、常亮和大字号。状态同时有文字与形状，触觉或动画作为辅助反馈。系统编辑态使用简中、繁中、英文。

## 3. 实施约定

```text
系统编辑器选定习惯 UUID
  → 组件读同一份本机习惯与习惯日状态
  → 点「打卡」后按当前数据重新校验
  → 共享习惯写入路径提交完成
  → 组件读取保存结果，App 消费本机变更，现有 iCloud 镜像继续同步
```

### 按身份和归属日完成一次

- 选择通过 `AppIntentConfiguration` 和 `AppEntity` 实现。候选列表按习惯域有效数据查询，设置用 UUID，覆盖排在现有组件前五项之外的习惯。同名项优先用文件夹和图标辅助区分。初次添加不自动选中第一项。预览渲染用示例，线上状态来自本机数据。读取路径区分「未选择」「习惯确实失效」与「库未就绪／查询失败」。新增独立的组件标识并注册到 `HoloWidgetsBundle`，既有「今日习惯」组件实例继续加载原组件。[小组件注册入口](<../../../Holo/Holo APP/Holo/HoloWidgets/HoloWidgetsBundle.swift>) · [Apple 可配置小组件](https://developer.apple.com/documentation/widgetkit/making-a-configurable-widget)
- 两套现有写入位于 `toggleCheckIn` 和 `performCheckInReceipt`。抽取同一个打卡写入规则，区分「标记完成」和「撤销」。App 和旧桌面组件保留界面上的打卡／撤销操作，执行时按用户所点的状态传递目标动作。同一条未完成状态在两处被点中时，两次点击都表达完成。AI 的正向打卡指令也按完成处理，原有备注按各入口规则保留。小组件使用可在扩展运行的仓库层，App 内协调器继续处理界面反馈。对可用的历史取消记录恢复原行并保留备注，完成已存在时直接返回原记录，读取失败直接回报失败。[旧打卡动作](<../../../Holo/Holo APP/Holo/HoloWidgets/HoloWidgetIntents.swift>) · [习惯回执](<../../../Holo/Holo APP/Holo/Holo/Models/HabitRepository+InteractionRebuild.swift>) · [对话打卡路径](<../../../Holo/Holo APP/Holo/Holo/Services/AI/IntentRouter.swift>)
- 动作带 `habitID` 和渲染时的归属日。执行时重新按同一套 `HabitDayAttribution` 计算归属日，并核对主记录、暂停、记录方式和权限。日界已变时先刷新。名称变更后仍写同一个 ID。一次事务内用同一个时刻判定归属并设置记录时间，测试覆盖零点存量兼容、非零点结算、时区和夏令时。未来显示按既有业务日界生成时间线，系统延迟时靠重新校验守住真正写入的日期。[习惯日规则](<../../../Holo/Holo APP/Holo/Holo/Models/HabitDayAttribution.swift>) · [Apple 刷新机制](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date)
- 同一设备的 App 和扩展可能并行读写。把「读最新有效记录 → 决定新增、更新或复用 → 保存」放到同一设备的共享串行边界。现有可同时写入同一习惯日的入口也进入该边界。组件请求携带渲染时的记录状态版本。遇到已完成就返回当前状态，若期间有更新的明确撤销或删除，旧请求只刷新，由新卡片接收下一次明确操作。版本优先复用共享库的变更凭据，并在并发测试证明上述约束。先用两个独立容器复现并发，再选最低成本的落地方式，优先验证 App Group 进程间协调配合独立写上下文，锁只覆盖短事务，取得失败即可重试。Widget 读操作走无副作用路径，计划恢复使用现有生命周期规则，避免显示或搜索时顺带改动其他习惯。

### 保存、刷新和同步

- **习惯记录是真源。** 复用 App Group 共享库和模型指纹预检，扩展打开失败时返回可重试状态。新组件只读绑定的习惯与必要记录，现有今日习惯总览继续使用其聚合快照。成功须由保存回执或已完成记录确认。保存成功但显示更新失败时，让下一轮从实际记录自愈，同一动作重试后仍只保留一次完成。缓存用于显示，无法读取真实数据时用未知状态。
- 写入先落库再刷新。WidgetKit 在按钮动作返回后安排刷新，App 内打卡、撤销、调整设置、iCloud 导入、权限变化也要使新组件失效重读。App 侧核对共享库存储历史／远程变更的接收与首次打开的回读，验证习惯详情、今天页、连续天数、成长和关联目标。当前进程内的 `.habitDataDidChange` 只能通知本进程，跨进程以共享库保存为准。[现有快照入口](<../../../Holo/Holo APP/Holo/Holo/Services/Widgets/HoloWidgetSnapshotService.swift>) · [Apple 点击后刷新](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities)
- **双设备离线打同一天要显式验收。** 当前新记录用随机 UUID，按 UUID 的旧副本去重无法处理两台设备各自生成的同日记录。应用按既有归属日对正向打卡做同日有效完成判定，详情、进度与撤销共享该规则。同日多条有效副本只贡献一个完成，撤销处理当前已知的同日有效完成并保留备注及原记录证据。并发且此前尚未同步到本机的新完成在导入后仍有效。遇到历史不一致项先保留证据，验证撤销、删除和后续同步不会让已见旧记录复活。跨设备收敛在改动前用隔离双端样本对拍。若旧版混用无法正确收敛，明确兼容方案后再发布。云端唯一约束无法承担此语义。[现有记录创建](<../../../Holo/Holo APP/Holo/Holo/Models/HabitRecord+CoreDataProperties.swift>) · [Apple CloudKit 模型约束](https://developer.apple.com/documentation/coredata/creating-a-core-data-model-for-cloudkit)
- 既有主 App 驱动 iCloud 镜像。分别验证「锁屏已存到本机」「主 App 后台有运行机会后导出」「另一设备成功导入」。重启未首次解锁、断网或 iCloud 暂不可用时，按本机库是否可用独立处理。界面上的「已打卡」对应本机保存。

### 权限、隐私与反馈

- 小组件选择列表、显示和动作入口都检查现有权益与隐私规则。主 App 把扩展所需的最小状态写入 App Group，包含可信的权益状态以及现有权益机制提供的有效期。迁移时区分已知免费、已知有效和状态缺失，避免首次升级把已付费且可验证的用户显示成免费。应用锁状态当前在 App 自己的设置里，需接入同一共享权限来源，状态未知或锁开启时仅显示通用内容。用系统 `privacySensitive` 保护名称、图标和完成状态，验证常亮、隐私遮罩和换锁屏的缓存。若原生验证显示私密名称可能残留，锁屏样式使用通用名称与图标直至可以可靠遮蔽。[现有应用锁设置](<../../../Holo/Holo APP/Holo/Holo/Services/Security/AppLockSettings.swift>) · [现有权益状态](<../../../Holo/Holo APP/Holo/Holo/Services/Subscription/HoloEntitlementState.swift>) · [Apple 小组件隐私](https://developer.apple.com/documentation/widgetkit/creating-a-widget-extension#Hide-sensitive-content)
- 失败反馈与习惯 ID、归属日和相应尝试关联，避免 A 的失败显示到 B，或旧失败覆盖新成功。成功后的对勾以本机库为准。验收记录点击到显示确认的中位数和慢样本，先用已认证、锁屏亮着的普通路径检验 **约 1 秒内可感知到反馈** 的体验目标，单列冷启动和系统认证时间。

## 4. 进入实施后的顺序和放行条件

| 阶段 | 交付 | 验收证据 |
| --- | --- | --- |
| 0 · 原生探针 | 先验证 iOS 18+ 底部控制按钮在设备仍锁定时能否落库。若评审仍接受需要系统认证的长条入口，用隔离测试习惯验证 iOS 17+ 长条组件的后台保存。 | 在对应入口的最低支持版本与当前日用版本录屏，记录每一步和系统认证状态，保存前后查同一个测试习惯的记录。必测 Face ID 已识别、未识别、密码和取消、App 在后台与手动划掉、飞行模式和重启后首次解锁前后。 |
| 1 · 共享写入 | 确认完成动作、归属日、失败恢复和共享库存储边界。 | 定向测试覆盖重复点击、两个进程同时点完成、撤销后延迟请求、写入失败后重试、保存后刷新失败、App 与对话打卡、旧取消行和备注、归档／删除／类型切换、自动恢复与结算边界。用隔离库测试读取失败和模型指纹拒绝。 |
| 2 · 完整体验 | 系统选择、锁屏长条、桌面小号、状态和三语。 | 真机从添加到完成走通。第 6 个以后的习惯、同名习惯、多实例、权限变化、编辑／恢复与 VoiceOver 均验收。已打开 App、旧桌面组件和目标联动做回归。 |
| 3 · 同步与试用 | 双设备同日收敛，完成候选版本的试用记录。 | 用隔离设备或测试账号验证双设备同日离线打卡、恢复联网、先后撤销／删除、旧版混用、另一端导入后的显示。用一次连续 7 天的真实日用试用记录是否愿意留着组件、成功／失败和是否还要补进 App。 |

**候选方案放行条件**是能用真机说明一件事。选中的习惯在系统认证后能就地保存。离线可查到一次真实记录，连点或同步恢复后均只贡献一次完成。日界、隐私和错误状态按上表处理。底部控制探针结果独立记录。构建、模拟器、真机和双设备各自保留结果。

**回退**优先用下一构建撤下新增组件入口，已保存的记录继续按同一习惯数据读取。方案范围为客户端，沿用现有 iCloud 模型和后端权益接口。验收使用隔离数据。把新组件、动作和项目接入放在可单独审查的改动里，发布前保留回退说明。
