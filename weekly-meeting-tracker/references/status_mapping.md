# 状态流转与关键词映射规则

## 状态流转顺序

状态按以下顺序流转，数字越大代表越靠后的阶段：

| 序号 | 状态 | 说明 |
|------|------|------|
| 1 | 待IT跟进 | 需求刚提出，等待 IT 接手 |
| 2 | 已IT跟进 | IT 已介入，开始了解需求 |
| 3 | 设计中 | 产品/技术方案设计中 |
| 4 | 设计完成 | 方案设计完成，待评审或排期 |
| 5 | 待研发 | 已通过评审，等待开发排期 |
| 6 | 研发中 | 开发进行中 |
| 7 | 待上线 | 开发完成，等待上线部署 |
| 8 | 待验收 | 已上线，等待业务验收 |

## 跟进记录关键词 → 期望状态映射

解析跟进记录中的动作关键词时，按以下规则映射到期望状态。匹配时忽略大小写，优先匹配更具体的关键词。

| 关键词（正则匹配） | 期望状态（满足其一即可） | 说明 |
|-------------------|------------------------|------|
| 评审、需求评审、技术评审、方案评审 | 设计完成, 待研发 | 评审通过后进入设计完成或待研发 |
| 设计、出方案、定方案、完成设计、输出方案、出草稿 | 设计完成 | 设计阶段的产出 |
| 研发、开发、进入开发、排期开发、进入研发、介入开发 | 研发中 | 进入开发阶段 |
| 上线、发布 | 待上线, 待验收 | 上线部署 |
| 验收 | 待验收 | 业务验收 |
| 提测、测试 | 待上线 | 提交测试 |
| 需求沟通、需求对接、需求澄清、对接需求、沟通需求 | 已IT跟进, 设计中 | 需求对接阶段 |
| 打标、业务打标 | 已IT跟进, 设计中 | 业务标注阶段 |
| 联调 | 待上线 | 前后端联调完成后待上线 |

## 时间节点解析正则表达式

以下正则用于从跟进记录文本中提取时间节点。解析前需先清除 HTML 标签。

### 清除 HTML 标签

```python
import re
text = re.sub(r'<[^>]+>', '', text)
```

### 明确日期格式

```python
# 匹配 M/DD, MM/DD, M-DD, MM-DD, M.DD, MM.DD 格式
pattern_slash = r'(\d{1,2})[/\-.](\d{1,2})'

# 匹配 MMDD 4位数字格式（需排除行首的跟进日期如 "0821："）
# 行首4位数字后跟冒号/空格的是跟进日期，不是节点时间
pattern_mmdd = r'(?<!^)(?<!\n)(\d{2})(\d{2})(?=[\u4e00-\u9fff])'

# 匹配 "XX日" 格式
pattern_ri = r'(\d{1,2})日'

# 匹配 "预计XX号" 格式
pattern_hao = r'(\d{1,2})号'
```

### 相对时间格式

```python
# 匹配 "下周X" 格式
pattern_next_week = r'下周([一二三四五六日天])'

# 匹配 "本周X" 格式
pattern_this_week = r'本周([一二三四五六日天])'

# 匹配 "明天"、"后天"
pattern_tomorrow = r'明天|明日'
pattern_day_after = r'后天'

# 匹配 "今天"、"今日"
pattern_today = r'今天|今日'
```

## 跟进日期 vs 节点时间的区分

跟进记录的典型格式为：`0820：研发进入联调。预计下周进入测试。`

其中 `0820` 是跟进日期（记录写入的日期），而 `下周` 是节点时间（预期的下一步时间）。区分规则：

1. 文本开头的 4 位数字后跟冒号（`：`或`:`）或空格的，视为跟进日期，不作为节点时间。
2. 文本中间出现的日期格式，结合上下文动作关键词，视为节点时间。
3. 如果文本中只有开头的跟进日期，没有其他时间信息，则标记为"无明确节点"。

## 年份推断规则

1. 默认年份取当前年份。
2. 如果解析出的月份比上期 sheet 的月份早 6 个月以上，则判定为下一年。
3. 如果解析出的月份比上期 sheet 的月份晚 6 个月以上，则判定为上一年（罕见情况）。
