# 周会需求进度追踪

## 概述

本技能用于每周五周会前的需求进度追踪。核心逻辑：读取上一期 sheet 中每条需求「跟进记录」里提到的下一节点时间和预期动作，在本期 sheet 中检查该需求的「状态」是否按预期变更，最终生成带 AI 判断的分析结果。

## 数据源规格

用户提供一个 Excel 文件（.xlsx），内部按周拆分为多个 sheet，sheet 名称为 4 位日期（如 `0821`、`0828`），代表当周周五的日期。

**固定表头（18 列）：**

| 列号 | 字段名 | 说明 |
|------|--------|------|
| A | 编号 | 需求唯一 ID（数字） |
| B | 系统模块 | 所属业务模块 |
| C | 跟进记录 | 本周跟进内容，含下一节点时间（核心字段） |
| D | 需求名称 | 需求标题 |
| E | 状态 | 当前需求状态 |
| F | IT标签 | 标签信息 |
| G | 实际完时 | 实际完成时间 |
| H | 业务标签 | 业务分类 |
| I | 耗时(天) | 耗时天数 |
| J | 第一提出人 | 需求提出人 |
| K | 提出日期 | 需求提出日期 |
| L | 跟进意见 | 跟进意见 |
| M | 任务工时(h) | 工时 |
| N | 业务跟进人 | 业务侧负责人 |
| O | IT跟进人 | IT侧负责人 |
| P | 类型 | 需求类型 |
| Q | 紧急度 | 紧急程度 |
| R | 预计完时 | 系统预计完成时间 |

**状态枚举值（按流转顺序）：** 待IT跟进 → 已IT跟进 → 设计中 → 设计完成 → 待研发 → 研发中 → 待上线 → 待验收

## 工作流程

执行 `scripts/weekly_tracker.py` 完成以下全部步骤。脚本接受 Excel 文件路径作为参数，自动完成解析、比对、判断和输出。如需调试或自定义，可按以下步骤手动执行。

### Step 1: 加载并校验 Excel

1. 读取用户提供的 Excel 文件，列出所有 sheet 名称。
2. 识别 sheet 名称中的日期格式（4 位数字如 `0821`），按时间排序。
3. 确认至少存在 2 个 sheet（上期 + 本期）。如果只有 1 个 sheet，提示用户这是首期数据，仅做基础统计，无法进行跨周比对。
4. 将最后一个 sheet 视为「本期」，倒数第二个视为「上期」。
5. 校验表头是否与固定 18 列一致，不一致时提示用户确认。

### Step 2: 解析上期「跟进记录」中的时间节点

对上期 sheet 中每条需求的「跟进记录」（C 列），提取下一节点时间和预期动作。详细解析规则见 `references/status_mapping.md`。

**时间节点解析优先级：**

1. **明确日期**：`6/25`、`06/25`、`0625`、`6.25`、`6-25`、`25日` → 具体月日
2. **日期 + 动作**：`6/25评审`、`预计21日完成设计` → 提取日期和动作关键词
3. **相对时间（兜底）**：`下周一`、`下周三`、`本周五` → 基于上期 sheet 日期推算（sheet 名 `0821` = 该周五 8/21，`下周一` = 8/24）
4. **模糊表述**：`节后`、`今天`、`明天` → 基于上期 sheet 日期推算
5. **无时间节点**：`优先级调整`、`有依赖，暂缓` → 标记为"无明确节点"

**注意：** 跟进记录可能包含 HTML 标签（`<span>`、`<br>`、`<img>`），解析前先清除。一条记录有多个时间节点时，取最远的。

### Step 3: 跨周比对状态变更

对上期中有明确时间节点的每条需求，在本期 sheet 中按「编号」查找并比对状态。判断逻辑：

- **本期找不到** → 需求已移出跟踪列表
- **节点未到** → 待下期验证
- **状态达到或超过预期** → 按期推进
- **状态未变化** → 未按期推进，计算延期天数
- **状态有变但未达预期** → 有进展未达预期

### Step 4: 生成 AI 判断列并输出

在本期数据基础上新增「AI进度判断」列，格式示例：

- `✅ 按期推进｜上期(0821)预计 8/26 评审，本期状态已变为「待研发」，符合预期。`
- `❌ 未按期推进｜上期(0821)预计 8/25 完成设计，本期状态仍为「已IT跟进」，延期 3 天，建议关注。`
- `⚠️ 有进展未达预期｜上期(0821)预计 8/25 上线，本期状态为「研发中」，已推进但尚未达到预期阶段。`
- `ℹ️ 无明确节点｜上期跟进记录未提及具体时间节点，本期状态为「设计中」（上期：已IT跟进），状态有变更。`
- `🔴 需求已移出｜编号 229907 在本期跟踪列表中未找到，请确认是否已关闭或转移。`

### Step 5: 输出交付物

1. 保存带「AI进度判断」列的 Excel 文件并交付。
2. 在消息中附上汇总统计（按期推进 / 未按期 / 有进展未达预期 / 已移出 / 节点未到 / 无明确节点 / 新增需求 各多少条）。
3. 重点列出所有「未按期推进」的需求清单，方便周会讨论。

## 兼容性

本技能为纯文本指令 + Python 脚本，兼容 Manus、Claude Code / Cline、CodeBuddy、Cursor 等 AI 编码工具。脚本依赖仅 `openpyxl` 和 `pandas`。

- **Manus**：直接读取 SKILL.md 并执行 `scripts/weekly_tracker.py`
- **Claude Code / Cline**：将 SKILL.md 放入项目根目录或 `CLAUDE.md` 中引用
- **Cursor / CodeBuddy**：将 SKILL.md 内容作为 rules 文件引用

## 资源

- **`scripts/weekly_tracker.py`**：核心分析脚本，接受 Excel 路径参数，执行完整的跨周比对和 AI 判断生成。
- **`references/status_mapping.md`**：状态流转顺序、关键词到期望状态的完整映射表、时间解析正则表达式，供自定义映射时参考。
