# 习惯补记（不限窗口历史补录）方案

日期：2026-08-19 · 状态：已定稿动工 · 决策人：东林

## 背景与缺口

补签功能（2026-08-17 实现，未提交）覆盖范围：

| 习惯类型 | 现状 | 缺口 |
|---|---|---|
| 每日打卡（好习惯） | 7 天窗口内漏卡日可补 | 7 天外的日子不可补 |
| 每周/每月打卡 | **完全无补历史入口** | 全部 |
| 数值型 | 7 天窗口内「无记录日」可补 | 7 天外；当天已有记录想追加 |

东林发现的场景：每周健身（无次数约束），昨天做了忘了打卡，今天想补——没有任何入口。

## 两个概念，两条通道

- **补签（找回断签）**：系统判定漏卡日 → 补上恢复连续天数。7 天窗口的快捷通道。现有三入口（磁贴点阵/详情横幅/记录行）保持不动。
- **补记（补录事实）**：用户自选任意过去日期，主动补一条记录。不限窗口（习惯创建日 ~ 昨天）。新入口，详情页记录列表。

两者共用同一条写入链路和额度池，差别只在日期校验宽窄。

## 已拍板的三个决策（2026-08-19）

1. 补记与补签**共用额度池**（免费 3 次/月全局共享，Plus 无限）。
2. 补记**不限时间窗口**（见下方 AI 影响评估，结论支持不限）。
3. 顺带修掉已知小尾巴：补签确认卡无「重选日期」入口。

## AI 影响评估（为什么不限窗口是安全的）

调研结论（2026-08-19，Explore 全链路核查）：

**不受影响的链路**（时间窗看不见旧记录）：Agent 默认窗口 14 天、聊天 UserContext focus 7 天、长期记忆萃取 14 天窗、健康洞察 14 天、LifePlan 数据充分度 7 天、DailySense 今昨两天。补一条 60 天前的记录对这些链路零影响。

**会受影响的链路**（且影响方向正确）：

1. 连续天数（streak，回溯上限 3650 天）：补上断点会抬高连续数——这正是补记的目的（那天确实做了）。
2. 显式时间窗分析：问「今年 6 月坚持得怎么样」时补记记录计入完成率——符合事实，用户补记就是声明「那天发生了」。
3. 上周期对比、全历史统计（Discover）、目标关联完成率：同理被修正为符合事实。

**已知边界→已实施（2026-08-19 同日追加，东林拍板）**：AI 感知「后补」已做进 Agent 主链路：
- `HoloHabitDailyCount` 加 `retroactiveCount`（该日后补条数，Optional 默认 nil）、`HoloHabitDailyNote` 加 `isRetroactive`——Optional 字段编码时省略，**零后补用户的 JSON 输出与 hash 完全不变**。
- 证据层：positive/negative events 的 excerpt 标「（其中 N 次后补）」；备注事件标「（后补）」。
- 语义层：含后补记录时工具结果 warnings 挂一条固定说明——「行为真实发生于该日，仅记录时间靠后，统计意义与实时记录相同；勿将后补本身解读为当天状态或主动性的证据」（防 AI 拿标记说教/过度解读的解读框架）。
- 跨域 `habit.daily` 行：后补>0 时 fields 加 `retroactiveCount` + excerpt 标注。
- 未动的链路：分析 ContextBuilder（聚合统计按修正后事实算是正确的）、记忆萃取（同前）、健康洞察。
- 顺手修正：DataSource 聚合与备注「同日取最新」原按 date 比较，同日零点相等会退化为 fetch 顺序先得；改为按 createdAt 比较（与 `getLatestValue` 口径一致，后补覆盖前值确定化）。

**历史洞察不回算**：已生成的洞察是快照语义，补记不触发重算（现有 snapshotHash 机制天然如此），符合预期。

## 实现设计

### 数据层（HabitRepository.swift）

`retroactiveCheckIn` 加参数 `allowsFullHistory: Bool = false`：

- `false`（默认）：保持 7 天窗口校验，现有三入口行为不变。
- `true`：跳过 7 天校验，仅要求 `day < 今天 && day >= 习惯创建日`。

其余全部复用现有链路：幂等（当日已有完成记录返回 alreadyCompleted 不扣额度）、额度校验、复用「取消态」记录、通知刷新。零新表字段（isRetroactive 已存在）。

### UI 层（HabitRetroactiveSheet.swift）

- `HabitRetroactiveSheetContext` 加 `mode: .sign / .backfill`（默认 .sign）。
- .sign 模式：现状不动（漏卡日列表选择）。
- .backfill 模式：日期选择改为 快捷 chips（昨天/前天/大前天）+ graphical DatePicker（项目标准先例），可选范围 = 创建日 ~ 昨天。
- 确认卡两模式通用，新增「重选日期」入口（修小尾巴，补签模式同样受益）。

### 入口（HabitDetailView.swift）

记录列表「记录」标题行右侧加「补记」按钮：好习惯可见（坏习惯被 `retroactiveSupported` 挡在数据层，UI 同步隐藏）。

### 各类型补记形态

| 类型 | 行为 |
|---|---|
| 打卡型（daily/weekly/monthly 好习惯） | 补一条完成记录；连续天数预览复用现有模拟逻辑（weekly 的周 streak 天然支持） |
| 计数类 | 当天已有记录也允许追加（value=1 新记录） |
| 测量类 | 当天已有记录允许再补（latest 聚合取当日最新，即修正当日值） |
| 坏习惯 | 不适用（入口隐藏+数据层拦截） |

## 边界情况

- 习惯创建日之前不可选（DatePicker 范围下界）。
- 今天/未来不可选（上界 = 昨天）。
- 习惯今天刚创建：无可补日期范围，入口置灰或隐藏。
- 纯客户端改动，**无需后端发版**。
